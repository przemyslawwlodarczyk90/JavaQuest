#T INTRO Test wiedzy: Java Core
Ta lekcja to zestaw pytań otwartych o fundamenty języka Java. Pytania pojawiają się w zakładce „Zadania” w losowej kolejności — przy każdym wejściu inna.

Jak pracować z pytaniami:
1. Przeczytaj pytanie i spróbuj odpowiedzieć pełnymi zdaniami — najlepiej na głos albo w polu odpowiedzi.
2. Jeśli utkniesz, odsłoń podpowiedź.
3. Dopiero potem porównaj się z odpowiedzią wzorcową. Zwróć uwagę nie tylko na fakty, ale też na argumenty i przykłady, których użyto.

#T NOTE Zakres
Platforma Java (JDK, JRE, JVM), typy proste i referencyjne, przekazywanie argumentów, klasa String, metody klasy Object, słowa kluczowe (static, final), klasy opakowujące, nowoczesne konstrukcje języka (var, rekordy, switch, klasy sealed, pattern matching) i dobre praktyki pisania kodu.

#EX
P: Czym różnią się JDK, JRE i JVM?
H: Pomyśl, co jest potrzebne do uruchomienia programu, a co do jego napisania i skompilowania.
S: JVM (Java Virtual Machine) to maszyna wirtualna, która wykonuje bajtkod (pliki .class) — ładuje klasy, weryfikuje je, interpretuje i kompiluje JIT do kodu maszynowego, zarządza pamięcią i wątkami.
JRE (Java Runtime Environment) to JVM plus biblioteka standardowa — wszystko, co potrzebne do uruchomienia programu.
JDK (Java Development Kit) to JRE plus narzędzia programisty: kompilator javac, jar, jdeps, jlink, javadoc, debugger, jshell.
Od Javy 11 Oracle nie dystrybuuje osobnego JRE — używa się JDK albo obrazu utworzonego przez jlink.

#EX
P: Dlaczego mówi się, że Java jest niezależna od platformy?
H: Co dokładnie produkuje kompilator javac?
S: Kompilator javac nie tworzy kodu maszynowego konkretnego procesora, tylko bajtkod — pośrednią, niezależną od systemu reprezentację. Ten sam plik .class uruchamia się na każdej JVM (Windows, Linux, macOS, ARM, x86). Zależna od platformy jest dopiero JVM, która tłumaczy bajtkod na instrukcje danego procesora. Hasło brzmi „write once, run anywhere”. Ograniczenia pojawiają się przy kodzie natywnym (JNI) albo przy założeniach dotyczących systemu plików, separatorów ścieżek czy kodowania znaków.

#EX
P: Czym jest kompilacja JIT i dlaczego aplikacje Java „rozgrzewają się”?
H: Interpreter, liczniki wywołań, kompilatory C1 i C2.
S: JIT (Just-In-Time) to kompilacja bajtkodu do kodu maszynowego w czasie działania programu. JVM (HotSpot) najpierw interpretuje kod i zbiera statystyki. Często wykonywane metody („gorące”) są kompilowane — najpierw szybko przez C1, potem z agresywnymi optymalizacjami przez C2 (inlining, eliminacja martwego kodu, analiza ucieczki, optymalizacja pętli). Dlatego tuż po starcie aplikacja działa wolniej, a po pewnym czasie osiąga pełną wydajność — to „rozgrzewka” (warm-up). Ma to znaczenie przy benchmarkach (trzeba odrzucić pierwsze iteracje) i przy krótko żyjących procesach, gdzie pomocne są CDS, AOT czy GraalVM Native Image.

#EX
P: Jakie typy proste ma Java i czym różnią się od typów referencyjnych?
H: Osiem typów, wartość a referencja, null, domyślne wartości.
S: Typy proste: byte, short, int, long (całkowite), float, double (zmiennoprzecinkowe), char (znak UTF-16) i boolean. Zmienna typu prostego przechowuje bezpośrednio wartość, nie może być null, a operacje na niej są szybkie.
Zmienna typu referencyjnego (klasy, interfejsy, tablice, enumy, rekordy) przechowuje referencję do obiektu na stercie albo null. Porównanie == dla referencji sprawdza, czy to ten sam obiekt.
Typy proste nie mogą być argumentami typów generycznych — do tego służą klasy opakowujące (Integer, Long…), z automatycznym pakowaniem i rozpakowywaniem.

#EX
P: Czy Java przekazuje argumenty przez wartość, czy przez referencję?
H: Co dokładnie jest kopiowane, gdy przekazujesz obiekt do metody?
S: Java zawsze przekazuje argumenty przez wartość. Dla typów prostych kopiowana jest wartość. Dla obiektów kopiowana jest wartość referencji — metoda dostaje kopię „adresu” tego samego obiektu.
Konsekwencje: metoda może zmienić stan obiektu (np. list.add(x) będzie widoczne u wywołującego), ale przypisanie nowego obiektu do parametru (list = new ArrayList<>()) nie zmienia zmiennej wywołującego. Dlatego nie da się w Javie napisać metody swap(a, b), która zamieni obiekty w zmiennych wywołującego.

#EX
P: Dlaczego klasa String jest niemutowalna i jakie to ma zalety?
H: Pula napisów, bezpieczeństwo, hashCode, wątki.
S: Obiektu String nie da się zmienić po utworzeniu — każda „modyfikacja” tworzy nowy obiekt. Zalety:
- pula napisów (string pool): te same literały mogą wskazywać jeden obiekt, co oszczędza pamięć;
- bezpieczeństwo: napisów używa się jako nazw plików, adresów URL, nazw klas, haseł połączeń — nikt nie zmieni ich po sprawdzeniu;
- bezpieczeństwo wątkowe bez synchronizacji;
- możliwość zapamiętania hashCode — String jest wydajnym kluczem w HashMap.
Wadą jest koszt wielu operacji łączenia w pętli — wtedy używa się StringBuildera.

#EX
P: Czym jest pula napisów (String pool) i jak działa metoda intern()?
H: Literały, new String, porównanie ==.
S: Pula napisów to obszar pamięci (obecnie na stercie), w którym JVM przechowuje unikalne napisy. Literały i stałe czasu kompilacji trafiają do puli automatycznie, więc "abc" == "abc" daje true. Wyrażenie new String("abc") zawsze tworzy nowy obiekt poza pulą.
Metoda intern() zwraca referencję do napisu z puli o tej samej treści (dodając go, jeśli go tam nie ma). Pozwala to deduplikować napisy, ale w praktyce rzadko się jej używa — G1 ma wbudowaną deduplikację napisów (-XX:+UseStringDeduplication). Do porównywania treści zawsze używa się equals, a nie ==.

#EX
P: Czym różnią się String, StringBuilder i StringBuffer?
H: Mutowalność i synchronizacja.
S: String jest niemutowalny. StringBuilder i StringBuffer są mutowalnymi buforami znaków z metodami append, insert, delete, reverse.
StringBuffer ma metody synchronizowane (bezpieczny wątkowo, ale wolniejszy) — to klasa z Javy 1.0. StringBuilder (Java 5) nie jest synchronizowany i jest szybszy — to domyślny wybór, bo bufor zwykle jest używany lokalnie w jednym wątku.
Kompilator i tak zamienia proste łączenie napisów a + b + c na wydajny kod (od Javy 9 przez invokedynamic), ale w pętli trzeba użyć StringBuildera, bo inaczej powstaje wiele obiektów pośrednich.

#EX
P: Jaki jest kontrakt między metodami equals() i hashCode()?
H: Co musi być prawdą dla dwóch obiektów równych według equals?
S: Jeśli a.equals(b) zwraca true, to a.hashCode() musi być równe b.hashCode(). Odwrotnie nie jest wymagane — różne obiekty mogą mieć ten sam skrót (kolizja).
Dodatkowo equals musi być zwrotne, symetryczne, przechodnie, spójne (powtarzalne) i dla null zwracać false; hashCode musi być stały, dopóki nie zmienią się pola używane w equals.
Złamanie kontraktu psuje kolekcje haszujące: obiekt dodany do HashSet może nie zostać znaleziony przez contains, a HashMap może przechowywać „duplikaty” kluczy. Dlatego nadpisuje się zawsze obie metody naraz, korzystając z tych samych pól (np. Objects.equals i Objects.hash) — albo używa się rekordów, które generują je automatycznie.

#EX
P: Czym różni się operator == od metody equals()?
H: Tożsamość a równość.
S: == porównuje wartości typów prostych, a dla referencji sprawdza tożsamość — czy obie zmienne wskazują ten sam obiekt w pamięci.
equals sprawdza równość logiczną zdefiniowaną przez klasę. Domyślna implementacja z Object działa jak ==, ale klasy takie jak String, Integer, LocalDate, kolekcje i rekordy nadpisują ją, porównując zawartość.
Typowe pułapki: porównywanie napisów przez == (działa przypadkiem dla literałów z puli), porównywanie Integer przez == (działa tylko w zakresie pamięci podręcznej -128..127).

#EX
P: Do czego służy słowo kluczowe final w odniesieniu do zmiennych, metod i klas?
H: Trzy różne znaczenia.
S: Zmienna final może zostać przypisana tylko raz (pole — w deklaracji, bloku inicjalizacyjnym lub konstruktorze). Dla referencji oznacza to stałą referencję, a nie niezmienny obiekt — final List można nadal modyfikować.
Metoda final nie może być przesłonięta w podklasie.
Klasa final nie może mieć podklas (np. String, Integer).
Dodatkowo: zmienne lokalne używane w lambdach i klasach anonimowych muszą być final lub efektywnie finalne, a pola final dają gwarancje widoczności po zakończeniu konstruktora w modelu pamięci Javy.

#EX
P: Czym różnią się final, finally i finalize?
H: Trzy zupełnie różne mechanizmy o podobnej nazwie.
S: final to modyfikator (stała zmienna, nieprzesłanialna metoda, klasa bez podklas).
finally to blok po try/catch, który wykonuje się zawsze — służy do zwalniania zasobów (dziś zwykle zastępuje go try-with-resources).
finalize() to metoda klasy Object, którą GC miał wywołać przed usunięciem obiektu. Jest przestarzała od Javy 9 i oznaczona do usunięcia (Java 18, JEP 421): nie gwarantuje, kiedy ani czy w ogóle się wykona, spowalnia GC i może „wskrzeszać” obiekty. Zamiast niej używa się try-with-resources albo klasy Cleaner.

#EX
P: Co oznacza słowo kluczowe static?
H: Należy do klasy, a nie do obiektu.
S: Składowa static należy do klasy, a nie do konkretnego obiektu.
- Pole statyczne istnieje w jednym egzemplarzu wspólnym dla wszystkich obiektów.
- Metoda statyczna nie ma this, więc nie może bezpośrednio używać pól i metod instancyjnych; wywołuje się ją przez nazwę klasy.
- Blok static wykonuje się raz przy inicjalizacji klasy.
- Klasa zagnieżdżona static nie ma referencji do obiektu klasy zewnętrznej.
- Import statyczny pozwala używać składowych statycznych bez nazwy klasy.
Metody statycznej nie da się przesłonić — można ją tylko ukryć.

#EX
P: Jakie są modyfikatory dostępu w Javie i jaki jest zakres każdego z nich?
H: Cztery poziomy od najbardziej restrykcyjnego.
S: private — tylko wewnątrz tej samej klasy (najwyższego poziomu, łącznie z klasami w niej zagnieżdżonymi).
Brak modyfikatora (package-private) — w obrębie tego samego pakietu.
protected — w pakiecie oraz w podklasach z innych pakietów (w podklasie dostęp przez referencję typu podklasy).
public — wszędzie.
Od Javy 9 nad tym działa system modułów: typ public w niewyeksportowanym pakiecie nie jest dostępny dla innych modułów. Dobra praktyka to możliwie najwęższy dostęp (enkapsulacja).

#EX
P: Czym różni się przeciążanie (overloading) od przesłaniania (overriding)?
H: Czas kompilacji kontra czas działania.
S: Przeciążanie to kilka metod o tej samej nazwie, ale różnych listach parametrów, w tej samej klasie lub hierarchii. Wybór następuje w czasie kompilacji na podstawie typów statycznych argumentów.
Przesłanianie to nowa implementacja metody nadklasy o tej samej sygnaturze w podklasie. Wybór następuje w czasie działania na podstawie rzeczywistego typu obiektu (polimorfizm, dynamiczne wiązanie).
Przesłonięcie musi zachować lub poszerzyć dostęp, może zawęzić typ zwracany (kowariancja) i nie może dodać szerszych wyjątków kontrolowanych. Adnotacja @Override pozwala kompilatorowi wykryć pomyłki.

#EX
P: Czym jest autoboxing i jakie niesie pułapki?
H: Null, ==, wydajność.
S: Autoboxing to automatyczna zamiana typu prostego na obiekt klasy opakowującej (int → Integer), a unboxing — odwrotnie. Pułapki:
- rozpakowanie null rzuca NullPointerException (np. int x = map.get(klucz) dla brakującego klucza);
- porównanie Integer przez == działa przypadkiem tylko dla wartości -128..127 (pamięć podręczna Integer.valueOf);
- w pętlach liczbowych tworzy wiele obiektów (Long sum += i), co spowalnia kod i obciąża GC;
- przeciążenia: remove(int) i remove(Object) w List<Integer> zachowują się inaczej.

#EX
P: Dlaczego do obliczeń finansowych nie należy używać double?
H: Reprezentacja binarna liczb dziesiętnych.
S: double i float używają binarnej reprezentacji zmiennoprzecinkowej (IEEE 754), w której wielu ułamków dziesiętnych, np. 0.1, nie da się zapisać dokładnie. Dlatego 0.1 + 0.2 daje 0.30000000000000004, a błędy kumulują się przy sumowaniu.
Do pieniędzy używa się BigDecimal (tworzonego z napisu lub przez BigDecimal.valueOf), z jawnie określoną skalą i trybem zaokrąglania (RoundingMode.HALF_UP, HALF_EVEN), albo liczb całkowitych w najmniejszej jednostce (grosze jako long). Przy BigDecimal pamiętaj, że equals uwzględnia skalę — do porównań wartości używa się compareTo.

#EX
P: Co się dzieje przy przepełnieniu liczby całkowitej w Javie?
H: Czy rzucany jest wyjątek?
S: Arytmetyka na int i long nie zgłasza przepełnienia — wartość „zawija się” w kodzie uzupełnień do dwóch, np. Integer.MAX_VALUE + 1 daje Integer.MIN_VALUE. Może to prowadzić do trudnych błędów (ujemne rozmiary, złe indeksy, błędne sumy).
Ochrona: metody Math.addExact, multiplyExact, toIntExact rzucają ArithmeticException przy przepełnieniu; można też liczyć na long albo BigInteger. Klasyczny przykład błędu to (low + high) / 2 w wyszukiwaniu binarnym — bezpieczniej low + (high - low) / 2 albo (low + high) >>> 1.

#EX
P: Jakie metody ma klasa Object i do czego służą?
H: Jest ich kilkanaście; najważniejsze to równość, tekst, synchronizacja.
S: equals i hashCode — równość logiczna i skrót do kolekcji haszujących.
toString — tekstowa reprezentacja (domyślnie nazwa klasy@skrót).
getClass — rzeczywista klasa obiektu w czasie działania.
clone — płytka kopia (wymaga implementacji Cloneable, inaczej CloneNotSupportedException).
wait, notify, notifyAll — niskopoziomowa koordynacja wątków na monitorze obiektu.
finalize — przestarzała, przeznaczona do usunięcia.
Każda klasa dziedziczy po Object, więc te metody są dostępne zawsze.

#EX
P: Czym różni się kopia płytka od głębokiej?
H: Co się dzieje z obiektami, do których odwołują się pola?
S: Kopia płytka tworzy nowy obiekt, ale pola referencyjne wskazują te same obiekty co w oryginale — zmiana zagnieżdżonej listy jest widoczna w obu kopiach. Tak działa domyślne Object.clone() i konstruktory kopiujące, które kopiują tylko referencje.
Kopia głęboka rekurencyjnie kopiuje także obiekty zagnieżdżone, więc kopie są w pełni niezależne.
W praktyce zamiast clone() (uważanego za źle zaprojektowany) używa się konstruktorów kopiujących, metod fabrykujących, List.copyOf, a najlepiej obiektów niemutowalnych, których w ogóle nie trzeba kopiować.

#EX
P: Jak zaprojektować klasę niemutowalną?
H: Pola, konstruktor, kopie obronne, dziedziczenie.
S: Zasady:
- klasa final (albo prywatny konstruktor), żeby podklasa nie dodała stanu mutowalnego;
- wszystkie pola private final;
- brak setterów;
- wszystkie pola ustawiane w konstruktorze;
- kopie obronne obiektów mutowalnych przy przyjmowaniu (List.copyOf) i przy zwracaniu (albo zwracanie widoków niemodyfikowalnych);
- metody „zmieniające” zwracają nowy obiekt (wzorzec withX).
Zalety: bezpieczeństwo wątkowe bez synchronizacji, łatwe rozumowanie o kodzie, bezpieczne klucze w mapach, możliwość buforowania. W nowoczesnej Javie najprościej użyć rekordu (pamiętając o kopiach obronnych komponentów mutowalnych).

#EX
P: Czym są rekordy (record) i kiedy ich używać?
H: Java 16, nośniki danych, co generuje kompilator.
S: Rekord to zwięzła deklaracja niemutowalnej klasy-nośnika danych: record Point(int x, int y) {}. Kompilator generuje pola private final, konstruktor kanoniczny, akcesory x() i y(), equals, hashCode i toString.
Rekord jest final, nie może rozszerzać innej klasy ani mieć dodatkowych pól instancyjnych, ale może implementować interfejsy, mieć metody, metody statyczne i konstruktor kompaktowy do walidacji.
Używa się ich do DTO, wartości (value objects), kluczy map, wyników metod zwracających kilka wartości i w połączeniu z klasami sealed oraz pattern matchingiem. Nie nadają się na encje JPA (wymagają mutowalności i konstruktora bezargumentowego).

#EX
P: Do czego służą klasy i interfejsy sealed?
H: Kontrolowana hierarchia, permits, wyczerpujący switch.
S: Klasa lub interfejs sealed ogranicza zbiór bezpośrednich podtypów do wymienionych w klauzuli permits (albo zdefiniowanych w tym samym pliku). Każdy podtyp musi być final, sealed albo non-sealed.
Zalety: hierarchia jest zamknięta i znana kompilatorowi — switch po typie sealed może być wyczerpujący bez default, a dodanie nowego podtypu powoduje błędy kompilacji w miejscach, które trzeba uzupełnić. Dobrze modeluje dane algebraiczne, np. sealed interface Wynik permits Sukces, Blad, albo różne rodzaje zdarzeń czy płatności. To bezpieczniejsza alternatywa dla otwartego dziedziczenia.

#EX
P: Czym jest pattern matching w Javie 21?
H: instanceof, switch, wzorce rekordów.
S: Pattern matching pozwala jednocześnie sprawdzić typ i wyciągnąć dane:
- instanceof ze wzorcem: if (obj instanceof String s && !s.isBlank()) — bez ręcznego rzutowania;
- switch ze wzorcami typów, warunkami when i case null: case Integer i when i > 0 -> ...;
- wzorce rekordów rozkładające obiekt na komponenty, także zagnieżdżone: case Point(int x, int y) -> ....
W połączeniu z klasami sealed kompilator sprawdza wyczerpującość switcha. Kod staje się krótszy i bezpieczniejszy niż łańcuchy if-instanceof z rzutowaniem. Trzeba pamiętać o kolejności przypadków (przypadek ogólny nie może poprzedzać szczegółowego).

#EX
P: Czym jest var i jakie ma ograniczenia?
H: Wnioskowanie typu zmiennej lokalnej.
S: var (Java 10) pozwala pominąć jawny typ zmiennej lokalnej — kompilator wywnioskuje go z inicjalizatora. Typ jest nadal statyczny i ustalony raz.
Ograniczenia: tylko zmienne lokalne (w tym w pętlach i try-with-resources) i parametry lambd; wymagany inicjalizator; nie działa z null, inicjalizatorem tablicy {…}, wieloma zmiennymi w jednej deklaracji ani dla pól, parametrów metod i typów zwracanych.
Dobra praktyka: używać var, gdy typ jest oczywisty z prawej strony (var list = new ArrayList<String>()), a unikać, gdy pogarsza czytelność (var x = service.process()). Uwaga na var z diamondem — daje ArrayList<Object>.

#EX
P: Czym różnią się switch-instrukcja z dwukropkiem i wyrażenie switch ze strzałką?
H: Fall-through, wartość, wyczerpującość.
S: Klasyczny switch z dwukropkiem „przechodzi” do kolejnych przypadków, dopóki nie napotka break — łatwo o błąd.
Składnia ze strzałką (Java 14) nie ma przechodzenia, pozwala łączyć etykiety (case 1, 2 ->) i może być wyrażeniem zwracającym wartość: int dni = switch (miesiac) { case LUTY -> 28; default -> 30; };. Wartość z bloku zwraca się przez yield.
Wyrażenie switch musi być wyczerpujące (default albo wszystkie stałe enuma / podtypy sealed). Od Javy 21 switch obsługuje też wzorce i case null.

#EX
P: Czym jest enum w Javie i co odróżnia go od stałych int?
H: Bezpieczeństwo typów, pola, metody, singleton.
S: Enum to typ o zamkniętym zbiorze nazwanych instancji, np. enum Status { NOWY, OPLACONY, WYSLANY }. W odróżnieniu od stałych int:
- zapewnia bezpieczeństwo typów — nie da się przekazać przypadkowej liczby;
- ma nazwę czytelną w logach (toString, name());
- może mieć pola, konstruktory, metody, a nawet osobne implementacje metod dla każdej stałej;
- działa w switch i z EnumSet/EnumMap (bardzo wydajne);
- ma metody values(), valueOf(), ordinal().
Enum z jedną stałą to zalecany sposób implementacji singletona (odporny na serializację i refleksję).

#EX
P: Czym różnią się klasy zagnieżdżone statyczne, wewnętrzne, lokalne i anonimowe?
H: Związek z obiektem zewnętrznym, miejsce deklaracji.
S: Statyczna klasa zagnieżdżona nie jest związana z obiektem klasy zewnętrznej — to zwykła klasa umieszczona w przestrzeni nazw innej (np. Map.Entry, budowniczy).
Klasa wewnętrzna (bez static) trzyma niejawną referencję do obiektu zewnętrznego i ma dostęp do jego pól; tworzy się ją przez outer.new Inner(). Może to powodować wycieki pamięci.
Klasa lokalna jest deklarowana w metodzie i widzi efektywnie finalne zmienne lokalne.
Klasa anonimowa to jednorazowa implementacja interfejsu lub rozszerzenie klasy w miejscu użycia; dziś często zastępują ją lambdy (dla interfejsów funkcyjnych).

#EX
P: Co to jest efektywnie finalna zmienna i dlaczego ma znaczenie?
H: Lambdy i klasy anonimowe.
S: Zmienna efektywnie finalna to zmienna lokalna, która nie ma modyfikatora final, ale nie jest zmieniana po inicjalizacji. Tylko takie (lub final) zmienne mogą być używane w lambdach, klasach anonimowych i lokalnych.
Powód: lambda przechwytuje kopię wartości zmiennej (zmienne lokalne żyją na stosie i mogą zniknąć, zanim lambda się wykona). Gdyby zmienna mogła się zmieniać, kopia i oryginał rozjechałyby się, a w kodzie wielowątkowym powstałyby wyścigi. Obejściem jest np. AtomicInteger albo tablica jednoelementowa, ale zwykle lepiej przemyśleć kod (np. użyć reduce w strumieniu).

#EX
P: Jaka jest różnica między interfejsem a klasą abstrakcyjną w nowoczesnej Javie?
H: Stan, konstruktory, wielodziedziczenie, metody default.
S: Interfejs opisuje kontrakt (co obiekt potrafi). Może mieć metody abstrakcyjne, default, statyczne i prywatne oraz stałe, ale nie ma stanu instancji ani konstruktorów. Klasa może implementować wiele interfejsów.
Klasa abstrakcyjna to częściowa implementacja (czym obiekt jest): może mieć pola, konstruktory, metody o dowolnym dostępie, a klasa może rozszerzać tylko jedną.
Wybór: interfejs do definiowania ról i API (łatwiej testować, mockować, łączyć), klasa abstrakcyjna do współdzielenia stanu i kodu między blisko spokrewnionymi klasami (np. szablon algorytmu).

#EX
P: Do czego służą metody default w interfejsach i jak rozwiązuje się konflikty?
H: Ewolucja API, reguła „klasa wygrywa”.
S: Metody default (Java 8) pozwalają dodać do interfejsu metodę z implementacją bez psucia istniejących klas implementujących — tak dodano np. forEach do Iterable czy stream do Collection.
Konflikty: metoda z klasy (także odziedziczona z nadklasy) ma pierwszeństwo przed default; bardziej szczegółowy interfejs wygrywa z ogólniejszym; jeśli klasa dziedziczy dwie niezwiązane metody default o tej samej sygnaturze, musi ją przesłonić i może wywołać wybraną wersję przez Interfejs.super.metoda().

#EX
P: Czym jest refleksja i kiedy się jej używa?
H: Inspekcja klas w czasie działania; frameworki.
S: Refleksja (java.lang.reflect) pozwala w czasie działania badać klasy (pola, metody, konstruktory, adnotacje), tworzyć obiekty i wywoływać metody na podstawie nazw.
Używają jej intensywnie frameworki: Spring (wstrzykiwanie zależności, adnotacje), Hibernate (mapowanie pól), Jackson (serializacja JSON), JUnit (wyszukiwanie metod testowych).
Wady: wolniejsza od bezpośrednich wywołań, omija kontrolę kompilatora (błędy ujawniają się w czasie działania), może łamać enkapsulację (setAccessible), a w modułach wymaga opens. W kodzie aplikacyjnym rzadko jest potrzebna; alternatywy to MethodHandle, generowanie kodu w czasie kompilacji (procesory adnotacji).

#EX
P: Czym są adnotacje i jak działają?
H: Metadane, retencja, przetwarzanie.
S: Adnotacje to metadane dołączane do elementów kodu (klas, metod, pól, parametrów). Same nic nie robią — znaczenie nadaje im kod, który je przetwarza:
- kompilator (@Override, @FunctionalInterface, @SuppressWarnings);
- procesory adnotacji w czasie kompilacji (Lombok, MapStruct, generatory);
- frameworki przez refleksję w czasie działania (@Autowired, @Entity, @Test).
Retencja określa, gdzie adnotacja przetrwa: SOURCE (tylko źródło), CLASS (plik class, domyślnie) lub RUNTIME (dostępna przez refleksję). @Target ogranicza miejsca użycia.

#EX
P: Dlaczego wyrażenie 0.1 + 0.2 == 0.3 daje false i jak poprawnie porównywać liczby zmiennoprzecinkowe?
H: Reprezentacja binarna i tolerancja.
S: Liczby 0.1 i 0.2 nie mają dokładnej reprezentacji w systemie binarnym, więc ich suma to 0.30000000000000004. Porównanie == jest dla double niemal zawsze błędem.
Poprawnie: porównanie z tolerancją, np. Math.abs(a - b) < 1e-9 (dobór epsilonu zależy od skali danych), albo użycie BigDecimal dla wartości wymagających dokładności. Uwaga też na NaN — NaN != NaN, do sprawdzania służy Double.isNaN; Double.compare poprawnie porządkuje także NaN i -0.0.

#EX
P: Czym różni się Integer.parseInt od Integer.valueOf?
H: Typ zwracany i pamięć podręczna.
S: parseInt(String) zwraca typ prosty int. valueOf(String) zwraca obiekt Integer, korzystając z pamięci podręcznej dla wartości -128..127 (te same obiekty).
Obie rzucają NumberFormatException dla niepoprawnego napisu (także dla spacji czy null). Gdy potrzebny jest int — parseInt (bez zbędnego obiektu); gdy obiekt (np. do kolekcji) — valueOf. Konstruktor new Integer(...) jest przestarzały i oznaczony do usunięcia.

#EX
P: Co to jest char w Javie i jak ma się do Unicode?
H: 16 bitów, UTF-16, pary zastępcze.
S: char to 16-bitowa jednostka kodowa UTF-16 bez znaku (0–65535). Większość popularnych znaków (w tym polskie litery) mieści się w jednym char, ale znaki spoza podstawowej płaszczyzny (np. wiele emoji) zajmują dwa char — parę zastępczą (surrogate pair).
Konsekwencje: String.length() zwraca liczbę jednostek UTF-16, a nie liczbę znaków widocznych dla człowieka; do poprawnej obsługi służą codePoints(), codePointCount(), Character.isLetter(int codePoint). Przy zamianie na bajty zawsze podaje się kodowanie (StandardCharsets.UTF_8).

#EX
P: Czym jest blok try-with-resources i jakie problemy rozwiązuje?
H: AutoCloseable, kolejność zamykania, wyjątki stłumione.
S: try-with-resources (Java 7) automatycznie zamyka zasoby implementujące AutoCloseable po zakończeniu bloku — także przy wyjątku. Zasoby zamykane są w odwrotnej kolejności otwarcia, przed blokami catch i finally.
Rozwiązuje problemy ręcznego finally: zapomniane close(), zagnieżdżone try przy wielu zasobach i utratę wyjątku — jeśli close() rzuci wyjątek po wyjątku z ciała, główny pozostaje wyjątek z ciała, a ten z close() trafia do getSuppressed(). Stosuje się go do strumieni, połączeń JDBC, egzekutorów (od Javy 19) i wszelkich zasobów.

#EX
P: Jaka jest różnica między wyjątkami kontrolowanymi (checked) a niekontrolowanymi (unchecked)?
H: Hierarchia klas i wymagania kompilatora.
S: Wyjątki kontrolowane to podklasy Exception poza RuntimeException (np. IOException, SQLException). Kompilator wymusza ich obsługę (try/catch) albo deklarację (throws). Sygnalizują przewidywalne problemy zewnętrzne, z których wywołujący może się podnieść.
Niekontrolowane to RuntimeException i jej podklasy (NullPointerException, IllegalArgumentException) oraz Error. Zwykle oznaczają błędy programistyczne lub naruszenie kontraktu.
W nowoczesnym kodzie (Spring, lambdy) częściej używa się wyjątków niekontrolowanych, bo kontrolowane źle współpracują ze strumieniami i zaśmiecają sygnatury — ale wymaga to dobrej dokumentacji i spójnej obsługi błędów.

#EX
P: Jakie są najczęstsze przyczyny NullPointerException i jak się przed nim chronić?
H: Wartości zwracane, rozpakowywanie, kolekcje, walidacja.
S: Przyczyny: wywołanie metody na null, rozpakowanie null do typu prostego, dostęp do pola lub elementu tablicy null, map.get dla brakującego klucza, niezainicjalizowane pola, synchronized na null.
Ochrona: walidacja argumentów (Objects.requireNonNull) na granicach API, zwracanie pustych kolekcji zamiast null, Optional dla wartości opcjonalnych zwracanych z metod, wartości domyślne (getOrDefault, requireNonNullElse), wywoływanie equals na stałej ("x".equals(s)), adnotacje @Nullable/@NonNull ze statyczną analizą. Od Javy 14 komunikaty NPE wskazują dokładnie, która referencja była null (helpful NullPointerExceptions).

#EX
P: Czym jest Optional i jak go poprawnie używać?
H: Typ zwracany, a nie pole czy parametr.
S: Optional<T> to kontener, który zawiera wartość albo jest pusty — jawnie sygnalizuje, że metoda może nie zwrócić wyniku. Poprawne użycie: jako typ zwracany metod wyszukujących (findById), z operacjami map, flatMap, filter, orElse, orElseGet, orElseThrow, ifPresent.
Złe praktyki: Optional jako pole klasy, parametr metody albo element kolekcji; wywoływanie get() bez sprawdzenia; isPresent() + get() zamiast map/orElse; zwracanie null zamiast Optional.empty(); orElse(kosztowneWywolanie()) zamiast orElseGet. Dla typów prostych istnieją OptionalInt, OptionalLong, OptionalDouble.

#EX
P: Czym jest wymazywanie typów (type erasure) w generykach?
H: Co zostaje z List<String> po kompilacji?
S: Generyki w Javie istnieją tylko w czasie kompilacji. Kompilator sprawdza typy, a potem zastępuje parametry typu ich ograniczeniem (zwykle Object) i wstawia rzutowania. W czasie działania List<String> i List<Integer> to ta sama klasa List.
Konsekwencje: nie można tworzyć new T() ani new T[], sprawdzać instanceof List<String>, przeciążać metod różniących się tylko argumentem typu, używać typów prostych jako argumentów typu ani parametru typu w kontekście statycznym. Typy surowe (raw types) i rzutowania niesprawdzane mogą prowadzić do zanieczyszczenia sterty i ClassCastException w nieoczekiwanym miejscu.

#EX
P: Co to jest serializacja w Javie i jakie ma wady?
H: Serializable, transient, bezpieczeństwo.
S: Serializacja zamienia graf obiektów na strumień bajtów (ObjectOutputStream), a deserializacja odtwarza go (ObjectInputStream). Klasa musi implementować Serializable; pola transient i static są pomijane; wersję kontroluje serialVersionUID.
Wady: poważne zagrożenia bezpieczeństwa (deserializacja niezaufanych danych może prowadzić do wykonania kodu), kruchość przy zmianie klas, ukryty „konstruktor” omijający walidację, słaba wydajność i brak przenośności. Dlatego do komunikacji i przechowywania używa się formatów takich jak JSON (Jackson), Protobuf czy Avro; jeśli trzeba deserializować, stosuje się filtry ObjectInputFilter. Rekordy deserializują się przez konstruktor kanoniczny, co jest bezpieczniejsze.

#EX
P: Czym jest Comparable, a czym Comparator?
H: Porządek naturalny kontra zewnętrzny.
S: Comparable<T> definiuje porządek naturalny obiektów klasy — klasa implementuje compareTo(T). Używają go Collections.sort(lista), TreeSet i TreeMap bez komparatora. Przykłady: String, Integer, LocalDate.
Comparator<T> to zewnętrzna strategia porównywania z metodą compare(a, b) — można mieć ich wiele dla tej samej klasy (po nazwisku, po wieku). Od Javy 8 tworzy się je fabrykami: Comparator.comparing(Osoba::nazwisko).thenComparing(Osoba::imie).reversed().
compareTo powinno być spójne z equals (zwracać 0 dla obiektów równych), inaczej TreeSet i HashSet mogą się zachowywać różnie.

#EX
P: Czym różnią się metody statyczne i instancyjne pod względem polimorfizmu?
H: Ukrywanie kontra przesłanianie.
S: Metody instancyjne są wiązane dynamicznie — wywołanie wykonuje implementację z rzeczywistej klasy obiektu (przesłanianie, polimorfizm).
Metody statyczne są wiązane statycznie według typu wyrażenia w czasie kompilacji. Metoda statyczna o tej samej sygnaturze w podklasie ukrywa metodę nadklasy, ale jej nie przesłania — wywołanie przez zmienną typu nadklasy wykona wersję z nadklasy. Dlatego metody statyczne wywołuje się przez nazwę klasy, a nie przez obiekt. Podobnie zachowują się pola: są wybierane według typu zmiennej.

#EX
P: Co to jest wzorzec „fail fast” i jak stosować go w Javie?
H: Walidacja na wejściu.
S: Fail fast oznacza wykrywanie błędów jak najwcześniej i natychmiastowe przerwanie z czytelnym komunikatem, zamiast kontynuowania z niepoprawnym stanem, który wybuchnie później w trudnym do zdiagnozowania miejscu.
W Javie: walidacja argumentów na początku metod i w konstruktorach (Objects.requireNonNull, IllegalArgumentException), konstruktory kompaktowe rekordów, iteratory kolekcji rzucające ConcurrentModificationException, niemodyfikowalne kolekcje rzucające UnsupportedOperationException, walidacja konfiguracji przy starcie aplikacji (Spring @Validated z @ConfigurationProperties).

#EX
P: Jakie są zalety pisania kodu z użyciem interfejsów zamiast konkretnych klas (programowanie do interfejsu)?
H: List<String> lista = new ArrayList<>(); — dlaczego tak?
S: Deklarowanie zmiennych, parametrów i typów zwracanych jako interfejsów (List, Map, Repository) zamiast implementacji:
- pozwala łatwo zmienić implementację bez zmiany kodu klienta (ArrayList → LinkedList, implementacja bazodanowa → w pamięci);
- ułatwia testowanie (mocki, stuby, implementacje testowe);
- zmniejsza powiązania między modułami (zasada odwracania zależności);
- jasno komunikuje kontrakt, a nie szczegóły.
W metodach publicznych warto przyjmować możliwie ogólne typy (Collection, Iterable) i zwracać możliwie konkretne interfejsy (List).

P: Co to jest kod „boilerplate” w Javie i jak nowoczesna Java go ogranicza?
H: Gettery, settery, equals, pętle, klasy anonimowe.
S: Boilerplate to powtarzalny, mało wartościowy kod: gettery, settery, equals/hashCode/toString, konstruktory, klasy anonimowe, ręczne pętle, rzutowania, zamykanie zasobów.
Ograniczają go: rekordy (nośniki danych), lambdy i referencje do metod (zamiast klas anonimowych), Stream API (deklaratywne przetwarzanie kolekcji), var, pattern matching (brak rzutowań), wyrażenia switch, bloki tekstowe, try-with-resources, fabryki kolekcji (List.of, Map.of). Dodatkowo narzędzia jak Lombok czy MapStruct generują kod w czasie kompilacji.

P: Czym jest klasa Object.hashCode() w domyślnej implementacji i czy jest to adres pamięci?
H: Tożsamościowy skrót obiektu.
S: Domyślny hashCode zwraca tożsamościowy skrót obiektu (identity hash code), dostępny też przez System.identityHashCode. Wbrew popularnemu przekonaniu nie jest to adres w pamięci — w HotSpot jest to zwykle liczba pseudolosowa wygenerowana przy pierwszym wywołaniu i zapisana w nagłówku obiektu (obiekty są przenoszone przez GC, więc adres się zmienia). Kontrakt wymaga tylko, by był stały przez cały czas życia obiektu i spójny z domyślnym equals (tożsamością).

P: Czym jest jshell i do czego może się przydać?
H: Java 9, REPL.
S: jshell to interaktywna konsola Javy (REPL — Read-Eval-Print Loop) dostępna od Javy 9. Pozwala wpisywać wyrażenia, instrukcje i deklaracje bez tworzenia klasy i metody main i od razu zobaczyć wynik.

P: Jakie znasz sposoby utworzenia obiektu w Javie?
H: Jest ich więcej niż tylko new.
S: Sposoby:
- operator new z konstruktorem;

- wzorzec budowniczego (Builder);

P: Czym jest wzorzec Builder i kiedy warto go stosować?
H: Wiele parametrów, parametry opcjonalne, niemutowalność.
S: Builder to wzorzec konstrukcyjny, w którym obiekt tworzy się krok po kroku przez obiekt pomocniczy z metodami ustawiającymi parametry i metodą build(): Pizza p = Pizza.builder().rozmiar(32).ser(true).build();.
Stosuje się go, gdy klasa ma wiele parametrów, zwłaszcza opcjonalnych — zamiast „teleskopowych” konstruktorów o wielu wariantach i zamiast setterów (które uniemożliwiają niemutowalność). Dla rekordów z kilkoma polami zwykle wystarczy konstruktor.

P: Czym jest singleton i jakie są problemy z jego stosowaniem?
H: Jedna instancja, globalny stan, testowanie.
S: Singleton gwarantuje istnienie dokładnie jednej instancji klasy z globalnym punktem dostępu. Implementacje: enum z jedną stałą (zalecana), statyczne pole final z prywatnym konstruktorem, leniwa inicjalizacja przez klasę holder (bezpieczna wątkowo bez synchronizacji).
Problemy: ukryte zależności i globalny stan, trudne testowanie (nie da się łatwo podmienić), ryzyko problemów wielowątkowych przy ręcznej leniwej inicjalizacji (double-checked locking wymaga volatile). W nowoczesnych aplikacjach zamiast ręcznych singletonów używa się kontenera wstrzykiwania zależności (beany Springa domyślnie mają zasięg singleton, ale są wstrzykiwane, a nie pobierane globalnie).

P: Co oznacza, że Java jest językiem silnie i statycznie typowanym?
H: Kiedy sprawdzane są typy i czy są niejawne konwersje?
S: Statyczne typowanie oznacza, że typy zmiennych i wyrażeń są znane i sprawdzane w czasie kompilacji — błędy typów wykrywa kompilator, a nie użytkownik w czasie działania. Silne typowanie oznacza brak niebezpiecznych, niejawnych konwersji między niezgodnymi typami (np. String nie zamieni się sam w liczbę, a zawężenie long → int wymaga rzutowania).
Dzięki temu IDE może podpowiadać i refaktoryzować kod, a wiele błędów wychwytuje się wcześnie. var nie zmienia tej zasady — typ nadal jest statyczny, tylko wywnioskowany.

P: Czym jest blok tekstowy (text block) i do czego się przydaje?
H: Trzy cudzysłowy, wcięcia.
S: Blok tekstowy (Java 15) to literał wielowierszowy zapisany między """ a """. Zaczyna się od nowej linii, wspólne wcięcie jest automatycznie usuwane, a końcowe spacje obcinane. Cudzysłowy nie wymagają ucieczki; \ na końcu linii łączy ją z następną, a \s wstawia chronioną spację.
Przydaje się do zapisu w kodzie fragmentów JSON, SQL, HTML, XML czy komunikatów — bez sklejania napisów i ręcznych \n, co poprawia czytelność. W połączeniu z formatted() pozwala tworzyć szablony: """ ... %s ... """.formatted(x).

P: Jakie znasz sposoby porównania dwóch napisów i kiedy którego użyć?
H: equals, equalsIgnoreCase, compareTo, Collator.
S: equals — równość treści z uwzględnieniem wielkości liter (podstawowe porównanie).
equalsIgnoreCase — bez wielkości liter.
compareTo / compareToIgnoreCase — porządek leksykograficzny według kodów znaków (do sortowania technicznego; wielkie litery są przed małymi).
Collator (java.text) — porównanie zgodne z regułami języka (np. polskie znaki ą, ł we właściwej kolejności) — do sortowania danych prezentowanych użytkownikom.
Nigdy nie używa się == do porównywania treści napisów. Przy porównaniu z możliwym null bezpieczne jest "stała".equals(zmienna) albo Objects.equals.

#EX
P: Jakie są zalety i wady używania wyjątków do sterowania przepływem programu?
H: Koszt tworzenia wyjątku, czytelność.
S: Używanie wyjątków zamiast warunków (np. łapanie NumberFormatException, by sprawdzić, czy napis jest liczbą, albo IndexOutOfBounds do zakończenia pętli) jest antywzorcem:
- tworzenie wyjątku jest kosztowne (zbieranie śladu stosu);
- kod staje się mniej czytelny — wyjątek sugeruje sytuację wyjątkową;
- utrudnia debugowanie i analizę logów.
Lepiej sprawdzać warunki z góry (isEmpty, containsKey, Optional, wzorce) i rezerwować wyjątki dla rzeczywiście nieoczekiwanych sytuacji. Wyjątkiem od reguły są API, które nie dają metody sprawdzającej — wtedy łapanie wyjątku jest akceptowalne.

#EX
P: Co to jest kod defensywny i kopie obronne?
H: Niezaufane dane wejściowe, mutowalne parametry.
S: Programowanie defensywne zakłada, że dane wejściowe mogą być błędne lub złośliwie zmienione. Kopie obronne to tworzenie kopii mutowalnych obiektów:
- przy przyjmowaniu (konstruktor kopiuje przekazaną listę lub datę, więc późniejsza zmiana oryginału nie zmieni stanu obiektu);
- przy zwracaniu (getter zwraca kopię lub widok niemodyfikowalny, więc klient nie zmodyfikuje wnętrza).
Przykłady: List.copyOf(lista), new ArrayList<>(lista), Collections.unmodifiableList. Kopię robi się przed walidacją, by uniknąć ataku TOCTOU (zmiana danych między sprawdzeniem a użyciem). Typy niemutowalne (String, LocalDate, rekordy z niemutowalnymi komponentami) nie wymagają kopii.

#EX
P: Do czego służy instrukcja assert i dlaczego nie należy jej używać do walidacji danych?
H: Domyślnie asercje są wyłączone.
S: assert warunek : "komunikat"; sprawdza założenie programisty i rzuca AssertionError, gdy warunek jest fałszywy. Asercje są jednak domyślnie wyłączone — włącza się je opcją JVM -ea (enableassertions).
Dlatego nie wolno ich używać do walidacji argumentów publicznych metod ani danych od użytkownika (w produkcji sprawdzenie po prostu się nie wykona), ani umieszczać w nich wyrażeń z efektami ubocznymi. Nadają się do dokumentowania i sprawdzania niezmienników wewnętrznych w czasie testów; do walidacji służą wyjątki (IllegalArgumentException, Objects.requireNonNull).

#Q
Q: Co faktycznie produkuje kompilator javac z pliku .java?
+ Bajtkod w plikach .class, wykonywany przez JVM
- Kod maszynowy konkretnego procesora
- Plik wykonywalny .exe dla bieżącego systemu
- Kod źródłowy w języku C przekazywany do kompilatora systemowego
E: javac tworzy bajtkod niezależny od platformy. Dopiero JVM (interpreter i kompilator JIT) zamienia go na instrukcje danego procesora.

#Q
Q: Jak Java przekazuje argumenty do metod?
+ Zawsze przez wartość — dla obiektów kopiowana jest wartość referencji
- Typy proste przez wartość, obiekty przez referencję
- Zawsze przez referencję
- Zależy od tego, czy parametr jest oznaczony jako final
E: Metoda dostaje kopię referencji, więc może zmienić stan wskazanego obiektu, ale przypisanie nowego obiektu do parametru nie zmienia zmiennej wywołującego.

#Q
Q: Który zestaw zawiera wyłącznie typy proste Javy?
+ byte, char, boolean, double
- int, Integer, long, float
- byte, String, char, short
- void, int, long, boolean
E: Typów prostych jest osiem: byte, short, int, long, float, double, char, boolean. Integer i String to klasy, a void nie jest typem wartości.

#Q
Q: Dlaczego klasa String jest niezmienna (immutable)?
+ Umożliwia współdzielenie literałów w puli, bezpieczne użycie jako klucz w HashMap i bezpieczeństwo wątkowe bez synchronizacji
- Bo JVM nie potrafi zmieniać tablic znaków
- Tylko po to, by konkatenacja była szybsza
- Bo String jest typem prostym
E: Niezmienność pozwala cache'ować hashCode, dzielić instancje w String pool i bezpiecznie przekazywać napisy między wątkami oraz do API bezpieczeństwa.

#Q
Q: Jaka jest główna zasada kontraktu equals/hashCode?
+ Obiekty równe według equals muszą mieć ten sam hashCode
- Obiekty o tym samym hashCode muszą być równe według equals
- hashCode musi być unikalny dla każdego obiektu
- equals musi zawsze porównywać referencje
E: Równe obiekty muszą dawać ten sam hashCode. Odwrotna implikacja nie obowiązuje — kolizje hashCode są dozwolone.

#Q
Q: Co się stanie, gdy klasa nadpisze equals, ale nie nadpisze hashCode, a jej obiekty trafią do HashSet?
+ Dwa równe obiekty mogą zostać dodane jako osobne elementy, a contains może zwracać false dla równego obiektu
- Kompilator zgłosi błąd
- HashSet rzuci wyjątek przy dodawaniu
- Nic — HashSet korzysta wyłącznie z equals
E: HashSet najpierw wybiera kubełek po hashCode. Domyślny hashCode z Object jest zwykle różny dla różnych instancji, więc równe obiekty trafią do różnych kubełków.

#Q
Q: Co oznacza słowo final przy deklaracji klasy?
+ Klasy nie można rozszerzyć (dziedziczyć po niej)
- Obiekty tej klasy są niezmienne
- Wszystkie metody klasy są statyczne
- Klasy nie można utworzyć operatorem new
E: final przy klasie blokuje dziedziczenie (np. String). Nie czyni automatycznie pól niezmiennymi.

#Q
Q: Zmienna final wskazuje na ArrayList. Co jest dozwolone?
+ Dodawanie elementów do listy, ale nie przypisanie zmiennej innej listy
- Ani dodawanie elementów, ani przypisanie innej listy
- Przypisanie innej listy, ale nie dodawanie elementów
- Wszystko — final dotyczy tylko typów prostych
E: final blokuje ponowne przypisanie referencji, a nie zmianę stanu obiektu. Do niezmiennej listy służy np. List.of albo List.copyOf.

#Q
Q: Czym różni się pole static od pola instancji?
+ Pole static należy do klasy i jest wspólne dla wszystkich obiektów
- Pole static jest niezmienne
- Pole static jest tworzone osobno dla każdego obiektu
- Pole static jest dostępne tylko w metodach prywatnych
E: Pole statyczne istnieje w jednej kopii na klasę (w danym class loaderze), niezależnie od liczby obiektów.

#Q
Q: Co zwróci porównanie Integer a = 1000, b = 1000; a == b?
+ Zwykle false, bo == porównuje referencje, a cache Integer obejmuje domyślnie -128..127
- Zawsze true
- Błąd kompilacji
- NullPointerException
E: Autoboxing używa Integer.valueOf, które cache'uje tylko mały zakres. Obiekty opakowujące porównuje się przez equals.

#Q
Q: Co dzieje się przy rozpakowaniu (unboxing) wartości null typu Integer do int?
+ Rzucany jest NullPointerException
- Zmienna dostaje wartość 0
- Kompilator nie pozwoli napisać takiego kodu
- Zmienna dostaje wartość -1
E: Rozpakowanie wywołuje intValue() na referencji, więc dla null kończy się NullPointerException w czasie działania.

#Q
Q: Do czego służy StringBuilder?
+ Do wydajnego budowania napisu w wielu krokach bez tworzenia wielu pośrednich obiektów String
- Do szyfrowania napisów
- Do porównywania napisów niezależnie od wielkości liter
- Do bezpiecznego współdzielenia napisów między wątkami z synchronizacją
E: StringBuilder jest zmienny i niesynchronizowany. Jego synchronizowanym odpowiednikiem jest starszy StringBuffer.

#Q
Q: Co oznacza var w deklaracji zmiennej lokalnej?
+ Typ zmiennej jest wnioskowany przez kompilator i ustalony na stałe
- Zmienna jest dynamicznie typowana jak w JavaScripcie
- Zmienna może przyjąć wartość dowolnego typu
- Zmienna jest automatycznie final
E: var to tylko skrót zapisu — typ statyczny zostaje ustalony z inicjalizatora w czasie kompilacji.

#Q
Q: Czym jest rekord (record) w Javie?
+ Zwięzłą klasą-nośnikiem danych z polami final, konstruktorem kanonicznym, akcesorami, equals, hashCode i toString
- Klasą, którą można dowolnie rozszerzać
- Specjalnym typem tablicy
- Interfejsem z metodami domyślnymi
E: Rekord jest niejawnie final, jego komponenty są polami prywatnymi final, a metody equals/hashCode/toString są generowane na podstawie komponentów.

#Q
Q: Co dają klasy sealed?
+ Pozwalają jawnie określić, które klasy mogą rozszerzać daną klasę lub implementować interfejs
- Blokują tworzenie obiektów klasy
- Czynią wszystkie pola klasy niezmiennymi
- Szyfrują bajtkod klasy
E: Lista permits zamyka hierarchię, dzięki czemu kompilator może sprawdzić kompletność switch po wzorcach.

#Q
Q: Jaka jest różnica między == a equals dla obiektów String?
+ == porównuje referencje, equals porównuje zawartość napisów
- == porównuje zawartość, equals porównuje referencje
- Oba porównują zawartość
- Oba porównują referencje
E: Dwa napisy o tej samej treści mogą być różnymi obiektami, więc treść porównuje się metodą equals.

#Q
Q: Która metoda klasy Object jest wywoływana przy łączeniu obiektu z napisem operatorem +?
+ toString
- hashCode
- equals
- getClass
E: Konkatenacja wywołuje String.valueOf(obiekt), które dla obiektu różnego od null wywołuje toString.

#Q
Q: Dlaczego nie należy porównywać kwot pieniężnych na typie double?
+ double ma reprezentację binarną, która nie przechowuje dokładnie wielu ułamków dziesiętnych, np. 0.1
- double ma za mały zakres
- Operacje na double rzucają wyjątki przy zaokrągleniu
- double nie obsługuje liczb ujemnych
E: 0.1 + 0.2 nie daje dokładnie 0.3. Do kwot używa się BigDecimal (tworzonego z napisu) albo liczb całkowitych w groszach.

#Q
Q: Co oznacza modyfikator dostępu package-private (brak modyfikatora)?
+ Element jest widoczny tylko w obrębie tego samego pakietu
- Element jest widoczny wszędzie
- Element jest widoczny tylko w tej samej klasie
- Element jest widoczny w pakiecie i we wszystkich podklasach z innych pakietów
E: Dostęp pakietowy jest węższy niż protected — podklasy z innych pakietów go nie widzą.

#Q
Q: Co wyróżnia switch z wyrażeniem strzałkowym (case X ->) w porównaniu z klasycznym switch?
+ Brak przechodzenia (fall-through) do kolejnych przypadków i możliwość zwrócenia wartości
- Działa tylko na typie int
- Wymaga instrukcji break po każdym przypadku
- Nie obsługuje enumów
E: Gałęzie strzałkowe wykonują się bez fall-through, a switch jako wyrażenie zwraca wartość (w bloku przez yield).
