#T INTRO Strumienie java.io i serializacja — ściąga egzaminacyjna
Pakiet `java.io` to starsze, ale nadal obecne na egzaminie API: strumienie bajtowe i znakowe, klasy opakowujące (buforowanie, formatowanie), klasa `File` oraz serializacja obiektów. Pytania dotyczą wyboru właściwej klasy, zachowania metod `read`/`write` i reguł serializacji.

#T DEFINITION Strumienie bajtowe i znakowe
```
              bajty (byte)                 znaki (char)
wejście       InputStream                  Reader
              FileInputStream              FileReader
              BufferedInputStream          BufferedReader (readLine)
              ObjectInputStream            InputStreamReader (bajty -> znaki)
wyjście       OutputStream                 Writer
              FileOutputStream             FileWriter
              BufferedOutputStream         BufferedWriter (newLine)
              ObjectOutputStream           PrintWriter
              PrintStream (System.out)     OutputStreamWriter (znaki -> bajty)
```
- Klasy niskiego poziomu łączą się bezpośrednio ze źródłem (plikiem), klasy wysokiego poziomu opakowują inny strumień.
- `read()` zwraca `int`: kolejny bajt (0–255) lub znak, a **-1** na końcu strumienia.
- `read(byte[] buf)` zwraca liczbę odczytanych bajtów albo -1.
- `readLine()` zwraca linię bez znaku końca linii albo `null` na końcu.

#T NOTE Ważne szczegóły
- `new FileOutputStream(plik)` nadpisuje plik; `new FileOutputStream(plik, true)` dopisuje.
- `flush()` wypycha bufor; `close()` robi flush i zamyka — także strumień opakowany.
- `PrintWriter` i `PrintStream` nie rzucają `IOException` — błędy sprawdza się metodą `checkError()`.
- `System.in` to `InputStream`, `System.out` i `System.err` to `PrintStream`.
- `Console` (`System.console()`) może być `null`, gdy program nie działa w interaktywnym terminalu; `readPassword()` zwraca `char[]`.
- `mark(limit)`/`reset()` działają tylko, gdy `markSupported()` zwraca `true`; `skip(n)` pomija bajty/znaki.

#T NOTE Serializacja
- Klasa musi implementować `Serializable` (interfejs znacznikowy). Pole typu, który nie jest serializowalny → `NotSerializableException` w czasie działania.
- Pola `transient` i `static` **nie są** zapisywane; po odczycie pole `transient` ma wartość domyślną (0, `null`, `false`).
- Przy deserializacji **nie są wywoływane** konstruktory klasy serializowalnej ani inicjalizatory jej pól — wywoływany jest tylko bezargumentowy konstruktor pierwszej **niesserializowalnej** nadklasy.
- `serialVersionUID` identyfikuje wersję klasy; niezgodność → `InvalidClassException`.
- Rekordy są serializowane przez komponenty i odtwarzane przez konstruktor kanoniczny.
- `ObjectOutputStream.writeObject` / `ObjectInputStream.readObject` (zwraca `Object`, rzuca `ClassNotFoundException`).

#T PITFALL Pułapki
- `FileReader`/`FileWriter` dotyczą znaków, a `FileInputStream`/`FileOutputStream` — bajtów; nie można ich mieszać bez mostu (`InputStreamReader`).
- `BufferedReader` przyjmuje `Reader`, a nie `InputStream` — `new BufferedReader(new FileInputStream(f))` się nie kompiluje.
- `File` reprezentuje ścieżkę; utworzenie obiektu `File` nie tworzy pliku. `delete()` na niepustym katalogu zwraca `false`.
- Pętla `while ((b = in.read()) != -1)` — przypisanie w nawiasie jest konieczne.

#T SUMMARY Podsumowanie
Rozróżniaj bajty i znaki, niski i wysoki poziom, pamiętaj o -1/`null` na końcu strumienia i o regułach serializacji: `transient` i `static` pomijane, konstruktor wywoływany tylko dla pierwszej niesserializowalnej nadklasy.

```
public class S1 {
    static class Person implements Serializable {
        String name = "Ola";
        transient int age = 30;
        static String group = "A";
    }
    public static void main(String[] args) throws Exception {
        ByteArrayOutputStream bout = new ByteArrayOutputStream();
        try (var out = new ObjectOutputStream(bout)) { out.writeObject(new Person()); }
        Person.group = "B";
        try (var in = new ObjectInputStream(new ByteArrayInputStream(bout.toByteArray()))) {
            Person p = (Person) in.readObject();
            System.out.println(p.name + " " + p.age + " " + Person.group);

    }
}
```

- Ola 30 A
- Ola 30 B
- null 0 B
X: out
E: Pole transient nie jest zapisywane — po odczycie ma wartość domyślną 0 (inicjalizator pola nie jest wykonywany). Pola statyczne nie należą do obiektu.

#Q
Q: Do czego służy pole serialVersionUID?
+ Identyfikuje wersję klasy serializowalnej; niezgodność przy odczycie powoduje InvalidClassException
- Określa kolejność zapisu pól
- Jest unikalnym identyfikatorem każdego obiektu
- Wyłącza serializację pól statycznych
E: Jawne serialVersionUID pozwala kontrolować zgodność wersji — bez niego JVM wylicza je z budowy klasy, więc drobna zmiana może zepsuć odczyt.
