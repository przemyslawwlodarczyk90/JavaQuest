#T INTRO Rekordy, enumy i klasy sealed — ściąga egzaminacyjna
To trzy specjalne rodzaje typów, którymi Java modeluje dane: rekord (niemutowalny nośnik wartości), enum (zamknięty zbiór stałych) i hierarchia sealed (zamknięty zbiór podtypów). Egzamin Java 21 pyta o nie bardzo szczegółowo, bo łączą się z pattern matchingiem w `switch`.

#T DEFINITION Rekord
```
record Point(int x, int y) { }
```
Kompilator generuje: pola `private final`, **konstruktor kanoniczny** (wszystkie komponenty w kolejności), akcesory `x()` i `y()` (bez przedrostka get), `equals`, `hashCode` i `toString` w formacie `Point[x=1, y=2]`.
- Rekord jest niejawnie `final` i dziedziczy po `java.lang.Record` — nie może rozszerzać innej klasy, ale może implementować interfejsy.
- Nie może deklarować **pól instancyjnych** poza komponentami (pola statyczne — tak).
- Może mieć metody instancyjne i statyczne, konstruktory dodatkowe (muszą zaczynać się od `this(...)`), klasy zagnieżdżone.

#T NOTE Konstruktor kompaktowy
```
record Range(int from, int to) {
    Range {                         // bez listy parametrów
        if (from > to) throw new IllegalArgumentException();
        from = Math.max(0, from);   // zmienia PARAMETR, nie pole
    }
}
```
- Pola są przypisywane automatycznie **na końcu** konstruktora kompaktowego.
- Wewnątrz nie wolno przypisywać `this.from = ...` (błąd kompilacji).
- Można zdefiniować albo kompaktowy, albo jawny kanoniczny — nie oba.
- Przesłonięty akcesor musi być `public` i zwracać dokładnie typ komponentu.

#T NOTE Enum
- Stałe są obiektami `public static final`, tworzonymi raz przy inicjalizacji klasy enum.
- Konstruktor jest niejawnie `private` (nie można go wywołać przez `new`).
- `values()`, `valueOf(String)` (zła nazwa → `IllegalArgumentException`), `name()`, `ordinal()` (od 0), `compareTo` według kolejności deklaracji.
- Stała może mieć własne ciało; metoda `abstract` w enumie wymusza implementację w każdej stałej.
- Enum nie może być rozszerzany ani rozszerzać klasy, ale może implementować interfejsy. Lista stałych musi być pierwsza w ciele.

#T NOTE Klasy i interfejsy sealed
```
sealed interface Shape permits Circle, Square, Poly { }
final class Circle implements Shape { }
record Square(double a) implements Shape { }   // rekord jest final
non-sealed class Poly implements Shape { }      // otwiera hierarchię dalej
```
- Każdy dozwolony podtyp musi bezpośrednio rozszerzać/implementować typ sealed i być `final`, `sealed` albo `non-sealed`.
- Podtypy muszą być w tym samym module (albo, bez modułów, w tym samym pakiecie).
- `permits` można pominąć, jeśli wszystkie podtypy są w tym samym pliku.
- `switch` po typie sealed jest wyczerpujący bez `default`, jeśli obsługuje wszystkie podtypy.

#T PITFALL Pułapki
- Rekord jest płytko niemutowalny: komponent typu `List` można zmienić, jeśli lista jest mutowalna.
- `equals` rekordu porównuje komponenty przez `equals` — dla tablic oznacza to porównanie referencji.
- `Enum.valueOf("red")` dla stałej `RED` rzuca wyjątek — wielkość liter ma znaczenie.
- `non-sealed` nie jest dozwolony na rekordzie ani enumie (one są niejawnie final/sealed).

#T SUMMARY Podsumowanie
Rekord: komponenty, kanoniczny/kompaktowy konstruktor, akcesory bez get, brak dodatkowych pól instancyjnych. Enum: stałe tworzone raz, prywatny konstruktor, ordinal od zera. Sealed: zamknięta lista podtypów, każdy final/sealed/non-sealed — i wyczerpujący switch bez default.
