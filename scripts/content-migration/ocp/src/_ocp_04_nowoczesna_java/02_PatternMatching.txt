#T INTRO Pattern matching — ściąga egzaminacyjna
Java 21 ma trzy powiązane mechanizmy: wzorzec typu w `instanceof`, wzorce w `switch` (z warunkami `when` i obsługą `null`) oraz wzorce rekordów, które rozkładają rekord na komponenty. Egzamin pyta przede wszystkim o **zasięg zmiennych wzorca**, **dominację** przypadków i **wyczerpującość** switcha.

#T DEFINITION Wzorzec typu w instanceof
```
if (obj instanceof String s && s.length() > 3) { ... s ... }
if (!(obj instanceof Integer i)) return;
... i ... // tutaj i jest w zasięgu - zasięg zależny od przepływu
```
- Zmienna wzorca istnieje tam, gdzie kompilator ma pewność, że dopasowanie się udało („flow scoping”).
- Przy `&&` jest widoczna po prawej stronie, przy `||` — nie.
- Nie może kolidować z istniejącą zmienną lokalną o tej samej nazwie.
- Jeśli typ wyrażenia nie może być w ogóle rzutowany na typ wzorca (niezwiązane klasy), kod się nie kompiluje.

#T NOTE Wzorce w switch
```
String describe(Object o) {
    return switch (o) {
        case null -> "null";
        case Integer i when i > 100 -> "duża liczba";
        case Integer i -> "liczba " + i;
        case String s -> "napis " + s.length();
        default -> "inne";
    };
}
```
- Kolejność ma znaczenie: przypadek, który **dominuje** następny (np. `case CharSequence cs` przed `case String s`, albo `case Integer i` przed `case Integer i when ...`), daje błąd kompilacji.
- `default` może stać na końcu; przypadek ze stałą nie może stać po wzorcu, który go obejmuje.
- Switch ze wzorcami musi być wyczerpujący (także instrukcja switch, nie tylko wyrażenie).
- Bez `case null` wartość `null` rzuca `NullPointerException`; `case null` można łączyć z `default`: `case null, default ->`.

#T NOTE Wzorce rekordów
```
record Point(int x, int y) { }
if (o instanceof Point(int x, int y)) { ... x + y ... }
switch (shape) {
    case Circle(Point(var cx, var cy), double r) -> ...
}
```
- Liczba i typy wzorców muszą pasować do komponentów rekordu; można używać `var`.
- Wzorce można zagnieżdżać.
- Wzorzec rekordu nie dopasowuje `null`.

#T PITFALL Pułapki
- Przy wyczerpującym switchu po typie sealed `default` nie jest potrzebny, ale dla `Object` — jest.
- Przypadek z wzorcem `case Object o` jest bezwarunkowy — nie może po nim stać `default`.
- Zmienna wzorca nie jest `final`, ale jej przypisanie bywa mylące — na egzaminie szukaj kolizji nazw.
- W `when` może stać dowolne wyrażenie logiczne, także wywołanie metody.

#T SUMMARY Podsumowanie
Sprawdzaj zasięg zmiennych wzorca (`&&` vs `||`, negacja i wczesny powrót), kolejność przypadków w switch (od szczegółowych do ogólnych), obsługę `null` i wyczerpującość. Wzorce rekordów rozkładają obiekt na komponenty, także zagnieżdżone.

#EX
P: Czym jest pattern matching dla instanceof i jaki ma zasięg zmienna wzorca?
H: Gdzie zmienna jest „na pewno przypisana”?
S: if (o instanceof String s) sprawdza typ i od razu tworzy zmienną s typu String. Zmienna jest widoczna tylko tam, gdzie dopasowanie na pewno się powiodło: w gałęzi then, w dalszej części warunku po && oraz za if, gdy gałąź negacji (if (!(o instanceof String s)) return;) kończy metodę. Nie można jej użyć po ||.

#EX
P: Czym są wzorce rekordów (record patterns)?
H: Rozbicie rekordu na komponenty, zagnieżdżanie.
S: Wzorzec rekordu dopasowuje obiekt do typu rekordu i od razu wydobywa jego komponenty: if (o instanceof Punkt(int x, int y)). Wzorce można zagnieżdżać, np. Linia(Punkt(var x1, var y1), Punkt p2). W komponentach można używać var. Działają w instanceof i w switch od Javy 21.

#EX
P: Do czego służy klauzula when w switch z wzorcami?
H: Strażnik i dominacja.
S: when dodaje warunek logiczny do wzorca: case Integer i when i > 0 -> .... Gałąź wybierana jest tylko wtedy, gdy typ pasuje i warunek jest prawdziwy. Wzorzec ze strażnikiem nie dominuje nad tym samym wzorcem bez strażnika, więc ogólniejszy przypadek musi być niżej.

#EX
P: Kiedy switch z wzorcami musi mieć default?
H: Kompletność.
S: switch na wzorcach (instrukcja lub wyrażenie) musi być wyczerpujący. Jeśli typ przełączany jest sealed i wszystkie dozwolone podtypy są obsłużone, default nie jest potrzebny. Dla typów otwartych, np. Object, potrzebny jest default albo wzorzec bezwarunkowy (np. case Object o).

#EX
P: Jak switch z wzorcami obsługuje null?
H: case null i zachowanie domyślne.
S: Bez etykiety case null switch rzuca NullPointerException dla wartości null, także przy wzorcach. Można dodać case null -> ... albo połączyć case null, default -> .... Wzorzec typu (np. case String s) nigdy nie dopasowuje null.

#EX
P: Czym różnią się wzorce typów od stałych etykiet w jednym switch?
H: Kolejność i mieszanie.
S: W jednym switch można łączyć stałe (np. enumy) z wzorcami typów, ale obowiązuje kolejność: przypadek ogólniejszy nie może poprzedzać szczegółowszego, a stałe muszą być przed wzorcem, który by je obejmował. Kompilator zgłasza błąd dla etykiety nieosiągalnej.

#EX
P: Dlaczego pattern matching ogranicza ryzyko ClassCastException?
H: Porównaj z ręcznym instanceof i rzutowaniem.
S: Tradycyjny kod sprawdzał typ, a potem osobno rzutował — łatwo było rzutować na inny typ niż sprawdzony albo zapomnieć o sprawdzeniu. Pattern matching łączy test i rzutowanie w jedną operację z nową, poprawnie typowaną zmienną, więc rzutowanie zawsze zgadza się z testem.

#EX
P: Czy zmienną wzorca można zmodyfikować i czy może ona przesłonić pole?
H: final i przesłanianie nazw.
S: Zmienna wzorca nie jest final i można ją ponownie przypisać (chyba że zadeklarujemy final String s), choć to zła praktyka. Może mieć tę samą nazwę co pole — wtedy przesłania je w swoim zasięgu. Nie może kolidować z istniejącą w tym zasięgu zmienną lokalną.
