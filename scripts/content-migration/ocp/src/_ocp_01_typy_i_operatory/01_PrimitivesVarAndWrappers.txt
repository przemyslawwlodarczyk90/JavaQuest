#T INTRO Typy proste, var i klasy opakowujące — ściąga egzaminacyjna
Pytania z tego obszaru rzadko pytają „ile bitów ma int”. Częściej pokazują przypisanie, które wygląda niewinnie, a się nie kompiluje, albo porównanie `Integer` przez `==`, które raz daje `true`, a raz `false`. Ta ściąga zbiera reguły, które trzeba znać na pamięć.

#T DEFINITION Osiem typów prostych
```
typ      rozmiar   zakres / uwagi                       wartość domyślna pola
byte     8 bit     -128 .. 127                          0
short    16 bit    -32768 .. 32767                      0
char     16 bit    0 .. 65535 (bez znaku!)              '\u0000'
int      32 bit    ok. -2,1 mld .. 2,1 mld              0
long     64 bit    literał z L: 10L                     0L
float    32 bit    literał z f: 1.5f                    0.0f
double   64 bit    domyślny typ literału z kropką       0.0
boolean  -         true / false (nie jest liczbą)       false
```
Zmienne lokalne **nie mają wartości domyślnej** — użycie przed przypisaniem to błąd kompilacji. Wartości domyślne mają tylko pola i elementy tablic.

#T NOTE Literały liczbowe
- Literał całkowity bez przyrostka ma typ `int`. `long big = 3000000000;` się nie kompiluje — potrzeba `3000000000L`.
- Literał z kropką ma typ `double`. `float f = 1.5;` się nie kompiluje — potrzeba `1.5f` albo rzutowania.
- Systemy: `0b101` (binarny), `017` (ósemkowy, wiodące zero!), `0x1F` (szesnastkowy).
- Podkreślenia `1_000_000` są dozwolone tylko **między cyframi**: nie na początku, nie na końcu, nie obok kropki, nie obok przyrostka `L`/`f`, nie zaraz po `0x`/`0b`.
- Stała całkowita typu `int`, której wartość mieści się w zakresie, może być przypisana do `byte`, `short` i `char` bez rzutowania (`byte b = 10;`). Działa to także dla zmiennych `final` z wartością znaną w czasie kompilacji.

#T NOTE var — wnioskowanie typu zmiennej lokalnej
- Tylko dla **zmiennych lokalnych** z inicjalizatorem (także w pętli `for` i w try-with-resources). Nie dla pól, parametrów metod ani typów zwracanych.
- Nie wolno: `var x;`, `var x = null;`, `var a = {1, 2};`, `var a = 1, b = 2;`.
- Typ jest ustalany raz: `var n = 10; n = "tekst";` się nie kompiluje.
- `var` może być typem parametru lambdy (`(var x, var y) -> x + y`), ale wtedy wszystkie parametry muszą go używać.
- `var` to zastrzeżona nazwa typu, nie słowo kluczowe: zmienna, metoda czy pakiet może nazywać się `var`, ale klasa — nie.

#T NOTE Klasy opakowujące i autoboxing
- Każdy typ prosty ma klasę: `Byte`, `Short`, `Character`, `Integer`, `Long`, `Float`, `Double`, `Boolean`.
- `Integer.valueOf(…)` korzysta z pamięci podręcznej dla wartości od **-128 do 127** — w tym zakresie `==` na obiektach „przypadkiem” daje `true`.
- `parseInt` zwraca `int`, `valueOf` zwraca `Integer`.
- Autoboxing nie łączy się z poszerzaniem: `Long l = 10;` się nie kompiluje (int → Integer, nie Long).
- Rozpakowanie `null` daje `NullPointerException`.
- `equals` w klasach opakowujących porównuje też typ: `Long.valueOf(1).equals(1)` daje `false`.

#T PITFALL Pułapki arytmetyki
- Dzielenie całkowite przez zero rzuca `ArithmeticException`, a zmiennoprzecinkowe daje `Infinity` albo `NaN`.
- `NaN` nie jest równe niczemu, nawet sobie: `Double.NaN == Double.NaN` to `false`.
- Przepełnienie `int` nie rzuca wyjątku — wartość „zawija się”.
- `Math.round(double)` zwraca `long`, a `Math.round(float)` zwraca `int`.
- `Math.abs(Integer.MIN_VALUE)` zwraca nadal `Integer.MIN_VALUE`.

#T SUMMARY Podsumowanie
Pamiętaj o typie literałów (`int`, `double`), o regułach podkreśleń, o braku wartości domyślnych dla zmiennych lokalnych, o ograniczeniach `var`, o pamięci podręcznej `Integer` i o tym, że autoboxing nie poszerza typu.

#Q
Q: Która deklaracja się kompiluje?
+ long big = 3_000_000_000L;
- long big = 3000000000;
- int big = 3_000_000_000;
- long big = 3_000_000_000_L;
X: opt-ok
E: Literał bez przyrostka ma typ int, a 3 000 000 000 przekracza zakres int, więc potrzebny jest przyrostek L. Podkreślenie nie może stać bezpośrednio przed przyrostkiem L.

#Q
Q: Która deklaracja się NIE kompiluje?
+ float f = 2.5;
- float f = 2.5f;
- double d = 2.5f;
- float f = 25;
X: opt-ce
E: Literał 2.5 ma typ double, a zawężenie double → float wymaga jawnego rzutowania. Literał int (25) i float (2.5f) można przypisać do float, a float do double — to poszerzenie.

#Q
Q: Który literał jest poprawny?
+ int a = 1__000;
- int a = _1000;
- int a = 1000_;
- int a = 0x_1F;
X: opt-ok
E: Podkreślenia mogą stać tylko między cyframi, także po kilka z rzędu. Nie mogą być na początku, na końcu ani bezpośrednio po prefiksie 0x/0b.

#Q
Q: Która deklaracja double się NIE kompiluje?
+ double d = 1_.5;
- double d = 1_0.5;
- double d = 1.5_0;
- double d = 1_0.5_0;
X: opt-ce
E: Podkreślenie nie może sąsiadować z kropką dziesiętną. Między cyframi po obu stronach kropki jest dozwolone.

#EX
P: Jakie typy proste ma Java i jakie mają rozmiary?
H: Cztery całkowite, dwa zmiennoprzecinkowe, znak i wartość logiczna.
S: byte (8 bitów), short (16), int (32), long (64) — liczby całkowite ze znakiem. float (32) i double (64) — liczby zmiennoprzecinkowe IEEE 754. char (16 bitów, bez znaku, jednostka UTF-16) i boolean (true/false, bez określonego w specyfikacji rozmiaru). Pola i elementy tablic dostają wartości domyślne (0, 0.0, '\u0000', false), a zmienne lokalne nie mają wartości domyślnej.

#EX
P: Dlaczego deklaracja long big = 3000000000; się nie kompiluje?
H: Jaki typ ma literał całkowity bez przyrostka?
S: Literał całkowity bez przyrostka ma typ int, a 3 000 000 000 przekracza zakres int (ok. 2,1 mld), więc kompilator zgłasza błąd, zanim w ogóle dojdzie do poszerzenia do long. Trzeba dodać przyrostek L: 3000000000L. Analogicznie float f = 1.5; się nie kompiluje, bo literał z kropką ma typ double — potrzeba 1.5f.

#EX
P: Gdzie wolno umieszczać podkreślenia w literałach liczbowych?
H: Tylko w jednym miejscu względem cyfr.
S: Podkreślenia są dozwolone wyłącznie między cyframi, np. 1_000_000. Nie mogą stać na początku ani na końcu literału, obok kropki dziesiętnej, obok przyrostka (L, f, d) ani bezpośrednio po prefiksie 0x lub 0b. Podkreślenia nie zmieniają wartości — służą tylko czytelności.

#EX
P: Jakie są ograniczenia słowa var?
H: Gdzie wolno go użyć, czego nie wolno w inicjalizatorze, czy typ może się zmienić?
S: var działa tylko dla zmiennych lokalnych z inicjalizatorem (także w pętli for i try-with-resources), a nie dla pól, parametrów metod ani typów zwracanych. Nie wolno napisać var x; ani var x = null; ani var a = {1, 2}; ani zadeklarować kilku zmiennych naraz. Typ jest ustalany raz z inicjalizatora i nie zmienia się. var to zastrzeżona nazwa typu, a nie słowo kluczowe — zmienna może nazywać się var, klasa nie.

#EX
P: Dlaczego Integer a = 127, b = 127; a == b daje true, a dla 128 daje false?
H: Integer.valueOf i pamięć podręczna.
S: Autoboxing wywołuje Integer.valueOf, który dla wartości od -128 do 127 zwraca obiekty z pamięci podręcznej — dwie zmienne wskazują wtedy ten sam obiekt, więc == daje true. Dla 128 powstają dwa różne obiekty i == porównujące referencje daje false. Obiekty opakowujące należy porównywać przez equals albo po rozpakowaniu.

#EX
P: Czym różnią się Integer.parseInt i Integer.valueOf?
H: Typ zwracany.
S: parseInt zwraca typ prosty int, a valueOf zwraca obiekt Integer (korzystając z pamięci podręcznej dla małych wartości). Obie metody rzucają NumberFormatException dla niepoprawnego napisu. W praktyce wybór zależy od tego, czy potrzebujemy wartości prostej, czy obiektu, np. do kolekcji.

#EX
P: Dlaczego Long l = 10; się nie kompiluje, choć long l = 10; jest poprawne?
H: Autoboxing a poszerzanie typu.
S: W przypisaniu long l = 10 literał int jest poszerzany do long. Przy Long l = 10 kompilator musiałby najpierw poszerzyć int do long, a potem opakować w Long — Java nie łączy poszerzania z autoboxingiem w jednym kroku. Literał int można opakować tylko w Integer. Poprawny zapis to Long l = 10L.

#EX
P: Jakie są pułapki arytmetyki zmiennoprzecinkowej i całkowitej w Javie?
H: Dzielenie przez zero, NaN, przepełnienie, Math.round.
S: Dzielenie całkowite przez zero rzuca ArithmeticException, a zmiennoprzecinkowe daje Infinity lub NaN. NaN nie jest równe niczemu, nawet sobie, więc sprawdza się je przez Double.isNaN. Przepełnienie int i long nie rzuca wyjątku — wartość się zawija (bezpieczne są Math.addExact i podobne). Math.round(double) zwraca long, a Math.round(float) — int. Math.abs(Integer.MIN_VALUE) zwraca wartość ujemną.
