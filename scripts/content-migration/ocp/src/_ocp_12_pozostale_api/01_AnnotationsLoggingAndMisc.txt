#T INTRO Adnotacje, logowanie i przydatne API — ściąga egzaminacyjna
Ostatni rozdział banku zbiera zagadnienia pojawiające się na pograniczu obszarów egzaminu: definiowanie i używanie adnotacji, podstawy logowania (`java.util.logging`), klasy narzędziowe `Arrays`, `Math`, `Objects` oraz `BigDecimal` do precyzyjnych obliczeń.

#T DEFINITION Definiowanie adnotacji
```
@Retention(RetentionPolicy.RUNTIME)       // SOURCE / CLASS (domyślnie) / RUNTIME
@Target({ElementType.TYPE, ElementType.METHOD})
@Documented
@Inherited                                 // dziedziczona przez podklasy (tylko dla klas)
public @interface Audyt {
    String value();                        // element wymagany
    int poziom() default 1;                // element opcjonalny
    String[] tagi() default {};
}

@Audyt("zamówienia")                       // skrót dla jedynego wymaganego elementu value
@Audyt(value = "x", poziom = 2, tagi = "a") // tablica z jednym elementem bez klamer
```
- Typy elementów: typy proste, `String`, `Class`, enum, inne adnotacje i tablice tych typów. **Nie**: klasy opakowujące (`Integer`), dowolne obiekty, tablice wielowymiarowe.
- Wartość domyślna nie może być `null` i musi być stałą.
- Elementy nie mają parametrów ani `throws`; są niejawnie `public abstract`.
- Stałe w adnotacji są niejawnie `public static final`.

#T NOTE Wbudowane adnotacje
- `@Override` — kompilator sprawdza, czy metoda przesłania inną.
- `@FunctionalInterface` — sprawdza warunek interfejsu funkcyjnego.
- `@Deprecated(since = "9", forRemoval = true)` — oznacza przestarzały element; użycie generuje ostrzeżenie.
- `@SuppressWarnings("unchecked")`, `("deprecation")`, `("removal")`, `("rawtypes")`, `("all")`.
- `@SafeVarargs` — tylko na konstruktorach i metodach `static`, `final` lub `private` z parametrem varargs.
- `@Repeatable(Kontener.class)` — pozwala użyć adnotacji wielokrotnie na jednym elemencie.

#T NOTE Logowanie (java.util.logging)
```
Logger log = Logger.getLogger(MojaKlasa.class.getName());
log.info("start");   log.warning("uwaga");   log.log(Level.FINE, "szczegół {0}", x);
```
- Poziomy od najwyższego: `SEVERE`, `WARNING`, `INFO`, `CONFIG`, `FINE`, `FINER`, `FINEST` (oraz `ALL`, `OFF`).
- Domyślnie wypisywane są komunikaty od `INFO` w górę (na `System.err`).
- `isLoggable(level)` pozwala uniknąć kosztownego budowania komunikatu; `log.fine(() -> ...)` przyjmuje `Supplier<String>`.
- `System.Logger` (Java 9) to fasada logowania platformy: `System.getLogger(nazwa)`.

#T NOTE Klasy narzędziowe
- `Arrays`: `sort`, `binarySearch`, `equals` (porównuje zawartość), `compare`, `mismatch`, `fill`, `copyOf`, `copyOfRange`, `asList`, `toString`, `deepToString`.
- `Math`: `max`, `min`, `abs`, `pow` (zwraca `double`), `sqrt`, `round`, `ceil`, `floor`, `random`, `addExact`/`multiplyExact` (rzucają `ArithmeticException` przy przepełnieniu), `floorDiv`, `floorMod`, `clamp` (Java 21).
- `Objects`: `equals`, `hash`, `hashCode`, `requireNonNull`, `requireNonNullElse`, `isNull`, `nonNull`, `toString(o, domyślny)`.
- `BigDecimal`: tworzyć z napisu (`new BigDecimal("0.1")`), `equals` uwzględnia skalę (`2.0` ≠ `2.00`), `compareTo` — nie; dzielenie bez zaokrąglenia może rzucić `ArithmeticException`.

#T PITFALL Pułapki
- `array1 == array2` i `array1.equals(array2)` porównują referencje — do zawartości służy `Arrays.equals`.
- `new BigDecimal(0.1)` przenosi błąd reprezentacji double; `BigDecimal.valueOf(0.1)` — nie.
- `Arrays.binarySearch` na nieposortowanej tablicy daje wynik nieokreślony.
- Adnotacja z `@Retention(SOURCE)` nie jest widoczna przez refleksję.

#T SUMMARY Podsumowanie
Pamiętaj dozwolone typy elementów adnotacji i skrót `value`, znaczenie wbudowanych adnotacji, kolejność poziomów logowania i domyślny próg `INFO` oraz różnicę `equals`/`compareTo` w `BigDecimal` i `==`/`Arrays.equals` dla tablic.

#Q
Q: Gdzie można użyć @SafeVarargs?
+ Na metodzie static, final lub private oraz na konstruktorze z parametrem varargs
- Na każdej metodzie z parametrem varargs
- Tylko na metodach abstrakcyjnych
- Na polach tablicowych
E: Metoda z @SafeVarargs nie może być przesłonięta (więc musi być static, final lub private), bo adnotacja to gwarancja dotycząca konkretnej implementacji.

#EX
P: Jak definiuje się własną adnotację i jakie typy mogą mieć jej elementy?
H: @interface i ograniczenia typów.
S: Adnotację deklaruje się słowem @interface. Elementy to metody bez parametrów, opcjonalnie z wartością domyślną (default). Dozwolone typy elementów to: typy proste, String, Class, enum, inna adnotacja oraz jednowymiarowe tablice tych typów. Wartości muszą być stałymi czasu kompilacji, a null jest niedozwolony.

#EX
P: Kiedy przy użyciu adnotacji można pominąć nazwę elementu?
H: Element value.
S: Gdy adnotacja ma element o nazwie value i podaje się tylko jego, można napisać @Adnotacja("x") zamiast @Adnotacja(value = "x"). Pozostałe elementy muszą mieć wtedy wartości domyślne. Dla elementu tablicowego z jedną wartością można pominąć nawiasy klamrowe.

#EX
P: Do czego służą @Retention i @Target?
H: Jak długo istnieje adnotacja i gdzie można ją umieścić.
S: @Retention określa, czy adnotacja zostaje tylko w źródle (SOURCE), w pliku class (CLASS, domyślnie) czy jest dostępna przez refleksję w czasie działania (RUNTIME). @Target ogranicza miejsca użycia przez ElementType, np. TYPE, METHOD, FIELD, PARAMETER, TYPE_USE. Inne metaadnotacje to @Documented, @Inherited (dziedziczenie przez podklasy) i @Repeatable.

#EX
P: Jakie są wbudowane adnotacje sprawdzane przez kompilator?
H: Override, FunctionalInterface, Deprecated, SuppressWarnings, SafeVarargs.
S: @Override wymusza, by metoda faktycznie nadpisywała metodę nadtypu. @FunctionalInterface wymusza dokładnie jedną metodę abstrakcyjną. @Deprecated oznacza przestarzały element (z since i forRemoval). @SuppressWarnings("unchecked", "deprecation" itd.) wycisza ostrzeżenia. @SafeVarargs można stosować tylko do metod, których nie da się nadpisać (static, final, private) i konstruktorów z parametrem varargs.

#EX
P: Jak działa adnotacja powtarzalna (@Repeatable)?
H: Adnotacja-kontener.
S: Aby użyć tej samej adnotacji kilka razy na jednym elemencie, oznacza się ją @Repeatable(Kontener.class), gdzie Kontener to adnotacja z elementem value będącym tablicą adnotacji powtarzalnej. Kompilator automatycznie opakowuje kilka wystąpień w kontener.

#EX
P: Jakie poziomy logowania ma java.util.logging i jak działa filtrowanie?
H: Od SEVERE do FINEST.
S: Poziomy od najwyższego: SEVERE, WARNING, INFO, CONFIG, FINE, FINER, FINEST, a dodatkowo OFF i ALL. Logger zapisuje komunikat tylko, gdy jego poziom jest nie niższy niż ustawiony poziom loggera i handlera. Domyślnie wypisywane są komunikaty od INFO w górę. Warto stosować wersje z Supplier, np. logger.fine(() -> ...), aby nie budować tekstu, gdy poziom jest wyłączony.

#EX
P: Do czego służą metody klasy Objects?
H: null-safe operacje.
S: Objects.equals(a, b) porównuje bezpiecznie przy null, hash(...) i hashCode(o) liczą skróty, requireNonNull(o, komunikat) rzuca NullPointerException przy null, requireNonNullElse(o, domyślna) zwraca wartość zastępczą, isNull/nonNull nadają się jako predykaty, a toString(o, domyślny) bezpiecznie zamienia na tekst. checkIndex(i, n) sprawdza zakres indeksu.

#EX
P: Jakie są pułapki metod Math.round, Math.floor i dzielenia całkowitego?
H: Typy wyników i liczby ujemne.
S: Math.round(double) zwraca long, a round(float) — int; zaokrągla w górę przy połówkach, więc round(-2.5) daje -2. floor i ceil zwracają double. Dzielenie całkowite obcina w stronę zera (-7 / 2 = -3), a reszta ma znak dzielnej (-7 % 2 = -1). Math.floorDiv i floorMod zaokrąglają w dół. Math.abs(Integer.MIN_VALUE) zwraca wartość ujemną z powodu przepełnienia.
