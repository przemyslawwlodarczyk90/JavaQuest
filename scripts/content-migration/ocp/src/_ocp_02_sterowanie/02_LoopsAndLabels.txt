#T INTRO Pętle, etykiety, break i continue — ściąga egzaminacyjna
Pytania o pętle sprawdzają głównie umiejętność dokładnego liczenia iteracji, rozpoznawania pętli nieskończonych i nieosiągalnego kodu oraz działania `break`/`continue` z etykietami w pętlach zagnieżdżonych.

#T DEFINITION Cztery rodzaje pętli
```
while (warunek) { ... }              // może nie wykonać się ani razu
do { ... } while (warunek);          // wykonuje się co najmniej raz; średnik!
for (init; warunek; update) { ... }  // każda część opcjonalna: for(;;) to pętla nieskończona
for (Typ e : tablicaLubIterable) { } // rozszerzony for
```
- W sekcji `init` pętli for można zadeklarować kilka zmiennych **tego samego typu**: `for (int i = 0, j = 10; ...)`.
- W sekcji `update` można wpisać kilka wyrażeń po przecinku: `i++, j--`.
- Rozszerzony for działa na tablicach i obiektach `Iterable` (nie na `Map` ani na `Iterator`).

#T NOTE break, continue i etykiety
- `break` kończy najbliższą pętlę lub `switch`, `continue` przechodzi do następnej iteracji najbliższej pętli.
- Etykieta (`outer:`) przed pętlą pozwala napisać `break outer;` lub `continue outer;` i dotyczy wskazanej pętli.
- `break etykieta` działa też na zwykłym bloku z etykietą, `continue` — tylko na pętli.

#T NOTE Nieosiągalny kod i pętle nieskończone
- `while (true) { }` bez `break` czyni kod po pętli nieosiągalnym — błąd kompilacji, jeśli coś po niej stoi.
- `while (false) { ... }` się nie kompiluje (ciało nieosiągalne), w przeciwieństwie do `if (false)`.
- Instrukcja zaraz po `break`, `continue`, `return` lub `throw` w tym samym bloku jest nieosiągalna.
- Kompilator rozpoznaje stałe warunki: `final boolean T = true; while (T) {}` jest dla niego pętlą nieskończoną.

#T PITFALL Pułapki
- Zmiana kolekcji w trakcie rozszerzonego for (`list.remove`) zwykle rzuca `ConcurrentModificationException`.
- Zmienna pętli for zadeklarowana w nagłówku nie istnieje po pętli.
- Przypisanie do zmiennej rozszerzonego for nie zmienia elementu tablicy.
- `do { } while (x < 5)` bez średnika na końcu to błąd kompilacji.

#T SUMMARY Podsumowanie
Licz iteracje na kartce, sprawdzaj warunek przed (`while`, `for`) lub po (`do-while`) każdej iteracji, a przy etykietach ustal, do której pętli odnosi się `break` lub `continue`.
