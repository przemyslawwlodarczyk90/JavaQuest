#T INTRO if, switch i yield — ściąga egzaminacyjna
Instrukcje warunkowe wydają się proste, ale egzamin sprawdza tu precyzyjne reguły: kiedy `switch` przechodzi do kolejnego przypadku, co może być etykietą `case`, kiedy wyrażenie `switch` musi być wyczerpujące i kiedy trzeba użyć `yield`.

#T DEFINITION Dwie formy switch
```
// instrukcja z dwukropkiem - przechodzenie (fall-through) bez break
switch (x) {
    case 1:
    case 2: System.out.print("1-2");
    case 3: System.out.print("3"); break;
    default: System.out.print("inne");
}

// strzałka - brak przechodzenia, po prawej wyrażenie, blok albo throw
switch (x) {
    case 1, 2 -> System.out.print("1-2");
    case 3 -> { System.out.print("3"); }
    default -> throw new IllegalStateException();
}
```
W jednym `switch` nie wolno mieszać `:` i `->`.

#T NOTE Wyrażenie switch
- Zwraca wartość: `int n = switch (s) { case "a" -> 1; default -> 0; };` — zwróć uwagę na średnik na końcu.
- Musi być **wyczerpujące**: dla `int`/`String` potrzebny jest `default`; dla `enum` wystarczy obsłużyć wszystkie stałe (kompilator dopisuje ukryty `default` rzucający `MatchException`).
- Gdy po strzałce jest blok, wartość podaje się przez `yield wartość;`. W wersji z dwukropkiem każda ścieżka też kończy się `yield`.
- W wyrażeniu switch nie wolno użyć `return` ani `break` wychodzącego z wyrażenia.

#T NOTE Co może być selektorem i etykietą
- Selektor: `char`, `byte`, `short`, `int`, ich klasy opakowujące, `String`, `enum` oraz (z wzorcami w Javie 21) dowolny typ referencyjny. **Nie**: `long`, `float`, `double`, `boolean`.
- Etykieta `case` musi być **stałą czasu kompilacji** zgodną z typem selektora: literał, zmienna `final` zainicjalizowana stałą, stała enum. Zmienna `final` inicjalizowana wywołaniem metody nie jest stałą.
- Etykiety nie mogą się powtarzać.
- Selektor `null` (dla typu referencyjnego) rzuca `NullPointerException`, chyba że istnieje `case null`.

#T PITFALL Pułapki
- `default` nie musi być na końcu — przy przechodzeniu wykonanie idzie dalej od miejsca dopasowania.
- `if (x > 0) if (x > 5) A; else B;` — `else` należy do najbliższego `if`.
- Instrukcja po `return`/`throw`/`break` w tym samym bloku jest nieosiągalna (błąd kompilacji).
- W `switch` z dwukropkiem zmienna zadeklarowana w jednym `case` jest widoczna w następnych, ale może nie być zainicjalizowana.

#T SUMMARY Podsumowanie
Sprawdź, czy selektor ma dozwolony typ, czy etykiety są stałymi, czy wyrażenie switch jest wyczerpujące i czy bloki kończą się `yield`. W formie z dwukropkiem licz przechodzenie do kolejnych przypadków aż do `break`.

#EX
P: Czym różni się switch z dwukropkiem od switch ze strzałką?
H: Przechodzenie do kolejnych przypadków, wiele etykiet, bloki.
S: W switch z dwukropkiem (case X:) po dopasowaniu wykonanie przechodzi przez kolejne przypadki, dopóki nie trafi na break (fall-through). W switch ze strzałką (case X ->) wykonuje się tylko dopasowana gałąź — bez przechodzenia i bez break. Obu stylów nie wolno mieszać w jednym switch. Oba pozwalają podać kilka etykiet po przecinku.

#EX
P: Kiedy switch jest wyrażeniem i jakie ma wtedy wymagania?
H: Zwracana wartość, kompletność, yield.
S: switch jest wyrażeniem, gdy jego wynik jest użyty, np. przypisany do zmiennej. Musi być wtedy wyczerpujący — obejmować wszystkie możliwe wartości (dla enumów i typów sealed wszystkie stałe lub podtypy, w innych przypadkach default). Gałąź strzałkowa z blokiem zwraca wartość przez yield, a w switch z dwukropkiem używanym jako wyrażenie wartość również zwraca się przez yield.

#EX
P: Czym jest yield i czym różni się od return?
H: W jakim kontekście działa?
S: yield zwraca wartość z bloku gałęzi wyrażenia switch i kończy tylko to wyrażenie, a nie metodę. return w środku wyrażenia switch jest niedozwolony. yield to kontekstowe słowo kluczowe — można mieć zmienną o nazwie yield, ale nie można wywołać metody yield bez kwalifikacji.

#EX
P: Jakie typy mogą być przedmiotem switch?
H: Typy proste, opakowujące, String, enum, od Javy 21 dowolne referencje.
S: Tradycyjnie: char, byte, short, int, ich klasy opakowujące, String i enum. Nie long, float, double ani boolean. Od Javy 21 switch obsługuje wzorce typów, więc może dostać dowolny typ referencyjny (np. Object) z przypadkami case String s ->. Etykiety stałe muszą być stałymi czasu kompilacji.

#EX
P: Co się dzieje, gdy switch dostanie null?
H: Zachowanie tradycyjne i z case null.
S: Tradycyjnie switch na null rzuca NullPointerException. Od Javy 21 można dodać jawną etykietę case null (także case null, default ->), która obsłuży tę wartość. Bez niej zachowanie pozostaje takie samo — wyjątek.

#EX
P: Jakie są pułapki instrukcji if-else w pytaniach egzaminacyjnych?
H: Nawiasy klamrowe, przypisanie zamiast porównania, wiszący else.
S: Bez nawiasów klamrowych do if należy tylko jedna instrukcja, a wcięcie nic nie znaczy. else łączy się z najbliższym if bez else. if (x = 5) się nie kompiluje dla int, ale if (flag = true) dla boolean się kompiluje i zawsze jest prawdziwe. Warunek musi mieć typ boolean — nie da się użyć liczby jak w C.

#EX
P: Czym jest kod nieosiągalny i dlaczego kompilator go zgłasza?
H: Instrukcje po return, break, throw.
S: Kod, który według reguł kompilatora nigdy nie może się wykonać, np. instrukcja po return, break, continue albo throw w tym samym bloku, albo kod po pętli while(true) bez break. Taki kod to błąd kompilacji, a nie ostrzeżenie. Wyjątkiem jest if (false) { ... } — świadomie dozwolony dla kompilacji warunkowej.

#EX
P: Czym jest dominacja etykiet w switch z wzorcami?
H: Kolejność przypadków ogólniejszych i bardziej szczegółowych.
S: Przypadek z typem ogólniejszym nie może poprzedzać przypadku z typem szczegółowszym, np. case CharSequence cs przed case String s — drugi byłby nieosiągalny, więc kompilator zgłasza błąd. Wzorzec ze strażnikiem (when) nie dominuje nad wzorcem bez strażnika tego samego typu. default musi być na końcu względem wzorców.
