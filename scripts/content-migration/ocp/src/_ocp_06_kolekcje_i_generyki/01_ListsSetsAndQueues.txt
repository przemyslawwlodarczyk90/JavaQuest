#T INTRO Listy, zbiory, kolejki i sortowanie — ściąga egzaminacyjna
Pytania o kolekcje sprawdzają znajomość dokładnego zachowania metod: które zwracają wartość specjalną, a które rzucają wyjątek, które kolekcje są niemodyfikowalne, w jakiej kolejności elementy wychodzą z `TreeSet` czy `PriorityQueue` oraz jak działają komparatory.

#T DEFINITION Tworzenie list i ich modyfikowalność
```
                       add/remove   set    null
new ArrayList<>(...)   tak          tak    tak
Arrays.asList(...)     NIE (UOE)    tak    tak     - widok na tablicę!
List.of(...)           NIE (UOE)    NIE    NIE (NPE już przy tworzeniu)
List.copyOf(coll)      NIE (UOE)    NIE    NIE
Collections.unmodifiableList(l)  NIE  NIE  tak     - widok, zmiany oryginału widoczne
```
UOE = `UnsupportedOperationException`. `Arrays.asList` jest powiązana z tablicą: `set` zmienia tablicę, zmiana tablicy widać w liście.

#T NOTE List i ArrayList
- `remove(int index)` kontra `remove(Object o)` — dla `List<Integer>` wywołanie `remove(1)` usuwa element o **indeksie** 1.
- `add(index, e)`, `set(index, e)` (zwraca starą wartość), `indexOf`, `contains`, `subList(od, do)` (widok).
- `replaceAll(UnaryOperator)`, `removeIf(Predicate)`, `forEach`.
- `equals` list porównuje elementy w kolejności, niezależnie od implementacji.

#T NOTE Set
- `HashSet` — brak gwarancji kolejności; `LinkedHashSet` — kolejność wstawiania; `TreeSet` — porządek naturalny lub komparatora (bez `null`).
- `add` zwraca `false`, gdy element już jest.
- `TreeSet` (`NavigableSet`): `first`, `last`, `floor(e)` ≤, `ceiling(e)` ≥, `lower(e)` <, `higher(e)` >, `headSet(e)` < (wyłącznie), `tailSet(e)` ≥ (włącznie), `pollFirst`, `descendingSet`.
- `TreeSet` uznaje elementy za równe, gdy `compareTo`/komparator zwraca 0 — nawet jeśli `equals` mówi inaczej.

#T NOTE Queue i Deque
```
                   rzuca wyjątek   zwraca wartość specjalną
dodanie            add(e)          offer(e)       -> false
usunięcie głowy    remove()        poll()         -> null
podgląd głowy      element()       peek()         -> null
```
- `Deque` (np. `ArrayDeque`) jako stos: `push` = `addFirst`, `pop` = `removeFirst`, `peek` = `peekFirst`.
- `ArrayDeque` nie przyjmuje `null`.
- `PriorityQueue` zwraca elementy w porządku priorytetu (najmniejszy pierwszy), ale `toString`/iteracja **nie** są posortowane.

#T PITFALL Pułapki
- `Collections.sort` i `List.sort` zmieniają listę; na `List.of` rzucą `UnsupportedOperationException`.
- `Collections.binarySearch` na nieposortowanej liście daje wynik nieokreślony; gdy brak elementu, zwraca `-(punkt wstawienia) - 1`.
- Porządek naturalny `String`: cyfry < wielkie litery < małe litery.
- Usuwanie w pętli for-each rzuca `ConcurrentModificationException` — używaj `removeIf` albo `Iterator.remove`.

#T SUMMARY Podsumowanie
Pamiętaj tabelę modyfikowalności, różnicę między metodami rzucającymi wyjątek a zwracającymi `null`/`false`, kolejność elementów w każdej implementacji `Set` i `Queue` oraz semantykę metod nawigacji `TreeSet`.
