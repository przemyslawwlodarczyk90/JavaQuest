#T INTRO Typy generyczne i wieloznaczniki — ściąga egzaminacyjna
Generyki to obszar, w którym kompilator jest bardzo restrykcyjny, a odpowiedzią na pytanie egzaminacyjne często jest „błąd kompilacji”. Trzeba wiedzieć, co wolno przypisać do czego, co można dodać do listy z wieloznacznikiem i czego zabrania wymazywanie typów (type erasure).

#T DEFINITION Niezmienniczość i wieloznaczniki
```
List<Object> lo = new ArrayList<String>();          // BŁĄD - generyki są niezmiennicze
List<? extends Number> ln = new ArrayList<Integer>(); // OK - górne ograniczenie
List<? super Integer> ls = new ArrayList<Number>();   // OK - dolne ograniczenie
List<?> lq = new ArrayList<String>();                 // OK - nieograniczony
```
- `List<? extends T>` — można **czytać** jako `T`, nie można **dodawać** (poza `null`).
- `List<? super T>` — można **dodawać** `T` i jego podtypy, odczyt daje `Object`.
- `List<?>` — odczyt jako `Object`, dodawać można tylko `null`.
- Zasada PECS: Producer Extends, Consumer Super.

#T NOTE Metody i klasy generyczne
- Klasa: `class Box<T> { T value; }`; metoda: `<T> T first(List<T> list)` — parametr typu deklarowany **przed** typem zwracanym.
- Ograniczenia: `<T extends Number>`, wiele ograniczeń: `<T extends Number & Comparable<T>>` (klasa pierwsza, potem interfejsy).
- Wieloznacznika `?` nie używa się w deklaracji parametru typu (`class Box<?>` — błąd).
- Jawne argumenty typu: `Util.<String>first(list)`.
- Diamond `<>` wnioskuje typ z lewej strony; z `var` daje `Object`.

#T NOTE Ograniczenia wynikające z wymazywania typów
Po kompilacji `List<String>` i `List<Integer>` to ten sam typ `List`. Dlatego **nie wolno**:
- `new T()`, `new T[10]`, `T.class`,
- `obj instanceof List<String>` (dozwolone `List<?>`),
- pola statycznego typu `T` ani użycia `T` w metodzie statycznej klasy,
- przeciążyć metod różniących się tylko parametrem typu: `m(List<String>)` i `m(List<Integer>)`,
- tworzyć tablic typów sparametryzowanych: `new List<String>[3]`,
- używać typów prostych jako argumentów: `List<int>`.

#T PITFALL Pułapki
- Typy surowe (raw types) kompilują się z ostrzeżeniem i mogą prowadzić do `ClassCastException` w miejscu odczytu.
- `List<Number>` nie przyjmie `List<Integer>` jako argumentu, ale `List<? extends Number>` — tak.
- Parametr typu metody może przesłonić parametr typu klasy o tej samej nazwie.
- `Comparable<T>` jest generyczny — `class A implements Comparable` (surowy) wymaga `compareTo(Object)`.

#T SUMMARY Podsumowanie
Generyki są niezmiennicze; elastyczność dają wieloznaczniki `? extends` (odczyt) i `? super` (zapis). Wymazywanie typów zabrania tworzenia obiektów i tablic typu `T`, sprawdzania `instanceof` z konkretnym argumentem typu i przeciążeń różniących się tylko argumentem typu.

#EX
P: Czym różnią się wildcardy ?, ? extends T i ? super T?
H: Co można czytać, a co wstawiać?
S: List<?> to lista nieznanego typu — można z niej czytać jako Object, a wstawiać tylko null. List<? extends Number> przyjmuje listy Number lub jego podtypów — można czytać jako Number, ale nie można wstawiać (poza null). List<? super Integer> przyjmuje listy Integer lub jego nadtypów — można wstawiać Integer, a czytać tylko jako Object.

#EX
P: Czego nie można zrobić z parametrem typu T z powodu wymazywania typów?
H: Tworzenie obiektów, tablic, instanceof, pola statyczne.
S: Nie można wywołać new T(), utworzyć tablicy new T[], sprawdzić instanceof T ani instanceof List<String>, zadeklarować pola statycznego typu T ani przeciążyć metod różniących się tylko argumentem typu generycznego (np. List<String> i List<Integer>). Typy proste nie mogą być argumentami typów.

#EX
P: Czym jest ograniczony parametr typu, np. <T extends Comparable<T>>?
H: Jakie metody można wtedy wywołać na T?
S: Ograniczenie mówi, że T musi być podtypem wskazanego typu, więc w ciele metody można wywoływać metody tego typu, np. compareTo. Ograniczeń może być kilka: <T extends Number & Comparable<T>> — klasa musi być wymieniona jako pierwsza. W parametrach typów używa się tylko extends, nigdy super.

#EX
P: Dlaczego nie można przypisać List<String> do List<Object>?
H: Niezmienniczość generyków.
S: Gdyby było to możliwe, przez referencję List<Object> można by wstawić Integer do listy, która miała zawierać tylko napisy. Dlatego generyki są niezmiennicze. Do elastycznego przyjmowania list różnych typów służą wildcardy, np. List<? extends Object> lub List<?>.

#EX
P: Jak działa operator diamentowy <> i gdzie nie można go użyć?
H: Wnioskowanie typu, klasy anonimowe.
S: new ArrayList<>() pozwala kompilatorowi wywnioskować argument typu z kontekstu przypisania. Od Javy 9 diament działa też z klasami anonimowymi, jeśli wywnioskowany typ jest możliwy do zapisania. Połączenie var z diamentem (var list = new ArrayList<>()) daje ArrayList<Object>.

#EX
P: Czym jest generyczna metoda i jak jawnie podać jej argument typu?
H: Deklaracja przed typem zwracanym.
S: Parametry typu metody deklaruje się przed typem zwracanym: static <T> List<T> powiel(T x, int n). Kompilator zwykle wnioskuje T z argumentów. Jawnie podaje się go przed nazwą metody, z kwalifikacją: Klasa.<String>powiel("a", 3) albo this.<String>metoda().

#EX
P: Czym jest „heap pollution” i kiedy kompilator ostrzega o niebezpiecznych operacjach?
H: Typy surowe, varargs z generykami.
S: Heap pollution to sytuacja, w której zmienna typu sparametryzowanego wskazuje obiekt innego typu, np. po przypisaniu przez typ surowy. Skutkiem jest ClassCastException w nieoczekiwanym miejscu. Kompilator ostrzega (unchecked) przy użyciu typów surowych i varargs z typami generycznymi; @SafeVarargs wycisza ostrzeżenie, gdy metoda jest bezpieczna.

#EX
P: Jak wybrać między extends a super przy projektowaniu parametru metody?
H: PECS.
S: Jeśli metoda tylko czyta elementy z kolekcji (kolekcja jest producentem), używamy ? extends T. Jeśli metoda tylko wstawia elementy (kolekcja jest konsumentem), używamy ? super T. Jeśli robi oba — konkretnego T bez wildcardu. Przykład z JDK: Collections.copy(List<? super T> dest, List<? extends T> src).
