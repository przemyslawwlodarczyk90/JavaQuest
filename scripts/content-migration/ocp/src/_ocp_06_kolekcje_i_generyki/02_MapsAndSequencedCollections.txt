#T INTRO Mapy i kolekcje uporządkowane (Sequenced Collections) — ściąga egzaminacyjna
Mapa nie jest kolekcją (`Map` nie rozszerza `Collection`), ale egzamin traktuje ją na równi z listami. Pytania dotyczą wartości zwracanych przez `put`, `merge`, `compute…`, kolejności kluczy w różnych implementacjach oraz nowych interfejsów Javy 21: `SequencedCollection` i `SequencedMap`.

#T DEFINITION Najważniejsze metody Map
Te metody i ich wartości zwracane pojawiają się w pytaniach najczęściej:
```
put(k, v)              zwraca POPRZEDNIĄ wartość albo null
get(k)                 wartość albo null
getOrDefault(k, d)     wartość albo d
putIfAbsent(k, v)      wstawia tylko, gdy brak klucza (lub wartość null); zwraca obecną wartość
remove(k)              zwraca usuniętą wartość
containsKey / containsValue
computeIfAbsent(k, f)  oblicza i wstawia, gdy brak; f zwracające null -> nic nie wstawia
computeIfPresent(k, f) przelicza istniejącą; null -> USUWA klucz
compute(k, f)          zawsze; null -> usuwa
merge(k, v, f)         brak klucza -> wstawia v; jest -> f(stara, v); null -> usuwa
replaceAll((k, v) -> nowa)
keySet() values() entrySet()   widoki - usunięcie z widoku usuwa z mapy
```

#T NOTE Implementacje
- `HashMap` — brak gwarancji kolejności, dopuszcza jeden klucz `null` i wartości `null`.
- `LinkedHashMap` — kolejność wstawiania (opcjonalnie kolejność dostępu).
- `TreeMap` — klucze posortowane, klucz `null` niedozwolony; metody nawigacji: `firstKey`, `floorKey`, `ceilingKey`, `headMap(k)` (wyłącznie), `tailMap(k)` (włącznie), `firstEntry`, `pollFirstEntry`, `descendingMap`.
- `Map.of(k1, v1, ...)` — do 10 par, niemodyfikowalna, bez `null`, duplikat klucza → `IllegalArgumentException`. `Map.ofEntries(Map.entry(k, v), ...)` — dowolna liczba par.

#T NOTE Sequenced Collections (Java 21)
Nowe interfejsy dla kolekcji o określonej kolejności:
```
SequencedCollection:  addFirst, addLast, getFirst, getLast, removeFirst, removeLast, reversed()
SequencedSet:         jak wyżej, reversed() zwraca SequencedSet
SequencedMap:         firstEntry, lastEntry, pollFirstEntry, pollLastEntry,
                      putFirst, putLast, reversed(), sequencedKeySet(), sequencedValues(), sequencedEntrySet()
```
- Implementują je m.in. `List`, `Deque`, `LinkedHashSet`, `SortedSet`/`TreeSet` (SequencedSet), `LinkedHashMap`, `SortedMap`/`TreeMap` (SequencedMap).
- `HashSet` i `HashMap` ich **nie** implementują.
- `reversed()` zwraca **widok** — zmiany są widoczne w obie strony.
- `getFirst()` na pustej liście rzuca `NoSuchElementException`.
- Kolekcje sortowane (`TreeSet`, `TreeMap`) rzucają `UnsupportedOperationException` przy `addFirst`/`addLast`/`putFirst`, bo kolejność wynika z porządku.
- `LinkedHashSet.addFirst(e)` dla istniejącego elementu przenosi go na początek; podobnie `LinkedHashMap.putFirst`.

#T PITFALL Pułapki
- `put` zwraca starą wartość, a nie nową.
- `merge` i `compute…` z funkcją zwracającą `null` usuwają wpis.
- `Map.of` nie gwarantuje kolejności iteracji.
- Iterowanie po `entrySet()` i jednoczesne `map.remove` rzuca `ConcurrentModificationException`; używaj `iterator.remove()` albo `entrySet().removeIf(...)`.

#T SUMMARY Podsumowanie
Zapamiętaj wartości zwracane przez metody mapy, zachowanie z wartością `null` w `merge`/`compute`, kolejność kluczy w HashMap/LinkedHashMap/TreeMap oraz metody Sequenced Collections — zwłaszcza `reversed()` jako widok i wyjątki dla kolekcji sortowanych.
