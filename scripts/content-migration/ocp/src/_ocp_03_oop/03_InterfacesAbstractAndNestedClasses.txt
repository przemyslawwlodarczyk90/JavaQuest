#T INTRO Interfejsy, klasy abstrakcyjne i klasy zagnieżdżone — ściąga egzaminacyjna
Interfejsy w nowoczesnej Javie mają metody abstrakcyjne, domyślne, statyczne i prywatne — każdy rodzaj z innymi regułami. Do tego dochodzą cztery rodzaje klas zagnieżdżonych, z których każdy inaczej widzi klasę otaczającą. Egzamin pyta o to, co się kompiluje i która metoda zostanie wywołana.

#T DEFINITION Składowe interfejsu
```
interface Shape {
    double PI = 3.14;              // zawsze public static final
    double area();                 // public abstract
    default String name() { ... }  // public, ma ciało, dziedziczona
    static Shape unit() { ... }    // public static, NIE dziedziczona - wywołanie Shape.unit()
    private int helper() { ... }   // prywatna, dla metod default/private
    private static int h2() { ... }// prywatna statyczna
}
```
- Metody bez modyfikatora są niejawnie `public abstract`. Nie mogą być `protected` ani `final`.
- Pola interfejsu muszą mieć wartość i nie mogą być zmienione.
- Metoda statyczna interfejsu jest wywoływana **tylko przez nazwę interfejsu**, nie przez obiekt ani klasę implementującą.

#T NOTE Konflikty metod default
1. **Klasa wygrywa**: metoda z nadklasy (także odziedziczona) ma pierwszeństwo przed metodą default interfejsu.
2. **Bardziej specyficzny interfejs wygrywa**: jeśli `B extends A` i oba mają `default m()`, wygrywa `B`.
3. Jeśli dwa niezwiązane interfejsy dają `default m()` o tej samej sygnaturze, klasa **musi** przesłonić `m()`; może wywołać wybraną wersję przez `A.super.m()`.

#T NOTE Cztery rodzaje klas zagnieżdżonych
- **Statyczna zagnieżdżona** (`static class`): nie ma referencji do obiektu zewnętrznego; tworzona przez `new Outer.Nested()`.
- **Wewnętrzna** (inner): związana z obiektem zewnętrznym; tworzona przez `outer.new Inner()`. Do pola zewnętrznego przesłoniętego nazwą: `Outer.this.x`. Od Javy 16 może mieć składowe statyczne.
- **Lokalna**: zadeklarowana w metodzie; widzi zmienne lokalne tylko efektywnie finalne; nie może mieć modyfikatora dostępu.
- **Anonimowa**: bez nazwy, rozszerza jedną klasę albo implementuje jeden interfejs; nie ma konstruktora (może mieć blok instancyjny).

#T NOTE Klasa abstrakcyjna a interfejs
- Klasa abstrakcyjna może mieć stan (pola instancyjne), konstruktory i metody o dowolnym dostępie; klasa może rozszerzać tylko jedną klasę.
- Interfejs nie ma stanu instancji ani konstruktorów; klasa może implementować wiele interfejsów, a interfejs może rozszerzać wiele interfejsów (`extends A, B`).
- Interfejs funkcyjny ma **dokładnie jedną** metodę abstrakcyjną (metody z `Object`, jak `equals`, się nie liczą).

#T PITFALL Pułapki
- Implementacja metody interfejsu musi być `public`.
- `default` nie może przesłonić metod `equals`, `hashCode`, `toString`.
- Interfejs nie może mieć metody `default` i `static` o tej samej sygnaturze.
- Klasa abstrakcyjna implementująca interfejs nie musi implementować jego metod.

#T SUMMARY Podsumowanie
Pamiętaj o domyślnych modyfikatorach składowych interfejsu, o kolejności rozstrzygania konfliktów (klasa, potem bardziej specyficzny interfejs, inaczej obowiązkowe przesłonięcie) i o tym, jak tworzy się obiekty klas zagnieżdżonych.

#EX
P: Jakie rodzaje metod może mieć interfejs w Javie 21?
H: abstrakcyjne, default, static, private.
S: Metody abstrakcyjne (niejawnie public abstract), metody default z ciałem (dziedziczone przez implementacje), metody static (wywoływane tylko przez nazwę interfejsu, niedziedziczone) oraz metody private i private static (pomocnicze dla metod default i static). Pola interfejsu są zawsze public static final.

#EX
P: Jak rozwiązać konflikt dwóch metod default o tej samej sygnaturze z dwóch interfejsów?
H: Obowiązkowe przesłonięcie i składnia wywołania konkretnej wersji.
S: Klasa implementująca oba interfejsy musi przesłonić tę metodę, inaczej kompilacja się nie powiedzie. W przesłonięciu może wywołać wybraną wersję składnią NazwaInterfejsu.super.metoda(). Reguła ogólna: metoda z klasy wygrywa z default z interfejsu, a bardziej szczegółowy interfejs wygrywa z ogólniejszym.

#EX
P: Jakie są rodzaje klas zagnieżdżonych w Javie?
H: Statyczne, wewnętrzne, lokalne, anonimowe.
S: Statyczna klasa zagnieżdżona nie ma powiązania z instancją klasy zewnętrznej. Klasa wewnętrzna (niestatyczna) ma niejawną referencję do obiektu zewnętrznego i tworzy się ją przez zewnetrzny.new Wewnetrzna(). Klasa lokalna jest zadeklarowana w metodzie. Klasa anonimowa to jednorazowa implementacja lub podklasa utworzona w wyrażeniu new.

#EX
P: Do jakich zmiennych mają dostęp klasy lokalne, anonimowe i lambdy?
H: effectively final.
S: Mogą czytać zmienne lokalne i parametry otaczającej metody tylko wtedy, gdy są one final lub effectively final (nigdy nie zmieniane po przypisaniu). Mają też dostęp do pól klasy zewnętrznej (klasy wewnętrzne i lokalne w kontekście instancji — także do pól instancyjnych), które mogą modyfikować.

#EX
P: Czym różni się interfejs od klasy abstrakcyjnej?
H: Stan, konstruktory, wielokrotna implementacja.
S: Interfejs nie ma pól instancji ani konstruktorów, a klasa może implementować wiele interfejsów. Klasa abstrakcyjna może mieć stan, konstruktory i metody o dowolnym dostępie, ale klasa może rozszerzać tylko jedną. Interfejs opisuje zdolność („co potrafi”), klasa abstrakcyjna — wspólną bazę implementacji rodziny klas.

#EX
P: Jak tworzy się instancję klasy wewnętrznej z zewnątrz klasy otaczającej?
H: Potrzebny jest obiekt klasy zewnętrznej.
S: Najpierw trzeba mieć obiekt klasy zewnętrznej: Outer o = new Outer(); Outer.Inner i = o.new Inner();. Dla statycznej klasy zagnieżdżonej obiekt zewnętrzny nie jest potrzebny: new Outer.Nested(). Wewnątrz klasy wewnętrznej do obiektu zewnętrznego odwołuje się przez Outer.this.

#EX
P: Czym jest interfejs funkcyjny i jak jego definicja ma się do metod z Object?
H: Jedna metoda abstrakcyjna — co się nie liczy?
S: Interfejs funkcyjny ma dokładnie jedną metodę abstrakcyjną. Nie liczą się metody default, static i private, ani metody abstrakcyjne o sygnaturze publicznej metody z Object (np. equals, toString) — dlatego Comparator z deklaracją equals jest nadal funkcyjny. Adnotacja @FunctionalInterface pozwala kompilatorowi to zweryfikować.

#EX
P: Jakie modyfikatory są niejawne w interfejsach?
H: Metody bez ciała, pola, typy zagnieżdżone.
S: Metody bez ciała są public abstract, metody bez modyfikatora dostępu są public, pola są public static final (więc muszą być zainicjalizowane), a typy zagnieżdżone są public static. Próba zadeklarowania pola bez wartości albo metody protected to błąd kompilacji.
