#T INTRO Interfejsy funkcyjne, lambdy i referencje do metod — ściąga egzaminacyjna
Egzamin wymaga znajomości na pamięć wbudowanych interfejsów funkcyjnych z `java.util.function` (nazwa metody, liczba parametrów, typ zwracany), poprawnej składni lambd oraz czterech rodzajów referencji do metod.

#T DEFINITION Najważniejsze interfejsy funkcyjne
```
Interfejs              metoda          parametry -> wynik
Supplier<T>            get()           ()     -> T
Consumer<T>            accept(t)       T      -> void
BiConsumer<T,U>        accept(t,u)     T,U    -> void
Predicate<T>           test(t)         T      -> boolean
BiPredicate<T,U>       test(t,u)       T,U    -> boolean
Function<T,R>          apply(t)        T      -> R
BiFunction<T,U,R>      apply(t,u)      T,U    -> R
UnaryOperator<T>       apply(t)        T      -> T     (rozszerza Function<T,T>)
BinaryOperator<T>      apply(t,u)      T,T    -> T     (rozszerza BiFunction<T,T,T>)
Runnable               run()           ()     -> void
Callable<V>            call()          ()     -> V, throws Exception
Comparator<T>          compare(a,b)    T,T    -> int
```
Wersje dla typów prostych: `IntPredicate`, `IntFunction<R>`, `ToIntFunction<T>`, `IntUnaryOperator`, `IntBinaryOperator`, `IntSupplier` (`getAsInt`), `BooleanSupplier` (`getAsBoolean`), `ObjIntConsumer<T>` i analogicznie dla `long` i `double`.

#T NOTE Składnia lambd
```
() -> 42
x -> x * 2                 // jeden parametr bez typu: nawiasy opcjonalne
(x, y) -> x + y
(int x, int y) -> x + y    // wszystkie z typem albo żaden
(var x, var y) -> x + y    // var dla wszystkich albo dla żadnego
x -> { return x * 2; }     // blok wymaga return (gdy jest wynik) i średników
```
- Nazwa parametru lambdy nie może kolidować ze zmienną lokalną w zasięgu.
- Zmienne lokalne używane w lambdzie muszą być **efektywnie finalne** (pola — nie).
- `this` w lambdzie oznacza obiekt klasy otaczającej.

#T NOTE Referencje do metod
```
Klasa::metodaStatyczna          Math::abs            x -> Math.abs(x)
obiekt::metodaInstancyjna       System.out::println  x -> System.out.println(x)
Klasa::metodaInstancyjna        String::length       s -> s.length()
                                String::compareTo    (a, b) -> a.compareTo(b)
Klasa::new                      ArrayList::new       () -> new ArrayList<>()
```
W trzecim rodzaju pierwszy parametr lambdy staje się obiektem, na którym wywoływana jest metoda.

#T NOTE Metody domyślne interfejsów funkcyjnych
- `Predicate`: `and`, `or`, `negate`, statyczne `not`, `isEqual`.
- `Function`: `andThen` (najpierw ta, potem argument), `compose` (najpierw argument, potem ta), statyczne `identity`.
- `Consumer`: `andThen`. `BinaryOperator`: `minBy`, `maxBy`.
- `Comparator`: `reversed`, `thenComparing`, statyczne `comparing`, `comparingInt`, `naturalOrder`, `reverseOrder`, `nullsFirst`.

#T PITFALL Pułapki
- `x -> { x * 2 }` się nie kompiluje — w bloku potrzebne jest `return` i średnik.
- Lambda bez typu docelowego (`var f = x -> x;`) się nie kompiluje.
- `Supplier` ma metodę `get`, a nie `apply`; `Consumer` — `accept`; `Predicate` — `test`.
- `f.andThen(g)` i `f.compose(g)` dają różne wyniki — kolejność ma znaczenie.

#T SUMMARY Podsumowanie
Zapamiętaj tabelę interfejsów (nazwy metod!), reguły nawiasów i typów w parametrach lambd, wymóg efektywnej finalności oraz cztery formy referencji do metod.

#Q
Q: Który interfejs funkcyjny ma metodę o sygnaturze T get()?
+ Supplier<T>
- Consumer<T>
- Function<T, R>
- Callable<T>
E: Supplier<T>.get() nie przyjmuje argumentów i zwraca T. Callable ma metodę call(), która może rzucić wyjątek.

#EX
P: Jakie są podstawowe interfejsy funkcyjne z java.util.function i ich metody?
H: Supplier, Consumer, Function, Predicate, UnaryOperator, BinaryOperator.
S: Supplier<T> — T get(), bez argumentów. Consumer<T> — void accept(T). Function<T, R> — R apply(T). Predicate<T> — boolean test(T). UnaryOperator<T> — Function<T, T>. BinaryOperator<T> — BiFunction<T, T, T>. Istnieją też wersje dwuargumentowe (BiConsumer, BiFunction, BiPredicate) i wyspecjalizowane dla typów prostych, np. IntPredicate, ToIntFunction.

#EX
P: Jakie są reguły składni lambdy?
H: Nawiasy, typy parametrów, klamry i return.
S: Jeden parametr bez typu można zapisać bez nawiasów: x -> x * 2. Przy zero lub wielu parametrach nawiasy są obowiązkowe. Typy parametrów podaje się wszystkie albo żadnego (można też użyć var dla wszystkich). Ciało z klamrami wymaga return, gdy lambda zwraca wartość, i średników; ciało bez klamer to jedno wyrażenie bez return.

#EX
P: Jakie są cztery rodzaje referencji do metod?
H: Statyczna, na konkretnym obiekcie, na dowolnym obiekcie typu, konstruktor.
S: Klasa::metodaStatyczna (np. Integer::parseInt), obiekt::metoda (np. System.out::println), Klasa::metodaInstancyjna wywoływana na pierwszym argumencie (np. String::length dla Function<String, Integer>) oraz Klasa::new jako referencja do konstruktora (np. ArrayList::new).

#EX
P: Dlaczego lambda może używać tylko zmiennych lokalnych effectively final?
H: Przechwytywanie wartości.
S: Lambda przechwytuje wartość zmiennej lokalnej w chwili utworzenia i może być wykonana później, nawet w innym wątku. Gdyby zmienna mogła się zmieniać, lambda widziałaby nieaktualną wartość. Dlatego zmienna musi być final lub effectively final. Pola obiektu i statyczne można zmieniać, bo lambda odwołuje się do nich przez referencję.

#EX
P: Jakie metody domyślne pozwalają składać interfejsy funkcyjne?
H: andThen, compose, and, or, negate.
S: Function ma andThen (najpierw ta funkcja, potem kolejna) i compose (najpierw argument, potem ta funkcja) oraz statyczne identity. Predicate ma and, or, negate oraz statyczne not i isEqual. Consumer ma andThen. Comparator ma comparing, thenComparing i reversed.

#EX
P: Czy lambda może przesłonić zmienną lokalną z otaczającego zakresu?
H: Nazwy parametrów i zmiennych w ciele lambdy.
S: Nie. Parametry lambdy i zmienne zadeklarowane w jej ciele nie mogą mieć tej samej nazwy co zmienne lokalne w otaczającej metodzie — to błąd kompilacji. this w lambdzie oznacza obiekt otaczający, a nie samą lambdę (inaczej niż w klasie anonimowej).

#EX
P: Jak kompilator ustala typ lambdy?
H: Typ docelowy.
S: Lambda nie ma własnego typu — dostaje go z kontekstu (przypisanie, argument metody, rzutowanie, return), który musi być interfejsem funkcyjnym. Dlatego var f = x -> x; się nie kompiluje. Przy przeciążonych metodach przyjmujących różne interfejsy funkcyjne wywołanie z lambdą bywa niejednoznaczne.

#EX
P: Czym są wyspecjalizowane interfejsy funkcyjne dla typów prostych i po co istnieją?
H: Unikanie autoboxingu.
S: To interfejsy takie jak IntPredicate, IntFunction<R>, ToIntFunction<T>, IntUnaryOperator, IntBinaryOperator, IntSupplier (z metodą getAsInt), oraz odpowiedniki dla long i double. Pozwalają przetwarzać liczby bez opakowywania ich w obiekty, co zmniejsza narzut przy dużych ilościach danych.
