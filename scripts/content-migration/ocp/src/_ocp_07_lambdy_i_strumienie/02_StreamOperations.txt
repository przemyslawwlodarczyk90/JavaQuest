#T INTRO Operacje na strumieniach — ściąga egzaminacyjna
Strumień to potok: źródło → operacje pośrednie (leniwe) → jedna operacja końcowa. Egzamin sprawdza, czy wiesz, **kiedy** operacje pośrednie się wykonują (lenistwo, skracanie), co zwracają operacje końcowe, jak działają strumienie typów prostych i co się dzieje przy ponownym użyciu strumienia.

#T DEFINITION Rodzaje operacji
Każdy potok ma źródło, zero lub więcej operacji pośrednich i dokładnie jedną operację końcową:
```
Źródła:     coll.stream(), Stream.of(...), Arrays.stream(arr), IntStream.range(a, b) / rangeClosed,
            Stream.iterate(seed, f) / iterate(seed, hasNext, next), Stream.generate(s), String.chars()

Pośrednie:  filter, map, mapToInt/ToLong/ToDouble/ToObj, flatMap, distinct, sorted, peek,
            limit, skip, takeWhile, dropWhile, boxed

Końcowe:    forEach, count, collect, toList(), reduce, min/max (Optional), findFirst/findAny,
            anyMatch/allMatch/noneMatch, toArray, sum/average (strumienie liczbowe)
```

#T NOTE Lenistwo i kolejność
- Bez operacji końcowej **nic się nie wykonuje** — nawet `peek` czy `map`.
- Elementy przechodzą przez potok **pojedynczo** (pionowo): pierwszy element przez wszystkie etapy, potem drugi.
- `sorted` i `distinct` są stanowe: `sorted` musi zebrać wszystkie elementy przed przekazaniem dalej.
- Operacje skracające: `limit`, `findFirst`, `anyMatch` (kończy na pierwszym `true`), `allMatch` (na pierwszym `false`), `noneMatch`. Dzięki nim działa nawet nieskończony strumień.
- Strumienia **nie można użyć ponownie** — druga operacja końcowa rzuca `IllegalStateException`.

#T NOTE Strumienie typów prostych
- `IntStream`, `LongStream`, `DoubleStream`: `sum()` zwraca liczbę, `average()` zwraca `OptionalDouble`, `max()`/`min()` — `OptionalInt` itd.
- `summaryStatistics()` daje min, max, średnią, sumę i liczbę naraz.
- `mapToObj` / `boxed` przechodzą z powrotem do `Stream<T>`.
- `Stream<Integer>` nie ma metody `sum()` — trzeba użyć `mapToInt(Integer::intValue).sum()` albo `reduce`.

#T NOTE reduce
```
T reduce(T identity, BinaryOperator<T> acc)                 -> T
Optional<T> reduce(BinaryOperator<T> acc)                   -> Optional<T>
<U> U reduce(U identity, BiFunction<U,T,U> acc, BinaryOperator<U> combiner)
```
Wartość neutralna (`identity`) musi być neutralna dla operacji (0 dla sumy, 1 dla iloczynu), szczególnie w strumieniach równoległych.

#T PITFALL Pułapki
- `Stream.of(arr)` dla `int[]` daje `Stream<int[]>` z jednym elementem — `Arrays.stream(arr)` daje `IntStream`.
- `findAny` w strumieniu równoległym może zwrócić dowolny element.
- `toList()` (Java 16) zwraca listę niemodyfikowalną; `collect(Collectors.toList())` — zwykle `ArrayList`.
- `forEach` na strumieniu równoległym nie zachowuje kolejności; `forEachOrdered` — tak.
- `peek` służy do podglądu, a nie do zmiany wyniku.

#T SUMMARY Podsumowanie
Sprawdź, czy jest operacja końcowa; śledź elementy pionowo przez potok; pamiętaj, które operacje skracają, które są stanowe i co zwracają operacje końcowe (zwłaszcza `Optional` z `min`/`max`/`reduce` bez wartości neutralnej).
