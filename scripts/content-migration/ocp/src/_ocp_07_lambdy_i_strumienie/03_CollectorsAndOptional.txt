#T INTRO Kolektory i Optional — ściąga egzaminacyjna
`collect` z klasą `Collectors` to najbardziej rozbudowana część Stream API. Egzamin pyta o typy wyników (`Map<K, List<V>>`, `Map<Boolean, …>`, `Long` z `counting()`), o wyjątki przy zduplikowanych kluczach w `toMap` i o kolektory zagnieżdżone. Druga część to `Optional`: tworzenie, odczyt i łańcuchy `map`/`flatMap`/`filter`.

#T DEFINITION Najważniejsze kolektory
Wszystkie poniższe metody są statycznymi metodami klasy java.util.stream.Collectors:
```
toList() / toSet() / toCollection(TreeSet::new)
joining() / joining(", ") / joining(", ", "[", "]")
counting()                         -> Long
summingInt(f) / averagingInt(f)    -> Integer / Double
minBy(cmp) / maxBy(cmp)            -> Optional<T>
mapping(f, downstream) / filtering(p, downstream) / flatMapping(f, downstream)
reducing(identity, op)
toMap(keyFn, valueFn)              duplikat klucza -> IllegalStateException
toMap(keyFn, valueFn, mergeFn)     łączenie wartości przy duplikacie
toMap(keyFn, valueFn, mergeFn, TreeMap::new)
groupingBy(classifier)             -> Map<K, List<T>>
groupingBy(classifier, downstream) -> Map<K, wynik downstream>
groupingBy(classifier, TreeMap::new, downstream)
partitioningBy(predicate)          -> Map<Boolean, List<T>>, ZAWSZE oba klucze
collectingAndThen(downstream, finisher)
teeing(c1, c2, merger)             (Java 12)
```

#T NOTE groupingBy a partitioningBy
- `groupingBy` tworzy klucze tylko dla grup, które wystąpiły; domyślnie `HashMap` i `List`.
- `partitioningBy` zawsze zwraca mapę z kluczami `false` i `true` — także gdy któraś grupa jest pusta.
- Kolektor podrzędny (downstream) zmienia to, co trafia do wartości: `groupingBy(f, counting())` daje `Map<K, Long>`.

#T NOTE Optional
```
Optional.of(v)          v == null -> NullPointerException
Optional.ofNullable(v)  null -> pusty
Optional.empty()
get() / orElseThrow()   pusty -> NoSuchElementException
orElse(v)               v obliczane ZAWSZE
orElseGet(supplier)     dostawca wywoływany tylko dla pustego
orElseThrow(supplier)   własny wyjątek
isPresent() / isEmpty() / ifPresent(c) / ifPresentOrElse(c, r)
map(f) / flatMap(f) / filter(p) / or(supplier) / stream()
```
- `map` z funkcją zwracającą `null` daje pusty `Optional`.
- `flatMap` stosuje się, gdy funkcja sama zwraca `Optional` (bez zagnieżdżenia `Optional<Optional<T>>`).
- Typy proste: `OptionalInt` (`getAsInt`), `OptionalDouble` (`getAsDouble`), `OptionalLong`.

#T PITFALL Pułapki
- `toMap` bez funkcji łączącej przy powtórzonym kluczu rzuca `IllegalStateException`, a wartość `null` — `NullPointerException`.
- `counting()` zwraca `Long`, nie `Integer`.
- `averagingInt` zwraca `Double` (dla pustej grupy 0.0).
- `Collectors.toList()` nie gwarantuje modyfikowalności, a `Stream.toList()` gwarantuje jej brak.
- Kolejność kluczy w `groupingBy` bez `TreeMap::new` nie jest określona.

#T SUMMARY Podsumowanie
Zapamiętaj sygnatury i typy wyników kolektorów, różnicę między `groupingBy` i `partitioningBy`, zachowanie `toMap` przy duplikatach oraz metody `Optional` — zwłaszcza różnicę `orElse`/`orElseGet` i `map`/`flatMap`.

#EX
P: Jakie kolektory z klasy Collectors są najważniejsze na egzaminie?
H: Listy, zbiory, mapy, łączenie napisów, grupowanie, statystyki.
S: toList, toSet, toMap, toCollection(Supplier), joining (z opcjonalnym separatorem, prefiksem i sufiksem), groupingBy, partitioningBy, counting, summingInt, averagingInt, mapping, filtering, flatMapping, minBy, maxBy, collectingAndThen i teeing (łączy wyniki dwóch kolektorów).

#EX
P: Czym różni się Stream.toList() od collect(Collectors.toList())?
H: Modyfikowalność wyniku.
S: Stream.toList() (od Javy 16) zwraca listę niemodyfikowalną, a próba dodania elementu rzuca UnsupportedOperationException; dopuszcza null. Collectors.toList() nie gwarantuje typu ani modyfikowalności — w praktyce zwraca ArrayList. Gdy potrzebna jest konkretna, modyfikowalna lista, używa się Collectors.toCollection(ArrayList::new).

#EX
P: Co zwraca groupingBy i jak kontrolować typ mapy i wartości?
H: Domyślne typy i wersje z dodatkowymi argumentami.
S: groupingBy(klasyfikator) zwraca Map<K, List<T>> (w praktyce HashMap z ArrayList). Drugi argument to kolektor podrzędny, np. counting() da Map<K, Long>, a mapping(f, toSet()) — zbiór przekształconych wartości. Wersja trzyargumentowa przyjmuje fabrykę mapy, np. TreeMap::new, aby klucze były posortowane.

#EX
P: Czym różni się partitioningBy od groupingBy?
H: Klucze wyniku.
S: partitioningBy dzieli elementy według predykatu na mapę z dokładnie dwoma kluczami, true i false — oba są obecne nawet przy pustej grupie. groupingBy tworzy tyle kluczy, ile różnych wartości zwróci klasyfikator, i nie tworzy kluczy dla pustych grup.

#EX
P: Jak działa toMap przy duplikatach kluczy?
H: Funkcja scalająca i fabryka mapy.
S: toMap(klucz, wartość) rzuca IllegalStateException, gdy dwa elementy dają ten sam klucz. Trzeci argument — funkcja scalająca — decyduje, jak połączyć wartości, np. (a, b) -> a + b. Czwarty argument to fabryka mapy, np. TreeMap::new. toMap nie przyjmuje wartości null.

#EX
P: Jakie są sposoby tworzenia Optional i czym się różnią?
H: of, ofNullable, empty.
S: Optional.of(x) wymaga wartości różnej od null — dla null rzuca NullPointerException. Optional.ofNullable(x) zwraca pusty Optional dla null. Optional.empty() tworzy pusty Optional. Optional nie jest serializowalny i nie powinien być używany jako pole czy parametr.

#EX
P: Jak bezpiecznie wydobyć wartość z Optional?
H: get, orElse, orElseGet, orElseThrow, ifPresent.
S: get() i orElseThrow() bez argumentu rzucają NoSuchElementException dla pustego Optional. orElse(wartość) zwraca wartość domyślną (zawsze ją obliczając), orElseGet(dostawca) oblicza ją leniwie, orElseThrow(dostawca) rzuca wybrany wyjątek. ifPresent i ifPresentOrElse wykonują akcję zależnie od obecności wartości, a map, flatMap i filter pozwalają przetwarzać wartość bez jej wyciągania.

#EX
P: Czym różnią się map i flatMap w Optional?
H: Funkcja zwracająca Optional.
S: map(f) stosuje funkcję do wartości i opakowuje wynik w Optional; gdy funkcja zwróci null, wynik jest pusty. Gdy funkcja sama zwraca Optional, map dałby Optional<Optional<T>> — flatMap spłaszcza go do Optional<T>. Na pustym Optional obie metody nie wywołują funkcji i zwracają pusty Optional.
