#T INTRO Boss rozdziału 13: koszyk sklepu z magazynem stanu
W sklepie z rozdziału 12 koszyk był kontekstem z localStorage. Teraz przebudujesz go jako porządny **stan globalny klienta**: z wyborem biblioteki (uzasadnionym na piśmie), trwałym zapisem z migracją wersji, synchronizacją między kartami przeglądarki, wartościami wyliczanymi i współpracą z danymi z serwera w TanStack Query. To typowy problem z prawdziwych sklepów internetowych.

#T DEFINITION Brief zadania
Koszyk sklepu:
1. **Akcje**: dodaj produkt (z ilością), zmień ilość, usuń, wyczyść, zastosuj kod rabatowy, usuń kod.
2. **Wartości wyliczane**: liczba sztuk, suma częściowa, rabat, koszt dostawy (darmowa od 200 zł), suma do zapłaty — wszystkie w groszach.
3. **Ceny z serwera**: koszyk przechowuje tylko `productId` i `qty`; aktualne ceny i dostępność pochodzą z TanStack Query (`/api/products?ids=1,5,9`). Produkt niedostępny jest oznaczony i nie liczy się do sumy.
4. **Trwałość**: koszyk w localStorage z wersją schematu; przy zmianie formatu (np. z `{ [id]: qty }` na tablicę `[{ productId, qty }]`) stare zapisy są migrowane, a uszkodzone — odrzucane.
5. **Synchronizacja między kartami**: dodanie produktu w jednej karcie przeglądarki od razu widać w drugiej (zdarzenie `storage`).
6. **Mini-koszyk w nagłówku** (licznik + suma) i **strona `/cart`**; mini-koszyk nie renderuje się przy zmianie kodu rabatowego.
7. **Uzasadnienie**: komentarz na górze pliku magazynu — dlaczego ta biblioteka (Zustand, Redux Toolkit lub Jotai) i co trzymasz poza nią.

#T CODE_JSX Kody rabatowe i stałe (JSX)
```
// cartRules.js
export const DISCOUNTS = {
  JESIEN10: { type: 'percent', value: 10 },
  DOSTAWA0: { type: 'freeShipping' },
  MINUS50: { type: 'amount', value: 5000, minSubtotal: 30000 },
};

export const FREE_SHIPPING_FROM = 20000; // grosze
export const SHIPPING_COST = 1499;

export function computeTotals(lines, discountCode) {
  const subtotal = lines.filter((l) => l.available).reduce((sum, l) => sum + l.priceGrosze * l.qty, 0);
  const d = discountCode ? DISCOUNTS[discountCode] : undefined;
  let discount = 0;
  if (d?.type === 'percent') discount = Math.round((subtotal * d.value) / 100);
  if (d?.type === 'amount' && subtotal >= d.minSubtotal) discount = d.value;
  const shipping = subtotal === 0 || subtotal >= FREE_SHIPPING_FROM || d?.type === 'freeShipping' ? 0 : SHIPPING_COST;
  return { subtotal, discount, shipping, total: Math.max(0, subtotal - discount) + shipping };
}
```

#T CODE_TSX Kody rabatowe i stałe (TSX)
Unia z dyskryminatorem `type` opisuje rodzaje rabatów — `d.value` jest dostępne tylko dla rabatów, które je mają.
```
// cartRules.ts
export type Discount =
  | { type: 'percent'; value: number }
  | { type: 'amount'; value: number; minSubtotal: number }
  | { type: 'freeShipping' };

export const DISCOUNTS: Record<string, Discount> = {
  JESIEN10: { type: 'percent', value: 10 },
  DOSTAWA0: { type: 'freeShipping' },
  MINUS50: { type: 'amount', value: 5000, minSubtotal: 30000 },
};

export const FREE_SHIPPING_FROM = 20000;
export const SHIPPING_COST = 1499;

export type CartLine = { productId: number; qty: number; priceGrosze: number; available: boolean };
export type Totals = { subtotal: number; discount: number; shipping: number; total: number };

export function computeTotals(lines: readonly CartLine[], discountCode: string | null): Totals {
  const subtotal = lines.filter((l) => l.available).reduce((sum, l) => sum + l.priceGrosze * l.qty, 0);
  const d = discountCode ? DISCOUNTS[discountCode] : undefined;
  let discount = 0;
  if (d?.type === 'percent') discount = Math.round((subtotal * d.value) / 100);
  if (d?.type === 'amount' && subtotal >= d.minSubtotal) discount = d.value;
  const shipping = subtotal === 0 || subtotal >= FREE_SHIPPING_FROM || d?.type === 'freeShipping' ? 0 : SHIPPING_COST;
  return { subtotal, discount, shipping, total: Math.max(0, subtotal - discount) + shipping };
}
```

#T STEP_BY_STEP Kryteria akceptacji
1. Magazyn przechowuje wyłącznie `{ lines: [{ productId, qty }], discountCode }` — bez cen, nazw i dostępności.
2. Ceny i dostępność pochodzą z jednego zapytania TanStack Query dla ID w koszyku (klucz zawiera posortowaną listę ID).
3. Sumy liczy czysta funkcja `computeTotals` (z testem ręcznym w konsoli lub testem jednostkowym w rozdziale 14); w komponentach nie ma arytmetyki cen.
4. Ilość jest ograniczona do 1–99; dodanie produktu, który już jest w koszyku, zwiększa ilość.
5. Zapis w localStorage z wersją; migracja z wersji 1 (`{ [id]: qty }`) do wersji 2 (tablica) działa — sprawdź, wpisując ręcznie stary format w DevTools.
6. Zmiana koszyka w jednej karcie przeglądarki pojawia się w drugiej bez odświeżania.
7. Mini-koszyk w nagłówku subskrybuje tylko potrzebne dane i nie renderuje się przy zmianie kodu rabatowego (sprawdź w DevTools „Highlight updates”).
8. Niepoprawny kod rabatowy daje komunikat przy polu, a kod `MINUS50` poniżej progu — informację, ile brakuje do progu.
9. W wersji TSX: typ magazynu, unia rabatów, `npm run build` bez błędów; w obu wersjach — komentarz z uzasadnieniem wyboru biblioteki.

#T NOTE Wskazówka 1 — persist z migracją (Zustand)
Middleware `persist` ma opcje `version` i `migrate(persistedState, version)`: zwróć z `migrate` stan w nowym formacie. Dla wersji 1: `Object.entries(old).map(([id, qty]) => ({ productId: Number(id), qty }))`. Dodaj walidację (np. schemat Zod) i przy błędzie zwróć pusty koszyk. W Redux Toolkit analogiczną logikę umieścisz w funkcji wczytującej `preloadedState`, a w Jotai — w `atomWithStorage` z własnym obiektem `storage`.

#T NOTE Wskazówka 2 — synchronizacja między kartami
Zdarzenie `window.addEventListener('storage', handler)` wywołuje się w **innych** kartach, gdy jedna zmieni localStorage. W handlerze sprawdź `event.key` i wczytaj nowy stan do magazynu (Zustand: `useCart.persist.rehydrate()`; RTK: `dispatch(cartReplaced(parsed))`; Jotai: `atomWithStorage` ma opcję `subscribe` domyślnie włączoną dla localStorage). Podepnij nasłuchiwanie raz — w module magazynu albo w efekcie w providerze aplikacji.

#T NOTE Wskazówka 3 — linie koszyka z danymi serwera
Połącz magazyn z zapytaniem w jednym hooku `useCartLines()`: pobierz `lines` z magazynu, zapytaj API o produkty dla ich ID (`enabled: lines.length > 0`), zmapuj na `CartLine` (produkt, którego brak w odpowiedzi, oznacz jako niedostępny) i zwróć razem z `computeTotals(...)`. Komponenty nie wiedzą, skąd pochodzą części danych.

#T PITFALL Typowe błędy w tym zadaniu
- Cena zapisana w koszyku w chwili dodania — po zmianie ceny w sklepie klient płaci starą (albo widzi inną kwotę na stronie produktu i w koszyku).
- Sumy liczone osobno w mini-koszyku i na stronie koszyka — różne zaokrąglenia rabatu procentowego.
- Liczby zmiennoprzecinkowe dla kwot (`12.99 * 3`) zamiast groszy.
- Brak migracji — po wdrożeniu nowego formatu użytkownicy ze starym koszykiem widzą błąd albo pusty koszyk bez wyjaśnienia.
- Nasłuchiwanie `storage` podpinane w każdym komponencie korzystającym z koszyka.

#T SUMMARY Podsumowanie rozdziału 13
W tym rozdziale poznałeś pięć rodzajów stanu i zasadę doboru narzędzia, Zustand (magazyn z selektorami, `useShallow`, `persist`, `devtools`), Redux Toolkit (`configureStore`, `createSlice`, Immer, typowane hooki, `createSelector`), operacje asynchroniczne w Reduxie (thunki i RTK Query z tagami) oraz Jotai (atomy, atomy pochodne, akcje, `atomWithStorage`, Provider). Najważniejsza lekcja: biblioteka stanu globalnego jest dla stanu klienta, a dane serwera należą do biblioteki danych. W TSX: `create<T>()()`, `PayloadAction`, `RootState`, generyki thunków i endpointów, typowane atomy.

Boss zaliczony, gdy wszystkie dziewięć kryteriów akceptacji jest spełnionych, a synchronizacja koszyka działa w dwóch kartach przeglądarki.
