#T INTRO Rozgrzewka i problem: Redux w każdym drugim istniejącym projekcie
Rozgrzewka: Jak działa selektor w Zustand i kiedy komponent się renderuje? Do czego służy `useShallow`? Dlaczego nie trzymasz danych serwera w magazynie?

Problem: Zustand wystarcza w DevDesk, ale ogromna liczba istniejących aplikacji React (szczególnie dużych, rozwijanych latami) używa **Reduxa**. Zobaczysz w nich `useSelector`, `dispatch`, „slice’y” i Redux DevTools. Starszy kod Reduxa był znany z mnóstwa ręcznie pisanych akcji i reducerów — **Redux Toolkit (RTK)** to oficjalny, nowoczesny sposób pisania Reduxa, który usuwa większość tego kodu. Przepiszesz „ostatnio oglądane” i „układ paneli” na RTK, żeby porównać podejścia.

#T DEFINITION Redux w pigułce
Redux to jeden **magazyn** (store) dla całej aplikacji. Stan zmienia się wyłącznie przez **akcje** (`{ type, payload }`) przetwarzane przez **reducery** — znasz to z `useReducer` (rozdział 06), tylko w skali aplikacji. Redux Toolkit dodaje:
- `configureStore` — magazyn z dobrymi domyślnymi ustawieniami (devtools, sprawdzanie niemutowalności i serializowalności w trybie deweloperskim),
- `createSlice` — w jednym miejscu: nazwa, stan początkowy i reducery; **akcje generują się automatycznie**,
- **Immer** w reducerach — możesz pisać „mutujący” kod (`state.ids.push(id)`), a powstaje nowy, niemutowalny stan,
- hooki z `react-redux`: `useSelector(selektor)` i `useDispatch()`; magazyn udostępnia `<Provider store={store}>`.

Instalacja: `npm install @reduxjs/toolkit react-redux`.

#T CODE_JSX Slice i magazyn (JSX)
```
// store.js
import { configureStore, createSlice } from '@reduxjs/toolkit';

const recentSlice = createSlice({
  name: 'recent',
  initialState: { ids: [] },
  reducers: {
    visited(state, action) {
      state.ids = [action.payload, ...state.ids.filter((id) => id !== action.payload)].slice(0, 10);
    },
    cleared(state) {
      state.ids = [];
    },
  },
});

const layoutSlice = createSlice({
  name: 'layout',
  initialState: { sidebarOpen: true, detailWidth: 420 },
  reducers: {
    sidebarToggled(state) {
      state.sidebarOpen = !state.sidebarOpen; // Immer: „mutacja” szkicu
    },
    detailResized(state, action) {
      state.detailWidth = Math.min(800, Math.max(280, action.payload));
    },
  },
});

export const { visited, cleared } = recentSlice.actions;
export const { sidebarToggled, detailResized } = layoutSlice.actions;

export const store = configureStore({
  reducer: { recent: recentSlice.reducer, layout: layoutSlice.reducer },
});
```

#T CODE_TSX Slice i magazyn (TSX)
Typ akcji z danymi podajesz przez `PayloadAction<T>`. Typy `RootState` i `AppDispatch` wyprowadzasz z magazynu — nie piszesz ich ręcznie.
```
// store.ts
import { configureStore, createSlice, type PayloadAction } from '@reduxjs/toolkit';

type RecentState = { ids: number[] };
type LayoutState = { sidebarOpen: boolean; detailWidth: number };

const recentSlice = createSlice({
  name: 'recent',
  initialState: { ids: [] } as RecentState,
  reducers: {
    visited(state, action: PayloadAction<number>) {
      state.ids = [action.payload, ...state.ids.filter((id) => id !== action.payload)].slice(0, 10);
    },
    cleared(state) {
      state.ids = [];
    },
  },
});

const layoutSlice = createSlice({
  name: 'layout',
  initialState: { sidebarOpen: true, detailWidth: 420 } as LayoutState,
  reducers: {
    sidebarToggled(state) {
      state.sidebarOpen = !state.sidebarOpen;
    },
    detailResized(state, action: PayloadAction<number>) {
      state.detailWidth = Math.min(800, Math.max(280, action.payload));
    },
  },
});

export const { visited, cleared } = recentSlice.actions;
export const { sidebarToggled, detailResized } = layoutSlice.actions;

export const store = configureStore({
  reducer: { recent: recentSlice.reducer, layout: layoutSlice.reducer },
});

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
```

#T NOTE JSX ↔ TSX — typowane hooki Reduxa
W TSX standardem jest utworzenie typowanych wersji hooków raz: `export const useAppSelector = useSelector.withTypes<RootState>()` i `export const useAppDispatch = useDispatch.withTypes<AppDispatch>()`. Wtedy selektor `useAppSelector((s) => s.layout.detailWidth)` zna typ całego stanu, a `dispatch(detailResized('wide'))` (tekst zamiast liczby) jest błędem. `PayloadAction<number>` w reducerze sprawia, że wygenerowany kreator akcji `detailResized` przyjmuje liczbę. W JSX hooki działają identycznie, a ochronę przed złymi danymi w akcjach dają tylko testy i devtools.

#T CODE_BASIC Typowane hooki i użycie w komponentach
```
import { Provider, useDispatch, useSelector } from 'react-redux';
import type { ReactNode } from 'react';
import { sidebarToggled, store, type AppDispatch, type RootState } from './store';

export const useAppSelector = useSelector.withTypes<RootState>();
export const useAppDispatch = useDispatch.withTypes<AppDispatch>();

export function StoreProvider({ children }: { children: ReactNode }) {
  return <Provider store={store}>{children}</Provider>;
}

export function SidebarToggle() {
  const open = useAppSelector((s) => s.layout.sidebarOpen);
  const dispatch = useAppDispatch();
  return (
    <button type="button" aria-expanded={open} onClick={() => dispatch(sidebarToggled())}>
      {open ? 'Ukryj panel' : 'Pokaż panel'}
    </button>
  );
}
```

#T CODE_PRACTICAL Selektory wielokrotnego użytku i createSelector
Selektory trzymaj obok slice’a. `createSelector` zapamiętuje wynik (memoizacja), dopóki nie zmienią się dane wejściowe — przydaje się, gdy selektor tworzy nową tablicę.
```
import { createSelector } from '@reduxjs/toolkit';
import type { RootState } from './store';

export const selectRecentIds = (s: RootState) => s.recent.ids;
export const selectDetailWidth = (s: RootState) => s.layout.detailWidth;

// nowa tablica tylko wtedy, gdy zmieni się lista ID
export const selectTopRecent = createSelector([selectRecentIds], (ids) => ids.slice(0, 5));

// w komponencie: const top = useAppSelector(selectTopRecent);
```

#T STEP_BY_STEP Budujemy razem: Redux Toolkit w DevDesk
1. Zainstaluj `@reduxjs/toolkit` i `react-redux`; utwórz `store` ze slice’ami `recent` i `layout`.
2. Dodaj `StoreProvider` do `AppProviders`; w wersji TS utwórz `useAppSelector` i `useAppDispatch`.
3. Przenieś „ostatnio oglądane” z Zustand do slice’a `recent` (w ramach eksperymentu porównawczego) — `dispatch(visited(id))` na ekranie ticketu.
4. Dodaj przełącznik panelu bocznego (`sidebarToggled`) i uchwyt zmiany szerokości panelu szczegółów (`detailResized` przy przeciąganiu).
5. Otwórz Redux DevTools: przejrzyj listę akcji, stan po każdej akcji i użyj „podróży w czasie” (przeskok do wcześniejszego stanu).
6. Zapisz układ w localStorage: `store.subscribe(() => localStorage.setItem('layout', JSON.stringify(store.getState().layout)))` i wczytaj w `preloadedState` przy tworzeniu magazynu (z walidacją).
7. Porównaj kod: ta sama funkcja w Zustand i w RTK — zapisz w komentarzu, które podejście wybrałbyś dla DevDesk i dlaczego.

#T PITFALL Prawdziwa mutacja poza reducerem
Immer działa **tylko wewnątrz reducerów** `createSlice`. `const s = store.getState(); s.layout.sidebarOpen = false;` mutuje stan magazynu bez akcji — komponenty się nie odświeżą, devtools nie pokażą zmiany, a w trybie deweloperskim RTK zgłosi błąd niemutowalności. Stan zmieniasz wyłącznie przez `dispatch(akcja)`.

#T WHEN_TO_USE Zustand czy Redux Toolkit
Zustand: mała i średnia ilość stanu globalnego, szybki start, mało kodu, brak providera. Redux Toolkit: duży zespół i duża aplikacja z wieloma powiązanymi fragmentami stanu, potrzeba ścisłych konwencji (akcje, reducery, selektory), zaawansowane devtools, middleware (np. synchronizacja między kartami, logowanie akcji), istniejący kod na Reduxie. Oba używają tej samej idei (magazyn poza Reactem + selektory) i oba są w pełni profesjonalne.

#T SUMMARY Kryterium akceptacji i podsumowanie
Redux Toolkit: `configureStore` tworzy magazyn, `createSlice` łączy stan, reducery (z Immerem) i automatycznie generowane akcje; komponenty używają `useSelector` i `useDispatch`, a aplikacja `<Provider store>`. Stan zmienia się wyłącznie przez akcje. Selektory trzymasz obok slice’a, a `createSelector` zapamiętuje wyniki. W TSX `PayloadAction<T>`, `RootState`/`AppDispatch` wyprowadzone z magazynu i hooki `withTypes` dają pełne typowanie.

Kryterium akceptacji: ostatnio oglądane tickety i układ paneli DevDesk działają na Redux Toolkit, akcje są widoczne w Redux DevTools (z podróżą w czasie), układ przetrwa odświeżenie, a w kodzie jest komentarz porównujący Zustand i RTK dla tej funkcji.
