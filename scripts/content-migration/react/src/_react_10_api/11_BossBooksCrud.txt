#T INTRO Boss rozdziału 10: katalog książek z pełnym CRUD
Ostatni sprawdzian rozdziału obejmuje wszystko o danych z serwera: kontrakt, udawane API z błędami i opóźnieniami, klienta API z walidacją, zapytania i mutacje w TanStack Query, stany ładowania, błędu i pustej listy, wyścigi i paginację. Domena: katalog książek w bibliotece firmowej. Kod piszesz od zera — bez kopiowania DevDesk (możesz kopiować własne narzędzia ogólne: klienta API, komponenty stanów, pager).

#T DEFINITION Brief zadania
Aplikacja „Biblioteka”:
1. **Lista książek** z paginacją serwerową (12 na stronę), wyszukiwaniem po tytule i autorze (z opóźnieniem), filtrem „tylko dostępne” i sortowaniem (tytuł, rok wydania).
2. **Szczegóły książki** po kliknięciu (panel boczny): opis, liczba egzemplarzy, historia wypożyczeń.
3. **Dodawanie i edycja** książki w modalu (tytuł, autor, rok, ISBN, liczba egzemplarzy) z walidacją Zod po stronie klienta i komunikatami błędów z serwera (np. „Książka z tym ISBN już istnieje” — 409).
4. **Wypożyczenie** (przycisk w szczegółach): aktualizacja optymistyczna liczby dostępnych egzemplarzy z wycofaniem przy błędzie.
5. **Usunięcie** z potwierdzeniem przez toast „Cofnij” (5 s).
6. **API w MSW** z: losowym opóźnieniem 200–1200 ms, co piątym żądaniem kończącym się błędem 500 (przełączane parametrem `?chaos=1`), 404 dla nieistniejących książek, 409 dla zduplikowanego ISBN.

#T CODE_JSX Dane i kontrakt (JSX)
```
// mocks/books.js
const AUTHORS = ['Ewa Lis', 'Jan Nowak', 'Anna Wiśniewska', 'Piotr Zając'];

export const books = Array.from({ length: 60 }, (_, i) => ({
  id: i + 1,
  title: `Programowanie, tom ${i + 1}`,
  author: AUTHORS[i % AUTHORS.length],
  year: 1995 + (i % 30),
  isbn: `978-83-${String(10000 + i).padStart(5, '0')}-0`,
  copies: 1 + (i % 4),
  available: i % 4,
}));

/*
GET    /api/books?q=&available=true&sort=title:asc&page=1&pageSize=12 → { items, total, page, pageSize }
GET    /api/books/:id                → Book | 404
POST   /api/books                    → 201 Book | 400 { fieldErrors } | 409 { message }
PATCH  /api/books/:id                → Book | 404 | 409
POST   /api/books/:id/borrow         → Book (available - 1) | 409 { message: 'Brak dostępnych egzemplarzy' }
DELETE /api/books/:id                → 204 | 404
*/
```

#T CODE_TSX Dane i kontrakt (TSX)
Schemat Zod jest źródłem typu `Book` i walidacji odpowiedzi.
```
// api/books.ts
import { z } from 'zod';

export const bookSchema = z.object({
  id: z.number(),
  title: z.string(),
  author: z.string(),
  year: z.number().int(),
  isbn: z.string(),
  copies: z.number().int().nonnegative(),
  available: z.number().int().nonnegative(),
});

export const bookPageSchema = z.object({
  items: z.array(bookSchema),
  total: z.number(),
  page: z.number(),
  pageSize: z.number(),
});

export type Book = z.infer<typeof bookSchema>;

export const bookFormSchema = bookSchema
  .omit({ id: true, available: true })
  .extend({ isbn: z.string().regex(/^978-\d{2}-\d{5}-\d$/, 'Format: 978-83-12345-0') });

export type BookForm = z.infer<typeof bookFormSchema>;

export const bookKeys = {
  all: ['books'] as const,
  list: (params: { q: string; available: boolean; sort: string; page: number }) => ['books', 'list', params] as const,
  detail: (id: number) => ['books', 'detail', id] as const,
};
```

#T STEP_BY_STEP Kryteria akceptacji
1. Wszystkie żądania przechodzą przez jednego klienta API; odpowiedzi są walidowane schematami (w TS — bez `as`).
2. Lista ma osobne widoki ładowania (skeleton), błędu (z „Spróbuj ponownie”), pustego wyniku (z „Wyczyść filtry”) i odświeżania (stare dane przyciemnione przy zmianie strony).
3. Wyszukiwanie z opóźnieniem 300 ms; przestarzałe żądania są przerywane (`signal` z `queryFn`); wynik zawsze odpowiada tekstowi w polu.
4. Zmiana filtra, wyszukiwania lub sortowania wraca na stronę 1 w handlerze; następna strona jest pobierana z wyprzedzeniem.
5. Formularz: walidacja Zod (ISBN, rok 1450–bieżący, liczba egzemplarzy ≥ 1), błąd 409 z serwera pojawia się przy polu ISBN, przycisk zapisu zablokowany podczas wysyłania.
6. Po dodaniu/edycji/usunięciu listy i szczegóły aktualizują się przez unieważnienie cache lub `setQueryData` — bez ręcznego odświeżania i bez kopii danych w `useState`.
7. Wypożyczenie zmienia liczbę dostępnych egzemplarzy natychmiast i wycofuje zmianę przy błędzie (sprawdź z `?chaos=1` i z książką bez dostępnych egzemplarzy — 409).
8. Usunięcie: książka znika od razu, „Cofnij” ją przywraca, żądanie `DELETE` wysyłane jest dopiero po wygaśnięciu toastu.
9. W wersji TSX: typy z `z.infer`, fabryka kluczy z `as const`, `npm run build` bez błędów.

#T NOTE Wskazówka 1 — kolejność budowy
Buduj warstwami: (1) handlery MSW i scenariusze błędów — sprawdź je w konsoli przeglądarki `fetch`-em; (2) klient API i schematy; (3) hooki zapytań i mutacji z fabryką kluczy; (4) komponenty widoków. Każdą warstwę sprawdź, zanim przejdziesz do następnej — błąd w kontrakcie wykryty na etapie (1) kosztuje minutę, na etapie (4) — godzinę.

#T NOTE Wskazówka 2 — wypożyczenie optymistyczne
Zmieniasz dwa miejsca w cache: szczegóły książki (`bookKeys.detail(id)`) i bieżącą stronę listy (znajdź ją przez `queryClient.getQueriesData({ queryKey: ['books', 'list'] })` albo po prostu unieważnij listy w `onSettled`). W `onMutate` sprawdź też regułę biznesową lokalnie: jeśli `available === 0`, nie wysyłaj żądania i pokaż komunikat — serwer i tak zwróci 409, ale lepiej nie czekać.

#T NOTE Wskazówka 3 — chaos w MSW
Licznik w module handlerów: `let calls = 0;` i w każdym handlerze `if (chaosEnabled() && ++calls % 5 === 0) return HttpResponse.json({ message: 'Losowy błąd serwera' }, { status: 500 });`. Dzięki `retry` TanStack Query część błędów „naprawi się” sama — zobaczysz w Network ponowione żądania. Dla mutacji ponawianie jest domyślnie wyłączone — i tak powinno zostać (podwójne wypożyczenie!).

#T PITFALL Typowe błędy w tym zadaniu
- Klucz zapytania bez wszystkich parametrów (np. bez `sort`) — po zmianie sortowania widać dane w starej kolejności.
- Włączone ponawianie mutacji — przy chwilowym błędzie wypożyczenie wykonuje się dwa razy.
- Błąd 409 pokazany tylko w toaście zamiast przy polu ISBN.
- Usunięcie wysłane od razu, a „Cofnij” tylko przywraca element w UI — książka „wraca”, ale na serwerze jej nie ma.
- `available` aktualizowane optymistycznie w szczegółach, ale nie w liście — dwa miejsca pokazują różne liczby.

#T SUMMARY Podsumowanie rozdziału 10
W tym rozdziale poznałeś HTTP i projektowanie kontraktu REST, udawane API przez MSW, ręczne pobieranie danych w efektach ze stanami ładowania, błędu i pustej listy, ochronę przed wyścigami (`ignore`, `AbortController`, debounce), mutacje CRUD z obsługą błędów walidacji z serwera, klienta API z walidacją odpowiedzi schematem oraz TanStack Query: zapytania, klucze, cache, mutacje, unieważnianie, aktualizacje optymistyczne, płynną paginację i nieskończone listy. W TSX: typy kontraktu, generyki handlerów MSW, klasa błędu API, przeciążenia klienta ze schematem i inferencja typów w hookach biblioteki.

Boss zaliczony, gdy wszystkie dziewięć kryteriów akceptacji jest spełnionych także przy włączonym `?chaos=1`.
