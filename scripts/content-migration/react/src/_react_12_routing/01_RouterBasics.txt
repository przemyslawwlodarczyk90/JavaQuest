#T INTRO Rozgrzewka i problem: jedna strona, wiele ekranów
Rozgrzewka: Jak frontend i Spring Boot porozumiewają się w trybie deweloperskim bez CORS? Co daje generowanie typów z OpenAPI? Dlaczego połączenie SSE otwierasz raz?

Problem: DevDesk ma już dashboard, tabelę ticketów, ekran „Mój dzień”, „Archiwum”, „Administrację” i ustawienia — ale wszystkie przełączasz stanem `view` w `App`. Adres w przeglądarce się nie zmienia: nie da się wysłać koledze linku do „Archiwum”, przycisk „Wstecz” wychodzi z aplikacji, a odświeżenie strony zawsze wraca na dashboard. Potrzebujesz **routingu**: każdy ekran ma swój adres URL.

#T DEFINITION SPA i routing po stronie klienta
Aplikacja React to **SPA** (single page application): przeglądarka ładuje jeden `index.html` i jeden pakiet JS, a zmiana ekranu nie pobiera nowej strony z serwera. Router:
1. czyta aktualny adres (`location.pathname`, np. `/tickets`) i renderuje pasujący komponent,
2. przy kliknięciu linku **zmienia adres przez History API** (`history.pushState`) bez przeładowania strony,
3. reaguje na „Wstecz/Dalej” (zdarzenie `popstate`) i odświeżenie (pierwszy render pod danym adresem).

W kursie używasz **React Router** — najpopularniejszej biblioteki routingu dla React. W trybie biblioteki (library/data mode) dodajesz go do istniejącej aplikacji Vite; w trybie frameworka (rozdział 18) przejmuje też budowanie i renderowanie na serwerze. Instalacja: `npm install react-router`.

#T CODE_JSX Pierwszy router (JSX)
`createBrowserRouter` definiuje trasy jako obiekty, a `RouterProvider` je renderuje.
```
// main.jsx
import { createRoot } from 'react-dom/client';
import { createBrowserRouter, RouterProvider } from 'react-router';
import { Dashboard } from './pages/Dashboard';
import { TicketsPage } from './pages/TicketsPage';
import { SettingsPage } from './pages/SettingsPage';

const router = createBrowserRouter([
  { path: '/', element: <Dashboard /> },
  { path: '/tickets', element: <TicketsPage /> },
  { path: '/settings', element: <SettingsPage /> },
]);

createRoot(document.getElementById('root')).render(<RouterProvider router={router} />);
```

#T CODE_TSX Pierwszy router (TSX)
Kod identyczny poza `!` przy `getElementById`. Definicja tras jest sprawdzana przez typy biblioteki — np. literówka `elemnt` w obiekcie trasy to błąd.
```
// main.tsx
import { createRoot } from 'react-dom/client';
import { createBrowserRouter, RouterProvider } from 'react-router';
import { Dashboard } from './pages/Dashboard';
import { TicketsPage } from './pages/TicketsPage';
import { SettingsPage } from './pages/SettingsPage';

const router = createBrowserRouter([
  { path: '/', element: <Dashboard /> },
  { path: '/tickets', element: <TicketsPage /> },
  { path: '/settings', element: <SettingsPage /> },
]);

createRoot(document.getElementById('root')!).render(<RouterProvider router={router} />);
```

#T NOTE JSX ↔ TSX — trasy jako dane
Definicja tras to zwykła tablica obiektów, więc w obu wersjach wygląda tak samo. W TSX dostajesz kontrolę kształtu obiektu trasy (`path`, `element`, `children`, `loader`, `errorElement`) i podpowiedzi opcji. Ścieżki w `<Link to="...">` są w trybie biblioteki zwykłymi tekstami — literówka `to="/tikets"` nie zostanie wykryta w żadnej wersji. Pełne typowanie ścieżek (z parametrami) daje tryb frameworka z generowanymi typami tras albo biblioteki takie jak TanStack Router — w tej lekcji wystarczy zbiór stałych ścieżek (niżej).

#T DEFINITION Link i NavLink zamiast a href
`<a href="/tickets">` przeładowuje całą stronę: znika stan aplikacji, cache TanStack Query, połączenie SSE. Router udostępnia:
- `<Link to="/tickets">` — renderuje prawdziwe `<a href>` (działa „otwórz w nowej karcie”, kopiowanie adresu), ale kliknięcie obsługuje router bez przeładowania,
- `<NavLink to="/tickets">` — `Link`, który wie, czy jego trasa jest aktywna: ustawia `aria-current="page"` i pozwala nadać klasę aktywną (`className={({ isActive }) => ...}`),
- `useNavigate()` — nawigacja z kodu (np. po zapisaniu formularza): `navigate('/tickets')`, `navigate(-1)` (wstecz), `navigate('/login', { replace: true })` (bez wpisu w historii).

#T CODE_BASIC Nawigacja w nagłówku
```
import { NavLink } from 'react-router';

export const paths = {
  dashboard: '/',
  tickets: '/tickets',
  settings: '/settings',
} as const;

const linkClass = ({ isActive }: { isActive: boolean }) => (isActive ? 'nav__link nav__link--active' : 'nav__link');

export function MainNav() {
  return (
    <nav aria-label="Główna">
      <NavLink to={paths.dashboard} end className={linkClass}>Dashboard</NavLink>
      <NavLink to={paths.tickets} className={linkClass}>Tickety</NavLink>
      <NavLink to={paths.settings} className={linkClass}>Ustawienia</NavLink>
    </nav>
  );
}
```

#T CODE_PRACTICAL Nawigacja z kodu po zapisie
`useNavigate` w handlerze — nawigacja to skutek zdarzenia, więc nie w efekcie.
```
import { useNavigate } from 'react-router';

export function useAfterCreate() {
  const navigate = useNavigate();
  return (ticketId: number) => {
    navigate(`/tickets?created=${ticketId}`);
  };
}

export function CancelButton() {
  const navigate = useNavigate();
  return <button type="button" onClick={() => navigate(-1)}>Anuluj</button>;
}
```

#T DEFINITION Serwer musi zwracać index.html dla każdej ścieżki
Gdy użytkownik odświeży stronę pod `/tickets`, przeglądarka poprosi serwer o `/tickets` — a takiego pliku nie ma. Serwer deweloperski Vite obsługuje to automatycznie (zwraca `index.html`). W produkcji musisz skonfigurować **fallback**: każda nieznana ścieżka (poza `/api` i plikami statycznymi) zwraca `index.html`, a router renderuje właściwy ekran. W Spring Boot robi się to kontrolerem przekierowującym ścieżki aplikacji na `index.html`, w Nginx — `try_files $uri /index.html` (rozdział 21).

#T STEP_BY_STEP Budujemy razem: routing w DevDesk
1. Zainstaluj `react-router` i przenieś ekrany do katalogu `src/pages/` (`Dashboard`, `TicketsPage`, `MyDayPage`, `ArchivePage`, `SettingsPage`).
2. Utwórz router z trasami `/`, `/tickets`, `/my-day`, `/archive`, `/settings` i zastąp nim przełączanie stanem `view`.
3. Providery (`AppProviders`: auth, query, toasty) zostaw nad `RouterProvider`, żeby działały we wszystkich ekranach.
4. W nagłówku użyj `MainNav` z `NavLink` i stylem `.nav__link--active` (oraz `[aria-current='page']` w CSS).
5. Sprawdź: kliknięcie w nawigację nie przeładowuje strony (w Network brak żądania `document`), „Wstecz” wraca do poprzedniego ekranu, odświeżenie pod `/archive` pokazuje archiwum.
6. Po utworzeniu ticketu w modalu przejdź na `/tickets` przez `useNavigate`.
7. Kliknij „Tickety” środkowym przyciskiem myszy — otwiera się nowa karta (to prawdziwy link).

#T PITFALL Zwykły link w aplikacji z routerem
`<a href="/settings">Ustawienia</a>` działa „prawie” — ale każde kliknięcie przeładowuje aplikację: znika zawartość formularzy, cache danych, połączenie na żywo, a użytkownik czeka na ponowne pobranie pakietu JS. Linki wewnątrz aplikacji zawsze przez `Link`/`NavLink`; zwykłe `<a>` tylko do adresów zewnętrznych (wtedy z `target="_blank"` i `rel="noopener noreferrer"`).

#T SUMMARY Kryterium akceptacji i podsumowanie
Router w SPA czyta adres URL, renderuje pasujący ekran i zmienia adres przez History API bez przeładowania. React Router: trasy w `createBrowserRouter`, render przez `RouterProvider`, nawigacja przez `Link`, `NavLink` (z `aria-current` i klasą aktywną) i `useNavigate` w handlerach. Serwer produkcyjny musi zwracać `index.html` dla ścieżek aplikacji. W TSX kształt tras jest sprawdzany, ale ścieżki w `to` to teksty — trzymaj je w obiekcie stałych.

Kryterium akceptacji: każdy ekran DevDesk ma własny adres, nawigacja w nagłówku podświetla aktywny ekran i nie przeładowuje strony, „Wstecz” i odświeżenie działają poprawnie, a linki otwierają się w nowej karcie środkowym przyciskiem.
