#T INTRO Rozgrzewka i problem: nagłówek skopiowany do każdego ekranu
Rozgrzewka: Czym różni się `Link` od `<a href>`? Co robi `NavLink` z `aria-current`? Dlaczego serwer musi zwracać `index.html` dla każdej ścieżki?

Problem: po dodaniu routingu każdy ekran sam renderuje `Header`, `Sidebar` i `Footer` — pięć kopii tego samego układu. Przy przejściu między ekranami nagłówek jest odmontowywany i montowany od nowa (miga, traci stan rozwiniętego menu użytkownika). Ekran „Ustawienia” ma podstrony (Profil, Powiadomienia, Bezpieczeństwo) z własnym menu bocznym. Rozwiązanie to **trasy zagnieżdżone** z **trasami layoutu** i komponentem `Outlet`.

#T DEFINITION Trasa layoutu i Outlet
Trasa może mieć `children` — trasy podrzędne. Komponent trasy-rodzica renderuje wspólny układ i w miejscu treści umieszcza `<Outlet />` — tam router wstawia aktualną trasę-dziecko. Przy przejściu między dziećmi **layout się nie odmontowuje**: zachowuje stan, a zmienia się tylko zawartość `Outlet`.

- **Trasa layoutu bez ścieżki** (`{ element: <AppLayout />, children: [...] }`) — tylko układ, nie zmienia adresu,
- **trasa indeksowa** (`{ index: true, element: <ProfileSettings /> }`) — dziecko wyświetlane pod adresem rodzica (`/settings` → profil),
- ścieżki dzieci są **względne** do rodzica: `path: 'notifications'` pod `/settings` daje `/settings/notifications`.

#T VISUAL_EXAMPLE Drzewo tras DevDesk
/                         AppLayout (nagłówek, menu boczne, toasty)
├── (index)               Dashboard
├── tickets               TicketsPage
├── my-day                MyDayPage
├── archive               ArchivePage
└── settings              SettingsLayout (menu ustawień + Outlet)
    ├── (index)           ProfileSettings          → /settings
    ├── notifications     NotificationSettings     → /settings/notifications
    └── security          SecuritySettings         → /settings/security

/login                    LoginPage (poza AppLayout — bez nagłówka i menu)

#T CODE_JSX Trasy zagnieżdżone i layout (JSX)
```
// router.jsx
import { createBrowserRouter, NavLink, Outlet } from 'react-router';
import { Header } from './components/Header';
import { Dashboard, TicketsPage, ArchivePage, LoginPage, ProfileSettings, NotificationSettings, SecuritySettings } from './pages';

function AppLayout() {
  return (
    <div className="app-shell">
      <Header />
      <main id="main" className="app-main">
        <Outlet />
      </main>
    </div>
  );
}

function SettingsLayout() {
  return (
    <div className="settings">
      <nav aria-label="Ustawienia">
        <NavLink to="/settings" end>Profil</NavLink>
        <NavLink to="/settings/notifications">Powiadomienia</NavLink>
        <NavLink to="/settings/security">Bezpieczeństwo</NavLink>
      </nav>
      <section className="settings__content"><Outlet /></section>
    </div>
  );
}

export const router = createBrowserRouter([
  { path: '/login', element: <LoginPage /> },
  {
    path: '/',
    element: <AppLayout />,
    children: [
      { index: true, element: <Dashboard /> },
      { path: 'tickets', element: <TicketsPage /> },
      { path: 'archive', element: <ArchivePage /> },
      {
        path: 'settings',
        element: <SettingsLayout />,
        children: [
          { index: true, element: <ProfileSettings /> },
          { path: 'notifications', element: <NotificationSettings /> },
          { path: 'security', element: <SecuritySettings /> },
        ],
      },
    ],
  },
]);
```

#T CODE_TSX Trasy zagnieżdżone i layout (TSX)
Typ `RouteObject[]` opisuje drzewo tras. Kod tras jest identyczny jak w JSX.
```
// router.tsx
import { createBrowserRouter, NavLink, Outlet, type RouteObject } from 'react-router';
import { Header } from './components/Header';
import { Dashboard, TicketsPage, ArchivePage, LoginPage, ProfileSettings, NotificationSettings, SecuritySettings } from './pages';

function AppLayout() {
  return (
    <div className="app-shell">
      <Header />
      <main id="main" className="app-main">
        <Outlet />
      </main>
    </div>
  );
}

function SettingsLayout() {
  return (
    <div className="settings">
      <nav aria-label="Ustawienia">
        <NavLink to="/settings" end>Profil</NavLink>
        <NavLink to="/settings/notifications">Powiadomienia</NavLink>
        <NavLink to="/settings/security">Bezpieczeństwo</NavLink>
      </nav>
      <section className="settings__content"><Outlet /></section>
    </div>
  );
}

export const routes: RouteObject[] = [
  { path: '/login', element: <LoginPage /> },
  {
    path: '/',
    element: <AppLayout />,
    children: [
      { index: true, element: <Dashboard /> },
      { path: 'tickets', element: <TicketsPage /> },
      { path: 'archive', element: <ArchivePage /> },
      {
        path: 'settings',
        element: <SettingsLayout />,
        children: [
          { index: true, element: <ProfileSettings /> },
          { path: 'notifications', element: <NotificationSettings /> },
          { path: 'security', element: <SecuritySettings /> },
        ],
      },
    ],
  },
];

export const router = createBrowserRouter(routes);
```

#T NOTE JSX ↔ TSX — RouteObject i dane dla Outlet
`RouteObject[]` w TSX pozwala wydzielić definicję tras do zmiennej i ją sprawdzić (np. trasa nie może mieć jednocześnie `index: true` i `children` — typy na to nie pozwolą). Layout może też przekazać dane do dziecka przez `<Outlet context={wartość} />`, a dziecko odczyta je `useOutletContext()`. W TSX typ kontekstu podajesz generykiem: `useOutletContext<{ user: User }>()` — kompilator nie sprawdzi jednak, czy layout naprawdę przekazał taki obiekt, więc dla danych współdzielonych przez wiele ekranów zwykle lepszy jest zwykły kontekst React lub cache danych.

#T DEFINITION end i aktywność linków w zagnieżdżeniu
`NavLink` jest aktywny, gdy aktualny adres **zaczyna się** od jego ścieżki — `NavLink to="/settings"` byłby aktywny także pod `/settings/security`. Prop `end` wymaga dokładnego dopasowania. W menu głównym link „Ustawienia” (bez `end`) świeci się na wszystkich podstronach ustawień — tak powinno być; w menu ustawień „Profil” (`to="/settings" end`) — tylko na samym `/settings`.

#T CODE_BASIC Okruszki (breadcrumbs) z aktualnej ścieżki
```
import { Link, useLocation } from 'react-router';

const LABELS: Record<string, string> = { tickets: 'Tickety', settings: 'Ustawienia', notifications: 'Powiadomienia', security: 'Bezpieczeństwo', archive: 'Archiwum' };

export function Breadcrumbs() {
  const { pathname } = useLocation();
  const parts = pathname.split('/').filter(Boolean);
  return (
    <nav aria-label="Ścieżka">
      <ol className="breadcrumbs">
        <li><Link to="/">DevDesk</Link></li>
        {parts.map((part, i) => {
          const to = '/' + parts.slice(0, i + 1).join('/');
          const last = i === parts.length - 1;
          return (
            <li key={to}>
              {last ? <span aria-current="page">{LABELS[part] ?? part}</span> : <Link to={to}>{LABELS[part] ?? part}</Link>}
            </li>
          );
        })}
      </ol>
    </nav>
  );
}
```

#T CODE_PRACTICAL Layout z danymi dla dzieci przez Outlet context
```
import { Outlet, useOutletContext } from 'react-router';

type SettingsCtx = { unsavedChanges: boolean; markDirty: (dirty: boolean) => void };

export function SettingsShell({ value }: { value: SettingsCtx }) {
  return (
    <section>
      {value.unsavedChanges && <p role="status">Masz niezapisane zmiany.</p>}
      <Outlet context={value} />
    </section>
  );
}

export function NotificationSettingsForm() {
  const { markDirty } = useOutletContext<SettingsCtx>();
  return <input type="checkbox" aria-label="Powiadomienia e-mail" onChange={() => markDirty(true)} />;
}
```

#T STEP_BY_STEP Budujemy razem: layout i ustawienia DevDesk
1. Utwórz `AppLayout` z nagłówkiem, menu bocznym i `Outlet`; przenieś do niego wszystko, co było kopiowane w ekranach.
2. Przebuduj router: `/login` poza layoutem, pozostałe ekrany jako dzieci `AppLayout`, dashboard jako trasa indeksowa.
3. Utwórz `SettingsLayout` z menu bocznym i trzema podstronami (przenieś tam zawartość modala profilu z rozdziału 08 albo prostsze formularze).
4. Rozwiń menu użytkownika w nagłówku i przejdź między ekranami — menu zostaje rozwinięte (layout się nie odmontował).
5. Dodaj `Breadcrumbs` nad treścią w `AppLayout`.
6. Sprawdź `end`: „Profil” podświetla się tylko pod `/settings`, a „Ustawienia” w menu głównym — na każdej podstronie ustawień.
7. Odśwież stronę pod `/settings/security` — trafiasz od razu na właściwą podstronę z layoutem.

#T PITFALL Layout renderowany w każdym ekranie
Jeśli ekran sam opakowuje się w `<AppLayout>...</AppLayout>`, przy każdej zmianie ekranu React widzi nowe drzewo pod trasą i montuje layout od nowa (bo zmienia się element trasy na danej pozycji): nagłówek miga, stan znika, efekty w layoucie (np. połączenie SSE) zrywają się i łączą ponownie. Layout należy do trasy-rodzica, a ekrany są jego dziećmi przez `Outlet`.

#T SUMMARY Kryterium akceptacji i podsumowanie
Trasy zagnieżdżone dzielą układ: trasa-rodzic renderuje layout z `<Outlet />`, w którym pojawia się aktywne dziecko. Layout nie odmontowuje się przy zmianie dziecka, więc zachowuje stan. Trasa layoutu może nie mieć ścieżki, trasa indeksowa wyświetla się pod adresem rodzica, ścieżki dzieci są względne. `NavLink` z `end` wymaga dokładnego dopasowania. W TSX `RouteObject[]` opisuje drzewo tras, a `useOutletContext<T>()` typuje dane z layoutu.

Kryterium akceptacji: nagłówek i menu boczne są zdefiniowane raz w `AppLayout` i nie migają przy nawigacji, ekran logowania jest bez layoutu, ustawienia mają trzy podstrony z własnym menu, a okruszki pokazują aktualną ścieżkę.
