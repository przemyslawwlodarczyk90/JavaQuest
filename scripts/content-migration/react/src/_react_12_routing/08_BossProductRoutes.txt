#T INTRO Boss rozdziału 12: sklep z adresami, które da się udostępnić
Wracasz do katalogu produktów z rozdziału 04 — tym razem jako aplikacja wieloekranowa z prawdziwymi adresami. Każdy widok ma być możliwy do odtworzenia z linku, „Wstecz” ma zachowywać się przewidywalnie, a błędy — mieć sensowne komunikaty. Budujesz routing samodzielnie; dane możesz brać z MSW (handlery piszesz sam, według kontraktu poniżej).

#T DEFINITION Brief zadania
Aplikacja „Sklep”:
1. **`/products`** — katalog z filtrami w adresie: `category`, `q` (wyszukiwanie), `sort` (`price-asc`, `price-desc`, `name`, `rating`), `page`, `inStock=1`.
2. **`/products/:productId`** — szczegóły produktu z zakładkami jako podtrasy: opis (indeks), `specs` (parametry), `reviews` (opinie z paginacją).
3. **`/cart`** — koszyk (stan w kontekście lub bibliotece stanu, z zapisem w localStorage); **`/checkout`** — formularz zamówienia (akcja trasy) z ochroną niezapisanych danych.
4. **`/categories/:slug`** — przekierowanie do `/products?category=slug` (z `replace`, żeby „Wstecz” nie wracał do przekierowania).
5. **Layout** z nagłówkiem (logo, wyszukiwarka, licznik koszyka), okruszkami i globalnym paskiem ładowania.
6. **Błędy**: 404 dla nieznanych adresów i nieistniejących produktów (z podpowiedzią wyszukania), komunikat z ponowieniem dla błędu serwera.

#T CODE_JSX Kontrakt API i trasy startowe (JSX)
```
// contract.js
/*
GET /api/products?category=&q=&sort=&page=&pageSize=12&inStock=1 → { items, total, page, pageSize }
GET /api/products/:id                                           → Product | 404
GET /api/products/:id/reviews?page=                             → { items: Review[], total }
POST /api/orders  body: { items: [{ productId, qty }], name, email, address } → 201 { orderId } | 400 { fieldErrors }
*/

// router.jsx — szkielet do uzupełnienia
import { createBrowserRouter, redirect } from 'react-router';

export const router = createBrowserRouter([
  {
    path: '/',
    element: <ShopLayout />,
    errorElement: <RouteError />,
    children: [
      { index: true, loader: () => redirect('/products') },
      { path: 'products', element: <ProductsPage /> },
      // { path: 'products/:productId', ... children: [...] },
      { path: 'categories/:slug', loader: ({ params }) => redirect(`/products?category=${params.slug}`) },
      // { path: 'cart', ... }, { path: 'checkout', action: ..., ... },
      { path: '*', element: <NotFoundPage /> },
    ],
  },
]);
```

#T CODE_TSX Kontrakt API i trasy startowe (TSX)
```
// router.tsx — szkielet do uzupełnienia
import { createBrowserRouter, redirect, type RouteObject } from 'react-router';

export type Product = { id: number; name: string; category: string; priceGrosze: number; rating: number; inStock: boolean; description: string; specs: Record<string, string> };
export type Review = { id: number; author: string; rating: number; text: string };

declare const ShopLayout: () => React.JSX.Element;
declare const ProductsPage: () => React.JSX.Element;
declare const RouteError: () => React.JSX.Element;
declare const NotFoundPage: () => React.JSX.Element;

export const paths = {
  products: (params?: Record<string, string>) => (params ? `/products?${new URLSearchParams(params)}` : '/products'),
  product: (id: number) => `/products/${id}`,
  productTab: (id: number, tab: 'specs' | 'reviews') => `/products/${id}/${tab}`,
  cart: '/cart',
  checkout: '/checkout',
} as const;

const routes: RouteObject[] = [
  {
    path: '/',
    element: <ShopLayout />,
    errorElement: <RouteError />,
    children: [
      { index: true, loader: () => redirect(paths.products()) },
      { path: 'products', element: <ProductsPage /> },
      { path: 'categories/:slug', loader: ({ params }) => redirect(paths.products({ category: params.slug ?? '' })) },
      { path: '*', element: <NotFoundPage /> },
    ],
  },
];

export const router = createBrowserRouter(routes);
```

#T STEP_BY_STEP Kryteria akceptacji
1. Każdy stan katalogu (kategoria, wyszukiwanie, sortowanie, strona, „tylko dostępne”) jest w adresie; skopiowany link odtwarza widok; w komponentach nie ma `useState` dla filtrów.
2. Błędne wartości w adresie (`?page=-1&sort=xxx`) dają wartości domyślne, nie błąd.
3. Szczegóły produktu ładuje loader (z cache TanStack Query); zakładki to podtrasy z własnymi adresami; opinie mają paginację w adresie zakładki.
4. Nieistniejący produkt daje stronę 404 z linkiem „Wyszukaj podobne” (z nazwą lub numerem w wyszukiwarce), a nagłówek sklepu działa nadal.
5. `/categories/laptopy` przekierowuje do `/products?category=laptopy`, a „Wstecz” po przekierowaniu nie wraca do adresu kategorii.
6. Wysłanie zamówienia działa przez akcję trasy `/checkout` (`<Form method="post">`), błędy walidacji pokazują się przy polach, po sukcesie — przekierowanie na `/orders/:orderId` (prosta strona potwierdzenia) i wyczyszczenie koszyka.
7. Opuszczenie `/checkout` z wypełnionym formularzem pyta o potwierdzenie (`useBlocker` + `beforeunload`).
8. Globalny pasek ładowania pojawia się przy wolnych nawigacjach (opóźnienie 150 ms), a linki w menu oznaczają ładowanie (`isPending`).
9. W wersji TSX: ścieżki budowane funkcjami z obiektu `paths`, `useLoaderData<typeof loader>()`, strażnicy typów dla parametrów adresu, `npm run build` bez błędów.

#T NOTE Wskazówka 1 — jedna funkcja parsująca adres katalogu
Napisz czystą funkcję `parseCatalogParams(searchParams)` zwracającą obiekt z poprawnymi typami i wartościami domyślnymi oraz odwrotną `toCatalogParams(filters)`. Używaj ich wszędzie (hook filtrów, budowanie linków w nagłówku, przekierowanie kategorii). Taka para funkcji jest też łatwa do przetestowania (rozdział 14).

#T NOTE Wskazówka 2 — wyszukiwarka w nagłówku
Wyszukiwarka w layoucie zmienia adres katalogu: na stronie `/products` — przez `setSearchParams` (zachowując inne filtry), na innych stronach — przez `navigate(paths.products({ q }))`. Po wejściu na `/products?q=...` z innego miejsca pole wyszukiwarki powinno pokazać aktualny tekst — trzymaj szkic w stanie z `key` zależnym od wartości w adresie.

#T PITFALL Typowe błędy w tym zadaniu
- Zakładki produktu jako stan zamiast podtras — link do opinii nie działa.
- Przekierowanie kategorii przez `useEffect` + `navigate` w komponencie — mignięcie pustej strony i wpis w historii; poprawnie: `loader` zwracający `redirect`.
- Koszyk przechowywany w adresie — adres rośnie i udostępnienie linku do katalogu „przenosi” cudzy koszyk; koszyk to stan aplikacji, nie widoku.
- Strona błędu bez nagłówka sklepu, bo `errorElement` jest tylko na korzeniu — dodaj granicę na trasie produktu.
- `useBlocker` aktywny także po udanym wysłaniu zamówienia — przekierowanie po sukcesie zostaje zablokowane (warunek blokady musi uwzględniać wysłanie).

#T SUMMARY Podsumowanie rozdziału 12
W tym rozdziale nauczyłeś się routingu w SPA: trasy, `Link`, `NavLink` i `useNavigate`; layouty i trasy zagnieżdżone z `Outlet`; parametry ścieżki z walidacją; parametry zapytania jako stan widoku; loadery i akcje tras (także z cache TanStack Query); stany nawigacji i ochronę niezapisanych zmian; strony 404 i granice błędów tras. W TSX: `RouteObject`, `LoaderFunctionArgs`, `useLoaderData<typeof loader>`, strażnicy typów dla adresu i błąd trasy jako `unknown`.

Boss zaliczony, gdy wszystkie dziewięć kryteriów akceptacji jest spełnionych, a każdy ekran sklepu da się otworzyć bezpośrednio z linku w nowej karcie.
