#T INTRO Rozgrzewka i problem: biały ekran po błędzie
Rozgrzewka: Jakie stany ma `useNavigation`? Dlaczego wskaźnik ładowania pokazujesz z opóźnieniem? Jak zablokować wyjście z formularza z niezapisanymi zmianami?

Problem: trzy różne sytuacje kończą się dziś tym samym — białym ekranem albo domyślnym komunikatem routera „Unexpected Application Error”: (1) adres, którego nie ma (`/tikety`), (2) ticket, którego nie ma (`/tickets/99999` — loader rzuca 404), (3) błąd serwera lub sieci w loaderze albo wyjątek w komponencie. Każda z tych sytuacji wymaga **innego komunikatu i innej akcji** dla użytkownika. React Router ma do tego trasę „catch-all” i **granice błędów tras** (`errorElement`).

#T DEFINITION Trasa * i errorElement
- **Trasa `path: '*'`** pasuje do każdego adresu, którego nie dopasowała żadna inna trasa — to Twoja strona 404. Umieszczona wewnątrz layoutu (jako dziecko `AppLayout`) zachowuje nagłówek i menu.
- **`errorElement`** na trasie to granica błędu: gdy loader, akcja albo render komponentu tej trasy (lub jej dzieci bez własnej granicy) rzuci błąd, router zamiast trasy wyświetla `errorElement`. Komponent błędu odczytuje błąd przez `useRouteError()`.
- **`isRouteErrorResponse(error)`** rozpoznaje błędy rzucone jako odpowiedź (`throw data('...', { status: 404 })`) — mają `status` i `data`. Pozostałe błędy to zwykłe wyjątki (`Error`).

Granica błędu najbliższa miejscu błędu „łapie” go; reszta strony (rodzic z layoutem) działa dalej.

#T CODE_JSX Komponent błędu trasy (JSX)
```
// RouteError.jsx
import { isRouteErrorResponse, Link, useNavigate, useRouteError } from 'react-router';

export function RouteError() {
  const error = useRouteError();
  const navigate = useNavigate();

  if (isRouteErrorResponse(error) && error.status === 404) {
    return (
      <section className="error-page">
        <h1>Nie znaleziono</h1>
        <p>{typeof error.data === 'string' ? error.data : 'Ta strona lub zasób nie istnieje.'}</p>
        <Link to="/tickets">Przejdź do listy ticketów</Link>
      </section>
    );
  }

  if (isRouteErrorResponse(error) && error.status === 403) {
    return <section className="error-page"><h1>Brak dostępu</h1><p>Nie masz uprawnień do tego widoku.</p></section>;
  }

  return (
    <section className="error-page" role="alert">
      <h1>Coś poszło nie tak</h1>
      <p>{error instanceof Error ? error.message : 'Nieoczekiwany błąd.'}</p>
      <button type="button" onClick={() => navigate(0)}>Spróbuj ponownie</button>
    </section>
  );
}
```

#T CODE_TSX Komponent błędu trasy (TSX)
`useRouteError()` zwraca `unknown` — błąd może być czymkolwiek. `isRouteErrorResponse` i `instanceof Error` zawężają typ do bezpiecznych gałęzi.
```
// RouteError.tsx
import { isRouteErrorResponse, Link, useNavigate, useRouteError } from 'react-router';

export function RouteError() {
  const error: unknown = useRouteError();
  const navigate = useNavigate();

  if (isRouteErrorResponse(error) && error.status === 404) {
    return (
      <section className="error-page">
        <h1>Nie znaleziono</h1>
        <p>{typeof error.data === 'string' ? error.data : 'Ta strona lub zasób nie istnieje.'}</p>
        <Link to="/tickets">Przejdź do listy ticketów</Link>
      </section>
    );
  }

  if (isRouteErrorResponse(error) && error.status === 403) {
    return <section className="error-page"><h1>Brak dostępu</h1><p>Nie masz uprawnień do tego widoku.</p></section>;
  }

  return (
    <section className="error-page" role="alert">
      <h1>Coś poszło nie tak</h1>
      <p>{error instanceof Error ? error.message : 'Nieoczekiwany błąd.'}</p>
      <button type="button" onClick={() => navigate(0)}>Spróbuj ponownie</button>
    </section>
  );
}
```

#T NOTE JSX ↔ TSX — błąd to unknown
`useRouteError()` w TSX ma typ `unknown`, tak jak parametr `catch`. Dostęp do `error.status` bez `isRouteErrorResponse` albo do `error.message` bez `instanceof Error` jest błędem kompilacji. To dokładnie te sytuacje, w których komponent błędu w JSX sam rzuca wyjątek (np. `error.message` dla odpowiedzi 404 to `undefined`, a `error.data.message` dla tekstu — wyjątek), zamieniając ładną stronę błędu w biały ekran. `navigate(0)` przeładowuje bieżącą trasę (ponownie uruchamia loadery).

#T CODE_BASIC Trasy z granicami błędów i 404
Granica na poziomie ticketu: błąd jednego ticketu pokazuje się w treści, a nagłówek i menu działają dalej. Granica na korzeniu łapie wszystko inne.
```
import { createBrowserRouter, type RouteObject } from 'react-router';
import { RouteError } from './RouteError';

declare const AppLayout: () => React.JSX.Element;
declare const TicketsPage: () => React.JSX.Element;
declare const TicketRoute: () => React.JSX.Element;
declare const NotFoundPage: () => React.JSX.Element;
declare const ticketLoader: () => Promise<unknown>;

const routes: RouteObject[] = [
  {
    path: '/',
    element: <AppLayout />,
    errorElement: <RouteError />, // ostatnia linia obrony
    children: [
      { path: 'tickets', element: <TicketsPage /> },
      { path: 'tickets/:ticketId', loader: ticketLoader, element: <TicketRoute />, errorElement: <RouteError /> },
      { path: '*', element: <NotFoundPage /> },
    ],
  },
];

export const router = createBrowserRouter(routes);
```

#T DEFINITION Brak zasobu a błąd sieci
To dwa różne stany i wymagają różnych komunikatów:
- **404 — zasobu nie ma** (usunięty, zła liczba w adresie): nie ma sensu „Spróbuj ponownie”; zaproponuj przejście do listy lub wyszukiwanie.
- **błąd sieci / 5xx**: zasób może istnieć, problem jest chwilowy — zaproponuj „Spróbuj ponownie”.
- **401**: sesja wygasła — przekieruj do logowania z powrotem na ten sam adres (`/login?redirect=/tickets/42`).
- **403**: zasób istnieje, ale nie dla Ciebie — wyjaśnij i nie pokazuj szczegółów.

Loader powinien zamieniać błędy klienta API na odpowiedzi z kodem: `if (error instanceof ApiError && error.status === 404) throw data('Ticket #42 nie istnieje', { status: 404 })`.

#T CODE_PRACTICAL Strona 404 z podpowiedzią
```
import { Link, useLocation } from 'react-router';

export function NotFoundPage() {
  const { pathname } = useLocation();
  const ticketMatch = /^\/tickets\/(\d+)/.exec(pathname);
  return (
    <section className="error-page">
      <h1>Nie ma takiej strony</h1>
      <p>Adres <code>{pathname}</code> nie istnieje w DevDesk.</p>
      {ticketMatch && <p>Szukasz ticketu? <Link to={`/tickets?q=${ticketMatch[1]}`}>Wyszukaj „{ticketMatch[1]}”</Link></p>}
      <Link to="/">Wróć na dashboard</Link>
    </section>
  );
}
```

#T STEP_BY_STEP Budujemy razem: przewidywalne błędy w DevDesk
1. Dodaj trasę `*` jako dziecko `AppLayout` z `NotFoundPage`.
2. Utwórz `RouteError` i ustaw `errorElement` na korzeniu oraz na trasie ticketu.
3. W `ticketLoader` zamieniaj błędy klienta API: 404 → `throw data('Ticket #N nie istnieje', { status: 404 })`, 403 → status 403; inne błędy przepuść dalej.
4. Sprawdź cztery scenariusze: `/tikety` (404 w layoucie), `/tickets/99999` (komunikat o brakującym tickecie, nagłówek działa), `?scenario=error` dla szczegółów (komunikat z „Spróbuj ponownie”), wyjątek w komponencie (dodaj na chwilę `throw new Error('test')` w `TicketRoute`).
5. Przy 401 w loaderze przekieruj: `throw redirect('/login?redirect=' + encodeURIComponent(new URL(request.url).pathname))`, a po zalogowaniu wróć pod adres z `redirect`.
6. Zadbaj, by każda strona błędu miała nagłówek `h1`, czytelny tekst i jedną główną akcję.

#T PITFALL Jedna strona błędu na wszystko
„Ups, coś poszło nie tak” dla adresu z literówką, nieistniejącego ticketu, braku uprawnień i awarii serwera nie daje użytkownikowi żadnej wskazówki, co zrobić — więc robi najgorsze: odświeża w kółko albo zgłasza błąd do pomocy technicznej. Rozpoznaj rodzaj błędu (`isRouteErrorResponse`, `status`) i dopasuj komunikat oraz akcję.

#T SUMMARY Kryterium akceptacji i podsumowanie
Trasa `path: '*'` (wewnątrz layoutu) obsługuje nieznane adresy. `errorElement` na trasie to granica błędu dla loaderów, akcji i renderu tej trasy i jej dzieci; komponent błędu czyta `useRouteError()` i rozróżnia odpowiedzi (`isRouteErrorResponse` ze `status`) od wyjątków. Brak zasobu (404), brak dostępu (403), wygasła sesja (401) i błąd chwilowy (5xx/sieć) mają osobne komunikaty i akcje. W TSX błąd trasy to `unknown`, co wymusza bezpieczne zawężanie.

Kryterium akceptacji: nieznany adres, nieistniejący ticket, brak uprawnień, błąd serwera i wyjątek w komponencie dają w DevDesk osobne, czytelne komunikaty z właściwą akcją, a nagłówek i menu aplikacji działają nadal.
