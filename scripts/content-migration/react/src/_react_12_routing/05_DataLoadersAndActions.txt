#T INTRO Rozgrzewka i problem: kaskada ładowania
Rozgrzewka: Dlaczego filtry trzymasz w adresie zamiast w `useState`? Kiedy używasz `replace`? Czym jest strażnik typu?

Problem: wejście na `/tickets/42` wygląda tak: router renderuje `TicketLayout` → ten montuje `TicketDetails` → efekt (albo `useQuery`) zaczyna pobierać ticket → dopiero po odpowiedzi renderuje się komentarzy komponent, który zaczyna pobierać komentarze. Dane ładują się **kaskadowo** (jedno po drugim), a ekran przez chwilę pokazuje kilka spinnerów. Router w trybie danych (data mode) ma **loadery**: funkcje, które pobierają dane trasy **równolegle i zanim komponent się wyrenderuje**. Ma też **akcje** do obsługi formularzy.

#T DEFINITION Loader i useLoaderData
`loader` to funkcja w definicji trasy, wywoływana przez router przy nawigacji (przed renderem trasy). Dostaje `{ params, request }` (z `request.signal` do przerwania) i zwraca dane — albo rzuca odpowiedź błędu. Komponent odczytuje wynik `useLoaderData()`. Router uruchamia loadery wszystkich pasujących tras (rodzica i dzieci) **równolegle**, więc nie ma kaskady.

Przy nawigacji do trasy z loaderem router czeka na dane, a stary ekran zostaje na miejscu (stan `useNavigation().state === 'loading'`) — wskaźnik ładowania pokazujesz globalnie (następna lekcja).

#T CODE_JSX Loader ticketu i komentarzy (JSX)
Oba pobrania startują równocześnie. Brak ticketu rzuca odpowiedź 404, którą obsłuży `errorElement` (lekcja 7).
```
// ticketRoute.jsx
import { data, useLoaderData } from 'react-router';
import { fetchTicket, fetchComments } from '../api/tickets';

export async function ticketLoader({ params, request }) {
  const id = Number(params.ticketId);
  if (!Number.isInteger(id) || id <= 0) throw data('Niepoprawny numer ticketu', { status: 400 });

  const [ticket, comments] = await Promise.all([
    fetchTicket(id, request.signal),
    fetchComments(id, request.signal),
  ]);
  if (!ticket) throw data('Nie znaleziono ticketu', { status: 404 });
  return { ticket, comments };
}

export function TicketRoute() {
  const { ticket, comments } = useLoaderData();
  return (
    <article>
      <h1>#{ticket.id} {ticket.title}</h1>
      <ul>{comments.map((c) => <li key={c.id}>{c.text}</li>)}</ul>
    </article>
  );
}

// { path: 'tickets/:ticketId', loader: ticketLoader, element: <TicketRoute /> }
```

#T CODE_TSX Loader ticketu i komentarzy (TSX)
Typ danych w komponencie wyprowadzasz z loadera: `useLoaderData<typeof ticketLoader>()` — zmiana tego, co zwraca loader, od razu zmienia typy w komponencie.
```
// ticketRoute.tsx
import { data, useLoaderData, type LoaderFunctionArgs } from 'react-router';

type Ticket = { id: number; title: string };
type Comment = { id: number; text: string };
declare function fetchTicket(id: number, signal: AbortSignal): Promise<Ticket | null>;
declare function fetchComments(id: number, signal: AbortSignal): Promise<Comment[]>;

export async function ticketLoader({ params, request }: LoaderFunctionArgs) {
  const id = Number(params.ticketId);
  if (!Number.isInteger(id) || id <= 0) throw data('Niepoprawny numer ticketu', { status: 400 });

  const [ticket, comments] = await Promise.all([
    fetchTicket(id, request.signal),
    fetchComments(id, request.signal),
  ]);
  if (!ticket) throw data('Nie znaleziono ticketu', { status: 404 });
  return { ticket, comments };
}

export function TicketRoute() {
  const { ticket, comments } = useLoaderData<typeof ticketLoader>();
  return (
    <article>
      <h1>#{ticket.id} {ticket.title}</h1>
      <ul>{comments.map((c) => <li key={c.id}>{c.text}</li>)}</ul>
    </article>
  );
}
```

#T NOTE JSX ↔ TSX — typ z loadera
`useLoaderData<typeof ticketLoader>()` to wygodny wzorzec: typ wynika z implementacji loadera, nie z ręcznie pisanego interfejsu. Po `throw` dla brakującego ticketu TypeScript wie, że zwracany `ticket` nie jest `null`. W JSX `useLoaderData()` zwraca „cokolwiek”, a dostęp `ticket.title` przy zmianie kształtu danych w loaderze nie zostanie wykryty. `LoaderFunctionArgs` typuje `params` (wartości `string | undefined`) i `request` (z `signal`).

#T DEFINITION Akcje i Form
`action` to funkcja trasy obsługująca **wysłanie formularza** do tej trasy. Komponent `<Form method="post">` z React Router działa jak zwykły formularz HTML, ale zamiast przeładowania strony router wywołuje akcję z `request` (dane przez `await request.formData()`). Po akcji router **automatycznie ponownie wywołuje loadery** aktywnych tras (rewalidacja), więc ekran pokazuje świeże dane bez ręcznego odświeżania. Akcja może zwrócić dane (np. błędy walidacji — `useActionData()`) albo przekierować (`redirect('/tickets/42')`).

#T CODE_BASIC Akcja dodawania komentarza
```
import { data, Form, useActionData, useNavigation, type ActionFunctionArgs } from 'react-router';

declare function addComment(ticketId: number, text: string): Promise<void>;

export async function commentAction({ params, request }: ActionFunctionArgs) {
  const form = await request.formData();
  const text = String(form.get('text') ?? '').trim();
  if (text.length < 3) return data({ error: 'Komentarz musi mieć co najmniej 3 znaki.' }, { status: 400 });
  await addComment(Number(params.ticketId), text);
  return { error: null };
}

export function CommentForm() {
  const result = useActionData<typeof commentAction>();
  const navigation = useNavigation();
  const sending = navigation.state === 'submitting';
  return (
    <Form method="post">
      <label htmlFor="comment">Komentarz</label>
      <textarea id="comment" name="text" rows={3} />
      {result?.error && <p role="alert">{result.error}</p>}
      <button type="submit" disabled={sending}>{sending ? 'Wysyłanie…' : 'Dodaj'}</button>
    </Form>
  );
}

// { path: 'tickets/:ticketId', loader: ticketLoader, action: commentAction, element: <TicketRoute /> }
```

#T CODE_PRACTICAL Loader z TanStack Query: najlepsze z obu światów
Loader może **zapełnić cache** TanStack Query (`ensureQueryData`) — dane są gotowe przed renderem, a komponent dalej używa `useQuery` (odświeżanie w tle, mutacje, unieważnianie).
```
import type { QueryClient } from '@tanstack/react-query';
import { useQuery } from '@tanstack/react-query';
import { useParams, type LoaderFunctionArgs } from 'react-router';

type Ticket = { id: number; title: string };
declare function fetchTicket(id: number, signal?: AbortSignal): Promise<Ticket>;

const ticketQuery = (id: number) => ({
  queryKey: ['tickets', 'detail', id] as const,
  queryFn: ({ signal }: { signal?: AbortSignal }) => fetchTicket(id, signal),
});

export const makeTicketLoader = (queryClient: QueryClient) => async ({ params }: LoaderFunctionArgs) => {
  const id = Number(params.ticketId);
  await queryClient.ensureQueryData(ticketQuery(id)); // z cache albo z serwera — przed renderem
  return null;
};

export function TicketScreen() {
  const id = Number(useParams().ticketId);
  const { data } = useQuery(ticketQuery(id)); // dane już są w cache
  return <h1>{data ? `#${data.id} ${data.title}` : null}</h1>;
}

// const router = createBrowserRouter([{ path: 'tickets/:ticketId', loader: makeTicketLoader(queryClient), element: <TicketScreen /> }]);
```

#T STEP_BY_STEP Budujemy razem: loadery w DevDesk
1. Dodaj `loader` do trasy `tickets/:ticketId`, który przez `ensureQueryData` ładuje równolegle ticket i komentarze (dwa zapytania w `Promise.all`).
2. W komponentach zostaw `useQuery` z tymi samymi definicjami zapytań — w Network widać dwa równoległe żądania zamiast kaskady.
3. Dodaj `action` do tej samej trasy dla formularza komentarza (`<Form method="post">`); w akcji wywołaj mutację przez klienta API i unieważnij zapytanie komentarzy.
4. Sprawdź: po dodaniu komentarza lista odświeża się bez ręcznego kodu; błąd walidacji z akcji pojawia się pod polem.
5. Dodaj loader do trasy ustawień, który pobiera profil użytkownika przed renderem — podstrony ustawień nie pokazują już spinnera.
6. Porównaj wrażenia: przejście do ticketu z loaderem (stary ekran zostaje do czasu danych) a bez loadera (pusty ekran ze spinnerem). W następnej lekcji dodasz globalny wskaźnik nawigacji.

#T PITFALL Loader, który czeka na wszystko
Loader blokuje wyświetlenie trasy do czasu zakończenia. Jeśli pobierasz w nim coś wolnego i mało ważnego (np. statystyki z ostatniego roku), cały ekran czeka. Ważne dane ładuj w loaderze, a pozostałe — w komponencie (`useQuery` z własnym stanem ładowania) albo zwróć z loadera **obietnicę bez `await`** i wyświetl ją przez `Suspense`/`Await` (strumieniowanie, rozdział 17).

#T SUMMARY Kryterium akceptacji i podsumowanie
Loader trasy pobiera dane przed renderem, równolegle dla wszystkich pasujących tras, z `request.signal` do przerwania; komponent czyta je `useLoaderData()`. Błędy rzucasz odpowiedzią (`throw data(..., { status: 404 })`). Akcja obsługuje `<Form method="post">`, a po niej router ponownie uruchamia loadery. Loader może zapełniać cache TanStack Query (`ensureQueryData`), a komponent nadal używa `useQuery`. W TSX `useLoaderData<typeof loader>()` i `useActionData<typeof action>()` wyprowadzają typy z implementacji.

Kryterium akceptacji: wejście na `/tickets/:id` ładuje ticket i komentarze równolegle przed renderem (dwa jednoczesne żądania w Network), formularz komentarza działa przez akcję trasy z automatycznym odświeżeniem listy i błędem walidacji pod polem.
