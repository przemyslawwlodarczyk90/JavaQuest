#T INTRO Rozgrzewka i problem: link do konkretnego ticketu
Rozgrzewka: Co robi `Outlet`? Czym jest trasa indeksowa? Dlaczego layout nie powinien być renderowany w każdym ekranie?

Problem: Anna chce wysłać Piotrowi link „zobacz ticket #481”. Dziś szczegóły ticketu to stan `selectedId` w tabeli — po odświeżeniu znikają, a adres zawsze brzmi `/tickets`. Ticket potrzebuje **własnego adresu** `/tickets/481`, który działa po odświeżeniu, w nowej karcie i po wysłaniu komuś. To parametr trasy.

#T DEFINITION Parametry ścieżki
Segment ścieżki zaczynający się dwukropkiem to **parametr**: `path: 'tickets/:ticketId'`. Adres `/tickets/481` pasuje do tej trasy, a komponent odczytuje wartość hookiem `useParams()` → `{ ticketId: '481' }`. Parametry są zawsze **tekstami** (adres to tekst) i mogą nie istnieć (gdy komponent jest użyty pod inną trasą) — trzeba je przekonwertować i zwalidować. Parametr opcjonalny zapisujesz ze znakiem zapytania (`':tab?'`), a „resztę ścieżki” — gwiazdką (`'files/*'`).

#T CODE_JSX Ekran szczegółów ticketu (JSX)
```
// TicketDetailPage.jsx
import { Link, useParams } from 'react-router';
import { useTicketDetail } from '../queries/tickets';

export function TicketDetailPage() {
  const { ticketId } = useParams();
  const id = Number(ticketId);
  const valid = Number.isInteger(id) && id > 0;
  const query = useTicketDetail(valid ? id : null);

  if (!valid) return <p role="alert">Niepoprawny numer ticketu: „{ticketId}”.</p>;
  if (query.isPending) return <p aria-busy="true">Ładowanie ticketu #{id}…</p>;
  if (query.isError) return <p role="alert">Nie udało się wczytać ticketu #{id}.</p>;

  return (
    <article>
      <Link to="/tickets">← Wróć do listy</Link>
      <h1>#{query.data.id} {query.data.title}</h1>
      <p>{query.data.description}</p>
    </article>
  );
}

// trasa: { path: 'tickets/:ticketId', element: <TicketDetailPage /> }
```

#T CODE_TSX Ekran szczegółów ticketu (TSX)
`useParams()` w trybie biblioteki zwraca `Readonly<Partial<Record<string, string>>>` — każdy parametr to `string | undefined`. Generyk `useParams<'ticketId'>()` zawęża nazwy kluczy, ale wartość nadal może być `undefined`.
```
// TicketDetailPage.tsx
import { Link, useParams } from 'react-router';
import { useQuery } from '@tanstack/react-query';

type Ticket = { id: number; title: string; description: string };
declare function fetchTicket(id: number, signal: AbortSignal): Promise<Ticket>;

function parseTicketId(raw: string | undefined): number | null {
  const id = Number(raw);
  return Number.isInteger(id) && id > 0 ? id : null;
}

export function TicketDetailPage() {
  const { ticketId } = useParams<'ticketId'>();
  const id = parseTicketId(ticketId);
  const query = useQuery({
    queryKey: ['tickets', 'detail', id],
    queryFn: ({ signal }) => fetchTicket(id!, signal),
    enabled: id !== null,
  });

  if (id === null) return <p role="alert">Niepoprawny numer ticketu: „{ticketId}”.</p>;
  if (query.isPending) return <p aria-busy="true">Ładowanie ticketu #{id}…</p>;
  if (query.isError) return <p role="alert">Nie udało się wczytać ticketu #{id}.</p>;

  return (
    <article>
      <Link to="/tickets">← Wróć do listy</Link>
      <h1>#{query.data.id} {query.data.title}</h1>
      <p>{query.data.description}</p>
    </article>
  );
}
```

#T NOTE JSX ↔ TSX — parametr to string | undefined
To klasyczne miejsce błędów w JSX: `Number(useParams().ticketId)` dla adresu `/tickets/abc` daje `NaN`, a zapytanie leci pod `/api/tickets/NaN`. W TSX typ `string | undefined` zmusza do obsługi braku wartości, a funkcja `parseTicketId(): number | null` — do świadomej walidacji. Kompilator nie sprawdzi natomiast, czy w ścieżce trasy naprawdę jest `:ticketId` (literówka `:tickedId` w definicji trasy da `undefined` w obu wersjach) — trzymaj nazwy parametrów i budowanie ścieżek w jednym miejscu.

#T CODE_PRACTICAL Zakładki ticketu jako podtrasy
Zakładka w adresie (`/tickets/42/activity`) sprawia, że link do konkretnej zakładki też działa. Trasa-rodzic ładuje ticket raz, zakładki dostają go przez `Outlet` context lub z cache zapytania.
```
import { NavLink, Outlet, useParams } from 'react-router';

export function TicketLayout() {
  const { ticketId } = useParams<'ticketId'>();
  return (
    <article>
      <nav aria-label="Sekcje ticketu" className="tabs">
        <NavLink to={`/tickets/${ticketId}`} end>Szczegóły</NavLink>
        <NavLink to={`/tickets/${ticketId}/activity`}>Aktywność</NavLink>
        <NavLink to={`/tickets/${ticketId}/history`}>Historia</NavLink>
      </nav>
      <Outlet />
    </article>
  );
}
```

#T STEP_BY_STEP Budujemy razem: ticket pod własnym adresem
1. Dodaj trasę `tickets/:ticketId` z `TicketLayout` i trzema podtrasami zakładek.
2. Tytuł ticketu w tabeli zamień na `<Link to={routes.ticket(t.id)}>` — kliknięcie przenosi na ekran szczegółów.
3. W `TicketDetails` odczytaj i zwaliduj parametr, pobierz ticket przez `useQuery` (cache z tabeli przyspieszy wyświetlenie, jeśli wcześniej pobrałeś szczegóły).
4. Otwórz `/tickets/481` w nowej karcie, odśwież stronę, wklej adres w innej przeglądarce (po zalogowaniu) — zawsze ten sam ticket.
5. Wpisz `/tickets/abc` i `/tickets/-5` — czytelny komunikat zamiast zapytania do API.
6. Po zamknięciu ticketu na ekranie szczegółów zostań na nim (dane odświeżą się przez unieważnienie), a po usunięciu przejdź do listy przez `navigate(routes.tickets, { replace: true })` — „Wstecz” nie wróci na usunięty ticket.
7. Komentarz dodany w zakładce „Aktywność” — po odświeżeniu adres `/tickets/42/activity` otwiera od razu tę zakładkę.

#T PITFALL Stan zamiast parametru dla rzeczy, które mają adres
Jeśli coś ma być widoczne po odświeżeniu, do wysłania komuś albo dostępne przez „Wstecz” — należy do adresu (parametr trasy lub zapytania), a nie do `useState`. Typowe przykłady: wybrany rekord, aktywna zakładka szczegółów, strona listy, filtry. Stan lokalny zostaw dla rzeczy ulotnych: rozwinięte menu, tekst wpisywany w formularzu, podświetlenie wiersza.

#T SUMMARY Kryterium akceptacji i podsumowanie
Parametry ścieżki (`:ticketId`) odczytujesz `useParams()`; są zawsze tekstami i mogą nie istnieć, więc konwertujesz je i walidujesz przed użyciem. Ścieżki z parametrami budujesz funkcjami w jednym miejscu. Zakładki ekranu mogą być podtrasami — wtedy też mają adresy. Rzeczy, które mają przetrwać odświeżenie i dać się udostępnić, należą do adresu, nie do stanu. W TSX `useParams` zwraca `string | undefined`, co wymusza walidację.

Kryterium akceptacji: każdy ticket ma adres `/tickets/:id` (z zakładkami `/activity` i `/history`), który działa po odświeżeniu i w nowej karcie, niepoprawny numer daje komunikat bez zapytania do API, a po usunięciu ticketu „Wstecz” nie wraca do usuniętego rekordu.
