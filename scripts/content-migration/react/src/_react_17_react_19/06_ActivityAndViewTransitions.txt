#T INTRO Rozgrzewka i problem: ukrywanie bez utraty stanu i płynne przejścia
Rozgrzewka: Gdzie React umieszcza `<title>` wyrenderowany w komponencie? Dlaczego tytuł składasz w jeden tekst? Do czego służy `preconnect`?

Problem 1: w DevDesk panel boczny z filtrami i panel szczegółów można zwinąć. Gdy znikają przez renderowanie warunkowe, tracą stan (przewinięcie, wpisane filtry, rozwinięte sekcje), a gdy są ukryte przez CSS, nadal wykonują efekty i renderują się przy każdej zmianie danych. Problem 2: przejście z listy do szczegółów ticketu jest „twarde” — ekran nagle się podmienia, użytkownik traci kontekst. React 19.2+ ma dwa nowe narzędzia: **`<Activity>`** (ukrywanie z zachowaniem stanu) i **`<ViewTransition>`** (animowane przejścia oparte na View Transitions API przeglądarki).

#T DEFINITION Activity: ukryj, ale zachowaj
`<Activity mode="visible" | "hidden">` opakowuje fragment drzewa:
- **`visible`** — zwykłe renderowanie,
- **`hidden`** — treść jest ukryta (`display: none`), ale komponenty **zachowują stan i DOM**; ich efekty są **odmontowane** (subskrypcje, timery wstrzymane), a aktualizacje w środku renderują się z najniższym priorytetem (w tle, gdy nic innego się nie dzieje).

Po powrocie do `visible` efekty montują się ponownie, a użytkownik widzi wszystko tak, jak zostawił (z danymi odświeżonymi w tle). `Activity` przydaje się też do **wstępnego renderowania** ukrytych widoków, do których użytkownik prawdopodobnie przejdzie (np. następna zakładka).

#T CODE_JSX Zakładki z Activity (JSX)
Każda zakładka zachowuje stan (wpisany szkic komentarza, przewinięcie listy), a ukryte nie wykonują efektów.
```
// TicketTabsActivity.jsx
import { Activity, useState } from 'react';
import { Details } from './Details';
import { Comments } from './Comments';
import { History } from './History';

export function TicketTabsActivity({ ticketId }) {
  const [tab, setTab] = useState('details');
  return (
    <div>
      <div role="tablist" aria-label="Sekcje">
        <button role="tab" aria-selected={tab === 'details'} onClick={() => setTab('details')}>Szczegóły</button>
        <button role="tab" aria-selected={tab === 'comments'} onClick={() => setTab('comments')}>Komentarze</button>
        <button role="tab" aria-selected={tab === 'history'} onClick={() => setTab('history')}>Historia</button>
      </div>
      <Activity mode={tab === 'details' ? 'visible' : 'hidden'}><Details ticketId={ticketId} /></Activity>
      <Activity mode={tab === 'comments' ? 'visible' : 'hidden'}><Comments ticketId={ticketId} /></Activity>
      <Activity mode={tab === 'history' ? 'visible' : 'hidden'}><History ticketId={ticketId} /></Activity>
    </div>
  );
}
```

#T CODE_TSX Zakładki z Activity (TSX)
Prop `mode` ma typ `'visible' | 'hidden'`; zakładki jako unia literałów.
```
// TicketTabsActivity.tsx
import { Activity, useState } from 'react';

declare function Details(props: { ticketId: number }): React.JSX.Element;
declare function Comments(props: { ticketId: number }): React.JSX.Element;
declare function History(props: { ticketId: number }): React.JSX.Element;

type TabId = 'details' | 'comments' | 'history';
const mode = (active: TabId, tab: TabId) => (active === tab ? 'visible' : 'hidden');

export function TicketTabsActivity({ ticketId }: { ticketId: number }) {
  const [tab, setTab] = useState<TabId>('details');
  return (
    <div>
      <div role="tablist" aria-label="Sekcje">
        <button role="tab" aria-selected={tab === 'details'} onClick={() => setTab('details')}>Szczegóły</button>
        <button role="tab" aria-selected={tab === 'comments'} onClick={() => setTab('comments')}>Komentarze</button>
        <button role="tab" aria-selected={tab === 'history'} onClick={() => setTab('history')}>Historia</button>
      </div>
      <Activity mode={mode(tab, 'details')}><Details ticketId={ticketId} /></Activity>
      <Activity mode={mode(tab, 'comments')}><Comments ticketId={ticketId} /></Activity>
      <Activity mode={mode(tab, 'history')}><History ticketId={ticketId} /></Activity>
    </div>
  );
}
```

#T NOTE JSX ↔ TSX — Activity a trzy sposoby ukrywania
W obu wersjach masz teraz trzy narzędzia (rozdziały 06 i 08): **renderowanie warunkowe** (stan znika, efekty odmontowane), **atrybut `hidden`/CSS** (stan zostaje, efekty działają, rendery w pełnym priorytecie) i **`<Activity mode="hidden">`** (stan i DOM zostają, efekty odmontowane, rendery w tle). TypeScript nie wybierze za Ciebie — ale typ `'visible' | 'hidden'` pilnuje poprawnej wartości propa, a funkcja pomocnicza `mode()` w TSX ma typ wyniku zgodny z tym, czego oczekuje `Activity`.

#T DEFINITION ViewTransition: animacje przejść
View Transitions API przeglądarki robi „zdjęcie” starego widoku i nowego, a potem animuje między nimi (domyślnie przenikanie, z możliwością własnych animacji CSS i „wspólnych elementów” przechodzących z jednego miejsca w drugie). React integruje to przez komponent `<ViewTransition>`:
- animacja uruchamia się, gdy zawartość `ViewTransition` zmienia się **w przejściu** (`startTransition`, akcja, nawigacja routera w przejściu, `Suspense` odsłaniający treść),
- `enter`/`exit`/`update`/`share` — nazwy klas CSS (lub mapy według typu przejścia) dla poszczególnych sytuacji,
- `name` — identyfikator **wspólnego elementu**: element z tą samą nazwą w starym i nowym widoku (np. tytuł ticketu na liście i w nagłówku szczegółów) zostanie animowany z jednej pozycji do drugiej,
- `addTransitionType('nazwa')` w przejściu pozwala wybrać różne animacje (np. „w przód” i „wstecz”).

Przeglądarki bez wsparcia View Transitions po prostu pokazują nowy widok bez animacji.

#T CODE_BASIC Wspólny element: tytuł z listy do szczegółów
```
import { startTransition, useState, ViewTransition } from 'react';

type Ticket = { id: number; title: string };

export function ListToDetail({ tickets }: { tickets: Ticket[] }) {
  const [selected, setSelected] = useState<Ticket | null>(null);

  if (selected) {
    return (
      <article>
        <ViewTransition name={`ticket-title-${selected.id}`}>
          <h1>{selected.title}</h1>
        </ViewTransition>
        <button type="button" onClick={() => startTransition(() => setSelected(null))}>← Wróć</button>
      </article>
    );
  }

  return (
    <ul>
      {tickets.map((t) => (
        <li key={t.id}>
          <ViewTransition name={`ticket-title-${t.id}`}>
            <button type="button" onClick={() => startTransition(() => setSelected(t))}>{t.title}</button>
          </ViewTransition>
        </li>
      ))}
    </ul>
  );
}
```

#T CODE_PRACTICAL Animacje CSS i preferencja ograniczonego ruchu
Animacje przejść definiujesz w CSS (pseudo-elementy `::view-transition-*`). Użytkownicy z `prefers-reduced-motion` nie powinni dostawać ruchu — wystarczy wyłączyć animacje w zapytaniu mediów.
```
/* transitions.css */
::view-transition-old(root),
::view-transition-new(root) {
  animation-duration: 200ms;
}

.slide-in { animation: slide-in 220ms ease-out; }
.slide-out { animation: slide-out 180ms ease-in; }

@keyframes slide-in { from { transform: translateX(24px); opacity: 0; } }
@keyframes slide-out { to { transform: translateX(-24px); opacity: 0; } }

@media (prefers-reduced-motion: reduce) {
  ::view-transition-group(*),
  ::view-transition-old(*),
  ::view-transition-new(*) {
    animation: none !important;
  }
}

/* w komponencie: <ViewTransition enter="slide-in" exit="slide-out">…</ViewTransition> */
```

#T STEP_BY_STEP Budujemy razem: Activity i przejścia w DevDesk
1. Przepisz zakładki ticketu na `Activity`: wpisz szkic komentarza, przełącz na „Historię” i z powrotem — szkic zostaje; w zakładce ukrytej subskrypcja SSE (rozdział 11) jest wstrzymana (sprawdź log połączenia).
2. Owiń zwijany panel filtrów w `Activity` zamiast renderowania warunkowego — filtry i przewinięcie zostają po rozwinięciu.
3. Dodaj `ViewTransition` z nazwą wspólnego elementu dla tytułu ticketu na liście i w nagłówku szczegółów; nawigację wykonaj w przejściu (w React Router dodaj do `<Link>` prop `viewTransition` albo wywołaj `navigate` wewnątrz `startTransition`).
4. Dodaj animacje `slide-in`/`slide-out` dla zmiany ekranu i wyłącz je przy `prefers-reduced-motion` (sprawdź w DevTools: Rendering → Emulate CSS prefers-reduced-motion).
5. Sprawdź w przeglądarce bez obsługi View Transitions (albo wyłączając API) — aplikacja działa bez animacji.
6. Zastanów się, gdzie animacja pomaga zrozumieć zmianę (lista → szczegóły, przeniesienie ticketu między kolumnami), a gdzie tylko spowalnia (otwieranie menu) — zostaw tylko te pierwsze.

#T PITFALL Activity dla rzadko odwiedzanych, ciężkich widoków
`Activity mode="hidden"` trzyma DOM i stan w pamięci. Ukrycie dziesięciu ciężkich ekranów (każdy z tysiącami węzłów) zamiast ich odmontowania zwiększa zużycie pamięci i spowalnia całą stronę. Używaj go dla kilku widoków, między którymi użytkownik często przełącza (zakładki, panele) albo do wstępnego renderowania następnego kroku — a rzadko odwiedzane ekrany odmontowuj.

#T SUMMARY Kryterium akceptacji i podsumowanie
`<Activity mode>` ukrywa fragment drzewa z zachowaniem stanu i DOM, odmontowując efekty i renderując ukrytą treść w tle — pośrednie rozwiązanie między renderowaniem warunkowym a ukryciem CSS, przydatne dla zakładek, paneli i wstępnego renderowania. `<ViewTransition>` animuje zmiany wykonane w przejściach przez View Transitions API: klasy `enter/exit/update`, wspólne elementy przez `name`, typy przejść przez `addTransitionType`. Szanuj `prefers-reduced-motion`. W TSX `mode` i propsy przejść mają ścisłe typy.

Kryterium akceptacji: zakładki ticketu i panel filtrów zachowują stan po ukryciu (`Activity`), ukryte zakładki nie utrzymują aktywnych subskrypcji, tytuł ticketu płynnie przechodzi z listy do szczegółów (wspólny element), a animacje są wyłączone przy ograniczonym ruchu.
