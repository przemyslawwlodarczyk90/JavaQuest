#T INTRO Rozgrzewka i problem: tytuł karty i metadane w SPA
Rozgrzewka: Czym jest akcja w React 19? Dlaczego aktualizację stanu po `await` opakowujesz w kolejne `startTransition`? Co zwraca `useFormStatus`?

Problem: w DevDesk tytuł karty przeglądarki ustawiasz efektem (`document.title = ...`, rozdział 07), a opisu strony, kanonicznego adresu czy podglądu linku (Open Graph) nie ma wcale — po wklejeniu linku do ticketu w komunikatorze widać tylko „DevDesk”. Biblioteki w stylu `react-helmet` rozwiązywały to przez lata. **React 19 obsługuje metadane dokumentu natywnie**: `<title>`, `<meta>` i `<link>` wyrenderowane w dowolnym komponencie trafiają do `<head>`. Do tego arkusze stylów z kolejnością i wskazówki ładowania zasobów.

#T DEFINITION Metadane w komponentach
W React 19 elementy `<title>`, `<meta>` i `<link>` wyrenderowane **gdziekolwiek** w drzewie komponentów React automatycznie przenosi do `<head>` dokumentu (hoisting). Gdy komponent zniknie, jego metadane też znikają. Działa to w SPA i — co ważniejsze — przy renderowaniu na serwerze (frameworki, rozdział 18), gdzie metadane trafiają do HTML-a wysyłanego robotom wyszukiwarek i komunikatorom.

Ograniczenia: `<title>` powinien być jeden na stronę (renderuj go w komponencie ekranu, nie w każdym elemencie listy); tekst w `<title>` musi być jednym tekstem — `{`#${id} ${title}`}` zamiast kilku wyrażeń obok siebie (React zgłosi ostrzeżenie dla wielu dzieci).

#T CODE_JSX Metadane ekranu ticketu (JSX)
```
// TicketMeta.jsx
export function TicketMeta({ ticket }) {
  const title = `#${ticket.id} ${ticket.title} · DevDesk`;
  const description = ticket.description.slice(0, 150) || 'Szczegóły ticketu w DevDesk';
  const url = `https://devdesk.example/tickets/${ticket.id}`;

  return (
    <>
      <title>{title}</title>
      <meta name="description" content={description} />
      <link rel="canonical" href={url} />
      <meta property="og:title" content={title} />
      <meta property="og:description" content={description} />
      <meta property="og:url" content={url} />
    </>
  );
}

// w ekranie ticketu: <TicketMeta ticket={ticket} /> … reszta widoku
```

#T CODE_TSX Metadane ekranu ticketu (TSX)
Elementy `meta` i `link` mają w TSX typy atrybutów — np. `rel` przyjmuje tekst, a `content` musi być tekstem (liczbę trzeba zamienić).
```
// TicketMeta.tsx
import type { Ticket } from '../types';

export function TicketMeta({ ticket }: { ticket: Ticket }) {
  const title = `#${ticket.id} ${ticket.title} · DevDesk`;
  const description = ticket.description.slice(0, 150) || 'Szczegóły ticketu w DevDesk';
  const url = `https://devdesk.example/tickets/${ticket.id}`;

  return (
    <>
      <title>{title}</title>
      <meta name="description" content={description} />
      <link rel="canonical" href={url} />
      <meta property="og:title" content={title} />
      <meta property="og:description" content={description} />
      <meta property="og:url" content={url} />
    </>
  );
}
```

#T NOTE JSX ↔ TSX — tytuł jako jeden tekst
W obu wersjach najczęstszy błąd to `<title>#{ticket.id} {ticket.title}</title>` — JSX tworzy z tego kilka dzieci (tekst i wyrażenia), a `<title>` przyjmuje jeden tekst. TypeScript tego nie zgłosi (dzieci są poprawnym `ReactNode`), React — tak, ostrzeżeniem w konsoli. Dlatego w przykładzie tytuł jest składany wcześniej szablonem tekstowym. Typy pomagają przy atrybutach (`content` jako tekst, `property` dla Open Graph jest dozwolone na `meta`).

#T DEFINITION Arkusze stylów z priorytetem
React 19 obsługuje `<link rel="stylesheet" href="…" precedence="…">` w komponentach: arkusz trafia do `<head>` w kolejności określonej przez `precedence` (np. `"base"`, `"component"`), jest dodany tylko raz (deduplikacja po `href`), a komponent **zawiesza się** (Suspense), dopóki arkusz się nie wczyta — dzięki temu nie ma mignięcia nieostylowanej treści. Przydatne dla ciężkich, rzadko używanych stylów (np. biblioteka edytora ładowana razem z leniwym komponentem).

#T CODE_BASIC Styl edytora ładowany razem z komponentem
```
import type { ReactNode } from 'react';

export function RichEditorStyles() {
  return <link rel="stylesheet" href="/vendor/editor.css" precedence="component" />;
}

export function LazyEditorShell({ children }: { children: ReactNode }) {
  return (
    <>
      <RichEditorStyles />
      {children}
    </>
  );
}
```

#T API_REFERENCE Wskazówki zasobów z react-dom
Funkcje do wywołania w komponencie lub handlerze; React umieszcza odpowiednie znaczniki w `<head>`:
- `prefetchDNS(href)` — wcześniejsze rozwiązanie DNS dla domeny, z której możesz pobierać,
- `preconnect(href)` — nawiązanie połączenia (DNS + TCP + TLS) z wyprzedzeniem,
- `preload(href, { as, type, crossOrigin, fetchPriority })` — pobranie zasobu (czcionka, obraz, styl, skrypt), który na pewno będzie potrzebny,
- `preloadModule(href)` — wstępne pobranie modułu ES,
- `preinit(href, { as: 'style' | 'script' })` — pobranie i od razu wykonanie/zastosowanie skryptu lub stylu,
- `preinitModule(href)` — to samo dla modułu ES.

Wywołania są deduplikowane — możesz je umieścić w komponencie renderowanym wielokrotnie.

#T CODE_PRACTICAL Wstępne ładowanie przy najechaniu na link
Najechanie na ticket w tabeli rozpoczyna pobieranie miniatury załącznika i nawiązuje połączenie z serwerem plików — po kliknięciu ekran pojawia się szybciej.
```
import { preconnect, preload } from 'react-dom';
import { Link } from 'react-router';

type Row = { id: number; title: string; thumbnailUrl: string | null };

export function TicketLink({ ticket }: { ticket: Row }) {
  function warmUp() {
    preconnect('https://files.devdesk.example');
    if (ticket.thumbnailUrl) preload(ticket.thumbnailUrl, { as: 'image', fetchPriority: 'low' });
  }
  return (
    <Link to={`/tickets/${ticket.id}`} onMouseEnter={warmUp} onFocus={warmUp}>
      {ticket.title}
    </Link>
  );
}
```

#T STEP_BY_STEP Budujemy razem: metadane i zasoby w DevDesk
1. Usuń efekty ustawiające `document.title` i zastąp je `<title>` renderowanym w komponentach ekranów (lista: „Tickety (N otwartych) · DevDesk”, szczegóły: `TicketMeta`).
2. Dodaj `meta description`, `link rel="canonical"` i podstawowe znaczniki Open Graph dla ekranu ticketu.
3. Sprawdź w DevTools (Elements → head), że przy przejściu między ekranami metadane się podmieniają, a nie dublują.
4. Przenieś arkusz stylów edytora opisu do `<link rel="stylesheet" precedence>` renderowanego razem z leniwym edytorem i sprawdź brak mignięcia nieostylowanej treści.
5. Dodaj `TicketLink` z `preconnect`/`preload` przy najechaniu i fokusie; w Network zobacz wcześniejsze pobranie.
6. Zanotuj, że w SPA metadane dla robotów i podglądów linków działają tylko częściowo (robot musi wykonać JavaScript) — pełne rozwiązanie to renderowanie na serwerze (rozdział 18).

#T PITFALL Tytuł w wielu komponentach naraz
Jeśli `<title>` renderuje zarówno layout („DevDesk”), jak i ekran („#42 API timeout”), w `<head>` znajdą się dwa tytuły, a przeglądarka użyje jednego z nich (zwykle pierwszego) — wynik zależy od kolejności. Ustal zasadę: tytuł renderuje wyłącznie komponent ekranu (trasy), a layout nie renderuje go wcale.

#T SUMMARY Kryterium akceptacji i podsumowanie
React 19 przenosi `<title>`, `<meta>` i `<link>` z dowolnego komponentu do `<head>` i usuwa je, gdy komponent znika — bez bibliotek typu Helmet i bez efektów. Tytuł składaj w jeden tekst i renderuj go tylko w komponencie ekranu. `<link rel="stylesheet" precedence>` ładuje arkusz z kolejnością, deduplikacją i zawieszeniem do czasu wczytania. Funkcje `prefetchDNS`, `preconnect`, `preload`, `preinit` z `react-dom` dodają wskazówki zasobów. Pełna korzyść dla robotów i podglądów linków pojawia się przy renderowaniu na serwerze.

Kryterium akceptacji: każdy ekran DevDesk ma własny tytuł karty bez efektów, ekran ticketu ma opis, adres kanoniczny i znaczniki Open Graph, styl edytora ładuje się z komponentem bez mignięcia, a najechanie na link ticketu rozpoczyna wstępne ładowanie zasobów.
