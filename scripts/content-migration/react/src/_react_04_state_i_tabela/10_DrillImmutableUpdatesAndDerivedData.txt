#T INTRO Trening: niemutowalne aktualizacje i dane wyliczane
React porównuje stan po referencji: jeśli przekażesz setterowi **ten sam** obiekt czy tablicę, uzna, że nic się nie zmieniło. Dlatego każda zmiana tablicy lub obiektu w stanie to stworzenie nowej kopii z poprawką. Ten trening to dwanaście zadań, po których operacje „dodaj, usuń, zamień, wstaw, przesuń, zaktualizuj zagnieżdżone pole” będziesz pisać odruchowo.

Ściąga, którą masz mieć w głowie:

- dodanie: zamiast `push` / `unshift` → `[...arr, x]` / `[x, ...arr]`,
- usunięcie: zamiast `splice`, `pop`, `shift` → `filter` albo `toSpliced`,
- zamiana: zamiast `arr[i] = x` → `map` albo `with(i, x)`,
- sortowanie: zamiast `sort` / `reverse` → `toSorted` / `toReversed`.

Wszystkie zadania budują jedną aplikację: listę zadań `TodoBoard`. Każde rozwiązanie pokazuje tylko nowy fragment — w swoim projekcie dopisuj kolejne funkcje do tego samego komponentu.

#T STEP_BY_STEP Zadanie 1 — dodawanie na koniec i na początek
Napisz `TodoBoard` ze stanem `todos` — tablicą obiektów `{ id, title, done }` (dwa przykładowe zadania na start).

Wymagania:
1. Pole tekstowe (input kontrolowany) i przycisk „Dodaj na koniec”.
2. Drugi przycisk „Dodaj na początek”.
3. ID z `crypto.randomUUID()`, `done: false`, tytuł przycięty `trim()`; pusty tytuł nie dodaje niczego.
4. Po dodaniu pole się czyści.

Sprawdź się: w kodzie nie ma ani `push`, ani `unshift`.

#T CODE_JSX Rozwiązanie 1 (JSX)
```
// TodoBoard.jsx
import { useState } from 'react';

const INITIAL = [
  { id: 'a', title: 'Przeczytać o useState', done: true },
  { id: 'b', title: 'Zrobić trening', done: false },
];

export function TodoBoard() {
  const [todos, setTodos] = useState(INITIAL);
  const [title, setTitle] = useState('');

  function add(position) {
    const trimmed = title.trim();
    if (!trimmed) return;
    const todo = { id: crypto.randomUUID(), title: trimmed, done: false };
    setTodos((list) => (position === 'start' ? [todo, ...list] : [...list, todo]));
    setTitle('');
  }

  return (
    <section>
      <input value={title} onChange={(e) => setTitle(e.target.value)} aria-label="Nowe zadanie" />
      <button type="button" onClick={() => add('end')}>Dodaj na koniec</button>
      <button type="button" onClick={() => add('start')}>Dodaj na początek</button>
      <ul>
        {todos.map((t) => <li key={t.id}>{t.title}</li>)}
      </ul>
    </section>
  );
}
```

#T STEP_BY_STEP Zadanie 2 — usuwanie, przełączanie i edycja jednego elementu
Dopisz do `TodoBoard` trzy operacje na pojedynczym zadaniu. Napisz je jako **czyste funkcje** poza komponentem (`(list, id) => nowaLista`), a w komponencie tylko je wywołuj — łatwo je wtedy przetestować.

Wymagania:
1. `removeTodo(list, id)` — przez `filter`.
2. `toggleTodo(list, id)` — przez `map`; zmieniany element to nowy obiekt `{ ...t, done: !t.done }`, pozostałe zostają **tymi samymi** obiektami.
3. `renameTodo(list, id, title)` — przez `map`.
4. W liście: checkbox przełącza `done`, przycisk „×” usuwa, przycisk „✎” pyta o nowy tytuł (`prompt`) i zmienia nazwę.

Sprawdź się: `toggleTodo(list, 'a')[1] === list[1]` daje `true` — niezmienione elementy nie są kopiowane.

#T CODE_PRACTICAL Użycie operacji w komponencie
Wiersz listy wywołuje funkcje przez setter w formie funkcyjnej — `setTodos((list) => toggleTodo(list, t.id))`. Dzięki temu nawet kilka szybkich kliknięć działa na najświeższej liście.
```
// TodoItems.tsx
import type { Dispatch, SetStateAction } from 'react';
import type { Todo } from './TodoBoard';
import { removeTodo, renameTodo, toggleTodo } from './todoOps';

type TodoItemsProps = { todos: Todo[]; setTodos: Dispatch<SetStateAction<Todo[]>> };

export function TodoItems({ todos, setTodos }: TodoItemsProps) {
  function handleRename(todo: Todo) {
    const title = prompt('Nowy tytuł', todo.title)?.trim();
    if (title) setTodos((list) => renameTodo(list, todo.id, title));
  }

  return (
    <ul>
      {todos.map((t) => (
        <li key={t.id}>
          <label>
            <input type="checkbox" checked={t.done} onChange={() => setTodos((list) => toggleTodo(list, t.id))} />
            {t.title}
          </label>
          <button type="button" aria-label={`Zmień nazwę: ${t.title}`} onClick={() => handleRename(t)}>✎</button>
          <button type="button" aria-label={`Usuń: ${t.title}`} onClick={() => setTodos((list) => removeTodo(list, t.id))}>×</button>
        </li>
      ))}
    </ul>
  );
}
```

#T STEP_BY_STEP Zadanie 3 — wstawianie w środek i przesuwanie
Dopisz dwie operacje zmieniające kolejność.

Wymagania:
1. `insertAfter(list, index, todo)` — wstawia element za podanym indeksem. Napisz dwie wersje: ze `slice` (`[...list.slice(0, i + 1), todo, ...list.slice(i + 1)]`) i z `toSpliced(i + 1, 0, todo)`.
2. `move(list, index, direction)` — zamienia element z sąsiadem (`direction` to `-1` albo `1`); na krawędzi listy zwraca **tę samą** tablicę (brak zmiany = brak renderu).
3. W wierszu przyciski „↑” i „↓” (wyłączone na krawędziach).

Sprawdź się: `move(list, 0, -1) === list` daje `true`.

#T CODE_JSX Rozwiązanie 3 (JSX)
```
// orderOps.js
export const insertAfter = (list, index, todo) => list.toSpliced(index + 1, 0, todo);

// Wersja bez toSpliced (starsze przeglądarki):
export const insertAfterSlice = (list, index, todo) => [
  ...list.slice(0, index + 1),
  todo,
  ...list.slice(index + 1),
];

export function move(list, index, direction) {
  const target = index + direction;
  if (target < 0 || target >= list.length) return list;
  return list.with(index, list[target]).with(target, list[index]);
}
```

#T CODE_TSX Rozwiązanie 3 (TSX)
```
// orderOps.ts
export const insertAfter = <T,>(list: T[], index: number, item: T): T[] => list.toSpliced(index + 1, 0, item);

// Wersja bez toSpliced (starsze przeglądarki):
export const insertAfterSlice = <T,>(list: T[], index: number, item: T): T[] => [
  ...list.slice(0, index + 1),
  item,
  ...list.slice(index + 1),
];

export function move<T>(list: T[], index: number, direction: -1 | 1): T[] {
  const target = index + direction;
  if (target < 0 || target >= list.length) return list;
  return list.with(index, list[target]).with(target, list[index]);
}
```

#T NOTE JSX ↔ TSX — operacje generyczne
W TSX operacje na kolejności nie muszą znać typu `Todo` — generyk `<T>` sprawia, że `move` zadziała dla zadań, produktów i kolumn tabeli, a typ wyniku zgadza się z typem wejścia. Przecinek w `<T,>` w funkcji strzałkowej to podpowiedź dla parsera w pliku `.tsx`, że to generyk, a nie znacznik JSX. `direction: -1 | 1` sprawia, że `move(list, 0, 2)` jest błędem kompilacji; w JSX taki błąd przejdzie po cichu.

#T CODE_BASIC Zadanie 4 — przewidź wynik: mutacja w handlerze
Dla każdego handlera odpowiedz: czy ekran się odświeży? Czy dane w stanie się zmienią? Jaki będzie skutek uboczny?
```
// @check-skip
// A
function handleAdd() {
  todos.push({ id: 'x', title: 'Nowe', done: false });
  setTodos(todos);
}

// B
function handleToggleFirst() {
  todos[0].done = !todos[0].done;
  setTodos([...todos]);
}

// C
function handleSort() {
  setTodos(todos.sort((a, b) => a.title.localeCompare(b.title)));

// D
function handleSortRight() {
  setTodos(todos.toSorted((a, b) => a.title.localeCompare(b.title)));
}
```

#T NOTE Odpowiedź do zadania 4
- **A** — tablica w stanie została zmieniona, ale `setTodos(todos)` dostaje **tę samą** referencję, więc React pomija render. Nowy element „pojawi się” dopiero przy jakimś innym renderze — pozornie losowo.
- **B** — ekran się odświeży (nowa tablica), ale obiekt `todos[0]` został zmutowany. Pierwsza i nowa tablica dzielą ten sam obiekt, więc poprzedni stan też jest „zepsuty”: nie zadziała porównanie poprzedniej i nowej wartości, `memo` w wierszu uzna, że nic się nie zmieniło, a historia (cofnij) pokaże zmienioną wartość.
- **C** — `sort` mutuje i zwraca **tę samą** tablicę, więc to przypadek A: brak renderu.
- **D** — poprawnie: `toSorted` zwraca nową tablicę, a obiekty w środku są nietknięte.

Kopia przez spread jest **płytka**: `[...todos]` to nowa tablica z tymi samymi obiektami. Kopiujesz każdy poziom, który zmieniasz.

```
import { useState } from 'react';
```

#T CODE_JSX Rozwiązanie 7 (JSX)

```
// SelectableTodos.jsx
import { useState } from 'react';

export function SelectableTodos({ todos, onRemoveMany }) {
  const [selected, setSelected] = useState(() => new Set());
  const allSelected = todos.length > 0 && todos.every((t) => selected.has(t.id));

  function toggle(id) {
    setSelected((prev) => {
      const next = new Set(prev);
      if (next.has(id)) next.delete(id);
      else next.add(id);
      return next;
    });
  }

  function toggleAll() {
    setSelected(allSelected ? new Set() : new Set(todos.map((t) => t.id)));
  }

  function removeSelected() {
    onRemoveMany(selected);
    setSelected(new Set());
  }

  return (
    <div>
      <label><input type="checkbox" checked={allSelected} onChange={toggleAll} /> Zaznacz wszystkie</label>
      <ul>
        {todos.map((t) => (
          <li key={t.id}>
            <label><input type="checkbox" checked={selected.has(t.id)} onChange={() => toggle(t.id)} /> {t.title}</label>
          </li>
        ))}
      </ul>
      <button type="button" disabled={selected.size === 0} onClick={removeSelected}>
        Usuń zaznaczone ({selected.size})
      </button>
    </div>
  );
}
```

#T STEP_BY_STEP Zadanie 8 — co jest stanem, a co danymi wyliczanymi
Dopisz do `TodoBoard` filtr i statystyki. Zanim zaczniesz pisać, wypisz na kartce wszystkie dane widoczne na ekranie i oznacz każdą: **stan** albo **wyliczane**.

Wymagania:
1. Przełącznik filtra: „Wszystkie / Do zrobienia / Zrobione”.
2. Wyszukiwarka po tytule (bez rozróżniania wielkości liter).
3. Statystyki: „Zrobione 3 z 7 (43%)”, pasek postępu `<progress>`.
4. Komunikat „Brak zadań pasujących do filtra”, gdy lista po filtrach jest pusta, ale `todos` nie jest.

Sprawdź się: w całej funkcji są dokładnie trzy stany: `todos` (w `TodoBoard`), `filter` i `query`.

#T CODE_JSX Rozwiązanie 8 (JSX)
```
// TodoStats.jsx
import { useState } from 'react';

const FILTERS = { all: 'Wszystkie', open: 'Do zrobienia', done: 'Zrobione' };
const matchesFilter = { all: () => true, open: (t) => !t.done, done: (t) => t.done };

export function FilteredTodos({ todos }) {
  const [filter, setFilter] = useState('all');
  const [query, setQuery] = useState('');

  const doneCount = todos.filter((t) => t.done).length;
  const percent = todos.length === 0 ? 0 : Math.round((doneCount / todos.length) * 100);
  const visible = todos
    .filter(matchesFilter[filter])
    .filter((t) => t.title.toLowerCase().includes(query.trim().toLowerCase()));

  return (
    <section>
      <p>Zrobione {doneCount} z {todos.length} ({percent}%)</p>
      <progress max={todos.length} value={doneCount} />
      <div role="group" aria-label="Filtr">
        {Object.entries(FILTERS).map(([key, label]) => (
          <button key={key} type="button" aria-pressed={filter === key} onClick={() => setFilter(key)}>{label}</button>
        ))}
      </div>
      <input type="search" value={query} onChange={(e) => setQuery(e.target.value)} aria-label="Szukaj zadań" />
      {visible.length === 0 && todos.length > 0
        ? <p>Brak zadań pasujących do filtra</p>
        : <ul>{visible.map((t) => <li key={t.id}>{t.title}</li>)}</ul>}
    </section>
  );
}
```

```
    .filter((t) => t.title.toLowerCase().includes(query.trim().toLowerCase()));

      <p>Zrobione {doneCount} z {todos.length} ({percent}%)</p>
```

#T STEP_BY_STEP Zadanie 10 — słownik zamiast tablicy: liczniki per kategoria
Masz listę wydatków `{ id, category, amount }`. Policz sumy dla kategorii i pozwól zwijać kategorie.

Wymagania:
1. Wydatki jako stan (tablica). Zwinięte kategorie jako stan — obiekt `{ [kategoria]: true }`.
2. Sumy per kategoria wylicz przez `reduce` do obiektu, a kolejność kategorii — malejąco po sumie (`toSorted`).
3. Zwijanie kategorii: `setCollapsed((c) => ({ ...c, [category]: !c[category] }))`.
4. Usuwanie wydatku aktualizuje sumy bez dodatkowego kodu.
5. Wydatki w środku rozwiniętej kategorii wybierz przez `filter` po kategorii — też w renderze.

Sprawdź się: sumy nie są w stanie, a dodanie nowej kategorii wymaga tylko dodania wydatku.

#T CODE_JSX Rozwiązanie 10 (JSX)
```
// Expenses.jsx
import { useState } from 'react';

const INITIAL = [
  { id: 1, category: 'Jedzenie', amount: 42 },
  { id: 2, category: 'Transport', amount: 15 },
  { id: 3, category: 'Jedzenie', amount: 27 },
  { id: 4, category: 'Rozrywka', amount: 60 },
];

export function Expenses() {
  const [expenses, setExpenses] = useState(INITIAL);
  const [collapsed, setCollapsed] = useState({});

  const totals = expenses.reduce((acc, e) => ({ ...acc, [e.category]: (acc[e.category] ?? 0) + e.amount }), {});
  const categories = Object.keys(totals).toSorted((a, b) => totals[b] - totals[a]);

  return (
    <div>
      {categories.map((category) => (
        <section key={category}>
          <button type="button" aria-expanded={!collapsed[category]} onClick={() => setCollapsed((c) => ({ ...c, [category]: !c[category] }))}>
            {category}: {totals[category]} zł
          </button>
          {!collapsed[category] && (
            <ul>
              {expenses.filter((e) => e.category === category).map((e) => (
                <li key={e.id}>
                  {e.amount} zł
                  <button type="button" onClick={() => setExpenses((list) => list.filter((x) => x.id !== e.id))}>×</button>
                </li>
              ))}
            </ul>
          )}
        </section>
      ))}
    </div>
  );
}
```

#T NOTE JSX ↔ TSX — reduce do obiektu
W TSX `reduce` potrzebuje typu akumulatora: `reduce<Record<string, number>>(…, {})`. Bez niego pusty obiekt `{}` ma typ `{}` i `acc[e.category]` jest błędem. W JSX kod działa tak samo, ale literówka w nazwie pola (`e.amout`) da po cichu `NaN` w sumie. Nowsze środowiska (lib ES2024) mają też `Object.groupBy(expenses, (e) => e.category)`, które grupuje elementy jednym wywołaniem — w TS zwraca `Partial<Record<…>>`, więc przy odczycie grupy dopisujesz `?? []`.

```
// UndoableTodos.jsx
import { useState } from 'react';
import { removeTodo, toggleTodo } from './todoOps';

export function UndoableTodos({ initial }) {
  const [history, setHistory] = useState([initial]);
  const [index, setIndex] = useState(0);
  const todos = history[index];

  function commit(next) {
    setHistory([...history.slice(0, index + 1), next]);
    setIndex(index + 1);
  }

  return (
    <section>
      <button type="button" disabled={index === 0} onClick={() => setIndex(index - 1)}>Cofnij</button>
      <button type="button" disabled={index === history.length - 1} onClick={() => setIndex(index + 1)}>Ponów</button>
      <ul>
        {todos.map((t) => (
          <li key={t.id}>
            <label><input type="checkbox" checked={t.done} onChange={() => commit(toggleTodo(todos, t.id))} /> {t.title}</label>
            <button type="button" onClick={() => commit(removeTodo(todos, t.id))}>×</button>
          </li>
        ))}
      </ul>
    </section>
  );
}
```

#T PITFALL Dwa stany zmieniane razem
W zadaniu 12 `history` i `index` zmieniają się zawsze razem. Tu działa to poprawnie, bo oba settery wywołujesz w jednym handlerze i React zrobi jeden render. Gdy takich par przybywa, łatwo o pomyłkę (zmienisz jeden, zapomnisz drugiego). To sygnał, że stan dojrzał do `useReducer` — wrócisz do tego przykładu w rozdziale 06.
