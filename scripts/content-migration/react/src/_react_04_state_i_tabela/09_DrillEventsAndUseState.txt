#T INTRO Trening: zdarzenia i useState na sztywno
Ta lekcja to sama praktyka: dwanaście zadań, które utrwalają podstawowy mechanizm Reacta — **zdarzenie → setter → nowy render**. Bez tego odruchu każdy kolejny temat (formularze, reducer, efekty) będzie się rozjeżdżał.

Jak pracować:
1. Przeczytaj zadanie i kryteria „Sprawdź się”.
2. Napisz rozwiązanie w `.jsx`, uruchom, przeklikaj. Potem przepisz na `.tsx` (typ props, typy zdarzeń, generyk `useState` tam, gdzie trzeba).
3. Porównaj z rozwiązaniem. Zadania „Przewidź wynik” rozwiązuj na kartce, zanim przeczytasz odpowiedź — to one budują model mentalny stanu jako migawki.

Dobrze jest mieć otwarte React DevTools: po każdym kliknięciu zobaczysz, która wartość stanu się zmieniła.

#T STEP_BY_STEP Zadanie 1 — licznik z krokiem i granicami
Napisz `BoundedCounter` z props `min` (domyślnie 0), `max` (domyślnie 10) i `step` (domyślnie 1).

Wymagania:
1. Stan `count` startuje od `min`.
2. Przyciski „−” i „+” zmieniają wartość o `step`, ale nigdy poza zakres (użyj `Math.min` / `Math.max`).
3. Przycisk jest `disabled`, gdy dalsza zmiana w jego kierunku jest niemożliwa.
4. Przycisk „Reset” wraca do `min`.

Sprawdź się: przy `step={3}` i `max={10}` klikanie „+” daje 0, 3, 6, 9, 10, a potem przycisk się wyłącza.

#T CODE_JSX Rozwiązanie 1 (JSX)
```
// BoundedCounter.jsx
import { useState } from 'react';

export function BoundedCounter({ min = 0, max = 10, step = 1 }) {
  const [count, setCount] = useState(min);

  return (
    <div className="counter">
      <button type="button" disabled={count <= min} onClick={() => setCount((c) => Math.max(min, c - step))}>
        −
      </button>
      <output aria-live="polite">{count}</output>
      <button type="button" disabled={count >= max} onClick={() => setCount((c) => Math.min(max, c + step))}>
        +
      </button>
      <button type="button" onClick={() => setCount(min)}>Reset</button>
    </div>
  );
}
```

#T NOTE Dlaczego w rozwiązaniu jest tylko jeden stan
Wersja z dwoma stanami (`liked` i `likes`) działa, ale trzeba pilnować, by zawsze zmieniały się razem — jeden zapomniany setter i liczba się rozjeżdża. #T CODE_BASIC Zadanie 4 — przewidź wynik: trzy wywołania settera
`count` startuje od 0. Ile wyświetli się po **jednym** kliknięciu każdego przycisku (każdy test zaczynasz od 0)? Co wypisze `alert`?
```
// @check-skip
<button onClick={() => {
  setCount(count + 1);
  setCount(count + 1);
  setCount(count + 1);
}}>A</button>

<button onClick={() => {
  setCount((c) => c + 1);
  setCount((c) => c + 1);
  setCount((c) => c + 1);
}}>B</button>

<button onClick={() => {
  setCount(count + 5);
  setCount((c) => c + 1);
}}>C</button>

<button onClick={() => {
  setCount((c) => c + 1);
  setCount(42);
}}>D</button>

<button onClick={() => {
  setCount(count + 1);
  alert(count);
}}>E</button>
```

#T NOTE Odpowiedź do zadania 4
- **A → 1.** W tym renderze `count` to 0, więc trzy razy kolejkujesz „ustaw 0 + 1”. Wynik: 1.
- **B → 3.** Każda funkcja dostaje wynik poprzedniej z kolejki: 0 → 1 → 2 → 3.
- **C → 6.** Najpierw „ustaw 5”, potem funkcja `5 → 6`.
- **D → 42.** Funkcja daje 1, ale potem zwykła wartość 42 zastępuje wynik.
- **E → alert pokaże 0**, a ekran po chwili 1. Setter nie zmienia zmiennej `count` w bieżącym renderze — zmieni się dopiero w następnym wywołaniu komponentu.

React przetwarza kolejkę po zakończeniu handlera (batching) i robi **jeden** render, a nie trzy.

import { useState } from 'react';

export function ScoreBoard() {

  const [away, setAway] = useState(0);

  const addHome = (points) => setHome((h) => h + points);

#T CODE_JSX Rozwiązanie 6 (JSX)
```
// ColorPicker.jsx
import { useState } from 'react';

const PALETTE = [
  { id: 'teal', name: 'Morski', hex: '#0e7490' },
  { id: 'amber', name: 'Bursztyn', hex: '#d97706' },
  { id: 'rose', name: 'Róż', hex: '#e11d48' },
];

export function ColorPicker() {
  const [selectedId, setSelectedId] = useState(null);
  const selected = PALETTE.find((c) => c.id === selectedId);

  function handlePick(id) {
    setSelectedId((current) => (current === id ? null : id));
  }

  return (
    <div>
      <div className="palette">
        {PALETTE.map((color) => (
          <button
            key={color.id}
            type="button"
            aria-label={color.name}
            aria-pressed={color.id === selectedId}
            style={{ background: color.hex, outline: color.id === selectedId ? '3px solid black' : 'none' }}
            onClick={() => handlePick(color.id)}
          />
        ))}
      </div>
      <p>{selected ? `Wybrano: ${selected.name} (${selected.hex})` : 'Nie wybrano koloru'}</p>
    </div>
  );
}
```

#T STEP_BY_STEP Zadanie 7 — stan w rodzicu, zdarzenia z dzieci: ankieta
Napisz `Poll` (rodzic ze stanem) i `PollOption` (dziecko bez stanu).

Wymagania:
1. `Poll` trzyma obiekt głosów `{ react: 0, vue: 0, svelte: 0 }` w jednym stanie.
2. `PollOption` dostaje `label`, `votes`, `percent` i `onVote` — sam niczego nie liczy i nie pamięta.
3. Głos dodaje się niemutowalnie: `setVotes((v) => ({ ...v, [key]: v[key] + 1 }))`.
4. Procent liczy rodzic (uważaj na dzielenie przez zero przy braku głosów).
5. Pod listą „Łącznie głosów: N”.

#T CODE_JSX Rozwiązanie 7 (JSX)
```
// Poll.jsx
import { useState } from 'react';

function PollOption({ label, votes, percent, onVote }) {
  return (
    <li className="poll-option">
      <button type="button" onClick={onVote}>{label}</button>
      <meter min={0} max={100} value={percent} /> {percent}% ({votes})
    </li>
  );
}

const LABELS = { react: 'React', vue: 'Vue', svelte: 'Svelte' };

export function Poll() {
  const [votes, setVotes] = useState({ react: 0, vue: 0, svelte: 0 });
  const total = Object.values(votes).reduce((sum, v) => sum + v, 0);

  function vote(key) {
    setVotes((v) => ({ ...v, [key]: v[key] + 1 }));
  }

  return (
    <section>
      <ul>
        {Object.keys(votes).map((key) => (
          <PollOption
            key={key}
            label={LABELS[key]}
            votes={votes[key]}
            percent={total === 0 ? 0 : Math.round((votes[key] / total) * 100)}
            onVote={() => vote(key)}
          />
        ))}
      </ul>
      <p>Łącznie głosów: {total}</p>
    </section>
  );
}
```

#T STEP_BY_STEP Zadanie 8 — zdarzenia: propagacja i domyślna akcja
Napisz `NotificationCard` — cała karta jest klikalna (oznacza powiadomienie jako przeczytane), ale ma w środku przycisk „Usuń” i link „Szczegóły”.

Wymagania:

2. Kliknięcie w kartę (`<article onClick>`) ustawia `read` na `true`.

4. Link `<a href="/details">Szczegóły</a>` nie przeładowuje strony — `e.preventDefault()` i `console.log('nawigacja')`; kliknięcie linku też nie oznacza karty jako przeczytanej.
5. Nieprzeczytana karta ma klasę `card--unread`.

Sprawdź się: kliknięcie „Usuń” w nieprzeczytanej karcie nie zmienia na chwilę klasy na przeczytaną (sprawdź w DevTools, że `read` nadal jest `false`).

#T CODE_JSX Rozwiązanie 8 (JSX)
```
// NotificationCard.jsx
import { useState } from 'react';

export function NotificationCard({ title }) {
  const [read, setRead] = useState(false);
  const [deleted, setDeleted] = useState(false);

  if (deleted) return null;

  function handleDelete(e) {
    e.stopPropagation();
    setDeleted(true);
  }

  function handleDetails(e) {
    e.preventDefault();
    e.stopPropagation();
    console.log('nawigacja');
  }

  return (
    <article className={read ? 'card' : 'card card--unread'} onClick={() => setRead(true)}>
      <h3>{title}</h3>
      <a href="/details" onClick={handleDetails}>Szczegóły</a>
      <button type="button" onClick={handleDelete}>Usuń</button>
    </article>
  );
}
```

#T PITFALL Hooki przed wczesnym return
W rozwiązaniu `if (deleted) return null;` stoi **po** obu `useState`. Gdyby był przed drugim hookiem, po usunięciu karty React zobaczyłby mniej wywołań hooków niż w poprzednim renderze i zgłosił błąd „Rendered fewer hooks than expected”. Funkcje-handlery mogą stać po wczesnym `return` — to nie hooki.

import { useState } from 'react';

const KEY = 'draft';
const LIMIT = 500;

export function DraftNote() {
  const [text, setText] = useState(() => localStorage.getItem(KEY) ?? '');

  function handleChange(e) {
    setText(e.target.value);
    localStorage.setItem(KEY, e.target.value);

    localStorage.removeItem(KEY);
  }

  return (

      <label htmlFor="draft">Notatka</label>
      <textarea id="draft" value={text} onChange={handleChange} rows={5} />
      <small className={text.length > LIMIT ? 'over' : undefined}>{text.length}/{LIMIT}</small>
      <button type="button" onClick={handleClear}>Wyczyść</button>
    </div>
  );
}

#T CODE_JSX Rozwiązanie 10 (JSX)
```
// Wizard.jsx
import { useState } from 'react';

const STEPS = ['Dane', 'Adres', 'Podsumowanie'];

export function Wizard() {
  const [step, setStep] = useState(0);
  const [finished, setFinished] = useState(false);
  const isLast = step === STEPS.length - 1;

  if (finished) {
    return (
      <div>
        <p>Gotowe!</p>
        <button type="button" onClick={() => { setStep(0); setFinished(false); }}>Zacznij od nowa</button>
      </div>
    );
  }

  return (
    <div className="wizard">
      <ol className="wizard__steps">
        {STEPS.map((name, i) => (
          <li key={name} className={i < step ? 'done' : undefined} aria-current={i === step ? 'step' : undefined}>
            {i < step ? <button type="button" onClick={() => setStep(i)}>{name}</button> : name}
          </li>
        ))}
      </ol>
      <h2>{STEPS[step]}</h2>
      <button type="button" disabled={step === 0} onClick={() => setStep((s) => s - 1)}>Wstecz</button>
      <button type="button" onClick={() => (isLast ? setFinished(true) : setStep((s) => s + 1))}>
        {isLast ? 'Zakończ' : 'Dalej'}
      </button>
    </div>
  );
}
```

#T CODE_BASIC Zadanie 11 — przewidź wynik: migawka w setTimeout
Użytkownik klika „Wyślij za 3 s”, a potem w ciągu tych trzech sekund trzy razy klika „+1”. Co pokaże `alert`? A co pokaże drugi wariant z `useRef`, jeśli już go znasz?
```
// @check-skip
function DelayedMessage() {
  const [count, setCount] = useState(0);

  function handleSend() {
    setTimeout(() => {
      alert(`Wysłano licznik: ${count}`);
    }, 3000);
  }

  return (
    <>
      <p>{count}</p>
      <button onClick={() => setCount((c) => c + 1)}>+1</button>
      <button onClick={handleSend}>Wyślij za 3 s</button>
    </>
  );
}
```

#T NOTE Odpowiedź do zadania 11
`alert` pokaże **0**, choć na ekranie jest już 3. Funkcja przekazana do `setTimeout` powstała w renderze, w którym `count` wynosiło 0, i zapamiętała tę wartość w domknięciu. Kolejne rendery tworzą nowe zmienne `count` — stare domknięcie ich nie widzi. To zamierzone: stan zachowuje się jak migawka, więc wysłana wiadomość odpowiada temu, co użytkownik widział w chwili kliknięcia. Jeśli naprawdę potrzebujesz „najświeższej” wartości w opóźnionym kodzie, użyjesz `useRef` (rozdział 08) — ref nie jest migawką, tylko jednym pudełkiem współdzielonym przez wszystkie rendery.

#T CODE_JSX Rozwiązanie 12 (JSX)

// MiniCart.jsx
import { useState } from 'react';

const PRODUCTS = [
  { id: 'kb', name: 'Klawiatura', price: 79 },
  { id: 'ms', name: 'Mysz', price: 39 },
  { id: 'pd', name: 'Podkładka', price: 19 },
];
const EMPTY = Object.fromEntries(PRODUCTS.map((p) => [p.id, 0]));

export function MiniCart() {
  const [quantities, setQuantities] = useState(EMPTY);

  const change = (id, delta) => setQuantities((q) => ({ ...q, [id]: Math.max(0, q[id] + delta) }));
  const itemsCount = PRODUCTS.reduce((sum, p) => sum + quantities[p.id], 0);
  const total = PRODUCTS.reduce((sum, p) => sum + p.price * quantities[p.id], 0);

  return (
    <section>
      <ul>
        {PRODUCTS.map((p) => (
          <li key={p.id}>
            {p.name} ({p.price} zł)
            <button type="button" disabled={quantities[p.id] === 0} onClick={() => change(p.id, -1)}>−</button>
            {quantities[p.id]}
            <button type="button" onClick={() => change(p.id, 1)}>+</button>
          </li>
        ))}
      </ul>
      <p>Sztuk: {itemsCount}, razem: {total} zł</p>
      {total > 100 && <p className="success">Darmowa dostawa!</p>}
      <button type="button" disabled={itemsCount === 0} onClick={() => setQuantities(EMPTY)}>Wyczyść koszyk</button>
    </section>
  );
}

#T NOTE JSX ↔ TSX — co dopisywaliśmy w tym treningu
- Typ props przy każdym komponencie przyjmującym dane.
- Generyk `useState<string | null>(null)` tylko tam, gdzie wartość startowa nie mówi wszystkiego; `useState(0)`, `useState(false)` i `useState(() => '…')` wystarczają same.
- Typy zdarzeń w handlerach wydzielonych do funkcji: `MouseEvent<HTMLButtonElement>`, `ChangeEvent<HTMLTextAreaElement>`. W handlerach zapisanych inline (`onClick={() => …}`) typ zdarzenia wynika z atrybutu.
- `Record<Klucz, number>` dla obiektów-słowników w stanie — TS wymusza komplet kluczy przy inicjalizacji.

#T SUMMARY Podsumowanie treningu
Przećwiczyłeś pełny cykl stanu: setter planuje render, każda instancja ma własny stan, w danym renderze stan jest migawką, a forma funkcyjna `set(prev => …)` pozwala bezpiecznie kolejkować kilka zmian. Zobaczyłeś też, ile rzeczy **nie** powinno być stanem (polubienia, suma koszyka, lider meczu, procent głosów) oraz jak przekazywać handlery do dzieci bez stanu, zatrzymywać propagację i blokować domyślną akcję przeglądarki.

Kryterium zaliczenia: wszystkie zadania zrobione samodzielnie, poprawne odpowiedzi do zadań 4 i 11, a w zadaniach 3, 6, 7 i 12 w stanie są wyłącznie dane, których nie da się wyliczyć.
