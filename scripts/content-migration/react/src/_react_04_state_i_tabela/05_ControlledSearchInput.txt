#T INTRO Rozgrzewka i problem: wyszukiwarka, która nic nie wie
Rozgrzewka: Dlaczego `tickets.push(x); setTickets(tickets)` nie odświeża ekranu? Jak niemutowalnie zmienić status jednego ticketu w tablicy? Czym jest płytka kopia?

Problem: w pasku narzędzi DevDesk jest pole „Szukaj…”, ale wpisany tekst istnieje tylko w DOM-ie przeglądarki. React go nie zna, więc nie może przefiltrować tabeli ani wyczyścić pola przyciskiem. Rozwiązanie to **input kontrolowany**: wartość pola pochodzi ze stanu React, a każda zmiana przechodzi przez stan.

#T DEFINITION Input kontrolowany
Pole jest kontrolowane, gdy:
1. jego wartość ustawiasz props `value={query}` ze stanu,
2. każdą zmianę obsługujesz w `onChange`, aktualizując stan: `onChange={(e) => setQuery(e.target.value)}`.

Stan jest jedynym źródłem prawdy: to, co widać w polu, zawsze równa się `query`. Dzięki temu możesz pole wyczyścić (`setQuery('')`), wypełnić programowo, przekształcić wpisywany tekst albo użyć jego wartości gdziekolwiek w komponencie.

#T VISUAL_EXAMPLE Obieg wartości w polu kontrolowanym
użytkownik wpisuje „a”
      │
      ▼
onChange(e) → setQuery(e.target.value)   // „a”
      │
      ▼
React renderuje komponent z query = „a”
      │
      ▼
<input value="a" />  → pole pokazuje „a”

Bez `onChange` pole z `value` jest „zamrożone” — React przy każdym renderze przywraca wartość ze stanu.

#T CODE_JSX Pole wyszukiwania (JSX)
```
// SearchInput.jsx
export function SearchInput({ value, onChange }) {
  return (
    <div className="search">
      <label htmlFor="ticket-search">Szukaj</label>
      <input
        id="ticket-search"
        type="search"
        placeholder="Tytuł, tag lub osoba…"
        value={value}
        onChange={(e) => onChange(e.target.value)}
        onKeyDown={(e) => {
          if (e.key === 'Escape') onChange('');
        }}
      />
      {value && (
        <button type="button" onClick={() => onChange('')} aria-label="Wyczyść wyszukiwanie">
          ✕
        </button>
      )}
    </div>
  );
}
```

#T CODE_TSX Pole wyszukiwania (TSX)
`onChange` w props przyjmuje gotowy tekst (`string`), a nie zdarzenie — komponent ukrywa szczegóły DOM-u przed rodzicem.
```
// SearchInput.tsx
type SearchInputProps = {
  value: string;
  onChange: (value: string) => void;
};

export function SearchInput({ value, onChange }: SearchInputProps) {
  return (
    <div className="search">
      <label htmlFor="ticket-search">Szukaj</label>
      <input
        id="ticket-search"
        type="search"
        placeholder="Tytuł, tag lub osoba…"
        value={value}
        onChange={(e) => onChange(e.target.value)}
        onKeyDown={(e) => {
          if (e.key === 'Escape') onChange('');
        }}
      />
      {value && (
        <button type="button" onClick={() => onChange('')} aria-label="Wyczyść wyszukiwanie">
          ✕
        </button>
      )}
    </div>
  );
}
```

#T NOTE JSX ↔ TSX — e.target.value jest zawsze tekstem
W TSX lambda `(e) => ...` w `onChange` dostaje typ `ChangeEvent<HTMLInputElement>`, a `e.target.value` ma typ `string` — nawet w `<input type="number">`. Gdy potrzebujesz liczby, musisz ją jawnie przekonwertować (`Number(e.target.value)`, `e.target.valueAsNumber`), inaczej TypeScript nie pozwoli zapisać tekstu do stanu typu `number`. W JSX zapiszesz tekst „5” do stanu liczbowego bez ostrzeżenia, a `count + 1` da „51”. Gdy handler jest osobną funkcją, typ zapisujesz jawnie: `function handleChange(e: ChangeEvent<HTMLInputElement>)`.

#T DEFINITION Kontrolowany czy niekontrolowany
- **Kontrolowany** — `value` + `onChange`; React zna wartość w każdej chwili. Wybór domyślny, gdy wartość wpływa na resztę UI (filtrowanie, walidacja na bieżąco, licznik znaków).
- **Niekontrolowany** — `defaultValue` (wartość startowa) i odczyt dopiero przy wysyłce formularza (np. przez `FormData`). Prostszy, gdy wartość jest potrzebna tylko raz — zobaczysz to w rozdziale 05.

Nie mieszaj obu trybów w jednym polu i nie zmieniaj trybu w trakcie życia pola — React wypisze ostrzeżenie „A component is changing an uncontrolled input to be controlled”.

#T CODE_WRONG value bez onChange i undefined jako wartość
Pierwsze pole jest tylko do odczytu, drugie przełącza się z niekontrolowanego na kontrolowany, gdy `ticket.title` przestanie być `undefined`.
```
<input value={query} />
<input value={ticket?.title} onChange={(e) => setTitle(e.target.value)} />
```

#T CODE_RIGHT Pełna para i zawsze tekst
```
<input value={query} onChange={(e) => setQuery(e.target.value)} />
<input value={title ?? ''} onChange={(e) => setTitle(e.target.value)} />
```

#T CODE_PRACTICAL Przekształcanie wpisywanego tekstu i licznik znaków
Pole kontrolowane pozwala zmienić tekst przed zapisaniem do stanu: tu tag zawsze małymi literami, bez spacji, maksymalnie 20 znaków.
```
import { useState } from 'react';

export function TagInput({ onAdd }: { onAdd: (tag: string) => void }) {
  const [tag, setTag] = useState('');

  return (
    <div>
      <input
        aria-label="Nowy tag"
        value={tag}
        onChange={(e) => setTag(e.target.value.toLowerCase().replace(/\s+/g, '-').slice(0, 20))}
        onKeyDown={(e) => {
          if (e.key === 'Enter' && tag) {
            onAdd(tag);
            setTag('');
          }
        }}
      />
      <small>{tag.length}/20</small>
    </div>
  );
}
```

#T STEP_BY_STEP Budujemy razem: wyszukiwarka w DevDesk
1. W `Main` dodaj stan `const [query, setQuery] = useState('');`.
2. Utwórz `SearchInput` i umieść go w slocie `start` paska narzędzi: `<SearchInput value={query} onChange={setQuery} />`.
3. Pod polem tymczasowo wyświetl `Szukasz: „{query}”` — sprawdź, że tekst zmienia się z każdym znakiem.
4. Sprawdź przycisk ✕ i klawisz Escape — oba czyszczą pole.
5. Dodaj przycisk „Szukaj: api” w panelu bocznym, który wywołuje `setQuery('api')` — pole wypełnia się samo, bo jest kontrolowane.
6. Dodaj `TagInput` w karcie szczegółów: Enter dopisuje tag do wybranego ticketu (niemutowalnie, `[...t.tags, tag]`).
7. W następnej lekcji `query` zacznie filtrować tabelę.

#T PITFALL Stan pola w złym komponencie
Jeśli `query` będzie stanem wewnątrz `SearchInput`, tabela nie ma do niego dostępu, a przycisk w panelu bocznym nie może go ustawić. Stan trzymaj w komponencie, który jest wspólnym rodzicem wszystkich, którzy go potrzebują (tu `Main`), a pole niech będzie kontrolowane przez props `value`/`onChange`. Ta zasada — podnoszenie stanu — dostanie osobną lekcję w rozdziale 06.

#T SUMMARY Kryterium akceptacji i podsumowanie
Input kontrolowany ma `value` ze stanu i `onChange` aktualizujące stan — stan jest jedynym źródłem prawdy. Pozwala czyścić, wypełniać i przekształcać tekst. Wartość nigdy nie może być `undefined` (używaj `?? ''`). Komponent pola najlepiej udostępnia `value` i `onChange(value: string)`, ukrywając zdarzenie DOM. W TSX `e.target.value` to zawsze `string`.

Kryterium akceptacji: tekst w polu wyszukiwania i stan `query` w `Main` są zawsze zgodne; ✕, Escape i przycisk „Szukaj: api” zmieniają pole; Enter w polu tagów dopisuje tag do wybranego ticketu.
