#T INTRO Rozgrzewka i problem: 300 wierszy na jednym ekranie
Rozgrzewka: Co trzymasz w stanie sortowania, a co wyliczasz? Dlaczego tytuły porównujesz przez `localeCompare(..., 'pl')`? Czym różni się `toSorted` od `sort`?

Problem: gdy ticketów jest kilkaset, tabela jest bardzo długa, a wyszukanie czegoś wzrokiem — niemożliwe. Potrzebna jest paginacja: 10 wierszy na stronę, przyciski „Poprzednia/Następna”, numery stron i wybór liczby wierszy. Paginacja to świetne ćwiczenie łączenia stanu z danymi wyliczanymi — i typowe miejsce na błędy o jeden (off-by-one).

#T DEFINITION Paginacja: dwa pola stanu, reszta wyliczana
Stan: `page` (numer strony, od 1) i `pageSize` (liczba wierszy). Wyliczane:
- `pageCount = Math.max(1, Math.ceil(total / pageSize))`,
- `currentPage = Math.min(page, pageCount)` — zabezpieczenie, gdy po filtrowaniu stron jest mniej,
- `start = (currentPage - 1) * pageSize`,
- `pageItems = sorted.slice(start, start + pageSize)`,
- opis „Wiersze 11–20 z 134”.

Kolejność przetwarzania jest zawsze ta sama: **filtr → sortowanie → strona**. Paginacja przed filtrowaniem dałaby strony z losowymi „dziurami”.

#T VISUAL_EXAMPLE Liczenie zakresu
total = 23, pageSize = 10 → pageCount = ceil(23 / 10) = 3

strona 1: start = 0   → slice(0, 10)  → wiersze 1–10
strona 2: start = 10  → slice(10, 20) → wiersze 11–20
strona 3: start = 20  → slice(20, 30) → wiersze 21–23 (slice nie wychodzi poza tablicę)

filtr zmniejsza total do 4 → pageCount = 1, a page = 3 → currentPage = min(3, 1) = 1 ✔

#T CODE_JSX Funkcja paginacji i pager (JSX)
```
// pagination.jsx — funkcja paginacji i komponent Pager
export function paginate(items, page, pageSize) {
  const pageCount = Math.max(1, Math.ceil(items.length / pageSize));
  const currentPage = Math.min(Math.max(1, page), pageCount);
  const start = (currentPage - 1) * pageSize;
  return {
    pageItems: items.slice(start, start + pageSize),
    currentPage,
    pageCount,
    from: items.length === 0 ? 0 : start + 1,
    to: Math.min(start + pageSize, items.length),
  };
}


export function Pager({ page, pageCount, onPageChange }) {
  return (
    <nav className="pager" aria-label="Paginacja">
      <button type="button" disabled={page <= 1} onClick={() => onPageChange(page - 1)}>← Poprzednia</button>
      {Array.from({ length: pageCount }, (_, i) => i + 1).map((n) => (
        <button key={n} type="button" aria-current={n === page ? 'page' : undefined} onClick={() => onPageChange(n)}>
          {n}
        </button>
      ))}
      <button type="button" disabled={page >= pageCount} onClick={() => onPageChange(page + 1)}>Następna →</button>
    </nav>
  );
}
```

#T CODE_TSX Funkcja paginacji i pager (TSX)
`paginate` jest generyczna — zadziała dla ticketów, użytkowników i produktów, zachowując typ elementów w `pageItems`.
```
// pagination.tsx — funkcja paginacji i komponent Pager
export type PageResult<T> = {
  pageItems: T[];
  currentPage: number;
  pageCount: number;
  from: number;
  to: number;
};

export function paginate<T>(items: readonly T[], page: number, pageSize: number): PageResult<T> {
  const pageCount = Math.max(1, Math.ceil(items.length / pageSize));
  const currentPage = Math.min(Math.max(1, page), pageCount);
  const start = (currentPage - 1) * pageSize;
  return {
    pageItems: items.slice(start, start + pageSize),
    currentPage,
    pageCount,
    from: items.length === 0 ? 0 : start + 1,
    to: Math.min(start + pageSize, items.length),
  };
}

type PagerProps = { page: number; pageCount: number; onPageChange: (page: number) => void };

export function Pager({ page, pageCount, onPageChange }: PagerProps) {
  return (
    <nav className="pager" aria-label="Paginacja">
      <button type="button" disabled={page <= 1} onClick={() => onPageChange(page - 1)}>← Poprzednia</button>
      {Array.from({ length: pageCount }, (_, i) => i + 1).map((n) => (
        <button key={n} type="button" aria-current={n === page ? 'page' : undefined} onClick={() => onPageChange(n)}>
          {n}
        </button>
      ))}
      <button type="button" disabled={page >= pageCount} onClick={() => onPageChange(page + 1)}>Następna →</button>
    </nav>
  );
}
```

#T NOTE JSX ↔ TSX — generyczny helper
`paginate<T>` to praktyczny przykład generyka z rozdziału 01: `paginate(tickets, 1, 10).pageItems` ma typ `Ticket[]`, a `paginate(users, 1, 10).pageItems` — `User[]`. Typ wyniku `PageResult<T>` dokumentuje, co funkcja zwraca. W JSX ta sama funkcja działa identycznie, ale pola zwracanego obiektu znasz tylko z kodu. W TSX `aria-current` ma typ unii (`'page' | 'step' | ... | boolean`) — wpisanie `aria-current="strona"` byłoby błędem.

#T DEFINITION Reset strony po zmianie filtra — w handlerze
Gdy użytkownik jest na stronie 5 i wpisuje nowy tekst wyszukiwania, powinien wrócić na stronę 1. To reakcja na **zdarzenie** (zmianę filtra), więc reset robisz w handlerze tego zdarzenia: `function handleQueryChange(q) { setQuery(q); setPage(1); }`. Nie w `useEffect` obserwującym `query` — taki efekt dodaje drugi render, w którym przez chwilę widać złą stronę. Dodatkowo `currentPage = min(page, pageCount)` chroni przed pustą stroną, gdyby reset gdzieś został pominięty.

#T CODE_WRONG Reset strony efektem
```
useEffect(() => {
  setPage(1);
}, [query, statusFilter]);
```

#T CODE_RIGHT Reset strony w handlerach
```
function handleQueryChange(next) {
  setQuery(next);
  setPage(1);
}

function handleStatusChange(next) {
  setStatusFilter(next);
  setPage(1);
}
```

#T CODE_PRACTICAL Wybór liczby wierszy i opis zakresu
```
type PageSizeSelectProps = { value: number; onChange: (size: number) => void };

export function PageSizeSelect({ value, onChange }: PageSizeSelectProps) {
  return (
    <label>
      Wierszy na stronę{' '}
      <select value={value} onChange={(e) => onChange(Number(e.target.value))}>
        {[10, 25, 50].map((n) => <option key={n} value={n}>{n}</option>)}
      </select>
    </label>
  );
}

export function RangeInfo({ from, to, total }: { from: number; to: number; total: number }) {
  return <p aria-live="polite">{total === 0 ? 'Brak wyników' : `Wiersze ${from}–${to} z ${total}`}</p>;
}
```

#T PITFALL Numeracja od zera i od jedynki
Najczęstszy błąd paginacji to pomieszanie indeksu tablicy (od 0) z numerem strony dla użytkownika (od 1): `slice(page * pageSize, ...)` przy `page` liczonym od 1 pomija pierwszą stronę. Wybierz jedną konwencję (w kursie: `page` od 1) i przeliczaj na indeks tylko w jednym miejscu — w funkcji `paginate`.

#T SUMMARY Kryterium akceptacji i podsumowanie
Paginacja to stan `page` i `pageSize` oraz wyliczane `pageCount`, `currentPage`, `pageItems` i zakres „od–do”. Kolejność: filtr → sort → strona. `currentPage = min(page, pageCount)` chroni przed pustą stroną. Reset strony po zmianie filtra robisz w handlerze zdarzenia, nie w efekcie. W TSX generyczna `paginate<T>` zachowuje typ elementów.

Kryterium akceptacji: przy 120 ticketach tabela pokazuje po 10 (lub 25/50) wierszy, przyciski brzegowe są wyłączane, opis „Wiersze X–Y z Z” jest zawsze poprawny, a zmiana filtra wraca na stronę 1 bez chwilowego mignięcia pustej strony.
