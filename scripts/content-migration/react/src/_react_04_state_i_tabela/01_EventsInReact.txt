Problem: DevDesk wyświetla dane, ale na nic nie reaguje. Kliknięcie wiersza, przycisku „Zamknij” czy „Eksport CSV” nie robi nic. W tej lekcji podłączysz obsługę zdarzeń — na razie z efektem w konsoli i w prostych akcjach, a w następnej lekcji zdarzenia zaczną zmieniać stan i ekran.

#T DEFINITION Zdarzenia w React
Obsługę zdarzeń dodajesz atrybutem w camelCase z funkcją jako wartością: `onClick={handleClick}`, `onChange`, `onSubmit`, `onKeyDown`, `onMouseEnter`, `onFocus`, `onBlur`. Przekazujesz **funkcję**, a nie jej wywołanie — React wywoła ją sam, gdy zdarzenie nastąpi, i przekaże obiekt zdarzenia.

Konwencja nazw: funkcja obsługująca zdarzenie to `handleX` (`handleRowClick`), a prop komponentu przyjmujący taką funkcję to `onX` (`onRowClick`).

#T CODE_JSX Handlery w JSX
```
// TicketActions.jsx
export function TicketActions({ ticket }) {
  function handleClose() {
    console.log('Zamykam ticket', ticket.id);
  }

  function handleCopyLink(event) {
    event.stopPropagation(); // nie przekazuj kliknięcia do wiersza
    navigator.clipboard.writeText(`${location.origin}/tickets/${ticket.id}`);
  }

  return (
    <div className="actions">
      <button type="button" onClick={handleClose}>Zamknij</button>
      <button type="button" onClick={handleCopyLink}>Kopiuj link</button>
      <button type="button" onClick={() => console.log('Edytuj', ticket.id)}>Edytuj</button>
    </div>
  );
}
```

#T CODE_TSX Handlery w TSX
Handler przekazany bezpośrednio (`onClick={handleCopyLink}`) potrzebuje typu parametru — `MouseEvent<HTMLButtonElement>` z Reacta. Lambda zapisana w miejscu (`onClick={() => ...}`) dostaje typ automatycznie.
```
// TicketActions.tsx
import type { MouseEvent } from 'react';
import type { Ticket } from '../types';

export function TicketActions({ ticket }: { ticket: Ticket }) {
  function handleClose() {
    console.log('Zamykam ticket', ticket.id);
  }

  function handleCopyLink(event: MouseEvent<HTMLButtonElement>) {
    event.stopPropagation();
    navigator.clipboard.writeText(`${location.origin}/tickets/${ticket.id}`);
  }

  return (
    <div className="actions">
      <button type="button" onClick={handleClose}>Zamknij</button>
      <button type="button" onClick={handleCopyLink}>Kopiuj link</button>
      <button type="button" onClick={() => console.log('Edytuj', ticket.id)}>Edytuj</button>
    </div>
  );
}
```

#T NOTE JSX ↔ TSX — typy zdarzeń
React ma własne typy zdarzeń, parametryzowane typem elementu: `MouseEvent<HTMLButtonElement>`, `ChangeEvent<HTMLInputElement>`, `KeyboardEvent<HTMLInputElement>`, `FormEvent<HTMLFormElement>`, `FocusEvent<HTMLInputElement>`. Importujesz je z `react` (nie myl z globalnym `MouseEvent` z DOM — to inne typy). Sztuczka: nie pamiętasz typu? Napisz handler jako lambdę w JSX, najedź myszą na `e` — edytor pokaże dokładny typ, który możesz skopiować. W JSX typ zdarzenia znasz tylko z dokumentacji, ale samo zdarzenie działa identycznie.

#T DEFINITION Obiekt zdarzenia (SyntheticEvent)
React przekazuje do handlera własny obiekt zdarzenia, który działa tak samo we wszystkich przeglądarkach i ma te same pola co natywne zdarzenia DOM:
- `event.target` — element, na którym zdarzenie powstało (np. kliknięty `<span>` wewnątrz przycisku),
- `event.currentTarget` — element, do którego podpięty jest handler,
- `event.preventDefault()` — zablokuj domyślne działanie przeglądarki (wysłanie formularza, przejście linku),
- `event.stopPropagation()` — zatrzymaj „wędrowanie” zdarzenia do rodziców,
- `event.key` w zdarzeniach klawiatury, `event.target.value` w zdarzeniach pól formularza.

Oryginalne zdarzenie przeglądarki jest dostępne jako `event.nativeEvent`.

#T VISUAL_EXAMPLE Propagacja: kliknięcie przycisku w wierszu
<tr onClick={selectRow}>               ③ wiersz też dostaje kliknięcie → zaznacza wiersz
  <td>
    <button onClick={closeTicket}>      ① kliknięcie powstaje tutaj → zamyka ticket
      <span>Zamknij</span>             (target = span, currentTarget = button)
    </button>                           ② zdarzenie „bąbelkuje” w górę
  </td>
</tr>

Bez `stopPropagation()` w `closeTicket` kliknięcie „Zamknij” jednocześnie zaznaczy wiersz. Czasem to pożądane, często — nie.

#T CODE_WRONG Wywołanie funkcji zamiast przekazania
Funkcja wykona się podczas renderowania (dla każdego wiersza, przy każdym renderze), a nie po kliknięciu.
```
<button onClick={handleClose()}>Zamknij</button>
<button onClick={console.log('Edytuj', ticket.id)}>Edytuj</button>
```

#T CODE_RIGHT Przekazanie funkcji lub lambdy
```
<button onClick={handleClose}>Zamknij</button>
<button onClick={() => console.log('Edytuj', ticket.id)}>Edytuj</button>
```

#T DEFINITION Przekazywanie argumentu do handlera
Gdy handler potrzebuje danych (ID ticketu), opakuj wywołanie w lambdę: `onClick={() => onSelect(ticket.id)}`. Lambda tworzy się przy każdym renderze — to normalne i nie jest problemem wydajności w typowych listach. Optymalizacjami zajmiemy się dopiero po pomiarze (rozdział 16).

#T CODE_PRACTICAL Wiersz zgłaszający zdarzenia do rodzica
Wiersz nie decyduje, co znaczy „wybór” — przekazuje informację w górę przez props `onSelect` i `onClose`.
```
import type { Ticket } from '../types';

type TicketRowProps = {
  ticket: Ticket;
  onSelect: (id: number) => void;
  onClose: (id: number) => void;
};

export function TicketRow({ ticket, onSelect, onClose }: TicketRowProps) {
  return (
    <tr onClick={() => onSelect(ticket.id)} className="row">
      <td>{ticket.id}</td>
      <td>{ticket.title}</td>
      <td>
        <button
          type="button"
          disabled={ticket.status === 'CLOSED'}
          onClick={(e) => {
            e.stopPropagation();
            onClose(ticket.id);
          }}
        >
          Zamknij
        </button>
      </td>
    </tr>
  );
}
```

#T PITFALL Klikalny wiersz bez obsługi klawiatury
`<tr onClick>` działa myszą, ale użytkownik klawiatury nie może „kliknąć” wiersza — `tr` nie przyjmuje fokusu. Gdy akcja jest ważna, daj w wierszu prawdziwy przycisk lub link (np. tytuł jako `<button>` lub `<a>`), który obsłuży Enter i Spację. Do zasady „interaktywny = semantyczny element” wrócimy w rozdziale o dostępności.

#T SUMMARY Kryterium akceptacji i podsumowanie
Zdarzenia obsługujesz props w camelCase (`onClick`, `onChange`, `onKeyDown`), przekazując funkcję, a nie jej wynik. Argumenty przekazujesz przez lambdę. Obiekt zdarzenia ma `target`, `currentTarget`, `preventDefault()`, `stopPropagation()`. Komponenty-dzieci zgłaszają zdarzenia przez props `onX`. W TSX handler przekazany przez nazwę potrzebuje typu, np. `MouseEvent<HTMLButtonElement>`; lambda w JSX dostaje go automatycznie.

Kryterium akceptacji: kliknięcie wiersza wypisuje w konsoli jego ID, przycisk „Zamknij” wypisuje tylko swoje zdarzenie (bez zaznaczania wiersza) i jest wyłączony dla zamkniętych ticketów, a Escape w polu wyszukiwania wywołuje swój handler.
