#T INTRO Boss rozdziału 04: katalog produktów
W DevDesk zbudowałeś tabelę z wyszukiwaniem, filtrem, sortowaniem i paginacją. Teraz ta sama umiejętność w innej domenie: katalog produktów sklepu internetowego, wyświetlany jako siatka kart. Nie dostajesz gotowej struktury — sam decydujesz, co jest stanem, co jest wyliczane i jak podzielić komponenty. To najważniejszy boss pierwszej części kursu: jeśli przejdziesz go samodzielnie, rozumiesz podstawy Reacta.

#T DEFINITION Brief zadania
Zbuduj stronę „Katalog” z:
1. **Wyszukiwarką** po nazwie i marce (wielkość liter bez znaczenia, ignorowane spacje na początku i końcu).
2. **Filtrem kategorii** (lista rozwijana: Wszystkie + kategorie z danych) i **przełącznikiem** „Tylko dostępne”.
3. **Sortowaniem** (lista rozwijana): cena rosnąco, cena malejąco, nazwa A–Z, ocena malejąco.
4. **Paginacją** po 12 produktów, z informacją „Produkty 13–24 z 57”.
5. **Siatką kart** produktu: nazwa, marka, cena w złotych (format `1 299,00 zł`), ocena (gwiazdki), plakietka „Brak” dla niedostępnych.
6. **Koszykiem w nagłówku**: przycisk „Dodaj do koszyka” na karcie zwiększa licznik produktów w koszyku; przycisk jest wyłączony dla produktów niedostępnych.
7. **Pustym stanem**: „Brak produktów spełniających kryteria” z przyciskiem „Wyczyść filtry”.

#T CODE_JSX Dane i generator (JSX)
```
// data/products.js
const CATEGORIES = ['Laptopy', 'Monitory', 'Akcesoria', 'Audio'];
const BRANDS = ['Lumen', 'Orbis', 'Zenit', 'Polar'];

export const products = Array.from({ length: 57 }, (_, i) => ({
  id: i + 1,
  name: `${CATEGORIES[i % 4].slice(0, -1)} ${100 + i}`,
  brand: BRANDS[(i * 7) % 4],
  category: CATEGORIES[i % 4],
  priceGrosze: 4999 + ((i * 3779) % 600000),
  rating: 1 + ((i * 13) % 50) / 10,
  inStock: i % 5 !== 0,
}));
```

#T CODE_TSX Dane i generator (TSX)
Cena w groszach jako liczba całkowita — unikasz błędów zaokrągleń liczb zmiennoprzecinkowych.
```
// data/products.ts
export type Product = {
  id: number;
  name: string;
  brand: string;
  category: string;
  priceGrosze: number;
  rating: number; // 1.0–5.9
  inStock: boolean;
};

const CATEGORIES = ['Laptopy', 'Monitory', 'Akcesoria', 'Audio'] as const;
const BRANDS = ['Lumen', 'Orbis', 'Zenit', 'Polar'] as const;

export const products: Product[] = Array.from({ length: 57 }, (_, i) => ({
  id: i + 1,
  name: `${CATEGORIES[i % 4].slice(0, -1)} ${100 + i}`,
  brand: BRANDS[(i * 7) % 4],
  category: CATEGORIES[i % 4],
  priceGrosze: 4999 + ((i * 3779) % 600000),
  rating: 1 + ((i * 13) % 50) / 10,
  inStock: i % 5 !== 0,
}));
```

#T STEP_BY_STEP Kryteria akceptacji
1. W kodzie istnieją wyłącznie stany: tekst wyszukiwania, kategoria, „tylko dostępne”, sortowanie, strona, zawartość koszyka. Lista po filtrach, liczba stron, zakres i licznik koszyka są wyliczane.
2. Kolejność przetwarzania: filtr → sort → strona.
3. Zmiana dowolnego filtra lub sortowania wraca na stronę 1 (w handlerze, nie w efekcie).
4. Ceny są formatowane przez `Intl.NumberFormat('pl-PL', { style: 'currency', currency: 'PLN' })`.
5. Sortowanie po nazwie używa `localeCompare(..., 'pl')`; żadna tablica nie jest sortowana w miejscu.
6. Koszyk przechowuje ID produktów z liczbą sztuk (np. obiekt `{ [id]: ilość }`), aktualizowany niemutowalnie; licznik w nagłówku pokazuje sumę sztuk.
7. Karty mają stabilne klucze; pusty wynik pokazuje komunikat i przycisk czyszczący filtry.
8. Kod filtrowania, sortowania i paginacji jest w czystych funkcjach poza komponentami (`paginate` możesz wziąć z DevDesk — sprawdzian, czy była generyczna).
9. W wersji TSX: typ sortowania jako unia (`'price-asc' | 'price-desc' | 'name' | 'rating'`), komparatory w `Record<...>`, `npm run build` bez błędów.

#T NOTE Wskazówka 1 — mapa stanu
Zanim napiszesz kod, wypisz wszystkie dane widoczne na ekranie i zakwalifikuj je: stan / wyliczane / stałe. Lista kategorii do filtra? Wyliczana z produktów (`[...new Set(products.map((p) => p.category))]`) albo stała — na pewno nie stan. Licznik koszyka? Wyliczany z obiektu koszyka. Czy produkt jest w koszyku? Wyliczane.

#T NOTE Wskazówka 2 — sortowanie jako jeden wybór
Lista rozwijana sortowania ma jedną wartość, która opisuje i pole, i kierunek. Zamiast `{ key, direction }` wygodniej trzymać jeden klucz `'price-asc'` i mapę `{ 'price-asc': (a, b) => a.priceGrosze - b.priceGrosze, 'price-desc': (a, b) => b.priceGrosze - a.priceGrosze, ... }`. To inne, prostsze rozwiązanie niż w DevDesk — dopasuj model stanu do interfejsu.

#T NOTE Wskazówka 3 — koszyk niemutowalnie
Dodanie sztuki: `setCart((prev) => ({ ...prev, [id]: (prev[id] ?? 0) + 1 }))`. Suma: `Object.values(cart).reduce((sum, n) => sum + n, 0)`. W TSX typ koszyka: `Record<number, number>`.

#T CODE_PRACTICAL Przykładowe rozwiązanie — logika katalogu (TSX)
Porównaj dopiero po samodzielnym spełnieniu kryteriów. Komponenty kart i nagłówka zbuduj sam.
```
import type { Product } from './data/products';

export type SortOption = 'price-asc' | 'price-desc' | 'name' | 'rating';
export type Filters = { query: string; category: string; onlyInStock: boolean };

const COMPARE: Record<SortOption, (a: Product, b: Product) => number> = {
  'price-asc': (a, b) => a.priceGrosze - b.priceGrosze,
  'price-desc': (a, b) => b.priceGrosze - a.priceGrosze,
  name: (a, b) => a.name.localeCompare(b.name, 'pl'),
  rating: (a, b) => b.rating - a.rating,
};

export function visibleProducts(all: readonly Product[], f: Filters, sort: SortOption): Product[] {
  const q = f.query.trim().toLowerCase();
  return all
    .filter((p) => f.category === 'ALL' || p.category === f.category)
    .filter((p) => !f.onlyInStock || p.inStock)
    .filter((p) => !q || p.name.toLowerCase().includes(q) || p.brand.toLowerCase().includes(q))
    .toSorted(COMPARE[sort]);
}

const pln = new Intl.NumberFormat('pl-PL', { style: 'currency', currency: 'PLN' });

export function formatPrice(grosze: number): string {
  return pln.format(grosze / 100);
}

export function cartCount(cart: Record<number, number>): number {
  return Object.values(cart).reduce((sum, n) => sum + n, 0);
}
```

#T PITFALL Typowe błędy w tym zadaniu
- Stan `filteredProducts` aktualizowany efektem — złamane kryterium 1.
- Reset strony w `useEffect([query, category])` — złamane kryterium 3; widać mignięcie złej strony.
- Ceny jako liczby zmiennoprzecinkowe (`12.99 * 3 = 38.97000000000001`) — dlatego grosze.
- Klucz karty `key={index}` — przy zmianie sortowania przycisk „dodano!” przeskakuje na inny produkt.
- `products.sort(...)` — zmienia dane modułu; po zmianie sortowania „Cena rosnąco” i powrocie do „Nazwa” kolejność bywa inna niż oczekiwana.

#T SUMMARY Podsumowanie rozdziału 04
W tym rozdziale nauczyłeś się obsługiwać zdarzenia, przechowywać stan w `useState`, rozumieć stan jako migawkę i kolejkę aktualizacji, aktualizować obiekty i tablice niemutowalnie, budować inputy kontrolowane, odróżniać stan od danych wyliczanych oraz łączyć filtrowanie, sortowanie i paginację. W TSX: typy zdarzeń, generyki w `useState`, unie dla filtrów i sortowania, `Record` dla komparatorów i generyczna paginacja.

Boss zaliczony, gdy wszystkie dziewięć kryteriów akceptacji jest spełnionych w obu wersjach.
