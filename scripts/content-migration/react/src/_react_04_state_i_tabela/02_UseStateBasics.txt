#T INTRO Rozgrzewka i problem: kliknięcie, którego nie widać
Rozgrzewka: Dlaczego `onClick={handleClose()}` to błąd? Do czego służy `stopPropagation`? Jak nazywamy handler, a jak prop przyjmujący handler?

Problem: kliknięcie wiersza wypisuje ID w konsoli, ale na ekranie nic się nie zmienia. Chcemy, żeby kliknięty wiersz był wyróżniony, a obok tabeli pojawiła się karta szczegółów wybranego ticketu. Zwykła zmienna tu nie zadziała — potrzebujesz **stanu**.

#T DEFINITION Stan komponentu: useState
Stan to dane, które komponent pamięta między renderami i których zmiana powoduje ponowne wyrenderowanie. Tworzysz go hookiem `useState`:

`const [selectedId, setSelectedId] = useState(null);`

- `selectedId` — aktualna wartość w tym renderze,
- `setSelectedId` — funkcja ustawiająca nową wartość i zlecająca Reactowi ponowny render,
- `null` — wartość początkowa, użyta tylko przy pierwszym renderze.

Nawias kwadratowy to destrukturyzacja tablicy (krotki) zwracanej przez `useState` — nazwy wybierasz sam, konwencja to `[coś, setCoś]`.

#T VISUAL_EXAMPLE Dlaczego zwykła zmienna nie wystarczy
let selectedId = null;            ← przy każdym renderze funkcja startuje od nowa: znów null
onClick → selectedId = 42         ← zmienna lokalna zmieniona, ale React nie wie, że ma renderować
                                    → ekran bez zmian

const [selectedId, setSelectedId] = useState(null);
onClick → setSelectedId(42)       ← React zapamiętuje 42 i planuje render
render  → useState zwraca 42      ← wiersz 42 dostaje klasę „selected”

#T CODE_JSX Zaznaczanie wiersza (JSX)
Stan żyje w `Main`, bo zarówno tabela, jak i karta szczegółów muszą znać wybrany ticket.
```
// Main.jsx
import { useState } from 'react';
import { tickets } from '../data/tickets';
import { TicketTable } from './TicketTable';
import { TicketCard } from './TicketCard';

export function Main() {
  const [selectedId, setSelectedId] = useState(null);
  const selected = tickets.find((t) => t.id === selectedId) ?? null;

  return (
    <main className="app-main">
      <TicketTable tickets={tickets} selectedId={selectedId} onSelect={setSelectedId} />
      <TicketCard ticket={selected} />
    </main>
  );
}
```

#T CODE_TSX Zaznaczanie wiersza (TSX)
Wartość startowa `null` nie mówi, jaki typ będzie później, więc podajesz go generykiem: `useState<number | null>(null)`.
```
// Main.tsx
import { useState } from 'react';
import { tickets } from '../data/tickets';
import { TicketTable } from './TicketTable';
import { TicketCard } from './TicketCard';

export function Main() {
  const [selectedId, setSelectedId] = useState<number | null>(null);
  const selected = tickets.find((t) => t.id === selectedId) ?? null;

  return (
    <main className="app-main">
      <TicketTable tickets={tickets} selectedId={selectedId} onSelect={setSelectedId} />
      <TicketCard ticket={selected} />
    </main>
  );
}
```

#T NOTE JSX ↔ TSX — kiedy useState potrzebuje typu
- `useState(0)` → `number`, `useState('')` → `string`, `useState(false)` → `boolean` — typ z wartości startowej, nic nie dopisujesz.
- `useState(null)` → bez generyka TypeScript uzna typ za `null` i `setSelectedId(42)` będzie błędem. Piszesz `useState<number | null>(null)`.
- `useState([])` → bez generyka typ `never[]`; piszesz `useState<Ticket[]>([])`.
- `useState<Theme>('light')` → gdy wartość ma być z unii literałów.

Setter ma typ `Dispatch<SetStateAction<number | null>>` — dlatego możesz go przekazać prosto jako `onSelect={setSelectedId}`, jeśli prop ma typ `(id: number) => void`. W JSX typy nie istnieją, ale zasada „co przechowuję w stanie” warto zapisać w nazwie zmiennej (`selectedId`, a nie `selected`).

#T CODE_BASIC Tabela wyróżniająca wybrany wiersz
```
import clsx from 'clsx';
import type { Ticket } from '../types';

type TicketTableProps = {
  tickets: readonly Ticket[];
  selectedId: number | null;
  onSelect: (id: number) => void;
};

export function TicketTable({ tickets, selectedId, onSelect }: TicketTableProps) {
  return (
    <table className="ticket-table">
      <tbody>
        {tickets.map((t) => (
          <tr
            key={t.id}
            className={clsx('row', t.id === selectedId && 'row--selected')}
            aria-selected={t.id === selectedId}
            onClick={() => onSelect(t.id)}
          >
            <td>{t.id}</td>
            <td>{t.title}</td>
          </tr>
        ))}
      </tbody>
    </table>
  );
}
```

#T DEFINITION Zasady hooków
`useState` i wszystkie inne hooki (funkcje zaczynające się od `use`) mają dwie zasady:
1. Wywołuj je **tylko na najwyższym poziomie** komponentu — nie w warunkach, pętlach, funkcjach zagnieżdżonych ani po wczesnym `return`.
2. Wywołuj je **tylko w komponentach lub własnych hookach** — nie w zwykłych funkcjach pomocniczych.

React rozpoznaje stany po kolejności wywołań hooków w każdym renderze. Gdyby hook był w `if`, w jednym renderze byłby pierwszy, w innym — wcale, i stany pomieszałyby się. ESLint z wtyczką `react-hooks` pilnuje obu zasad.

#T DEFINITION Każda instancja ma własny stan
Stan należy do konkretnego miejsca komponentu w drzewie. Dwie instancje `<Counter />` obok siebie mają dwa niezależne liczniki. Gdy komponent zniknie z ekranu (odmontowanie), jego stan przepada; po ponownym pojawieniu się zaczyna od wartości początkowej.

#T CODE_PRACTICAL Przełącznik „rozwiń opis” w karcie
Stan lokalny dla karty — nikt poza nią nie musi wiedzieć, czy opis jest rozwinięty.
```
import { useState } from 'react';
import type { Ticket } from '../types';

export function TicketDescription({ ticket }: { ticket: Ticket }) {
  const [expanded, setExpanded] = useState(false);
  const isLong = ticket.description.length > 120;
  const text = expanded || !isLong ? ticket.description : `${ticket.description.slice(0, 120)}…`;

  return (
    <div>
      <p>{text}</p>
      {isLong && (
        <button type="button" onClick={() => setExpanded(!expanded)} aria-expanded={expanded}>
          {expanded ? 'Zwiń' : 'Pokaż całość'}
        </button>
      )}
    </div>
  );
}
```

#T STEP_BY_STEP Budujemy razem: wybór ticketu i panel szczegółów
1. W `Main` dodaj stan `selectedId` (w TS z typem `number | null`).
2. Przekaż `selectedId` i `onSelect={setSelectedId}` do `TicketTable`, a wiersz niech dostaje klasę `row--selected` i `aria-selected`.
3. Dodaj styl `.row--selected { background: var(--color-primary-soft, #eff6ff); }`.
4. Wylicz `selected` przez `find` i przekaż do `TicketCard` (z rozdziału 02) — karta pokaże wybrany ticket albo „Wybierz ticket z listy”.
5. Ułóż tabelę i kartę obok siebie (`display: grid; grid-template-columns: 2fr 1fr;`).
6. Dodaj `TicketDescription` w karcie z przyciskiem „Pokaż całość”.
7. W React DevTools kliknij `Main` i obserwuj, jak zmienia się hook `State` po kliknięciu wiersza.
8. Dodaj przycisk „Odznacz” w karcie, wywołujący `onClear`, które w `Main` robi `setSelectedId(null)`.

#T PITFALL Przechowywanie w stanie całego obiektu zamiast ID
`const [selected, setSelected] = useState(ticketObject)` zapamiętuje **kopię referencji** z chwili kliknięcia. Gdy ticket w danych się zmieni (np. po edycji), karta nadal pokazuje starą wersję. Przechowuj w stanie ID, a obiekt wyliczaj przez `find` przy każdym renderze — zawsze jest aktualny. To pierwsze zetknięcie z zasadą „minimalnego stanu”, którą rozwiniesz w lekcji o danych wyliczanych.

#T CODE_WRONG Hook wywołany warunkowo
```
export function TicketCard({ ticket }) {
  if (!ticket) return <p>Wybierz ticket</p>;
  const [expanded, setExpanded] = useState(false); // hook po wczesnym return
  return <p onClick={() => setExpanded(!expanded)}>{ticket.title}</p>;
}
```

#T CODE_RIGHT Hook przed jakimkolwiek return
```
export function TicketCard({ ticket }) {
  const [expanded, setExpanded] = useState(false);
  if (!ticket) return <p>Wybierz ticket</p>;
  return <p onClick={() => setExpanded(!expanded)}>{ticket.title}</p>;
}
```

#T SUMMARY Kryterium akceptacji i podsumowanie
`useState(start)` zwraca `[wartość, setter]`; wywołanie settera zapamiętuje nową wartość i powoduje ponowny render. Stan należy do instancji komponentu i przepada przy odmontowaniu. Hooki wywołujesz tylko na najwyższym poziomie komponentu. Przechowuj w stanie minimum (ID), a resztę wyliczaj. W TSX podaj generyk, gdy wartość startowa nie określa typu (`null`, `[]`, unia literałów).

Kryterium akceptacji: kliknięty wiersz jest wyróżniony (zawsze tylko jeden), karta obok pokazuje szczegóły wybranego ticketu, przycisk „Odznacz” czyści wybór, a opis dłuższy niż 120 znaków można rozwinąć i zwinąć.
