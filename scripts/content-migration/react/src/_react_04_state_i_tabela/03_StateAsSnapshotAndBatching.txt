Problem: w DevDesk dodajesz przycisk „+3 komentarze (test)”, który trzy razy wywołuje `setCount(count + 1)`. Licznik rośnie o 1. Do tego `console.log(count)` zaraz po `setCount` pokazuje starą wartość. To nie błąd Reacta — tak działa stan. Zrozumienie tej lekcji oszczędzi Ci wielu godzin debugowania.

#T DEFINITION Stan jest migawką
Każdy render to „zdjęcie” komponentu z wartościami stanu z chwili renderu. Zmienna `count` w danym renderze jest **stała** — wywołanie `setCount` nie zmienia jej, tylko zleca Reactowi kolejny render, w którym `useState` zwróci nową wartość. Handler zdarzenia, utworzony w danym renderze, „widzi” wartości z tego renderu — nawet jeśli wykona się później (np. w `setTimeout`).

#T ANALOGY Zamówienie w restauracji
Kelner (React) przynosi Ci menu wydrukowane rano (migawka). Ty składasz zamówienie „zmień danie na rybę” (setter). Menu w Twoich rękach się nie zmienia — dopiero przy następnej wizycie kelnera (kolejny render) dostajesz zaktualizowaną kartę z rybą.

#T CODE_JSX Pułapka trzech wywołań (JSX)
```
// CommentCounter.jsx
import { useState } from 'react';

export function CommentCounter() {
  const [count, setCount] = useState(0);

  function addThree() {
    setCount(count + 1); // count = 0 → ustaw 1
    setCount(count + 1); // count nadal 0 → ustaw 1
    setCount(count + 1); // count nadal 0 → ustaw 1
    console.log(count);  // 0 — wartość z tego renderu
  }

  return <button onClick={addThree}>Komentarze: {count}</button>;
}
```

#T CODE_TSX Rozwiązanie: aktualizacja funkcyjna (TSX)
Funkcja przekazana do settera dostaje **najnowszą** wartość z kolejki aktualizacji. Typ `prev` TypeScript wnioskuje ze stanu.
```
// CommentCounter.tsx
import { useState } from 'react';

export function CommentCounter() {
  const [count, setCount] = useState(0);

  function addThree() {
    setCount((prev) => prev + 1); // 0 → 1
    setCount((prev) => prev + 1); // 1 → 2
    setCount((prev) => prev + 1); // 2 → 3
  }

  return <button onClick={addThree}>Komentarze: {count}</button>;
}
```

#T NOTE JSX ↔ TSX — typ aktualizacji funkcyjnej
Setter przyjmuje albo nową wartość, albo funkcję `(prev) => nowa` — w TSX ten typ to `SetStateAction<T>`. Parametr `prev` ma typ stanu (`number`), więc `setCount((prev) => prev + '1')` jest błędem. Jeśli przekazujesz setter dalej przez props, a dziecko ma używać formy funkcyjnej, typ props zapisujesz jako `Dispatch<SetStateAction<number>>` (import z `react`). W JSX obie formy działają identycznie.

#T DEFINITION Kolejkowanie i batching
React nie renderuje po każdym wywołaniu settera. Zbiera wszystkie aktualizacje z jednego zdarzenia (a od React 18 — także z `setTimeout`, obietnic i innych źródeł) i wykonuje **jeden** render na końcu. To tzw. **automatyczny batching**. Dzięki temu trzy settery w jednym handlerze dają jeden render, a nie trzy.

Kolejka działa po kolei: wartość przekazana wprost zastępuje stan, funkcja dostaje wynik poprzedniej pozycji kolejki.

#T VISUAL_EXAMPLE Kolejka aktualizacji
stan = 0
kolejka:  setCount(5)          → 5
          setCount(n => n + 1) → 6
          setCount(n => n * 2) → 12
          setCount(42)         → 42
render z count = 42 (jeden render po zdarzeniu)

#T DEFINITION Kiedy używać formy funkcyjnej
Używaj `set(prev => ...)`, gdy nowa wartość zależy od poprzedniej i:
- kilka aktualizacji następuje w jednym handlerze,
- aktualizacja dzieje się asynchronicznie (po `await`, w `setTimeout`, w odpowiedzi z API),
- przekazujesz setter do innego komponentu lub hooka, który nie zna aktualnej wartości.

Gdy ustawiasz wartość niezależną od poprzedniej (`setSelectedId(42)`, `setQuery('')`), forma funkcyjna nie jest potrzebna.

#T CODE_BASIC Przełącznik z formą funkcyjną
```
import { useState } from 'react';

export function WatchToggle() {
  const [watching, setWatching] = useState(false);
  return (
    <button type="button" aria-pressed={watching} onClick={() => setWatching((w) => !w)}>
      {watching ? '★ Obserwujesz' : '☆ Obserwuj'}
    </button>
  );
}
```

#T CODE_PRACTICAL Opóźniona akcja widzi starą migawkę
Po kliknięciu „Zamknij za 3 s” i szybkim kliknięciu „+1” komunikat pokaże wartość z chwili pierwszego kliknięcia. Komunikat ma pokazywać stan z momentu zlecenia — to celowe. Jeśli potrzebujesz najnowszej wartości w opóźnionym kodzie, użyj formy funkcyjnej settera albo refa (rozdział 08).
```
import { useState } from 'react';

export function DelayedReport() {
  const [count, setCount] = useState(0);

  function reportLater() {
    setTimeout(() => {
      alert(`W chwili kliknięcia było: ${count}`); // migawka z renderu, w którym kliknięto
    }, 3000);
  }

  return (
    <>
      <button type="button" onClick={() => setCount((c) => c + 1)}>+1 ({count})</button>
      <button type="button" onClick={reportLater}>Raport za 3 s</button>
    </>
  );
}
```

#T PITFALL Odczyt stanu zaraz po setterze
`setQuery(value); fetchResults(query);` — `query` to nadal stara wartość, więc wyszukiwanie dostaje poprzedni tekst. Jeśli potrzebujesz nowej wartości w tym samym handlerze, użyj zmiennej lokalnej: `const next = value; setQuery(next); fetchResults(next);`.

#T CODE_WRONG Stara wartość po setterze
```
function handleChange(e) {
  setQuery(e.target.value);
  console.log('Szukam:', query); // poprzedni tekst
}
```

#T CODE_RIGHT Zmienna lokalna z nową wartością
```
function handleChange(e) {
  const next = e.target.value;
  setQuery(next);
  console.log('Szukam:', next);
}
```

#T SUMMARY Kryterium akceptacji i podsumowanie
Stan w danym renderze jest stałą migawką: setter nie zmienia zmiennej, tylko planuje render z nową wartością. React grupuje aktualizacje (batching) i renderuje raz po zdarzeniu. Gdy nowa wartość zależy od poprzedniej, używaj formy funkcyjnej `set(prev => ...)`. Nową wartość potrzebną w tym samym handlerze trzymaj w zmiennej lokalnej. W TSX setter ma typ `Dispatch<SetStateAction<T>>`, a `prev` dostaje typ stanu.

Kryterium akceptacji: przycisk testowy dodaje dokładnie 3 komentarze dzięki formie funkcyjnej, gwiazdka „Obserwuj” przełącza się poprawnie, a Ty potrafisz wyjaśnić, dlaczego `console.log` po setterze pokazuje starą wartość.
