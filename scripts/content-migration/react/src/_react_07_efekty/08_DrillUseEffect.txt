#T INTRO Trening: useEffect, zależności i sprzątanie
`useEffect` służy do jednego: **synchronizacji komponentu z czymś spoza Reacta** — tytułem karty, timerem, nasłuchem okna, połączeniem, zewnętrzną biblioteką. Większość błędów z Effectami bierze się z trzech źródeł: brakującego sprzątania, źle dobranych zależności (nieaktualne domknięcia, pętle) i używania Effectu tam, gdzie wystarczy obliczenie w renderze albo handler.

Ten trening to dwanaście zadań, w tym trzy „przewidź wynik” o kolejności wywołań — tę kolejność musisz znać na pamięć. Do każdego zadania z Effectem dopisuj `console.log` w ciele Effectu i w funkcji sprzątającej, uruchamiaj w StrictMode i obserwuj konsolę.

Szkielet, który będziesz pisać kilkanaście razy:

`useEffect(() => { /* podłącz */ return () => { /* odłącz */ }; }, [zależności]);`

#T STEP_BY_STEP Zadanie 1 — tytuł karty przeglądarki
Napisz `Inbox` z listą wiadomości (stan) i przyciskiem „Przeczytaj wszystko”.

Wymagania:
1. Liczba nieprzeczytanych jest wyliczana z listy.
2. Effect ustawia `document.title` na „(3) Skrzynka” albo „Skrzynka”, gdy nie ma nieprzeczytanych.
3. Zależności: tylko to, czego Effect używa (liczba nieprzeczytanych).
4. Sprzątanie: przy odmontowaniu przywróć poprzedni tytuł (zapamiętany na początku Effectu).

Sprawdź się: kliknięcie „Przeczytaj wszystko” zmienia tytuł karty, a zmiana czegoś innego w stanie (np. filtra) nie uruchamia Effectu ponownie.

#T CODE_JSX Rozwiązanie 1 (JSX)
```
// Inbox.jsx
import { useEffect, useState } from 'react';

const INITIAL = [
  { id: 1, subject: 'Nowy ticket #42', read: false },
  { id: 2, subject: 'Komentarz do #17', read: false },
  { id: 3, subject: 'Raport tygodniowy', read: true },
];

export function Inbox() {
  const [messages, setMessages] = useState(INITIAL);
  const unread = messages.filter((m) => !m.read).length;

  useEffect(() => {
    const previous = document.title;
    document.title = unread > 0 ? `(${unread}) Skrzynka` : 'Skrzynka';
    return () => {
      document.title = previous;
    };
  }, [unread]);

  return (
    <section>
      <ul>{messages.map((m) => <li key={m.id} className={m.read ? '' : 'unread'}>{m.subject}</li>)}</ul>
      <button type="button" onClick={() => setMessages((list) => list.map((m) => ({ ...m, read: true })))}>
        Przeczytaj wszystko
      </button>
    </section>
  );
}
```

#T STEP_BY_STEP Zadanie 2 — stoper: setInterval i sprzątanie
Napisz `Stopwatch` ze startem, pauzą i resetem.

Wymagania:
1. Stany: `running` (boolean) i `elapsed` (dziesiąte części sekundy).
2. Effect zależny od `running`: gdy `true`, uruchamia `setInterval` co 100 ms, który zwiększa `elapsed` **formą funkcyjną**; gdy `false` — nic nie robi.
3. Sprzątanie czyści interwał (`clearInterval`).
4. Wyświetlanie w formacie `12.3 s`.
5. Reset zatrzymuje stoper i zeruje czas.

Sprawdź się: w StrictMode stoper liczy z normalną prędkością (nie dwa razy szybciej) — to dowód, że sprzątanie działa.

#T CODE_JSX Rozwiązanie 2 (JSX)
```
// Stopwatch.jsx
import { useEffect, useState } from 'react';

export function Stopwatch() {
  const [running, setRunning] = useState(false);
  const [elapsed, setElapsed] = useState(0);

  useEffect(() => {
    if (!running) return;
    const id = setInterval(() => setElapsed((e) => e + 1), 100);
    return () => clearInterval(id);
  }, [running]);

  return (
    <div>
      <output>{(elapsed / 10).toFixed(1)} s</output>
      <button type="button" onClick={() => setRunning((r) => !r)}>{running ? 'Pauza' : 'Start'}</button>
      <button type="button" onClick={() => { setRunning(false); setElapsed(0); }}>Reset</button>
    </div>
  );
}
```

#T NOTE Wczesny return w Effecie
`if (!running) return;` kończy Effect bez sprzątania — i to jest poprawne, bo nic nie zostało podłączone. Funkcję sprzątającą zwracasz tylko wtedy, gdy jest co odłączyć. W TSX typ zwracany Effectu to `void | (() => void)`, więc obie gałęzie się zgadzają. Interwał co 100 ms nie jest dokładnym zegarem (przeglądarka spowalnia timery w tle) — w prawdziwym stoperze zapisujesz `Date.now()` przy starcie i wyliczasz różnicę.

#T STEP_BY_STEP Zadanie 3 — nasłuch zdarzeń okna
Napisz dwa małe komponenty z nasłuchem na `window`.

Wymagania:
1. `WindowSize` pokazuje aktualną szerokość i wysokość okna (`resize`) oraz napis „tryb mobilny” poniżej 640 px.
2. `EscapeToClose` — panel otwierany przyciskiem, zamykany klawiszem Escape (`keydown` na `window`). Nasłuch ma działać **tylko gdy panel jest otwarty**.
3. Oba Effecty usuwają nasłuch w sprzątaniu (`removeEventListener` z **tą samą** funkcją).

Sprawdź się: w zakładce Elements → Event Listeners (DevTools) po zamknięciu panelu nie ma już nasłuchu `keydown` z tego komponentu.

#T CODE_JSX Rozwiązanie 3 (JSX)
```
// WindowListeners.jsx
import { useEffect, useState } from 'react';

export function WindowSize() {
  const [size, setSize] = useState({ width: window.innerWidth, height: window.innerHeight });

  useEffect(() => {
    function handleResize() {
      setSize({ width: window.innerWidth, height: window.innerHeight });
    }
    window.addEventListener('resize', handleResize);
    return () => window.removeEventListener('resize', handleResize);
  }, []);

  return <p>{size.width} × {size.height} {size.width < 640 && '(tryb mobilny)'}</p>;
}

export function EscapeToClose() {
  const [open, setOpen] = useState(false);

  useEffect(() => {
    if (!open) return;
    function handleKey(e) {
      if (e.key === 'Escape') setOpen(false);
    }
    window.addEventListener('keydown', handleKey);
    return () => window.removeEventListener('keydown', handleKey);
  }, [open]);

  return (
    <div>
      <button type="button" onClick={() => setOpen(true)}>Otwórz panel</button>
      {open && <aside className="panel">Panel — naciśnij Escape, aby zamknąć</aside>}
    </div>
  );
}
```

#T CODE_BASIC Zadanie 4 — przewidź wynik: kolejność logów
Aplikacja działa w trybie deweloperskim ze StrictMode. Wypisz kolejność logów w konsoli dla trzech sytuacji: (1) pierwsze wyświetlenie `<Room id="a" />`, (2) zmiana na `<Room id="b" />`, (3) usunięcie komponentu.
```
// @check-skip
function Room({ id }) {
  console.log('render', id);

  useEffect(() => {
    console.log('connect', id);
    return () => console.log('disconnect', id);
  }, [id]);

  return <h2>Pokój {id}</h2>;
}
```

#T NOTE Odpowiedź do zadania 4
1. **Pierwsze wyświetlenie:** `render a`, `render a` (StrictMode renderuje dwa razy, drugi log bywa wyszarzony), `connect a`, `disconnect a`, `connect a`. StrictMode w trybie deweloperskim montuje komponent, od razu go „odmontowuje” i montuje ponownie — żeby sprawdzić, czy sprzątanie poprawnie cofa podłączenie.
2. **Zmiana id na b:** `render b` (×2), potem `disconnect a` — sprzątanie **poprzedniego** Effectu z poprzednimi wartościami — i `connect b`.
3. **Usunięcie:** `disconnect b`.

W wersji produkcyjnej punkt 1 to po prostu `render a`, `connect a`. Zapamiętaj regułę: przy każdej zmianie zależności najpierw sprzątanie starego Effectu (ze starymi wartościami z domknięcia), potem nowy Effect.

#T CODE_BASIC Zadanie 5 — przewidź wynik: tablica zależności
Jak często uruchomi się każdy Effect? Który z nich jest błędny?
```
// @check-skip

  console.log('A');
});

// B
useEffect(() => {
  console.log('B');
}, []);

#T NOTE Odpowiedź do zadania 5
- **A** — po **każdym** renderze. Rzadko tego chcesz.
- **B** — raz po zamontowaniu (w StrictMode w dev: zamontuj–posprzątaj–zamontuj).
- **C** — po montowaniu i po każdej zmianie `query`.
- **D** — błąd: Effect używa `page`, ale go nie deklaruje. Gdy zmieni się tylko `page`, Effect się nie uruchomi i pracuje na starej wartości. Reguła `react-hooks/exhaustive-deps` w ESLint to zgłosi — nie wyciszaj jej, tylko dopisz zależność albo przenieś logikę.
- **E** — nieskończona pętla: Effect po każdym renderze zmienia stan → nowy render → Effect → … React przerwie to błędem „Maximum update depth exceeded”. Liczenie renderów nie jest zadaniem dla stanu ani Effectu.

#T STEP_BY_STEP Zadanie 6 — nieaktualne domknięcie w interwale
Ten licznik miał rosnąć co sekundę, ale zatrzymuje się na 1:

`useEffect(() => { const id = setInterval(() => setCount(count + 1), 1000); return () => clearInterval(id); }, []);`

Wymagania:
1. Wyjaśnij w komentarzu, dlaczego zawsze widać 1.
2. Napraw na dwa sposoby: (a) forma funkcyjna settera, (b) dodanie `count` do zależności — i porównaj, ile razy tworzony jest interwał w każdej wersji (log w Effecie).
3. Dodaj prop `step` — licznik rośnie o `step`. Która wersja wymaga `step` w zależnościach?

Sprawdź się: wersja (a) tworzy interwał tylko przy montowaniu lub zmianie `step`, wersja (b) — co sekundę.

#T CODE_JSX Rozwiązanie 6 (JSX)
```
// AutoCounter.jsx
import { useEffect, useState } from 'react';

export function AutoCounter({ step = 1 }) {
  const [count, setCount] = useState(0);

  // Wersja z pustą tablicą i setCount(count + step) widziałaby zawsze count z pierwszego renderu (0),
  // więc co sekundę ustawiałaby 0 + 1 = 1. Forma funkcyjna nie czyta count z domknięcia.
  useEffect(() => {
    console.log('tworzę interwał, krok', step);
    const id = setInterval(() => setCount((c) => c + step), 1000);
    return () => clearInterval(id);
  }, [step]);

  return <output>{count}</output>;
}
```

  // więc co sekundę ustawiałaby 0 + 1 = 1. Forma funkcyjna nie czyta count z domknięcia.

#T NOTE Porównanie napraw
Wersja (b) z `[count]` też działa poprawnie: po każdej zmianie licznika stary interwał jest sprzątany, a nowy tworzony z aktualnym `count`. Ale tworzy interwał co sekundę, a przy krótkich odstępach może gubić „tyknięcia”. Forma funkcyjna usuwa zależność od `count` w ogóle — Effect nie musi wiedzieć, ile wynosi licznik, tylko jak go zmienić. `step` musi być w zależnościach w obu wersjach, bo Effect go czyta.

#T STEP_BY_STEP Zadanie 7 — obiekt w zależnościach
Komponent `ChatRoom` łączy się z pokojem przez udawaną bibliotekę `createConnection(options)`:

`const options = { serverUrl, roomId };` + `useEffect(() => { const c = createConnection(options); c.connect(); return () => c.disconnect(); }, [options]);`

Problem: połączenie restartuje się przy każdym wpisanym znaku w polu wiadomości.

Wymagania:
1. Napisz `createConnection` (loguje `connect` / `disconnect`).
2. Wyjaśnij, dlaczego `options` w zależnościach powoduje restart przy każdym renderze.
3. Napraw: utwórz obiekt **wewnątrz** Effectu i zależ od wartości prostych (`serverUrl`, `roomId`).
4. Pole wiadomości (stan `message`) nie może powodować ponownego łączenia.

Sprawdź się: wpisywanie w pole nie generuje logów `disconnect` / `connect`, a zmiana pokoju — generuje.

#T CODE_JSX Rozwiązanie 7 (JSX)
```
// ChatRoom.jsx
import { useEffect, useState } from 'react';

function createConnection({ serverUrl, roomId }) {
  return {
    connect: () => console.log(`connect ${roomId} @ ${serverUrl}`),
    disconnect: () => console.log(`disconnect ${roomId}`),
  };
}

export function ChatRoom({ roomId, serverUrl = 'wss://chat.example.com' }) {
  const [message, setMessage] = useState('');

  useEffect(() => {
    // Nowy obiekt w każdym renderze miałby nową referencję — tu powstaje tylko, gdy Effect naprawdę się uruchamia.
    const connection = createConnection({ serverUrl, roomId });
    connection.connect();
    return () => connection.disconnect();
  }, [serverUrl, roomId]);

  return (
    <section>
      <h2>Pokój: {roomId}</h2>
      <input value={message} onChange={(e) => setMessage(e.target.value)} aria-label="Wiadomość" />
    </section>
  );
}
```

#T CODE_TSX Rozwiązanie 7 (TSX)
```
// ChatRoom.tsx
import { useEffect, useState } from 'react';

type ConnectionOptions = { serverUrl: string; roomId: string };
type Connection = { connect: () => void; disconnect: () => void };

function createConnection({ serverUrl, roomId }: ConnectionOptions): Connection {
  return {
    connect: () => console.log(`connect ${roomId} @ ${serverUrl}`),
    disconnect: () => console.log(`disconnect ${roomId}`),
  };
}

export function ChatRoom({ roomId, serverUrl = 'wss://chat.example.com' }: { roomId: string; serverUrl?: string }) {
  const [message, setMessage] = useState('');

  useEffect(() => {
    // Nowy obiekt w każdym renderze miałby nową referencję — tu powstaje tylko, gdy Effect naprawdę się uruchamia.
    const connection = createConnection({ serverUrl, roomId });
    connection.connect();
    return () => connection.disconnect();
  }, [serverUrl, roomId]);

  return (
    <section>
      <h2>Pokój: {roomId}</h2>
      <input value={message} onChange={(e) => setMessage(e.target.value)} aria-label="Wiadomość" />
    </section>
  );
}
```

#T NOTE Dlaczego obiekt w zależnościach restartuje Effect
React porównuje zależności przez `Object.is`. `const options = { … }` w ciele komponentu tworzy **nowy obiekt przy każdym renderze** — nawet z identyczną zawartością to inna referencja, więc dla Reacta zależność „się zmieniła”. Każdy znak w polu → render → nowy `options` → sprzątanie i ponowne połączenie. To samo dotyczy funkcji zdefiniowanych w komponencie. Naprawy, od najlepszej: przenieś tworzenie obiektu do Effectu; zależ od wartości prostych; jeśli obiekt przychodzi z props — wyciągnij z niego pola prymitywne przed Effectem.

#T STEP_BY_STEP Zadanie 8 — usuń zbędne Effecty
Poniższy komponent ma cztery Effecty i żaden nie jest potrzebny:

1. `useEffect(() => setFullName(first + ' ' + last), [first, last]);`
2. `useEffect(() => setVisible(items.filter((i) => i.title.includes(query))), [items, query]);`
3. `useEffect(() => setComment(''), [ticketId]);` — reset szkicu komentarza przy zmianie ticketu,
4. `useEffect(() => { if (submitted) onSaved(form); }, [submitted]);` — powiadomienie rodzica po zapisie.

Wymagania: przepisz komponent bez żadnego `useEffect`, zachowując działanie. Dla każdego punktu nazwij technikę: dane wyliczane, reset przez `key`, logika w handlerze.

Sprawdź się: komponent nie importuje `useEffect`, a każdy render pokazuje od razu poprawne dane (bez „mignięcia” starej wartości).

// TicketEditor.jsx
import { useState } from 'react';

function CommentBox({ onSend }) {
  const [comment, setComment] = useState('');
  return (
    <div>
      <textarea value={comment} onChange={(e) => setComment(e.target.value)} aria-label="Komentarz" />
      <button type="button" onClick={() => { onSend(comment); setComment(''); }}>Dodaj komentarz</button>
    </div>
  );
}

export function TicketEditor({ ticketId, items, onSaved }) {
  const [form, setForm] = useState({ first: '', last: '' });
  const [query, setQuery] = useState('');

  // 1. Dane wyliczane zamiast stanu fullName.
  const fullName = `${form.first} ${form.last}`.trim();
  // 2. Filtrowanie w renderze zamiast stanu visible.
  const visible = items.filter((i) => i.title.includes(query));

  // 4. Powiadomienie rodzica w handlerze zdarzenia, które je powoduje.
  function handleSave(e) {
    e.preventDefault();
    onSaved(form);
  }

  return (
    <form onSubmit={handleSave}>
      <input value={form.first} onChange={(e) => setForm((f) => ({ ...f, first: e.target.value }))} aria-label="Imię" />
      <input value={form.last} onChange={(e) => setForm((f) => ({ ...f, last: e.target.value }))} aria-label="Nazwisko" />
      <p>Zgłaszający: {fullName || '—'}</p>
      <input type="search" value={query} onChange={(e) => setQuery(e.target.value)} aria-label="Szukaj powiązanych" />
      <ul>{visible.map((i) => <li key={i.id}>{i.title}</li>)}</ul>
      <CommentBox key={ticketId} onSend={(text) => console.log('komentarz', ticketId, text)} />
      <button type="submit">Zapisz</button>
    </form>
  );
}

    </div>

}

type TicketEditorProps = { ticketId: number; items: Item[]; onSaved: (reporter: Reporter) => void };

export function TicketEditor({ ticketId, items, onSaved }: TicketEditorProps) {

  const [query, setQuery] = useState('');

  // 1. Dane wyliczane zamiast stanu fullName.
  const fullName = `${form.first} ${form.last}`.trim();

  const visible = items.filter((i) => i.title.includes(query));

  // 4. Powiadomienie rodzica w handlerze zdarzenia, które je powoduje.
  function handleSave(e: FormEvent<HTMLFormElement>) {
    e.preventDefault();
    onSaved(form);
  }

  return (
    <form onSubmit={handleSave}>
      <input value={form.first} onChange={(e) => setForm((f) => ({ ...f, first: e.target.value }))} aria-label="Imię" />
      <input value={form.last} onChange={(e) => setForm((f) => ({ ...f, last: e.target.value }))} aria-label="Nazwisko" />
      <p>Zgłaszający: {fullName || '—'}</p>
      <input type="search" value={query} onChange={(e) => setQuery(e.target.value)} aria-label="Szukaj powiązanych" />
      <ul>{visible.map((i) => <li key={i.id}>{i.title}</li>)}</ul>
      <CommentBox key={ticketId} onSend={(text) => console.log('komentarz', ticketId, text)} />
      <button type="submit">Zapisz</button>
    </form>
  );
}
```

#T NOTE Test „czy to Effect?”
Zadaj sobie pytanie: **dlaczego** ten kod ma się wykonać? Jeśli dlatego, że użytkownik coś zrobił (kliknął, wysłał) — to handler. Jeśli dlatego, że komponent jest widoczny i ma być zsynchronizowany z czymś zewnętrznym (połączenie, nasłuch, tytuł karty) — to Effect. Jeśli wartość da się policzyć z props i stanu — to zwykła zmienna w renderze. Effecty z punktów 1 i 2 dodatkowo powodowały podwójny render: najpierw ze starą wartością, potem z nową.

#T NOTE Zasady useEffectEvent
Funkcja z `useEffectEvent` zawsze widzi **najnowsze** props i stan, ale nie jest „reaktywna” — nie wpisujesz jej do zależności i jej zmiana nie restartuje Effectu. Wywołuj ją tylko z wnętrza Effectów (nie z handlerów i nie w renderze) i nie przekazuj do innych komponentów. #T STEP_BY_STEP Zadanie 11 — zewnętrzny obiekt i zależność od props
Zsynchronizuj komponent z obiektami przeglądarki, które nie wymagają refa do elementu (refy poznasz w rozdziale 08): `document.body.style` i `matchMedia`.

Wymagania:
1. `ModalLock` — gdy `open` jest `true`, blokuje przewijanie strony (`document.body.style.overflow = 'hidden'`); sprzątanie przywraca poprzednią wartość.
2. `useMediaQuery(query)` — własny hook zwracający `true`/`false` dla zapytania (`window.matchMedia(query)`), aktualizowany przez nasłuch `change`; zależność: `query`.
3. Użyj `useMediaQuery('(prefers-color-scheme: dark)')`, żeby wyświetlić „System preferuje ciemny motyw”.

Sprawdź się: zmiana motywu systemu (w DevTools: Rendering → Emulate CSS media) od razu zmienia napis, a zamknięcie modala przywraca przewijanie.

#T CODE_JSX Rozwiązanie 11 (JSX)
```
// useMediaQuery.jsx
import { useEffect, useState } from 'react';

export function useMediaQuery(query) {
  const [matches, setMatches] = useState(() => window.matchMedia(query).matches);

  useEffect(() => {
    const list = window.matchMedia(query);
    setMatches(list.matches); // query mogło się zmienić od pierwszego renderu
    const handleChange = (e) => setMatches(e.matches);
    list.addEventListener('change', handleChange);
    return () => list.removeEventListener('change', handleChange);
  }, [query]);

  return matches;
}

export function ModalLock({ open, children }) {
  useEffect(() => {
    if (!open) return;
    const previous = document.body.style.overflow;
    document.body.style.overflow = 'hidden';
    return () => {
      document.body.style.overflow = previous;
    };
  }, [open]);

  return open ? <div className="modal">{children}</div> : null;
}

export function SystemTheme() {
  const prefersDark = useMediaQuery('(prefers-color-scheme: dark)');
  return <p>System preferuje {prefersDark ? 'ciemny' : 'jasny'} motyw</p>;
}
```

#T STEP_BY_STEP Zadanie 12 — autozapis z opóźnieniem
Zadanie łączone: notatka zapisuje się automatycznie sekundę po tym, jak użytkownik przestanie pisać.

Wymagania:
1. Stany: `text` (pole kontrolowane), `savedText` (treść ostatnio zapisana), `saving` (boolean), `savedAt` (godzina ostatniego zapisu).
2. „Niezapisane zmiany” to dane wyliczane: `text !== savedText` — bez osobnego stanu `dirty`.
3. Effect zależny od `text` i `savedText`: gdy są różne, planuje `setTimeout` na 1000 ms, który wywołuje `saveNote(text)` (udawany zapis 300 ms); sprzątanie anuluje timer — dzięki temu każde kolejne naciśnięcie klawisza przesuwa zapis.
4. Odpowiedź z zapisu, który został „wyprzedzony” przez nową zmianę lub odmontowanie, nie może ustawić `savedText` (flaga jak w zadaniu 9).
5. Wskaźnik: „Zapisano o 14:32”, „Niezapisane zmiany…”, „Zapisywanie…”.

Sprawdź się: pisanie bez przerwy przez 5 sekund daje **jeden** zapis, sekundę po ostatnim znaku.

#T CODE_JSX Rozwiązanie 12 (JSX)
```
// AutosaveNote.jsx
import { useEffect, useState } from 'react';

function saveNote(text) {
  return new Promise((resolve) => setTimeout(() => resolve(text.length), 300));
}

export function AutosaveNote() {
  const [text, setText] = useState('');
  const [savedText, setSavedText] = useState('');
  const [saving, setSaving] = useState(false);
  const [savedAt, setSavedAt] = useState(null);

  useEffect(() => {
    if (text === savedText) return;
    let ignore = false;
    const timer = setTimeout(async () => {
      setSaving(true);
      await saveNote(text);
      setSaving(false);
      if (!ignore) {
        setSavedText(text);
        setSavedAt(new Date());
      }
    }, 1000);
    return () => {
      ignore = true;
      clearTimeout(timer);
    };
  }, [text, savedText]);

  let label = 'Brak zmian';
  if (saving) label = 'Zapisywanie…';
  else if (text !== savedText) label = 'Niezapisane zmiany…';
  else if (savedAt) label = `Zapisano o ${savedAt.toLocaleTimeString('pl-PL', { hour: '2-digit', minute: '2-digit' })}`;

  return (
    <div>
      <textarea value={text} onChange={(e) => setText(e.target.value)} aria-label="Notatka" />
      <small role="status">{label}</small>
    </div>
  );
}
```

#T PITFALL Kusząca wersja ze statusem w zależnościach
Naturalny pierwszy pomysł to jeden stan `status` (`'saved' | 'dirty' | 'saving'`), handler ustawiający `'dirty'` i Effect z warunkiem `if (status !== 'dirty') return;` oraz zależnościami `[text, status]`. Wygląda dobrze, ale się zacina: `setStatus('saving')` w timerze zmienia zależność Effectu, więc React od razu wywołuje sprzątanie — `ignore` staje się `true` — a po zakończeniu zapisu `if (!ignore)` się nie wykona. Status zostaje na zawsze „Zapisywanie…”. Wniosek: stan zmieniany **wewnątrz** Effectu nie powinien być jego zależnością, jeśli nie chcesz restartu. W rozwiązaniu `saving` nie jest zależnością, a „niezapisane zmiany” są wyliczane z porównania `text` i `savedText`.

#T SUMMARY Podsumowanie treningu
Przećwiczyłeś pełny cykl Effectu: kiedy się uruchamia (po renderze, zależnie od tablicy zależności), w jakiej kolejności następują render, sprzątanie i nowy Effect (także w StrictMode), jak sprzątać timery, nasłuchy i połączenia, jak unikać nieaktualnych domknięć (forma funkcyjna settera), restartów od obiektów w zależnościach (tworzenie obiektów w Effecie) i wyścigów odpowiedzi (flaga `ignore`). Usunąłeś też Effecty, które nie były potrzebne (dane wyliczane, `key`, handlery), i oddzieliłeś logikę zdarzeń od reaktywnej części Effectu przez `useEffectEvent`.

Kryterium zaliczenia: poprawne odpowiedzi do zadań 4 i 5; w StrictMode żaden komponent z treningu nie zostawia aktywnych timerów ani nasłuchów po odmontowaniu, a autozapis z zadania 12 robi jeden zapis po serii zmian.
