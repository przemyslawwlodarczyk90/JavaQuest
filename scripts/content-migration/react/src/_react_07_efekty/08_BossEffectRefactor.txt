#T INTRO Boss rozdziału 07: refaktoryzacja nadużytych efektów
Tym razem nie budujesz od zera — dostajesz działający, ale źle napisany komponent. Tak wygląda duża część prawdziwej pracy z Reactem: przejęty kod z łańcuchem efektów, wyciekami i podwójnymi zapytaniami. Twoje zadanie: poprawić go tak, by zachowanie z punktu widzenia użytkownika zostało takie samo (lub lepsze), a każdy pozostały efekt miał uzasadnienie.

#T DEFINITION Brief zadania
Komponent `TicketWorkbench` (poniżej) obsługuje: wyszukiwanie z opóźnieniem, listę ticketów z filtrem, wybrany ticket, licznik w tytule karty, automatyczne zapisywanie szkicu notatki, nasłuchiwanie skrótu Escape (odznacz ticket) i zegar „ostatnie odświeżenie N s temu”. Zawiera co najmniej dziewięć błędów i antywzorców. Znajdź je, nazwij i napraw.

#T CODE_JSX Kod do refaktoryzacji (JSX)
```
// TicketWorkbench.jsx — wersja do poprawy
import { useEffect, useState } from 'react';

export function TicketWorkbench({ tickets, onSelectionChange }) {
  const [query, setQuery] = useState('');
  const [debouncedQuery, setDebouncedQuery] = useState('');
  const [filtered, setFiltered] = useState([]);
  const [selectedId, setSelectedId] = useState(null);
  const [selected, setSelected] = useState(null);
  const [note, setNote] = useState('');
  const [secondsAgo, setSecondsAgo] = useState(0);

  useEffect(() => {
    setTimeout(() => setDebouncedQuery(query), 300);
  }, [query]);

  useEffect(() => {
    setFiltered(tickets.filter((t) => t.title.toLowerCase().includes(debouncedQuery.toLowerCase())));
  }, [tickets, debouncedQuery]);

  useEffect(() => {
    setSelected(tickets.find((t) => t.id === selectedId));
  }, [selectedId]);

  useEffect(() => {
    onSelectionChange(selectedId);
  }, [selectedId]);

  useEffect(() => {
    setNote('');
  }, [selectedId]);

  useEffect(() => {
    document.title = `DevDesk (${filtered.length})`;
  });

  useEffect(() => {
    localStorage.setItem(`note-${selectedId}`, note);
  }, [note]);

  useEffect(() => {
    window.addEventListener('keydown', (e) => {
      if (e.key === 'Escape') setSelectedId(null);
    });
  }, []);

  useEffect(() => {
    setInterval(() => setSecondsAgo(secondsAgo + 1), 1000);
  }, []);

  return (
    <div>
      <input aria-label="Szukaj" value={query} onChange={(e) => setQuery(e.target.value)} />
      <ul>
        {filtered.map((t) => (
          <li key={t.id} onClick={() => setSelectedId(t.id)}>{t.title}</li>
        ))}
      </ul>
      {selected && (
        <section>
          <h3>{selected.title}</h3>
          <textarea aria-label="Notatka" value={note} onChange={(e) => setNote(e.target.value)} />
        </section>
      )}
      <small>Ostatnie odświeżenie: {secondsAgo} s temu</small>
    </div>
  );
}
```

#T STEP_BY_STEP Kryteria akceptacji
1. Wypisz w komentarzu na górze pliku każdy znaleziony problem z nazwą kategorii (dane wyliczane w efekcie, brak sprzątania, nieaktualne domknięcie, logika zdarzenia w efekcie, reset stanu efektem, brakujące zależności, efekt bez tablicy zależności, wyciek nasłuchiwania itp.).
2. `filtered` i `selected` są wyliczane w renderze — bez stanu i bez efektów.
3. Opóźnione wyszukiwanie korzysta z hooka (np. `useDebouncedValue`) ze sprzątaniem timera.
4. Rodzic jest powiadamiany o zmianie zaznaczenia w handlerze (kliknięcie wiersza i Escape), nie w efekcie.
5. Notatka resetuje się przy zmianie ticketu bez efektu (osobny komponent z `key`), a jej zapis dotyczy właściwego ticketu (zapis nie może trafić pod klucz poprzedniego ticketu przy przełączaniu).
6. Nasłuchiwanie Escape i zegar mają sprzątanie; zegar rośnie poprawnie (aktualizacja funkcyjna).
7. Tytuł karty aktualizuje się tylko przy zmianie liczby wyników (poprawna tablica zależności).
8. `npm run lint` nie zgłasza ostrzeżeń, nie ma wyciszeń `eslint-disable`.
9. W StrictMode wszystkie funkcje działają poprawnie (żadne zdarzenie nie jest obsługiwane podwójnie).

#T NOTE Wskazówka 1 — policz efekty, które mają zostać
Zadaj każdemu efektowi dwa pytania z lekcji 5. Po refaktoryzacji powinny zostać tylko efekty synchronizujące z systemem zewnętrznym: tytuł karty, zapis notatki do localStorage, nasłuchiwanie klawiatury, interwał zegara — oraz timer wewnątrz hooka opóźnienia. Wszystko inne to dane wyliczane albo logika zdarzeń.

#T NOTE Wskazówka 2 — notatka jako osobny komponent
Wydziel `TicketNote({ ticketId })` z własnym stanem notatki (inicjalizowanym z localStorage dla `ticketId`) i efektem zapisu zależnym od `[ticketId, note]`. Renderuj go jako `<TicketNote key={selected.id} ticketId={selected.id} />`. `key` resetuje stan przy zmianie ticketu, a ponieważ efekt zapisu należy do instancji danego ticketu, nigdy nie zapisze tekstu pod cudzym kluczem.

#T NOTE Wskazówka 3 — Escape i powiadomienie rodzica
Escape to zdarzenie użytkownika — w funkcji obsługi klawisza wywołaj `setSelectedId(null)` i `onSelectionChange(null)` razem. Żeby nie podpinać nasłuchiwania przy każdej zmianie `onSelectionChange`, opakuj reakcję w `useEffectEvent` albo trzymaj w efekcie tylko `addEventListener`/`removeEventListener` z funkcją z `useEffectEvent`.

#T CODE_PRACTICAL Fragment rozwiązania — notatka i zegar (TSX)
```
import { useEffect, useState } from 'react';

export function TicketNote({ ticketId }: { ticketId: number }) {
  const [note, setNote] = useState(() => localStorage.getItem(`note-${ticketId}`) ?? '');

  useEffect(() => {
    localStorage.setItem(`note-${ticketId}`, note); // synchronizacja z localStorage
  }, [ticketId, note]);

  return <textarea aria-label="Notatka" value={note} onChange={(e) => setNote(e.target.value)} />;
}

export function useSecondsSince() {
  const [seconds, setSeconds] = useState(0);
  useEffect(() => {
    const id = setInterval(() => setSeconds((s) => s + 1), 1000);
    return () => clearInterval(id);
  }, []);
  return seconds;
}
```

#T PITFALL Pułapki tej refaktoryzacji
- Zastąpienie stanu `selected` zmienną z `find`, ale pozostawienie typu `Ticket | undefined` i warunku `selected &&` — działa, ale w TSX lepiej `?? null` dla spójności z resztą kursu.
- Przeniesienie `onSelectionChange` do handlera kliknięcia, ale zapomnienie o Escape — rodzic nie dowie się o odznaczeniu.
- Zapis notatki w efekcie zależnym tylko od `[note]` — przy przełączeniu ticketu stara notatka trafi pod nowy klucz (stąd `key` i `ticketId` w zależnościach).
- Usunięcie `StrictMode`, żeby „naprawić” podwójne obsługiwanie Escape — prawdziwa naprawa to sprzątanie nasłuchiwania.

#T SUMMARY Podsumowanie rozdziału 07
W tym rozdziale poznałeś model montowania, aktualizacji i odmontowania oraz myślenie o efektach jako synchronizacji; napisałeś efekty zapisujące stan w localStorage; nauczyłeś się poprawnie deklarować zależności i unikać nieaktualnych domknięć; pisać sprzątanie odporne na StrictMode; rozpoznawać i usuwać zbędne efekty; używać `useEffectEvent`, `useLayoutEffect` i `useSyncExternalStore`. W TSX: typ funkcji sprzątającej, typy zewnętrznych API i kontrakt `subscribe`.

Boss zaliczony, gdy wszystkie dziewięć kryteriów akceptacji jest spełnionych w obu wersjach.
