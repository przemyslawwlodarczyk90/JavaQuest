#T INTRO Rozgrzewka i problem: komponent z dwudziestoma propsami
Rozgrzewka: Jak zbudować dostępne zakładki i kto przechowuje aktywną zakładkę? Czym jest slot? Kiedy używasz kontekstu?

Problem: komponent `Tabs` z rozdziału 08 przyjmuje tablicę `tabs={[{ id, label, content }]}`. Pierwsze prośby z zespołu: ikona przy jednej zakładce, licznik przy drugiej, wyłączona trzecia, przycisk „+” na końcu listy, panel z innym układem. Każda prośba to nowy prop (`tabIcons`, `tabBadges`, `disabledTabs`, `tabListExtra`…). Wzorzec **komponentów złożonych** (compound components) odwraca sytuację: zamiast konfigurować jeden wielki komponent, użytkownik składa go z małych części.

#T DEFINITION Komponenty złożone
Komponent złożony to grupa współpracujących komponentów, które razem tworzą jedną całość i dzielą stan przez **kontekst**:

`<Tabs> <Tabs.List> <Tabs.Tab id="a">…</Tabs.Tab> </Tabs.List> <Tabs.Panel id="a">…</Tabs.Panel> </Tabs>`

- `Tabs` (korzeń) trzyma stan i udostępnia go kontekstem,
- `Tabs.List`, `Tabs.Tab`, `Tabs.Panel` czytają kontekst i renderują swoją część,
- użytkownik decyduje o układzie i treści — może wstawić ikonę, licznik czy dowolny element między części.

Tak działa wiele bibliotek: Radix (`Dialog.Root`, `Dialog.Trigger`, `Dialog.Content`), React Aria, Headless UI. Podobną zasadę zna HTML: `<select>` i `<option>`.

#T CODE_JSX Zakładki złożone (JSX)
```
// Tabs.jsx
import { createContext, useContext, useId, useState } from 'react';

const TabsContext = createContext(null);

function useTabs() {
  const ctx = useContext(TabsContext);
  if (!ctx) throw new Error('Części Tabs muszą być wewnątrz <Tabs>');
  return ctx;
}

function TabsRoot({ defaultValue, value, onChange, children }) {
  const [internal, setInternal] = useState(defaultValue);
  const active = value ?? internal;
  const baseId = useId();
  const select = (id) => {
    if (value === undefined) setInternal(id);
    onChange?.(id);
  };
  return <TabsContext value={{ active, select, baseId }}>{children}</TabsContext>;
}

function List({ label, children }) {
  return <div role="tablist" aria-label={label}>{children}</div>;
}

function Tab({ id, disabled = false, children }) {
  const { active, select, baseId } = useTabs();
  return (
    <button
      type="button"
      role="tab"
      id={`${baseId}-tab-${id}`}
      aria-selected={active === id}
      aria-controls={`${baseId}-panel-${id}`}
      tabIndex={active === id ? 0 : -1}
      disabled={disabled}
      onClick={() => select(id)}
    >
      {children}
    </button>
  );
}

function Panel({ id, children }) {
  const { active, baseId } = useTabs();
  return (
    <div role="tabpanel" id={`${baseId}-panel-${id}`} aria-labelledby={`${baseId}-tab-${id}`} hidden={active !== id}>
      {children}
    </div>
  );
}

export const Tabs = Object.assign(TabsRoot, { List, Tab, Panel });
```

#T CODE_TSX Zakładki złożone (TSX)
Kontekst przechowuje `string` jako ID — zgodność ID między `Tab` a `Panel` jest sprawdzana w czasie działania, nie przez typy (to cena elastyczności wzorca).
```
// Tabs.tsx
import { createContext, useContext, useId, useState, type ReactNode } from 'react';

type TabsContextValue = { active: string; select: (id: string) => void; baseId: string };

const TabsContext = createContext<TabsContextValue | null>(null);

function useTabs(): TabsContextValue {
  const ctx = useContext(TabsContext);
  if (!ctx) throw new Error('Części Tabs muszą być wewnątrz <Tabs>');
  return ctx;
}

type RootProps = { defaultValue: string; value?: string; onChange?: (id: string) => void; children: ReactNode };

function TabsRoot({ defaultValue, value, onChange, children }: RootProps) {
  const [internal, setInternal] = useState(defaultValue);
  const active = value ?? internal;
  const baseId = useId();
  const select = (id: string) => {
    if (value === undefined) setInternal(id);
    onChange?.(id);
  };
  return <TabsContext value={{ active, select, baseId }}>{children}</TabsContext>;
}

function List({ label, children }: { label: string; children: ReactNode }) {
  return <div role="tablist" aria-label={label}>{children}</div>;
}

function Tab({ id, disabled = false, children }: { id: string; disabled?: boolean; children: ReactNode }) {
  const { active, select, baseId } = useTabs();
  return (
    <button
      type="button"
      role="tab"
      id={`${baseId}-tab-${id}`}
      aria-selected={active === id}
      aria-controls={`${baseId}-panel-${id}`}
      tabIndex={active === id ? 0 : -1}
      disabled={disabled}
      onClick={() => select(id)}
    >
      {children}
    </button>
  );
}

function Panel({ id, children }: { id: string; children: ReactNode }) {
  const { active, baseId } = useTabs();
  return (
    <div role="tabpanel" id={`${baseId}-panel-${id}`} aria-labelledby={`${baseId}-tab-${id}`} hidden={active !== id}>
      {children}
    </div>
  );
}

export const Tabs = Object.assign(TabsRoot, { List, Tab, Panel });
```

#T NOTE JSX ↔ TSX — typowanie podkomponentów
`Object.assign(TabsRoot, { List, Tab, Panel })` daje w TSX typ, który łączy funkcję korzenia z polami `Tabs.List`, `Tabs.Tab`, `Tabs.Panel` — edytor podpowiada podkomponenty po wpisaniu `Tabs.`. W JSX zapis działa tak samo, ale podpowiedzi zależą od tego, czy edytor wywnioskuje kształt obiektu. Ograniczenie wzorca w obu wersjach: TypeScript nie sprawdzi, czy każdy `Tab` ma odpowiadający mu `Panel` o tym samym `id` — składanie części daje elastyczność kosztem części kontroli. Alternatywą bez `Object.assign` są osobne eksporty (`TabsList`, `TabsTab`) — wybór stylu.

#T CODE_BASIC Użycie: pełna kontrola nad treścią
Ikony, liczniki i dodatkowy przycisk bez żadnego nowego propa w `Tabs`.
```
import { Tabs } from './Tabs';

export function TicketSections({ commentCount }: { commentCount: number }) {
  return (
    <Tabs defaultValue="details">
      <div className="tabs-header">
        <Tabs.List label="Sekcje ticketu">
          <Tabs.Tab id="details">📄 Szczegóły</Tabs.Tab>
          <Tabs.Tab id="activity">💬 Aktywność <span className="badge">{commentCount}</span></Tabs.Tab>
          <Tabs.Tab id="history" disabled>🕓 Historia</Tabs.Tab>
        </Tabs.List>
        <button type="button">Eksport</button>
      </div>
      <Tabs.Panel id="details">Opis ticketu…</Tabs.Panel>
      <Tabs.Panel id="activity">Komentarze…</Tabs.Panel>
      <Tabs.Panel id="history">Zmiany…</Tabs.Panel>
    </Tabs>
  );
}
```

#T CODE_PRACTICAL Accordion jako komponent złożony
Ten sam wzorzec dla listy rozwijanych sekcji (np. FAQ w panelu pomocy). Kontekst sekcji zagnieżdżony w kontekście całego accordiona.
```
import { createContext, useContext, useId, useState, type ReactNode } from 'react';

const AccordionCtx = createContext<{ openId: string | null; toggle: (id: string) => void } | null>(null);
const ItemCtx = createContext<{ id: string; headerId: string; panelId: string } | null>(null);

function Root({ children }: { children: ReactNode }) {
  const [openId, setOpenId] = useState<string | null>(null);
  const toggle = (id: string) => setOpenId((cur) => (cur === id ? null : id));
  return <AccordionCtx value={{ openId, toggle }}>{children}</AccordionCtx>;
}

function Item({ id, children }: { id: string; children: ReactNode }) {
  const base = useId();
  return <ItemCtx value={{ id, headerId: `${base}-h`, panelId: `${base}-p` }}><div className="acc-item">{children}</div></ItemCtx>;
}

function Trigger({ children }: { children: ReactNode }) {
  const acc = useContext(AccordionCtx)!;
  const item = useContext(ItemCtx)!;
  const open = acc.openId === item.id;
  return (
    <h3>
      <button type="button" id={item.headerId} aria-expanded={open} aria-controls={item.panelId} onClick={() => acc.toggle(item.id)}>
        {children}
      </button>
    </h3>
  );
}

function Content({ children }: { children: ReactNode }) {
  const acc = useContext(AccordionCtx)!;
  const item = useContext(ItemCtx)!;
  return <div id={item.panelId} role="region" aria-labelledby={item.headerId} hidden={acc.openId !== item.id}>{children}</div>;
}

export const Accordion = Object.assign(Root, { Item, Trigger, Content });
```

#T STEP_BY_STEP Budujemy razem: zakładki złożone w DevDesk
1. Przepisz `Tabs` z rozdziału 08 na wersję złożoną (zachowaj obsługę strzałek: przenieś ją do `List`, który może znaleźć przyciski zakładek przez `querySelectorAll('[role=tab]')`).
2. W karcie ticketu użyj nowej wersji: ikona przy każdej zakładce, licznik komentarzy przy „Aktywności”.
3. Dodaj w nagłówku zakładek przycisk „Eksport” bez zmian w komponencie `Tabs`.
4. Zbuduj `Accordion` i panel „Pomoc” w panelu bocznym z trzema sekcjami.
5. Wyrenderuj `<Tabs.Tab>` poza `<Tabs>` — przeczytaj czytelny błąd z hooka `useTabs`.
6. Porównaj ilość kodu w miejscu użycia: wersja z tablicą konfiguracji a wersja złożona.

#T WHEN_TO_USE Konfiguracja czy kompozycja części
Tablica konfiguracji (`tabs={[...]}`) jest prostsza, gdy elementy są jednolite i nie potrzebujesz niestandardowej treści — np. zakładki generowane z danych. Komponenty złożone wygrywają, gdy użytkownicy komponentu potrzebują elastyczności układu i treści, gdy komponent ma wiele współpracujących części (dialog, menu, select, accordion), albo gdy budujesz bibliotekę komponentów dla zespołu.

#T SUMMARY Kryterium akceptacji i podsumowanie
Komponenty złożone to grupa części (`Tabs.List`, `Tabs.Tab`, `Tabs.Panel`) dzielących stan przez kontekst korzenia; użytkownik składa je swobodnie, zamiast konfigurować jeden komponent dziesiątkami props. Każda część czyta kontekst przez hook rzucający błąd poza korzeniem. Podkomponenty dołączasz przez `Object.assign` albo eksportujesz osobno. W TSX dostajesz podpowiedzi części, ale zgodność ID między częściami jest sprawdzana tylko w czasie działania.

Kryterium akceptacji: karta ticketu używa złożonych zakładek z ikonami, licznikiem i dodatkowym przyciskiem w nagłówku bez nowych props w `Tabs`, a panel pomocy działa na komponencie `Accordion`.
