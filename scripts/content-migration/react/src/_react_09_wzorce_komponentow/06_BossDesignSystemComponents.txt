#T INTRO Boss rozdziału 09: mini design system
W rozdziale poznałeś wzorce, z których buduje się biblioteki komponentów. Teraz zbudujesz małą bibliotekę dla zespołu: trzy komponenty, każdy w innym wzorcu, z dokumentacją użycia na stronie przewodnika stylu z rozdziału 03. To zadanie sprawdza, czy umiesz zaprojektować **API komponentu** — wygodne dla innych programistów, dostępne i odporne na złe użycie.

#T DEFINITION Brief zadania
Zbuduj:
1. **`Accordion`** jako komponent złożony (`Accordion`, `Accordion.Item`, `Accordion.Trigger`, `Accordion.Content`) z trybem „jedna sekcja otwarta” lub „wiele naraz” (prop `type: 'single' | 'multiple'`), kontrolowany lub niekontrolowany (`value`/`defaultValue`/`onValueChange`), z obsługą strzałek góra/dół między nagłówkami.
2. **`Select`** jako hook headless `useSelect` + jeden domyślny komponent `Select`: lista rozwijana z własnym wyglądem (przycisk + lista opcji), obsługa klawiatury (strzałki, Enter, Escape, wpisanie litery przechodzi do opcji na tę literę), atrybuty ARIA listbox.
3. **`Button`** polimorficzny (`as` albo `asChild`) z wariantami `primary | secondary | danger | ghost`, rozmiarami `sm | md`, stanem `loading` (spinner, `aria-busy`, blokada kliknięć) i przekazywaniem `ref`.
4. Stronę **„Komponenty”** w przewodniku stylu: każdy komponent w kilku konfiguracjach z krótkim opisem API i przykładem kodu.

#T STEP_BY_STEP Kryteria akceptacji
1. `Accordion`: części rzucają czytelny błąd poza korzeniem; `type="single"` zamyka poprzednią sekcję, `type="multiple"` nie; oba tryby kontroli działają (sprawdź przyciskiem „Rozwiń wszystkie” sterującym z zewnątrz).
2. `Accordion` ma poprawne ARIA: nagłówek `<button aria-expanded aria-controls>`, panel `role="region"` z `aria-labelledby`.
3. `useSelect` nie zawiera JSX; komponent `Select` korzysta tylko z prop getterów; drugi, inny wygląd selecta (np. kompaktowy w pasku narzędzi) da się zbudować z tego samego hooka bez kopiowania logiki.
4. `Select` działa wyłącznie z klawiatury, zamyka się kliknięciem poza listą, a po wyborze fokus wraca na przycisk.
5. `Button` z `loading` nie wywołuje `onClick`, ma `aria-busy="true"` i zachowuje szerokość (tekst nie skacze).
6. `Button as="a"` (lub `asChild` z linkiem) renderuje link z poprawnym `href`; własne `className`, `aria-*` i `ref` są przekazywane do elementu.
7. Wszystkie komponenty obsługują `className` użytkownika (doklejane do własnych klas) i nie używają `div` z `onClick` zamiast przycisków.
8. Strona „Komponenty” pokazuje każdy wariant i stan, w obu motywach.
9. W wersji TSX: typy props eksportowane razem z komponentami; generyczny `useSelect<T>`; `Button` nie przyjmuje `href` bez `as="a"`; `npm run build` bez błędów.

#T NOTE Wskazówka 1 — Accordion single/multiple
Trzymaj wartość zawsze jako tablicę otwartych ID (`string[]`), niezależnie od trybu. W trybie `single` przełączenie robi `open.includes(id) ? [] : [id]`, w `multiple` — dodaje lub usuwa ID. Publiczne API może przyjmować `string` dla `single` i `string[]` dla `multiple` — w TSX to dobra okazja na unię props z dyskryminatorem `type`. Do kontroli użyj `useControllableState` z poprzedniej lekcji.

#T NOTE Wskazówka 2 — wpisywanie litery w Select
W `onKeyDown` przycisku: jeśli `e.key.length === 1` (zwykły znak), znajdź pierwszą opcję, której etykieta zaczyna się na tę literę (bez względu na wielkość liter), zaczynając od pozycji za aktywną — kolejne wciśnięcie tej samej litery przejdzie do następnej opcji. To zachowanie natywnego `<select>`, którego użytkownicy klawiatury oczekują.

#T CODE_JSX Szkielet Button z loading (JSX)
```
// Button.jsx
import clsx from 'clsx';

export function Button({ as: Component = 'button', variant = 'primary', size = 'md', loading = false, className, children, onClick, ...rest }) {
  return (
    <Component
      className={clsx('btn', `btn--${variant}`, `btn--${size}`, loading && 'btn--loading', className)}
      aria-busy={loading || undefined}
      onClick={loading ? (e) => e.preventDefault() : onClick}
      {...(Component === 'button' ? { type: rest.type ?? 'button', disabled: rest.disabled } : {})}
      {...rest}
    >
      <span className="btn__label">{children}</span>
      {loading && <span className="btn__spinner" aria-hidden="true" />}
    </Component>
  );
}
```

#T CODE_TSX Szkielet Button z loading (TSX)
```
// Button.tsx
import clsx from 'clsx';
import type { ComponentPropsWithoutRef, ElementType, MouseEvent } from 'react';

type OwnProps<E extends ElementType> = {
  as?: E;
  variant?: 'primary' | 'secondary' | 'danger' | 'ghost';
  size?: 'sm' | 'md';
  loading?: boolean;
  className?: string;
};

export type ButtonProps<E extends ElementType = 'button'> = OwnProps<E> & Omit<ComponentPropsWithoutRef<E>, keyof OwnProps<E>>;

export function Button<E extends ElementType = 'button'>({
  as, variant = 'primary', size = 'md', loading = false, className, children, onClick, ...rest
}: ButtonProps<E>) {
  const Component: ElementType = as ?? 'button';
  return (
    <Component
      className={clsx('btn', `btn--${variant}`, `btn--${size}`, loading && 'btn--loading', className)}
      aria-busy={loading || undefined}
      onClick={loading ? (e: MouseEvent) => e.preventDefault() : onClick}
      {...rest}
    >
      <span className="btn__label">{children}</span>
      {loading && <span className="btn__spinner" aria-hidden="true" />}
    </Component>
  );
}
```

#T NOTE Wskazówka 3 — szerokość przy loading
Żeby przycisk nie zmieniał szerokości, nie usuwaj tekstu przy ładowaniu — ukryj go wizualnie (`.btn--loading .btn__label { visibility: hidden; }`) i pokaż spinner wyśrodkowany absolutnie (`.btn { position: relative; }`, `.btn__spinner { position: absolute; inset: 0; margin: auto; }`). Tekst nadal zajmuje miejsce, a czytnik ekranu może go odczytać razem z `aria-busy`.

#T PITFALL Typowe błędy w tym zadaniu
- `Select` zbudowany na `div`-ach bez ról — czytnik ekranu nie wie, że to lista wyboru (użyj `role="listbox"`/`option` albo zostań przy natywnym `<select>`, jeśli własny wygląd nie jest konieczny).
- `Accordion` z otwartymi ID w dwóch stanach (dla `single` i `multiple`) — jedna tablica wystarczy.
- `Button` z `disabled` przy `loading` — wyłączony przycisk traci fokus i jest pomijany przez czytnik; lepiej `aria-busy` i blokada kliknięcia.
- Gubienie `className` użytkownika (nadpisanie zamiast doklejenia) — komponent przestaje być rozszerzalny.

#T SUMMARY Podsumowanie rozdziału 09
W tym rozdziale poznałeś wzorce projektowania API komponentów: komponenty złożone dzielące stan przez kontekst, render props i HOC (oraz kiedy zastąpić je hookiem), komponenty działające w trybie kontrolowanym i niekontrolowanym (`useControllableState`), komponenty polimorficzne (`as`, `asChild`) i komponenty headless z prop getterami. W TSX: `Object.assign` dla podkomponentów, `children` jako funkcja, generyczne HOC i hooki, `ElementType` z `ComponentPropsWithoutRef`.

Boss zaliczony, gdy wszystkie dziewięć kryteriów akceptacji jest spełnionych, a inny programista potrafi użyć Twoich komponentów, czytając tylko stronę „Komponenty”.
