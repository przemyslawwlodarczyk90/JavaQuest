#T INTRO Rozgrzewka i problem: przycisk, który czasem jest linkiem
Rozgrzewka: Jak działa hook `useControllableState`? Dlaczego nie kopiujesz `value` do stanu wewnętrznego? Jak wymusić w TSX, że `value` wymaga `onChange`?

Problem: komponent `Button` w DevDesk ma ładne warianty, ale „Zobacz ticket” to nawigacja — powinien być linkiem (`<a href>`), żeby działało „otwórz w nowej karcie”, środkowy przycisk myszy i poprawna semantyka dla czytników ekranu. Skopiowanie stylów do osobnego `LinkButton` duplikuje kod. Rozwiązaniem jest komponent **polimorficzny**: ten sam wygląd, różny element HTML — przez prop `as` albo wzorzec `asChild`.

#T DEFINITION Prop as i przekazywanie atrybutów
Komponent polimorficzny przyjmuje prop `as` z nazwą elementu lub komponentem (`as="a"`, `as={RouterLink}`) i renderuje go z własnymi klasami, przekazując wszystkie pozostałe atrybuty (`href`, `target`, `onClick`, `aria-*`) dalej. Kluczowe są dwie rzeczy:
1. **spread pozostałych props** (`...rest`) — komponent nie musi znać wszystkich atrybutów elementu,
2. **łączenie klas** — własna klasa wariantu + `className` od użytkownika.

W JSX to kilka linii. W TSX to najtrudniejsze typowanie w kursie, bo typ props zależy od wartości `as` (dla `a` dozwolone jest `href`, dla `button` — `type`).

#T CODE_JSX Polimorficzny Button (JSX)
```
// Button.jsx
import clsx from 'clsx';

export function Button({ as: Component = 'button', variant = 'primary', className, ...rest }) {
  const extra = Component === 'button' && !rest.type ? { type: 'button' } : {};
  return <Component className={clsx('btn', `btn--${variant}`, className)} {...extra} {...rest} />;
}

// <Button onClick={save}>Zapisz</Button>
// <Button as="a" href="/tickets/42" variant="secondary">Zobacz ticket</Button>
```

#T CODE_TSX Polimorficzny Button (TSX)
Generyk `E` to typ elementu. `ComponentPropsWithoutRef<E>` pobiera wszystkie atrybuty tego elementu (dla `'a'` — także `href`), a `Omit` usuwa z nich nasze własne nazwy, żeby uniknąć konfliktów.
```
// Button.tsx
import clsx from 'clsx';
import type { ComponentPropsWithoutRef, ElementType } from 'react';

type Variant = 'primary' | 'secondary' | 'danger';

type OwnProps<E extends ElementType> = { as?: E; variant?: Variant; className?: string };

export type ButtonProps<E extends ElementType = 'button'> = OwnProps<E> &
  Omit<ComponentPropsWithoutRef<E>, keyof OwnProps<E>>;

export function Button<E extends ElementType = 'button'>({ as, variant = 'primary', className, ...rest }: ButtonProps<E>) {
  const Component: ElementType = as ?? 'button';
  return <Component className={clsx('btn', `btn--${variant}`, className)} {...rest} />;
}

export const examples = (
  <>
    <Button type="submit">Zapisz</Button>
    <Button as="a" href="/tickets/42" variant="secondary">Zobacz ticket</Button>
    {/* @ts-expect-error — przycisk nie ma atrybutu href */}
    <Button href="/x">Błąd</Button>
  </>
);
```

#T NOTE JSX ↔ TSX — tu TypeScript jest najtrudniejszy, ale najwięcej daje
Typ `ButtonProps<E>` sprawia, że `<Button as="a" href="...">` jest poprawne, a `<Button href="...">` (bez `as`) — błędem, bo `<button>` nie ma `href`. Podpowiedzi atrybutów zmieniają się po wpisaniu `as="a"`. W JSX każda kombinacja przejdzie, a pomyłka da martwy link (`<button href>` nic nie robi). Koszt: skomplikowane typy (`ElementType`, `ComponentPropsWithoutRef`, `Omit`) i jedno rzutowanie `const Component: ElementType`. To jest przypadek, w którym w zespole często korzysta się z gotowego rozwiązania biblioteki zamiast pisać typy samemu.

#T DEFINITION Wzorzec asChild (Slot)
Alternatywa spopularyzowana przez Radix: zamiast `as`, komponent przyjmuje `asChild` i **przekazuje swoje props dziecku**: `<Button asChild><a href="/tickets/42">Zobacz</a></Button>`. Implementacja korzysta z `cloneElement`: łączy klasy i props komponentu z props dziecka. Zaleta: dziecko może być dowolnym komponentem (np. `Link` z routera) z pełnymi własnymi typami — bez skomplikowanych generyków. Wada: mniej oczywiste działanie, bo `cloneElement` „wstrzykuje” props.

#T CODE_PRACTICAL Prosty Slot dla asChild
```
import { cloneElement, isValidElement, type HTMLAttributes, type ReactElement } from 'react';
import clsx from 'clsx';

type SlotChildProps = { className?: string };

export function Slot({ children, className, ...rest }: HTMLAttributes<HTMLElement>) {
  if (!isValidElement<SlotChildProps>(children)) return null;
  const child = children as ReactElement<SlotChildProps>;
  return cloneElement(child, { ...rest, className: clsx(className, child.props.className) });
}

type ButtonProps = HTMLAttributes<HTMLButtonElement> & { asChild?: boolean; variant?: 'primary' | 'secondary' };

export function SlotButton({ asChild = false, variant = 'primary', className, ...rest }: ButtonProps) {
  const classes = clsx('btn', `btn--${variant}`, className);
  if (asChild) return <Slot className={classes} {...rest} />;
  return <button type="button" className={classes} {...rest} />;
}

// <SlotButton asChild variant="secondary"><a href="/tickets/42">Zobacz ticket</a></SlotButton>
```

#T DEFINITION Przekazywanie atrybutów a dostępność
Komponenty-opakowania (przyciski, pola, karty) powinny przepuszczać atrybuty `aria-*`, `id`, `data-*` i `ref` do właściwego elementu — inaczej użytkownik komponentu nie może go opisać dla czytnika ekranu ani podpiąć etykiety. Spread `...rest` na elemencie docelowym robi to automatycznie. W TSX typ `ComponentPropsWithoutRef<'input'>` (lub `ComponentProps<'input'>` z refem) daje pełną listę atrybutów elementu za darmo.

#T CODE_BASIC Pole tekstowe przepuszczające atrybuty
```
import type { ComponentProps } from 'react';

type InputProps = ComponentProps<'input'> & { label: string; error?: string };

export function Input({ label, error, id, ...rest }: InputProps) {
  const inputId = id ?? `input-${label.toLowerCase().replace(/\s+/g, '-')}`;
  return (
    <div className="field">
      <label htmlFor={inputId}>{label}</label>
      <input id={inputId} aria-invalid={error ? true : undefined} {...rest} />
      {error && <p className="field__error">{error}</p>}
    </div>
  );
}

// <Input label="E-mail" type="email" autoComplete="email" required ref={emailRef} />
```

#T STEP_BY_STEP Budujemy razem: przyciski i linki w DevDesk
1. Przepisz `Button` na wersję z `as`; wszystkie dotychczasowe użycia działają bez zmian (domyślnie `button`).
2. W tabeli zamień „Zobacz” na `<Button as="a" href={`/tickets/${t.id}`} variant="secondary">` — kliknij środkowym przyciskiem myszy, link otwiera się w nowej karcie (routing dodasz w rozdziale 12).
3. Zbuduj `Input` z `ComponentProps<'input'>` i zastąp nim pola w formularzach; przekaż `autoComplete`, `required`, `ref` — wszystko działa bez dodatkowego kodu.
4. Zbuduj `SlotButton` z `asChild` i porównaj zapis w miejscu użycia z wersją `as`.
5. W wersji TS sprawdź podpowiedzi atrybutów po wpisaniu `as="a"` i błąd przy `href` bez `as`.
6. Przejrzyj DevDesk w poszukiwaniu `<div onClick>` udających przyciski lub linki i zamień je na `Button`.

#T PITFALL Link przez onClick zamiast href
`<Button onClick={() => (location.href = '/tickets/42')}>Zobacz</Button>` działa po kliknięciu, ale nie ma „otwórz w nowej karcie”, kopiowania adresu, podglądu adresu w pasku statusu ani poprawnej roli dla czytnika ekranu (ogłosi „przycisk”, a nie „link”). Nawigacja = link (`<a href>` lub `Link` routera); akcja = przycisk.

#T SUMMARY Kryterium akceptacji i podsumowanie
Komponent polimorficzny renderuje różne elementy z tym samym wyglądem: przez prop `as` (spread pozostałych atrybutów, łączenie klas) albo wzorzec `asChild` ze `Slot` i `cloneElement`. Komponenty-opakowania przepuszczają atrybuty (`aria-*`, `id`, `ref`) do właściwego elementu. Nawigacja to link, akcja to przycisk. W TSX: `ElementType`, `ComponentPropsWithoutRef<E>` z `Omit` dla `as`, `ComponentProps<'input'>` dla opakowań — najtrudniejsze typy w kursie, ale chroniące przed martwymi linkami.

Kryterium akceptacji: przyciski i linki w DevDesk korzystają z jednego komponentu `Button` (link „Zobacz” otwiera się w nowej karcie środkowym przyciskiem), pola formularzy używają `Input` przepuszczającego atrybuty i ref, a w aplikacji nie ma `div` udających przyciski.
