#T INTRO Rozgrzewka i problem: ta sama logika, trzy różne wyglądy
Rozgrzewka: Czym różni się `as` od `asChild`? Dlaczego nawigacja powinna być linkiem, a nie przyciskiem z `onClick`? Co daje typ `ComponentProps<'input'>`?

Problem: DevDesk potrzebuje pola „Przypisz do” z podpowiedziami (combobox): wpisujesz „an”, lista pokazuje „anna, andrzej”, strzałkami wybierasz, Enter zatwierdza. Projektant chce trzech wersji wyglądu: w formularzu, w filtrze paska narzędzi i w wąskiej kolumnie tabeli. Gdy logika (filtrowanie, aktywna pozycja, klawiatura, atrybuty ARIA) jest wbudowana w JSX komponentu, każda wersja wyglądu to kopia całej logiki. **Komponenty headless** oddzielają zachowanie od wyglądu: hook dostarcza stan i gotowe zestawy props, a Ty renderujesz, jak chcesz.

#T DEFINITION Hook headless i prop getters
Hook headless zwraca:
- **stan** (np. `isOpen`, `activeIndex`, `filteredItems`, `inputValue`),
- **akcje** (np. `select(item)`, `close()`),
- **prop getters** — funkcje zwracające obiekt props do rozłożenia na Twoich elementach: `getInputProps()`, `getListProps()`, `getItemProps(item, index)`. Zawierają handlery zdarzeń, atrybuty ARIA i identyfikatory powiązań.

Prop getter przyjmuje też Twoje własne props i łączy je z wewnętrznymi (np. dwa handlery `onKeyDown` wywołane po kolei). Tak działają biblioteki Downshift, TanStack Table, React Aria (hooki), Floating UI (`getReferenceProps`).

#T CODE_JSX Hook useCombobox (JSX)
```
// useCombobox.js
import { useId, useState } from 'react';

export function useCombobox({ items, onSelect, toLabel = (x) => String(x) }) {
  const [inputValue, setInputValue] = useState('');
  const [isOpen, setIsOpen] = useState(false);
  const [activeIndex, setActiveIndex] = useState(0);
  const listId = useId();

  const filtered = items.filter((it) => toLabel(it).toLowerCase().includes(inputValue.toLowerCase()));

  function select(item) {
    onSelect(item);
    setInputValue(toLabel(item));
    setIsOpen(false);
  }

  return {
    isOpen,
    filtered,
    activeIndex,
    getInputProps: (own = {}) => ({
      ...own,
      role: 'combobox',
      'aria-expanded': isOpen,
      'aria-controls': listId,
      'aria-activedescendant': isOpen && filtered[activeIndex] ? `${listId}-${activeIndex}` : undefined,
      value: inputValue,
      onChange: (e) => { setInputValue(e.target.value); setIsOpen(true); setActiveIndex(0); },
      onKeyDown: (e) => {
        own.onKeyDown?.(e);
        if (e.key === 'ArrowDown') { e.preventDefault(); setIsOpen(true); setActiveIndex((i) => Math.min(i + 1, filtered.length - 1)); }
        if (e.key === 'ArrowUp') { e.preventDefault(); setActiveIndex((i) => Math.max(i - 1, 0)); }
        if (e.key === 'Enter' && isOpen && filtered[activeIndex]) { e.preventDefault(); select(filtered[activeIndex]); }
        if (e.key === 'Escape') setIsOpen(false);
      },
      onBlur: () => setIsOpen(false),
    }),
    getListProps: () => ({ id: listId, role: 'listbox' }),
    getItemProps: (item, index) => ({
      id: `${listId}-${index}`,
      role: 'option',
      'aria-selected': index === activeIndex,
      onMouseDown: (e) => { e.preventDefault(); select(item); }, // przed blur pola
      onMouseEnter: () => setActiveIndex(index),
    }),
  };
}
```

#T CODE_TSX Hook useCombobox (TSX)
Generyk `T` to typ pozycji — może to być tekst, użytkownik albo ticket. Typy prop getterów pochodzą z Reacta (`InputHTMLAttributes`, `HTMLAttributes`), więc rozłożenie ich na elementach jest sprawdzane.
```
// useCombobox.ts
import { useId, useState, type HTMLAttributes, type InputHTMLAttributes, type KeyboardEvent } from 'react';

type Options<T> = { items: readonly T[]; onSelect: (item: T) => void; toLabel?: (item: T) => string };

export function useCombobox<T>({ items, onSelect, toLabel = (x) => String(x) }: Options<T>) {
  const [inputValue, setInputValue] = useState('');
  const [isOpen, setIsOpen] = useState(false);
  const [activeIndex, setActiveIndex] = useState(0);
  const listId = useId();

  const filtered = items.filter((it) => toLabel(it).toLowerCase().includes(inputValue.toLowerCase()));

  function select(item: T) {
    onSelect(item);
    setInputValue(toLabel(item));
    setIsOpen(false);
  }

  function getInputProps(own: InputHTMLAttributes<HTMLInputElement> = {}): InputHTMLAttributes<HTMLInputElement> {
    return {
      ...own,
      role: 'combobox',
      'aria-expanded': isOpen,
      'aria-controls': listId,
      'aria-activedescendant': isOpen && filtered[activeIndex] !== undefined ? `${listId}-${activeIndex}` : undefined,
      value: inputValue,
      onChange: (e) => { setInputValue(e.target.value); setIsOpen(true); setActiveIndex(0); },
      onKeyDown: (e: KeyboardEvent<HTMLInputElement>) => {
        own.onKeyDown?.(e);
        if (e.key === 'ArrowDown') { e.preventDefault(); setIsOpen(true); setActiveIndex((i) => Math.min(i + 1, filtered.length - 1)); }
        if (e.key === 'ArrowUp') { e.preventDefault(); setActiveIndex((i) => Math.max(i - 1, 0)); }
        const active = filtered[activeIndex];
        if (e.key === 'Enter' && isOpen && active !== undefined) { e.preventDefault(); select(active); }
        if (e.key === 'Escape') setIsOpen(false);
      },
      onBlur: () => setIsOpen(false),
    };
  }

  const getListProps = (): HTMLAttributes<HTMLUListElement> => ({ id: listId, role: 'listbox' });

  const getItemProps = (item: T, index: number): HTMLAttributes<HTMLLIElement> => ({
    id: `${listId}-${index}`,
    role: 'option',
    'aria-selected': index === activeIndex,
    onMouseDown: (e) => { e.preventDefault(); select(item); },
    onMouseEnter: () => setActiveIndex(index),
  });

  return { isOpen, filtered, activeIndex, getInputProps, getListProps, getItemProps };
}
```

#T NOTE JSX ↔ TSX — generyczny hook headless
W TSX generyk `T` przechodzi przez cały hook: `useCombobox({ items: users, toLabel: (u) => u.name, onSelect: (u) => assign(u.login) })` — w `toLabel` i `onSelect` parametr ma typ `User`, a `filtered` to `User[]`. Typy zwracane przez prop gettery są typami atrybutów Reacta, więc rozłożenie `{...getItemProps(u, i)}` na `<li>` jest sprawdzane (np. `aria-selected` musi być wartością logiczną). W JSX hook działa identycznie, ale pozycja w `onSelect` jest „czymkolwiek” — łatwo pomylić użytkownika z jego loginem.

#T CODE_BASIC Wygląd 1: pole w formularzu
```
import { useCombobox } from './useCombobox';

type User = { login: string; name: string };

export function AssigneeField({ users, onAssign }: { users: User[]; onAssign: (login: string) => void }) {
  const cb = useCombobox({ items: users, toLabel: (u) => u.name, onSelect: (u) => onAssign(u.login) });
  return (
    <div className="combobox">
      <label htmlFor="assignee-input">Przypisz do</label>
      <input id="assignee-input" {...cb.getInputProps({ placeholder: 'Zacznij pisać…' })} />
      {cb.isOpen && cb.filtered.length > 0 && (
        <ul {...cb.getListProps()} className="combobox__list">
          {cb.filtered.map((u, i) => (
            <li key={u.login} {...cb.getItemProps(u, i)} className={i === cb.activeIndex ? 'active' : undefined}>
              {u.name} <small>@{u.login}</small>
            </li>
          ))}
        </ul>
      )}
    </div>
  );
}
```

#T CODE_PRACTICAL Wygląd 2: kompaktowy filtr z tym samym hookiem
```
import { useCombobox } from './useCombobox';

const TAGS = ['api', 'ui', 'export', 'auth', 'mobile', 'billing'];

export function TagFilterBox({ onPick }: { onPick: (tag: string) => void }) {
  const cb = useCombobox({ items: TAGS, onSelect: onPick });
  return (
    <span className="chip-input">
      #<input aria-label="Filtr tagu" size={8} {...cb.getInputProps()} />
      {cb.isOpen && (
        <ul {...cb.getListProps()} className="chip-input__menu">
          {cb.filtered.map((t, i) => <li key={t} {...cb.getItemProps(t, i)}>#{t}</li>)}
        </ul>
      )}
    </span>
  );
}
```

#T DEFINITION Biblioteki headless w praktyce
- **TanStack Table** — logika tabel (sortowanie, filtrowanie, paginacja, grupowanie, zaznaczanie, zmiana rozmiaru kolumn) bez żadnego wyglądu; Ty renderujesz `<table>`. Kiedy Twoja tabela DevDesk urośnie (rozdział 16), to naturalny następny krok.
- **Downshift** — hooki `useCombobox`, `useSelect`, `useMultipleSelection` (wzór dla tej lekcji).
- **React Aria** — dziesiątki hooków (przyciski, pola, kalendarze, listy, przeciąganie) z bardzo dokładną dostępnością i internacjonalizacją.
- **Floating UI** — pozycjonowanie i interakcje (rozdział 08).

#T STEP_BY_STEP Budujemy razem: combobox osoby w DevDesk
1. Utwórz `useCombobox` w `hooks/`.
2. Zbuduj `AssigneeField` w formularzu ticketu — wybór osoby z podpowiedziami.
3. Zbuduj `TagFilterBox` w pasku narzędzi tabeli — wybrany tag dopisuje się do filtra.
4. Zbuduj trzecią wersję wyglądu: mały combobox w komórce tabeli do szybkiej zmiany osoby (bez etykiety widocznej — z `aria-label`).
5. Sprawdź klawiaturę: strzałki zmieniają aktywną pozycję, Enter wybiera, Escape zamyka; czytnik ekranu ogłasza aktywną pozycję (dzięki `aria-activedescendant`).
6. Kliknij pozycję myszą — wybór działa, mimo że kliknięcie zabiera fokus z pola (dzięki `onMouseDown` z `preventDefault`).
7. Policz: logika (filtrowanie, klawiatura, ARIA) jest w jednym pliku, a trzy komponenty to tylko JSX.

#T PITFALL Nadpisanie handlera z prop gettera
`<input {...cb.getInputProps()} onKeyDown={myHandler} />` — Twój `onKeyDown` zastępuje ten z hooka i klawiatura przestaje działać. Własne handlery przekazuj **do** prop gettera (`getInputProps({ onKeyDown: myHandler })`), który wywoła oba. To ta sama pułapka co ze spreadem `register` w React Hook Form.

#T SUMMARY Kryterium akceptacji i podsumowanie
Komponent headless oddziela zachowanie od wyglądu: hook zwraca stan, akcje i prop gettery (`getInputProps`, `getItemProps`) z handlerami i atrybutami ARIA, a komponent decyduje o JSX i stylach. Prop getter łączy własne props użytkownika z wewnętrznymi. Biblioteki headless (TanStack Table, Downshift, React Aria, Floating UI) stosują ten wzorzec. W TSX generyczny hook przenosi typ pozycji do callbacków, a prop gettery zwracają typy atrybutów Reacta.

Kryterium akceptacji: combobox wyboru osoby działa w trzech różnych wyglądach z jednego hooka, obsługuje klawiaturę (strzałki, Enter, Escape) i mysz, a czytnik ekranu ogłasza aktywną pozycję.
