#T INTRO Rozgrzewka i problem: powtarzające się ramki
Rozgrzewka: Dlaczego `key={index}` psuje stan wierszy po usunięciu elementu? Gdzie umieszczasz `key`, gdy wiersz jest osobnym komponentem?

Problem: tabela, statystyki i karta szczegółów mają tę samą „ramkę”: nagłówek panelu, opcjonalne akcje po prawej, obramowanie i odstępy. Można dodać do każdego komponentu props `showFrame`, `frameTitle`, `frameActions`… i po tygodniu mieć komponenty z dwudziestoma flagami. Lepszy sposób to **kompozycja**: komponent-ramka, do którego wkładasz dowolną treść.

#T DEFINITION children: treść między tagami
Wszystko, co wpiszesz między otwierający i zamykający tag komponentu, React przekazuje jako specjalny prop `children`:

`<Panel title="Tickety"><TicketTable tickets={tickets} /></Panel>`

Komponent `Panel` decyduje, gdzie wyrenderować `{children}` — nie musi wiedzieć, co to jest. Tak działają kontenery: karty, panele, modale, layouty.

#T ANALOGY Ramka na zdjęcie
Ramka nie wie, jakie zdjęcie do niej włożysz — zapewnia passe-partout, szkło i zawieszkę. Zdjęcie (children) wybierasz przy każdym użyciu. Gdy zmienisz ramkę na inną, wszystkie zdjęcia dostają nowy wygląd bez zmian w samych zdjęciach.

#T CODE_JSX Panel z children i slotem actions
`actions` to prop przyjmujący JSX — tzw. **slot**. Daje drugie miejsce na treść, obok `children`.
```
// Panel.jsx
export function Panel({ title, actions, children }) {
  return (
    <section className="panel">
      <header className="panel__header">
        <h2>{title}</h2>
        {actions && <div className="panel__actions">{actions}</div>}
      </header>
      <div className="panel__body">{children}</div>
    </section>
  );
}
```

#T CODE_TSX Panel z children i slotem actions w TSX
`ReactNode` dla obu slotów — przyjmą element, tekst, listę albo nic.
```
// Panel.tsx
import type { ReactNode } from 'react';

type PanelProps = {
  title: string;
  actions?: ReactNode;
  children: ReactNode;
};

export function Panel({ title, actions, children }: PanelProps) {
  return (
    <section className="panel">
      <header className="panel__header">
        <h2>{title}</h2>
        {actions && <div className="panel__actions">{actions}</div>}
      </header>
      <div className="panel__body">{children}</div>
    </section>
  );
}
```

#T NOTE JSX ↔ TSX — typowanie children i slotów
W TSX `children: ReactNode` (wymagane) oznacza, że `<Panel title="X" />` bez treści będzie błędem — świadoma decyzja projektowa. Gdy treść jest opcjonalna, piszesz `children?: ReactNode`. Typ `ReactNode` przyjmuje wszystko renderowalne; jeśli slot ma przyjmować tylko konkretny komponent, w praktyce i tak zostaje `ReactNode` — TypeScript nie rozróżnia typów elementów JSX. W JSX całą tę wiedzę przekazujesz nazwą props i dokumentacją.

#T CODE_PRACTICAL Toolbar: kompozycja z lewą i prawą stroną
Sloty `start` i `end` pozwalają układać dowolne kontrolki bez zmian w Toolbarze.
```
import type { ReactNode } from 'react';

type ToolbarProps = { start?: ReactNode; end?: ReactNode };

export function Toolbar({ start, end }: ToolbarProps) {
  return (
    <div className="toolbar">
      <div className="toolbar__start">{start}</div>
      <div className="toolbar__end">{end}</div>
    </div>
  );
}

export function TicketsToolbar() {
  return (
    <Toolbar
      start={<input type="search" placeholder="Szukaj…" aria-label="Szukaj ticketów" />}
      end={<button type="button">Eksport CSV</button>}
    />
  );
}
```

#T DEFINITION Thinking in React, krok 1: granice komponentów
Oficjalna metoda „Thinking in React” zaczyna od narysowania ramek wokół każdego fragmentu makiety i nadania im nazw. Wskazówki, gdzie postawić granicę:
- **jedna odpowiedzialność** — komponent robi jedną rzecz (wiersz, pasek narzędzi, plakietka),
- **dane** — fragment, który wyświetla jeden kawałek danych (ticket, statystyka), jest naturalnym komponentem,
- **powtarzalność** — to, co występuje kilka razy, staje się komponentem z props,
- **kontenery** — to, co „otacza” różną treść (ramka, modal, layout), staje się komponentem z `children`.

#T STEP_BY_STEP Budujemy razem: panele i pasek narzędzi
1. Utwórz `components/Panel.jsx` (`.tsx`) i style: `.panel { border: 1px solid #e5e7eb; border-radius: 8px; margin-bottom: 1rem; }`, `.panel__header { display: flex; justify-content: space-between; align-items: center; padding: 0.75rem 1rem; border-bottom: 1px solid #e5e7eb; }`, `.panel__body { padding: 1rem; }`.
2. Opakuj statystyki w `<Panel title="Podsumowanie">`, a tabelę w `<Panel title="Tickety">`.
3. Dodaj do panelu ticketów slot `actions` z przyciskiem „+ Nowy ticket”.
4. Utwórz `Toolbar` ze slotami `start` i `end` i umieść go w panelu ticketów nad tabelą: wyszukiwarka po lewej, „Eksport CSV” po prawej.
5. Zmień zaokrąglenie ramki w jednym miejscu (`.panel`) — zmieniają się wszystkie panele.
6. W React DevTools zobacz, że `TicketTable` jest dzieckiem `Panel` — kliknij `Panel` i obejrzyj prop `children`.

#T PITFALL Komponent-kombajn z flagami
Zamiast kompozycji programiści często dokładają flagi: `<Panel showHeader showActions actionsType="export" tableMode compact />`. Każdy nowy przypadek to nowa flaga i nowy `if` w środku. Kompozycja odwraca zależność: Panel zapewnia tylko ramkę, a treść i akcje przekazuje rodzic.

#T CODE_WRONG Flagi zamiast treści
```
export function Panel({ title, showExport, showNewButton }) {
  return (
    <section className="panel">
      <h2>{title}</h2>
      {showExport && <button>Eksport CSV</button>}
      {showNewButton && <button>+ Nowy</button>}
    </section>
  );
}
```

#T CODE_RIGHT Slot na dowolne akcje
```
export function Panel({ title, actions, children }) {
  return (
    <section className="panel">
      <h2>{title}</h2>
      {actions}
      {children}
    </section>
  );
}
```

#T SUMMARY Kryterium akceptacji i podsumowanie
Kompozycja to składanie komponentów przez wkładanie treści: prop `children` (treść między tagami) i sloty (props przyjmujące JSX, np. `actions`, `start`, `end`). Kontener zapewnia ramkę i nie musi wiedzieć, co zawiera. W TSX sloty typujesz jako `ReactNode`. Granice komponentów wyznaczasz według odpowiedzialności, danych i powtarzalności.

Kryterium akceptacji: statystyki i tabela są opakowane w ten sam komponent `Panel`, panel ticketów ma w nagłówku przycisk „+ Nowy ticket”, a nad tabelą jest `Toolbar` z wyszukiwarką i przyciskiem eksportu.
