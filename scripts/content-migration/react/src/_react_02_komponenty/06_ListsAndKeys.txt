#T INTRO Rozgrzewka i problem: pierwsza tabela ticketów
Rozgrzewka: Jak podzielić komponent na ogólny i domenowy? Co daje unia literałów w props `tone`? Co wyświetli `{0 && <b>x</b>}`?

Problem: DevDesk pokazuje jeden ticket w karcie, a ma pokazywać wszystkie w tabeli. Liczba ticketów zmienia się — nie da się napisać wierszy ręcznie. Potrzebujesz renderowania listy z tablicy danych, a React do tego wymaga jeszcze jednej rzeczy: **kluczy** (`key`).

#T DEFINITION Lista w JSX to tablica elementów
React potrafi wyrenderować tablicę elementów JSX. Tablicę danych zamieniasz w tablicę elementów metodą `map` znaną z toru JavaScript: `tickets.map((t) => <TicketRow ticket={t} />)`. Wynik wstawiasz w JSX w klamrach. Przed `map` możesz użyć `filter`, `slice`, `toSorted` — to zwykły JavaScript.

#T DEFINITION key: tożsamość elementu listy
Każdy element tablicy musi mieć prop `key` — wartość unikalną wśród rodzeństwa i **stabilną** (ten sam rekord = ten sam klucz przy każdym renderze). React używa klucza, żeby przy zmianie listy dopasować elementy z poprzedniego renderu do nowych: który wiersz został, który zniknął, który przesunął się na inną pozycję. Dzięki temu nie przebudowuje całej listy i nie myli stanu wierszy.

Najlepszy klucz to ID z danych (`ticket.id`). `key` nie trafia do komponentu jako prop — jest informacją dla Reacta.

#T CODE_JSX Tabela ticketów w JSX
```
// TicketTable.jsx
import { StatusBadge } from './StatusBadge';

export function TicketTable({ tickets }) {
  return (
    <table className="ticket-table">
      <thead>
        <tr>
          <th scope="col">ID</th>
          <th scope="col">Tytuł</th>
          <th scope="col">Status</th>
          <th scope="col">Osoba</th>
        </tr>
      </thead>
      <tbody>
        {tickets.map((ticket) => (
          <tr key={ticket.id}>
            <td>{ticket.id}</td>
            <td>{ticket.title}</td>
            <td><StatusBadge status={ticket.status} /></td>
            <td>{ticket.assignee ?? '—'}</td>
          </tr>
        ))}
      </tbody>
    </table>
  );
}
```

#T CODE_TSX Tabela ticketów w TSX
`tickets: Ticket[]` sprawia, że w `map` parametr `ticket` ma typ `Ticket` — edytor podpowiada pola, a literówka w nazwie jest błędem.
```
// TicketTable.tsx
import type { Ticket } from '../types';
import { StatusBadge } from './StatusBadge';

export function TicketTable({ tickets }: { tickets: Ticket[] }) {
  return (
    <table className="ticket-table">
      <thead>
        <tr>
          <th scope="col">ID</th>
          <th scope="col">Tytuł</th>
          <th scope="col">Status</th>
          <th scope="col">Osoba</th>
        </tr>
      </thead>
      <tbody>
        {tickets.map((ticket) => (
          <tr key={ticket.id}>
            <td>{ticket.id}</td>
            <td>{ticket.title}</td>
            <td><StatusBadge status={ticket.status} /></td>
            <td>{ticket.assignee ?? '—'}</td>
          </tr>
        ))}
      </tbody>
    </table>
  );
}
```

#T NOTE JSX ↔ TSX — listy
Typ elementu listy przepływa przez `map`, `filter` i `find` bez dodatkowych adnotacji. TypeScript wymaga, żeby `key` był `string`, `number` lub `bigint` — przekazanie obiektu (`key={ticket}`) to błąd kompilacji. Brak `key` nie jest błędem ani w JSX, ani w TSX — wykryje go React (ostrzeżenie w konsoli) i ESLint (reguła `react/jsx-key`, jeśli jest włączona).

#T VISUAL_EXAMPLE Dlaczego index jako klucz psuje stan
Lista przed usunięciem pierwszego elementu i po nim, z kluczem = index:

przed:  key=0 → #41 „Błąd logowania”   [☑ zaznaczony checkbox]
        key=1 → #42 „API timeout”      [☐]
        key=2 → #43 „Eksport CSV”      [☐]

po usunięciu #41:
        key=0 → #42 „API timeout”      [☑]  ← React uważa, że to ten sam wiersz co key=0!
        key=1 → #43 „Eksport CSV”      [☐]

Stan wiersza (zaznaczenie, wpisany tekst, otwarty podgląd) „przeskakuje” na inny rekord. Z kluczem `ticket.id` React wie, że wiersz #41 zniknął, a #42 i #43 zostały.

#T CODE_WRONG Index jako klucz w liście, która się zmienia
```
{tickets.map((ticket, index) => (
  <TicketRow key={index} ticket={ticket} />
))}
```

#T CODE_RIGHT Stabilne ID jako klucz
```
{tickets.map((ticket) => (
  <TicketRow key={ticket.id} ticket={ticket} />
))}
```

#T DEFINITION Pusta lista
`[].map(...)` zwraca pustą tablicę — tabela będzie miała same nagłówki. Użytkownik nie wie, czy to błąd, czy brak danych. Pusta lista zawsze potrzebuje komunikatu, najlepiej wewnątrz tabeli (wiersz z `colSpan`) albo zamiast niej.

#T CODE_PRACTICAL Tabela z pustym stanem i wydzielonym wierszem
Wiersz wydzielony do komponentu `TicketRow`. Klucz podajesz tam, gdzie jest `map` — na `<TicketRow>`, nie wewnątrz niego.
```
import type { Ticket } from '../types';
import { StatusBadge } from './StatusBadge';

function TicketRow({ ticket }: { ticket: Ticket }) {
  return (
    <tr>
      <td>{ticket.id}</td>
      <td>{ticket.title}</td>
      <td><StatusBadge status={ticket.status} /></td>
      <td>{ticket.assignee ?? '—'}</td>
    </tr>
  );
}

export function TicketTable({ tickets }: { tickets: Ticket[] }) {
  return (
    <table className="ticket-table">
      <thead>
        <tr><th scope="col">ID</th><th scope="col">Tytuł</th><th scope="col">Status</th><th scope="col">Osoba</th></tr>
      </thead>
      <tbody>
        {tickets.length === 0 ? (
          <tr><td colSpan={4} className="empty">Brak ticketów do wyświetlenia</td></tr>
        ) : (
          tickets.map((ticket) => <TicketRow key={ticket.id} ticket={ticket} />)
        )}
      </tbody>
    </table>
  );
}
```

#T STEP_BY_STEP Budujemy razem: tabela w DevDesk
1. Rozbuduj dane do ok. 12 ticketów w różnych statusach i priorytetach (będą potrzebne do filtrowania i paginacji).
2. Utwórz `components/TicketTable.jsx` (`.tsx`) z wydzielonym `TicketRow`.
3. W `Main` wyrenderuj `<TicketTable tickets={tickets} />` pod dashboardem.
4. Dodaj style: `.ticket-table { width: 100%; border-collapse: collapse; }`, `th, td { text-align: left; padding: 8px; border-bottom: 1px solid #e5e7eb; }`.
5. Usuń na chwilę `key` — otwórz konsolę przeglądarki i przeczytaj ostrzeżenie „Each child in a list should have a unique key prop”. Przywróć `key`.
6. Przekaż `tickets={[]}` — sprawdź komunikat pustej listy.
7. Wyświetl tylko otwarte: `tickets.filter((t) => t.status !== 'CLOSED')` w miejscu przekazania props.

#T PITFALL Klucz generowany przy renderze
`key={Math.random()}` albo `key={crypto.randomUUID()}` w `map` daje nowy klucz przy każdym renderze. React uważa wtedy każdy wiersz za nowy — odmontowuje i montuje wszystko od zera, tracąc stan i wydajność. ID generujesz raz, przy tworzeniu rekordu (rozdział 05), a nie podczas renderowania.

#T WHEN_TO_USE Kiedy index jako klucz jest akceptowalny
Tylko gdy lista jest statyczna: nigdy się nie zmienia, nie jest sortowana ani filtrowana, a elementy nie mają własnego stanu — np. lista stałych punktów w stopce. W każdym innym przypadku użyj ID z danych. Jeśli dane nie mają ID, nadaj je przy tworzeniu danych (np. podczas wczytywania).

#T SUMMARY Kryterium akceptacji i podsumowanie
Listę renderujesz przez `map`, zamieniając tablicę danych w tablicę elementów. Każdy element potrzebuje stabilnego, unikalnego `key` — najlepiej ID z danych; klucz podajesz na elemencie zwracanym z `map`. Index jako klucz psuje stan wierszy przy usuwaniu i sortowaniu. Pusta lista potrzebuje komunikatu. W TSX typ elementu przepływa przez `map` automatycznie.

Kryterium akceptacji: tabela pokazuje wszystkie tickety z kolorowymi statusami, konsola nie zawiera ostrzeżeń o kluczach, a pusta lista wyświetla komunikat „Brak ticketów do wyświetlenia”.
