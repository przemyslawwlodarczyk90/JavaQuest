#T INTRO Rozgrzewka i problem: pusty ekran DevDesk
Rozgrzewka (odpowiedz z pamięci): Co robi `createRoot(...).render(...)`? Dlaczego w TSX piszemy `getElementById('root')!`? Gdzie w projekcie Vite jest punkt wejścia aplikacji?

Problem: po rozdziale 00 DevDesk wyświetla tylko `<h1>DevDesk</h1>`. W tej lekcji budujesz szkielet aplikacji — nagłówek, boczny panel i główny obszar — z osobnych komponentów. Na koniec ekran ma strukturę docelowej aplikacji, choć jeszcze bez danych.

#T DEFINITION Komponent to funkcja zwracająca JSX
Komponent React to zwykła funkcja JavaScript, która:
- ma nazwę zaczynającą się **wielką literą** (`Header`, nie `header`),
- zwraca JSX (albo `null`, gdy nie ma nic do wyświetlenia),
- jest używana w JSX jak tag: `<Header />`.

Wielka litera nie jest kwestią stylu. Po niej React odróżnia komponent od elementu HTML: `<header>` to element HTML, `<Header />` to wywołanie Twojej funkcji.

#T ANALOGY Komponenty jak klocki z instrukcją
Komponent to instrukcja budowy jednego klocka: „nagłówek składa się z logo, nazwy i menu”. Raz napisaną instrukcję używasz wiele razy, a z małych klocków składasz większe — `AppShell` składa się z `Header`, `Sidebar` i `Main`. Zmiana instrukcji klocka zmienia go wszędzie, gdzie został użyty.

#T CODE_JSX Pierwsze komponenty w JSX
Trzy komponenty w jednym pliku i komponent `App`, który je składa.
```
// App.jsx
function Header() {
  return (
    <header className="app-header">
      <strong>DevDesk</strong>
      <nav>Dashboard | Tickety | Ustawienia</nav>
    </header>
  );
}

function Sidebar() {
  return <aside className="app-sidebar">Filtry</aside>;
}

function Main() {
  return <main className="app-main">Tu będzie tabela ticketów</main>;
}

export default function App() {
  return (
    <div className="app-shell">
      <Header />
      <Sidebar />
      <Main />
    </div>
  );
}
```

#T CODE_TSX Te same komponenty w TSX
Komponenty bez props wyglądają w TSX identycznie. TypeScript sam wywnioskuje, że funkcje zwracają JSX.
```

function Header() {
  return (
    <header className="app-header">
      <strong>DevDesk</strong>
      <nav>Dashboard | Tickety | Ustawienia</nav>
    </header>

}

function Sidebar() {
  return <aside className="app-sidebar">Filtry</aside>;
}

function Main() {
  return <main className="app-main">Tu będzie tabela ticketów</main>;
}

export default function App() {
  return (
    <div className="app-shell">
      <Header />
      <Sidebar />
      <Main />
    </div>
  );
}
```

#T NOTE JSX ↔ TSX — komponenty bez props
Różnica: żadna, poza rozszerzeniem pliku. To dobra wiadomość — TypeScript w React nie wymaga typów tam, gdzie nie ma danych wejściowych. Różnice zaczną się w lekcji 4, gdy komponenty dostaną props. Gdybyś w TSX wpisał `<Heder />` (literówka), dostaniesz błąd „Cannot find name 'Heder'” w edytorze; w JSX — błąd „Heder is not defined” dopiero w konsoli przeglądarki.

#T DEFINITION Eksport i import komponentów
Każdy większy komponent trafia do osobnego pliku w `src/components`. Są dwa sposoby eksportu:
- **eksport nazwany** — `export function Header() {...}` i import `import { Header } from './components/Header'`,
- **eksport domyślny** — `export default function App() {...}` i import `import App from './App'` (nazwę wybiera importujący).

W kursie komponenty eksportujemy nazwanie (łatwiej szukać i refaktoryzować), a domyślnie tylko `App` — tak jak w szablonie Vite.

#T VISUAL_EXAMPLE Drzewo komponentów po tej lekcji
main.jsx
└── App
    └── div.app-shell
        ├── Header      (components/Header.jsx)
        ├── Sidebar     (components/Sidebar.jsx)
        └── Main        (components/Main.jsx)

W React DevTools (zakładka Components) zobaczysz dokładnie to drzewo — bez elementów HTML, same komponenty.

#T STEP_BY_STEP Budujemy razem: szkielet DevDesk
1. W `src/components` utwórz pliki `Header.jsx`, `Sidebar.jsx`, `Main.jsx` (w projekcie TS — `.tsx`).
2. Przenieś każdy komponent do swojego pliku i dodaj `export` przed `function`.
3. W `App.jsx` zaimportuj je: `import { Header } from './components/Header';` (i dwa kolejne).
4. W `src/App.css` dodaj układ siatki dla `.app-shell` (kod poniżej) i zaimportuj plik w `App`: `import './App.css';`.
5. Uruchom `npm run dev` — nagłówek na górze, wąski panel z lewej, obszar główny z prawej.
6. Otwórz React DevTools i znajdź komponenty `Header`, `Sidebar`, `Main` w drzewie.
7. Zrób commit: „Szkielet DevDesk: Header, Sidebar, Main”.

#T PITFALL Definiowanie komponentu wewnątrz innego komponentu
Kuszące jest zapisanie małego komponentu w środku drugiego. Problem: przy każdym renderze rodzica powstaje NOWA funkcja, więc React traktuje ją jak zupełnie inny komponent — odmontowuje stary i montuje nowy, tracąc jego stan (np. tekst wpisany w pole). Komponenty definiuj zawsze na najwyższym poziomie pliku.

#T CODE_WRONG Komponent zdefiniowany w komponencie
```
export default function App() {
  function Sidebar() {          // nowa funkcja przy każdym renderze App
    return <aside>Filtry</aside>;
  }
  return <Sidebar />;
}
```

#T CODE_RIGHT Komponent na najwyższym poziomie
```
function Sidebar() {
  return <aside>Filtry</aside>;
}

export default function App() {
  return <Sidebar />;
}
```

#T WHEN_TO_USE Kiedy wydzielić komponent
Wydziel komponent, gdy fragment UI: ma własną odpowiedzialność (nagłówek, wiersz tabeli), powtarza się w kilku miejscach, jest na tyle duży, że funkcja-rodzic przestaje mieścić się na ekranie, albo będzie miał własny stan. Nie wydzielaj każdego `<div>` — komponent z jedną linią, użyty raz, zwykle tylko utrudnia czytanie.

#T SUMMARY Kryterium akceptacji i podsumowanie
Komponent to funkcja z nazwą z wielkiej litery, zwracająca JSX i używana jak tag. Komponenty trzymamy w osobnych plikach z eksportem nazwanym i definiujemy wyłącznie na najwyższym poziomie modułu. W wersji TSX komponenty bez props nie różnią się od JSX.

Kryterium akceptacji: aplikacja pokazuje nagłówek, panel boczny i obszar główny w układzie siatki; każdy z trzech komponentów jest w osobnym pliku w `src/components`; w React DevTools widać drzewo `App → Header, Sidebar, Main`.
