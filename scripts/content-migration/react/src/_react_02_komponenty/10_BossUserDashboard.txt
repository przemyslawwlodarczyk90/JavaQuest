#T INTRO Boss rozdziału 02: dashboard użytkowników
Czas sprawdzić, czy umiesz zastosować wiedzę z rozdziału w nowej sytuacji. Tym razem nie DevDesk, tylko panel zarządzania użytkownikami systemu. Nie dostajesz gotowej struktury komponentów — projektujesz ją sam. Wskazówki są stopniowane: zaglądaj do kolejnych dopiero wtedy, gdy utkniesz na dłużej niż 10–15 minut.

Rozwiąż zadanie w wybranej wersji (JSX albo TSX), a potem przepisz na drugą i porównaj.

#T DEFINITION Brief zadania
Zbuduj stronę „Użytkownicy” z następującymi elementami:
1. **Wiersz statystyk**: liczba wszystkich użytkowników, aktywnych, administratorów.
2. **Lista użytkowników** w tabeli: avatar (inicjały w kółku), imię i nazwisko, login, rola jako plakietka, status aktywny/nieaktywny.
3. **Plakietki ról**: `admin` — czerwona, `agent` — niebieska, `viewer` — szara.
4. Użytkownik **bez imienia** (`name: null`) wyświetla login zamiast imienia.
5. Użytkownik **nieaktywny** ma wiersz wyszarzony i dopisek „(nieaktywny)”.
6. Gdy lista jest pusta — komunikat „Brak użytkowników”.
7. Statystyki i tabela w osobnych panelach z tytułem; panel tabeli ma w nagłówku przycisk „+ Zaproś”.

#T STEP_BY_STEP Kryteria akceptacji
1. Statystyki pokazują 5 / 4 / 1 i zmieniają się po edycji danych.
2. Wszystkie karty statystyk są jednym komponentem z props.
3. Plakietki ról korzystają z jednego ogólnego komponentu (np. `Badge`) i jednego domenowego (`RoleBadge`).
4. Użytkownik `kasia` wyświetla „kasia” zamiast pustego imienia, a jej avatar pokazuje „K”.
5. `tomek` ma wyszarzony wiersz i dopisek „(nieaktywny)”.
6. Konsola nie zawiera ostrzeżeń o kluczach.
7. Pusta tablica `users` daje komunikat „Brak użytkowników”.
8. Żaden komponent nie mutuje props; dodatkowo w wersji TSX `npm run build` przechodzi bez błędów.

#T NOTE Wskazówka 1 — struktura komponentów
Rozrysuj ramki na makiecie. Proponowany podział: `UsersPage` → `Panel` (×2) → `StatsRow` → `StatCard` (×3); `UserTable` → `UserRow` (×N) → `Avatar`, `RoleBadge` → `Badge`. `Panel`, `StatCard` i `Badge` możesz przenieść z DevDesk bez zmian — to sprawdzian, czy były naprawdę ogólne.

#T NOTE Wskazówka 2 — inicjały i nazwa wyświetlana
Wylicz nazwę wyświetlaną jedną funkcją: `const displayName = user.name ?? user.login;`. Inicjały: podziel `displayName` po spacji, weź pierwsze litery maksymalnie dwóch słów i zamień na wielkie litery. Funkcję trzymaj poza komponentem (`utils/users.js`) — nie zależy od props komponentu, tylko od argumentu.

#T NOTE Wskazówka 3 — wyszarzony wiersz
Dodaj klasę warunkowo: `className={user.active ? 'row' : 'row row--inactive'}` i styl `.row--inactive { opacity: 0.5; }`. Dopisek: `{!user.active && <small> (nieaktywny)</small>}` — warunek jest wartością logiczną, więc nie grozi wyświetlenie zera.

#T CODE_PRACTICAL Przykładowe rozwiązanie — wiersz i avatar (TSX)
Porównaj ze swoim rozwiązaniem dopiero po spełnieniu kryteriów akceptacji. W wersji JSX usuń typy — reszta bez zmian.
```
import type { ReactNode } from 'react';

type Role = 'admin' | 'agent' | 'viewer';
type User = { id: number; login: string; name: string | null; role: Role; active: boolean };
type Tone = 'neutral' | 'danger' | 'info';

function Badge({ tone, children }: { tone: Tone; children: ReactNode }) {
  return <span className={`badge badge--${tone}`}>{children}</span>;
}

const ROLE_TONE: Record<Role, Tone> = { admin: 'danger', agent: 'info', viewer: 'neutral' };

function RoleBadge({ role }: { role: Role }) {
  return <Badge tone={ROLE_TONE[role]}>{role}</Badge>;
}

function initials(text: string): string {
  return text.split(' ').slice(0, 2).map((part) => part[0]?.toUpperCase() ?? '').join('');
}

function Avatar({ label }: { label: string }) {
  return <span className="avatar" aria-hidden="true">{initials(label)}</span>;
}

export function UserRow({ user }: { user: User }) {
  const displayName = user.name ?? user.login;
  return (
    <tr className={user.active ? 'row' : 'row row--inactive'}>
      <td><Avatar label={displayName} /></td>
      <td>
        {displayName}
        {!user.active && <small> (nieaktywny)</small>}
      </td>
      <td>{user.login}</td>
      <td><RoleBadge role={user.role} /></td>
    </tr>
  );
}
```

#T PITFALL Typowe błędy w tym zadaniu
- Liczenie statystyk wewnątrz `StatCard` (karta przestaje być ogólna) — liczby liczy rodzic, karta je tylko wyświetla.
- `key={index}` w tabeli użytkowników — użyj `user.id`.
- `user.name.split(' ')` bez obsługi `null` — w JSX błąd w przeglądarce przy `kasia`, w TSX błąd kompilacji.
- Kopiowanie `Badge` z DevDesk i dopisywanie do niego `if (role === 'admin')` — logika ról należy do `RoleBadge`.

#T SUMMARY Podsumowanie rozdziału 02
W tym rozdziale nauczyłeś się: budować komponenty i dzielić je na pliki, wstawiać dane do JSX, renderować warunkowo, przekazywać props (także warianty i sloty), renderować listy ze stabilnymi kluczami, komponować interfejs przez `children` i pilnować czystości komponentów. W wersji TSX: typy props, unie literałów, `ReactNode`, `Record` i `readonly`.

Boss zaliczony, gdy wszystkie osiem kryteriów akceptacji jest spełnionych w obu wersjach (JSX i TSX).
