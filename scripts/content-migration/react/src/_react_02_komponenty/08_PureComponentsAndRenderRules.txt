#T INTRO Rozgrzewka i problem: komponent, który daje różne wyniki
Rozgrzewka: Czym jest `children`? Czym slot różni się od `children`? Kiedy kompozycja jest lepsza od dodawania flag?

Problem: ktoś dopisał do `TicketTable` licznik „wyrenderowano N wierszy” oparty na zmiennej globalnej i sortowanie przez `tickets.sort(...)`. W trybie deweloperskim liczby są dwa razy za duże, a po każdym kliknięciu kolejność ticketów w całej aplikacji się zmienia. Przyczyna: komponent nie jest **czysty**. Ta lekcja wyjaśnia najważniejszą zasadę renderowania w React.

#T DEFINITION Czysty komponent
Komponent jest czysty, gdy:
1. **dla tych samych props i stanu zwraca ten sam JSX** — jak funkcja matematyczna `f(x) = 2x`,
2. **podczas renderowania nie zmienia niczego, co istniało przed jego wywołaniem** — zmiennych globalnych, otrzymanych props, obiektów współdzielonych, DOM-u, localStorage.

Render to **obliczenie** opisu UI, a nie miejsce na działania. React może wywołać komponent wiele razy, w dowolnym momencie, a nawet przerwać renderowanie i zacząć od nowa — dlatego obliczenie musi być bezpieczne do powtórzenia.

#T ANALOGY Przepis kulinarny a gotowanie
Przepis (komponent) mówi: „z 2 jajek i 100 g mąki wychodzą 4 naleśniki”. Przeczytanie przepisu dwa razy nie daje 8 naleśników i nie zużywa jajek z lodówki. Gdyby czytanie przepisu zjadało składniki — to byłby efekt uboczny w renderze.

#T CODE_JSX Nieczysty komponent w JSX
Dwa błędy: zmiana zmiennej spoza komponentu i mutacja otrzymanej tablicy przez `sort`.
```
// TicketTable.jsx — ŹLE
let renderedRows = 0;

export function TicketTable({ tickets }) {
  renderedRows += tickets.length;            // zmienia stan globalny
  const sorted = tickets.sort((a, b) => a.id - b.id); // sort() zmienia tablicę rodzica!
  return (
    <table>
      <caption>Wyrenderowano wierszy: {renderedRows}</caption>
      <tbody>
        {sorted.map((t) => <tr key={t.id}><td>{t.title}</td></tr>)}
      </tbody>
    </table>
  );
}
```

#T CODE_TSX Nieczysty komponent w TSX
TypeScript przepuści ten kod — `sort` na `Ticket[]` jest poprawny typowo. Czystości nie sprawdza kompilator. Można ją częściowo wymusić typem `readonly Ticket[]`, który zabroni wywołania `sort` na otrzymanej tablicy.
```
// TicketTable.tsx — ŹLE, ale kompiluje się
import type { Ticket } from '../types';

let renderedRows = 0;

export function TicketTable({ tickets }: { tickets: Ticket[] }) {
  renderedRows += tickets.length;
  const sorted = tickets.sort((a, b) => a.id - b.id);
  return (
    <table>
      <caption>Wyrenderowano wierszy: {renderedRows}</caption>
      <tbody>
        {sorted.map((t) => <tr key={t.id}><td>{t.title}</td></tr>)}
      </tbody>
    </table>
  );
}
```

#T NOTE JSX ↔ TSX — readonly jako ochrona props
Napisz w TSX `{ tickets }: { tickets: readonly Ticket[] }` — wtedy `tickets.sort(...)`, `tickets.push(...)` i `tickets.splice(...)` są błędami kompilacji, bo `readonly` tablica nie ma metod mutujących. Zostają ci metody zwracające nowe tablice: `toSorted`, `filter`, `map`, `slice`, `with`. W JSX podobnej ochrony nie ma — zostaje dyscyplina i StrictMode, który przez podwójne wywołanie szybko ujawnia takie błędy.

#T CODE_RIGHT Czysty komponent
`toSorted` (ES2023) zwraca nową, posortowaną tablicę i nie rusza oryginału. Licznik wierszy jest wyliczony z danych, a nie zliczany w zmiennej globalnej.
```
import type { Ticket } from '../types';

export function TicketTable({ tickets }: { tickets: readonly Ticket[] }) {
  const sorted = tickets.toSorted((a, b) => a.id - b.id);
  return (
    <table>
      <caption>Wierszy: {sorted.length}</caption>
      <tbody>
        {sorted.map((t) => <tr key={t.id}><td>{t.title}</td></tr>)}
      </tbody>
    </table>
  );
}
```

#T DEFINITION Lokalna mutacja jest w porządku
Czystość dotyczy rzeczy istniejących **przed** renderem. Tablicę lub obiekt utworzone **wewnątrz** komponentu w trakcie tego renderu możesz dowolnie zmieniać — nikt inny ich nie widzi. Np. `const rows = []; for (const t of tickets) rows.push(<Row key={t.id} ticket={t} />);` jest poprawne.

#T DEFINITION Gdzie zatem robić efekty uboczne
Zmiany świata (zapis do API, localStorage, zmiana tytułu strony, licznik analityczny) mają dwa właściwe miejsca:
- **handlery zdarzeń** — kod uruchamiany po kliknięciu, wpisaniu, wysłaniu formularza (rozdział 04),
- **efekty (`useEffect`)** — synchronizacja z systemem zewnętrznym po renderze (rozdział 07).

Nigdy w samym ciele komponentu podczas renderowania.

#T VISUAL_EXAMPLE Co robi StrictMode z nieczystym komponentem
Tryb deweloperski + StrictMode → każdy komponent wywołany 2× przy renderze:

czysty:    TicketTable() → JSX A   TicketTable() → JSX A   ✔ wynik ten sam, nic się nie dzieje
nieczysty: TicketTable() → licznik 12, tablica rodzica posortowana
           TicketTable() → licznik 24 ✘ widać błąd od razu w trybie deweloperskim

Dlatego StrictMode jest Twoim sprzymierzeńcem — pokazuje błędy, które w produkcji wyszłyby rzadko i losowo.

3. W wersji TS zmień typ props tablic na `readonly Ticket[]` i sprawdź, czy kompilator nie zgłasza mutacji.
4. Wklej na chwilę nieczystą wersję `TicketTable` z tej lekcji i obserwuj podwójny licznik w trybie deweloperskim. Usuń ją.
5. Upewnij się, że `main.jsx` nadal ma `<StrictMode>`.

#T PITFALL Odczyt zmiennych środowiska w renderze
`new Date()`, `Math.random()` w renderze sprawiają, że komponent przy tych samych props daje inny wynik. Data „stan na dzisiaj” w nagłówku jest akceptowalna (zmienia się rzadko i nie ma skutków ubocznych), ale losowe ID czy klucze generowane przy renderze już nie. Wartości, które mają być stałe, wylicz raz (przy tworzeniu danych) albo przechowaj w stanie lub refie.

#T SUMMARY Kryterium akceptacji i podsumowanie
Komponent musi być czysty: te same props i stan → ten sam JSX, bez zmieniania czegokolwiek, co istniało przed renderem. Lokalnie utworzone obiekty możesz mutować. Efekty uboczne należą do handlerów zdarzeń i `useEffect`. StrictMode wywołuje komponenty podwójnie, żeby ujawnić nieczystość. W TSX `readonly T[]` w props blokuje mutujące metody tablic.

Kryterium akceptacji: żaden komponent DevDesk nie mutuje props ani zmiennych globalnych, sortowanie używa `toSorted`, w wersji TS tablice w props są `readonly`, a podwójne renderowanie w StrictMode nie zmienia wyników na ekranie.
