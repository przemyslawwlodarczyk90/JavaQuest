#T INTRO Trening: jak pracować z tą lekcją
To lekcja bez nowej teorii — sama praktyka mechanizmów z całego rozdziału: JSX, warunki, listy z `key`, props (wartości domyślne, funkcje, reszta props) i `children`. Każde zadanie to mały, zamknięty komponent. Rytm pracy:

1. Przeczytaj treść zadania i kryteria „Sprawdź się”.
2. Napisz rozwiązanie sam — najpierw w `.jsx`, potem przepisz na `.tsx` i dopisz typ props.
3. Dopiero wtedy porównaj z rozwiązaniem poniżej. Różnice w nazwach nie mają znaczenia, ważne, czy spełniasz kryteria.

Zadania oznaczone „Przewidź wynik” rozwiązujesz w głowie: najpierw zapisz, co pojawi się na ekranie, potem sprawdź odpowiedź. Wszystkie komponenty możesz wrzucić do jednego pliku `Drill.jsx` i renderować kolejno w `App`.

#T STEP_BY_STEP Zadanie 1 — wyrażenia w JSX: UserGreeting
Napisz komponent `UserGreeting`, który przyjmuje `name` (tekst) i `unread` (liczba).

Wymagania:
1. Nagłówek `h2` z tekstem „Cześć, ANNA!” — imię wielkimi literami, wyliczone w JSX.
2. Akapit „Masz 3 nieprzeczytane wiadomości”, gdzie liczba pochodzi z props.
3. Akapit ma klasę `muted`, gdy `unread` wynosi 0, a `highlight` w przeciwnym razie.
4. Pod spodem dzisiejsza data w formacie lokalnym (`toLocaleDateString('pl-PL')`).

Sprawdź się: `<UserGreeting name="Anna" unread={0} />` renderuje akapit z klasą `muted` i tekstem z liczbą 0.

#T CODE_JSX Rozwiązanie 1 (JSX)
```
// UserGreeting.jsx
export function UserGreeting({ name, unread }) {
  const today = new Date().toLocaleDateString('pl-PL');

  return (
    <section>
      <h2>Cześć, {name.toUpperCase()}!</h2>
      <p className={unread === 0 ? 'muted' : 'highlight'}>
        Masz {unread} nieprzeczytane wiadomości
      </p>
      <small>{today}</small>
    </section>
  );
}
```

#T STEP_BY_STEP Zadanie 2 — renderowanie warunkowe: StockInfo
Komponent `StockInfo` przyjmuje `quantity` (liczba albo `null`, gdy stan magazynu jest nieznany).

Wymagania:
1. `null` → komponent nie renderuje niczego (wczesny `return null`).
2. `0` → czerwony napis „Brak w magazynie”.
3. 1–4 → „Ostatnie sztuki: 3”.
4. 5 i więcej → „Dostępne: 12 szt.”.
5. Nie używaj zagnieżdżonych operatorów `?:` — wybierz wariant w zwykłym kodzie przed `return`.

Sprawdź się: dla `quantity={0}` widać komunikat o braku, a nie cyfrę 0.

#T CODE_JSX Rozwiązanie 2 (JSX)

```
// StockInfo.jsx
export function StockInfo({ quantity }) {
```

```
    return <p className="stock stock--low">Ostatnie sztuki: {quantity}</p>;
  }
  return <p className="stock">Dostępne: {quantity} szt.</p>;
}
```

#T CODE_BASIC Zadanie 3 — przewidź wynik: && z liczbą
Co zobaczysz na ekranie dla `count = 0`, `items = []` i `user = null`? Zapisz odpowiedź dla każdej linii, zanim przeczytasz rozwiązanie.
```
// @check-skip
<div>
  {count && <span>Nowe: {count}</span>}          {/* A */}
  {items.length && <ul>…</ul>}                  {/* B */}
  {items.length > 0 && <ul>…</ul>}              {/* C */}
  {user && <p>{user.name}</p>}                  {/* D */}
  {count ? <span>Nowe: {count}</span> : null}   {/* E */}
</div>
```

#T NOTE Odpowiedź do zadania 3
- **A** — na ekranie pojawi się „0”. `0 && …` zwraca `0`, a React renderuje liczby (pomija tylko `null`, `undefined`, `true` i `false`).
- **B** — to samo: `items.length` to `0`, więc znowu widać „0”.
- **C** — nic. Porównanie zwraca `false`, a `false` nie jest renderowane.
- **D** — nic. `null && …` zwraca `null`.
- **E** — nic. Operator `?:` z `null` w drugiej gałęzi jest bezpieczny.

Zasada: po lewej stronie `&&` w JSX stawiaj **wartość logiczną** (`count > 0`, `Boolean(x)`, `!!x`), nigdy gołą liczbę.

#T STEP_BY_STEP Zadanie 4 — lista z kluczami: TagList
Komponent `TagList` przyjmuje tablicę tekstów `tags`.

Wymagania:
1. Każdy tag jako `<li>` w `<ul className="tags">`, poprzedzony znakiem `#`.
2. Klucz: sam tekst tagu (tagi są unikalne).
3. Pusta tablica → akapit „Brak tagów” zamiast pustej listy.
4. Dodatkowy prop `max` (domyślnie 3): pokaż tylko pierwsze `max` tagów, a jeśli jest ich więcej, dopisz `<li>` „+2 więcej”.

Sprawdź się: `tags={['react', 'jsx', 'props', 'state', 'hooks']}` → trzy tagi i „+2 więcej”, bez ostrzeżeń o `key` w konsoli.

#T CODE_JSX Rozwiązanie 4 (JSX)
```
// TagList.jsx
export function TagList({ tags, max = 3 }) {
  if (tags.length === 0) return <p className="muted">Brak tagów</p>;

  const visible = tags.slice(0, max);
  const hidden = tags.length - visible.length;

  return (
    <ul className="tags">
      {visible.map((tag) => (
        <li key={tag}>#{tag}</li>
      ))}
      {hidden > 0 && <li className="tags__more">+{hidden} więcej</li>}
    </ul>
  );
}
```

#T STEP_BY_STEP Zadanie 5 — wartości domyślne props: Avatar
Komponent `Avatar` pokazuje kółko z inicjałami.

Wymagania:
1. Props: `name` (wymagany), `size` (domyślnie 40), `rounded` (domyślnie `true`), `imageUrl` (opcjonalny).
2. Gdy jest `imageUrl` — renderuj `<img>` z `alt` równym imieniu.
3. W przeciwnym razie — `<span>` z inicjałami (pierwsze litery dwóch pierwszych słów, wielkie litery: „Jan Kowalski” → „JK”).
4. Rozmiar przez `style={{ width: size, height: size }}`, zaokrąglenie przez `borderRadius: rounded ? '50%' : 8`.
5. Funkcję `initials` wydziel poza komponent — to czysta funkcja.

Sprawdź się: `<Avatar name="Jan Kowalski" />` daje kółko 40×40 z „JK”; `<Avatar name="Ola" size={64} rounded={false} />` — kwadrat 64×64 z „O”.

#T CODE_JSX Rozwiązanie 5 (JSX)
```
// Avatar.jsx
function initials(name) {
  return name
    .split(' ')
    .filter(Boolean)
    .slice(0, 2)
    .map((word) => word[0].toUpperCase())
    .join('');
}

export function Avatar({ name, size = 40, rounded = true, imageUrl }) {
  const style = { width: size, height: size, borderRadius: rounded ? '50%' : 8 };

  if (imageUrl) {
    return <img src={imageUrl} alt={name} style={style} className="avatar" />;
  }
  return (
    <span className="avatar avatar--initials" style={style} aria-label={name}>
      {initials(name)}
    </span>
  );
}
```

#T STEP_BY_STEP Zadanie 6 — props-funkcje: RatingStars
Komponent `RatingStars` nie ma własnego stanu — wartość dostaje od rodzica, a o kliknięciu informuje przez callback.

Wymagania:

#T STEP_BY_STEP Zadanie 7 — reszta props: IconButton
Komponent `IconButton` opakowuje zwykły `<button>`, ale ma przyjmować **wszystkie** atrybuty przycisku (`onClick`, `disabled`, `title`, `aria-*`…), bez wypisywania ich ręcznie.

Wymagania:
1. Własne props: `icon` (tekst, np. emoji) i `label` (tekst przycisku).
2. Wszystko inne zbierz operatorem reszty `...rest` i przekaż na `<button>`.
3. Domyślnie `type="button"`, ale tak, by rodzic mógł nadpisać go na `submit`.
4. Klasa `icon-button` zawsze, plus ewentualna `className` od rodzica.

Sprawdź się: `<IconButton icon="🗑" label="Usuń" disabled className="danger" onClick={…} />` daje wyłączony przycisk z klasami `icon-button danger`.

#T CODE_JSX Rozwiązanie 7 (JSX)
```
// IconButton.jsx
export function IconButton({ icon, label, className = '', type = 'button', ...rest }) {
  return (
    <button type={type} className={`icon-button ${className}`.trim()} {...rest}>
      <span aria-hidden="true">{icon}</span> {label}
    </button>
  );
}
```

#T CODE_TSX Rozwiązanie 7 (TSX)
```
// IconButton.tsx
import type { ComponentProps } from 'react';

type IconButtonProps = ComponentProps<'button'> & {
  icon: string;
  label: string;
};

export function IconButton({ icon, label, className = '', type = 'button', ...rest }: IconButtonProps) {
  return (
    <button type={type} className={`icon-button ${className}`.trim()} {...rest}>
      <span aria-hidden="true">{icon}</span> {label}
    </button>
  );
}
```

#T NOTE JSX ↔ TSX — skąd wziąć typy atrybutów HTML
`ComponentProps<'button'>` to wszystkie atrybuty, które przyjmuje `<button>` w JSX — razem z `onClick`, `disabled` i `aria-*`. Dzięki temu w TSX `<IconButton disabledd />` jest błędem, a IDE podpowiada atrybuty. W JSX `...rest` przekaże wszystko, także literówki — zobaczysz je dopiero jako ostrzeżenie w konsoli przeglądarki. Kolejność ma znaczenie: atrybuty zapisane **po** `{...rest}` nadpisują to, co przyszło od rodzica, a te **przed** — mogą zostać nadpisane.

#T CODE_BASIC Zadanie 10 — przewidź wynik: czystość i props tylko do odczytu
Każdy z trzech komponentów ma błąd. Dla każdego zapisz: co się stanie (błąd, dziwne zachowanie, ostrzeżenie) i jak to naprawić.
```
// @check-skip
// A
function Title(props) {
  props.text = props.text.trim();
  return <h1>{props.text}</h1>;
}

// B
let renderCount = 0;
function Counter() {
  renderCount++;
  return <p>Render nr {renderCount}</p>;
}

// C
function SortedList({ items }) {
  items.sort();
  return <ul>{items.map((i) => <li key={i}>{i}</li>)}</ul>;
}
```

#T NOTE Odpowiedź do zadania 10
- **A** — props są zamrożone (w trybie deweloperskim React wywołuje `Object.freeze`), więc przypisanie rzuci `TypeError: Cannot assign to read only property`. Naprawa: wylicz nową zmienną — `const text = props.text.trim();`.
- **B** — komponent zmienia zmienną spoza siebie, więc jest nieczysty. W StrictMode render wykonuje się dwa razy i zobaczysz „Render nr 2” już przy pierwszym wyświetleniu, a potem liczby skaczą co dwa. Naprawa: liczba renderów to nie dane interfejsu — jeśli potrzebujesz licznika kliknięć, użyjesz stanu (rozdział 04).
- **C** — `sort()` sortuje tablicę **w miejscu**, czyli mutuje props rodzica. Rodzic nagle ma posortowane dane, a w StrictMode ten sam render daje inny efekt uboczny. Naprawa: `const sorted = items.toSorted();` (albo `[...items].sort()`).

#T STEP_BY_STEP Zadanie 11 — warianty z obiektu: PriorityBadge i lista
Połącz kilka mechanizmów w jednym zadaniu.

Wymagania:

Sprawdź się: dodanie piątego priorytetu wymaga zmiany **tylko** obiektu konfiguracji.

#T CODE_JSX Rozwiązanie 11 (JSX)
```
// PriorityBadge.jsx
const PRIORITY_CONFIG = {
  LOW: { label: 'Niski', className: 'badge--gray' },
  MEDIUM: { label: 'Średni', className: 'badge--blue' },
  HIGH: { label: 'Wysoki', className: 'badge--orange' },

export function PriorityBadge({ priority }) {
  const { label, className } = PRIORITY_CONFIG[priority];
  return <span className={`badge ${className}`}>{label}</span>;

export function PriorityLegend({ highlighted }) {
  return (
    <ul className="legend">
      {Object.keys(PRIORITY_CONFIG).map((priority) => (
        <li key={priority}>
          {priority === highlighted
            ? <mark><PriorityBadge priority={priority} /></mark>
            : <PriorityBadge priority={priority} />}
        </li>
      ))}
    </ul>
  );
}
```

```
  MEDIUM: { label: 'Średni', className: 'badge--blue' },
  HIGH: { label: 'Wysoki', className: 'badge--orange' },
  CRITICAL: { label: 'Krytyczny', className: 'badge--red' },
};

export function PriorityBadge({ priority }: { priority: TicketPriority }) {
  const { label, className } = PRIORITY_CONFIG[priority];
  return <span className={`badge ${className}`}>{label}</span>;
}

export function PriorityLegend({ highlighted }: { highlighted?: TicketPriority }) {
  // Object.keys zwraca string[] — rzutujemy, bo klucze pochodzą z obiektu o znanym typie.
  const priorities = Object.keys(PRIORITY_CONFIG) as TicketPriority[];
  return (
    <ul className="legend">
      {priorities.map((priority) => (
        <li key={priority}>
          {priority === highlighted
            ? <mark><PriorityBadge priority={priority} /></mark>
            : <PriorityBadge priority={priority} />}
        </li>
      ))}
    </ul>
  );
}
```

#T NOTE JSX ↔ TSX — Record pilnuje kompletności
`Record<TicketPriority, …>` wymaga wpisu dla **każdej** wartości unii. Gdy dodasz `'BLOCKER'` do typu `TicketPriority`, TSX od razu pokaże błąd w `PRIORITY_CONFIG`, że brakuje klucza. W JSX brakujący wpis wyjdzie dopiero w działaniu: `PRIORITY_CONFIG['BLOCKER']` to `undefined`, a destrukturyzacja rzuci `TypeError`.

#T STEP_BY_STEP Zadanie 12 — kompozycja: ProductCard
Zadanie końcowe: zbuduj kartę produktu wyłącznie z komponentów z poprzednich zadań i jednego nowego.

Wymagania:
1. `ProductCard` przyjmuje obiekt `product` (`{ id, name, price, quantity, tags, rating }`) i callback `onRate(id, rating)`.
2. Wewnątrz: nazwa, cena sformatowana przez `toLocaleString('pl-PL', { style: 'currency', currency: 'PLN' })`, `StockInfo`, `TagList`, `RatingStars`.
3. `RatingStars` dostaje `onRate`, który wywołuje callback karty **z id produktu** — karta „dokleja” swoje dane do zdarzenia.
4. `ProductGrid` renderuje listę kart z kluczem `product.id`.

Sprawdź się: kliknięcie trzeciej gwiazdki w karcie produktu o id 7 wywołuje `onRate(7, 3)` w rodzicu siatki.

#T CODE_JSX Rozwiązanie 12 (JSX)
```
// ProductCard.jsx
import { StockInfo } from './StockInfo';
import { TagList } from './TagList';
import { RatingStars } from './RatingStars';

const price = (value) => value.toLocaleString('pl-PL', { style: 'currency', currency: 'PLN' });

export function ProductCard({ product, onRate }) {

      {products.map((product) => (
        <ProductCard key={product.id} product={product} onRate={onRate} />
      ))}
    </div>
  );
}
```

#T CODE_TSX Rozwiązanie 12 (TSX)
```
// ProductCard.tsx
import { StockInfo } from './StockInfo';
import { TagList } from './TagList';
import { RatingStars } from './RatingStars';

export type Product = {
  id: number;
  name: string;
  price: number;
  quantity: number | null;
  tags: string[];
  rating: number;
};

type RateHandler = (productId: number, rating: number) => void;

const price = (value: number) => value.toLocaleString('pl-PL', { style: 'currency', currency: 'PLN' });

export function ProductCard({ product, onRate }: { product: Product; onRate: RateHandler }) {
  return (
    <article className="card">
      <h3>{product.name}</h3>
      <p className="card__price">{price(product.price)}</p>
      <StockInfo quantity={product.quantity} />
      <TagList tags={product.tags} />
      <RatingStars value={product.rating} onRate={(rating) => onRate(product.id, rating)} />
    </article>
  );
}

export function ProductGrid({ products, onRate }: { products: Product[]; onRate: RateHandler }) {
  return (
    <div className="grid">
      {products.map((product) => (
        <ProductCard key={product.id} product={product} onRate={onRate} />
      ))}
    </div>
  );
}
```

#T PITFALL Najczęstsze błędy z tego treningu
- `onClick={onRate(n)}` zamiast `onClick={() => onRate(n)}` — funkcja wykona się w trakcie renderu, a nie po kliknięciu.
- Liczba po lewej stronie `&&` — na ekranie pojawia się „0”.
- `key` z indeksu tablicy przy liście, która się zmienia, albo `key` nadany elementowi wewnątrz komponentu zamiast elementowi zwracanemu z `map`.
- Mutowanie props (`props.x = …`, `items.sort()`) zamiast wyliczenia nowej wartości.
- Mnożenie flag (`showSidebar`, `showHeader`) tam, gdzie wystarczy przekazać JSX w slocie lub `children`.

#T SUMMARY Podsumowanie treningu
Przećwiczyłeś cały warsztat komponentu bez stanu: wyrażenia i warunki w JSX, listy z kluczami, props z wartościami domyślnymi, callbacki w props (dane w dół, zdarzenia w górę), reszta props przekazywana na element HTML, `children` i sloty, konfigurację wariantów obiektem oraz kompozycję gotowych klocków w większy komponent. W TSX każdy komponent dostał typ props, a `Record` i `ComponentProps<'button'>` pokazały, jak kompilator pilnuje kompletności i poprawności atrybutów.

Kryterium zaliczenia: wszystkie 12 zadań napisane samodzielnie w JSX i TSX, odpowiedzi do zadań 3 i 10 zgodne z rozwiązaniem, a w konsoli przeglądarki brak ostrzeżeń o `key`.
