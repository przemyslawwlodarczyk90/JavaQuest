#T INTRO Rozgrzewka i problem: trzy prawie identyczne karty
Rozgrzewka: Kiedy użyć wczesnego `return`, a kiedy `?:`? Dlaczego `{count && ...}` bywa niebezpieczne?

Problem: dashboard DevDesk ma trzy karty statystyk: „Otwarte: 124”, „Pilne: 17”, „Moje: 8”. Skopiowanie tego samego JSX trzy razy działa, ale każda zmiana wyglądu karty to trzy poprawki. Potrzebujesz jednego komponentu `StatCard`, któremu przekazujesz różne dane. Do tego służą **props**.

#T DEFINITION Props: argumenty komponentu
Props (properties) to dane przekazywane komponentowi przez rodzica — w JSX zapisujesz je jak atrybuty: `<StatCard label="Otwarte" value={124} />`. React zbiera wszystkie atrybuty w jeden obiekt i przekazuje go jako pierwszy argument funkcji komponentu. Zwykle od razu go destrukturyzujesz: `function StatCard({ label, value })`.

Props są **tylko do odczytu**. Komponent nie zmienia otrzymanych props — jeśli dane mają się zmienić, zmienia je właściciel (rodzic), a komponent dostaje nowe props przy kolejnym renderze.

#T ANALOGY Props jak parametry zamówienia
Komponent to kucharz z jednym przepisem na kanapkę. Props to karteczka z zamówieniem: „z szynką, bez pomidora, duża”. Ten sam kucharz z różnymi karteczkami robi różne kanapki. Kucharz nie przerabia karteczki — realizuje to, co na niej jest.

#T CODE_JSX StatCard w JSX
Wartości tekstowe w cudzysłowie, wszystkie inne (liczby, obiekty, funkcje, zmienne) w klamrach.
```
// StatCard.jsx
export function StatCard({ label, value, hint = '' }) {
  return (
    <div className="stat-card">
      <span className="stat-card__label">{label}</span>
      <strong className="stat-card__value">{value}</strong>
      {hint && <small>{hint}</small>}
    </div>
  );
}

// użycie
export function StatsRow() {
  return (
    <div className="stats-row">
      <StatCard label="Otwarte" value={124} />
      <StatCard label="Pilne" value={17} hint="HIGH i CRITICAL" />
      <StatCard label="Moje" value={8} />
    </div>
  );
}
```

#T CODE_TSX StatCard w TSX
Typ props mówi, które pola są wymagane, a które opcjonalne (`hint?`). Wartość domyślną podajesz w destrukturyzacji, tak jak w JS.
```
// StatCard.tsx
type StatCardProps = {
  label: string;
  value: number;
  hint?: string;
};

export function StatCard({ label, value, hint = '' }: StatCardProps) {
  return (
    <div className="stat-card">
      <span className="stat-card__label">{label}</span>
      <strong className="stat-card__value">{value}</strong>
      {hint && <small>{hint}</small>}
    </div>
  );
}

export function StatsRow() {
  return (
    <div className="stats-row">
      <StatCard label="Otwarte" value={124} />
      <StatCard label="Pilne" value={17} hint="HIGH i CRITICAL" />
      <StatCard label="Moje" value={8} />
    </div>
  );
}
```

#T NOTE JSX ↔ TSX — co daje typ props
- `<StatCard label="Otwarte" />` bez `value` → w TSX błąd „Property 'value' is missing”, w JSX karta pokaże pustą wartość,
- `value="124"` (tekst zamiast liczby) → w TSX błąd typu, w JSX zadziała „przypadkiem”, ale np. sortowanie kart po wartości porównywałoby teksty,
- `<StatCard lable="Otwarte" ... />` (literówka w nazwie) → w TSX błąd, w JSX props `label` będzie `undefined`,
- edytor przy wpisywaniu `<StatCard ` podpowiada dostępne props wraz z typami.

W JSX tę samą umowę możesz udokumentować komentarzem JSDoc — edytor użyje go do podpowiedzi, ale bez błędów kompilacji.

#T DEFINITION Co można przekazać przez props
Wszystko, co jest wartością JavaScript:
- tekst: `title="Raport"`,
- liczby i wartości logiczne: `value={17}`, `compact={true}` (skrót: samo `compact`),
- obiekty i tablice: `ticket={ticket}`, `tags={['api', 'ui']}`,
- funkcje: `onSelect={handleSelect}` (lekcja o zdarzeniach),
- JSX: `icon={<AlertIcon />}`, a także specjalny prop `children` (lekcja o kompozycji).

Zapis `{...ticket}` przekazuje wszystkie pola obiektu jako osobne props — wygodne, ale ukrywa, czego komponent naprawdę używa. Stosuj z umiarem.

#T CODE_BASIC Przekazywanie obiektu zamiast wielu props
```
import type { Ticket } from '../types';

export function TicketSummary({ ticket }: { ticket: Ticket }) {
  return (
    <p>
      #{ticket.id} · {ticket.title} · {ticket.status}
    </p>
  );
}
```

#T CODE_PRACTICAL Karty liczone z danych
StatCard nie wie nic o ticketach — dostaje gotowe liczby. Liczenie zostaje w komponencie, który ma dane.
```
import { tickets } from '../data/tickets';
import { StatCard } from './StatCard';

export function Dashboard() {
  const open = tickets.filter((t) => t.status === 'OPEN').length;
  const urgent = tickets.filter((t) => t.priority === 'HIGH' || t.priority === 'CRITICAL').length;
  const mine = tickets.filter((t) => t.assignee === 'anna').length;

  return (
    <div className="stats-row">
      <StatCard label="Otwarte" value={open} />
      <StatCard label="Pilne" value={urgent} hint="HIGH i CRITICAL" />
      <StatCard label="Moje" value={mine} />
    </div>
  );
}
```

#T STEP_BY_STEP Budujemy razem: wiersz statystyk na dashboardzie
1. Utwórz `components/StatCard.jsx` (`.tsx`) z props `label`, `value`, opcjonalnym `hint`.
2. Dodaj style: `.stats-row { display: flex; gap: 1rem; }` i `.stat-card { border: 1px solid #e5e7eb; border-radius: 8px; padding: 1rem; min-width: 140px; }`.
3. Utwórz `components/Dashboard.jsx` liczący trzy wartości z `tickets` i renderujący trzy karty.
4. Wstaw `<Dashboard />` na górze `Main`.
5. Otwórz React DevTools, kliknij każdą kartę — w panelu props zobaczysz różne `label` i `value`.
6. W wersji TS usuń `value` z jednej karty — przeczytaj błąd; przywróć.
7. Zmień wygląd karty (np. kolor wartości) w jednym miejscu — zmienią się wszystkie trzy.

#T PITFALL Modyfikowanie props
Zmiana props wewnątrz komponentu (`props.value = 0`, `ticket.status = 'CLOSED'`) narusza zasadę „props tylko do odczytu”. Rodzic nie dowie się o zmianie, ekran się nie zaktualizuje albo zaktualizuje w przypadkowym momencie, a do tego zmienisz współdzielony obiekt danych. Zmiany danych realizuje się przez stan rodzica (rozdział 04).

#T CODE_WRONG Komponent zmienia otrzymany obiekt
```
export function CloseButton({ ticket }) {
  return <button onClick={() => { ticket.status = 'CLOSED'; }}>Zamknij</button>;
}
```

#T CODE_RIGHT Komponent prosi rodzica o zmianę
```
export function CloseButton({ ticket, onClose }) {
  return <button onClick={() => onClose(ticket.id)}>Zamknij</button>;
}
```

#T SUMMARY Kryterium akceptacji i podsumowanie
Props to argumenty komponentu przekazywane jak atrybuty JSX i odbierane jednym obiektem (zwykle przez destrukturyzację z wartościami domyślnymi). Są tylko do odczytu. W TSX typ props określa wymagane i opcjonalne pola oraz ich typy, co daje podpowiedzi i błędy przy złym użyciu.

Kryterium akceptacji: dashboard pokazuje trzy karty statystyk z jednego komponentu `StatCard`, wartości są liczone z danych ticketów, a zmiana wyglądu karty w jednym pliku zmienia wszystkie trzy.
