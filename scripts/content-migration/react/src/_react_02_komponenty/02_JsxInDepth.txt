#T INTRO Rozgrzewka i problem: liczby wpisane na sztywno
Rozgrzewka: Dlaczego nazwa komponentu musi zaczynać się wielką literą? Dlaczego nie definiujemy komponentu wewnątrz innego?

Problem: nagłówek głównego obszaru ma wyświetlać „Otwarte tickety: 124”. Wpisanie 124 na sztywno jest bez sensu — liczba ma wynikać z danych. W tej lekcji poznasz JSX dokładnie: jak wstawiać wartości JavaScript, jak działają atrybuty i dlaczego `class` to `className`.

#T DEFINITION JSX to wyrażenie JavaScript
JSX wygląda jak HTML, ale jest wyrażeniem JavaScript — po kompilacji zamienia się w wywołanie funkcji zwracające obiekt. Konsekwencje:
- JSX można przypisać do zmiennej, zwrócić z funkcji, przekazać jako argument, umieścić w tablicy,
- w nawiasach klamrowych `{ }` wstawiasz **dowolne wyrażenie** JavaScript: zmienną, wywołanie funkcji, działanie, operator warunkowy,
- w `{ }` nie wstawisz **instrukcji**: `if`, `for`, deklaracji `const`. Zamiast tego używasz wyrażeń (`?:`, `&&`, `map`).

#T CODE_JSX Wyrażenia w JSX
```
// Main.jsx
import { tickets } from '../data/tickets';

export function Main() {
  const openCount = tickets.filter((t) => t.status === 'OPEN').length;
  const today = new Date().toLocaleDateString('pl-PL');

  return (
    <main className="app-main">
      <h1>Otwarte tickety: {openCount}</h1>
      <p>Stan na {today} · wszystkich: {tickets.length}</p>
      <p>Udział otwartych: {Math.round((openCount / tickets.length) * 100)}%</p>
    </main>
  );
}
```

#T CODE_TSX Wyrażenia w TSX
Kod identyczny. TypeScript zna typ `tickets` (`Ticket[]`), więc literówka w `t.status === 'OPNE'` byłaby błędem: porównanie typu `TicketStatus` z wartością spoza unii.
```
// Main.tsx
import { tickets } from '../data/tickets';

export function Main() {
  const openCount = tickets.filter((t) => t.status === 'OPEN').length;
  const today = new Date().toLocaleDateString('pl-PL');

  return (
    <main className="app-main">
      <h1>Otwarte tickety: {openCount}</h1>
      <p>Stan na {today} · wszystkich: {tickets.length}</p>
      <p>Udział otwartych: {Math.round((openCount / tickets.length) * 100)}%</p>
    </main>
  );
}
```

#T NOTE JSX ↔ TSX — co sprawdza TypeScript w samym JSX
W TSX kompilator sprawdza także znaczniki: czy element HTML przyjmuje dany atrybut (`<img scr="...">` — błąd), czy wartość atrybutu ma dobry typ (`<input maxLength="10">` — błąd, oczekiwana liczba `{10}`), czy obiekt `style` ma poprawne właściwości CSS. W JSX te pomyłki przejdą bez słowa — atrybut zostanie po cichu zignorowany albo React wypisze ostrzeżenie w konsoli.

#T API_REFERENCE Różnice między JSX a HTML
- `className` zamiast `class` (bo `class` to słowo kluczowe JS),
- `htmlFor` zamiast `for` w `<label>`,
- atrybuty w camelCase: `onClick`, `tabIndex`, `maxLength`, `readOnly`, `autoFocus`; wyjątki: `aria-*` i `data-*` zostają z myślnikiem,
- `style` przyjmuje **obiekt** z właściwościami w camelCase: `style={{ backgroundColor: 'red', marginTop: 8 }}` (liczba = piksele),
- każdy element musi być zamknięty: `<br />`, `<img />`, `<input />`,
- komponent zwraca **jeden** element główny — kilka elementów opakowujesz we fragment `<>...</>`,
- komentarz w JSX: `{/* komentarz */}`,
- wartości logiczne, `null` i `undefined` nie wyświetlają się nic; liczba `0` się wyświetla,
- wartości liczbowe atrybutów w klamrach: `tabIndex={0}`, tekstowe w cudzysłowie: `type="text"`.

#T CODE_BASIC Fragment, style i atrybuty
```
export function StatsHeader() {
  const urgent = 17;
  return (
    <>
      {/* fragment: dwa elementy bez dodatkowego diva */}
      <h2 style={{ color: urgent > 10 ? 'crimson' : 'inherit', marginBottom: 4 }}>
        Pilne: {urgent}
      </h2>
      <label htmlFor="search">Szukaj</label>
      <input id="search" type="search" maxLength={50} aria-label="Szukaj ticketów" />
    </>
  );
}
```

#T DEFINITION Atrybuty z wyrażeniami i spread atrybutów
Wartość atrybutu może być wyrażeniem: `className={isActive ? 'tab tab--active' : 'tab'}`, `src={user.avatarUrl}`, `disabled={!canSave}`. Można też przekazać wiele atrybutów naraz ze zmiennej obiektowej: `<input {...inputProps} />` — każde pole obiektu staje się atrybutem.

#T CODE_PRACTICAL Licznik w nagłówku z danych
Funkcje pomocnicze wywołane w JSX — wynik trafia na ekran. Funkcje trzymaj poza komponentem, jeśli nie zależą od jego danych.
```
import { tickets } from '../data/tickets';

function countByStatus(status) {
  return tickets.filter((t) => t.status === status).length;
}

function plural(n) {
  return n === 1 ? 'ticket' : n % 10 >= 2 && n % 10 <= 4 && (n % 100 < 10 || n % 100 >= 20) ? 'tickety' : 'ticketów';
}

export function Summary() {
  const open = countByStatus('OPEN');
  return (
    <p>
      {open} {plural(open)} czeka na obsługę, {countByStatus('IN_PROGRESS')} w toku.
    </p>
  );
}
```

#T STEP_BY_STEP Budujemy razem: liczniki z danych
1. Upewnij się, że masz `src/data/tickets.js` (lub `.ts`) z co najmniej pięcioma ticketami w różnych statusach.
2. W `Main` zaimportuj `tickets` i policz otwarte tickety przez `filter(...).length`.
3. Wyświetl w nagłówku „Otwarte tickety: {openCount}”.
4. Dodaj akapit z liczbą wszystkich ticketów i datą (`toLocaleDateString('pl-PL')`).
5. Dodaj funkcję `plural` i użyj jej do poprawnej odmiany słowa „ticket”.
6. Zmień status jednego ticketu w danych z `CLOSED` na `OPEN` i zapisz — licznik zmieni się sam.
7. W wersji TS spróbuj wpisać `<input maxLength="50">` i przeczytaj błąd typu; popraw na `{50}`.

#T PITFALL Instrukcja zamiast wyrażenia w klamrach
`{ if (open > 0) { 'Są tickety' } }` to błąd składni — w JSX klamry przyjmują tylko wyrażenia. Warunki zapisujesz operatorem `?:` albo przenosisz logikę nad `return` do zwykłej zmiennej. Renderowaniu warunkowemu poświęcona jest następna lekcja.

#T CODE_WRONG Obiekt wstawiony jako tekst
React nie wyświetli obiektu — rzuci błąd „Objects are not valid as a React child”.
```
export function TicketTitle({ ticket }) {
  return <h3>{ticket}</h3>;
}
```

#T CODE_RIGHT Wstawiamy konkretne pole
```
export function TicketTitle({ ticket }) {
  return <h3>#{ticket.id} {ticket.title}</h3>;
}
```

#T SUMMARY Kryterium akceptacji i podsumowanie
JSX jest wyrażeniem JavaScript: w `{ }` wstawiasz wyrażenia, nie instrukcje. Atrybuty w camelCase (`className`, `htmlFor`, `onClick`), `style` jako obiekt, każdy element zamknięty, jeden element główny lub fragment `<>...</>`. W TSX kompilator sprawdza także nazwy i typy atrybutów.

Kryterium akceptacji: nagłówek pokazuje liczbę otwartych ticketów wyliczaną z danych (zmiana danych zmienia liczbę), obok widać liczbę wszystkich ticketów i datę, a słowo „ticket” jest poprawnie odmienione.
