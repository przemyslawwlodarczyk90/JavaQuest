#T INTRO Boss rozdziału 08: dostępny modal edycji profilu
Ostatni sprawdzian rozdziału łączy refy, portal, fokus, klawiaturę, zakładki, menu i powiadomienia. Domena: profil użytkownika w ustawieniach aplikacji. Budujesz własne komponenty (bez bibliotek headless) — chodzi o to, żebyś rozumiał każdy mechanizm. Wynik ma być w pełni obsługiwalny klawiaturą i czytnikiem ekranu.

#T DEFINITION Brief zadania
Przycisk „Edytuj profil” w nagłówku otwiera modal z:
1. **Zakładkami** „Dane”, „Powiadomienia”, „Bezpieczeństwo” (dostępne zakładki z obsługą strzałek).
2. Zakładka **Dane**: imię i nazwisko, e-mail, awatar (wybór pliku z podglądem miniatury), krótki opis z licznikiem znaków (max 160).
3. Zakładka **Powiadomienia**: przełączniki (checkboxy) e-mail/w aplikacji/dźwięk i lista rozwijana częstotliwości podsumowań.
4. Zakładka **Bezpieczeństwo**: przycisk „Wyloguj ze wszystkich urządzeń” z menu potwierdzenia (popover z „Potwierdź / Anuluj”).
5. **Zapis**: przycisk „Zapisz” wysyła dane (symulacja 800 ms), zamyka modal i pokazuje toast „Zapisano profil”.
6. **Niezapisane zmiany**: zamknięcie modala (Escape, ✕, kliknięcie tła) przy zmienionych danych pyta „Masz niezapisane zmiany — Odrzuć / Wróć do edycji”.
7. **Błąd walidacji**: niepoprawny e-mail przełącza na zakładkę „Dane”, ustawia fokus na polu i „trzęsie” nim.

#T STEP_BY_STEP Kryteria akceptacji
1. Modal renderowany przez portal (lub `<dialog>`) z `role="dialog"`, `aria-modal`, tytułem w `aria-labelledby`.
2. Po otwarciu fokus na pierwszym polu aktywnej zakładki; Tab nie wychodzi poza modal; po zamknięciu fokus wraca na „Edytuj profil”.
3. Zakładki spełniają wzorzec ARIA i działają strzałkami, Home, End; stan zakładek, które nie są widoczne, jest zachowany (przełączanie nie gubi wpisanych danych).
4. Podgląd awatara używa `URL.createObjectURL` i zwalnia adres (`URL.revokeObjectURL`) przy zmianie pliku i zamknięciu modala.
5. „Niezapisane zmiany” to wartość wyliczana z porównania danych formularza z zapisanymi (bez dodatkowego stanu „dirty”).
6. Popover potwierdzenia zamyka się Escape i kliknięciem obok; fokus wraca na przycisk, który go otworzył.
7. Błąd e-maila: przełączenie zakładki + fokus + animacja przez uchwyt `useImperativeHandle` (np. `ShakeBox`).
8. Toast po zapisie jest odczytywany przez czytnik ekranu (`aria-live`).
9. Wszystkie timery i nasłuchiwania mają sprzątanie; w StrictMode nic nie dzieje się podwójnie. W wersji TSX: generyczne zakładki z unią ID zakładek, typowane refy i uchwyty, `npm run build` bez błędów.

#T NOTE Wskazówka 1 — gdzie żyje stan
Dane formularza (wszystkie trzy zakładki) trzymaj w jednym obiekcie stanu w komponencie modala — wtedy zakładki mogą być ukrywane przez `hidden`, a porównanie z zapisanym profilem jest jednym wyrażeniem. Zapisany profil przychodzi z props (albo kontekstu użytkownika). Stan „czy pokazać pytanie o niezapisane zmiany” to osobny, mały stan; sama informacja o zmianach — wyliczana.

#T NOTE Wskazówka 2 — podgląd pliku bez wycieków
Adres podglądu twórz w handlerze `onChange` pola pliku i trzymaj w stanie. Efekt zależny od adresu zwalnia go w sprzątaniu: `useEffect(() => () => { if (previewUrl) URL.revokeObjectURL(previewUrl); }, [previewUrl]);` — przy zmianie pliku zwolni poprzedni, przy odmontowaniu ostatni.

#T CODE_JSX Szkielet modala i zamykanie z pytaniem (JSX)
```
// ProfileModal.jsx — fragment do rozbudowy
import { useState } from 'react';

export function useCloseGuard(isDirty, onClose) {
  const [confirming, setConfirming] = useState(false);

  function requestClose() {
    if (isDirty) setConfirming(true);
    else onClose();
  }

  return {
    confirming,
    requestClose,
    discard: () => { setConfirming(false); onClose(); },
    keepEditing: () => setConfirming(false),
  };
}
```

#T CODE_TSX Szkielet modala i zamykanie z pytaniem (TSX)
```
// ProfileModal.tsx — fragment do rozbudowy
import { useState } from 'react';

export type Profile = {
  name: string;
  email: string;
  bio: string;
  notifyEmail: boolean;
  notifyInApp: boolean;
  sound: boolean;
  digest: 'daily' | 'weekly' | 'never';
};

export function isProfileDirty(current: Profile, saved: Profile): boolean {
  return (Object.keys(saved) as (keyof Profile)[]).some((key) => current[key] !== saved[key]);
}

export function useCloseGuard(isDirty: boolean, onClose: () => void) {
  const [confirming, setConfirming] = useState(false);

  function requestClose() {
    if (isDirty) setConfirming(true);
    else onClose();
  }

  return {
    confirming,
    requestClose,
    discard: () => { setConfirming(false); onClose(); },
    keepEditing: () => setConfirming(false),
  };
}
```

#T NOTE Wskazówka 3 — jeden punkt zamykania
Escape, przycisk ✕ i kliknięcie tła wywołują tę samą funkcję `requestClose` z `useCloseGuard`. Dzięki temu logika „czy pytać” jest w jednym miejscu. Zwróć uwagę: gdy otwarte jest pytanie o niezapisane zmiany albo popover potwierdzenia, Escape powinien zamknąć **tylko najwyżej położony** element — obsłuż kolejność (np. `stopPropagation` w popoverze albo sprawdzenie stanu w handlerze modala).

#T PITFALL Typowe błędy w tym zadaniu
- Zakładki renderowane warunkowo — przełączenie gubi dane z formularza innej zakładki.
- `isDirty` jako stan ustawiany przy każdej zmianie pola — rozjeżdża się po cofnięciu zmiany do pierwotnej wartości.
- Escape zamyka jednocześnie popover i cały modal.
- Brak `revokeObjectURL` — każdy wybrany plik zostaje w pamięci do zamknięcia karty.
- Fokus po zamknięciu modala ląduje na `body`, bo przycisk otwierający został odmontowany (np. nagłówek renderowany warunkowo) — sprawdź, czy element do przywrócenia fokusu nadal istnieje.

#T SUMMARY Podsumowanie rozdziału 08
W tym rozdziale poznałeś refy na wartości i na elementy DOM, ref jako prop i `useImperativeHandle`, zbudowałeś dostępne zakładki, modal przez portal i na elemencie `dialog`, zarządzanie fokusem i skróty klawiszowe, system toastów z cofaniem oraz menu, popovery i podpowiedzi (ręcznie, przez Popover API i Floating UI). W TSX: `useRef<HTMLElement>`, typy uchwytów, komponenty generyczne, rozróżnienie zdarzeń natywnych i Reactowych oraz zawężanie typów DOM.

Boss zaliczony, gdy wszystkie dziewięć kryteriów akceptacji jest spełnionych, a cały przepływ (otwórz, edytuj, przełączaj zakładki, zapisz, zamknij z niezapisanymi zmianami) da się przejść wyłącznie klawiaturą.
