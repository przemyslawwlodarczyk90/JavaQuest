#T INTRO Rozgrzewka i problem: klawiatura gubi się w modalu
Rozgrzewka: Gdzie w DOM trafia komponent renderowany przez portal, a gdzie w drzewie Reacta? Dlaczego tło modala zamyka go na `onMouseDown`? Co daje element `<dialog>`?

Problem: po otwarciu własnego modala fokus zostaje na przycisku „+ Nowy ticket” pod spodem. Tab przechodzi po elementach strony za modalem, a po zamknięciu fokus ląduje na początku dokumentu — użytkownik klawiatury musi przejść całą stronę od nowa. Do tego DevDesk nie ma skrótów klawiszowych do nawigacji po liście. Ta lekcja to praktyczne zarządzanie fokusem.

#T DEFINITION Trzy zasady fokusu dla okien i paneli
1. **Przy otwarciu** — przenieś fokus do środka: na pierwsze pole formularza albo na sam dialog (z `tabIndex={-1}`).
2. **W trakcie** — fokus nie może wyjść poza modal: Tab z ostatniego elementu wraca na pierwszy, Shift+Tab z pierwszego — na ostatni (pułapka fokusu, focus trap). Reszta strony powinna być niedostępna (atrybut `inert` na kontenerze aplikacji albo `aria-modal`).
3. **Przy zamknięciu** — przywróć fokus na element, który otworzył modal.

#T CODE_JSX Hook zarządzający fokusem modala (JSX)
```
// useFocusTrap.js
import { useEffect, useRef } from 'react';

const FOCUSABLE = 'a[href], button:not([disabled]), input:not([disabled]), select:not([disabled]), textarea:not([disabled]), [tabindex]:not([tabindex="-1"])';

export function useFocusTrap(open) {
  const containerRef = useRef(null);

  useEffect(() => {
    if (!open || !containerRef.current) return;
    const container = containerRef.current;
    const previouslyFocused = document.activeElement;

    const items = () => Array.from(container.querySelectorAll(FOCUSABLE));
    (items()[0] ?? container).focus();

    function handleKey(e) {
      if (e.key !== 'Tab') return;
      const list = items();
      if (list.length === 0) return;
      const first = list[0];
      const last = list[list.length - 1];
      if (e.shiftKey && document.activeElement === first) {
        e.preventDefault();
        last.focus();
      } else if (!e.shiftKey && document.activeElement === last) {
        e.preventDefault();
        first.focus();
      }
    }

    container.addEventListener('keydown', handleKey);
    return () => {
      container.removeEventListener('keydown', handleKey);
      previouslyFocused?.focus?.(); // powrót fokusu
    };
  }, [open]);

  return containerRef;
}
```

#T CODE_TSX Hook zarządzający fokusem modala (TSX)
Ref ma typ `HTMLDivElement`. `document.activeElement` to `Element | null` — przed `focus()` trzeba sprawdzić, czy to `HTMLElement`.
```
// useFocusTrap.ts
import { useEffect, useRef } from 'react';

const FOCUSABLE = 'a[href], button:not([disabled]), input:not([disabled]), select:not([disabled]), textarea:not([disabled]), [tabindex]:not([tabindex="-1"])';

export function useFocusTrap(open: boolean) {
  const containerRef = useRef<HTMLDivElement>(null);

  useEffect(() => {
    const container = containerRef.current;
    if (!open || !container) return;
    const previouslyFocused = document.activeElement instanceof HTMLElement ? document.activeElement : null;

    const items = () => Array.from(container.querySelectorAll<HTMLElement>(FOCUSABLE));
    (items()[0] ?? container).focus();

    function handleKey(e: KeyboardEvent) {
      if (e.key !== 'Tab') return;
      const list = items();
      if (list.length === 0) return;
      const first = list[0];
      const last = list[list.length - 1];
      if (e.shiftKey && document.activeElement === first) {
        e.preventDefault();
        last.focus();
      } else if (!e.shiftKey && document.activeElement === last) {
        e.preventDefault();
        first.focus();
      }
    }

    container.addEventListener('keydown', handleKey);
    return () => {
      container.removeEventListener('keydown', handleKey);
      previouslyFocused?.focus();
    };
  }, [open]);

  return containerRef;
}
```

#T NOTE JSX ↔ TSX — elementy DOM wymagają zawężania
Kod pracujący na DOM-ie to miejsce, gdzie TSX wymusza sprawdzenia, które w JSX łatwo pominąć: `document.activeElement` może być `null` albo elementem bez `focus()` (np. SVG), `querySelectorAll` bez generyka zwraca `Element`, który nie ma metody `focus`. Generyk `querySelectorAll<HTMLElement>(...)` i `instanceof HTMLElement` rozwiązują problem. W JSX zapis `previouslyFocused?.focus?.()` robi to samo w czasie działania — działa, ale wymaga pamiętania o każdym przypadku.

#T DEFINITION Atrybut inert
`inert` na elemencie sprawia, że cała jego zawartość jest niedostępna: nie przyjmuje fokusu, nie reaguje na kliknięcia, jest ukryta przed czytnikami ekranu. Ustawiony na kontenerze aplikacji (`#root` albo `<main>`) podczas otwartego modala daje to, co pułapka fokusu, ale na poziomie przeglądarki. W React 19 to zwykły atrybut logiczny: `<div inert={modalOpen}>`. Natywny `<dialog>` otwierany `showModal()` robi to automatycznie dla reszty strony.

#T CODE_BASIC Modal z pułapką fokusu
```
import type { ReactNode } from 'react';
import { createPortal } from 'react-dom';
import { useFocusTrap } from './useFocusTrap';

export function AccessibleModal({ open, title, children }: { open: boolean; title: string; children: ReactNode }) {
  const containerRef = useFocusTrap(open);
  if (!open) return null;
  return createPortal(
    <div className="modal-backdrop">
      <div ref={containerRef} role="dialog" aria-modal="true" aria-label={title} tabIndex={-1} className="modal">
        {children}
      </div>
    </div>,
    document.body,
  );
}
```

#T CODE_PRACTICAL Nawigacja po liście klawiszami j/k
Skróty jak w wielu narzędziach dla programistów: j — następny, k — poprzedni, Enter — otwórz. Działają tylko, gdy użytkownik nie pisze w polu.
```
import { useEffect } from 'react';

type ListKeysOptions = { count: number; activeIndex: number; onMove: (index: number) => void; onOpen: () => void };

export function useListKeys({ count, activeIndex, onMove, onOpen }: ListKeysOptions) {
  useEffect(() => {
    function handleKey(e: KeyboardEvent) {
      const target = e.target as HTMLElement;
      if (target.closest('input, textarea, select, [contenteditable="true"]')) return;
      if (e.key === 'j') onMove(Math.min(count - 1, activeIndex + 1));
      else if (e.key === 'k') onMove(Math.max(0, activeIndex - 1));
      else if (e.key === 'Enter') onOpen();
    }
    window.addEventListener('keydown', handleKey);
    return () => window.removeEventListener('keydown', handleKey);
  }, [count, activeIndex, onMove, onOpen]);
}
```

#T STEP_BY_STEP Budujemy razem: DevDesk obsługiwany klawiaturą
1. Dodaj `useFocusTrap` do własnego modala; fokus po otwarciu trafia na pole tytułu (pierwszy element).
2. Ustaw `inert={dialogOpen}` na kontenerze `.app-shell` — elementy pod modalem są niedostępne.
3. Zamknij modal Escape — fokus wraca na przycisk „+ Nowy ticket”.
4. Dodaj `useListKeys` w tabeli ticketów: j/k przesuwają zaznaczenie, Enter otwiera kartę szczegółów; aktywny wiersz jest przewijany do widoku (ref z poprzedniej lekcji).
5. Dodaj link „Przejdź do treści” (skip link) na samym początku strony, widoczny po fokusie — prowadzi do `<main id="main">`.
6. Przejdź cały przepływ bez myszy: otwórz modal, wypełnij formularz, wyślij, wybierz ticket klawiszami, dodaj komentarz.
7. Sprawdź `:focus-visible` — każdy element z fokusem ma wyraźne obramowanie w obu motywach.

#T PITFALL Fokus ustawiany w renderze albo za wcześnie
`inputRef.current?.focus()` w ciele komponentu nie zadziała przy pierwszym renderze (element jeszcze nie istnieje) i łamie czystość renderu. Fokus ustawiasz w efekcie (po commicie) lub w handlerze. Gdy element pojawia się z animacją albo w portalu, który montuje się w tym samym renderze, efekt zwykle wystarcza; jeśli nie — `requestAnimationFrame` w efekcie.

#T SUMMARY Kryterium akceptacji i podsumowanie
Zarządzanie fokusem okna: przenieś fokus do środka przy otwarciu, zatrzymaj go w środku (pułapka Tab/Shift+Tab lub `inert` na reszcie strony), przywróć na element otwierający przy zamknięciu. Skróty klawiszowe podpinaj w efekcie ze sprzątaniem i wyłączaj podczas pisania w polach. Skip link pozwala pominąć nawigację. W TSX elementy DOM wymagają zawężania (`instanceof HTMLElement`, `querySelectorAll<HTMLElement>`).

Kryterium akceptacji: modal przenosi fokus do pierwszego pola, Tab nie wychodzi poza modal, po zamknięciu fokus wraca na przycisk otwierający, lista ticketów obsługuje j/k/Enter, a cały przepływ tworzenia ticketu da się przejść bez myszy.
