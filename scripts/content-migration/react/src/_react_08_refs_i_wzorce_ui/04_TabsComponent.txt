#T INTRO Rozgrzewka i problem: karta ticketu jest za długa
Rozgrzewka: Kiedy użyć `useImperativeHandle`, a kiedy zwykłego propa? Jak przekazać ref do wnętrza komponentu w React 19? Dlaczego nie zmieniasz `innerHTML` przez ref?

Problem: karta szczegółów ticketu zawiera opis, komentarze, historię zmian, załączniki i powiązane tickety — trzeba przewijać przez cały ekran. Rozwiązaniem są **zakładki**: „Szczegóły / Aktywność / Historia”. Wygląda prosto, ale dobre zakładki muszą być dostępne (role ARIA, obsługa strzałek na klawiaturze) i mieć przemyślaną odpowiedź na pytanie: kto przechowuje aktywną zakładkę?

#T DEFINITION Wzorzec zakładek (tabs) według WAI-ARIA
Struktura dostępnych zakładek:
- kontener z `role="tablist"` i etykietą (`aria-label`),
- każda zakładka: `<button role="tab">` z `aria-selected`, `aria-controls` (ID panelu) i `id`,
- każdy panel: `role="tabpanel"` z `aria-labelledby` (ID zakładki),
- klawiatura: Tab wchodzi do listy zakładek tylko raz (na aktywną), **strzałki lewo/prawo** przełączają zakładki, Home/End — pierwsza/ostatnia; aktywna zakładka ma `tabIndex={0}`, pozostałe `tabIndex={-1}` (tzw. roving tabindex).

#T DEFINITION Kontrolowany czy niekontrolowany
- **Niekontrolowany**: komponent sam trzyma `activeTab` (z `defaultTab` na start). Prosty w użyciu, ale rodzic nie może przełączyć zakładki („pokaż Historię po zapisie”).
- **Kontrolowany**: `activeTab` przychodzi z props razem z `onTabChange`. Rodzic ma pełną kontrolę — może zapamiętać zakładkę w URL, przełączyć ją z kodu, zresetować przy zmianie ticketu.

Dobry komponent zakładek obsługuje oba tryby: jeśli rodzic poda `value`, komponent jest kontrolowany; jeśli nie — używa własnego stanu.

#T CODE_JSX Dostępne zakładki (JSX)
```
// Tabs.jsx
import { useId, useRef, useState } from 'react';

export function Tabs({ tabs, value, defaultValue, onChange, label }) {
  const [internal, setInternal] = useState(defaultValue ?? tabs[0].id);
  const active = value ?? internal; // kontrolowany, jeśli podano value
  const baseId = useId();
  const buttonsRef = useRef([]);

  function select(id) {
    if (value === undefined) setInternal(id);
    onChange?.(id);
  }

  function handleKeyDown(e, index) {
    const last = tabs.length - 1;
    const next = e.key === 'ArrowRight' ? (index === last ? 0 : index + 1)
      : e.key === 'ArrowLeft' ? (index === 0 ? last : index - 1)
      : e.key === 'Home' ? 0 : e.key === 'End' ? last : null;
    if (next === null) return;
    e.preventDefault();
    select(tabs[next].id);
    buttonsRef.current[next]?.focus();
  }

  return (
    <div>
      <div role="tablist" aria-label={label}>
        {tabs.map((tab, i) => (
          <button
            key={tab.id}
            ref={(el) => { buttonsRef.current[i] = el; }}
            type="button"
            role="tab"
            id={`${baseId}-tab-${tab.id}`}
            aria-selected={tab.id === active}
            aria-controls={`${baseId}-panel-${tab.id}`}
            tabIndex={tab.id === active ? 0 : -1}
            onClick={() => select(tab.id)}
            onKeyDown={(e) => handleKeyDown(e, i)}
          >
            {tab.label}
          </button>
        ))}
      </div>
      {tabs.map((tab) => (
        <div key={tab.id} role="tabpanel" id={`${baseId}-panel-${tab.id}`} aria-labelledby={`${baseId}-tab-${tab.id}`} hidden={tab.id !== active}>
          {tab.content}
        </div>
      ))}
    </div>
  );
}
```

#T CODE_TSX Dostępne zakładki (TSX)
Komponent jest generyczny: `T extends string` to typ identyfikatorów zakładek. Rodzic używający `Tabs` z ID `'details' | 'activity' | 'history'` dostaje w `onChange` dokładnie tę unię.
```
// Tabs.tsx
import { useId, useRef, useState, type KeyboardEvent, type ReactNode } from 'react';

export type Tab<T extends string> = { id: T; label: string; content: ReactNode };

type TabsProps<T extends string> = {
  tabs: readonly Tab<T>[];
  label: string;
  value?: T;
  defaultValue?: T;
  onChange?: (id: T) => void;
};

export function Tabs<T extends string>({ tabs, value, defaultValue, onChange, label }: TabsProps<T>) {
  const [internal, setInternal] = useState<T>(defaultValue ?? tabs[0].id);
  const active = value ?? internal;
  const baseId = useId();
  const buttonsRef = useRef<(HTMLButtonElement | null)[]>([]);

  function select(id: T) {
    if (value === undefined) setInternal(id);
    onChange?.(id);
  }

  function handleKeyDown(e: KeyboardEvent<HTMLButtonElement>, index: number) {
    const last = tabs.length - 1;
    const next = e.key === 'ArrowRight' ? (index === last ? 0 : index + 1)
      : e.key === 'ArrowLeft' ? (index === 0 ? last : index - 1)
      : e.key === 'Home' ? 0 : e.key === 'End' ? last : null;
    if (next === null) return;
    e.preventDefault();
    select(tabs[next].id);
    buttonsRef.current[next]?.focus();
  }

  return (
    <div>
      <div role="tablist" aria-label={label}>
        {tabs.map((tab, i) => (
          <button
            key={tab.id}
            ref={(el) => { buttonsRef.current[i] = el; }}
            type="button"
            role="tab"
            id={`${baseId}-tab-${tab.id}`}
            aria-selected={tab.id === active}
            aria-controls={`${baseId}-panel-${tab.id}`}
            tabIndex={tab.id === active ? 0 : -1}
            onClick={() => select(tab.id)}
            onKeyDown={(e) => handleKeyDown(e, i)}
          >
            {tab.label}
          </button>
        ))}
      </div>
      {tabs.map((tab) => (
        <div key={tab.id} role="tabpanel" id={`${baseId}-panel-${tab.id}`} aria-labelledby={`${baseId}-tab-${tab.id}`} hidden={tab.id !== active}>
          {tab.content}
        </div>
      ))}
    </div>
  );
}
```

#T NOTE JSX ↔ TSX — komponent generyczny
To pierwszy **generyczny komponent** w kursie: `function Tabs<T extends string>(props: TabsProps<T>)`. TypeScript wnioskuje `T` z przekazanych zakładek, więc `value="histroy"` (literówka) jest błędem, a `onChange` dostaje `'details' | 'activity' | 'history'` zamiast `string`. W JSX komponent działa tak samo, ale ID zakładek to zwykłe teksty. Uwaga składniowa: w pliku `.tsx` zapis strzałkowy `const Tabs = <T,>(props) => ...` wymaga przecinka po `T` (inaczej parser weźmie `<T>` za znacznik JSX) — dlatego generyczne komponenty wygodniej pisać jako `function`.

#T DEFINITION Ukrywanie paneli: hidden czy warunek
Panel nieaktywny możesz ukryć atrybutem `hidden` (element zostaje w DOM, stan jego komponentów jest **zachowany**) albo nie renderować go wcale (`{active === 'x' && <Panel />}` — stan **przepada** przy przełączeniu). Wybór zależy od tego, czy zakładka ma pamiętać np. wpisany komentarz albo pozycję przewinięcia. Pamiętaj z rozdziału 06: odmontowanie kasuje stan. Kosztowne panele (np. wykres) często lepiej odmontować, a lekkie — ukryć.

#T CODE_BASIC Użycie kontrolowane w karcie ticketu
Zakładka resetuje się do „Szczegółów” przy zmianie ticketu (stan w rodzicu + reset w handlerze wyboru) i przełącza się na „Aktywność” po dodaniu komentarza.
```
import { useState } from 'react';
import { Tabs } from './Tabs';

type DetailTab = 'details' | 'activity' | 'history';

export function TicketDetails({ description }: { description: string }) {
  const [tab, setTab] = useState<DetailTab>('details');

  return (
    <Tabs
      label="Sekcje ticketu"
      value={tab}
      onChange={setTab}
      tabs={[
        { id: 'details', label: 'Szczegóły', content: <p>{description}</p> },
        { id: 'activity', label: 'Aktywność', content: <p>Komentarze…</p> },
        { id: 'history', label: 'Historia', content: <p>Zmiany statusu…</p> },
      ]}
    />
  );
}
```

#T STEP_BY_STEP Budujemy razem: zakładki w karcie ticketu
1. Utwórz `Tabs` według przykładu (z obsługą trybu kontrolowanego i niekontrolowanego).
2. Podziel kartę ticketu na zakładki: „Szczegóły” (opis, tagi, priorytet), „Aktywność” (komentarze z formularzem), „Historia” (lista zmian statusu).
3. Sterowanie z rodzica: po dodaniu komentarza przełącz na „Aktywność”; przy wyborze innego ticketu wróć na „Szczegóły” (w handlerze wyboru, nie w efekcie).
4. Przetestuj klawiaturą: Tab wchodzi na aktywną zakładkę, strzałki przełączają, Home/End skaczą na skraj, kolejny Tab przechodzi do zawartości panelu.
5. Wpisz komentarz w „Aktywności”, przełącz na „Historię” i z powrotem — tekst zostaje (panel ukryty przez `hidden`). Zmień na renderowanie warunkowe i zobacz różnicę.
6. Sprawdź czytnikiem ekranu, że ogłaszane jest „zakładka, wybrana, 1 z 3”.

#T PITFALL Zakładki z div-ów bez semantyki
`<div className="tab" onClick={...}>` wygląda jak zakładka, ale nie przyjmuje fokusu, nie reaguje na Enter, a czytnik ekranu odczyta zwykły tekst. Interaktywne elementy to przyciski (`<button>`), a rolę zakładek nadajesz przez `role="tab"` i atrybuty ARIA. Jeśli nie chcesz pisać tego sam — biblioteki headless (Radix Tabs, React Aria) robią dokładnie to samo.

#T SUMMARY Kryterium akceptacji i podsumowanie
Dostępne zakładki to `role="tablist"`, przyciski `role="tab"` z `aria-selected`/`aria-controls` i panele `role="tabpanel"` z `aria-labelledby`, obsługa strzałek, Home/End i roving tabindex. Komponent może być kontrolowany (`value` + `onChange`) lub niekontrolowany (`defaultValue`) — obsłuż oba. Panele ukryte przez `hidden` zachowują stan, odmontowane — tracą. W TSX `Tabs<T extends string>` to komponent generyczny: ID zakładek są typowaną unią.

Kryterium akceptacji: karta ticketu ma trzy zakładki obsługiwane myszą i klawiaturą (strzałki, Home, End), dodanie komentarza przełącza na „Aktywność”, wybór innego ticketu wraca na „Szczegóły”, a niezapisany komentarz przetrwa przełączanie zakładek.
