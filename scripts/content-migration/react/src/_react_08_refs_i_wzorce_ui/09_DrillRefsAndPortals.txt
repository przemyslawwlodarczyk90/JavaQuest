#T INTRO Trening: useRef, refy do DOM i portale
Ref to „furtka” poza model renderowania: pudełko `{ current }`, które przetrwa między renderami, ale którego zmiana **nie** powoduje renderu. Używasz go do dwóch rzeczy: przechowywania wartości niepotrzebnych na ekranie (ID timerów, poprzednie wartości, najświeższy stan dla callbacków) oraz dostępu do elementów DOM (fokus, przewijanie, pomiar, natywne API jak `<dialog>` czy `<video>`). Portal z kolei renderuje fragment drzewa Reacta w innym miejscu DOM — przy zachowaniu kontekstu i propagacji zdarzeń Reacta.

Dwanaście zadań, w tym jedno „przewidź wynik” z czterema wariantami. Zasada nadrzędna, którą sprawdzasz w każdym rozwiązaniu: **nie czytaj i nie zapisuj `ref.current` w trakcie renderu** — tylko w handlerach i Effectach.

#T STEP_BY_STEP Zadanie 1 — ref czy stan: licznik kliknięć
Napisz `ClickStats` z dwoma licznikami kliknięć tego samego przycisku: jeden w stanie, drugi w refie.

Wymagania:
1. `const [stateCount, setStateCount] = useState(0)` i `const refCount = useRef(0)`.
2. Przycisk „Klik” zwiększa oba.
3. Na ekranie pokaż tylko `stateCount`; przycisk „Pokaż ref” robi `alert(refCount.current)`.
4. Drugi przycisk „Klik (tylko ref)” zwiększa wyłącznie ref.

Sprawdź się: po trzech kliknięciach „Klik (tylko ref)” ekran się nie zmienia, ale „Pokaż ref” wyświetla o 3 więcej niż licznik na ekranie.

#T CODE_JSX Rozwiązanie 1 (JSX)
```
// ClickStats.jsx
import { useRef, useState } from 'react';

export function ClickStats() {
  const [stateCount, setStateCount] = useState(0);
  const refCount = useRef(0);

  function handleClick() {
    setStateCount((c) => c + 1);
    refCount.current += 1;
  }

  return (
    <div>
      <p>Kliknięcia (stan): {stateCount}</p>
      <button type="button" onClick={handleClick}>Klik</button>
      <button type="button" onClick={() => { refCount.current += 1; }}>Klik (tylko ref)</button>
      <button type="button" onClick={() => alert(refCount.current)}>Pokaż ref</button>
    </div>
  );
}
```

#T STEP_BY_STEP Zadanie 2 — ID timera w refie: wysyłka z anulowaniem
Napisz `UndoSend` — przycisk „Wyślij” planuje wysłanie wiadomości za 3 sekundy, a w tym czasie można je anulować.

Wymagania:
1. Stan `pending` (boolean) — do pokazania „Wysyłanie za 3 s… [Anuluj]”.
2. ID timera w `useRef(null)` — nie w stanie i nie w zwykłej zmiennej.
3. „Anuluj” czyści timer (`clearTimeout(timerRef.current)`) i ustawia `pending` na `false`.
4. Przy odmontowaniu komponentu zaplanowany timer też musi zostać anulowany (Effect ze sprzątaniem).

Sprawdź się: wyjaśnij, dlaczego `let timerId` w ciele komponentu nie zadziała (podpowiedź: co się dzieje z tą zmienną po `setPending(true)`?).

#T CODE_JSX Rozwiązanie 2 (JSX)
```
// UndoSend.jsx
import { useEffect, useRef, useState } from 'react';

export function UndoSend({ onSend }) {
  const [pending, setPending] = useState(false);
  const timerRef = useRef(null);

  useEffect(() => () => clearTimeout(timerRef.current), []);

  function handleSend() {
    setPending(true);
    timerRef.current = setTimeout(() => {
      setPending(false);
      onSend();
    }, 3000);
  }

  function handleCancel() {
    clearTimeout(timerRef.current);
    setPending(false);
  }

  return pending ? (
    <p role="status">
      Wysyłanie za 3 s… <button type="button" onClick={handleCancel}>Anuluj</button>
    </p>
  ) : (
    <button type="button" onClick={handleSend}>Wyślij</button>
  );
}
```

#T CODE_TSX Rozwiązanie 2 (TSX)

// UndoSend.tsx
import { useEffect, useRef, useState } from 'react';

export function UndoSend({ onSend }: { onSend: () => void }) {
  const [pending, setPending] = useState(false);
  const timerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

  useEffect(() => () => {
    if (timerRef.current) clearTimeout(timerRef.current);
  }, []);

  function handleSend() {
    setPending(true);
    timerRef.current = setTimeout(() => {
      setPending(false);
      onSend();
    }, 3000);
  }

  function handleCancel() {
    if (timerRef.current) clearTimeout(timerRef.current);
    setPending(false);
  }

  return pending ? (
    <p role="status">
      Wysyłanie za 3 s… <button type="button" onClick={handleCancel}>Anuluj</button>
    </p>
  ) : (
    <button type="button" onClick={handleSend}>Wyślij</button>
  );
}
```

#T NOTE Dlaczego zwykła zmienna nie wystarczy
`setPending(true)` powoduje render, czyli ponowne wywołanie funkcji komponentu — `let timerId` zostaje utworzone na nowo jako `undefined`. Handler „Anuluj” z nowego renderu nie zna ID timera z poprzedniego, więc `clearTimeout(undefined)` niczego nie anuluje i wiadomość wychodzi. Ref to jedno pudełko dla wszystkich renderów tej instancji. W TSX `ReturnType<typeof setTimeout>` działa i w przeglądarce (`number`), i w Node (`Timeout`) — przydatne, gdy ten sam kod uruchamiasz w testach.

#T STEP_BY_STEP Zadanie 4 — fokus: wyszukiwarka
Napisz `SearchBox` z polem i dwoma przyciskami.

Wymagania:
1. `useRef(null)` podpięty do `<input ref={inputRef}>`.
2. Przycisk „Szukaj” — jeśli pole jest puste, ustawia na nim fokus zamiast szukać.
3. Przycisk „Wyczyść” czyści pole (stan) i ustawia fokus.
4. Skrót klawiszowy `/` w dowolnym miejscu strony ustawia fokus w polu (nasłuch `keydown` na `window` w Effecie; pomiń, gdy użytkownik pisze już w innym polu).
5. W TSX obsłuż przypadek `inputRef.current === null`.

Sprawdź się: naciśnięcie `/` na stronie przenosi kursor do wyszukiwarki, a znak `/` nie zostaje wpisany do pola.

#T CODE_JSX Rozwiązanie 4 (JSX)
```
// SearchBox.jsx
import { useEffect, useRef, useState } from 'react';

export function SearchBox({ onSearch }) {
  const [query, setQuery] = useState('');
  const inputRef = useRef(null);

  useEffect(() => {
    function handleKey(e) {
      const typing = ['INPUT', 'TEXTAREA', 'SELECT'].includes(document.activeElement?.tagName);
      if (e.key === '/' && !typing) {
        e.preventDefault();
        inputRef.current?.focus();
      }
    }
    window.addEventListener('keydown', handleKey);
    return () => window.removeEventListener('keydown', handleKey);
  }, []);

  function handleSearch() {
    if (!query.trim()) {
      inputRef.current.focus();
      return;
    }
    onSearch(query.trim());
  }

  return (
    <div role="search">
      <input ref={inputRef} value={query} onChange={(e) => setQuery(e.target.value)} aria-label="Szukaj (skrót /)" />
      <button type="button" onClick={handleSearch}>Szukaj</button>
      <button type="button" onClick={() => { setQuery(''); inputRef.current.focus(); }}>Wyczyść</button>
    </div>
  );
}
```

#T STEP_BY_STEP Zadanie 5 — przewijanie: czat z autoprzewijaniem
Napisz `ChatLog` — lista wiadomości z polem do dodawania nowych.

Wymagania:
1. Pusty `<div ref={endRef} />` na końcu listy.
2. Po dodaniu wiadomości lista przewija się na dół: `endRef.current.scrollIntoView({ behavior: 'smooth' })` w Effecie zależnym od liczby wiadomości.
3. Przycisk „Do góry” przewija kontener listy na początek (`listRef.current.scrollTo({ top: 0 })`).
4. Lista ma stałą wysokość i `overflow-y: auto`.

Sprawdź się: po dodaniu dwudziestej wiadomości widać ją bez ręcznego przewijania.

#T CODE_JSX Rozwiązanie 5 (JSX)
```
// ChatLog.jsx
import { useEffect, useRef, useState } from 'react';

export function ChatLog() {
  const [messages, setMessages] = useState([]);
  const [draft, setDraft] = useState('');
  const listRef = useRef(null);
  const endRef = useRef(null);

  useEffect(() => {
    endRef.current?.scrollIntoView({ behavior: 'smooth', block: 'end' });
  }, [messages.length]);

  function send() {
    if (!draft.trim()) return;
    setMessages((list) => [...list, { id: crypto.randomUUID(), text: draft.trim() }]);
    setDraft('');
  }

  return (
    <section>
      <div ref={listRef} style={{ height: 240, overflowY: 'auto' }} aria-live="polite">
        {messages.map((m) => <p key={m.id}>{m.text}</p>)}
        <div ref={endRef} />
      </div>
      <input value={draft} onChange={(e) => setDraft(e.target.value)} onKeyDown={(e) => e.key === 'Enter' && send()} aria-label="Wiadomość" />
      <button type="button" onClick={send}>Wyślij</button>
      <button type="button" onClick={() => listRef.current.scrollTo({ top: 0, behavior: 'smooth' })}>Do góry</button>
    </section>
  );
}
```

  return (

      <div ref={listRef} style={{ height: 240, overflowY: 'auto' }} aria-live="polite">
        {messages.map((m) => <p key={m.id}>{m.text}</p>)}
        <div ref={endRef} />
      </div>
      <input value={draft} onChange={(e) => setDraft(e.target.value)} onKeyDown={(e) => e.key === 'Enter' && send()} aria-label="Wiadomość" />

#T NOTE Dlaczego przewijanie jest w Effecie, a nie w handlerze
W `send()` nowa wiadomość jeszcze **nie istnieje** w DOM — `setMessages` tylko planuje render. Gdybyś po nim wywołał `scrollIntoView`, przewinąłbyś do przedostatniej wiadomości. Effect uruchamia się po zatwierdzeniu zmian w DOM, więc element jest już na miejscu. Alternatywa w handlerze to `flushSync(() => setMessages(…))` z `react-dom`, które wymusza natychmiastowy render — przydatne rzadko, ale warto wiedzieć, że istnieje.

#T STEP_BY_STEP Zadanie 6 — lista refów: ref callback i Map
Galeria miniatur z przyciskami „Pokaż 1”, „Pokaż 2”… przewijającymi do konkretnego zdjęcia. Liczba zdjęć jest zmienna, więc nie możesz napisać `useRef` dla każdego.

Wymagania:
1. Jeden `useRef(new Map())` przechowujący elementy po ID.
2. Ref callback na każdym `<li>`: `ref={(node) => { map.set(id, node); return () => map.delete(id); }}` (React 19 — funkcja sprzątająca w ref callback).
3. Funkcja `scrollToItem(id)` pobiera element z mapy i wywołuje `scrollIntoView({ behavior: 'smooth', inline: 'center' })`.
4. Przyciski generowane z tej samej listy co miniatury.

Sprawdź się: usunięcie zdjęcia z listy usuwa też jego wpis z mapy (sprawdź `map.size` w konsoli).

#T CODE_JSX Rozwiązanie 6 (JSX)
```
// Gallery.jsx
import { useRef } from 'react';

export function Gallery({ photos }) {
  const itemsRef = useRef(new Map());

  function scrollToItem(id) {
    itemsRef.current.get(id)?.scrollIntoView({ behavior: 'smooth', block: 'nearest', inline: 'center' });
  }

  return (
    <section>
      <nav>
        {photos.map((p, i) => (
          <button key={p.id} type="button" onClick={() => scrollToItem(p.id)}>Pokaż {i + 1}</button>
        ))}
      </nav>
      <ul className="gallery" style={{ display: 'flex', overflowX: 'auto' }}>
        {photos.map((p) => (
          <li
            key={p.id}
            ref={(node) => {
              itemsRef.current.set(p.id, node);
              return () => itemsRef.current.delete(p.id);
            }}
          >
            <img src={p.url} alt={p.alt} width={200} height={150} />
          </li>
        ))}
      </ul>
    </section>
  );
}
```

#T STEP_BY_STEP Zadanie 7 — ref jako prop: własny komponent pola
Masz komponent `TextField` (etykieta + input + komunikat błędu). Rodzic chce ustawić fokus na **inpucie w środku**.

Wymagania:
1. `TextField` przyjmuje `ref` jak każdy inny prop (React 19) i przekazuje go na `<input>`.
2. Pozostałe props: `label`, `error`, reszta atrybutów inputa przez `...rest`.
3. Rodzic `SignupForm` przy wysłaniu z pustym e-mailem ustawia fokus na polu e-mail przez ref.
4. Napisz też wersję dla starszego Reacta z `forwardRef` (zobaczysz ją w istniejącym kodzie).

Sprawdź się: kliknięcie „Wyślij” z pustym polem przenosi kursor do pola e-mail i pokazuje błąd.

#T CODE_JSX Rozwiązanie 7 (JSX)
```
// TextField.jsx
import { forwardRef, useId, useRef, useState } from 'react';

export function TextField({ label, error, ref, ...rest }) {
  const id = useId();
  return (
    <div className="field">
      <label htmlFor={id}>{label}</label>
      <input id={id} ref={ref} aria-invalid={Boolean(error)} aria-describedby={error ? `${id}-error` : undefined} {...rest} />
      {error && <p id={`${id}-error`} className="error">{error}</p>}
    </div>
  );
}

// Starszy zapis (React 18 i wcześniej) — ref jako drugi argument:
export const LegacyTextField = forwardRef(function LegacyTextField({ label, ...rest }, ref) {
  return <label>{label} <input ref={ref} {...rest} /></label>;
});

export function SignupForm() {
  const [email, setEmail] = useState('');
  const [error, setError] = useState('');
  const emailRef = useRef(null);

  function handleSubmit(e) {
    e.preventDefault();
    if (!email.includes('@')) {
      setError('Podaj e-mail');
      emailRef.current.focus();
      return;
    }
    setError('');
  }

  return (
    <form onSubmit={handleSubmit} noValidate>
      <TextField ref={emailRef} label="E-mail" type="email" value={email} onChange={(e) => setEmail(e.target.value)} error={error} />
      <button type="submit">Wyślij</button>
    </form>
  );
}
```

// TextField.tsx
import { forwardRef, useId, useRef, useState, type ComponentProps, type FormEvent } from 'react';

type TextFieldProps = ComponentProps<'input'> & { label: string; error?: string };

export function TextField({ label, error, ref, ...rest }: TextFieldProps) {
  const id = useId();
  return (
    <div className="field">
      <label htmlFor={id}>{label}</label>
      <input id={id} ref={ref} aria-invalid={Boolean(error)} aria-describedby={error ? `${id}-error` : undefined} {...rest} />
      {error && <p id={`${id}-error`} className="error">{error}</p>}
    </div>
  );
}

// Starszy zapis (React 18 i wcześniej) — ref jako drugi argument:
export const LegacyTextField = forwardRef<HTMLInputElement, { label: string } & ComponentProps<'input'>>(
  function LegacyTextField({ label, ...rest }, ref) {
    return <label>{label} <input ref={ref} {...rest} /></label>;
  },
);

export function SignupForm() {
  const [email, setEmail] = useState('');
  const [error, setError] = useState('');
  const emailRef = useRef<HTMLInputElement>(null);

  function handleSubmit(e: FormEvent<HTMLFormElement>) {
    e.preventDefault();
    if (!email.includes('@')) {
      setError('Podaj e-mail');
      emailRef.current?.focus();
      return;
    }
    setError('');
  }

  return (
    <form onSubmit={handleSubmit} noValidate>
      <TextField ref={emailRef} label="E-mail" type="email" value={email} onChange={(e) => setEmail(e.target.value)} error={error} />
      <button type="submit">Wyślij</button>
    </form>
  );
}
```

#T NOTE JSX ↔ TSX — typ ref w props
`ComponentProps<'input'>` w React 19 zawiera już `ref?: Ref<HTMLInputElement>`, więc `TextField` przyjmuje ref bez dodatkowej deklaracji, a rodzic dostaje błąd kompilacji, gdy poda ref do innego elementu (`useRef<HTMLDivElement>`). Jeśli typujesz props ręcznie, dopisz `ref?: Ref<HTMLInputElement>`. W JSX ref przekazany do komponentu, który go nie obsługuje, po prostu zostanie zignorowany — a w React 18 bez `forwardRef` dostałbyś ostrzeżenie w konsoli.

#T STEP_BY_STEP Zadanie 8 — useImperativeHandle: ograniczone API pola
`TextField` z zadania 7 oddaje rodzicowi cały element `<input>` — rodzic może zmienić mu styl, wartość, cokolwiek. Ogranicz to.

Wymagania:
1. Nowy komponent `CodeInput` (pole na sześciocyfrowy kod) przez `useImperativeHandle` udostępnia rodzicowi tylko `focus()` i `clear()`.
2. `clear()` czyści wartość (stan wewnątrz `CodeInput`) i ustawia fokus.

// CodeInput.jsx
import { useImperativeHandle, useRef, useState } from 'react';

export function CodeInput({ ref, onComplete }) {
  const [code, setCode] = useState('');
  const inputRef = useRef(null);

  useImperativeHandle(ref, () => ({
    focus: () => inputRef.current.focus(),
    clear: () => {
      setCode('');
      inputRef.current.focus();
    },
  }), []);

  function handleChange(e) {
    const digits = e.target.value.replace(/\D/g, '').slice(0, 6);
    setCode(digits);
    if (digits.length === 6) onComplete(digits);
  }

  return <input ref={inputRef} value={code} onChange={handleChange} inputMode="numeric" autoComplete="one-time-code" aria-label="Kod z SMS" />;
}

export function VerifyForm() {
  const codeRef = useRef(null);
  return (
    <div>
      <CodeInput ref={codeRef} onComplete={(code) => console.log('weryfikuję', code)} />
      <button type="button" onClick={() => codeRef.current.clear()}>Wyślij kod ponownie</button>
    </div>
  );
}

#T STEP_BY_STEP Zadanie 10 — pomiar elementu: dymek nad przyciskiem
Napisz `TooltipButton` — po najechaniu pokazuje dymek **nad** przyciskiem, a gdy nad nim nie ma miejsca — pod nim.

Wymagania:
1. Ref do przycisku i ref do dymka.
2. `useLayoutEffect` zależny od widoczności dymka: mierzy przycisk i dymek (`getBoundingClientRect`), decyduje o pozycji i zapisuje ją w stanie `{ top, left }`.
3. Dymek renderowany z `position: fixed` w obliczonym miejscu.
4. Wyjaśnij, dlaczego `useLayoutEffect`, a nie `useEffect` (odpowiedź w notatce).

Sprawdź się: przewiń stronę tak, by przycisk był przy górnej krawędzi — dymek pojawia się pod nim, bez widocznego „skoku”.

#T CODE_JSX Rozwiązanie 10 (JSX)
```
// TooltipButton.jsx
import { useLayoutEffect, useRef, useState } from 'react';

export function TooltipButton({ label, tip }) {
  const [visible, setVisible] = useState(false);
  const [position, setPosition] = useState({ top: 0, left: 0 });
  const buttonRef = useRef(null);
  const tipRef = useRef(null);

  useLayoutEffect(() => {
    if (!visible) return;
    const button = buttonRef.current.getBoundingClientRect();
    const bubble = tipRef.current.getBoundingClientRect();
    const fitsAbove = button.top - bubble.height - 8 > 0;
    setPosition({
      top: fitsAbove ? button.top - bubble.height - 8 : button.bottom + 8,
      left: button.left + button.width / 2 - bubble.width / 2,
    });
  }, [visible]);

  return (
    <>
      <button ref={buttonRef} type="button" onMouseEnter={() => setVisible(true)} onMouseLeave={() => setVisible(false)}
        onFocus={() => setVisible(true)} onBlur={() => setVisible(false)} aria-describedby={visible ? 'tip' : undefined}>
        {label}
      </button>
      {visible && (
        <div ref={tipRef} id="tip" role="tooltip" style={{ position: 'fixed', top: position.top, left: position.left }}>
          {tip}
        </div>
      )}
    </>
  );
}
```

// TooltipButton.tsx
import { useLayoutEffect, useRef, useState } from 'react';

export function TooltipButton({ label, tip }: { label: string; tip: string }) {
  const [visible, setVisible] = useState(false);
  const [position, setPosition] = useState({ top: 0, left: 0 });
  const buttonRef = useRef<HTMLButtonElement>(null);
  const tipRef = useRef<HTMLDivElement>(null);

  useLayoutEffect(() => {
    if (!visible || !buttonRef.current || !tipRef.current) return;
    const button = buttonRef.current.getBoundingClientRect();
    const bubble = tipRef.current.getBoundingClientRect();
    const fitsAbove = button.top - bubble.height - 8 > 0;
    setPosition({
      top: fitsAbove ? button.top - bubble.height - 8 : button.bottom + 8,
      left: button.left + button.width / 2 - bubble.width / 2,
    });
  }, [visible]);

  return (
    <>
      <button ref={buttonRef} type="button" onMouseEnter={() => setVisible(true)} onMouseLeave={() => setVisible(false)}
        onFocus={() => setVisible(true)} onBlur={() => setVisible(false)} aria-describedby={visible ? 'tip' : undefined}>
        {label}
      </button>
      {visible && (
        <div ref={tipRef} id="tip" role="tooltip" style={{ position: 'fixed', top: position.top, left: position.left }}>
          {tip}
        </div>

    </>
  );

#T NOTE Odpowiedź: dlaczego useLayoutEffect
`useLayoutEffect` uruchamia się po zmianie DOM, ale **przed** namalowaniem klatki przez przeglądarkę. Pomiar i `setPosition` dzieją się więc, zanim użytkownik cokolwiek zobaczy, a React od razu renderuje dymek w poprawnym miejscu. Z `useEffect` przeglądarka najpierw namalowałaby dymek w pozycji `{ top: 0, left: 0 }`, a chwilę później przesunęła — widoczne mignięcie. `useLayoutEffect` blokuje malowanie, więc używaj go tylko do pomiarów i korekt układu. W praktyce pozycjonowanie dymków zostawiasz bibliotece (Floating UI, lekcja 08).

// Modal.jsx
import { useEffect, useId, useState } from 'react';
import { createPortal } from 'react-dom';

export function Modal({ open, onClose, title, children }) {
  const titleId = useId();

  useEffect(() => {
    if (!open) return;
    const handleKey = (e) => e.key === 'Escape' && onClose();
    window.addEventListener('keydown', handleKey);
    return () => window.removeEventListener('keydown', handleKey);
  }, [open, onClose]);

  if (!open) return null;

  return createPortal(
    <div className="backdrop" onClick={(e) => e.target === e.currentTarget && onClose()}>
      <div role="dialog" aria-modal="true" aria-labelledby={titleId} className="modal">
        <h2 id={titleId}>{title}</h2>
        {children}
        <button type="button" onClick={onClose}>Zamknij</button>
      </div>
    </div>,
    document.body,
  );
}

export function ModalDemo() {

  return (

      <Modal open={open} onClose={() => setOpen(false)} title="Nowy ticket">
        <p>Formularz ticketu…</p>

#T STEP_BY_STEP Zadanie 12 — natywny dialog sterowany przez props
Element `<dialog>` ma wbudowane: warstwę nad stroną, pułapkę fokusu i zamykanie Escape — ale otwiera się metodami `showModal()` i `close()`, a nie atrybutem. Połącz go z deklaratywnym `open`.

Wymagania:
1. `Dialog` przyjmuje `open`, `onClose`, `title`, `children`.
2. Ref do `<dialog>`; Effect zależny od `open` wywołuje `showModal()` albo `close()` (sprawdź `dialog.open`, żeby nie wywołać dwa razy).
3. Natywne zdarzenie `close` (Escape, `form method="dialog"`) wywołuje `onClose` — podłącz przez `onClose` na elemencie.
4. Przycisk „Anuluj” w `<form method="dialog">` zamyka bez JavaScriptu; przycisk „Zapisz” wywołuje callback i zamyka.
5. Po zamknięciu fokus wraca do przycisku, który otworzył dialog (zachowanie przeglądarki — sprawdź).

Sprawdź się: Escape zamyka dialog **i** aktualizuje stan rodzica (`open` staje się `false`), więc ponowne kliknięcie „Otwórz” działa.

#T CODE_JSX Rozwiązanie 12 (JSX)
```
// Dialog.jsx
import { useEffect, useRef, useState } from 'react';

export function Dialog({ open, onClose, title, children }) {
  const dialogRef = useRef(null);

  useEffect(() => {
    const dialog = dialogRef.current;
    if (open && !dialog.open) dialog.showModal();
    if (!open && dialog.open) dialog.close();
  }, [open]);

  return (
    <dialog ref={dialogRef} onClose={onClose} aria-labelledby="dialog-title">
      <h2 id="dialog-title">{title}</h2>
      {children}
      <form method="dialog">
        <button type="submit">Anuluj</button>
      </form>
    </dialog>
  );
}

export function DialogDemo() {
  const [open, setOpen] = useState(false);
  return (
    <>
      <button type="button" onClick={() => setOpen(true)}>Otwórz</button>
      <Dialog open={open} onClose={() => setOpen(false)} title="Edytuj profil">
        <button type="button" onClick={() => { console.log('zapisano'); setOpen(false); }}>Zapisz</button>
      </Dialog>
    </>
  );
}
```

#T NOTE Wzorzec: imperatywne API za deklaratywnym propem
Zadanie 12 to wzorzec, który powtórzysz dla `<video>` (`play`/`pause`), map, edytorów tekstu czy wykresów: komponent przyjmuje deklaratywny prop (`open`, `playing`), a Effect z refem tłumaczy go na wywołania imperatywnego API. #T SUMMARY Podsumowanie treningu
Przećwiczyłeś obie role refów. Jako pudełko na wartości: liczniki bez renderu, ID timerów, najświeższa wartość dla opóźnionego kodu i mapa elementów listy. Jako dostęp do DOM: fokus, przewijanie po renderze (Effect), pomiar przed malowaniem (`useLayoutEffect`), ref przekazywany jak zwykły prop (React 19) i `forwardRef` w starszym kodzie, ograniczone API przez `useImperativeHandle`, a na koniec portal z modalem i natywny `<dialog>` sterowany deklaratywnym propem. Zasada, która spina wszystko: refy czytasz i zapisujesz w handlerach i Effectach, nigdy w renderze; jeśli wartość ma być widoczna na ekranie — to stan.

Kryterium zaliczenia: poprawne odpowiedzi do zadania 9 (wszystkie cztery warianty) i do pytań z zadań 2 i 10; w TSX każdy ref do elementu ma typ elementu (`useRef<HTMLInputElement>(null)`), a odczyty obsługują `null`.
