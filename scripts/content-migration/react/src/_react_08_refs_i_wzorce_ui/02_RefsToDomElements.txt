#T INTRO Rozgrzewka i problem: React nie umie „kliknąć” za Ciebie w pole
Rozgrzewka: Czym różni się ref od stanu? Dlaczego nie odczytujesz `ref.current` podczas renderu? Do czego nadaje się ref z ID timera?

Problem: po otwarciu modala „Nowy ticket” kursor powinien od razu być w polu tytułu. Po dodaniu komentarza lista powinna przewinąć się do nowego wpisu. Pole wyszukiwania powinno dostać fokus po wciśnięciu `/`. To operacje na prawdziwych elementach DOM (`focus()`, `scrollIntoView()`), których nie da się wyrazić przez JSX. Potrzebujesz **refa do elementu DOM**.

#T DEFINITION Ref do elementu
Gdy przekażesz obiekt refa do atrybutu `ref` elementu JSX (`<input ref={inputRef} />`), React po zamontowaniu wstawi do `inputRef.current` prawdziwy węzeł DOM, a przy odmontowaniu ustawi `null`. Od tej chwili możesz wywoływać na nim metody przeglądarki: `focus()`, `blur()`, `select()`, `scrollIntoView()`, `getBoundingClientRect()`, `showModal()` (dla `<dialog>`), `play()` (dla `<video>`).

Ref do DOM odczytujesz w handlerach i efektach — podczas renderu element jeszcze nie istnieje (pierwszy render) albo może być nieaktualny.

#T CODE_JSX Fokus i przewijanie (JSX)
```
// CommentsPanel.jsx
import { useRef } from 'react';

export function CommentsPanel({ comments, onAdd }) {
  const inputRef = useRef(null);
  const listEndRef = useRef(null);

  function handleSubmit(e) {
    e.preventDefault();
    const text = inputRef.current.value.trim();
    if (!text) {
      inputRef.current.focus();
      return;
    }
    onAdd(text);
    inputRef.current.value = '';
    // przewiń po wyrenderowaniu nowego komentarza
    requestAnimationFrame(() => listEndRef.current?.scrollIntoView({ behavior: 'smooth' }));
  }

  return (
    <section>
      <ul className="comments">
        {comments.map((c) => <li key={c.id}>{c.text}</li>)}
        <li ref={listEndRef} aria-hidden="true" />
      </ul>
      <form onSubmit={handleSubmit}>
        <input ref={inputRef} aria-label="Nowy komentarz" />
        <button type="submit">Dodaj</button>
      </form>
    </section>
  );
}
```

#T CODE_TSX Fokus i przewijanie (TSX)
Typ elementu w generyku: `useRef<HTMLInputElement>(null)`. `current` może być `null` (element jeszcze nie zamontowany), więc TypeScript wymusza sprawdzenie albo `?.`.
```
// CommentsPanel.tsx
import { useRef, type FormEvent } from 'react';

type Comment = { id: number; text: string };

export function CommentsPanel({ comments, onAdd }: { comments: Comment[]; onAdd: (text: string) => void }) {
  const inputRef = useRef<HTMLInputElement>(null);
  const listEndRef = useRef<HTMLLIElement>(null);

  function handleSubmit(e: FormEvent<HTMLFormElement>) {
    e.preventDefault();
    const input = inputRef.current;
    if (!input) return;
    const text = input.value.trim();
    if (!text) {
      input.focus();
      return;
    }
    onAdd(text);
    input.value = '';
    requestAnimationFrame(() => listEndRef.current?.scrollIntoView({ behavior: 'smooth' }));
  }

  return (
    <section>
      <ul className="comments">
        {comments.map((c) => <li key={c.id}>{c.text}</li>)}
        <li ref={listEndRef} aria-hidden="true" />
      </ul>
      <form onSubmit={handleSubmit}>
        <input ref={inputRef} aria-label="Nowy komentarz" />
        <button type="submit">Dodaj</button>
      </form>
    </section>
  );
}
```

#T NOTE JSX ↔ TSX — typ elementu i null
W TSX `useRef<HTMLInputElement>(null)` daje dwie rzeczy: `inputRef.current` ma typ `HTMLInputElement | null`, więc musisz obsłużyć brak elementu (w JSX `inputRef.current.focus()` przed zamontowaniem rzuca wyjątek), a podpowiedzi pokazują metody właściwe dla elementu (`select()`, `value` dla inputa; `showModal()` dla `HTMLDialogElement`). Przekazanie refa typu `HTMLInputElement` do `<textarea ref={...}>` jest błędem kompilacji. Najczęstsze typy: `HTMLInputElement`, `HTMLTextAreaElement`, `HTMLButtonElement`, `HTMLDivElement`, `HTMLDialogElement`, `HTMLFormElement`.

#T DEFINITION ref jako zwykły prop (React 19)
Własny komponent nie ma DOM-u — żeby rodzic mógł dostać ref do jego wewnętrznego elementu, komponent musi przekazać ref dalej. W React 19 `ref` jest **zwykłym propem** komponentu funkcyjnego: przyjmujesz go w props i przekazujesz na element. W starszym kodzie (React 18 i wcześniej) zobaczysz opakowanie `forwardRef((props, ref) => ...)` — działa nadal, ale w nowym kodzie nie jest potrzebne.

#T CODE_BASIC Własne pole tekstowe przyjmujące ref
```
import type { Ref } from 'react';

type SearchFieldProps = { value: string; onChange: (v: string) => void; ref?: Ref<HTMLInputElement> };

export function SearchField({ value, onChange, ref }: SearchFieldProps) {
  return (
    <input
      ref={ref}
      type="search"
      aria-label="Szukaj ticketów"
      value={value}
      onChange={(e) => onChange(e.target.value)}
    />
  );
}

// rodzic: const searchRef = useRef<HTMLInputElement>(null); <SearchField ref={searchRef} ... />
```

#T CODE_PRACTICAL Skrót „/” przenosi fokus do wyszukiwarki
```
import { useEffect, useRef, useState } from 'react';
import { SearchField } from './SearchField';

export function SearchWithShortcut() {
  const [query, setQuery] = useState('');
  const searchRef = useRef<HTMLInputElement>(null);

  useEffect(() => {
    function handleKey(e: KeyboardEvent) {
      const typing = e.target instanceof HTMLInputElement || e.target instanceof HTMLTextAreaElement;
      if (e.key === '/' && !typing) {
        e.preventDefault();
        searchRef.current?.focus();
      }
    }
    window.addEventListener('keydown', handleKey);
    return () => window.removeEventListener('keydown', handleKey);
  }, []);

  return <SearchField ref={searchRef} value={query} onChange={setQuery} />;
}
```

#T DEFINITION Ref callback i listy elementów
Zamiast obiektu możesz przekazać do `ref` **funkcję** — React wywoła ją z elementem po zamontowaniu (a w React 19 funkcja może zwrócić sprzątanie wywoływane przy odmontowaniu). Przydaje się, gdy refów jest wiele (np. ref do każdego wiersza listy, żeby przewinąć do wybranego): trzymasz w refie `Map<id, element>` i w callbacku dodajesz i usuwasz wpisy.

#T CODE_JSX Przewijanie do wybranego wiersza (JSX)
```
// TicketList.jsx
import { useRef } from 'react';

export function TicketList({ tickets, onSelect }) {
  const rowsRef = useRef(new Map());

  function scrollTo(id) {
    rowsRef.current.get(id)?.scrollIntoView({ block: 'center', behavior: 'smooth' });
    onSelect(id);
  }

  return (
    <>
      <button type="button" onClick={() => scrollTo(tickets.at(-1).id)}>Przejdź do ostatniego</button>
      <ul>
        {tickets.map((t) => (
          <li
            key={t.id}
            ref={(el) => {
              rowsRef.current.set(t.id, el);
              return () => rowsRef.current.delete(t.id);
            }}
          >
            {t.title}
          </li>
        ))}
      </ul>
    </>
  );
}
```

#T CODE_TSX Przewijanie do wybranego wiersza (TSX)
`Map<number, HTMLLIElement>` — w callbacku `el` ma typ `HTMLLIElement`. Funkcja sprzątająca w nawiasach klamrowych, bo `Map.delete` zwraca `boolean`.
```
// TicketList.tsx
import { useRef } from 'react';
import type { Ticket } from '../types';

export function TicketList({ tickets, onSelect }: { tickets: Ticket[]; onSelect: (id: number) => void }) {
  const rowsRef = useRef(new Map<number, HTMLLIElement>());

  function scrollTo(id: number) {
    rowsRef.current.get(id)?.scrollIntoView({ block: 'center', behavior: 'smooth' });
    onSelect(id);
  }

  const last = tickets.at(-1);

  return (
    <>
      <button type="button" disabled={!last} onClick={() => last && scrollTo(last.id)}>Przejdź do ostatniego</button>
      <ul>
        {tickets.map((t) => (
          <li
            key={t.id}
            ref={(el) => {
              if (el) rowsRef.current.set(t.id, el);
              return () => { rowsRef.current.delete(t.id); };
            }}
          >
            {t.title}
          </li>
        ))}
      </ul>
    </>
  );
}
```

#T PITFALL Manipulowanie DOM-em zarządzanym przez Reacta
Ref daje dostęp do elementu, ale nie oznacza, że możesz zmieniać jego zawartość: `ref.current.innerHTML = '...'`, `appendChild`, `remove()` na elementach, które renderuje React, rozjedzie DOM z tym, co React uważa za aktualne — przy następnym renderze dostaniesz błędy lub zniknie Twoja zmiana. Bezpieczne operacje: fokus, przewijanie, pomiary, odtwarzanie mediów, wywołania API przeglądarki (`showModal`). Zawartość zmieniaj przez stan.

#T SUMMARY Kryterium akceptacji i podsumowanie
Ref przekazany w atrybucie `ref` dostaje węzeł DOM po zamontowaniu i `null` po odmontowaniu; używasz go w handlerach i efektach do fokusu, przewijania, pomiarów i API przeglądarki. W React 19 `ref` to zwykły prop komponentu (w starszym kodzie `forwardRef`). Wiele refów obsługujesz ref callbackiem i mapą. Nie zmieniaj przez ref zawartości zarządzanej przez React. W TSX `useRef<HTMLInputElement>(null)` daje typ elementu i wymusza obsługę `null`.

Kryterium akceptacji: po otwarciu modala fokus jest w polu tytułu, dodanie komentarza przewija listę do nowego wpisu, `/` przenosi fokus do wyszukiwarki (ale nie podczas pisania w innym polu), a „Przejdź do zaznaczonego” przewija tabelę do wybranego ticketu.
