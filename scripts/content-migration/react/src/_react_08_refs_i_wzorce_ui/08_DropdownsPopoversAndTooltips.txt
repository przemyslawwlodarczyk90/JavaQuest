#T INTRO Rozgrzewka i problem: menu „Więcej akcji” ucieka za ekran
Rozgrzewka: Jak działa wzorzec „usuń z cofnięciem”? Dlaczego krytyczny błąd nie powinien być tylko w toaście? Co robi `aria-live="polite"`?

Problem: każdy wiersz tabeli dostaje menu „⋯” z akcjami: Edytuj, Przypisz, Zmień priorytet, Usuń. Pierwsza wersja z `position: absolute` działa w środku tabeli, ale przy ostatnim wierszu menu wychodzi poza dolną krawędź ekranu, w wąskim oknie — poza prawą, a w kontenerze z `overflow: hidden` jest ucięte. Do tego menu nie zamyka się kliknięciem obok i nie da się go obsłużyć klawiaturą. Elementy pływające (menu, popover, podpowiedź) to jedno z trudniejszych zadań w UI — poznasz trzy drogi: ręczną, natywne Popover API i bibliotekę Floating UI.

#T DEFINITION Rodzaje elementów pływających
- **Podpowiedź (tooltip)** — krótki opis elementu po najechaniu lub fokusie; tylko tekst, bez elementów interaktywnych; `role="tooltip"` i `aria-describedby` na elemencie wyzwalającym.
- **Popover** — pływający panel z dowolną treścią (np. szczegóły użytkownika po kliknięciu awatara), zamykany kliknięciem obok lub Escape.
- **Menu akcji** — lista poleceń (`role="menu"`, elementy `role="menuitem"`), wywoływana przyciskiem z `aria-haspopup="menu"` i `aria-expanded`; obsługa strzałek góra/dół, Enter, Escape (fokus wraca na przycisk).

Wspólne problemy: pozycjonowanie względem elementu wyzwalającego, odwracanie przy krawędzi ekranu, wyjście poza kontenery (portal lub top layer), zamykanie kliknięciem poza elementem.

#T CODE_JSX Menu akcji z zamykaniem kliknięciem poza (JSX)
```
// RowMenu.jsx
import { useEffect, useRef, useState } from 'react';

export function RowMenu({ actions }) {
  const [open, setOpen] = useState(false);
  const rootRef = useRef(null);
  const buttonRef = useRef(null);

  useEffect(() => {
    if (!open) return;
    function handlePointer(e) {
      if (!rootRef.current?.contains(e.target)) setOpen(false);
    }
    function handleKey(e) {
      if (e.key === 'Escape') {
        setOpen(false);
        buttonRef.current?.focus();
      }
    }
    document.addEventListener('pointerdown', handlePointer);
    document.addEventListener('keydown', handleKey);
    return () => {
      document.removeEventListener('pointerdown', handlePointer);
      document.removeEventListener('keydown', handleKey);
    };
  }, [open]);

  return (
    <div ref={rootRef} className="row-menu">
      <button ref={buttonRef} type="button" aria-haspopup="menu" aria-expanded={open} aria-label="Więcej akcji" onClick={() => setOpen((o) => !o)}>
        ⋯
      </button>
      {open && (
        <ul role="menu" className="row-menu__list">
          {actions.map((a) => (
            <li key={a.label} role="none">
              <button type="button" role="menuitem" onClick={() => { a.onSelect(); setOpen(false); }}>{a.label}</button>
            </li>
          ))}
        </ul>
      )}
    </div>
  );
}
```

#T CODE_TSX Menu akcji z zamykaniem kliknięciem poza (TSX)
`e.target` z natywnego zdarzenia ma typ `EventTarget | null`, a `contains` wymaga `Node` — stąd sprawdzenie `instanceof Node`.
```
// RowMenu.tsx
import { useEffect, useRef, useState } from 'react';

export type MenuAction = { label: string; onSelect: () => void; danger?: boolean };

export function RowMenu({ actions }: { actions: MenuAction[] }) {
  const [open, setOpen] = useState(false);
  const rootRef = useRef<HTMLDivElement>(null);
  const buttonRef = useRef<HTMLButtonElement>(null);

  useEffect(() => {
    if (!open) return;
    function handlePointer(e: PointerEvent) {
      if (e.target instanceof Node && !rootRef.current?.contains(e.target)) setOpen(false);
    }
    function handleKey(e: KeyboardEvent) {
      if (e.key === 'Escape') {
        setOpen(false);
        buttonRef.current?.focus();
      }
    }
    document.addEventListener('pointerdown', handlePointer);
    document.addEventListener('keydown', handleKey);
    return () => {
      document.removeEventListener('pointerdown', handlePointer);
      document.removeEventListener('keydown', handleKey);
    };
  }, [open]);

  return (
    <div ref={rootRef} className="row-menu">
      <button ref={buttonRef} type="button" aria-haspopup="menu" aria-expanded={open} aria-label="Więcej akcji" onClick={() => setOpen((o) => !o)}>
        ⋯
      </button>
      {open && (
        <ul role="menu" className="row-menu__list">
          {actions.map((a) => (
            <li key={a.label} role="none">
              <button type="button" role="menuitem" className={a.danger ? 'danger' : undefined} onClick={() => { a.onSelect(); setOpen(false); }}>
                {a.label}
              </button>
            </li>
          ))}
        </ul>
      )}
    </div>
  );
}
```

#T NOTE JSX ↔ TSX — EventTarget a Node
To typowy przykład, gdzie TSX zmusza do poprawnego kodu: `e.target` może być dowolnym `EventTarget` (np. `window`), a `Node.contains()` przyjmuje tylko `Node`. Sprawdzenie `e.target instanceof Node` zadowala kompilator i chroni przed rzadkimi przypadkami (zdarzenie z `window`). W JSX `contains(e.target)` działa w typowych sytuacjach, a w nietypowych rzuca wyjątek. Typ `MenuAction` z opcjonalnym `danger` dokumentuje API menu.

#T DEFINITION Popover API przeglądarki
Nowoczesne przeglądarki mają wbudowane **Popover API**: element z atrybutem `popover` jest domyślnie ukryty, przycisk z `popoverTarget="id"` go przełącza, a przeglądarka sama obsługuje: wyświetlanie w **top layer** (ponad wszystkim, bez portalu i bez `z-index`), zamykanie kliknięciem poza i klawiszem Escape (tryb `popover="auto"`) oraz zamykanie innych otwartych popoverów. W React 19 to zwykłe atrybuty. Pozycjonowanie względem przycisku zapewnia CSS (anchor positioning) w przeglądarkach, które go obsługują, albo biblioteka.

#T CODE_BASIC Popover bez JavaScriptu
```
export function AssigneeInfo({ login, email }: { login: string; email: string }) {
  const id = `user-${login}`;
  return (
    <>
      <button type="button" popoverTarget={id}>@{login}</button>
      <div id={id} popover="auto" className="popover">
        <strong>{login}</strong>
        <p>{email}</p>
      </div>
    </>
  );
}
```

#T DEFINITION Floating UI: pozycjonowanie z odwracaniem
**Floating UI** (`@floating-ui/react`) to biblioteka, która liczy pozycję elementu pływającego względem wyzwalacza i reaguje na krawędzie ekranu: `flip()` odwraca stronę, gdy brakuje miejsca, `shift()` przesuwa, by element nie wyszedł poza ekran, `offset()` dodaje odstęp, `autoUpdate` przelicza pozycję przy przewijaniu i zmianie rozmiaru. Daje też hooki interakcji (`useClick`, `useDismiss`, `useRole`) i `FloatingPortal`. Z niej korzystają biblioteki headless.

#T CODE_PRACTICAL Podpowiedź z Floating UI
```
import { useState, type ReactNode } from 'react';
import { autoUpdate, flip, offset, shift, useDismiss, useFloating, useFocus, useHover, useInteractions, useRole, FloatingPortal } from '@floating-ui/react';

export function Hint({ text, children }: { text: string; children: ReactNode }) {
  const [open, setOpen] = useState(false);
  const { refs, floatingStyles, context } = useFloating({
    open,
    onOpenChange: setOpen,
    placement: 'top',
    middleware: [offset(6), flip(), shift({ padding: 8 })],
    whileElementsMounted: autoUpdate,
  });
  const { getReferenceProps, getFloatingProps } = useInteractions([
    useHover(context, { delay: { open: 300 } }),
    useFocus(context),
    useDismiss(context),
    useRole(context, { role: 'tooltip' }),
  ]);

  return (
    <>
      <span ref={refs.setReference} {...getReferenceProps()} tabIndex={0}>{children}</span>
      {open && (
        <FloatingPortal>
          <div ref={refs.setFloating} style={floatingStyles} className="tooltip" {...getFloatingProps()}>{text}</div>
        </FloatingPortal>
      )}
    </>
  );
}
```

#T PITFALL Treść interaktywna w podpowiedzi
Tooltip znika, gdy kursor opuszcza wyzwalacz — przycisk albo link w środku jest więc nieosiągalny, a dla klawiatury i czytników ekranu zwykle niewidoczny. Jeśli pływający element ma zawierać cokolwiek klikalnego, to jest popover lub menu (otwierany kliknięciem, z obsługą fokusu), a nie tooltip.

#T SUMMARY Kryterium akceptacji i podsumowanie
Elementy pływające: tooltip (tylko tekst, `aria-describedby`), popover (dowolna treść, zamykany kliknięciem obok/Escape) i menu (`role="menu"`, `aria-haspopup`, `aria-expanded`, powrót fokusu). Ręcznie potrzebujesz zamykania kliknięciem poza (`contains`) i Escape; Popover API daje top layer i zamykanie bez kodu; Floating UI liczy pozycję z odwracaniem i przesuwaniem przy krawędziach. W TSX zawężasz `EventTarget` do `Node` przed `contains`.

Kryterium akceptacji: menu „⋯” w każdym wierszu działa myszą i klawiaturą, zamyka się kliknięciem obok i Escape, w ostatnim wierszu otwiera się w górę; informacja o osobie działa na Popover API; podpowiedź przy kolumnie priorytetu pojawia się po najechaniu i po fokusie.
