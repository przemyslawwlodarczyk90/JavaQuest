#T INTRO Rozgrzewka i problem: modal przycięty przez kontener
Rozgrzewka: Czym różni się zakładka kontrolowana od niekontrolowanej? Co daje `hidden` w porównaniu z renderowaniem warunkowym? Czym jest roving tabindex?

Problem: w rozdziale 03 modal zbudowałeś z Radix. Teraz piszesz go sam, żeby rozumieć mechanizmy. Pierwsza próba: modal renderowany wewnątrz karty ticketu jest przycięty przez `overflow: hidden` karty i schowany pod nagłówkiem aplikacji mimo `z-index: 9999`. To klasyczny problem kontekstu nakładania w CSS — rozwiązuje go **portal**: renderowanie komponentu w innym miejscu DOM-u niż w drzewie komponentów.

#T DEFINITION createPortal
`createPortal(jsx, węzełDocelowy)` z `react-dom` renderuje JSX jako dziecko wskazanego węzła DOM (np. `document.body`), mimo że komponent żyje w drzewie Reacta w zupełnie innym miejscu. Dzięki temu modal, podpowiedź czy menu „wychodzi” z kontenerów z `overflow: hidden` i z ich kontekstu nakładania.

Ważne: portal zmienia tylko **miejsce w DOM**. W drzewie Reacta komponent dalej jest dzieckiem swojego rodzica: dostaje kontekst (motyw, preferencje), a zdarzenia (np. `onClick`) **bąbelkują przez drzewo Reacta**, czyli do rodzica komponentu, a nie do `body`.

#T VISUAL_EXAMPLE Drzewo Reacta a drzewo DOM
Drzewo Reacta:                         Drzewo DOM:
App                                    <body>
└── TicketCard (overflow: hidden)        ├── <div id="root">
    └── Modal  ── createPortal ──┐       │     └── <div class="ticket-card"> ... </div>
                                 └────►  └── <div class="modal-backdrop"> ← modal tutaj

Kontekst i zdarzenia: jak w drzewie Reacta (Modal jest dzieckiem TicketCard).
CSS i pozycjonowanie: jak w drzewie DOM (modal jest dzieckiem body).

#T CODE_JSX Modal przez portal (JSX)
Pełna wersja: portal, Escape, kliknięcie tła, blokada przewijania strony, tytuł powiązany przez `aria-labelledby`.
```
// Modal.jsx
import { useEffect, useId } from 'react';
import { createPortal } from 'react-dom';

export function Modal({ open, title, onClose, children }) {
  const titleId = useId();

  useEffect(() => {
    if (!open) return;
    function handleKey(e) {
      if (e.key === 'Escape') onClose();
    }
    document.addEventListener('keydown', handleKey);
    const previousOverflow = document.body.style.overflow;
    document.body.style.overflow = 'hidden';
    return () => {
      document.removeEventListener('keydown', handleKey);
      document.body.style.overflow = previousOverflow;
    };
  }, [open, onClose]);

  if (!open) return null;

  return createPortal(
    <div className="modal-backdrop" onMouseDown={onClose}>
      <div role="dialog" aria-modal="true" aria-labelledby={titleId} className="modal" onMouseDown={(e) => e.stopPropagation()}>
        <h2 id={titleId}>{title}</h2>
        {children}
        <button type="button" className="modal__close" aria-label="Zamknij" onClick={onClose}>✕</button>
      </div>
    </div>,
    document.body,
  );
}
```

#T CODE_TSX Modal przez portal (TSX)
`createPortal` zwraca `ReactPortal` — poprawny wynik komponentu. Typ props zawiera `onClose: () => void`, wymagany zawsze, nawet jeśli modal zamyka się tylko przyciskiem.
```
// Modal.tsx
import { useEffect, useId, type ReactNode } from 'react';
import { createPortal } from 'react-dom';

type ModalProps = { open: boolean; title: string; onClose: () => void; children: ReactNode };

export function Modal({ open, title, onClose, children }: ModalProps) {
  const titleId = useId();

  useEffect(() => {
    if (!open) return;
    function handleKey(e: KeyboardEvent) {
      if (e.key === 'Escape') onClose();
    }
    document.addEventListener('keydown', handleKey);
    const previousOverflow = document.body.style.overflow;
    document.body.style.overflow = 'hidden';
    return () => {
      document.removeEventListener('keydown', handleKey);
      document.body.style.overflow = previousOverflow;
    };
  }, [open, onClose]);

  if (!open) return null;

  return createPortal(
    <div className="modal-backdrop" onMouseDown={onClose}>
      <div role="dialog" aria-modal="true" aria-labelledby={titleId} className="modal" onMouseDown={(e) => e.stopPropagation()}>
        <h2 id={titleId}>{title}</h2>
        {children}
        <button type="button" className="modal__close" aria-label="Zamknij" onClick={onClose}>✕</button>
      </div>
    </div>,
    document.body,
  );
}
```

#T NOTE JSX ↔ TSX — dwa różne KeyboardEvent
W TSX handler w `document.addEventListener` dostaje **natywny** `KeyboardEvent` z DOM (typ globalny, bez importu), a handler podpięty w JSX (`onKeyDown={...}`) — `KeyboardEvent` z Reacta (import z `react`, z parametrem elementu). To dwa różne typy o tej samej nazwie; pomylenie importów daje mylące błędy. W JSX oba obiekty mają te same najważniejsze pola (`key`, `ctrlKey`), więc różnicy nie widać. Druga uwaga: `onClose` jest w zależnościach efektu — jeśli rodzic przekazuje nową lambdę przy każdym renderze, nasłuchiwanie będzie podpinane na nowo; rozwiązaniem jest `useEffectEvent` dla obsługi Escape (rozdział 07).

#T DEFINITION Element dialog — natywna alternatywa
HTML ma element `<dialog>`: metoda `showModal()` otwiera go w **warstwie top layer** (ponad wszystkim, bez portalu i bez `z-index`), sama blokuje interakcję z resztą strony, obsługuje Escape (zdarzenie `cancel`) i przenosi fokus do środka. W React sterujesz nim przez ref i efekt synchronizujący prop `open` z `showModal()`/`close()`. To dziś dobra, lekka alternatywa dla portalu — a portal przydaje się nadal dla podpowiedzi, menu i powiadomień.

#T CODE_PRACTICAL Modal na elemencie dialog
```
import { useEffect, useRef, type ReactNode } from 'react';

type DialogProps = { open: boolean; title: string; onClose: () => void; children: ReactNode };

export function NativeDialog({ open, title, onClose, children }: DialogProps) {
  const ref = useRef<HTMLDialogElement>(null);

  useEffect(() => {
    const dialog = ref.current;
    if (!dialog) return;
    if (open && !dialog.open) dialog.showModal();
    if (!open && dialog.open) dialog.close();
  }, [open]);

  return (
    <dialog ref={ref} onClose={onClose} aria-labelledby="dlg-title" className="modal">
      <h2 id="dlg-title">{title}</h2>
      {children}
      <form method="dialog">
        <button type="submit">Zamknij</button>
      </form>
    </dialog>
  );
}
```

#T STEP_BY_STEP Budujemy razem: własny modal DevDesk
1. Utwórz `Modal` z portalem i style: `.modal-backdrop { position: fixed; inset: 0; background: rgb(0 0 0 / .4); display: grid; place-items: center; }`, `.modal { background: var(--surface); border-radius: var(--radius); padding: 1.5rem; min-width: min(480px, 90vw); }`.
2. Zastąp modal Radix własnym w „+ Nowy ticket”; otwarcie sterowane stanem `dialogOpen` w rodzicu.
3. Umieść przycisk otwierający modal wewnątrz karty z `overflow: hidden` — modal i tak wyświetla się na środku ekranu.
4. Sprawdź: Escape zamyka, kliknięcie tła zamyka, kliknięcie w treść nie zamyka, strona pod spodem się nie przewija.
5. Sprawdź bąbelkowanie: dodaj `onClick` na kontenerze karty — kliknięcie w modalu wywoła go, choć w DOM modal jest w `body` (zdarzenia idą drzewem Reacta). Zastanów się, czy to dla Ciebie problem.
6. Zbuduj wariant `NativeDialog` i porównaj zachowanie fokusu: dialog sam przenosi fokus do środka. W następnej lekcji dodasz zarządzanie fokusem do wersji z portalem.

#T PITFALL Zamykanie przez kliknięcie tła z onClick
Jeśli tło zamyka modal przez `onClick`, a użytkownik zaznacza myszą tekst w polu modala i puszcza przycisk nad tłem — zdarzenie `click` trafi na tło i modal się zamknie, gubiąc wpisane dane. Dlatego w przykładzie użyto `onMouseDown` (początek kliknięcia musi być na tle) i zatrzymania propagacji w treści.

#T SUMMARY Kryterium akceptacji i podsumowanie
`createPortal(jsx, węzeł)` renderuje JSX w innym miejscu DOM (np. `body`), zachowując pozycję w drzewie Reacta: kontekst i bąbelkowanie zdarzeń działają jak u rodzica, a CSS i pozycjonowanie — jak w nowym miejscu. Dostępny modal ma `role="dialog"`, `aria-modal`, tytuł w `aria-labelledby`, obsługę Escape i kliknięcia tła oraz blokadę przewijania. Natywny `<dialog>` z `showModal()` jest alternatywą bez portalu. W TSX rozróżniaj natywny `KeyboardEvent` od Reactowego.

Kryterium akceptacji: własny modal „Nowy ticket” wyświetla się nad całą aplikacją także z kontenera z `overflow: hidden`, zamyka się Escape i kliknięciem tła (ale nie przy zaznaczaniu tekstu), a strona pod modalem nie przewija się.
