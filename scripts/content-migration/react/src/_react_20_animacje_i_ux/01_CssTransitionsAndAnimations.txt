#T INTRO Rozgrzewka i problem: interfejs, który „skacze”
Rozgrzewka: Czym jest argument (args) historii w Storybooku? Skąd w TSX bierze się tabela props w dokumentacji? Po co dekorator w `preview`?

Problem: w DevDesk wszystko pojawia się i znika natychmiast. Panel filtrów wyskakuje znikąd, toast „Zapisano” miga i znika, rozwinięcie opisu ticketu przesuwa całą tabelę w jednej klatce, a usunięty wiersz po prostu wyparowuje — użytkownik nie jest pewien, co się stało. Krótka animacja (150–300 ms) mówi, **skąd** coś przyszło i **dokąd** poszło. W tej lekcji zrobisz to samym CSS-em sterowanym stanem Reacta: przejścia (`transition`), animacje klatek kluczowych (`@keyframes`), animacje wejścia i — trudniejsze — wyjścia, rozwijanie wysokości oraz szacunek dla ustawienia „ogranicz ruch”.

#T DEFINITION transition i @keyframes
- **`transition`** animuje zmianę wartości właściwości CSS między dwoma stanami: `transition: transform 200ms ease-out, opacity 200ms;`. React zmienia klasę lub styl (np. `panel--open`), a przeglądarka płynnie przechodzi od starej do nowej wartości. Potrzebny jest **stan początkowy i końcowy** — element musi już istnieć w DOM, zanim wartość się zmieni.
- **`@keyframes`** opisuje animację w czasie (`from`/`to` albo procenty) i uruchamia się, gdy element dostanie `animation: nazwa 300ms`. Działa także przy pierwszym pojawieniu się elementu — dlatego nadaje się do animacji **wejścia**.
- **`@starting-style`** (nowoczesne przeglądarki) definiuje wartości „sprzed” pierwszego renderu elementu, dzięki czemu zwykłe `transition` działa też przy wejściu.

Animuj przede wszystkim `transform` i `opacity` — przeglądarka liczy je na karcie graficznej, bez przeliczania układu strony. Animowanie `width`, `height`, `top` czy `margin` powoduje przeliczanie layoutu w każdej klatce i zacina się na słabszych urządzeniach.

#T CODE_BASIC Style: panel wysuwany z boku i rozwijany opis
```
/* animations.css */
.filters-panel {
  transform: translateX(-100%);
  opacity: 0;
  transition: transform 220ms ease-out, opacity 220ms ease-out;
}
.filters-panel--open {
  transform: translateX(0);
  opacity: 1;
}

/* Rozwijanie „do auto”: grid z 0fr → 1fr animuje się płynnie, w przeciwieństwie do height: auto */
.collapse {
  display: grid;
  grid-template-rows: 0fr;
  transition: grid-template-rows 250ms ease;
}
.collapse--open {
  grid-template-rows: 1fr;
}
.collapse > .collapse__inner {
  overflow: hidden;
}

@media (prefers-reduced-motion: reduce) {
  .filters-panel,
  .collapse {
    transition: none;
  }
}
```

#T CODE_JSX Panel filtrów i rozwijany opis sterowane stanem (JSX)
Komponent zmienia tylko klasę — całą animację robi CSS. Panel jest zawsze w DOM (ukryty transformacją), więc przejście ma stan początkowy. `inert` wyłącza ukryty panel z nawigacji klawiaturą i czytników ekranu.
```
// TicketFilters.jsx
import { useState } from 'react';
import './animations.css';

export function TicketFilters({ children }) {
  const [open, setOpen] = useState(false);

  return (
    <>
      <button type="button" aria-expanded={open} aria-controls="filters" onClick={() => setOpen((o) => !o)}>
        Filtry
      </button>
      <aside id="filters" className={open ? 'filters-panel filters-panel--open' : 'filters-panel'} inert={!open}>
        {children}
      </aside>
    </>
  );
}

export function TicketDescription({ text }) {
  const [expanded, setExpanded] = useState(false);

  return (
    <div>
      <div className={expanded ? 'collapse collapse--open' : 'collapse'}>
        <div className="collapse__inner"><p>{text}</p></div>
      </div>
      <button type="button" aria-expanded={expanded} onClick={() => setExpanded((e) => !e)}>
        {expanded ? 'Zwiń opis' : 'Pokaż opis'}
      </button>
    </div>
  );
}
```

#T NOTE JSX ↔ TSX — atrybut inert i style
`inert` jest w React 19 zwykłym atrybutem logicznym (`inert={!open}`), a w TSX ma typ `boolean | undefined` — w starszych wersjach `@types/react` trzeba było pisać `inert=""` albo rozszerzać typy. Gdy animujesz przez `style`, TSX sprawdza nazwy i wartości właściwości (`React.CSSProperties`): `style={{ transfrom: 'scale(1)' }}` jest błędem kompilacji, a w JSX literówka po prostu nic nie zrobi. Zmienne CSS w `style` (`{ '--delay': '100ms' }`) wymagają w TSX rzutowania: `style={{ '--delay': '100ms' } as React.CSSProperties}`.

#T DEFINITION Problem animacji wyjścia
Wejście jest łatwe: element pojawia się w DOM z animacją `@keyframes` (albo z `@starting-style`). Wyjście jest trudne, bo `{visible && <Toast />}` usuwa element z DOM **natychmiast** po zmianie stanu — nie ma już czego animować. Rozwiązania:
1. **Element zostaje w DOM** i jest ukrywany klasą (jak panel filtrów) — proste, ale ukryty element zajmuje pamięć i wymaga `inert` / `aria-hidden`.
2. **Stan pośredni „zamykanie”**: najpierw ustawiasz `closing`, element dostaje animację wyjścia, a w `onAnimationEnd` dopiero go usuwasz.
3. **Biblioteka** (`AnimatePresence` z Motion — następna lekcja) albo **View Transitions** (rozdział 17), które robią „zdjęcie” starego stanu przed usunięciem.

#T CODE_JSX Toast z animacją wejścia i wyjścia (JSX)
Stan `phase` ma trzy wartości. Usunięcie elementu odkładamy do końca animacji wyjścia (`onAnimationEnd`). Gdy użytkownik ma włączone ograniczanie ruchu, animacji nie ma — wtedy zdarzenie by nie przyszło, więc usuwamy od razu.
```
// Toast.jsx
import { useEffect, useState } from 'react';

const reducedMotion = () => window.matchMedia('(prefers-reduced-motion: reduce)').matches;

export function Toast({ message, onDismiss, duration = 3000 }) {
  const [phase, setPhase] = useState('visible'); // 'visible' | 'leaving'

  function startLeaving() {
    if (reducedMotion()) onDismiss();
    else setPhase('leaving');
  }

  useEffect(() => {
    const id = setTimeout(startLeaving, duration);
    return () => clearTimeout(id);
    // eslint-disable-next-line react-hooks/exhaustive-deps -- timer startuje raz, przy pojawieniu się
  }, [duration]);

  return (
    <div
      role="status"
      className={phase === 'leaving' ? 'toast toast--leaving' : 'toast'}
      onAnimationEnd={(e) => {
        if (e.animationName === 'toast-out') onDismiss();
      }}
    >
      {message}
      <button type="button" aria-label="Zamknij" onClick={startLeaving}>×</button>
    </div>
  );
}
```

#T CODE_TSX Toast z animacją wejścia i wyjścia (TSX)
`AnimationEvent<HTMLDivElement>` daje dostęp do `animationName` — sprawdzamy, która animacja się skończyła, bo `onAnimationEnd` przychodzi też dla animacji wejścia (i animacji dzieci, które bąbelkują w górę).
```
// Toast.tsx
import { useEffect, useState, type AnimationEvent } from 'react';

type Phase = 'visible' | 'leaving';
type ToastProps = { message: string; onDismiss: () => void; duration?: number };

const reducedMotion = () => window.matchMedia('(prefers-reduced-motion: reduce)').matches;

export function Toast({ message, onDismiss, duration = 3000 }: ToastProps) {
  const [phase, setPhase] = useState<Phase>('visible');

  function startLeaving() {
    if (reducedMotion()) onDismiss();
    else setPhase('leaving');
  }

  useEffect(() => {
    const id = setTimeout(startLeaving, duration);
    return () => clearTimeout(id);
    // eslint-disable-next-line react-hooks/exhaustive-deps -- timer startuje raz, przy pojawieniu się
  }, [duration]);

  function handleAnimationEnd(e: AnimationEvent<HTMLDivElement>) {
    if (e.animationName === 'toast-out') onDismiss();
  }

  return (
    <div role="status" className={phase === 'leaving' ? 'toast toast--leaving' : 'toast'} onAnimationEnd={handleAnimationEnd}>
      {message}
      <button type="button" aria-label="Zamknij" onClick={startLeaving}>×</button>
    </div>
  );
}
```

```
@keyframes toast-in {
  from { transform: translateY(16px); opacity: 0; }
  to   { transform: translateY(0);    opacity: 1; }
}
@keyframes toast-out {
  to { transform: translateX(110%); opacity: 0; }
}

.toast {
  animation: toast-in 200ms ease-out;
}
.toast--leaving {

  .toast,
  .toast--leaving {
    animation: none;
  }
}
```

#T CODE_PRACTICAL Wejście samym CSS: @starting-style i dialog
Nowoczesny CSS potrafi animować także pojawienie się elementu i przejście z `display: none`. Dla natywnego `<dialog>` (rozdział 08) to wystarcza do animacji otwierania i zamykania bez żadnego kodu w React.
```
/* dialog.css */
dialog {
  opacity: 0;
  transform: scale(0.96);
  transition:
    opacity 200ms ease,
    transform 200ms ease,
    overlay 200ms allow-discrete,
    display 200ms allow-discrete;
}
dialog[open] {
  opacity: 1;
  transform: scale(1);
}
@starting-style {
  dialog[open] {
    opacity: 0;
    transform: scale(0.96);
  }
}
dialog::backdrop {
  background: rgb(0 0 0 / 0);
  transition: background 200ms, overlay 200ms allow-discrete, display 200ms allow-discrete;
}
dialog[open]::backdrop {
  background: rgb(0 0 0 / 0.4);
}
@starting-style {
  dialog[open]::backdrop {
    background: rgb(0 0 0 / 0);
  }
}
```

#T USAGE Hook usePrefersReducedMotion
Ustawienie systemowe „ogranicz ruch” (macOS, Windows, Android, iOS) to dla części osób kwestia zdrowia — duże ruchy i paralaksa mogą wywoływać zawroty głowy i nudności. Obsługujesz je na dwóch poziomach:
- **CSS** — `@media (prefers-reduced-motion: reduce)` wyłącza lub skraca animacje (zamiast przesuwania: samo przenikanie `opacity`),
- **JS** — gdy animacja jest sterowana kodem (przewijanie `behavior: 'smooth'`, biblioteki animacji), czytasz ustawienie hookiem: `useMediaQuery('(prefers-reduced-motion: reduce)')` z treningu `useEffect` i wybierasz `behavior: reduced ? 'auto' : 'smooth'`.

Ograniczenie ruchu nie znaczy „zero zmian” — zmiana stanu nadal ma być widoczna (np. natychmiastowa albo przez przenikanie), tylko bez dużego przemieszczania elementów.

#T STEP_BY_STEP Budujemy razem: płynny DevDesk
1. Panel filtrów wysuwany z lewej (`transform` + `transition`), ukryty panel z `inert`.
2. Rozwijany opis ticketu z techniką `grid-template-rows: 0fr → 1fr` — tabela pod spodem przesuwa się płynnie.
3. Toasty: wejście `@keyframes`, wyjście przez stan `leaving` i `onAnimationEnd`; zamknięcie przyciskiem też animowane.
4. Nowy wiersz tabeli podświetla się na chwilę (`@keyframes highlight` na tle, 1 s) — klasa dodawana przy dodaniu ticketu.
5. Modal oparty na `<dialog>` z animacją otwierania i zamykania samym CSS (`@starting-style`, `allow-discrete`).
6. Dodaj blok `prefers-reduced-motion` do każdego pliku z animacjami; przewijanie do nowego komentarza wybiera `behavior` zależnie od ustawienia.
7. Sprawdź w DevTools: Rendering → „Emulate CSS media feature prefers-reduced-motion” oraz zakładka Performance — czy animacje nie powodują przeliczania layoutu (fioletowe paski „Layout”).

#T PITFALL Animacja, która blokuje użytkownika
Animacje dłuższe niż ~300 ms przy częstych akcjach (otwarcie menu, przełączenie zakładki) męczą już po kilku użyciach, a animacja, podczas której nie można klikać (bo element „jeszcze się wsuwa”), spowalnia pracę. Zasady: krótko (150–250 ms dla małych elementów), `ease-out` przy wejściu, `ease-in` przy wyjściu, interfejs reaguje na kliknięcia także w trakcie animacji, a stan logiczny (np. `open`) zmienia się natychmiast — animacja jest tylko warstwą prezentacji. Nigdy nie opóźniaj usunięcia danych do końca animacji w sposób, który przy jej braku (ograniczony ruch, karta w tle) zostawi element na zawsze — dlatego w toaście jest ścieżka bez animacji.

#T SUMMARY Kryterium akceptacji i podsumowanie
React steruje animacjami CSS przez stan i klasy: `transition` animuje zmianę między dwoma stanami istniejącego elementu, `@keyframes` — pojawienie się elementu, a `@starting-style` z `allow-discrete` pozwala animować wejście i `display: none` samym CSS. Wyjście wymaga, by element pozostał w DOM do końca animacji: ukrywanie klasą (z `inert`) albo stan pośredni i `onAnimationEnd`. Animujesz `transform` i `opacity`, wysokość „do auto” — przez `grid-template-rows`. `prefers-reduced-motion` obsługujesz w CSS i w kodzie. W TSX `CSSProperties` i `AnimationEvent` pilnują nazw właściwości i zdarzeń.

Kryterium akceptacji: panel filtrów, opis ticketu, toasty i modal animują się płynnie (bez przeliczania layoutu w zakładce Performance), toast znika z animacją także po kliknięciu „×”, a przy włączonym „ogranicz ruch” wszystkie elementy działają bez przesuwania i nic nie zostaje na ekranie.
