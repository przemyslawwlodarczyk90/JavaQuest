#T INTRO Rozgrzewka i problem: animacja wyjścia w każdym komponencie od nowa
Rozgrzewka: Dlaczego `{visible && <Toast />}` nie może zanimować wyjścia? Które właściwości CSS animują się bez przeliczania layoutu? Jak sprawdzić `prefers-reduced-motion` w kodzie?

Problem: toast z poprzedniej lekcji działa, ale kosztem stanu `phase`, `onAnimationEnd` i osobnej ścieżki dla ograniczonego ruchu. Teraz to samo trzeba zrobić dla wierszy usuwanych z listy, kart przenoszonych między kolumnami, zakładek z przesuwanym podkreśleniem i panelu zamykanego gestem przesunięcia na telefonie. Ręcznie to dziesiątki linii na każdy przypadek, a animacja **zmiany układu** (wiersze zsuwające się po usunięciu jednego z nich) jest w czystym CSS prawie niewykonalna. Biblioteka **Motion** (dawniej Framer Motion) robi to deklaratywnie: opisujesz stany, a ona animuje przejścia — także wyjście i zmianę pozycji.

#T DEFINITION motion, initial, animate, exit
Instalacja: `npm i motion`, import z `motion/react`.
- **`motion.div`** (i `motion.li`, `motion.button`…) — zwykły element HTML z dodatkowymi props animacji.
- **`initial`** — stan przy pojawieniu się (np. `{ opacity: 0, y: 16 }`); `initial={false}` wyłącza animację wejścia przy pierwszym renderze.
- **`animate`** — stan docelowy; gdy wartości się zmienią (bo zmienił się stan Reacta), Motion animuje do nowych.
- **`exit`** — stan przy usuwaniu; działa tylko wewnątrz **`AnimatePresence`**, który przytrzymuje usuwane dziecko w DOM do końca animacji.
- **`transition`** — czas i krzywa: `{ duration: 0.2, ease: 'easeOut' }` albo fizyka sprężyny `{ type: 'spring', stiffness: 400, damping: 30 }`.

Skróty transformacji: `x`, `y`, `scale`, `rotate` zamiast pisania całego `transform`. Dzieci `AnimatePresence` muszą mieć **unikalny `key`** — po nim biblioteka rozpoznaje, który element wychodzi.

#T CODE_JSX Lista toastów z AnimatePresence (JSX)
Porównaj z poprzednią lekcją: brak stanu `phase`, brak `onAnimationEnd`. Toast usunięty ze stanu wychodzi z animacją, a pozostałe zsuwają się płynnie dzięki `layout`.
```
// Toasts.jsx
import { AnimatePresence, motion } from 'motion/react';

export function Toasts({ toasts, onDismiss }) {
  return (
    <ol className="toasts" aria-live="polite">
      <AnimatePresence initial={false}>
        {toasts.map((t) => (
          <motion.li
            key={t.id}
            layout
            initial={{ opacity: 0, y: 16, scale: 0.95 }}
            animate={{ opacity: 1, y: 0, scale: 1 }}
            exit={{ opacity: 0, x: 80, transition: { duration: 0.15 } }}
            transition={{ type: 'spring', stiffness: 500, damping: 35 }}
            className="toast"
          >
            {t.message}
            <button type="button" aria-label="Zamknij" onClick={() => onDismiss(t.id)}>×</button>
          </motion.li>
        ))}
      </AnimatePresence>
    </ol>
  );
}
```

#T NOTE JSX ↔ TSX — typy animacji
Motion jest napisany w TypeScript: w TSX `animate={{ opactiy: 1 }}` to błąd kompilacji, a `transition={{ type: 'sprng' }}` — też. Props `motion.li` łączą atrybuty `<li>` z props animacji, więc `onClick`, `className` i `aria-*` mają poprawne typy. Gdy przekazujesz konfigurację animacji przez props własnego komponentu, użyj typów z biblioteki: `import type { Transition, Variants } from 'motion/react'`. W JSX literówka w nazwie właściwości animacji po prostu nic nie zrobi — element pojawi się bez animacji i bez ostrzeżenia.

#T DEFINITION Animacje układu: layout i layoutId
- **`layout`** — gdy pozycja lub rozmiar elementu zmieni się po renderze (bo sąsiad zniknął, lista się przesortowała, zmieniła się klasa), Motion mierzy stary i nowy układ i animuje przejście transformacją. Tak działają płynne zmiany kolejności i zsuwanie się listy.
- **`layoutId`** — dwa **różne** elementy z tym samym `layoutId` traktowane są jak jeden: gdy jeden znika, a drugi się pojawia, Motion animuje „przeniesienie” (efekt „shared element”). Klasyczne zastosowania: podkreślenie aktywnej zakładki, miniatura rozwijana w pełny widok.
- **`LayoutGroup`** — grupuje komponenty, które mają wspólnie reagować na zmiany układu (np. dwie listy obok siebie).

Animacje układu używają `transform`, więc są wydajne — ale przy bardzo długich listach mierzenie wszystkich elementów kosztuje; animuj układ tylko tam, gdzie widać efekt.

#T CODE_JSX Zakładki z przesuwanym podkreśleniem (JSX)
Podkreślenie renderuje się tylko pod aktywną zakładką — ale dzięki `layoutId` przy zmianie zakładki przesuwa się płynnie zamiast przeskakiwać.
```
// AnimatedTabs.jsx
import { motion } from 'motion/react';
import { useState } from 'react';

const TABS = [
  { id: 'details', label: 'Szczegóły' },
  { id: 'activity', label: 'Aktywność' },
  { id: 'history', label: 'Historia' },
];

export function AnimatedTabs() {
  const [active, setActive] = useState('details');

  return (
    <div role="tablist" className="tabs">
      {TABS.map((tab) => (
        <button
          key={tab.id}
          role="tab"
          type="button"
          aria-selected={active === tab.id}
          onClick={() => setActive(tab.id)}
          style={{ position: 'relative' }}
        >
          {tab.label}
          {active === tab.id && (
            <motion.span layoutId="tab-underline" className="tabs__underline" transition={{ type: 'spring', stiffness: 500, damping: 40 }} />
          )}
        </button>
      ))}
    </div>
  );
}
```

#T CODE_PRACTICAL Warianty i opóźnione wejście dzieci
**Warianty** (`variants`) to nazwane stany animacji. Rodzic przełącza nazwę (`animate="visible"`), a dzieci z tymi samymi nazwami wariantów dziedziczą ją automatycznie. `staggerChildren` uruchamia dzieci kolejno — lista „wjeżdża” element po elemencie.
```
// StaggeredList.tsx
import { motion, type Variants } from 'motion/react';

const list: Variants = {
  hidden: {},
  visible: { transition: { staggerChildren: 0.04, delayChildren: 0.05 } },
};

const item: Variants = {
  hidden: { opacity: 0, y: 8 },
  visible: { opacity: 1, y: 0, transition: { duration: 0.2, ease: 'easeOut' } },
};

export function StaggeredList({ items }: { items: { id: number; title: string }[] }) {
  return (
    <motion.ul variants={list} initial="hidden" animate="visible">
      {items.map((i) => (
        <motion.li key={i.id} variants={item}>
          {i.title}
        </motion.li>
      ))}
    </motion.ul>
  );
}
```

#T CODE_JSX Gesty: przycisk z reakcją i karta zamykana przesunięciem (JSX)
`whileHover` / `whileTap` / `whileFocus` to stany na czas gestu. `drag="x"` pozwala przeciągać w poziomie; w `onDragEnd` sprawdzasz, jak daleko i jak szybko przesunięto element — powyżej progu karta jest odrzucana.
```
// SwipeCard.jsx
import { motion } from 'motion/react';

export function PressableButton({ children, onClick }) {
  return (
    <motion.button type="button" whileHover={{ scale: 1.03 }} whileTap={{ scale: 0.97 }} onClick={onClick}>
      {children}
    </motion.button>
  );
}

export function SwipeCard({ ticket, onDismiss }) {
  return (
    <motion.article
      className="swipe-card"
      drag="x"
      dragConstraints={{ left: 0, right: 0 }}
      dragElastic={0.6}
      onDragEnd={(_, info) => {
        if (Math.abs(info.offset.x) > 120 || Math.abs(info.velocity.x) > 600) onDismiss(ticket.id);
      }}
      exit={{ opacity: 0, x: 300 }}
    >
      <h3>{ticket.title}</h3>
      {/* Gest to skrót — zawsze zostaw zwykły przycisk dla klawiatury i czytników ekranu */}
      <button type="button" onClick={() => onDismiss(ticket.id)}>Odrzuć</button>
    </motion.article>
  );
}
```

#T CODE_TSX Gesty: przycisk z reakcją i karta zamykana przesunięciem (TSX)
`PanInfo` opisuje gest: `offset` (przesunięcie od początku), `velocity` (prędkość w px/s), `point` (pozycja).
```
// SwipeCard.tsx
import { motion, type PanInfo } from 'motion/react';
import type { ReactNode } from 'react';

export function PressableButton({ children, onClick }: { children: ReactNode; onClick: () => void }) {
  return (
    <motion.button type="button" whileHover={{ scale: 1.03 }} whileTap={{ scale: 0.97 }} onClick={onClick}>
      {children}
    </motion.button>
  );
}

type SwipeCardProps = { ticket: { id: number; title: string }; onDismiss: (id: number) => void };

export function SwipeCard({ ticket, onDismiss }: SwipeCardProps) {
  function handleDragEnd(_: MouseEvent | TouchEvent | PointerEvent, info: PanInfo) {
    if (Math.abs(info.offset.x) > 120 || Math.abs(info.velocity.x) > 600) onDismiss(ticket.id);
  }

  return (
    <motion.article
      className="swipe-card"
      drag="x"
      dragConstraints={{ left: 0, right: 0 }}
      dragElastic={0.6}
      onDragEnd={handleDragEnd}
      exit={{ opacity: 0, x: 300 }}
    >
      <h3>{ticket.title}</h3>
      {/* Gest to skrót — zawsze zostaw zwykły przycisk dla klawiatury i czytników ekranu */}
      <button type="button" onClick={() => onDismiss(ticket.id)}>Odrzuć</button>
    </motion.article>
  );
}
```

#T USAGE Ograniczony ruch i rozmiar paczki
- **`<MotionConfig reducedMotion="user">`** w korzeniu aplikacji — przy włączonym „ogranicz ruch” Motion wyłącza animacje transformacji i układu (przesunięcia, skalowanie), a zostawia przenikanie `opacity`. Jedna linia zamiast warunków w każdym komponencie.
- **`useReducedMotion()`** — hook zwracający `true`, gdy użytkownik ogranicza ruch; przydatny do decyzji w kodzie (np. wyłączenie gestu przesuwania albo paralaksy).
- **Rozmiar** — pełny `motion` to kilkadziesiąt kB. Przy ograniczonym budżecie użyj `LazyMotion` z `domAnimation` i komponentów `m.div` zamiast `motion.div`, a zestaw funkcji doładuj dynamicznie. Proste przejścia (hover, rozwinięcie) nadal rób w CSS — bibliotekę włączaj tam, gdzie daje wartość: wyjście, układ, gesty, sprężyny.

#T STEP_BY_STEP Budujemy razem: Motion w DevDesk
1. Zainstaluj `motion` i owiń aplikację w `<MotionConfig reducedMotion="user">`.
2. Przepisz toasty na `AnimatePresence` + `motion.li` z `layout` — usuń stan `phase` i `onAnimationEnd` z poprzedniej lekcji.
3. Usuwanie ticketu z listy: wiersz wychodzi (`exit`), pozostałe zsuwają się (`layout`). Uwaga: `motion.tr` w tabeli — sprawdź, czy animacja układu nie psuje szerokości kolumn; jeśli tak, animuj tylko `opacity`.
4. Zakładki „Szczegóły / Aktywność / Historia” z podkreśleniem `layoutId`.
5. Zmiana treści zakładki z `AnimatePresence mode="wait"` (stara treść wychodzi, zanim wejdzie nowa) i `key={active}`.
6. Lista ticketów przy pierwszym wyświetleniu wchodzi z `staggerChildren` (tylko pierwsze ~15 elementów — reszta bez opóźnienia).
7. Na telefonie karta ticketu w widoku „do przejrzenia” zamykana gestem przesunięcia, z przyciskiem „Odrzuć” jako alternatywą.
8. Sprawdź z włączonym „ogranicz ruch”: brak przesunięć i skalowania, zostaje przenikanie.

#T PITFALL AnimatePresence, które nie animuje wyjścia
Trzy najczęstsze przyczyny, dla których `exit` się nie wykonuje: (1) `AnimatePresence` jest **wewnątrz** warunku albo komponentu, który sam znika — musi pozostać w drzewie, a warunkowe ma być jego dziecko; (2) dzieci nie mają stabilnego, unikalnego `key` (np. indeks tablicy) — biblioteka nie wie, który element wychodzi; (3) bezpośrednim dzieckiem jest własny komponent, który nie przekazuje animacji dalej — `exit` musi być na elemencie `motion.*`, a komponent pośredni nie może opakowywać go w zwykły `div` z innym kluczem. Do tego pamiętaj, że animowany element nadal jest w DOM podczas wyjścia: czytnik ekranu może go odczytać, a przyciski w nim działają — przy usuwaniu dodaj `pointerEvents: 'none'` w stanie `exit`.

#T SUMMARY Kryterium akceptacji i podsumowanie
Motion opisuje animacje deklaratywnie: `initial`, `animate` i `exit` na elementach `motion.*`, `AnimatePresence` przytrzymujący usuwane dzieci (po `key`) do końca animacji wyjścia, `layout` dla płynnych zmian pozycji, `layoutId` dla efektu wspólnego elementu, warianty ze `staggerChildren` dla list oraz gesty (`whileHover`, `whileTap`, `drag` z `onDragEnd`). `MotionConfig reducedMotion="user"` szanuje ustawienie systemu, a `LazyMotion` zmniejsza paczkę. W TSX typy biblioteki (`Variants`, `Transition`, `PanInfo`) pilnują nazw właściwości i parametrów gestów.

Kryterium akceptacji: toasty i usuwane wiersze wychodzą z animacją, a lista zsuwa się płynnie; podkreślenie zakładek przesuwa się między zakładkami; karta daje się odrzucić gestem i przyciskiem; przy „ogranicz ruch” nie ma przesunięć ani skalowania; w kodzie nie ma już ręcznego stanu faz animacji.
