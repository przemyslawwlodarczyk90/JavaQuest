Rozgrzewka: Po co `activationConstraint` w czujniku wskaźnika? Do czego służy `DragOverlay`? Jaką alternatywę dla przeciągania wymaga WCAG 2.2?

Problem: kierownik zespołu pyta: „czy tickety przybywają szybciej, niż je zamykamy?” i „który priorytet nas zalewa?”. Odpowiedź jest w danych DevDesk, ale tabela 2000 wierszy jej nie pokazuje. Potrzebny jest **dashboard**: wykres liniowy otwartych i zamkniętych ticketów w czasie, wykres słupkowy według priorytetu i statusu oraz liczby kluczowe. W tej lekcji przygotujesz dane do wykresów (to połowa pracy), narysujesz je biblioteką **Recharts**, dopasujesz do szerokości ekranu i motywu oraz zadbasz o to, by wykres był czytelny także bez wzroku.

#T DEFINITION Recharts: wykres jako drzewo komponentów
Recharts buduje wykresy SVG z komponentów Reacta — wykres składasz jak zwykły JSX:
- **kontener wykresu**: `LineChart`, `BarChart`, `AreaChart`, `PieChart`, `ComposedChart` — przyjmuje `data` (tablicę obiektów, jeden obiekt = jeden punkt na osi X),
- **serie**: `Line`, `Bar`, `Area` z `dataKey` — nazwą pola w obiektach danych,
- **osie i pomoce**: `XAxis dataKey="day"`, `YAxis`, `CartesianGrid`, `Tooltip`, `Legend`, `ReferenceLine`,
- **`ResponsiveContainer`** — dopasowuje wykres do rozmiaru rodzica (rodzic musi mieć określoną wysokość).

Biblioteka nie liczy danych za Ciebie: grupowanie po dniach, sumy i średnie przygotowujesz wcześniej, w czystej funkcji. Wykres dostaje gotową, małą tablicę — dziesiątki, a nie tysiące punktów.

#T CODE_JSX Przygotowanie danych: tickety po dniach (JSX)
Czysta funkcja zamienia listę ticketów w serię dzienną: ile otwarto i zamknięto każdego dnia oraz ile było otwartych na koniec dnia. Dni bez zdarzeń też muszą być na osi — inaczej linia „przeskoczy” lukę.
```
// ticketStats.js
const dayKey = (iso) => iso.slice(0, 10); // '2026-10-25T14:00:00Z' → '2026-10-25'

export function dailySeries(tickets, from, days) {
  const series = Array.from({ length: days }, (_, i) => {
    const date = new Date(from);
    date.setDate(date.getDate() + i);
    return { day: date.toISOString().slice(0, 10), opened: 0, closed: 0, open: 0 };
  });
  const index = new Map(series.map((point, i) => [point.day, i]));

  for (const t of tickets) {
    const openedAt = index.get(dayKey(t.createdAt));
    if (openedAt !== undefined) series[openedAt].opened += 1;
    if (t.closedAt) {
      const closedAt = index.get(dayKey(t.closedAt));
      if (closedAt !== undefined) series[closedAt].closed += 1;
    }
  }

  let running = tickets.filter((t) => dayKey(t.createdAt) < series[0].day && (!t.closedAt || dayKey(t.closedAt) >= series[0].day)).length;
  for (const point of series) {
    running += point.opened - point.closed;
    point.open = running;
  }
  return series;
}

export function byPriorityAndStatus(tickets) {
  const priorities = ['LOW', 'MEDIUM', 'HIGH', 'CRITICAL'];
  return priorities.map((priority) => {
    const group = tickets.filter((t) => t.priority === priority);
    return {
      priority,
      OPEN: group.filter((t) => t.status === 'OPEN').length,
      IN_PROGRESS: group.filter((t) => t.status === 'IN_PROGRESS').length,
      CLOSED: group.filter((t) => t.status === 'CLOSED').length,
    };
  });
}
```

#T CODE_TSX Przygotowanie danych: tickety po dniach (TSX)
Typy punktów wykresu (`DailyPoint`, `PriorityRow`) dokumentują, jakie `dataKey` istnieją — literówka w `dataKey="opend"` jest wtedy łatwa do wychwycenia przy przeglądzie, choć sam Recharts przyjmuje dowolny tekst.
```
// ticketStats.ts
import type { Ticket, TicketPriority, TicketStatus } from '../types';

export type StatsTicket = Ticket & { closedAt: string | null };
export type DailyPoint = { day: string; opened: number; closed: number; open: number };
export type PriorityRow = { priority: TicketPriority } & Record<TicketStatus, number>;

const dayKey = (iso: string) => iso.slice(0, 10); // '2026-10-25T14:00:00Z' → '2026-10-25'

export function dailySeries(tickets: StatsTicket[], from: Date, days: number): DailyPoint[] {
  const series: DailyPoint[] = Array.from({ length: days }, (_, i) => {
    const date = new Date(from);
    date.setDate(date.getDate() + i);
    return { day: date.toISOString().slice(0, 10), opened: 0, closed: 0, open: 0 };
  });
  const index = new Map(series.map((point, i) => [point.day, i]));

  for (const t of tickets) {
    const openedAt = index.get(dayKey(t.createdAt));
    if (openedAt !== undefined) series[openedAt].opened += 1;
    if (t.closedAt) {
      const closedAt = index.get(dayKey(t.closedAt));
      if (closedAt !== undefined) series[closedAt].closed += 1;
    }
  }

  let running = tickets.filter((t) => dayKey(t.createdAt) < series[0].day && (!t.closedAt || dayKey(t.closedAt) >= series[0].day)).length;
  for (const point of series) {
    running += point.opened - point.closed;
    point.open = running;
  }
  return series;
}

export function byPriorityAndStatus(tickets: StatsTicket[]): PriorityRow[] {
  const priorities: TicketPriority[] = ['LOW', 'MEDIUM', 'HIGH', 'CRITICAL'];
  return priorities.map((priority) => {
    const group = tickets.filter((t) => t.priority === priority);
    return {
      priority,
      OPEN: group.filter((t) => t.status === 'OPEN').length,
      IN_PROGRESS: group.filter((t) => t.status === 'IN_PROGRESS').length,
      CLOSED: group.filter((t) => t.status === 'CLOSED').length,
    };
  });
}
```

#T CODE_JSX Wykres liniowy ticketów w czasie (JSX)
`useMemo` zapamiętuje przeliczone dane — przeliczenie 2000 ticketów nie powtarza się przy najechaniu kursorem (Tooltip zmienia stan wykresu). Kolory pochodzą ze zmiennych CSS, więc wykres zmienia się razem z motywem.
```
// TicketsTrendChart.jsx
import { useMemo } from 'react';
import { CartesianGrid, Legend, Line, LineChart, ResponsiveContainer, Tooltip, XAxis, YAxis } from 'recharts';
import { dailySeries } from './ticketStats';

const shortDate = (day) => new Date(day).toLocaleDateString('pl-PL', { day: 'numeric', month: 'short' });

export function TicketsTrendChart({ tickets, from, days = 30 }) {
  const data = useMemo(() => dailySeries(tickets, from, days), [tickets, from, days]);

  return (
    <figure className="chart">
      <figcaption>Otwarte i zamknięte tickety — ostatnie {days} dni</figcaption>
      <div style={{ height: 280 }}>
        <ResponsiveContainer width="100%" height="100%">
          <LineChart data={data} margin={{ top: 8, right: 16, bottom: 0, left: 0 }}>
            <CartesianGrid strokeDasharray="3 3" stroke="var(--color-border)" />
            <XAxis dataKey="day" tickFormatter={shortDate} minTickGap={24} />
            <YAxis allowDecimals={false} width={32} />
            <Tooltip labelFormatter={(day) => shortDate(String(day))} />
            <Legend />
            <Line type="monotone" dataKey="open" name="Otwarte (stan)" stroke="var(--color-primary)" strokeWidth={2} dot={false} />
            <Line type="monotone" dataKey="opened" name="Nowe" stroke="var(--color-warning)" dot={false} />
            <Line type="monotone" dataKey="closed" name="Zamknięte" stroke="var(--color-success)" dot={false} />
          </LineChart>
        </ResponsiveContainer>
      </div>
    </figure>
  );
}
```

#T NOTE JSX ↔ TSX — dataKey to zwykły tekst
`dataKey="opened"` w Recharts ma typ ogólny (tekst, liczba albo funkcja), więc TypeScript **nie** sprawdzi, czy pole istnieje w danych — literówka da pustą serię w obu wersjach. TSX pomaga pośrednio: typ `DailyPoint` widać w podpowiedziach, a jeśli chcesz pełnej kontroli, użyj funkcji `dataKey={(p: DailyPoint) => p.opened}` albo stałej `const KEYS = { opened: 'opened' } satisfies Record<string, keyof DailyPoint>`. Formatery (`tickFormatter`, `labelFormatter`) dostają wartości typu `unknown`/ogólnego — stąd `String(day)`.

#T CODE_PRACTICAL Słupki skumulowane i własny tooltip
Wykres słupkowy z `stackId` kumuluje statusy w jednym słupku priorytetu. Własny tooltip pokazuje sumę i polskie nazwy statusów.
```
// PriorityChart.tsx
import { Bar, BarChart, CartesianGrid, Legend, ResponsiveContainer, Tooltip, XAxis, YAxis, type TooltipContentProps } from 'recharts';
import type { PriorityRow } from './ticketStats';

const PRIORITY_LABEL: Record<string, string> = { LOW: 'Niski', MEDIUM: 'Średni', HIGH: 'Wysoki', CRITICAL: 'Krytyczny' };

function PriorityTooltip({ active, payload, label }: TooltipContentProps) {
  if (!active || !payload?.length) return null;
  const total = payload.reduce((sum, entry) => sum + Number(entry.value ?? 0), 0);
  return (
    <div className="chart-tooltip">
      <strong>{PRIORITY_LABEL[String(label)]}: {total}</strong>
      <ul>
        {payload.map((entry) => (
          <li key={String(entry.dataKey)} style={{ color: entry.color }}>{entry.name}: {entry.value}</li>
        ))}
      </ul>
    </div>
  );
}

export function PriorityChart({ data }: { data: PriorityRow[] }) {
  return (
    <figure className="chart">
      <figcaption>Tickety według priorytetu i statusu</figcaption>
      <div style={{ height: 260 }}>
        <ResponsiveContainer width="100%" height="100%">
          <BarChart data={data}>
            <CartesianGrid vertical={false} stroke="var(--color-border)" />
            <XAxis dataKey="priority" tickFormatter={(p) => PRIORITY_LABEL[String(p)]} />
            <YAxis allowDecimals={false} width={32} />
            <Tooltip content={(props) => <PriorityTooltip {...props} />} />
            <Legend />
            <Bar dataKey="OPEN" name="Otwarte" stackId="status" fill="var(--color-warning)" />
            <Bar dataKey="IN_PROGRESS" name="W toku" stackId="status" fill="var(--color-primary)" />
            <Bar dataKey="CLOSED" name="Zamknięte" stackId="status" fill="var(--color-success)" />
          </BarChart>
        </ResponsiveContainer>
      </div>
    </figure>
  );
}
```

#T DEFINITION Wykres dostępny i czytelny
Wykres to obraz — dla czytnika ekranu i dla osoby, która nie rozróżnia kolorów, trzeba zadbać o kilka rzeczy:
- **Podpis**: `<figure>` z `<figcaption>` mówiącym, co pokazuje wykres; dla najważniejszego wniosku — zdanie pod wykresem („W ostatnim tygodniu zamknięto o 12 ticketów więcej, niż otwarto”).
- **Dane w tabeli**: przycisk „Pokaż dane jako tabelę” albo `<details>` z tabelą tych samych liczb — dostępna alternatywa i możliwość skopiowania.
- **Klawiatura**: Recharts 3 ma `accessibilityLayer` (domyślnie włączony) — wykres dostaje fokus, a strzałki przesuwają po punktach z tooltipem.
- **Kolory**: nie koduj informacji **wyłącznie** kolorem — różne style linii (`strokeDasharray`), etykiety bezpośrednio przy seriach, wystarczający kontrast z tłem w obu motywach.
- **Oś Y od zera** dla słupków (inaczej różnice wyglądają na większe), ograniczona liczba serii (3–5), jednostki w opisie osi.

#T USAGE Rozmiar i wydajność
- Recharts waży kilkadziesiąt–kilkaset kB — dashboard ładuj leniwie (`lazy(() => import('./Dashboard'))`, rozdział 16), żeby lista ticketów nie płaciła za wykresy.
- `ResponsiveContainer` mierzy rodzica przez `ResizeObserver`; rodzic **musi mieć wysokość** (np. `height: 280` albo `aspect-ratio`), inaczej wykres ma 0 px.
- Animacje wejścia serii (`isAnimationActive`) wyłącz przy częstym odświeżaniu danych i przy „ogranicz ruch”.
- Przy tysiącach punktów agreguj (dni → tygodnie) albo próbkuj — SVG z 10 000 elementów zwalnia przeglądarkę. Dla bardzo dużych zbiorów i wykresów na żywo rozważ biblioteki rysujące na `canvas` (np. ECharts, uPlot).

#T PITFALL Wykres liczony przy każdym ruchu kursora
Najczęstszy problem wydajności dashboardów: agregacja danych w ciele komponentu bez `useMemo`, a do tego nowa tablica `data` przy każdym renderze. Najechanie kursorem zmienia wewnętrzny stan wykresu (tooltip), rodzic renderuje się z innego powodu (np. zegar „ostatnia synchronizacja”), a 2000 ticketów jest grupowanych od nowa kilkadziesiąt razy na sekundę. Przygotowanie danych zamykaj w czystych funkcjach i `useMemo` z właściwymi zależnościami (albo w `select` TanStack Query) — i mierz Profilerem, czy wykres nie renderuje się częściej, niż zmieniają się dane.

#T SUMMARY Kryterium akceptacji i podsumowanie
Wykres w Recharts to drzewo komponentów: kontener (`LineChart`, `BarChart`) z danymi, serie z `dataKey`, osie, siatka, tooltip i legenda, a `ResponsiveContainer` dopasowuje go do rodzica o znanej wysokości. Najważniejsza praca to przygotowanie danych w czystej, przetestowanej funkcji (także dni bez zdarzeń) i zapamiętanie wyniku `useMemo`. Dostępny wykres ma podpis, tabelę z danymi, obsługę klawiatury i nie opiera informacji wyłącznie na kolorze. W TSX typy punktów danych i `TooltipContentProps` porządkują kod, choć sam `dataKey` nie jest sprawdzany przez kompilator.

Kryterium akceptacji: dashboard ładuje się leniwie, pokazuje trend 7/30/90 dni i podział według priorytetu, ma tabelę danych pod każdym wykresem, działa na 360 px i w obu motywach, a najechanie kursorem nie powoduje ponownego przeliczania danych (sprawdzone Profilerem).
