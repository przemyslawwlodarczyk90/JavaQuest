#T INTRO Rozgrzewka i problem: kod sprzed hooków
Rozgrzewka: Od jakiego przekroju funkcji zaczynasz projekt końcowy? Co zapisujesz w rekordzie decyzji? Dlaczego ochrona ról w interfejsie nie wystarcza?

Problem: dostajesz do utrzymania starszy moduł raportów firmy — napisany w 2017 roku, zanim pojawiły się hooki (React 16.8, 2019). Zamiast `useState` i `useEffect` widzisz `class ReportPanel extends React.Component`, `this.state`, `this.setState`, `componentDidMount`, `componentDidUpdate(prevProps)` i `this.handleClick = this.handleClick.bind(this)`. Takiego kodu jest w firmach wciąż bardzo dużo, a jedno API Reacta — granice błędów — nadal wymaga klasy. W tej lekcji nauczysz się czytać i bezpiecznie zmieniać komponenty klasowe, rozumiejąc, jak ich metody odpowiadają temu, co już znasz.

#T DEFINITION Komponent klasowy
Komponent klasowy to klasa dziedzicząca po `React.Component` (albo `PureComponent`) z metodą `render()`, która zwraca JSX:
- **props** — w `this.props` (zamiast parametru funkcji),
- **stan** — jeden obiekt w `this.state`, inicjalizowany w konstruktorze albo polem klasy,
- **zmiana stanu** — `this.setState(zmiana)`: **scala płytko** podany obiekt z obecnym stanem (inaczej niż setter `useState`, który zastępuje wartość) i planuje render,
- **metody cyklu życia** — wywoływane przez Reacta w określonych momentach: po zamontowaniu, po aktualizacji, przed odmontowaniem,
- **`this`** — metody klasy przekazywane jako handlery tracą `this`, więc trzeba je wiązać (`bind` w konstruktorze) albo pisać jako pola ze strzałką.

Komponenty klasowe działają w React 19 bez zmian, ale nie mogą używać hooków. Nowy kod pisze się funkcjami.

#T CODE_JSX Panel raportu jako klasa (JSX)
Typowy komponent z tamtych lat: stan, pobranie danych po zamontowaniu, ponowne pobranie po zmianie props, timer z odświeżaniem i sprzątanie przy odmontowaniu.
```
// ReportPanel.jsx
import { Component } from 'react';

export class ReportPanel extends Component {
  state = { data: null, loading: true, error: null, autoRefresh: false };

  componentDidMount() {
    this.load();
  }

  componentDidUpdate(prevProps, prevState) {
    if (prevProps.reportId !== this.props.reportId) this.load();
    if (prevState.autoRefresh !== this.state.autoRefresh) this.toggleTimer();
  }

  componentWillUnmount() {
    clearInterval(this.timer);
    this.cancelled = true;
  }

  async load() {
    this.setState({ loading: true, error: null }); // scala: data i autoRefresh zostają
    try {
      const res = await fetch(`/api/reports/${this.props.reportId}`);
      const data = await res.json();
      if (!this.cancelled) this.setState({ data, loading: false });
    } catch (error) {
      if (!this.cancelled) this.setState({ error, loading: false });
    }
  }

  toggleTimer() {
    clearInterval(this.timer);
    if (this.state.autoRefresh) this.timer = setInterval(() => this.load(), 30_000);
  }

  // Pole ze strzałką — this jest związane z instancją, bez bind w konstruktorze.
  handleToggle = () => {
    this.setState((prev) => ({ autoRefresh: !prev.autoRefresh }));
  };

  render() {
    const { data, loading, error, autoRefresh } = this.state;
    if (loading && !data) return <p>Ładowanie raportu…</p>;
    if (error) return <p role="alert">Nie udało się wczytać raportu.</p>;
    return (
      <section>
        <h2>{data.title}</h2>
        <label>
          <input type="checkbox" checked={autoRefresh} onChange={this.handleToggle} /> Odświeżaj co 30 s
        </label>
        <p>Zgłoszeń: {data.count}</p>
      </section>
    );
  }
}
```

#T CODE_TSX Panel raportu jako klasa (TSX)
W TSX klasa dostaje dwa parametry typu: `Component<Props, State>`. Pola instancji (timer, flaga anulowania) deklarujesz jawnie.
```
// ReportPanel.tsx
import { Component } from 'react';

type Report = { title: string; count: number };
type Props = { reportId: number };
type State = { data: Report | null; loading: boolean; error: unknown; autoRefresh: boolean };

export class ReportPanel extends Component<Props, State> {
  state: State = { data: null, loading: true, error: null, autoRefresh: false };
  private timer: ReturnType<typeof setInterval> | undefined;
  private cancelled = false;

  componentDidMount() {
    void this.load();
  }

  componentDidUpdate(prevProps: Props, prevState: State) {
    if (prevProps.reportId !== this.props.reportId) void this.load();
    if (prevState.autoRefresh !== this.state.autoRefresh) this.toggleTimer();
  }

  componentWillUnmount() {
    clearInterval(this.timer);
    this.cancelled = true;
  }

  async load() {
    this.setState({ loading: true, error: null }); // scala: data i autoRefresh zostają
    try {
      const res = await fetch(`/api/reports/${this.props.reportId}`);
      const data = (await res.json()) as Report;
      if (!this.cancelled) this.setState({ data, loading: false });
    } catch (error) {
      if (!this.cancelled) this.setState({ error, loading: false });
    }
  }

  toggleTimer() {
    clearInterval(this.timer);
    if (this.state.autoRefresh) this.timer = setInterval(() => void this.load(), 30_000);
  }

  // Pole ze strzałką — this jest związane z instancją, bez bind w konstruktorze.
  handleToggle = () => {
    this.setState((prev) => ({ autoRefresh: !prev.autoRefresh }));
  };

  render() {
    const { data, loading, error, autoRefresh } = this.state;
    if (loading && !data) return <p>Ładowanie raportu…</p>;
    if (error || !data) return <p role="alert">Nie udało się wczytać raportu.</p>;
    return (
      <section>
        <h2>{data.title}</h2>
        <label>
          <input type="checkbox" checked={autoRefresh} onChange={this.handleToggle} /> Odświeżaj co 30 s
        </label>
        <p>Zgłoszeń: {data.count}</p>
      </section>
    );
  }
}
```

#T NOTE JSX ↔ TSX — typy w klasach
`Component<Props, State>` sprawia, że `this.props.reportId` ma typ `number`, a `this.setState({ autoRefreh: true })` jest błędem. `setState` przyjmuje w TS obiekt z **częścią** pól stanu (`Pick<State, K>`), więc częściowe aktualizacje są poprawne — tak jak scalanie w działaniu. W starszym kodzie TSX zobaczysz też `React.Component<Props, State>` z interfejsami `IProps`, `IState` i pola `public`/`private` — to kwestia stylu, nie działania. W JSX komponenty klasowe często mają `static propTypes = { reportId: PropTypes.number.isRequired }` — sprawdzanie props w czasie działania (tylko w trybie deweloperskim, a od React 19 PropTypes nie są już sprawdzane przez Reacta).

#T VISUAL_EXAMPLE Metody cyklu życia na osi czasu
MONTOWANIE      constructor → (getDerivedStateFromProps) → render → [zmiany w DOM] → componentDidMount
AKTUALIZACJA    (getDerivedStateFromProps) → shouldComponentUpdate → render → getSnapshotBeforeUpdate
                → [zmiany w DOM] → componentDidUpdate(prevProps, prevState, snapshot)
ODMONTOWANIE    componentWillUnmount
BŁĄD POTOMKA    static getDerivedStateFromError → componentDidCatch   (granice błędów, rozdział 19)

Odpowiedniki w hookach (szczegóły w następnej lekcji):
componentDidMount + componentWillUnmount     ≈ useEffect(() => { …; return () => … }, [])
componentDidUpdate z porównaniem prevProps   ≈ useEffect(…, [zależność])
shouldComponentUpdate / PureComponent        ≈ memo
getSnapshotBeforeUpdate                      ≈ useLayoutEffect (pomiar przed zmianą)

#T DEFINITION setState: scalanie, kolejka i callback
Trzy cechy `setState`, które trzeba znać, czytając stary kod:
- **Płytkie scalanie** — `this.setState({ loading: true })` zmienia tylko `loading`; pozostałe pola zostają. Ale zagnieżdżone obiekty **nie** są scalane: `this.setState({ filters: { status: 'OPEN' } })` zastępuje cały obiekt `filters`.
- **Asynchroniczność i grupowanie** — po `setState` wartość `this.state` jeszcze się nie zmieniła; kilka wywołań w jednym handlerze daje jeden render. Gdy nowy stan zależy od poprzedniego, używasz formy funkcyjnej: `this.setState((prev, props) => ({ count: prev.count + props.step }))` — to ten sam mechanizm co `set(prev => …)` z treningu useState.
- **Callback po aktualizacji** — drugi argument: `this.setState({ page: 1 }, () => this.load())` wywołuje funkcję po zastosowaniu zmiany i renderze. W hookach odpowiednikiem jest Effect zależny od tej wartości (albo — częściej — wywołanie logiki bezpośrednio w handlerze).

#T CODE_PRACTICAL PureComponent, getDerivedStateFromProps i createRef
Trzy elementy, które spotkasz w starszych bazach kodu — z komentarzami, jak je rozumieć.
```
// LegacyPatterns.tsx
import { Component, PureComponent, createRef } from 'react';

type Row = { id: number; title: string };

// PureComponent = Component z płytkim porównaniem props i stanu (jak memo dla funkcji).
export class TicketRowLegacy extends PureComponent<{ row: Row; onSelect: (id: number) => void }> {
  render() {
    const { row, onSelect } = this.props;
    return <li onClick={() => onSelect(row.id)}>{row.title}</li>;
  }
}

// getDerivedStateFromProps — stan wyliczany z props przed każdym renderem. Rzadko potrzebny:
// dziś zwykle wystarcza obliczenie w renderze albo reset przez key.
type FilterProps = { items: Row[] };
type FilterState = { query: string; prevItems: Row[] | null };

export class FilteredList extends Component<FilterProps, FilterState> {
  state: FilterState = { query: '', prevItems: null };

  static getDerivedStateFromProps(props: FilterProps, state: FilterState): Partial<FilterState> | null {
    // Nowa lista z zewnątrz → wyczyść wyszukiwanie (w hookach: <FilteredList key={…} />).
    return props.items !== state.prevItems ? { query: '', prevItems: props.items } : null;
  }

  // createRef — odpowiednik useRef dla klas; ref.current wypełnia React po zamontowaniu.
  private inputRef = createRef<HTMLInputElement>();

  componentDidMount() {
    this.inputRef.current?.focus();
  }

  render() {
    const visible = this.props.items.filter((i) => i.title.includes(this.state.query));
    return (
      <div>
        <input ref={this.inputRef} value={this.state.query} onChange={(e) => this.setState({ query: e.target.value })} aria-label="Szukaj" />
        <ul>{visible.map((i) => <li key={i.id}>{i.title}</li>)}</ul>
      </div>
    );
  }
}
```

#T DEFINITION Metody, których już nie używaj
W bardzo starym kodzie (React 15–16.2) spotkasz metody oznaczone dziś prefiksem `UNSAFE_`:
- `componentWillMount` → logika do konstruktora albo `componentDidMount`,
- `componentWillReceiveProps(nextProps)` → `componentDidUpdate` z porównaniem albo `getDerivedStateFromProps`, a najczęściej — dane wyliczane w renderze lub reset przez `key`,
- `componentWillUpdate` → `componentDidUpdate` / `getSnapshotBeforeUpdate`.

Działają (z ostrzeżeniami w StrictMode), ale w renderowaniu współbieżnym mogą być wywołane wielokrotnie i powodować błędy. Spotkasz też stare **string refs** (`ref="input"` i `this.refs.input`) oraz **legacy context** (`contextTypes`, `getChildContext`) — oba **usunięte w React 19**; przy aktualizacji Reacta trzeba je przepisać na `createRef` i `createContext`.

#T STEP_BY_STEP Budujemy razem: czytanie i poprawianie modułu raportów
1. Przeczytaj `ReportPanel` i zapisz na kartce: co jest stanem, kiedy pobierane są dane, co jest sprzątane przy odmontowaniu.
2. Znajdź błąd: zmiana `reportId` w trakcie ładowania — czy stara odpowiedź może nadpisać nową? (Tak: flaga `cancelled` działa tylko przy odmontowaniu.) Napraw licznikiem żądań w polu instancji.
3. Dodaj do klasy filtr dat jako zagnieżdżony obiekt stanu i sprawdź pułapkę scalania (`setState({ range: { from } })` gubi `to`).
4. Zamień `bind` w konstruktorze na pola ze strzałką w całym module.
5. Uruchom moduł w StrictMode i usuń ostrzeżenia o metodach `UNSAFE_`.
6. W wersji TSX dodaj typy `Component<Props, State>` i sprawdź, ile błędów znajdzie kompilator.

#T PITFALL Mutowanie this.state i zgubione this
Dwa klasyczne błędy w kodzie klasowym. Pierwszy: `this.state.items.push(x); this.setState({ items: this.state.items })` albo wręcz `this.state.count = 5` — mutacja stanu, przy której `PureComponent` nie widzi zmiany, a przypisanie bez `setState` nie wywołuje renderu wcale (tylko w konstruktorze wolno przypisać `this.state = …`). Drugi: `<button onClick={this.handleClick}>` z metodą zwykłą (nie strzałkową) i bez `bind` — w handlerze `this` jest `undefined` i pada `TypeError: Cannot read properties of undefined (reading 'setState')`. Naprawa: pola ze strzałką albo `this.handleClick = this.handleClick.bind(this)` w konstruktorze — nie `onClick={() => this.handleClick()}` w każdym renderze, jeśli dziecko jest `PureComponent`.

#T SUMMARY Kryterium akceptacji i podsumowanie
Komponent klasowy dziedziczy po `Component` lub `PureComponent`, ma `render()`, props w `this.props` i jeden obiekt stanu w `this.state`, zmieniany przez `setState` (płytkie scalanie, grupowanie, forma funkcyjna, callback po aktualizacji). Metody cyklu życia — `componentDidMount`, `componentDidUpdate(prevProps, prevState)`, `componentWillUnmount`, `shouldComponentUpdate` — mają odpowiedniki w hookach. `getDerivedStateFromProps` i `getSnapshotBeforeUpdate` to rzadkie przypadki, a metody `UNSAFE_`, string refs i legacy context nie nadają się do dalszego użycia (dwa ostatnie usunięto w React 19). W TSX klasa ma typy `Component<Props, State>`.

Kryterium akceptacji: potrafisz opisać, co robi każdy komponent klasowy w module raportów, wyścig odpowiedzi w `ReportPanel` jest naprawiony, w module nie ma `bind` w renderze ani mutacji `this.state`, a StrictMode nie zgłasza ostrzeżeń o przestarzałych metodach.
