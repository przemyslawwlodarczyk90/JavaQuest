#T INTRO Rozgrzewka i problem: tickety tworzone tylko w kodzie
Rozgrzewka: Co odróżnia input kontrolowany od niekontrolowanego? Dlaczego reset strony po zmianie filtra robisz w handlerze, a nie w efekcie? Jaka jest kolejność filtr–sort–strona?

Problem: przycisk „+ Nowy ticket” otwiera modal, ale w środku nie ma formularza. Użytkownik musi móc wpisać tytuł i opis, a aplikacja — odczytać dane i dodać ticket. Zaczynasz od najprostszego formularza z dwoma polami kontrolowanymi i obsługą wysłania.

#T DEFINITION Formularz w React
Formularz to element `<form>` z polami i przyciskiem `type="submit"`. Wysłanie (kliknięcie przycisku albo Enter w polu tekstowym) wywołuje zdarzenie `submit`. Domyślnie przeglądarka przeładowuje wtedy stronę — w aplikacji React blokujesz to `event.preventDefault()` i sam decydujesz, co zrobić z danymi.

Stan formularza możesz trzymać jako osobne pola (`useState` na każde pole) albo jeden obiekt (`useState({ title: '', description: '' })`). Przy więcej niż dwóch polach wygodniejszy jest obiekt z jednym handlerem dla wszystkich pól.

#T CODE_JSX Formularz nowego ticketu (JSX)
Jeden handler `handleChange` obsługuje wszystkie pola dzięki atrybutowi `name` — nazwa pola w formularzu odpowiada nazwie klucza w stanie.
```
// NewTicketForm.jsx
import { useState } from 'react';

const EMPTY = { title: '', description: '' };

export function NewTicketForm({ onCreate }) {
  const [form, setForm] = useState(EMPTY);

  function handleChange(e) {
    const { name, value } = e.target;
    setForm((prev) => ({ ...prev, [name]: value }));
  }

  function handleSubmit(e) {
    e.preventDefault();
    onCreate(form);
    setForm(EMPTY);
  }

  return (
    <form onSubmit={handleSubmit} className="form">
      <label htmlFor="title">Tytuł</label>
      <input id="title" name="title" value={form.title} onChange={handleChange} />

      <label htmlFor="description">Opis</label>
      <textarea id="description" name="description" value={form.description} onChange={handleChange} rows={4} />

      <button type="submit">Utwórz ticket</button>
    </form>
  );
}
```

#T CODE_TSX Formularz nowego ticketu (TSX)
Typ formularza osobno od typu `Ticket` — formularz ma tylko pola, które wypełnia użytkownik. Handler obsługuje `input` i `textarea`, więc typ zdarzenia to unia elementów.
```
// NewTicketForm.tsx
import { useState, type ChangeEvent, type FormEvent } from 'react';

export type NewTicketFormValues = { title: string; description: string };

const EMPTY: NewTicketFormValues = { title: '', description: '' };

export function NewTicketForm({ onCreate }: { onCreate: (values: NewTicketFormValues) => void }) {
  const [form, setForm] = useState(EMPTY);

  function handleChange(e: ChangeEvent<HTMLInputElement | HTMLTextAreaElement>) {
    const { name, value } = e.target;
    setForm((prev) => ({ ...prev, [name]: value }));
  }

  function handleSubmit(e: FormEvent<HTMLFormElement>) {
    e.preventDefault();
    onCreate(form);
    setForm(EMPTY);
  }

  return (
    <form onSubmit={handleSubmit} className="form">
      <label htmlFor="title">Tytuł</label>
      <input id="title" name="title" value={form.title} onChange={handleChange} />

      <label htmlFor="description">Opis</label>
      <textarea id="description" name="description" value={form.description} onChange={handleChange} rows={4} />

      <button type="submit">Utwórz ticket</button>
    </form>
  );
}
```

#T NOTE JSX ↔ TSX — klucz z [name] nie jest sprawdzany
Uwaga na subtelność: `{ ...prev, [name]: value }` z `name` typu `string` TypeScript akceptuje, ale nie sprawdza, czy `name` to istniejące pole formularza — literówka `name="titel"` w JSX doda do stanu nowe pole w obu wersjach. Bezpieczniejszy wariant w TSX to handler per pole albo funkcja `setField<K extends keyof NewTicketFormValues>(key: K, value: NewTicketFormValues[K])`. Za to typy `FormEvent<HTMLFormElement>` i `onCreate: (values: NewTicketFormValues) => void` pilnują kontraktu z rodzicem: rodzic dostaje dokładnie `{ title, description }`.

#T CODE_PRACTICAL Typowany setter pola zamiast [name]
Każde wywołanie `setField` jest sprawdzane: zła nazwa albo zły typ wartości to błąd kompilacji.
```
import { useState } from 'react';

type Values = { title: string; description: string };

export function useFormValues(initial: Values) {
  const [values, setValues] = useState(initial);

  function setField<K extends keyof Values>(key: K, value: Values[K]) {
    setValues((prev) => ({ ...prev, [key]: value }));
  }

  return { values, setField, reset: () => setValues(initial) };
}

// użycie w JSX: <input value={values.title} onChange={(e) => setField('title', e.target.value)} />
```

#T DEFINITION Przyciski w formularzu
Przycisk w `<form>` **bez atrybutu `type`** jest domyślnie przyciskiem wysyłającym (`type="submit"`). Przycisk „Anuluj” albo „Dodaj tag” bez `type="button"` wyśle formularz. Zasada: w formularzu każdemu przyciskowi nadawaj jawny typ — `submit` dla jednego głównego, `button` dla pozostałych, `reset` rzadko (resetuje tylko pola niekontrolowane).

#T VISUAL_EXAMPLE Obieg wysłania formularza
Enter w polu / klik „Utwórz ticket”
        │
        ▼
<form onSubmit={handleSubmit}>
        │  e.preventDefault()  → brak przeładowania strony
        ▼
onCreate(form)  → rodzic (Main) dodaje ticket do stanu listy
        │
        ▼
setForm(EMPTY)  → pola formularza czyszczą się (są kontrolowane)

#T STEP_BY_STEP Budujemy razem: formularz w modalu
1. Utwórz `NewTicketForm` według przykładu.
2. Umieść formularz w modalu „Nowy ticket” (z rozdziału 03).
3. W `Main` napisz `handleCreate(values)`: utwórz ticket `{ ...values, id, status: 'OPEN', priority: 'MEDIUM', assignee: null, createdAt: new Date().toISOString(), tags: [] }` i dopisz go na początek listy w stanie.
4. Przekaż `onCreate={handleCreate}` do formularza.
5. Wpisz tytuł, naciśnij Enter w polu tytułu — ticket pojawia się w tabeli, formularz się czyści, strona się nie przeładowuje.
6. Dodaj przycisk „Anuluj” z `type="button"` zamykający modal i sprawdź, że nie wysyła formularza.
7. Zakomentuj `e.preventDefault()` i zobacz pełne przeładowanie strony (utrata stanu). Przywróć.

#T PITFALL Przycisk bez typu wysyła formularz
```
<form onSubmit={handleSubmit}>
  <input name="tag" />
  <button onClick={addTag}>Dodaj tag</button>   {/* wysyła formularz! */}
  <button type="submit">Zapisz</button>
</form>
```

#T CODE_RIGHT Jawne typy przycisków
```
<form onSubmit={handleSubmit}>
  <input name="tag" />
  <button type="button" onClick={addTag}>Dodaj tag</button>
  <button type="submit">Zapisz</button>
</form>
```

#T WHEN_TO_USE onSubmit zamiast onClick na przycisku
Logikę wysłania podpinaj pod `onSubmit` formularza, a nie pod `onClick` przycisku. `onSubmit` obsługuje też Enter w polach tekstowych, współpracuje z walidacją HTML (`required`) i z czytnikami ekranu. `onClick` na przycisku „Zapisz” pomija Enter i wymaga ręcznego blokowania domyślnego działania.

#T SUMMARY Kryterium akceptacji i podsumowanie
Formularz obsługujesz przez `onSubmit` z `e.preventDefault()`. Stan formularza trzymasz w obiekcie, aktualizowanym jednym handlerem po atrybucie `name` (albo typowanym `setField`). Dane przekazujesz rodzicowi callbackiem i czyścisz formularz, ustawiając stan na pusty obiekt. Każdy przycisk w formularzu ma jawny `type`. W TSX: `FormEvent<HTMLFormElement>`, `ChangeEvent<HTMLInputElement | HTMLTextAreaElement>` i osobny typ wartości formularza.

Kryterium akceptacji: w modalu jest formularz z polami tytułu i opisu; Enter lub przycisk „Utwórz ticket” dodaje ticket na górze tabeli bez przeładowania strony; formularz czyści się po wysłaniu; „Anuluj” nie wysyła formularza.
