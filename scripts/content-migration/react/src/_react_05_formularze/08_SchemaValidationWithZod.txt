#T INTRO Rozgrzewka i problem: reguły walidacji w trzech miejscach
Rozgrzewka: Co robi `handleSubmit` w React Hook Form oprócz wywołania Twojej funkcji? Do czego służy `Controller`? Kiedy formularz jest „dirty”?

Problem: reguły ticketu są rozproszone: część w `register` (min. 5 znaków), część w typie TypeScript (priorytet z listy), a dane z API i z localStorage nie są sprawdzane wcale. Gdy zmieni się reguła, trzeba pamiętać o trzech miejscach. **Zod** pozwala zapisać reguły raz, jako schemat, i użyć go do walidacji formularza, sprawdzania danych z zewnątrz oraz — w TypeScripcie — do wyprowadzenia typu.

#T DEFINITION Schemat Zod
Schemat to opis danych, który potrafi je sprawdzić w czasie działania programu:
- `z.object({...})`, `z.string()`, `z.number()`, `z.boolean()`, `z.enum([...])`, `z.array(...)`, `z.nullable(...)`,
- reguły: `.min()`, `.max()`, `.trim()`, `.email()`, `.int()`, `.nonnegative()`, `.regex()`,
- komunikaty jako drugi argument: `z.string().min(5, 'Co najmniej 5 znaków.')`,
- reguły zależne od kilku pól: `.refine(fn, { message, path })` na obiekcie,
- `schema.parse(dane)` — zwraca dane albo rzuca błąd; `schema.safeParse(dane)` — zwraca `{ success, data }` albo `{ success: false, error }`.

Instalacja: `npm install zod`. Schemat jest zwykłym obiektem JavaScript — działa tak samo w `.js` i `.ts`.

#T CODE_JSX Schemat ticketu i walidacja danych (JSX)
```
// ticketSchema.js
import { z } from 'zod';

export const ticketFormSchema = z
  .object({
    title: z.string().trim().min(5, 'Tytuł musi mieć co najmniej 5 znaków.').max(120, 'Najwyżej 120 znaków.'),
    description: z.string().trim(),
    priority: z.enum(['LOW', 'MEDIUM', 'HIGH', 'CRITICAL']),
    assignee: z.string().nullable(),
  })
  .refine((t) => t.priority !== 'CRITICAL' || t.description.length > 0, {
    message: 'Ticket krytyczny wymaga opisu.',
    path: ['description'],
  });

// sprawdzenie danych spoza formularza, np. z localStorage
export function readDraft() {
  const raw = localStorage.getItem('ticket-draft');
  if (!raw) return null;
  const result = ticketFormSchema.safeParse(JSON.parse(raw));
  return result.success ? result.data : null;
}
```

#T CODE_TSX Schemat ticketu i typ wyprowadzony ze schematu (TSX)
`z.infer<typeof schema>` tworzy typ TypeScript ze schematu — reguła i typ mają jedno źródło. Po `safeParse` z `success: true` TypeScript zna kształt `result.data`.
```
// ticketSchema.ts
import { z } from 'zod';

export const ticketFormSchema = z
  .object({
    title: z.string().trim().min(5, 'Tytuł musi mieć co najmniej 5 znaków.').max(120, 'Najwyżej 120 znaków.'),
    description: z.string().trim(),
    priority: z.enum(['LOW', 'MEDIUM', 'HIGH', 'CRITICAL']),
    assignee: z.string().nullable(),
  })
  .refine((t) => t.priority !== 'CRITICAL' || t.description.length > 0, {
    message: 'Ticket krytyczny wymaga opisu.',
    path: ['description'],
  });

export type TicketFormValues = z.infer<typeof ticketFormSchema>;

export function readDraft(): TicketFormValues | null {
  const raw = localStorage.getItem('ticket-draft');
  if (!raw) return null;
  const result = ticketFormSchema.safeParse(JSON.parse(raw));
  return result.success ? result.data : null;
}
```

#T NOTE JSX ↔ TSX — schemat zastępuje typ
To jedna z lekcji, w których obie wersje zbliżają się do siebie. Zod daje walidację **w czasie działania**, więc wersja JSX dostaje ochronę, której wcześniej nie miała wcale — także dla danych z API, localStorage i adresu URL. W TSX zyskujesz dodatkowo `z.infer`: nie piszesz typu `TicketFormValues` ręcznie, więc typ i reguły nie mogą się rozjechać. Przypomnienie z rozdziału 01: typy TypeScript znikają po kompilacji i nie sprawdzą odpowiedzi serwera — schemat Zod tak.

#T DEFINITION Zod + React Hook Form: zodResolver
Pakiet `@hookform/resolvers` łączy obie biblioteki: `useForm({ resolver: zodResolver(schema) })`. Reguły znikają z `register` (zostaje samo `register('title')`), a komunikaty błędów pochodzą ze schematu. Instalacja: `npm install @hookform/resolvers`.

#T CODE_PRACTICAL Formularz ze schematem (TSX)
```
import { zodResolver } from '@hookform/resolvers/zod';
import { useForm } from 'react-hook-form';
import { ticketFormSchema, type TicketFormValues } from './ticketSchema';

export function SchemaTicketForm({ onCreate }: { onCreate: (values: TicketFormValues) => void }) {
  const { register, handleSubmit, formState: { errors } } = useForm<TicketFormValues>({
    resolver: zodResolver(ticketFormSchema),
    defaultValues: { title: '', description: '', priority: 'MEDIUM', assignee: null },
  });

  return (
    <form onSubmit={handleSubmit(onCreate)} noValidate>
      <label htmlFor="s-title">Tytuł</label>
      <input id="s-title" {...register('title')} aria-invalid={errors.title ? true : undefined} />
      {errors.title && <p role="alert">{errors.title.message}</p>}

      <label htmlFor="s-description">Opis</label>
      <textarea id="s-description" {...register('description')} />
      {errors.description && <p role="alert">{errors.description.message}</p>}

      <label htmlFor="s-priority">Priorytet</label>
      <select id="s-priority" {...register('priority')}>
        <option value="LOW">Niski</option>
        <option value="MEDIUM">Średni</option>
        <option value="HIGH">Wysoki</option>
        <option value="CRITICAL">Krytyczny</option>
      </select>
      <button type="submit">Utwórz</button>
    </form>
  );
}
```

#T CODE_BASIC Komunikaty błędów z safeParse
Gdy walidujesz bez React Hook Form, `z.flattenError` (Zod 4) zamienia błąd w obiekt „pole → lista komunikatów”.
```
import { z } from 'zod';

const loginSchema = z.object({
  email: z.email('Podaj poprawny adres e-mail.'),
  password: z.string().min(8, 'Hasło musi mieć co najmniej 8 znaków.'),
});

export function validateLogin(input: unknown) {
  const result = loginSchema.safeParse(input);
  if (result.success) return { data: result.data, errors: {} };
  return { data: null, errors: z.flattenError(result.error).fieldErrors };
}
```

#T STEP_BY_STEP Budujemy razem: jedno źródło reguł ticketu
1. Zainstaluj `zod` i `@hookform/resolvers`.
2. Utwórz `ticketSchema.js` (`.ts`) z regułami z poprzednich lekcji.
3. W wersji TS usuń ręczny typ `TicketFormValues` i zastąp go `z.infer`.
4. Podłącz `zodResolver` w `NewTicketForm`; usuń reguły z `register`.
5. Dodaj zapisywanie szkicu: w handlerze „Zapisz szkic” `localStorage.setItem('ticket-draft', JSON.stringify(getValues()))`, a przy otwarciu formularza `defaultValues: readDraft() ?? EMPTY`.
6. Ręcznie popsuj szkic w DevTools (Application → Local Storage), np. `priority: "PILNE"` — `readDraft` zwraca `null` i formularz startuje pusty, zamiast się wysypać.
7. Zmień regułę długości tytułu w jednym miejscu (schemat) i sprawdź, że zmienił się komunikat w formularzu.

#T PITFALL Ufanie danym z zewnątrz
`const draft = JSON.parse(localStorage.getItem('draft'))` i od razu `draft.title.trim()` — jeśli zapis jest stary, ręcznie zmieniony albo z innej wersji aplikacji, aplikacja się wysypie. W TSX rzutowanie `as TicketFormValues` tylko ukrywa problem. Dane z localStorage, API, adresu URL i od użytkownika zawsze przepuszczaj przez `safeParse`.

#T CODE_WRONG Rzutowanie zamiast walidacji
```
const draft = JSON.parse(localStorage.getItem('ticket-draft') ?? '{}') as TicketFormValues;
draft.title.trim(); // wybuchnie, jeśli w zapisie nie ma title
```

#T CODE_RIGHT Walidacja schematem
```
const parsed = ticketFormSchema.safeParse(JSON.parse(localStorage.getItem('ticket-draft') ?? '{}'));
const draft = parsed.success ? parsed.data : null;
```

#T SUMMARY Kryterium akceptacji i podsumowanie
Zod opisuje dane schematem, który sprawdza je w czasie działania: `parse` rzuca błąd, `safeParse` zwraca wynik z flagą `success`. Reguły zależne od kilku pól zapisujesz w `.refine` z `path`. Z React Hook Form łączysz go przez `zodResolver`. Dane z zewnątrz (localStorage, API, URL) zawsze waliduj schematem. W TSX `z.infer<typeof schema>` wyprowadza typ ze schematu — reguły i typ mają jedno źródło.

Kryterium akceptacji: reguły ticketu są tylko w schemacie, formularz pokazuje komunikaty ze schematu, szkic zapisuje się w localStorage, a uszkodzony szkic nie psuje aplikacji (formularz startuje pusty).
