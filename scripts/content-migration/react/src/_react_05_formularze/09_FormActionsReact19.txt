#T INTRO Rozgrzewka i problem: stan wysyłania pisany od nowa w każdym formularzu
Rozgrzewka: Co zwraca `safeParse`? Jak połączyć Zod z React Hook Form? Dlaczego danych z localStorage nie rzutujesz przez `as`?

Problem: każdy formularz wysyłający dane ma ten sam kod: stan „wysyłanie”, blokada przycisku, stan błędu z serwera, komunikat sukcesu. React 19 wprowadził **akcje formularzy** — wbudowany sposób obsługi wysyłania, który robi większość tej pracy. Poznasz `action` w elemencie `form`, hook `useActionState` i hook `useFormStatus`.

#T DEFINITION Akcja formularza
W React 19 do `<form>` możesz przekazać funkcję w atrybucie `action` (zamiast adresu URL): `<form action={createTicket}>`. Gdy formularz zostanie wysłany:
1. React wywołuje funkcję z obiektem `FormData` — bez `preventDefault`,
2. funkcja może być asynchroniczna — React traktuje jej wykonanie jako przejście (transition), więc interfejs pozostaje responsywny,
3. po pomyślnym zakończeniu akcji React **resetuje pola niekontrolowane** formularza.

Akcje naturalnie współpracują z polami niekontrolowanymi (`name`, `defaultValue`), które poznałeś w lekcji o `FormData`.

#T DEFINITION useActionState
`const [state, formAction, isPending] = useActionState(akcja, stanPoczątkowy)`:
- `akcja(poprzedniStan, formData)` — Twoja funkcja; to, co zwróci, staje się nowym `state` (np. `{ error: '...' }` albo `{ ok: true }`),
- `formAction` — przekazujesz do `<form action={formAction}>`,
- `isPending` — `true`, dopóki akcja się wykonuje.

Dzięki temu stan wyniku i stan oczekiwania masz bez ani jednego `useState`.

#T CODE_JSX Formularz komentarza z useActionState (JSX)
```
// CommentForm.jsx
import { useActionState } from 'react';

async function saveComment(text) {
  await new Promise((r) => setTimeout(r, 700));
  if (text.toLowerCase().includes('błąd')) throw new Error('Serwer odrzucił komentarz.');
}

export function CommentForm({ ticketId, onAdded }) {
  const [state, formAction, isPending] = useActionState(async (prev, formData) => {
    const text = String(formData.get('text') ?? '').trim();
    if (text.length < 3) return { error: 'Komentarz musi mieć co najmniej 3 znaki.' };
    try {
      await saveComment(text);
      onAdded(ticketId, text);
      return { error: null };
    } catch (e) {
      return { error: e.message };
    }
  }, { error: null });

  return (
    <form action={formAction}>
      <label htmlFor="comment">Komentarz</label>
      <textarea id="comment" name="text" rows={3} />
      {state.error && <p role="alert">{state.error}</p>}
      <button type="submit" disabled={isPending}>{isPending ? 'Wysyłanie…' : 'Dodaj komentarz'}</button>
    </form>
  );
}
```

#T CODE_TSX Formularz komentarza z useActionState (TSX)
Typ stanu akcji podajesz raz (`CommentState`); funkcja akcji musi zwracać ten typ. `e` w `catch` ma typ `unknown`, więc trzeba sprawdzić, czy to `Error`.
```
// CommentForm.tsx
import { useActionState } from 'react';

type CommentState = { error: string | null };

async function saveComment(text: string): Promise<void> {
  await new Promise((r) => setTimeout(r, 700));
  if (text.toLowerCase().includes('błąd')) throw new Error('Serwer odrzucił komentarz.');
}

type Props = { ticketId: number; onAdded: (ticketId: number, text: string) => void };

export function CommentForm({ ticketId, onAdded }: Props) {
  const [state, formAction, isPending] = useActionState(
    async (_prev: CommentState, formData: FormData): Promise<CommentState> => {
      const text = String(formData.get('text') ?? '').trim();
      if (text.length < 3) return { error: 'Komentarz musi mieć co najmniej 3 znaki.' };
      try {
        await saveComment(text);
        onAdded(ticketId, text);
        return { error: null };
      } catch (e) {
        return { error: e instanceof Error ? e.message : 'Nieznany błąd.' };
      }
    },
    { error: null },
  );

  return (
    <form action={formAction}>
      <label htmlFor="comment">Komentarz</label>
      <textarea id="comment" name="text" rows={3} />
      {state.error && <p role="alert">{state.error}</p>}
      <button type="submit" disabled={isPending}>{isPending ? 'Wysyłanie…' : 'Dodaj komentarz'}</button>
    </form>
  );
}
```

#T NOTE JSX ↔ TSX — typ stanu akcji i błąd w catch
Dwie różnice warte zapamiętania. Po pierwsze, w TSX funkcja akcji ma jawny typ wyniku `Promise<CommentState>` — gdyby jedna gałąź zwracała `{ message: '...' }` zamiast `{ error }`, kompilator to zgłosi; w JSX komponent wyświetliłby `undefined`. Po drugie, w `catch (e)` TypeScript traktuje `e` jako `unknown` (rzucić można cokolwiek, nie tylko `Error`), więc `e.message` wymaga sprawdzenia `e instanceof Error`. Wersja JSX zakłada, że to zawsze `Error` — zwykle słusznie, ale nie zawsze.

#T DEFINITION useFormStatus: stan formularza w komponencie-dziecku
`useFormStatus()` z pakietu `react-dom` zwraca `{ pending, data, method, action }` formularza, **wewnątrz którego** komponent jest wyrenderowany. Pozwala zrobić uniwersalny przycisk „Wyślij”, który sam wie, że formularz jest w trakcie wysyłania — bez przekazywania props. Ważne: hook musi być wywołany w komponencie-dziecku formularza, a nie w komponencie, który renderuje `<form>`.

#T CODE_BASIC Uniwersalny przycisk wysyłania
```
import { useFormStatus } from 'react-dom';

export function SubmitButton({ label, pendingLabel }: { label: string; pendingLabel: string }) {
  const { pending } = useFormStatus();
  return (
    <button type="submit" disabled={pending} aria-busy={pending}>
      {pending ? pendingLabel : label}
    </button>
  );
}

// <form action={formAction}> ... <SubmitButton label="Dodaj" pendingLabel="Wysyłanie…" /> </form>
```

#T CODE_PRACTICAL Walidacja schematem wewnątrz akcji
Akcja to dobre miejsce na `safeParse` danych z `FormData` — w obu wersjach dostajesz komunikaty per pole.
```
import { useActionState } from 'react';
import { z } from 'zod';

const schema = z.object({ title: z.string().trim().min(5, 'Co najmniej 5 znaków.') });
type State = { errors: { title?: string[] }; ok: boolean };

export function QuickTicketForm({ onCreate }: { onCreate: (title: string) => void }) {
  const [state, formAction] = useActionState(async (_prev: State, formData: FormData): Promise<State> => {
    const parsed = schema.safeParse({ title: formData.get('title') });
    if (!parsed.success) return { errors: z.flattenError(parsed.error).fieldErrors, ok: false };
    onCreate(parsed.data.title);
    return { errors: {}, ok: true };
  }, { errors: {}, ok: false });

  return (
    <form action={formAction}>
      <input name="title" aria-label="Tytuł" />
      {state.errors.title?.map((m) => <p key={m} role="alert">{m}</p>)}
      {state.ok && <p role="status">Dodano.</p>}
      <button type="submit">Dodaj</button>
    </form>
  );
}
```

#T STEP_BY_STEP Budujemy razem: komentarze do ticketu
1. Dodaj do typu `Ticket` pole `comments: { id: number; text: string; createdAt: string }[]` (w TS kompilator pokaże dane do uzupełnienia; w JS dopisz pustą tablicę w danych).
2. W karcie szczegółów wyświetl listę komentarzy wybranego ticketu.
3. Dodaj `CommentForm` z `useActionState`; `onAdded` w `Main` dopisuje komentarz niemutowalnie.
4. Zastąp przycisk komponentem `SubmitButton` z `useFormStatus`.
5. Wyślij komentarz zawierający słowo „błąd” — zobaczysz komunikat z akcji, ale pole jest PUSTE. Akcja zakończyła się bez wyjątku (zwróciła stan z błędem), więc React uznał ją za udaną i zresetował pola niekontrolowane. Popraw to: zwracaj w stanie także wpisany tekst (`return { error, text }`) i ustaw `defaultValue={state.text}` na polu z `key={state.text}`, żeby pole pokazało tekst po resecie.
6. Wyślij poprawny komentarz — pole czyści się automatycznie po zakończeniu akcji.
7. Kliknij szybko kilka razy „Dodaj” — przycisk jest zablokowany podczas wysyłania.

#T PITFALL useFormStatus w złym komponencie
Wywołanie `useFormStatus()` w tym samym komponencie, który renderuje `<form>`, zawsze zwróci `pending: false` — hook odczytuje stan formularza-rodzica, a ten komponent nie jest wewnątrz formularza, tylko go tworzy. Przenieś przycisk do osobnego komponentu wyrenderowanego w środku `<form>`.

#T PITFALL Reset pól po błędzie walidacji
Automatyczny reset pól niekontrolowanych następuje po każdym zakończeniu akcji, które nie rzuciło wyjątku — także wtedy, gdy akcja zwróciła stan z komunikatem błędu. Użytkownik widzi „Komentarz musi mieć co najmniej 3 znaki” i pusty formularz. Jeśli chcesz zachować wpisane dane, zwracaj je w stanie akcji i podawaj jako `defaultValue` (z `key` wymuszającym nowe pole), albo użyj pól kontrolowanych.

#T WHEN_TO_USE Akcje, React Hook Form czy ręcznie
Akcje React 19: proste i średnie formularze z polami niekontrolowanymi, wysyłanie na serwer, komponenty serwerowe w frameworkach (rozdział 18) — akcje działają tam także bez JavaScriptu w przeglądarce. React Hook Form: rozbudowana walidacja na żywo, dynamiczne listy pól, formularze wieloetapowe, integracja z bibliotekami UI. Oba podejścia można łączyć ze schematem Zod. Ręczny kontrolowany formularz: gdy UI zależy od każdego znaku.

#T SUMMARY Kryterium akceptacji i podsumowanie
W React 19 `<form action={fn}>` wywołuje funkcję z `FormData`, bez `preventDefault`, a po sukcesie resetuje pola niekontrolowane. `useActionState(akcja, start)` zwraca `[stan, formAction, isPending]`; akcja dostaje poprzedni stan i `FormData`, a zwraca nowy stan (np. błędy). `useFormStatus()` (z `react-dom`) daje `pending` w komponencie wewnątrz formularza. W TSX typujesz stan akcji i obsługujesz `e: unknown` w `catch`.

Kryterium akceptacji: w karcie ticketu można dodawać komentarze formularzem z akcją; podczas wysyłania przycisk jest zablokowany i pokazuje „Wysyłanie…”; błąd serwera i za krótki tekst pokazują komunikat; po sukcesie pole się czyści, a komentarz pojawia się na liście.
