#T INTRO Rozgrzewka i problem: ticket to więcej niż tytuł
Rozgrzewka: Dlaczego w `onSubmit` wywołujesz `preventDefault()`? Jaki typ ma przycisk w formularzu bez atrybutu `type`? Jak jeden handler obsługuje wiele pól?

Problem: nowy ticket potrzebuje priorytetu (lista), osoby przypisanej (lista z opcją „nikt”), typu zgłoszenia (przyciski radio), flagi „Zgłoszenie klienta” (checkbox), tagów (kilka checkboxów) i szacowanego czasu w godzinach (liczba). Każdy typ pola zachowuje się w React trochę inaczej — ta lekcja zbiera wszystkie różnice w jednym miejscu.

#T API_REFERENCE Pola formularza w React — ściąga
- `<input type="text">`, `email`, `search`, `password`, `textarea` → `value` + `onChange`, wartość to `e.target.value` (string),
- `<input type="number">` → `value` (string lub liczba) + konwersja `Number(e.target.value)` lub `e.target.valueAsNumber`; pusty tekst daje `0` z `Number` i `NaN` z `valueAsNumber` — obsłuż jawnie,
- `<input type="checkbox">` → **`checked`** + `onChange`, wartość to `e.target.checked` (boolean),
- `<input type="radio">` → `checked={value === 'BUG'}` dla każdej opcji, wspólne `name`, wartość z `e.target.value`,
- `<select>` → `value` na elemencie `select` (nie `selected` na `option`!), wartość z `e.target.value`,
- `<select multiple>` → `value` jako tablica, odczyt: `Array.from(e.target.selectedOptions, (o) => o.value)`,
- `<textarea>` → `value` jako atrybut (w HTML treść jest między tagami, w React — w `value`),
- `<input type="date">` → wartość w formacie `RRRR-MM-DD` jako tekst.

#T CODE_JSX Pełny formularz ticketu (JSX)
```
// TicketFields.jsx
const PEOPLE = ['anna', 'piotr', 'kasia'];
const TAGS = ['api', 'ui', 'export', 'auth'];

export function TicketFields({ form, setForm }) {
  const set = (key, value) => setForm((prev) => ({ ...prev, [key]: value }));

  function toggleTag(tag) {
    set('tags', form.tags.includes(tag) ? form.tags.filter((t) => t !== tag) : [...form.tags, tag]);
  }

  return (
    <>
      <label htmlFor="priority">Priorytet</label>
      <select id="priority" value={form.priority} onChange={(e) => set('priority', e.target.value)}>
        <option value="LOW">Niski</option>
        <option value="MEDIUM">Średni</option>
        <option value="HIGH">Wysoki</option>
        <option value="CRITICAL">Krytyczny</option>
      </select>

      <label htmlFor="assignee">Osoba</label>
      <select id="assignee" value={form.assignee ?? ''} onChange={(e) => set('assignee', e.target.value || null)}>
        <option value="">— nikt —</option>
        {PEOPLE.map((p) => <option key={p} value={p}>{p}</option>)}
      </select>

      <fieldset>
        <legend>Typ zgłoszenia</legend>
        {['BUG', 'TASK', 'QUESTION'].map((kind) => (
          <label key={kind}>
            <input type="radio" name="kind" value={kind} checked={form.kind === kind} onChange={(e) => set('kind', e.target.value)} />
            {kind}
          </label>
        ))}
      </fieldset>

      <label>
        <input type="checkbox" checked={form.fromCustomer} onChange={(e) => set('fromCustomer', e.target.checked)} />
        Zgłoszenie klienta
      </label>

      <fieldset>
        <legend>Tagi</legend>
        {TAGS.map((tag) => (
          <label key={tag}>
            <input type="checkbox" checked={form.tags.includes(tag)} onChange={() => toggleTag(tag)} />
            {tag}
          </label>
        ))}
      </fieldset>

      <label htmlFor="estimate">Szacowany czas (h)</label>
      <input id="estimate" type="number" min={0} step={0.5} value={form.estimateHours}
        onChange={(e) => set('estimateHours', e.target.value === '' ? '' : Number(e.target.value))} />
    </>
  );
}
```

#T CODE_TSX Pełny formularz ticketu (TSX)
Typ modelu formularza opisuje każde pole. `set` jest generyczne, więc `set('fromCustomer', 'tak')` to błąd. Wartości z `select` i `radio` rzutujesz na unie, bo opcje są pod kontrolą komponentu.
```
// TicketFields.tsx
import type { Dispatch, SetStateAction } from 'react';
import type { TicketPriority } from '../types';

export type TicketKind = 'BUG' | 'TASK' | 'QUESTION';

export type TicketFormValues = {
  title: string;
  priority: TicketPriority;
  assignee: string | null;
  kind: TicketKind;
  fromCustomer: boolean;
  tags: string[];
  estimateHours: number | '';
};

const PEOPLE = ['anna', 'piotr', 'kasia'];
const TAGS = ['api', 'ui', 'export', 'auth'];
const KINDS: TicketKind[] = ['BUG', 'TASK', 'QUESTION'];

type Props = { form: TicketFormValues; setForm: Dispatch<SetStateAction<TicketFormValues>> };

export function TicketFields({ form, setForm }: Props) {
  const set = <K extends keyof TicketFormValues>(key: K, value: TicketFormValues[K]) =>
    setForm((prev) => ({ ...prev, [key]: value }));

  function toggleTag(tag: string) {
    set('tags', form.tags.includes(tag) ? form.tags.filter((t) => t !== tag) : [...form.tags, tag]);
  }

  return (
    <>
      <label htmlFor="priority">Priorytet</label>
      <select id="priority" value={form.priority} onChange={(e) => set('priority', e.target.value as TicketPriority)}>
        <option value="LOW">Niski</option>
        <option value="MEDIUM">Średni</option>
        <option value="HIGH">Wysoki</option>
        <option value="CRITICAL">Krytyczny</option>
      </select>

      <label htmlFor="assignee">Osoba</label>
      <select id="assignee" value={form.assignee ?? ''} onChange={(e) => set('assignee', e.target.value || null)}>
        <option value="">— nikt —</option>
        {PEOPLE.map((p) => <option key={p} value={p}>{p}</option>)}
      </select>

      <fieldset>
        <legend>Typ zgłoszenia</legend>
        {KINDS.map((kind) => (
          <label key={kind}>
            <input type="radio" name="kind" value={kind} checked={form.kind === kind} onChange={() => set('kind', kind)} />
            {kind}
          </label>
        ))}
      </fieldset>

      <label>
        <input type="checkbox" checked={form.fromCustomer} onChange={(e) => set('fromCustomer', e.target.checked)} />
        Zgłoszenie klienta
      </label>

      <fieldset>
        <legend>Tagi</legend>
        {TAGS.map((tag) => (
          <label key={tag}>
            <input type="checkbox" checked={form.tags.includes(tag)} onChange={() => toggleTag(tag)} />
            {tag}
          </label>
        ))}
      </fieldset>

      <label htmlFor="estimate">Szacowany czas (h)</label>
      <input id="estimate" type="number" min={0} step={0.5} value={form.estimateHours}
        onChange={(e) => set('estimateHours', e.target.value === '' ? '' : Number(e.target.value))} />
    </>
  );
}
```

#T NOTE JSX ↔ TSX — typy wartości pól
Najważniejsze różnice: w TSX `estimateHours: number | ''` wymusza świadomą obsługę pustego pola liczbowego (w JSX łatwo zapisać tekst „3” i potem dodawać teksty). `assignee: string | null` wymusza zamianę pustej opcji na `null`. Radio w TSX ustawia wartość z tablicy `KINDS` (typ `TicketKind`), więc nie trzeba rzutować `e.target.value`. Przekazywany setter ma typ `Dispatch<SetStateAction<TicketFormValues>>` — taki sam, jaki zwraca `useState`.

#T DEFINITION Etykiety i grupy pól
Każde pole potrzebuje etykiety: `<label htmlFor="id">` z pasującym `id` pola albo pole umieszczone wewnątrz `<label>`. Kliknięcie etykiety przenosi fokus (lub zaznacza checkbox), a czytnik ekranu odczytuje nazwę pola. Grupy radio i checkboxów opakowuj w `<fieldset>` z `<legend>` — legenda jest nazwą całej grupy („Typ zgłoszenia”).

#T CODE_WRONG checked jako value i selected na option
```
<input type="checkbox" value={form.fromCustomer} onChange={(e) => set('fromCustomer', e.target.value)} />
<select>
  <option value="HIGH" selected={form.priority === 'HIGH'}>Wysoki</option>
</select>
```

#T CODE_RIGHT checked dla checkboxa, value na select
```
<input type="checkbox" checked={form.fromCustomer} onChange={(e) => set('fromCustomer', e.target.checked)} />
<select value={form.priority} onChange={(e) => set('priority', e.target.value)}>
  <option value="HIGH">Wysoki</option>
</select>
```

#T STEP_BY_STEP Budujemy razem: kompletny formularz ticketu
1. Rozszerz model formularza o pola z tej lekcji; ustal wartości domyślne (priorytet `MEDIUM`, typ `TASK`, `assignee: null`, `tags: []`, `estimateHours: ''`).
2. Utwórz `TicketFields` i użyj go w `NewTicketForm` pod polami tytułu i opisu.
3. W `handleCreate` przenieś priorytet, osobę i tagi do nowego ticketu; `kind`, `fromCustomer` i `estimateHours` dopisz do typu `Ticket` jako nowe pola (w TS zaktualizuj `types.ts` — kompilator pokaże miejsca do uzupełnienia, np. dane testowe).
4. Tymczasowo wyświetl pod formularzem `<pre>{JSON.stringify(form, null, 2)}</pre>` i obserwuj stan przy każdym kliknięciu.
5. Sprawdź puste pole czasu: po wyczyszczeniu w stanie jest `''`, a nie `0`.
6. Sprawdź klawiaturą: strzałki przełączają radio w grupie, Spacja zaznacza checkbox, etykiety są klikalne.

#T PITFALL Wartość liczby z pustego pola
`Number('')` daje `0`. Jeśli użytkownik wyczyści pole „Szacowany czas”, a Ty zapiszesz `0`, nie odróżnisz „zero godzin” od „nie podano”. Trzymaj pusty tekst lub `null` dla braku wartości i konwertuj dopiero przy zapisie.

#T SUMMARY Kryterium akceptacji i podsumowanie
Checkbox używa `checked` i `e.target.checked`, radio — `checked` porównującego wartość i wspólnego `name`, `select` — `value` na elemencie `select`, `textarea` — atrybutu `value`. Wartość z pól tekstowych i liczbowych to tekst — konwertuj świadomie, obsługując pustą wartość. Grupy pól w `fieldset` z `legend`, każde pole z etykietą. W TSX: model formularza z unią dla pól wyboru, `number | ''` dla liczb i generyczny `set`.

Kryterium akceptacji: formularz ticketu obsługuje priorytet, osobę (z opcją „nikt” zapisywaną jako `null`), typ, flagę klienta, tagi i czas; wszystkie pola aktualizują jeden obiekt stanu, a nowy ticket ma te dane w tabeli.
