#T INTRO Boss rozdziału 05: formularz rejestracji
Formularze rejestracji to klasyczny sprawdzian: kilka typów pól, reguły zależne od siebie (hasło i jego powtórzenie), sprawdzanie dostępności loginu, zgody, dostępność dla czytników ekranu i dobra obsługa błędów. Budujesz go samodzielnie, w wybranym podejściu (ręcznie, React Hook Form lub akcje React 19) — z jednym wymogiem: reguły w schemacie Zod.

#T DEFINITION Brief zadania
Formularz „Załóż konto w DevDesk”:
1. **Login** — wymagany, 3–20 znaków, tylko małe litery, cyfry i `-`; sprawdzenie dostępności (symulowane: zajęte są `anna`, `piotr`, `admin`).
2. **E-mail** — wymagany, poprawny format.
3. **Hasło** — co najmniej 10 znaków, przynajmniej jedna cyfra i jedna wielka litera; wskaźnik siły hasła (słabe / średnie / silne) liczony na bieżąco.
4. **Powtórz hasło** — musi być identyczne z hasłem (komunikat przy polu „Powtórz hasło”).
5. **Rola** — radio: „Agent”, „Obserwator”.
6. **Zespół** — lista rozwijana, wymagana tylko dla roli „Agent”.
7. **Zgoda na regulamin** — wymagany checkbox.
8. Po wysłaniu: symulowane opóźnienie 1 s, przycisk w stanie „Tworzenie konta…”, potem ekran „Witaj, {login}!” zamiast formularza.

#T STEP_BY_STEP Kryteria akceptacji
1. Wszystkie reguły są w jednym schemacie Zod (z `.refine` dla hasła i zespołu).
2. Błędy pojawiają się po opuszczeniu pola lub po próbie wysłania i znikają po poprawieniu.
3. Każde pole ma etykietę; błędne pole ma `aria-invalid` i komunikat połączony przez `aria-describedby`; grupa radio jest w `fieldset` z `legend`.
4. Po nieudanym wysłaniu fokus trafia na pierwsze błędne pole.
5. Wskaźnik siły hasła jest wartością wyliczaną z hasła, a nie osobnym stanem.
6. Pole „Zespół” jest widoczne tylko dla roli „Agent”; po zmianie roli na „Obserwator” błąd zespołu znika.
7. Podczas wysyłania przycisk jest zablokowany, a ponowne kliknięcie nie wysyła drugi raz.
8. Zajęty login daje komunikat przy polu login (błąd „z serwera” po wysłaniu).
9. W wersji TSX typ danych formularza pochodzi z `z.infer`, a `npm run build` przechodzi.

#T CODE_JSX Schemat i symulowany serwer (JSX)
Punkt startowy — możesz go zmienić.
```
// registerSchema.js
import { z } from 'zod';

export const registerSchema = z
  .object({
    login: z.string().regex(/^[a-z0-9-]{3,20}$/, 'Login: 3–20 znaków, małe litery, cyfry i myślnik.'),
    email: z.email('Podaj poprawny e-mail.'),
    password: z.string().min(10, 'Co najmniej 10 znaków.')
      .regex(/[0-9]/, 'Hasło musi zawierać cyfrę.')
      .regex(/[A-Z]/, 'Hasło musi zawierać wielką literę.'),
    confirmPassword: z.string(),
    role: z.enum(['agent', 'viewer']),
    team: z.string(),
    terms: z.boolean().refine((v) => v, 'Musisz zaakceptować regulamin.'),
  })
  .refine((d) => d.password === d.confirmPassword, { message: 'Hasła muszą być identyczne.', path: ['confirmPassword'] })
  .refine((d) => d.role !== 'agent' || d.team !== '', { message: 'Wybierz zespół.', path: ['team'] });

const TAKEN = ['anna', 'piotr', 'admin'];

export async function registerOnServer(login) {
  await new Promise((r) => setTimeout(r, 1000));
  if (TAKEN.includes(login)) return { ok: false, field: 'login', message: 'Ten login jest zajęty.' };
  return { ok: true };
}
```

#T CODE_TSX Schemat i symulowany serwer (TSX)
```
// registerSchema.ts
import { z } from 'zod';

export const registerSchema = z
  .object({
    login: z.string().regex(/^[a-z0-9-]{3,20}$/, 'Login: 3–20 znaków, małe litery, cyfry i myślnik.'),
    email: z.email('Podaj poprawny e-mail.'),
    password: z.string().min(10, 'Co najmniej 10 znaków.')
      .regex(/[0-9]/, 'Hasło musi zawierać cyfrę.')
      .regex(/[A-Z]/, 'Hasło musi zawierać wielką literę.'),
    confirmPassword: z.string(),
    role: z.enum(['agent', 'viewer']),
    team: z.string(),
    terms: z.boolean().refine((v) => v, 'Musisz zaakceptować regulamin.'),
  })
  .refine((d) => d.password === d.confirmPassword, { message: 'Hasła muszą być identyczne.', path: ['confirmPassword'] })
  .refine((d) => d.role !== 'agent' || d.team !== '', { message: 'Wybierz zespół.', path: ['team'] });

export type RegisterValues = z.infer<typeof registerSchema>;

type ServerResult = { ok: true } | { ok: false; field: keyof RegisterValues; message: string };

const TAKEN = ['anna', 'piotr', 'admin'];

export async function registerOnServer(login: string): Promise<ServerResult> {
  await new Promise((r) => setTimeout(r, 1000));
  if (TAKEN.includes(login)) return { ok: false, field: 'login', message: 'Ten login jest zajęty.' };
  return { ok: true };
}
```

#T NOTE Wskazówka 1 — siła hasła jako dane wyliczane
Napisz czystą funkcję `passwordStrength(pw)` zwracającą `'weak' | 'medium' | 'strong'` (np. punkty za długość ≥ 10, ≥ 14, cyfrę, wielką literę, znak specjalny). W React Hook Form odczytasz bieżące hasło przez `watch('password')`, w formularzu ręcznym — ze stanu. Wynik wyświetl z `aria-live="polite"`, żeby czytnik ekranu ogłaszał zmianę.

#T NOTE Wskazówka 2 — błąd z serwera przy polu
W React Hook Form: `const result = await registerOnServer(values.login); if (!result.ok) setError(result.field, { message: result.message });` — błąd trafi do `errors.login` jak każdy inny, a `setFocus('login')` przeniesie fokus. W akcjach React 19: zwróć błąd w stanie akcji (`{ fieldErrors: { login: [...] } }`). W wersji TSX unia `ServerResult` wymusza sprawdzenie `ok` przed odczytem `field`.

#T NOTE Wskazówka 3 — pole warunkowe
Pole „Zespół” renderuj warunkowo na podstawie roli (`watch('role') === 'agent'`). Reguła w `.refine` sprawdza zespół tylko dla agenta, więc po przełączeniu na obserwatora walidacja przejdzie. Jeśli używasz React Hook Form, rozważ opcję `shouldUnregister: true` dla tego pola albo jawne `setValue('team', '')` przy zmianie roli — zastanów się, które zachowanie jest lepsze dla użytkownika.

#T PITFALL Typowe błędy w tym zadaniu
- Komunikat o niezgodnych hasłach przypięty do całego formularza zamiast do pola „Powtórz hasło” — brak `path` w `.refine`.
- Siła hasła w `useState` aktualizowanym w `useEffect` — to dane wyliczane.
- Podwójne konto po dwóch szybkich kliknięciach — brak blokady przycisku podczas wysyłania.
- `<input type="checkbox" value={terms}>` zamiast `checked` (albo `register('terms')`, które obsługuje checkbox poprawnie).
- Komunikat „Hasło musi zawierać cyfrę” ukryty, bo pokazujesz tylko pierwszy błąd pola — zdecyduj świadomie, czy wyświetlasz jeden, czy wszystkie.

#T SUMMARY Podsumowanie rozdziału 05
W tym rozdziale zbudowałeś formularze kontrolowane i niekontrolowane, obsłużyłeś wszystkie typy pól, zaprojektowałeś walidację z dostępnymi komunikatami, uporządkowałeś wysyłanie i reset, rozwiązałeś problem formularza edycji przez `key`, poznałeś React Hook Form, schematy Zod i akcje formularzy React 19. W TSX: typy zdarzeń formularza, typy wartości wyprowadzane z rekordu, `useForm<T>`, `z.infer` i typowany stan akcji.

Boss zaliczony, gdy wszystkie dziewięć kryteriów akceptacji jest spełnionych, a formularz da się wypełnić i wysłać wyłącznie klawiaturą.
