#T INTRO Rozgrzewka i problem: co dokładnie dzieje się po kliknięciu „Utwórz”
Rozgrzewka: Kiedy pokazujesz błąd pola? Dlaczego błędy walidacji nie są stanem? Do czego służy `aria-describedby`?

Problem: formularz działa, ale kod wysyłania rozrósł się: tworzenie ID, ustawianie daty, domyślnego statusu, dopisanie do listy, zamknięcie modala, wyczyszczenie formularza, zaznaczenie nowego ticketu, komunikat „Utworzono #57”. Część z tego jest w formularzu, część w `Main`, a jedna rzecz wylądowała w `useEffect`. Ta lekcja porządkuje odpowiedzialności: co robi formularz, co rodzic i gdzie wykonać każdą operację.

#T DEFINITION Logika zdarzenia należy do handlera
Wszystko, co jest **skutkiem kliknięcia „Utwórz”**, wykonujesz w handlerze tego zdarzenia: budowę rekordu, aktualizację listy, zamknięcie modala, komunikat. Nie w renderze (byłoby wykonywane przy każdym renderze) i nie w `useEffect` reagującym na zmianę stanu (efekt nie wie, *dlaczego* stan się zmienił — czy po kliknięciu, czy po wczytaniu danych).

Podział odpowiedzialności:
- **formularz** — zbiera i waliduje dane, informuje rodzica o poprawnym wysłaniu (`onSubmit(values)`), czyści się,
- **rodzic** — zamienia wartości formularza w rekord (ID, data, status), zapisuje go i decyduje o dalszych krokach (zamknąć modal, zaznaczyć ticket, pokazać komunikat).

#T CODE_JSX Tworzenie ticketu w rodzicu (JSX)
```
// Main.jsx
import { useState } from 'react';
import { tickets as initial } from '../data/tickets';

function buildTicket(values, existing) {
  const nextId = existing.reduce((max, t) => Math.max(max, t.id), 0) + 1;
  return {
    ...values,
    title: values.title.trim(),
    id: nextId,
    status: 'OPEN',
    createdAt: new Date().toISOString(),
    tags: values.tags ?? [],
  };
}

export function useTicketCreation() {
  const [tickets, setTickets] = useState(initial);
  const [selectedId, setSelectedId] = useState(null);
  const [dialogOpen, setDialogOpen] = useState(false);
  const [notice, setNotice] = useState(null);

  function handleCreate(values) {
    const ticket = buildTicket(values, tickets);
    setTickets((prev) => [ticket, ...prev]);
    setSelectedId(ticket.id);
    setDialogOpen(false);
    setNotice(`Utworzono ticket #${ticket.id}`);
  }

  return { tickets, selectedId, dialogOpen, setDialogOpen, notice, handleCreate };
}
```

#T CODE_TSX Tworzenie ticketu w rodzicu (TSX)
`buildTicket` przyjmuje wartości formularza i zwraca pełny `Ticket` — TypeScript sprawdzi, że żadne wymagane pole nie zostało pominięte.
```
// Main.tsx
import { useState } from 'react';
import { tickets as initial } from '../data/tickets';
import type { Ticket } from '../types';

export type NewTicketValues = Pick<Ticket, 'title' | 'description' | 'priority' | 'assignee'> & { tags?: string[] };

function buildTicket(values: NewTicketValues, existing: readonly Ticket[]): Ticket {
  const nextId = existing.reduce((max, t) => Math.max(max, t.id), 0) + 1;
  return {
    ...values,
    title: values.title.trim(),
    id: nextId,
    status: 'OPEN',
    createdAt: new Date().toISOString(),
    tags: values.tags ?? [],
  };
}

export function useTicketCreation() {
  const [tickets, setTickets] = useState(initial);
  const [selectedId, setSelectedId] = useState<number | null>(null);
  const [dialogOpen, setDialogOpen] = useState(false);
  const [notice, setNotice] = useState<string | null>(null);

  function handleCreate(values: NewTicketValues) {
    const ticket = buildTicket(values, tickets);
    setTickets((prev) => [ticket, ...prev]);
    setSelectedId(ticket.id);
    setDialogOpen(false);
    setNotice(`Utworzono ticket #${ticket.id}`);
  }

  return { tickets, selectedId, dialogOpen, setDialogOpen, notice, handleCreate };
}
```

#T NOTE JSX ↔ TSX — typ wartości formularza a typ rekordu
`NewTicketValues = Pick<Ticket, ...>` wyprowadza typ formularza z typu rekordu: gdy zmienisz typ pola `priority` w `Ticket`, formularz automatycznie dostanie nowy typ. Funkcja `buildTicket(...): Ticket` to jedyne miejsce, gdzie z wartości formularza powstaje rekord — jeśli dodasz do `Ticket` nowe wymagane pole, kompilator wskaże dokładnie tę funkcję. W JSX to samo miejsce musisz znaleźć sam, zanim zgłosi się użytkownik z ticketem bez pola `status`.

#T DEFINITION Reset formularza
Formularz kontrolowany resetujesz, ustawiając stan na wartości początkowe (`setValues(INITIAL)` i wyzerowanie `touched`/`submitted`). Jeśli formularz jest w modalu, który się zamyka, często nie musisz robić nic: zamknięcie odmontowuje formularz, a ponowne otwarcie montuje go od nowa z pustym stanem. Formularz niekontrolowany resetujesz przez `form.reset()`.

#T CODE_WRONG Reakcja na wysłanie w efekcie
Efekt uruchamia się też przy wczytaniu danych, przy cofnięciu zmian i przy każdej innej zmianie listy — komunikat „Utworzono” pojawi się w złych momentach.
```
useEffect(() => {
  if (tickets.length > previousLength) {
    setNotice('Utworzono nowy ticket');
    setDialogOpen(false);
  }
}, [tickets]);
```

#T CODE_RIGHT Reakcja w handlerze zdarzenia
```
function handleCreate(values) {
  const ticket = buildTicket(values, tickets);
  setTickets((prev) => [ticket, ...prev]);
  setDialogOpen(false);
  setNotice(`Utworzono ticket #${ticket.id}`);
}
```

#T CODE_PRACTICAL Komunikat, który można zamknąć
```
export function Notice({ text, onDismiss }: { text: string | null; onDismiss: () => void }) {
  if (!text) return null;
  return (
    <div className="notice" role="status">
      {text}
      <button type="button" onClick={onDismiss} aria-label="Zamknij komunikat">✕</button>
    </div>
  );
}
```

#T STEP_BY_STEP Budujemy razem: kompletny przepływ tworzenia
1. Przenieś budowę rekordu do funkcji `buildTicket` w `Main` (lub w `utils/tickets`).
2. W `handleCreate` dodaj ticket, zaznacz go, zamknij modal i ustaw komunikat.
3. Formularz po poprawnym wysłaniu wywołuje `onCreate` i resetuje swój stan (wartości, `touched`, `submitted`).
4. Dodaj komponent `Notice` nad tabelą; przycisk ✕ czyści komunikat.
5. Sprawdź przepływ: otwórz modal, wpisz błędny tytuł (komunikat błędu), popraw, wyślij — modal się zamyka, nowy ticket jest na górze i zaznaczony, karta szczegółów go pokazuje, pojawia się „Utworzono ticket #N”.
6. Otwórz modal ponownie — formularz jest pusty.
7. Upewnij się, że w kodzie nie ma `useEffect` reagującego na dodanie ticketu.

#T PITFALL Generowanie ID w renderze formularza
`const id = Date.now()` w ciele komponentu formularza daje nowe ID przy każdym renderze i nie wiadomo, które trafi do rekordu. ID (i datę utworzenia) generujesz w handlerze, w chwili tworzenia rekordu — raz. W prawdziwej aplikacji ID nada serwer (rozdział 10).

#T SUMMARY Kryterium akceptacji i podsumowanie
Skutki wysłania formularza wykonujesz w handlerze zdarzenia, nie w renderze i nie w efekcie. Formularz zbiera i waliduje dane, a rodzic buduje rekord, zapisuje go i decyduje o kolejnych krokach. Reset to ustawienie stanu na wartości początkowe (lub odmontowanie formularza). W TSX typ wartości formularza wyprowadzasz z typu rekordu (`Pick`/`Omit`), a funkcja budująca rekord zwraca pełny typ.

Kryterium akceptacji: utworzenie ticketu zamyka modal, dodaje rekord na górze tabeli, zaznacza go i pokazuje zamykany komunikat; ponowne otwarcie modala daje pusty formularz; nie ma efektu reagującego na dodanie ticketu.
