#T INTRO Rozgrzewka i problem: formularze z dwudziestoma polami
Rozgrzewka: Dlaczego bez `key` formularz edycji pokazuje stary ticket? Czym jest „pozycja w drzewie”? Dlaczego nie synchronizujesz stanu z props efektem?

Problem: ręcznie napisany formularz ticketu ma już stan wartości, `touched`, `submitted`, funkcję walidacji, obsługę fokusu na pierwszym błędzie i reset. Kolejny formularz (ustawienia użytkownika, 20 pól) wymagałby powtórzenia wszystkiego. **React Hook Form** to najpopularniejsza biblioteka formularzy w React — robi to wszystko i jest bardzo wydajna, bo domyślnie używa pól niekontrolowanych.

#T DEFINITION React Hook Form w pigułce
Hook `useForm()` zwraca narzędzia formularza:
- `register('nazwa', reguły)` — podłącza pole (zwraca `name`, `ref`, `onChange`, `onBlur` do rozłożenia na input przez spread),
- `handleSubmit(onValid)` — opakowuje funkcję wysyłania: najpierw waliduje, wywołuje `onValid(dane)` tylko dla poprawnych danych i ustawia fokus na pierwszym błędnym polu,
- `formState: { errors, isSubmitting, isDirty, isValid }` — stan formularza,
- `reset(wartości?)` — przywraca wartości (np. po zapisie albo dla innego rekordu),
- `watch('pole')` — odczyt wartości na bieżąco (gdy UI zależy od pola),
- `setValue`, `setError`, `trigger` — sterowanie z kodu.

Reguły walidacji w `register`: `required`, `minLength`, `maxLength`, `min`, `max`, `pattern`, `validate` (własna funkcja). Komunikat podajesz jako tekst lub `{ value, message }`. Instalacja: `npm install react-hook-form`.

#T CODE_JSX Formularz ticketu z React Hook Form (JSX)
```
// NewTicketForm.jsx
import { useForm } from 'react-hook-form';

export function NewTicketForm({ onCreate }) {
  const { register, handleSubmit, reset, formState: { errors, isSubmitting } } = useForm({
    defaultValues: { title: '', description: '', priority: 'MEDIUM', estimateHours: '' },
  });

  async function onValid(values) {
    await onCreate(values);
    reset();
  }

  return (
    <form onSubmit={handleSubmit(onValid)} noValidate>
      <label htmlFor="title">Tytuł</label>
      <input
        id="title"
        aria-invalid={errors.title ? true : undefined}
        {...register('title', {
          required: 'Tytuł jest wymagany.',
          minLength: { value: 5, message: 'Co najmniej 5 znaków.' },
        })}
      />
      {errors.title && <p role="alert">{errors.title.message}</p>}

      <label htmlFor="priority">Priorytet</label>
      <select id="priority" {...register('priority')}>
        <option value="LOW">Niski</option>
        <option value="MEDIUM">Średni</option>
        <option value="HIGH">Wysoki</option>
        <option value="CRITICAL">Krytyczny</option>
      </select>

      <label htmlFor="estimate">Szacowany czas (h)</label>
      <input id="estimate" type="number" {...register('estimateHours', { min: { value: 0, message: 'Nie może być ujemny.' } })} />
      {errors.estimateHours && <p role="alert">{errors.estimateHours.message}</p>}

      <button type="submit" disabled={isSubmitting}>{isSubmitting ? 'Zapisywanie…' : 'Utwórz'}</button>
    </form>
  );
}
```

#T CODE_TSX Formularz ticketu z React Hook Form (TSX)
Generyk `useForm<FormValues>()` sprawia, że `register('titel')` jest błędem, a `errors.title` i dane w `onValid` mają znany typ. `valueAsNumber` zamienia wartość pola na liczbę.
```
// NewTicketForm.tsx
import { useForm } from 'react-hook-form';
import type { TicketPriority } from '../types';

type FormValues = {
  title: string;
  description: string;
  priority: TicketPriority;
  estimateHours: number;
};

export function NewTicketForm({ onCreate }: { onCreate: (values: FormValues) => Promise<void> }) {
  const { register, handleSubmit, reset, formState: { errors, isSubmitting } } = useForm<FormValues>({
    defaultValues: { title: '', description: '', priority: 'MEDIUM', estimateHours: 0 },
  });

  async function onValid(values: FormValues) {
    await onCreate(values);
    reset();
  }

  return (
    <form onSubmit={handleSubmit(onValid)} noValidate>
      <label htmlFor="title">Tytuł</label>
      <input
        id="title"
        aria-invalid={errors.title ? true : undefined}
        {...register('title', {
          required: 'Tytuł jest wymagany.',
          minLength: { value: 5, message: 'Co najmniej 5 znaków.' },
        })}
      />
      {errors.title && <p role="alert">{errors.title.message}</p>}

      <label htmlFor="priority">Priorytet</label>
      <select id="priority" {...register('priority')}>
        <option value="LOW">Niski</option>
        <option value="MEDIUM">Średni</option>
        <option value="HIGH">Wysoki</option>
        <option value="CRITICAL">Krytyczny</option>
      </select>

      <label htmlFor="estimate">Szacowany czas (h)</label>
      <input
        id="estimate"
        type="number"
        {...register('estimateHours', { valueAsNumber: true, min: { value: 0, message: 'Nie może być ujemny.' } })}
      />
      {errors.estimateHours && <p role="alert">{errors.estimateHours.message}</p>}

      <button type="submit" disabled={isSubmitting}>{isSubmitting ? 'Zapisywanie…' : 'Utwórz'}</button>
    </form>
  );
}
```

#T NOTE JSX ↔ TSX — największa przewaga TSX w formularzach
React Hook Form jest pisany w TypeScripcie i właśnie tu TSX daje najwięcej: nazwy pól w `register`, `watch`, `setValue` i `errors` są sprawdzane względem `FormValues` (także zagnieżdżone ścieżki typu `'address.city'`), a funkcja przekazana do `handleSubmit` dostaje dane o pewnym kształcie. W JSX `register('titel')` po cichu utworzy nowe pole, a `errors.title` nigdy się nie pojawi. Zauważ różnicę w polu liczbowym: w TSX `valueAsNumber: true` daje typ `number` (pusty tekst → `NaN`, który warto obsłużyć w walidacji), w wersji JSX bez tej opcji dostajesz tekst.

#T DEFINITION Kontrolowane komponenty: Controller
`register` działa z natywnymi polami (`input`, `select`, `textarea`). Komponenty z bibliotek UI (np. wybór daty, Select z Radix) często nie przyjmują `ref` ani zdarzenia `onChange` w natywnej postaci — mają `value` i `onValueChange(wartość)`. Dla nich jest komponent `Controller` (lub hook `useController`): przekazuje `field.value` i `field.onChange` do kontrolowanego komponentu.

#T CODE_PRACTICAL Controller z własnym komponentem wyboru priorytetu
```
import { Controller, useForm } from 'react-hook-form';
import type { TicketPriority } from '../types';

const PRIORITIES: TicketPriority[] = ['LOW', 'MEDIUM', 'HIGH', 'CRITICAL'];

function PriorityPicker({ value, onChange }: { value: TicketPriority; onChange: (p: TicketPriority) => void }) {
  return (
    <div role="radiogroup" aria-label="Priorytet">
      {PRIORITIES.map((p) => (
        <button key={p} type="button" role="radio" aria-checked={value === p} onClick={() => onChange(p)}>
          {p}
        </button>
      ))}
    </div>
  );
}

export function PriorityForm() {
  const { control, handleSubmit } = useForm<{ priority: TicketPriority }>({ defaultValues: { priority: 'MEDIUM' } });
  return (
    <form onSubmit={handleSubmit((v) => console.log(v))}>
      <Controller
        name="priority"
        control={control}
        render={({ field }) => <PriorityPicker value={field.value} onChange={field.onChange} />}
      />
      <button type="submit">Zapisz</button>
    </form>
  );
}
```

#T DEFINITION Formularz edycji: defaultValues i reset
Formularz edycji ustawiasz przez `defaultValues` z danych rekordu. Dla innego rekordu masz dwie drogi: `key={ticket.id}` na komponencie (jak w poprzedniej lekcji) albo `reset(nowyRekord)` wywołane w handlerze wyboru. `isDirty` mówi, czy użytkownik coś zmienił — przydatne do pytania „Masz niezapisane zmiany” i do wyłączenia przycisku „Zapisz”, gdy nie ma czego zapisywać.

#T STEP_BY_STEP Budujemy razem: formularz ticketu na React Hook Form
1. Zainstaluj `react-hook-form`.
2. Przepisz `NewTicketForm` na `useForm` z regułami: tytuł wymagany (5–120 znaków), czas nieujemny, opis wymagany dla `CRITICAL` (reguła `validate` z dostępem do wszystkich wartości: `validate: (value, all) => all.priority !== 'CRITICAL' || value.trim() !== '' || 'Opis wymagany'`).
3. Zrób `onCreate` asynchroniczne z opóźnieniem 800 ms (`await new Promise((r) => setTimeout(r, 800))`) i sprawdź stan przycisku „Zapisywanie…”.
4. Wyślij pusty formularz — fokus sam trafia na pole tytułu (to robi `handleSubmit`).
5. Przepisz `EditTicketForm`: `useForm({ defaultValues: ticket })`, przycisk „Zapisz” wyłączony, gdy `!isDirty`.
6. Otwórz React DevTools i porównaj liczbę renderów przy pisaniu w polu z wersją ręczną (kontrolowaną) — pola niekontrolowane nie renderują formularza przy każdym znaku.
7. Usuń starą funkcję `validateTicket` albo zostaw ją jako pomoc dla następnej lekcji (Zod przejmie jej rolę).

#T PITFALL Spread register przed własnym onChange
`<input {...register('title')} onChange={myHandler} />` — Twój `onChange` nadpisuje ten z `register` i biblioteka przestaje widzieć zmiany. Jeśli potrzebujesz własnej reakcji, przekaż ją w opcjach: `register('title', { onChange: (e) => ... })`, albo użyj `watch`.

#T WHEN_TO_USE Ręcznie czy React Hook Form
Ręcznie: 1–3 pola, prosta walidacja, nauka mechanizmów (dlatego zaczynaliśmy od ręcznej wersji). React Hook Form: formularze z wieloma polami, złożoną walidacją, polami dynamicznymi (`useFieldArray` dla list typu „dodaj kolejną osobę”), formularze wieloetapowe, wymagana wydajność przy dużych formularzach. W połączeniu ze schematem Zod (następna lekcja) to dziś najczęstszy standard w projektach React.

#T SUMMARY Kryterium akceptacji i podsumowanie
`useForm` daje `register` (podłączenie pola z regułami), `handleSubmit` (walidacja + fokus na błędzie + wywołanie z poprawnymi danymi), `formState` (`errors`, `isSubmitting`, `isDirty`), `reset` i `watch`. Komponenty kontrolowane podłączasz przez `Controller`. Biblioteka domyślnie używa pól niekontrolowanych, więc nie renderuje formularza przy każdym znaku. W TSX `useForm<FormValues>()` sprawdza nazwy pól i typ danych przekazywanych do `onValid`.

Kryterium akceptacji: formularze tworzenia i edycji ticketu działają na React Hook Form, błędy pojawiają się przy polach, fokus trafia na pierwszy błąd, przycisk pokazuje „Zapisywanie…” podczas zapisu, a „Zapisz” w edycji jest aktywny tylko po zmianie danych.
