#T INTRO Rozgrzewka i problem: czy każdy formularz musi być kontrolowany?
Rozgrzewka: Jak odczytać stan checkboxa? Gdzie ustawiasz wartość listy rozwijanej? Dlaczego pusty tekst z pola liczbowego trzeba obsłużyć osobno?

Problem: formularz „Zgłoś problem z aplikacją” w stopce DevDesk ma sześć pól, nie waliduje się na bieżąco i nic poza wysłaniem z niego nie korzysta. Trzymanie sześciu pól w stanie i przepisywanie każdego znaku przez `onChange` to sporo kodu bez korzyści. Pola **niekontrolowane** z odczytem przez `FormData` dają ten sam efekt prościej.

#T DEFINITION Pole niekontrolowane
Pole niekontrolowane przechowuje wartość samo — w DOM-ie, jak w zwykłym HTML. W React:
- wartość startową podajesz przez `defaultValue` (lub `defaultChecked` dla checkboxów),
- nie podajesz `value` ani nie musisz podawać `onChange`,
- wartość odczytujesz, gdy jest potrzebna — najczęściej przy wysłaniu formularza, przez `new FormData(form)`.

React nie renderuje ponownie przy każdym znaku, a kodu jest mniej. W zamian nie znasz wartości „na żywo” (np. do licznika znaków).

#T CODE_JSX Formularz zgłoszenia z FormData (JSX)
`FormData` zbiera wartości wszystkich pól z atrybutem `name`. `Object.fromEntries` zamienia je w obiekt.
```
// FeedbackForm.jsx
export function FeedbackForm({ onSend }) {
  function handleSubmit(e) {
    e.preventDefault();
    const form = e.currentTarget;
    const data = new FormData(form);

    onSend({
      email: String(data.get('email') ?? ''),
      area: String(data.get('area') ?? ''),
      message: String(data.get('message') ?? ''),
      contactMe: data.get('contactMe') === 'on',
    });
    form.reset(); // czyści pola niekontrolowane
  }

  return (
    <form onSubmit={handleSubmit} className="form">
      <label htmlFor="fb-email">E-mail</label>
      <input id="fb-email" name="email" type="email" required />

      <label htmlFor="fb-area">Obszar</label>
      <select id="fb-area" name="area" defaultValue="tickets">
        <option value="tickets">Tickety</option>
        <option value="dashboard">Dashboard</option>
        <option value="other">Inne</option>
      </select>

      <label htmlFor="fb-message">Opis</label>
      <textarea id="fb-message" name="message" required rows={4} />

      <label><input type="checkbox" name="contactMe" defaultChecked /> Skontaktujcie się ze mną</label>

      <button type="submit">Wyślij</button>
    </form>
  );
}
```

#T CODE_TSX Formularz zgłoszenia z FormData (TSX)
`data.get()` zwraca `FormDataEntryValue | null` (tekst albo plik) — TypeScript wymusza konwersję na tekst. Typ wyniku `Feedback` opisuje, co trafia do rodzica.
```
// FeedbackForm.tsx
import type { FormEvent } from 'react';

export type Feedback = { email: string; area: string; message: string; contactMe: boolean };

export function FeedbackForm({ onSend }: { onSend: (feedback: Feedback) => void }) {
  function handleSubmit(e: FormEvent<HTMLFormElement>) {
    e.preventDefault();
    const form = e.currentTarget;
    const data = new FormData(form);

    onSend({
      email: String(data.get('email') ?? ''),
      area: String(data.get('area') ?? ''),
      message: String(data.get('message') ?? ''),
      contactMe: data.get('contactMe') === 'on',
    });
    form.reset();
  }

  return (
    <form onSubmit={handleSubmit} className="form">
      <label htmlFor="fb-email">E-mail</label>
      <input id="fb-email" name="email" type="email" required />

      <label htmlFor="fb-area">Obszar</label>
      <select id="fb-area" name="area" defaultValue="tickets">
        <option value="tickets">Tickety</option>
        <option value="dashboard">Dashboard</option>
        <option value="other">Inne</option>
      </select>

      <label htmlFor="fb-message">Opis</label>
      <textarea id="fb-message" name="message" required rows={4} />

      <label><input type="checkbox" name="contactMe" defaultChecked /> Skontaktujcie się ze mną</label>

      <button type="submit">Wyślij</button>
    </form>
  );
}
```

#T NOTE JSX ↔ TSX — FormData nie zna kształtu formularza
`FormData` jest „luźne” w obu wersjach: `data.get('emial')` (literówka) zwróci `null` bez błędu kompilacji, bo nazwy pól to zwykłe teksty. TypeScript pomaga tylko w jednym: wymusza obsługę `null` i rozróżnienie tekstu od pliku (`FormDataEntryValue = string | File`). Pełną kontrolę kształtu daje dopiero walidacja schematem (lekcja o Zod), która sprawdza dane w czasie działania — przydatne w obu wersjach. Zwróć też uwagę na `e.currentTarget`: w TSX ma typ `HTMLFormElement` (z typu zdarzenia), więc `form.reset()` jest podpowiadane i sprawdzane.

#T DEFINITION Checkbox w FormData
Zaznaczony checkbox bez atrybutu `value` trafia do `FormData` z wartością `'on'`; niezaznaczony — nie trafia wcale (`data.get()` zwraca `null`). Stąd porównanie `data.get('contactMe') === 'on'`. Kilka checkboxów o tej samej nazwie odczytasz przez `data.getAll('tags')` — zwraca tablicę wartości zaznaczonych.

#T CODE_BASIC Walidacja wbudowana w HTML
Atrybuty `required`, `type="email"`, `minLength`, `maxLength`, `min`, `max`, `pattern` działają także w React. Przeglądarka blokuje wysłanie i pokazuje komunikat, a `onSubmit` nie zostaje wywołane.
```
export function QuickTicket() {
  return (
    <form onSubmit={(e) => { e.preventDefault(); alert('wysłano'); }}>
      <input name="title" required minLength={5} maxLength={120} placeholder="Tytuł (min. 5 znaków)" />
      <input name="ticketRef" pattern="DD-[0-9]+" title="Format: DD-123" placeholder="DD-123" />
      <button type="submit">Dodaj</button>
    </form>
  );
}
```

#T DEFINITION Pole pliku jest zawsze niekontrolowane
`<input type="file">` nie może mieć `value` ustawianego przez React — przeglądarka ze względów bezpieczeństwa nie pozwala programowo wybrać pliku. Wybrany plik odczytujesz z `e.target.files` w `onChange` albo z `FormData` przy wysłaniu (`data.get('attachment')` zwraca obiekt `File`). Wysyłanie plików na serwer pokażemy w rozdziale 11.

#T CODE_PRACTICAL Załącznik w formularzu (TSX)
```
import { useState, type ChangeEvent } from 'react';

export function AttachmentInput() {
  const [info, setInfo] = useState<string | null>(null);

  function handleChange(e: ChangeEvent<HTMLInputElement>) {
    const file = e.target.files?.[0];
    setInfo(file ? `${file.name} (${Math.round(file.size / 1024)} KB)` : null);
  }

  return (
    <div>
      <label htmlFor="attachment">Załącznik</label>
      <input id="attachment" name="attachment" type="file" accept="image/*,.pdf" onChange={handleChange} />
      {info && <small>{info}</small>}
    </div>
  );
}
```

#T STEP_BY_STEP Budujemy razem: formularz „Zgłoś problem”
1. Utwórz `FeedbackForm` z polami niekontrolowanymi i obsługą `FormData`.
2. Umieść go w stopce lub w panelu bocznym DevDesk; `onSend` niech na razie wypisuje dane w konsoli i pokazuje komunikat „Dziękujemy!”.
3. Spróbuj wysłać pusty formularz — przeglądarka pokaże komunikat walidacji `required` i nie wywoła `onSubmit`.
4. Wpisz niepoprawny e-mail — zadziała walidacja `type="email"`.
5. Dodaj `AttachmentInput` i sprawdź, że w danych z `FormData` pole `attachment` jest obiektem `File`.
6. Po wysłaniu sprawdź, że `form.reset()` wyczyścił pola i przywrócił `defaultValue`/`defaultChecked`.

#T PITFALL defaultValue nie aktualizuje pola
`defaultValue` jest użyte tylko przy pierwszym zamontowaniu pola. Jeśli zmienisz props `defaultValue={ticket.title}` na inny ticket, pole pokaże stary tekst. Albo użyj pola kontrolowanego, albo wymuś nowe pole przez zmianę `key` (lekcja o formularzu edycji).

#T WHEN_TO_USE Kontrolowane czy niekontrolowane
Niekontrolowane: proste formularze, wartości potrzebne tylko przy wysłaniu, pola plików, integracja z akcjami formularzy React 19 i z bibliotekami (React Hook Form domyślnie używa pól niekontrolowanych). Kontrolowane: wartość wpływa na UI na bieżąco (filtrowanie, licznik znaków, zależne pola, formatowanie w trakcie pisania), walidacja przy każdym znaku, programowe wypełnianie pól.

#T SUMMARY Kryterium akceptacji i podsumowanie
Pola niekontrolowane trzymają wartość w DOM; wartość startowa przez `defaultValue`/`defaultChecked`, odczyt przy wysłaniu przez `new FormData(e.currentTarget)`. Zaznaczony checkbox daje `'on'`, niezaznaczony — `null`. Walidacja HTML (`required`, `type`, `pattern`) działa także w React. Pole pliku jest zawsze niekontrolowane. W TSX `data.get()` zwraca `string | File | null`, co wymusza konwersję.

Kryterium akceptacji: formularz „Zgłoś problem” działa bez stanu React dla pól, blokuje wysłanie pustych wymaganych pól, przekazuje rodzicowi poprawny obiekt danych (z wartością logiczną dla checkboxa) i czyści się po wysłaniu.
