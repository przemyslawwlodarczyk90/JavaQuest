#T INTRO Boss rozdziału 03: strona przewodnika stylu
W tym zadaniu budujesz stronę, którą w prawdziwych zespołach nazywa się „style guide” albo „kitchen sink”: jedno miejsce pokazujące wszystkie podstawowe komponenty w każdym wariancie i w obu motywach. Taka strona szybko ujawnia niespójności i jest punktem odniesienia dla całego zespołu. Projektujesz ją samodzielnie — wskazówki są poniżej, rozwiązanie częściowe na końcu.

#T DEFINITION Brief zadania
Zbuduj trasę/stronę „Przewodnik stylu” (na razie jako komponent `StyleGuide` wyrenderowany zamiast `Main`) z sekcjami:
1. **Kolory** — próbki wszystkich tokenów kolorów z nazwą zmiennej i wartością.
2. **Typografia** — nagłówki h1–h3, tekst, tekst wyciszony, kod.
3. **Przyciski** — warianty `primary`, `secondary`, `danger`, każdy także w stanie `disabled`.
4. **Plakietki** — wszystkie tony `Badge` oraz wszystkie statusy i priorytety.
5. **Karty i panele** — `StatCard` w zwykłej i wyróżnionej wersji, `Panel` z akcjami i bez.
6. **Pole tekstowe** — zwykłe, z błędem (czerwona ramka i komunikat), wyłączone.
7. Przełącznik motywu u góry strony — wszystko poprawnie wygląda w trybie jasnym i ciemnym.

#T STEP_BY_STEP Kryteria akceptacji
1. Każda sekcja używa istniejących komponentów DevDesk — strona nie zawiera „kopii” stylów.
2. Kolory w komponentach pochodzą wyłącznie z tokenów (żaden plik `.module.css` nie ma surowego `#hex`).
3. Lista tokenów w sekcji „Kolory” jest generowana z tablicy (`map`), nie wpisana ręcznie w JSX.
4. Przycisk wyłączony nie reaguje na kliknięcie i ma widoczny styl `:disabled`.
5. Pole z błędem ma `aria-invalid="true"` i komunikat powiązany przez `aria-describedby`.
6. Fokus klawiatury jest widoczny na każdym interaktywnym elemencie w obu motywach.
7. W wersji TSX warianty (`Variant`, `Tone`) są uniami literałów, a listy wariantów w przewodniku pochodzą z tablic `as const`, z których wyprowadzono te typy.
8. `npm run lint` i (w TS) `npm run build` przechodzą bez błędów.

#T NOTE Wskazówka 1 — próbki kolorów
Wartość zmiennej CSS odczytasz w przeglądarce przez `getComputedStyle(document.documentElement).getPropertyValue('--color-primary')`, ale w renderze to odczyt z DOM — nieczysty i nieaktualny po zmianie motywu. Prościej: próbka to `<span style={{ background: `var(${token})` }} />` — przeglądarka sama podstawi aktualną wartość w każdym motywie, a obok wypisujesz nazwę tokenu.

#T NOTE Wskazówka 2 — jedna lista wariantów
Zamiast utrzymywać osobno typ i listę do wyświetlenia, zapisz tablicę `const VARIANTS = ['primary', 'secondary', 'danger'] as const;` i wyprowadź z niej typ `type Variant = (typeof VARIANTS)[number];`. Przewodnik iteruje po `VARIANTS`, a `Button` przyjmuje `Variant`. Dodanie wariantu w tablicy automatycznie pokaże go w przewodniku i rozszerzy typ.

#T CODE_JSX Sekcja kolorów i przycisków (JSX)
```
// StyleGuide.jsx
import { Button } from './Button';

const COLOR_TOKENS = ['--color-primary', '--color-danger', '--color-warning', '--color-success', '--bg', '--surface', '--text', '--border'];
const VARIANTS = ['primary', 'secondary', 'danger'];

export function StyleGuide() {
  return (
    <div className="style-guide">
      <section>
        <h2>Kolory</h2>
        <ul className="swatches">
          {COLOR_TOKENS.map((token) => (
            <li key={token}>
              <span className="swatch" style={{ background: `var(${token})` }} />
              <code>{token}</code>
            </li>
          ))}
        </ul>
      </section>
      <section>
        <h2>Przyciski</h2>
        {VARIANTS.map((v) => (
          <p key={v}>
            <Button variant={v}>{v}</Button> <Button variant={v} disabled>{v} (wyłączony)</Button>
          </p>
        ))}
      </section>
    </div>
  );
}
```

#T CODE_TSX Sekcja kolorów i przycisków (TSX)
`VARIANTS` i typ `Variant` z jednego źródła. `Button` przyjmuje też `disabled` — rozszerz jego typ props.
```
// StyleGuide.tsx
import type { ReactNode } from 'react';

export const VARIANTS = ['primary', 'secondary', 'danger'] as const;
export type Variant = (typeof VARIANTS)[number];

type ButtonProps = { variant?: Variant; disabled?: boolean; children: ReactNode };

export function Button({ variant = 'primary', disabled = false, children }: ButtonProps) {
  return <button type="button" className={`btn btn--${variant}`} disabled={disabled}>{children}</button>;
}

const COLOR_TOKENS = ['--color-primary', '--color-danger', '--color-warning', '--color-success', '--bg', '--surface', '--text', '--border'] as const;

export function StyleGuide() {
  return (
    <div className="style-guide">
      <section>
        <h2>Kolory</h2>
        <ul className="swatches">
          {COLOR_TOKENS.map((token) => (
            <li key={token}>
              <span className="swatch" style={{ background: `var(${token})` }} />
              <code>{token}</code>
            </li>
          ))}
        </ul>
      </section>
      <section>
        <h2>Przyciski</h2>
        {VARIANTS.map((v) => (
          <p key={v}>
            <Button variant={v}>{v}</Button> <Button variant={v} disabled>{v} (wyłączony)</Button>
          </p>
        ))}
      </section>
    </div>
  );
}
```

#T NOTE Wskazówka 3 — pole z błędem
Komponent `TextField` z props `label`, `error?` i `disabled?`. Identyfikator pola i komunikatu wygeneruj przez `useId()` z Reacta (stabilny identyfikator dla danego komponentu): `const id = useId(); const errorId = `${id}-error`;`. Na `<input>` ustaw `aria-invalid={Boolean(error)}` i `aria-describedby={error ? errorId : undefined}`. Szczegóły dostępnych formularzy w rozdziale 05.

#T PITFALL Typowe błędy w tym zadaniu
- Kopiowanie stylów przycisku do przewodnika zamiast użycia komponentu — przewodnik ma pokazywać prawdziwe komponenty.
- Odczyt wartości tokenów przez `getComputedStyle` w renderze — nieczyste i nieaktualne po zmianie motywu.
- Brak `type="button"` na przyciskach — wewnątrz formularza każdy przycisk bez typu wysyła formularz.
- Usunięcie obramowania fokusu (`outline: none`) dla „ładniejszego” wyglądu bez zamiennika.

#T SUMMARY Podsumowanie rozdziału 03
W tym rozdziale poznałeś: klasy, `style` i `clsx`; CSS Modules z izolacją nazw; tokeny projektowe i motyw ciemny na zmiennych CSS; Tailwind z wariantami `hover:`, `md:` i `dark:`; CSS-in-JS i rozwiązania zero-runtime; biblioteki komponentów ostylowanych, headless i kopiowanych. W TSX: `CSSProperties`, unie literałów dla wariantów, typy z bibliotek i wyprowadzanie typów z tablic `as const`.

Boss zaliczony, gdy wszystkie osiem kryteriów akceptacji jest spełnionych, a przewodnik wygląda poprawnie w obu motywach.
