#T INTRO Rozgrzewka i problem: klasy sklejane z kawałków
Rozgrzewka: Co to znaczy, że komponent jest czysty? Dlaczego `tickets.sort()` na props to błąd? Czym jest slot?

Problem: w DevDesk klasy CSS sklejasz szablonami: `` `row ${selected ? 'row--selected' : ''} ${inactive ? 'row--inactive' : ''}` ``. Wynik zawiera podwójne spacje, a przy trzecim warunku zapis staje się nieczytelny. W tej lekcji poznasz wszystkie podstawowe sposoby stylowania w React i narzędzie `clsx` do składania klas.

#T DEFINITION Trzy podstawowe sposoby stylowania
1. **Globalny plik CSS** importowany w komponencie: `import './App.css'`. Vite dołącza go do strony; klasy działają w całej aplikacji.
2. **`className`** — atrybut z nazwą klasy (lub kilkoma oddzielonymi spacją), może być wyliczany wyrażeniem.
3. **`style`** — obiekt z właściwościami CSS w camelCase: `style={{ width: 120, backgroundColor: '#fff' }}`. Liczby bez jednostki to piksele (dla właściwości długości).

Zasada: wygląd opisujesz klasami, a `style` zostawiasz dla wartości naprawdę dynamicznych (szerokość paska postępu, kolor wybrany przez użytkownika, pozycja z obliczeń).

#T CODE_JSX Klasy warunkowe przez clsx (JSX)
`clsx` przyjmuje teksty, obiekty `{ klasa: warunek }` i tablice; pomija wartości fałszywe i nie zostawia podwójnych spacji. Instalacja: `npm install clsx`.
```
// TicketRow.jsx
import clsx from 'clsx';

export function TicketRow({ ticket, selected, compact }) {
  const className = clsx('row', {
    'row--selected': selected,
    'row--closed': ticket.status === 'CLOSED',
    'row--compact': compact,
  });

  return (
    <tr className={className}>
      <td>{ticket.id}</td>
      <td>{ticket.title}</td>
    </tr>
  );
}
```

#T CODE_TSX Klasy warunkowe przez clsx (TSX)
`clsx` ma własne typy w paczce — nie trzeba instalować `@types`. Parametr `compact` ma wartość domyślną, więc jest opcjonalny.
```
// TicketRow.tsx
import clsx from 'clsx';
import type { Ticket } from '../types';

type TicketRowProps = { ticket: Ticket; selected: boolean; compact?: boolean };

export function TicketRow({ ticket, selected, compact = false }: TicketRowProps) {
  const className = clsx('row', {
    'row--selected': selected,
    'row--closed': ticket.status === 'CLOSED',
    'row--compact': compact,
  });

  return (
    <tr className={className}>
      <td>{ticket.id}</td>
      <td>{ticket.title}</td>
    </tr>
  );
}
```

#T NOTE JSX ↔ TSX — atrybut style i nazwy klas
`className` w obu wersjach to zwykły tekst — TypeScript nie sprawdza, czy klasa istnieje w CSS (to zmieni się przy CSS Modules z odpowiednimi wtyczkami). Za to obiekt `style` w TSX ma typ `CSSProperties`: literówka `style={{ backgroundColour: 'red' }}` albo `display: 'flexx'` to błąd kompilacji z podpowiedzią poprawnej nazwy. W JSX taka właściwość zostanie po cichu zignorowana. Gdy przekazujesz styl przez props, typ zapisujesz jako `style?: CSSProperties` (import z `react`).

#T CODE_BASIC Pasek postępu — dobry przypadek dla style
Szerokość wynika z danych i może mieć dowolną wartość — klasy CSS by tu nie wystarczyły.
```
import type { CSSProperties } from 'react';

export function ProgressBar({ value }: { value: number }) {
  const percent = Math.min(100, Math.max(0, value));
  const fill: CSSProperties = { width: `${percent}%` };
  return (
    <div className="progress" role="progressbar" aria-valuenow={percent} aria-valuemin={0} aria-valuemax={100}>
      <div className="progress__fill" style={fill} />
    </div>
  );
}
```

#T CODE_PRACTICAL Zmienne CSS ustawiane z React
Zamiast liczyć cały styl w JavaScripcie, ustaw zmienną CSS, a resztę zostaw w arkuszu. W TSX własne właściwości `--nazwa` wymagają rzutowania, bo nie są w typie `CSSProperties`.
```
import type { CSSProperties } from 'react';

export function TagChip({ label, color }: { label: string; color: string }) {
  return (
    <span className="chip" style={{ '--chip-color': color } as CSSProperties}>
      {label}
    </span>
  );
}

// CSS: .chip { border: 1px solid var(--chip-color); color: var(--chip-color); }
```

#T DEFINITION Stany interakcji zostają w CSS
`:hover`, `:focus-visible`, `:active`, `:disabled`, `::placeholder` obsługujesz w arkuszu CSS — nie przez stan React. Śledzenie najechania myszą w `useState` tylko po to, żeby zmienić kolor, to niepotrzebne rendery i gorsza dostępność. Pamiętaj zwłaszcza o `:focus-visible` — użytkownicy klawiatury muszą widzieć, gdzie jest fokus.

#T CODE_WRONG Hover przez stan React
```
import { useState } from 'react';

export function Row({ children }) {
  const [hover, setHover] = useState(false);
  return (
    <tr onMouseEnter={() => setHover(true)} onMouseLeave={() => setHover(false)}
        style={{ background: hover ? '#f3f4f6' : 'white' }}>
      {children}
    </tr>
  );
}
```

#T CODE_RIGHT Hover w CSS
```
export function Row({ children }) {
  return <tr className="row">{children}</tr>;
}

/* CSS:
.row:hover { background: #f3f4f6; }
.row:focus-visible { outline: 2px solid #2563eb; }

```

#T STEP_BY_STEP Budujemy razem: wygląd tabeli i wierszy
1. Zainstaluj `clsx` w obu projektach.
2. W `TicketRow` złóż klasy przez `clsx`: `row`, `row--closed` dla zamkniętych.
3. W CSS dodaj `.row:hover { background: #f9fafb; }` i `.row--closed td { color: #9ca3af; text-decoration: line-through; }`.
4. Dodaj komponent `ProgressBar` w karcie statystyk „Otwarte” pokazujący udział otwartych ticketów w procentach.
5. Dodaj `TagChip` z kolorem zależnym od tagu (np. mapa `{ api: '#2563eb', ui: '#9333ea' }`) i wyświetl tagi w wierszach.
6. W wersji TS wpisz celowo `style={{ widht: 10 }}` — przeczytaj błąd i popraw.
7. Przejdź tabelę klawiszem Tab po przyciskach — upewnij się, że fokus jest widoczny.

#T WHEN_TO_USE Globalny CSS — zalety i granice
Globalny CSS jest prosty i wystarcza w małych projektach. Problem pojawia się przy rozroście: dwa komponenty używające klasy `.title` wpływają na siebie nawzajem, a usunięcie komponentu nie usuwa jego stylów. Konwencja nazewnictwa (np. BEM: `blok__element--modyfikator`, jak w kursie) łagodzi problem, a w pełni rozwiązują go CSS Modules — następna lekcja.

#T SUMMARY Kryterium akceptacji i podsumowanie
Wygląd opisujesz klasami (`className`), składając je przez `clsx`; `style` tylko dla wartości dynamicznych, najlepiej przez zmienne CSS. Stany `:hover`, `:focus-visible` i `:disabled` zostają w CSS. W TSX obiekt `style` ma typ `CSSProperties`, który wykrywa literówki w nazwach właściwości.

Kryterium akceptacji: klasy wierszy są składane przez `clsx`, zamknięte tickety są wyszarzone i przekreślone, karta „Otwarte” ma pasek postępu ustawiany przez `style`, a fokus klawiatury jest widoczny.
