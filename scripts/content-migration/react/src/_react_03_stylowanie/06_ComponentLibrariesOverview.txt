#T INTRO Rozgrzewka i problem: czy pisać wszystko samemu?
Rozgrzewka: Czym różni się styled-components od CSS Modules w miejscu, gdzie powstaje CSS? Co oznacza prefiks `$` w props stylowanego komponentu?

Problem: DevDesk wkrótce będzie potrzebował listy rozwijanej z wyszukiwaniem, kalendarza, modala, menu kontekstowego i podpowiedzi. Każdy z tych elementów jest trudny: obsługa klawiatury, fokus, czytniki ekranu, pozycjonowanie przy krawędzi ekranu. Biblioteki komponentów rozwiązują te problemy — ale jest ich wiele i działają według różnych filozofii. Ta lekcja pomaga wybrać.

#T DEFINITION Trzy rodzaje bibliotek komponentów
1. **Gotowe, ostylowane** — komponenty z wyglądem i motywem: MUI (Material UI), Mantine, Chakra UI, Ant Design. Szybki start, gotowy wygląd, trudniej odejść od ich stylu.
2. **Headless (bez wyglądu)** — logika, dostępność i obsługa klawiatury bez żadnych stylów: Radix UI Primitives, React Aria (Adobe), Headless UI, Base UI. Wygląd dodajesz sam (CSS Modules, Tailwind).
3. **Kopiowany kod** — shadcn/ui: narzędzie kopiuje do Twojego projektu kod komponentów zbudowanych na bibliotece headless i Tailwindzie. Kod jest Twój — możesz go dowolnie zmieniać.

#T ANALOGY Meble
Gotowa biblioteka to meble z salonu — od razu ładne, ale wszystkie w jednym stylu. Headless to stelaże i okucia najwyższej jakości — mechanizm działa perfekcyjnie, ale fronty i kolory wybierasz sam. shadcn/ui to projekt stolarski z gotowymi elementami, który przywozisz do swojego warsztatu i przerabiasz.

#T CODE_JSX Dialog z Radix UI (JSX)
Radix daje strukturę i zachowanie: fokus przenosi się do okna, Escape zamyka, tło blokuje interakcję, czytnik ekranu dostaje rolę `dialog` z tytułem. Wygląd — Twoje klasy. Instalacja: `npm install @radix-ui/react-dialog`.
```
// NewTicketDialog.jsx
import * as Dialog from '@radix-ui/react-dialog';
import styles from './NewTicketDialog.module.css';

export function NewTicketDialog() {
  return (
    <Dialog.Root>
      <Dialog.Trigger className={styles.trigger}>+ Nowy ticket</Dialog.Trigger>
      <Dialog.Portal>
        <Dialog.Overlay className={styles.overlay} />
        <Dialog.Content className={styles.content}>
          <Dialog.Title>Nowy ticket</Dialog.Title>
          <Dialog.Description>Opisz problem, który zgłaszasz.</Dialog.Description>
          <Dialog.Close className={styles.close}>Anuluj</Dialog.Close>
        </Dialog.Content>
      </Dialog.Portal>
    </Dialog.Root>
  );
}
```

#T CODE_TSX Dialog z Radix UI (TSX)
Kod identyczny — Radix jest napisany w TypeScripcie, więc typy przychodzą z paczką. Dopisujemy tylko opcjonalny callback, żeby rodzic wiedział o otwarciu.
```
// NewTicketDialog.tsx
import * as Dialog from '@radix-ui/react-dialog';
import styles from './NewTicketDialog.module.css';

type NewTicketDialogProps = { onOpenChange?: (open: boolean) => void };

export function NewTicketDialog({ onOpenChange }: NewTicketDialogProps) {
  return (
    <Dialog.Root onOpenChange={onOpenChange}>
      <Dialog.Trigger className={styles.trigger}>+ Nowy ticket</Dialog.Trigger>
      <Dialog.Portal>
        <Dialog.Overlay className={styles.overlay} />
        <Dialog.Content className={styles.content}>
          <Dialog.Title>Nowy ticket</Dialog.Title>
          <Dialog.Description>Opisz problem, który zgłaszasz.</Dialog.Description>
          <Dialog.Close className={styles.close}>Anuluj</Dialog.Close>
        </Dialog.Content>
      </Dialog.Portal>
    </Dialog.Root>
  );
}
```

#T NOTE JSX ↔ TSX — praca z typowaną biblioteką
Prawie wszystkie współczesne biblioteki komponentów są pisane w TypeScripcie. W TSX dostajesz podpowiedzi wszystkich props (`Dialog.Root` podpowie `open`, `defaultOpen`, `onOpenChange`, `modal`), a typ callbacku `onOpenChange` jest znany z biblioteki. W JSX ta sama wiedza jest w dokumentacji — VS Code i tak pokaże część podpowiedzi, bo czyta typy paczki także dla plików `.jsx`. Gdy chcesz w TSX przyjąć „wszystkie props tego komponentu”, używasz `ComponentProps<typeof Dialog.Root>` — wrócimy do tego w rozdziale o wzorcach komponentów.

#T CODE_BASIC Ten sam przycisk w bibliotece ostylowanej (MUI)
Gotowy wygląd i warianty z biblioteki; dostosowanie przez motyw biblioteki lub prop `sx`.
```
import Button from '@mui/material/Button';

export function SaveButton({ onSave }: { onSave: () => void }) {
  return (
    <Button variant="contained" color="primary" onClick={onSave}>
      Zapisz
    </Button>
  );
}
```

#T API_REFERENCE Przegląd bibliotek (stan na 2026)
- **MUI** — największa gotowa biblioteka, wygląd Material Design, rozbudowane komponenty danych (osobny pakiet tabel MUI X).
- **Mantine** — bogata, nowoczesna, dużo gotowych hooków i komponentów formularzy.
- **Chakra UI**, **Ant Design** — gotowe zestawy z własnym systemem motywów; Ant popularny w panelach administracyjnych.
- **Radix UI Primitives** — headless, prymitywy (Dialog, Popover, DropdownMenu, Tabs, Tooltip, Select).
- **React Aria** (Adobe) — headless, bardzo dokładna dostępność i internacjonalizacja, hooki i komponenty.
- **Headless UI** — od twórców Tailwinda, mniejszy zestaw komponentów.
- **Base UI** — headless od twórców Radix i MUI.
- **shadcn/ui** — kopiowane komponenty (Tailwind + prymitywy headless), dodawane poleceniem CLI do projektu.

#T STEP_BY_STEP Budujemy razem: modal „Nowy ticket” z Radix
1. Zainstaluj `@radix-ui/react-dialog`.
2. Utwórz `NewTicketDialog` według przykładu i podepnij go pod slot `actions` panelu ticketów zamiast zwykłego przycisku.
3. Dodaj style w `NewTicketDialog.module.css`: `.overlay { position: fixed; inset: 0; background: rgb(0 0 0 / 0.4); }` oraz `.content` z `position: fixed`, wyśrodkowaniem i tłem `var(--surface)`.
4. Otwórz modal klawiaturą (Tab do przycisku i Enter), przejdź Tab po elementach — fokus nie wychodzi poza okno.
5. Zamknij Escape — fokus wraca na przycisk „+ Nowy ticket”.
6. Włącz czytnik ekranu (Narrator w Windows lub VoiceOver w macOS) i posłuchaj, jak ogłaszany jest dialog z tytułem.
7. W rozdziale 08 zbudujesz modal samodzielnie przez portal — wtedy docenisz, ile pracy wykonał Radix.

#T PITFALL Mieszanie kilku bibliotek UI
Projekt z MUI dla formularzy, Ant Design dla tabel i własnym CSS dla reszty ma trzy systemy motywów, trzy wyglądy przycisków i duży rozmiar paczki. Wybierz jedną bibliotekę (albo jedno podejście headless + własne style) i trzymaj się jej. Wyjątkiem są wyspecjalizowane komponenty bez wyglądu (np. tabela TanStack Table, edytor tekstu).

#T WHEN_TO_USE Jak wybrać
- Szybki panel wewnętrzny, wygląd mniej ważny → biblioteka ostylowana (MUI, Mantine, Ant Design).
- Własny design marki, wysoka dostępność → headless (Radix, React Aria) + CSS Modules lub Tailwind.
- Projekt na Tailwindzie, chęć pełnej kontroli nad kodem → shadcn/ui.
- Nauka (ten kurs) → najpierw budujesz komponenty sam, żeby rozumieć problemy, a biblioteki stosujesz tam, gdzie rozwiązują trudne rzeczy (dostępny dialog, menu, select).

#T SUMMARY Kryterium akceptacji i podsumowanie
Biblioteki komponentów dzielą się na ostylowane (MUI, Mantine, Ant), headless (Radix, React Aria, Base UI, Headless UI) i kopiowane (shadcn/ui). Headless rozwiązuje najtrudniejsze — dostępność, fokus, klawiaturę — i zostawia wygląd Tobie. Biblioteki mają typy w paczkach, więc w TSX dostajesz pełne podpowiedzi props. Wybierz jedno podejście na projekt.

Kryterium akceptacji: przycisk „+ Nowy ticket” otwiera modal Radix ostylowany CSS Modules; modal można obsłużyć wyłącznie klawiaturą, Escape go zamyka, a fokus wraca na przycisk.
