#T INTRO Rozgrzewka i problem: kolizja nazw klas
Rozgrzewka: Kiedy używać `style`, a kiedy klas? Co robi `clsx`? Dlaczego hover nie powinien być w stanie React?

Problem: komponenty `Panel` i `TicketCard` mają klasę `.title` z różnym wyglądem. Który styl wygra, zależy od kolejności importów — po zmianie kolejności plików nagłówek panelu nagle robi się mniejszy. **CSS Modules** rozwiązują ten problem: każda klasa jest lokalna dla pliku, w którym ją zdefiniowano.

#T DEFINITION CSS Modules
Plik z rozszerzeniem `.module.css` jest traktowany przez Vite jako moduł CSS:
- każda nazwa klasy dostaje unikalny przyrostek, np. `.title` → `.Panel_title_x7k2a`,
- importujesz obiekt: `import styles from './Panel.module.css'`,
- klasę podajesz jako `className={styles.title}`.

Dwa komponenty mogą mieć klasę `.title` i nigdy się nie pogryzą. Style żyją obok komponentu i znikają razem z nim. Nie potrzeba żadnej konfiguracji — Vite obsługuje CSS Modules od razu.

#T CODE_JSX Panel ze stylami modułowymi (JSX)
```
// Panel.jsx
import styles from './Panel.module.css';

export function Panel({ title, actions, children }) {
  return (
    <section className={styles.panel}>
      <header className={styles.header}>
        <h2 className={styles.title}>{title}</h2>
        {actions}
      </header>
      <div className={styles.body}>{children}</div>
    </section>
  );
}
```

#T CODE_TSX Panel ze stylami modułowymi (TSX)
Import modułu CSS w TSX działa dzięki deklaracjom `vite/client`: obiekt `styles` ma typ słownika `{ readonly [key: string]: string }`.
```
// Panel.tsx
import type { ReactNode } from 'react';
import styles from './Panel.module.css';

type PanelProps = { title: string; actions?: ReactNode; children: ReactNode };

export function Panel({ title, actions, children }: PanelProps) {
  return (
    <section className={styles.panel}>
      <header className={styles.header}>
        <h2 className={styles.title}>{title}</h2>
        {actions}
      </header>
      <div className={styles.body}>{children}</div>
    </section>
  );
}
```

#T NOTE JSX ↔ TSX — typy klas w CSS Modules
Domyślne typy Vite mówią tylko „to słownik tekstów”, więc `styles.tittle` (literówka) nie jest błędem — da `undefined` i element bez klasy, w obu wersjach. Jeśli chcesz, by TypeScript znał nazwy klas, możesz użyć wtyczki generującej pliki `.module.css.d.ts` (np. `typescript-plugin-css-modules` dla podpowiedzi w edytorze albo generator plików deklaracji przy budowaniu). Bez tego CSS Modules dają te same gwarancje w JSX i TSX: izolację nazw, ale nie kontrolę literówek.

#T CODE_BASIC Plik Panel.module.css
Wewnątrz modułu piszesz zwykły CSS i krótkie nazwy klas — nie musisz już stosować długich nazw BEM.
```
.panel {
  border: 1px solid #e5e7eb;
  border-radius: 8px;
  margin-bottom: 1rem;
}

.header {
  display: flex;
  justify-content: space-between;
  align-items: center;
  padding: 0.75rem 1rem;
  border-bottom: 1px solid #e5e7eb;
}

.title { margin: 0; font-size: 1rem; }
.body { padding: 1rem; }
```

#T DEFINITION Klasy złożone, warunkowe i globalne
- Kilka klas modułowych łączysz przez `clsx(styles.row, selected && styles.selected)`.
- Nazwy z myślnikiem odczytujesz nawiasem: `styles['row-selected']` — dlatego w modułach wygodniej pisać camelCase (`.rowSelected` → `styles.rowSelected`).
- `composes: base;` wewnątrz klasy dziedziczy style z innej klasy (także z innego pliku: `composes: base from './shared.module.css';`).
- `:global(.dark) .panel { ... }` — odwołanie do klasy globalnej (np. motywu) z wnętrza modułu.

#T CODE_PRACTICAL Wiersz tabeli z modułem i clsx
```
import clsx from 'clsx';
import type { Ticket } from '../types';
import styles from './TicketRow.module.css';

export function TicketRow({ ticket, selected }: { ticket: Ticket; selected: boolean }) {
  return (
    <tr className={clsx(styles.row, selected && styles.selected, ticket.status === 'CLOSED' && styles.closed)}>
      <td>{ticket.id}</td>
      <td>{ticket.title}</td>
    </tr>
  );
}

/* TicketRow.module.css:
.row:hover { background: #f9fafb; }
.selected { background: #eff6ff; }
.closed td { color: #9ca3af; }
*/
```

#T STEP_BY_STEP Budujemy razem: przenieś DevDesk na CSS Modules
1. Dla `Panel` utwórz `Panel.module.css` i przenieś do niego style `.panel*` z `App.css`, skracając nazwy (`.panel__header` → `.header`).
2. Zaimportuj `styles` i zamień `className="panel__header"` na `className={styles.header}`.
3. Powtórz dla `StatCard`, `Badge` (warianty: `styles[tone]` — klasy `.success`, `.warning`…) i `TicketRow`.
4. W `App.css` zostaw tylko style globalne: reset, `body`, układ `.app-shell`.
5. Otwórz narzędzia deweloperskie przeglądarki i zobacz wygenerowane nazwy klas.
6. Dodaj w `TicketCard.module.css` klasę `.title` innego rozmiaru niż w panelu i sprawdź, że oba nagłówki wyglądają poprawnie.

#T PITFALL Wariant przez sklejanie nazwy klasy
`className={styles['badge--' + tone]}` działa, ale łatwo tu o literówkę, której nic nie zgłosi. Czytelniej jest trzymać warianty jako osobne klasy o nazwach równych wartości wariantu (`.success`, `.danger`) i pisać `clsx(styles.badge, styles[tone])`. W TSX z unią literałów `tone` przynajmniej masz pewność, że przekazywane wartości są z listy.

#T WHEN_TO_USE Kiedy CSS Modules
CSS Modules to rozsądny domyślny wybór dla aplikacji React budowanej z Vite: zwykły CSS (bez nowej składni do nauki), izolacja nazw, zero zależności i zero kosztu w czasie działania. Rozważ alternatywy, gdy zespół woli klasy narzędziowe (Tailwind — lekcja 4) albo potrzebujesz stylów silnie zależnych od props i motywów w JS (CSS-in-JS — lekcja 5).

#T SUMMARY Kryterium akceptacji i podsumowanie
Plik `.module.css` daje klasy lokalne dla komponentu: importujesz obiekt `styles` i używasz `className={styles.nazwa}`. Vite dopisuje do nazw unikalne przyrostki, więc kolizje znikają. Klasy łączysz przez `clsx`, dziedziczysz przez `composes`, a do klas globalnych odwołujesz się przez `:global`. W obu wersjach TypeScript domyślnie nie sprawdza nazw klas modułu.

Kryterium akceptacji: `Panel`, `StatCard`, `Badge` i `TicketRow` używają własnych plików `.module.css`, w `App.css` zostały tylko style globalne, a dwie klasy `.title` w różnych modułach nie wpływają na siebie.
