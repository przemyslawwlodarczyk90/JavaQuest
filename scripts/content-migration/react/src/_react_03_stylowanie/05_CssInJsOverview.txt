#T INTRO Rozgrzewka i problem: kod, w którym style są w JavaScripcie
Rozgrzewka: Dlaczego Tailwind nie rozpozna klasy `bg-${color}-500`? Jak w Tailwind 4 dodać własny kolor? Kiedy wybrałbyś CSS Modules zamiast Tailwinda?

Problem: w wielu istniejących projektach React style są zapisane w plikach JavaScript — przez `styled-components` albo Emotion. Wejdziesz do takiego projektu i zobaczysz `const Card = styled.div`...``. Ta lekcja uczy czytać i pisać taki kod oraz wyjaśnia, dlaczego w nowych projektach trend odwraca się w stronę rozwiązań bez kosztu w czasie działania.

#T DEFINITION CSS-in-JS
CSS-in-JS to grupa bibliotek, w których style zapisujesz w JavaScripcie, często obok komponentu. Najpopularniejsze: **styled-components** i **Emotion**. Biblioteka w czasie działania aplikacji generuje unikalne klasy i wstrzykuje reguły CSS do `<head>`. Zalety: style mają dostęp do props i motywu w JS, są izolowane jak w CSS Modules, łatwo tworzyć warianty. Wada: praca wykonywana w przeglądarce przy renderowaniu (koszt w czasie działania) i trudniejsza współpraca z renderowaniem na serwerze i komponentami serwerowymi.

#T CODE_JSX Karta w styled-components (JSX)
Szablon z tagiem `styled.div` tworzy komponent ze stylami. Funkcja `${(p) => ...}` w środku odczytuje props.
```
// StatCard.jsx
import styled from 'styled-components';

const Card = styled.div`
  border: 1px solid #e5e7eb;
  border-radius: 8px;
  padding: 16px;
  background: ${(p) => (p.$highlight ? '#eff6ff' : 'white')};
`;

const Value = styled.strong`
  display: block;
  font-size: 1.5rem;
`;

export function StatCard({ label, value, highlight = false }) {
  return (
    <Card $highlight={highlight}>
      <span>{label}</span>
      <Value>{value}</Value>
    </Card>
  );
}
```

#T CODE_TSX Karta w styled-components (TSX)
Typ props dla stylowanego komponentu podajesz generykiem `styled.div<{ $highlight: boolean }>`. Prefiks `$` oznacza „transient prop” — trafia do stylów, ale nie do elementu DOM.
```
// StatCard.tsx
import styled from 'styled-components';

const Card = styled.div<{ $highlight: boolean }>`
  border: 1px solid #e5e7eb;
  border-radius: 8px;
  padding: 16px;
  background: ${(p) => (p.$highlight ? '#eff6ff' : 'white')};
`;

const Value = styled.strong`
  display: block;
  font-size: 1.5rem;
`;

type StatCardProps = { label: string; value: number; highlight?: boolean };

export function StatCard({ label, value, highlight = false }: StatCardProps) {
  return (
    <Card $highlight={highlight}>
      <span>{label}</span>
      <Value>{value}</Value>
    </Card>
  );
}
```

#T NOTE JSX ↔ TSX — props stylów
W TSX generyk `styled.div<{ $highlight: boolean }>` sprawia, że `p.$highlight` w szablonie stylów ma znany typ, a użycie `<Card>` bez `$highlight` lub z tekstem zamiast wartości logicznej jest błędem. W JSX `p.$highlight` może być czymkolwiek — literówka `p.$higlight` po prostu da zawsze białe tło. To ten sam zysk, co przy typowaniu props zwykłych komponentów, przeniesiony na style.

#T DEFINITION Motyw w CSS-in-JS
styled-components i Emotion mają `ThemeProvider`: obiekt motywu przekazany na górze drzewa jest dostępny w każdym stylu jako `p.theme`. W TSX typ motywu rozszerzasz przez deklarację modułu (`declare module 'styled-components' { export interface DefaultTheme {...} }`), żeby `p.theme.colors.primary` miało podpowiedzi. To odpowiednik tokenów z lekcji 3, tylko trzymany w JavaScripcie.

#T DEFINITION Rozwiązania zero-runtime
Nowsza generacja narzędzi zachowuje zalety pisania stylów w TS/JS, ale generuje zwykły plik CSS **podczas budowania**, a nie w przeglądarce:
- **vanilla-extract** — style w plikach `.css.ts`, pełne typowanie, wynik to statyczny CSS,
- **Panda CSS**, **StyleX** (używany w Meta), **Linaria** — podobna idea, różne API.

Brak kosztu w czasie działania i zgodność z komponentami serwerowymi sprawiły, że w nowych projektach to one (albo CSS Modules lub Tailwind) zastępują klasyczne CSS-in-JS.

#T CODE_BASIC vanilla-extract: style w pliku .css.ts
Plik `Card.css.ts` jest wykonywany przy budowaniu; eksportowane stałe to nazwy wygenerowanych klas.
```
// Card.css.ts
import { style } from '@vanilla-extract/css';

export const card = style({
  border: '1px solid #e5e7eb',
  borderRadius: 8,
  padding: 16,
  ':hover': { background: '#f9fafb' },
});

// Card.tsx
// import { card } from './Card.css';
// export function Card({ children }) { return <div className={card}>{children}</div>; }
```

#T VISUAL_EXAMPLE Gdzie powstaje CSS
styled-components / Emotion:   build → JS ze stylami  →  przeglądarka: render → generowanie klas → <style> w <head>
CSS Modules / Tailwind:        build → plik .css      →  przeglądarka: tylko pobiera plik
vanilla-extract / Panda:       build → plik .css      →  przeglądarka: tylko pobiera plik

Im mniej pracy w przeglądarce przy każdym renderze, tym szybciej interfejs reaguje na dużych listach i przy pierwszym ładowaniu.

#T STEP_BY_STEP Ćwiczenie: przepisz kartę w trzech stylach
1. Na osobnej gałęzi zainstaluj `styled-components` i przepisz `StatCard` według przykładu.
2. Dodaj prop `highlight` dla karty „Pilne” i sprawdź w DevTools, że `$highlight` nie trafia jako atrybut do elementu `div`.
3. Otwórz zakładkę Elements i znajdź w `<head>` wstrzyknięty `<style>` z wygenerowanymi klasami.
4. Porównaj z wersją CSS Modules: tam style są w osobnym pliku `.css` ładowanym przez `<link>`.
5. Usuń gałąź albo zostaw jako notatkę — w kursie dalej stosujemy CSS Modules.

#T PITFALL Definiowanie stylowanego komponentu w środku komponentu
`const Card = styled.div`...`` zapisane wewnątrz funkcji komponentu tworzy nowy komponent przy każdym renderze — to ten sam błąd co definiowanie komponentu w komponencie (rozdział 02): utrata stanu dzieci, wolne rendery, a biblioteka ostrzeże w konsoli. Stylowane komponenty zawsze definiuj na najwyższym poziomie modułu.

#T WHEN_TO_USE Kiedy CSS-in-JS
Wybierz klasyczne CSS-in-JS, gdy dołączasz do projektu, który już go używa (spójność ważniejsza od mody) albo budujesz bibliotekę komponentów silnie zależną od motywu w JS i nie potrzebujesz renderowania na serwerze. W nowym projekcie najpierw rozważ CSS Modules, Tailwinda albo rozwiązanie zero-runtime (vanilla-extract, Panda) — dają podobny komfort bez kosztu w przeglądarce.

#T SUMMARY Kryterium akceptacji i podsumowanie
CSS-in-JS (styled-components, Emotion) zapisuje style w JS, generuje klasy w czasie działania i daje dostęp do props i motywu. W TSX typ props stylów podajesz generykiem `styled.div<{...}>`, a prefiks `$` chroni DOM przed przekazaniem props stylów. Rozwiązania zero-runtime (vanilla-extract, Panda, StyleX) generują CSS przy budowaniu. Stylowane komponenty definiuj poza funkcjami komponentów.

Kryterium akceptacji: potrafisz przeczytać i przepisać komponent ze styled-components na CSS Modules, wskazać, gdzie biblioteka wstrzykuje style, i uzasadnić wybór podejścia do stylowania w nowym projekcie.
