#T INTRO Rozgrzewka i problem: dlaczego tyle projektów używa Tailwinda
Rozgrzewka: Czym są tokeny projektowe i dlaczego nazywamy je według znaczenia? Jak działa motyw ciemny przez `data-theme`?

Problem: w wielu projektach React, które spotkasz, zamiast plików CSS komponenty mają długie listy klas w stylu `flex items-center gap-2 rounded-lg border px-3 py-2`. To Tailwind CSS — najpopularniejsze dziś podejście do stylowania w ekosystemie React. W tej lekcji postawisz Tailwinda w osobnej gałęzi DevDesk i przepiszesz na niego jeden widok, żeby wiedzieć, jak z nim pracować i kiedy go wybrać.

#T DEFINITION Tailwind: klasy narzędziowe
Tailwind dostarcza tysiące małych klas, z których każda ustawia jedną rzecz: `p-4` (padding 1rem), `text-sm`, `bg-white`, `rounded-lg`, `flex`, `gap-2`. Zamiast pisać CSS w osobnym pliku, składasz wygląd z tych klas bezpośrednio w JSX. Narzędzie skanuje Twój kod i generuje CSS tylko dla klas, których faktycznie użyłeś, więc wynikowy plik jest mały.

Kluczowe elementy składni:
- **warianty stanu**: `hover:bg-gray-50`, `focus-visible:outline-2`, `disabled:opacity-50`,
- **responsywność**: `md:grid-cols-3` (od szerokości „md” wzwyż), podejście mobile-first,
- **tryb ciemny**: `dark:bg-slate-900`,
- **wartości dowolne**: `w-[220px]`, `grid-cols-[220px_1fr]`.

#T STEP_BY_STEP Instalacja w projekcie Vite (Tailwind 4)
1. Utwórz gałąź: `git checkout -b tailwind`.
2. Zainstaluj: `npm install tailwindcss @tailwindcss/vite`.
3. W `vite.config.js` (`.ts`) dodaj wtyczkę: `import tailwindcss from '@tailwindcss/vite'` i `plugins: [react(), tailwindcss()]`.
4. Na początku `src/index.css` dodaj linię `@import "tailwindcss";`.
5. Uruchom `npm run dev` i dodaj do dowolnego elementu klasę `text-red-600` — tekst zmieni kolor.
6. Zainstaluj rozszerzenie edytora „Tailwind CSS IntelliSense” — podpowiada nazwy klas i pokazuje wygenerowany CSS po najechaniu.

#T CODE_JSX StatCard w Tailwindzie (JSX)
```
// StatCard.jsx
export function StatCard({ label, value, hint }) {
  return (
    <div className="min-w-36 rounded-lg border border-gray-200 bg-white p-4 shadow-sm dark:border-slate-700 dark:bg-slate-800">
      <span className="text-sm text-gray-500 dark:text-slate-400">{label}</span>
      <strong className="mt-1 block text-2xl font-semibold">{value}</strong>
      {hint && <small className="text-xs text-gray-400">{hint}</small>}
    </div>
  );
}
```

#T CODE_TSX StatCard w Tailwindzie (TSX)
```
// StatCard.tsx
type StatCardProps = { label: string; value: number; hint?: string };

export function StatCard({ label, value, hint }: StatCardProps) {
  return (
    <div className="min-w-36 rounded-lg border border-gray-200 bg-white p-4 shadow-sm dark:border-slate-700 dark:bg-slate-800">
      <span className="text-sm text-gray-500 dark:text-slate-400">{label}</span>
      <strong className="mt-1 block text-2xl font-semibold">{value}</strong>
      {hint && <small className="text-xs text-gray-400">{hint}</small>}
    </div>
  );
}
```

#T NOTE JSX ↔ TSX — Tailwind a typy
Klasy Tailwinda to zwykłe teksty w `className`, więc TypeScript ich nie sprawdza — literówka `text-gray-50O` przejdzie w obu wersjach. Kontrolę nad klasami daje wtyczka edytora (podkreśla nieznane klasy) i Prettier z `prettier-plugin-tailwindcss` (sortuje klasy w stałej kolejności). Różnica JSX/TSX pojawia się dopiero przy wariantach komponentu: w TSX mapujesz unię literałów na zestaw klas i masz pewność, że każdy wariant ma klasy.

#T CODE_PRACTICAL Warianty przycisku: mapa wariant → klasy
Pełne nazwy klas muszą występować w kodzie dosłownie — Tailwind skanuje tekst plików i nie rozpozna klas sklejanych w locie (`bg-${color}-600`).
```
import clsx from 'clsx';
import type { ReactNode } from 'react';

type Variant = 'primary' | 'secondary' | 'danger';

const VARIANT_CLASSES: Record<Variant, string> = {
  primary: 'bg-blue-600 text-white hover:bg-blue-700',
  secondary: 'border border-gray-300 bg-white text-gray-800 hover:bg-gray-50',
  danger: 'bg-red-600 text-white hover:bg-red-700',
};

type ButtonProps = { variant?: Variant; children: ReactNode; onClick?: () => void };

export function Button({ variant = 'primary', children, onClick }: ButtonProps) {
  return (
    <button
      type="button"
      onClick={onClick}
      className={clsx(
        'rounded-md px-3 py-1.5 text-sm font-medium focus-visible:outline-2 focus-visible:outline-offset-2 disabled:opacity-50',
        VARIANT_CLASSES[variant],
      )}
    >
      {children}
    </button>
  );
}
```

#T DEFINITION Tokeny w Tailwindzie
W Tailwind 4 własne tokeny definiujesz w CSS dyrektywą `@theme`: `@theme { --color-brand: #2563eb; }` — od razu dostajesz klasy `bg-brand`, `text-brand`, `border-brand`. Tryb ciemny sterowany atrybutem (zamiast tylko ustawień systemu) włączasz własnym wariantem: `@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));`. Dzięki temu przełącznik motywu z poprzedniej lekcji działa także z klasami `dark:`.

#T CODE_BASIC Konfiguracja tokenów i trybu ciemnego w index.css
```
@import "tailwindcss";

@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));

@theme {
  --color-brand: #2563eb;
  --color-surface: #f9fafb;
  --radius-card: 8px;
}
```

#T STEP_BY_STEP Budujemy razem: dashboard w Tailwindzie
1. Na gałęzi `tailwind` przepisz `StatCard`, `Panel` i `Button` na klasy Tailwinda.
2. Układ `AppShell` zapisz klasami: `grid min-h-screen grid-cols-[220px_1fr] grid-rows-[56px_1fr]`.
3. Na wąskim ekranie panel boczny ma znikać: `hidden md:block` na `Sidebar` i `grid-cols-1 md:grid-cols-[220px_1fr]` na kontenerze.
4. Dodaj `@custom-variant dark` i sprawdź, że przełącznik motywu działa z klasami `dark:`.
5. Porównaj w DevTools rozmiar wygenerowanego CSS z wersją CSS Modules.
6. Zdecyduj, którą wersję zostawiasz w głównej gałęzi kursu. Lekcje kursu dalej pokazują CSS Modules — klasy Tailwinda możesz stosować równolegle we własnym projekcie.

#T PITFALL Klasy budowane dynamicznie
Tailwind generuje CSS tylko dla klas znalezionych w kodzie jako pełne teksty. `className={`text-${color}-600`}` nie zadziała dla żadnego koloru, bo w kodzie nie ma tekstu `text-red-600`. Rozwiązanie: mapa wariantów z pełnymi nazwami klas (jak w przykładzie Button) albo zmienna CSS ustawiana przez `style`.

#T CODE_WRONG Sklejana nazwa klasy
```
export function Dot({ color }) {
  return <span className={`h-2 w-2 rounded-full bg-${color}-500`} />;
}
```

#T CODE_RIGHT Pełne nazwy w mapie
```
const DOT = { green: 'bg-green-500', red: 'bg-red-500', gray: 'bg-gray-400' };

export function Dot({ color }) {
  return <span className={`h-2 w-2 rounded-full ${DOT[color]}`} />;
}
```

#T WHEN_TO_USE Tailwind czy CSS Modules
Tailwind: szybkie prototypowanie, spójność wymuszona skalą, brak przełączania między plikami, mały CSS wynikowy, ogromna popularność (biblioteki jak shadcn/ui są na nim oparte). Wady: długie listy klas w JSX, nowa „składnia” do nauki, trudniejsze czytanie kodu przez osoby, które go nie znają. CSS Modules: zwykły CSS, czysty JSX, łatwe dla osób znających CSS. Oba podejścia są w pełni profesjonalne — w zespole decyduje konwencja projektu.

#T SUMMARY Kryterium akceptacji i podsumowanie
Tailwind to klasy narzędziowe składane w `className`, z wariantami stanu (`hover:`), responsywności (`md:`) i trybu ciemnego (`dark:`). Instalacja w Vite: paczki `tailwindcss` i `@tailwindcss/vite`, wtyczka w konfiguracji i `@import "tailwindcss"`. Własne tokeny przez `@theme`. Klasy muszą występować w kodzie jako pełne teksty. TypeScript nie sprawdza klas, ale pomaga w mapowaniu wariantów.

Kryterium akceptacji: na gałęzi `tailwind` dashboard (karty, panele, przyciski i układ) działa na klasach Tailwinda, panel boczny chowa się na wąskim ekranie, a przełącznik motywu obsługuje klasy `dark:`.
