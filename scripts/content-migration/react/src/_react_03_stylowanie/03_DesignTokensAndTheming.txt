#T INTRO Rozgrzewka i problem: kolory rozsiane po plikach
Rozgrzewka: Jak CSS Modules zapobiegają kolizjom nazw? Jak połączyć dwie klasy modułowe warunkowo? Co robi `:global`?

Problem: kolor `#2563eb` występuje w DevDesk w czternastu plikach CSS, a odstępy to raz `12px`, raz `0.75rem`, raz `14px`. Projektant prosi o nowy odcień niebieskiego i o tryb ciemny. Bez wspólnego słownika wartości to godziny szukania. Rozwiązaniem są **tokeny projektowe** zapisane jako zmienne CSS.

#T DEFINITION Tokeny projektowe
Token to nazwana decyzja projektowa: „kolor główny”, „tło powierzchni”, „odstęp średni”, „promień zaokrąglenia”. Zapisujesz je raz jako zmienne CSS na `:root`, a w komponentach używasz tylko zmiennych, nigdy surowych wartości. Dobre tokeny mają nazwy według **znaczenia** (`--color-danger`, `--surface`), a nie wyglądu (`--red-500`) — wtedy zmiana motywu to zmiana wartości, a nie nazw.

#T CODE_BASIC Plik tokens.css
```
:root {
  --color-primary: #2563eb;
  --color-danger: #dc2626;
  --color-warning: #d97706;
  --color-success: #16a34a;

  --bg: #ffffff;
  --surface: #f9fafb;
  --text: #111827;
  --text-muted: #6b7280;
  --border: #e5e7eb;

  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --radius: 8px;
}

body { background: var(--bg); color: var(--text); }
```

#T CODE_PRACTICAL Motyw ciemny przez atrybut data-theme
Komponenty nie wiedzą nic o motywie — używają tych samych zmiennych, które zmieniają wartości.
```
[data-theme='dark'] {
  --bg: #0f172a;
  --surface: #1e293b;
  --text: #e5e7eb;
  --text-muted: #94a3b8;
  --border: #334155;
  --color-primary: #60a5fa;
}

/* domyślnie według ustawień systemu, jeśli użytkownik nie wybrał inaczej */
@media (prefers-color-scheme: dark) {
  :root:not([data-theme='light']) {
    --bg: #0f172a;
    --surface: #1e293b;
    --text: #e5e7eb;
    --text-muted: #94a3b8;
    --border: #334155;
    --color-primary: #60a5fa;
  }
}

/* Panel.module.css — tylko tokeny */
.panel { background: var(--surface); border: 1px solid var(--border); border-radius: var(--radius); }
```

#T CODE_JSX Przełącznik motywu (JSX)
Na razie bez zapamiętywania wyboru — zapis w localStorage dodasz w rozdziale o efektach. `useState` poznasz dokładnie w rozdziale 04; tu wystarczy wiedzieć, że przechowuje aktualny motyw.
```
// ThemeToggle.jsx
import { useState } from 'react';

export function ThemeToggle() {
  const [theme, setTheme] = useState('light');

  function toggle() {
    const next = theme === 'light' ? 'dark' : 'light';
    setTheme(next);
    document.documentElement.dataset.theme = next;
  }

  return (
    <button type="button" onClick={toggle} aria-label="Przełącz motyw">
      {theme === 'light' ? '🌙 Ciemny' : '☀️ Jasny'}
    </button>
  );
}
```

#T CODE_TSX Przełącznik motywu (TSX)
Typ `Theme` jako unia literałów — `setTheme('blue')` jest błędem. Zmiana atrybutu na `<html>` dzieje się w handlerze kliknięcia, czyli w dozwolonym miejscu na efekt uboczny.
```
// ThemeToggle.tsx
import { useState } from 'react';

export type Theme = 'light' | 'dark';

export function ThemeToggle() {
  const [theme, setTheme] = useState<Theme>('light');

  function toggle() {
    const next: Theme = theme === 'light' ? 'dark' : 'light';
    setTheme(next);
    document.documentElement.dataset.theme = next;
  }

  return (
    <button type="button" onClick={toggle} aria-label="Przełącz motyw">
      {theme === 'light' ? '🌙 Ciemny' : '☀️ Jasny'}
    </button>
  );
}
```

#T NOTE JSX ↔ TSX — typ motywu
W TSX `useState<Theme>('light')` wymaga podania typu jawnie: bez niego TypeScript wywnioskowałby typ `string` (bo `'light'` w `useState` traktuje jako zwykły tekst) i przepuścił `setTheme('blu')`. To pierwszy przykład zasady z rozdziału 01 w praktyce: generyk podajesz wtedy, gdy wartość startowa nie mówi wszystkiego. W JSX jedynym zabezpieczeniem jest logika `toggle`, która generuje tylko dwie wartości.

#T DEFINITION Skala odstępów i typografii
Oprócz kolorów tokenami opisuje się:
- **odstępy** — skala, np. 4 / 8 / 12 / 16 / 24 / 32 px; komponenty używają tylko wartości ze skali,
- **typografię** — rozmiary (`--font-sm`, `--font-md`, `--font-lg`), grubości, wysokość linii,
- **zaokrąglenia i cienie** — `--radius`, `--shadow-1`,
- **czas animacji** — `--duration-fast: 120ms`.

Skala ogranicza wybór i daje spójny wygląd bez dyskusji „12 czy 14 pikseli?”.

#T STEP_BY_STEP Budujemy razem: tokeny i tryb ciemny w DevDesk
1. Utwórz `src/styles/tokens.css` z tokenami z lekcji i zaimportuj go w `main.jsx` przed `index.css`.
2. Przejrzyj wszystkie pliki `.module.css` i zastąp surowe kolory i odstępy zmiennymi (`#e5e7eb` → `var(--border)`).
3. Dodaj blok `[data-theme='dark']` i regułę `prefers-color-scheme`.
4. Dodaj `ThemeToggle` w nagłówku aplikacji (`Header`).
5. Przełącz motyw — wszystkie panele, tabela i plakietki zmieniają kolory bez zmian w komponentach.
6. Zmień w systemie operacyjnym tryb na ciemny i przeładuj stronę bez klikania przełącznika — aplikacja powinna uruchomić się w ciemnym motywie.
7. Sprawdź kontrast tekstu `--text-muted` na `--surface` w obu motywach (np. narzędziem kontrastu w DevTools przeglądarki).

#T PITFALL Motyw przez warunki w każdym komponencie
Przekazywanie `theme` do każdego komponentu i pisanie `style={{ color: theme === 'dark' ? '#eee' : '#111' }}` mnoży kod, wymusza rendery całej aplikacji przy zmianie motywu i łatwo pominąć któryś komponent. Zmienne CSS zmieniają wygląd bez renderowania komponentów — przeglądarka przelicza style sama.

#T WHEN_TO_USE Kiedy wystarczą zmienne CSS
Zmienne CSS wystarczą do większości motywów: jasny/ciemny, kolory marki dla różnych klientów, gęstość interfejsu (`--space-*` mniejsze w trybie kompaktowym). Motyw w JavaScripcie (np. przez Context, rozdział 06) jest potrzebny dopiero wtedy, gdy wartości motywu są używane w logice — np. biblioteka wykresów wymaga kolorów jako tekstów w JS.

#T SUMMARY Kryterium akceptacji i podsumowanie
Tokeny projektowe to nazwane decyzje (kolory, odstępy, typografia) zapisane jako zmienne CSS na `:root`. Komponenty używają tylko zmiennych. Motyw ciemny to nadpisanie wartości zmiennych pod `[data-theme='dark']` i domyślnie według `prefers-color-scheme`. W TSX typ `Theme` jako unia literałów wymaga jawnego generyka w `useState`.

Kryterium akceptacji: w plikach `.module.css` DevDesk nie ma surowych kolorów, przełącznik w nagłówku zmienia motyw całej aplikacji, a przy ciemnym motywie systemu aplikacja startuje w ciemnym motywie.
