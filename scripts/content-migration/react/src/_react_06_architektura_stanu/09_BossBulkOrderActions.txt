#T INTRO Boss rozdziału 06: panel zamówień z akcjami zbiorczymi
Ten boss sprawdza projektowanie stanu: sam decydujesz, gdzie żyje każdy kawałek stanu, co jest wyliczane, jakie są akcje reducera i co trafia do kontekstu. Domena: panel obsługi zamówień w sklepie internetowym. Dane i wymagania są poniżej, struktura — po Twojej stronie.

#T DEFINITION Brief zadania
Panel „Zamówienia”:
1. **Lista zamówień** w tabeli: numer, klient, kwota, status (`NEW`, `PAID`, `SHIPPED`, `CANCELLED`), data.
2. **Zaznaczanie wielu** zamówień checkboxami, z checkboxem „zaznacz wszystkie widoczne” w stanie pośrednim.
3. **Akcje zbiorcze**: „Oznacz jako opłacone” (tylko z `NEW`), „Wyślij” (tylko z `PAID`), „Anuluj” (z `NEW` i `PAID`). Akcja pomija zamówienia, dla których przejście jest niedozwolone, i pokazuje podsumowanie: „Wysłano 3, pominięto 1”.
4. **Filtr statusu i wyszukiwanie** po kliencie, z licznikami przy statusach.
5. **Historia zmian**: każde przejście statusu dopisuje wpis `{ orderId, from, to, at }`; panel „Ostatnie zmiany” pokazuje 5 najnowszych.
6. **Cofnij ostatnią akcję zbiorczą** — przywraca statusy sprzed akcji.
7. **Preferencja waluty wyświetlania** (PLN / EUR po stałym kursie) dostępna w całym panelu przez kontekst.

#T CODE_JSX Dane startowe (JSX)
```
// data/orders.js
const CUSTOMERS = ['Lumen sp. z o.o.', 'Jan Kowalski', 'Orbis S.A.', 'Maria Wiśniewska', 'Zenit'];
const STATUSES = ['NEW', 'PAID', 'SHIPPED', 'CANCELLED'];

export const orders = Array.from({ length: 30 }, (_, i) => ({
  id: 1000 + i,
  customer: CUSTOMERS[i % CUSTOMERS.length],
  totalGrosze: 9900 + ((i * 4721) % 250000),
  status: STATUSES[i % 3 === 0 ? 0 : i % 3 === 1 ? 1 : (i % 7 === 0 ? 3 : 2)],
  createdAt: new Date(Date.UTC(2026, 9, 1 + (i % 20))).toISOString(),
}));
```

#T CODE_TSX Dane startowe (TSX)
```
// data/orders.ts
export type OrderStatus = 'NEW' | 'PAID' | 'SHIPPED' | 'CANCELLED';

export type Order = {
  id: number;
  customer: string;
  totalGrosze: number;
  status: OrderStatus;
  createdAt: string;
};

const CUSTOMERS = ['Lumen sp. z o.o.', 'Jan Kowalski', 'Orbis S.A.', 'Maria Wiśniewska', 'Zenit'];
const STATUSES: OrderStatus[] = ['NEW', 'PAID', 'SHIPPED', 'CANCELLED'];

export const orders: Order[] = Array.from({ length: 30 }, (_, i) => ({
  id: 1000 + i,
  customer: CUSTOMERS[i % CUSTOMERS.length],
  totalGrosze: 9900 + ((i * 4721) % 250000),
  status: STATUSES[i % 3 === 0 ? 0 : i % 3 === 1 ? 1 : (i % 7 === 0 ? 3 : 2)],
  createdAt: new Date(Date.UTC(2026, 9, 1 + (i % 20))).toISOString(),
}));
```

#T STEP_BY_STEP Kryteria akceptacji
1. Zamówienia, historia i „migawka do cofnięcia” są w jednym reducerze; wszystkie przejścia statusu przechodzą przez reducer.
2. Reguły dozwolonych przejść są w jednej strukturze danych (np. mapa „status → dozwolone statusy docelowe”), używanej i przez reducer, i do wyłączania przycisków akcji.
3. Zaznaczenie to zbiór ID; licznik zaznaczonych, „zaznacz wszystkie” i podsumowanie akcji są wyliczane.
4. Po akcji zbiorczej zaznaczenie jest czyszczone w tym samym zdarzeniu (bez efektu).
5. Filtry i wyszukiwanie są w lokalnym stanie ekranu (najlepiej we własnym hooku), nie w kontekście.
6. Waluta jest w osobnym kontekście z hookiem `useCurrency()`; zmiana waluty nie wymaga przekazywania props.
7. „Cofnij” przywraca dokładnie statusy sprzed ostatniej akcji zbiorczej i usuwa odpowiadające wpisy historii; po cofnięciu przycisk znika.
8. Reducer jest czysty: data wpisu historii przychodzi w akcji, a nie z `new Date()` wewnątrz reducera.
9. W wersji TSX: unia akcji z `never` w `default`, `Dispatch<OrdersAction>` w kontekście, `npm run build` bez błędów.

#T NOTE Wskazówka 1 — reguły przejść jako dane
`const TRANSITIONS = { NEW: ['PAID', 'CANCELLED'], PAID: ['SHIPPED', 'CANCELLED'], SHIPPED: [], CANCELLED: [] };` i funkcja `canTransition(from, to)`. W TSX typ: `Record<OrderStatus, OrderStatus[]>`. Przycisk „Wyślij” jest aktywny, gdy którekolwiek zaznaczone zamówienie może przejść do `SHIPPED`.

#T NOTE Wskazówka 2 — akcja zbiorcza i cofanie
Akcja `{ type: 'bulkTransitioned', ids, to, at }`. Reducer: dla każdego ID sprawdza `canTransition`, zmienia status dozwolonych, dopisuje wpisy historii i zapisuje w stanie `lastBulk: { previous: [{ id, status }], historyCount }`. Akcja `{ type: 'bulkUndone' }` przywraca statusy z `previous`, obcina historię i ustawia `lastBulk: null`. Podsumowanie „Wysłano 3, pominięto 1” wylicz w handlerze przed `dispatch` tą samą funkcją `canTransition`.

#T NOTE Wskazówka 3 — waluta w kontekście
Kontekst przechowuje `currency: 'PLN' | 'EUR'` i funkcję `format(grosze)`. Kurs stały, np. 1 EUR = 4,30 PLN. Formatowanie przez `Intl.NumberFormat('pl-PL', { style: 'currency', currency })`. Komponent komórki kwoty czyta `useCurrency()` — to jedyne miejsce, które wie o walucie.

#T CODE_PRACTICAL Przykładowe rozwiązanie — reducer (TSX)
Porównaj po samodzielnym spełnieniu kryteriów.
```
import type { Order, OrderStatus } from './data/orders';

export const TRANSITIONS: Record<OrderStatus, OrderStatus[]> = {
  NEW: ['PAID', 'CANCELLED'],
  PAID: ['SHIPPED', 'CANCELLED'],
  SHIPPED: [],
  CANCELLED: [],
};

export const canTransition = (from: OrderStatus, to: OrderStatus) => TRANSITIONS[from].includes(to);

type HistoryEntry = { orderId: number; from: OrderStatus; to: OrderStatus; at: string };

export type OrdersState = {
  orders: Order[];
  history: HistoryEntry[];
  lastBulk: { previous: { id: number; status: OrderStatus }[]; historyCount: number } | null;
};

export type OrdersAction =
  | { type: 'bulkTransitioned'; ids: number[]; to: OrderStatus; at: string }
  | { type: 'bulkUndone' };

export function ordersReducer(state: OrdersState, action: OrdersAction): OrdersState {
  switch (action.type) {
    case 'bulkTransitioned': {
      const affected = state.orders.filter((o) => action.ids.includes(o.id) && canTransition(o.status, action.to));
      const affectedIds = new Set(affected.map((o) => o.id));
      return {
        orders: state.orders.map((o) => (affectedIds.has(o.id) ? { ...o, status: action.to } : o)),
        history: [...affected.map((o) => ({ orderId: o.id, from: o.status, to: action.to, at: action.at })), ...state.history],
        lastBulk: { previous: affected.map((o) => ({ id: o.id, status: o.status })), historyCount: affected.length },
      };
    }
    case 'bulkUndone': {
      if (!state.lastBulk) return state;
      const previous = new Map(state.lastBulk.previous.map((p) => [p.id, p.status]));
      return {
        orders: state.orders.map((o) => (previous.has(o.id) ? { ...o, status: previous.get(o.id)! } : o)),
        history: state.history.slice(state.lastBulk.historyCount),
        lastBulk: null,
      };
    }
    default: {
      const unreachable: never = action;
      return unreachable;
    }
  }
}
```

#T PITFALL Typowe błędy w tym zadaniu
- Reguły przejść zapisane osobno w reducerze i w warunkach `disabled` przycisków — rozjadą się przy pierwszej zmianie.
- Zaznaczenie przechowywane jako tablica obiektów zamówień — po akcji zbiorczej statusy w zaznaczeniu są nieaktualne.
- Czyszczenie zaznaczenia w `useEffect` po zmianie listy zamówień — powinno być w handlerze akcji.
- Filtr i wyszukiwanie w kontekście — każde naciśnięcie klawisza renderuje cały panel, w tym komponenty czytające tylko walutę.
- `new Date()` w reducerze — w StrictMode dwa wywołania dadzą różne czasy w historii.

#T SUMMARY Podsumowanie rozdziału 06
W tym rozdziale nauczyłeś się projektować stan metodą Thinking in React, podnosić stan do wspólnego rodzica, utrzymywać jedno źródło prawdy, rozumieć zachowanie i reset stanu w drzewie, porządkować przejścia stanu reducerem, udostępniać dane kontekstem (także w połączeniu z reducerem) i wydzielać logikę do własnych hooków. W TSX: unie akcji z `never`, `Dispatch<Action>`, `createContext<T | null>`, generyczne hooki i `as const` dla krotek.

Boss zaliczony, gdy wszystkie dziewięć kryteriów akceptacji jest spełnionych w obu wersjach.
