#T INTRO Rozgrzewka i problem: ta sama logika w trzech ekranach
Rozgrzewka: Dlaczego `dispatch` trzymasz w osobnym kontekście? Gdzie powinien żyć stan wyszukiwania — w kontekście czy lokalnie? Co się stanie, gdy komponent użyje kontekstu bez providera?

Problem: ekrany „Tickety”, „Mój dzień” i „Archiwum” mają identyczną logikę: tekst wyszukiwania, filtr statusu, sortowanie, paginację i reset strony przy zmianie filtra. Kod jest skopiowany trzy razy i już się różni (w „Archiwum” zapomniano o resecie strony). **Własny hook** pozwala wydzielić logikę ze stanem do jednej funkcji i używać jej w wielu komponentach.

#T DEFINITION Własny hook
Własny hook to zwykła funkcja JavaScript, której nazwa zaczyna się od `use` i która wywołuje inne hooki (`useState`, `useReducer`, `useContext`, `useEffect`, inne własne hooki). Zwraca to, czego potrzebuje komponent: wartości, funkcje, dane wyliczane.

Kluczowa zasada: **hook współdzieli logikę, nie stan**. Każdy komponent, który wywoła `useTicketFilters()`, dostaje własną, niezależną kopię stanu — tak jak dwa wywołania `useState` w dwóch komponentach. Jeśli stan ma być wspólny, potrzebujesz podniesienia stanu albo kontekstu.

Hooki podlegają zasadom hooków: wywołuj je na najwyższym poziomie komponentu lub innego hooka.

#T CODE_JSX Hook useTicketFilters (JSX)
```
// useTicketFilters.js
import { useState } from 'react';
import { paginate } from './pagination';
import { sortTickets } from './sorting';

export function useTicketFilters(tickets, { pageSize = 10 } = {}) {
  const [query, setQueryState] = useState('');
  const [status, setStatusState] = useState('ALL');
  const [sort, setSort] = useState({ key: 'createdAt', direction: 'desc' });
  const [page, setPage] = useState(1);

  // zmiana filtra zawsze wraca na stronę 1 — w jednym miejscu dla wszystkich ekranów
  const setQuery = (q) => { setQueryState(q); setPage(1); };
  const setStatus = (s) => { setStatusState(s); setPage(1); };

  const q = query.trim().toLowerCase();
  const filtered = tickets.filter(
    (t) => (status === 'ALL' || t.status === status) && (!q || t.title.toLowerCase().includes(q)),
  );
  const result = paginate(sortTickets(filtered, sort), page, pageSize);

  return { query, setQuery, status, setStatus, sort, setSort, page: result.currentPage, setPage, total: filtered.length, ...result };
}
```

#T CODE_TSX Hook useTicketFilters (TSX)
Typ zwracany wynika z implementacji — TypeScript wyprowadzi go sam. Opcje przyjmujesz obiektem z wartościami domyślnymi.
```
// useTicketFilters.ts
import { useState } from 'react';
import type { Ticket, TicketStatus } from '../types';
import { paginate } from './pagination';
import { sortTickets, type SortState } from './sorting';

type StatusFilter = TicketStatus | 'ALL';

export function useTicketFilters(tickets: readonly Ticket[], { pageSize = 10 }: { pageSize?: number } = {}) {
  const [query, setQueryState] = useState('');
  const [status, setStatusState] = useState<StatusFilter>('ALL');
  const [sort, setSort] = useState<SortState>({ key: 'createdAt', direction: 'desc' });
  const [page, setPage] = useState(1);

  const setQuery = (q: string) => { setQueryState(q); setPage(1); };
  const setStatus = (s: StatusFilter) => { setStatusState(s); setPage(1); };

  const q = query.trim().toLowerCase();
  const filtered = tickets.filter(
    (t) => (status === 'ALL' || t.status === status) && (!q || t.title.toLowerCase().includes(q)),
  );
  const result = paginate(sortTickets(filtered, sort), page, pageSize);

  return { query, setQuery, status, setStatus, sort, setSort, page: result.currentPage, setPage, total: filtered.length, ...result };
}
```

#T NOTE JSX ↔ TSX — typ wyniku hooka
W TSX nie musisz pisać typu zwracanego obiektu — TypeScript wyprowadzi go z `return`, a komponenty dostaną podpowiedzi `filters.query`, `filters.setStatus` itd. Jeśli hook jest częścią publicznego API (np. biblioteki zespołu), warto typ zapisać jawnie (`type TicketFilters = ReturnType<typeof useTicketFilters>`), żeby zmiana implementacji nie zmieniała po cichu kontraktu. W JSX zwracany obiekt jest dokumentowany wyłącznie przez kod — dobrą praktyką jest komentarz JSDoc nad hookiem.

#T CODE_BASIC Ten sam hook w dwóch ekranach
Każdy ekran ma własny, niezależny stan filtrów — wyszukiwanie w „Archiwum” nie wpływa na „Tickety”.
```
import { useTicketFilters } from './useTicketFilters';
import { useTickets } from './TicketsContext';

export function TicketsPage() {
  const { tickets } = useTickets();
  const f = useTicketFilters(tickets);
  return (
    <section>
      <input aria-label="Szukaj" value={f.query} onChange={(e) => f.setQuery(e.target.value)} />
      <p>Znaleziono {f.total}, strona {f.page} z {f.pageCount}</p>
      <ul>{f.pageItems.map((t) => <li key={t.id}>{t.title}</li>)}</ul>
    </section>
  );
}

export function ArchivePage() {
  const { tickets } = useTickets();
  const f = useTicketFilters(tickets.filter((t) => t.status === 'CLOSED'), { pageSize: 25 });
  return <p>Archiwum: {f.total} ticketów</p>;
}
```

#T CODE_PRACTICAL Małe hooki ogólnego użytku
Hooki nie muszą być duże. `useToggle` i `useLocalStorageState` przydadzą się w wielu miejscach (efekty w drugim — dokładnie w rozdziale 07).
```
import { useEffect, useState } from 'react';

export function useToggle(initial = false) {
  const [on, setOn] = useState(initial);
  const toggle = () => setOn((v) => !v);
  return [on, toggle] as const;
}

export function useLocalStorageState<T>(key: string, initial: T) {
  const [value, setValue] = useState<T>(() => {
    try {
      const raw = localStorage.getItem(key);
      return raw === null ? initial : (JSON.parse(raw) as T);
    } catch {
      return initial;
    }
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);

  return [value, setValue] as const;
}
```

#T NOTE Krotka czy obiekt jako wynik hooka
`useToggle` zwraca krotkę `[wartość, funkcja]` (jak `useState`) — wygodną, gdy hook zwraca 2 elementy i użytkownik chce nadać im własne nazwy. `as const` w TSX sprawia, że typ wyniku to `readonly [boolean, () => void]`, a nie tablica `(boolean | (() => void))[]`. Przy więcej niż 2–3 wartościach zwracaj obiekt (jak `useTicketFilters`) — nazwy pól są czytelniejsze niż pozycje. `useLocalStorageState` jest generyczny: `useLocalStorageState('density', 'compact')` daje stan typu `string`, a z jawnym `<'compact' | 'comfortable'>` — unii. Uwaga: `JSON.parse(raw) as T` to rzutowanie — dla ważnych danych waliduj schematem (lekcja o Zod).

#T STEP_BY_STEP Budujemy razem: wydzielenie logiki ekranów
1. Utwórz `useTicketFilters` i przenieś do niego stan i logikę filtrów, sortowania i paginacji z `Main`.
2. Przepisz ekran „Tickety” na hook — komponent powinien skurczyć się do kilku linii JSX.
3. Dodaj ekran „Archiwum” (tylko zamknięte, 25 na stronę) korzystający z tego samego hooka.
4. Przenieś `useSelection` z poprzedniej lekcji do osobnego pliku `hooks/useSelection` (to też własny hook).
5. Utwórz `useToggle` i użyj go do rozwijania opisu w karcie oraz do przełącznika widoku.
6. Sprawdź niezależność: wpisz tekst w wyszukiwarce „Ticketów”, przejdź do „Archiwum” — tam wyszukiwarka jest pusta.
7. W React DevTools zobacz, że hooki własne są widoczne pod nazwą (np. `TicketFilters`) z zagnieżdżonymi stanami.

#T PITFALL Funkcja z nazwą use bez hooków — i hook bez nazwy use
Funkcja `useFormatDate(iso)`, która nie wywołuje żadnego hooka, nie jest hookiem — nazwa wprowadza w błąd i niepotrzebnie nakłada zasady hooków (nie można jej wywołać w warunku). Nazwij ją `formatDate`. Odwrotnie: funkcja wywołująca `useState`, ale nazwana `getFilters`, nie zostanie sprawdzona przez ESLint pod kątem zasad hooków — łatwo wywołasz ją w pętli i zepsujesz stan.

#T WHEN_TO_USE Kiedy wydzielić hook
Wydziel hook, gdy ta sama logika ze stanem lub efektem pojawia się w więcej niż jednym komponencie, gdy komponent ma tyle logiki, że JSX ginie wśród stanów i handlerów, albo gdy chcesz nazwać i odizolować jeden aspekt (np. „połączenie z WebSocketem”, „wybór zaznaczenia”). Nie wydzielaj hooka dla jednej linii `useState` — „hook dla hooka” tylko dodaje plik.

#T SUMMARY Kryterium akceptacji i podsumowanie
Własny hook to funkcja `useX`, która wywołuje inne hooki i zwraca wartości oraz funkcje. Współdzieli logikę, nie stan — każde wywołanie ma własny stan. Wynik zwracaj jako krotkę (2 elementy, `as const` w TSX) lub obiekt (więcej elementów). Funkcje bez hooków nie mają przedrostka `use`. W TSX typ wyniku wyprowadza się sam, a hooki mogą być generyczne (`useLocalStorageState<T>`).

Kryterium akceptacji: ekrany „Tickety” i „Archiwum” korzystają z jednego hooka `useTicketFilters` i mają niezależne filtry, reset strony przy zmianie filtra jest w jednym miejscu, a `useToggle` i `useSelection` są osobnymi hookami użytymi w kilku komponentach.
