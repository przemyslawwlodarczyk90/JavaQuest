#T INTRO Trening: Context i własne hooki
Context rozwiązuje problem **przekazywania** danych przez wiele poziomów, a własne hooki — problem **powtarzania** logiki stanowej w wielu komponentach. Oba mechanizmy łatwo nadużyć: Context zamienia się w globalny worek na wszystko, a hook — w funkcję, po której ktoś oczekuje współdzielonego stanu, choć każdy komponent dostaje własny.

Ten trening to dwanaście zadań: sześć o Context (Provider, hook-strażnik, domyślna wartość, zagnieżdżanie, kontekst z reducerem, rerendery) i sześć o hookach (`useToggle`, `useCounter`, `useLocalStorage`, `useDebounce`, `useForm`, hook nad kontekstem). Pracuj tak samo: najpierw sam w `.jsx`, potem `.tsx`, potem porównanie.

Uwaga: w zadaniach 9 i 12 pojawia się `useEffect` — w pełni omawiamy go w rozdziale 07. Tu wystarczy wiedzieć, że uruchamia kod **po** renderze i może zwrócić funkcję sprzątającą.

#T STEP_BY_STEP Zadanie 1 — pierwszy kontekst: motyw jasny i ciemny
Napisz `ThemeContext` i trzy komponenty na różnych głębokościach, które z niego korzystają.

Wymagania:
1. `ThemeProvider` trzyma stan `theme` (`'light' | 'dark'`) i udostępnia `{ theme, toggleTheme }`.
2. `App` → `Layout` → `Toolbar` → `ThemeButton`: tylko `ThemeButton` i `Page` czytają kontekst; `Layout` i `Toolbar` **nie** dostają motywu w props.
3. `Page` ustawia `className={`page page--${theme}`}`.
4. `ThemeButton` pokazuje „🌙 Ciemny” lub „☀ Jasny” i przełącza motyw.

Sprawdź się: z `Layout` i `Toolbar` nie da się wyczytać, że w aplikacji istnieje motyw — nie ma prop drillingu.

#T CODE_JSX Rozwiązanie 1 (JSX)
```
// ThemeContext.jsx
import { createContext, useContext, useState } from 'react';

export const ThemeContext = createContext(null);

export function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light');
  const toggleTheme = () => setTheme((t) => (t === 'light' ? 'dark' : 'light'));

  return <ThemeContext value={{ theme, toggleTheme }}>{children}</ThemeContext>;
}

export function ThemeButton() {
  const { theme, toggleTheme } = useContext(ThemeContext);
  return (
    <button type="button" onClick={toggleTheme}>
      {theme === 'light' ? '🌙 Ciemny' : '☀ Jasny'}
    </button>
  );
}

function Toolbar() {
  return <header className="toolbar"><ThemeButton /></header>;
}

function Page({ children }) {
  const { theme } = useContext(ThemeContext);
  return <main className={`page page--${theme}`}>{children}</main>;
}

function Layout({ children }) {
  return (
    <>
      <Toolbar />
      <Page>{children}</Page>
    </>
  );
}

export function App() {
  return (
    <ThemeProvider>
      <Layout><p>Treść strony</p></Layout>
    </ThemeProvider>
  );
}
```

#T CODE_TSX Rozwiązanie 1 (TSX)
```
// ThemeContext.tsx
import { createContext, useContext, useState, type ReactNode } from 'react';

type Theme = 'light' | 'dark';
type ThemeContextValue = { theme: Theme; toggleTheme: () => void };

export const ThemeContext = createContext<ThemeContextValue | null>(null);

export function ThemeProvider({ children }: { children: ReactNode }) {
  const [theme, setTheme] = useState<Theme>('light');
  const toggleTheme = () => setTheme((t) => (t === 'light' ? 'dark' : 'light'));

  return <ThemeContext value={{ theme, toggleTheme }}>{children}</ThemeContext>;
}

export function ThemeButton() {
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error('ThemeButton musi być wewnątrz ThemeProvider');
  return (
    <button type="button" onClick={ctx.toggleTheme}>
      {ctx.theme === 'light' ? '🌙 Ciemny' : '☀ Jasny'}
    </button>
  );
}

function Toolbar() {
  return <header className="toolbar"><ThemeButton /></header>;
}

function Page({ children }: { children: ReactNode }) {
  const ctx = useContext(ThemeContext);
  return <main className={`page page--${ctx?.theme ?? 'light'}`}>{children}</main>;
}

function Layout({ children }: { children: ReactNode }) {
  return (
    <>
      <Toolbar />
      <Page>{children}</Page>
    </>
  );
}

export function App() {
  return (
    <ThemeProvider>
      <Layout><p>Treść strony</p></Layout>
    </ThemeProvider>
  );
}
```

#T NOTE ThemeContext jako Provider w React 19
Od React 19 kontekst renderujesz bezpośrednio: `<ThemeContext value={…}>`. W starszym kodzie zobaczysz `<ThemeContext.Provider value={…}>` — działa tak samo i nadal jest wspierane. W TSX `createContext<ThemeContextValue | null>(null)` zmusza do obsługi braku Providera przy każdym odczycie — stąd `if (!ctx) throw` i `ctx?.theme`. To powtarzalne, więc w zadaniu 2 zamkniesz to w hooku.

#T STEP_BY_STEP Zadanie 2 — hook-strażnik: useTheme

#T CODE_BASIC Zadanie 3 — przewidź wynik: domyślna wartość i najbliższy Provider
`SizeContext` utworzono przez `createContext('medium')`. Komponent `Label` wyświetla `useContext(SizeContext)`. Co pokaże każdy `Label`?
```
// @check-skip
const SizeContext = createContext('medium');

<>
  <Label />                                   {/* A */}
  <SizeContext value="large">
    <Label />                                 {/* B */}
    <SizeContext value="small">
      <Label />                               {/* C */}
    </SizeContext>
    <Label />                                 {/* D */}
  </SizeContext>
  <SizeContext value={undefined}>
    <Label />                                 {/* E */}
  </SizeContext>
</>
```

#T NOTE Odpowiedź do zadania 3
- **A — medium.** Brak Providera nad komponentem → wartość domyślna z `createContext`.
- **B — large.** Najbliższy Provider nad komponentem.
- **C — small.** Wewnętrzny Provider przesłania zewnętrzny dla swojego poddrzewa.
- **D — large.** Wewnętrzny Provider obejmuje tylko swoje dzieci; rodzeństwo widzi zewnętrzny.
- **E — undefined.** Domyślna wartość działa **tylko** przy braku Providera. Provider z `value={undefined}` przekazuje dokładnie `undefined`. To częsty błąd, gdy wartość Providera pochodzi z ładowanych danych.

#T STEP_BY_STEP Zadanie 4 — kontekst z reducerem: koszyk dla całej aplikacji
Połącz `useReducer` z Context, żeby lista produktów, ikona w nagłówku i strona koszyka korzystały z tego samego koszyka.

Wymagania:
1. Reducer koszyka: akcje `added` (produkt), `removed` (id), `cleared`. Stan: tablica pozycji `{ id, name, price, qty }`; dodanie istniejącego produktu zwiększa `qty`.
2. **Dwa** konteksty: `CartStateContext` (stan) i `CartDispatchContext` (dispatch) — oba w jednym `CartProvider`.
3. Hooki `useCart()` i `useCartDispatch()` ze strażnikiem.
4. Komponenty: `AddToCartButton` (tylko dispatch), `CartBadge` (liczba sztuk — wyliczona), `CartSummary` (lista i suma).

Sprawdź się: `AddToCartButton` nie czyta stanu koszyka — korzysta wyłącznie z `useCartDispatch`.

#T CODE_JSX Rozwiązanie 4 (JSX)
```
// cart.jsx
import { createContext, useContext, useReducer } from 'react';

function cartReducer(items, action) {
  switch (action.type) {
    case 'added': {
      const existing = items.find((i) => i.id === action.product.id);
      return existing
        ? items.map((i) => (i.id === action.product.id ? { ...i, qty: i.qty + 1 } : i))
        : [...items, { ...action.product, qty: 1 }];
    }
    case 'removed':
      return items.filter((i) => i.id !== action.id);
    case 'cleared':
      return [];
    default:
      throw new Error(`Nieznana akcja: ${action.type}`);
  }
}

const CartStateContext = createContext(null);
const CartDispatchContext = createContext(null);

export function CartProvider({ children }) {
  const [items, dispatch] = useReducer(cartReducer, []);
  return (
    <CartStateContext value={items}>
      <CartDispatchContext value={dispatch}>{children}</CartDispatchContext>
    </CartStateContext>
  );
}

export function useCart() {
  const items = useContext(CartStateContext);
  if (!items) throw new Error('useCart musi być użyty wewnątrz <CartProvider>');
  return items;
}

export function useCartDispatch() {
  const dispatch = useContext(CartDispatchContext);
  if (!dispatch) throw new Error('useCartDispatch musi być użyty wewnątrz <CartProvider>');
  return dispatch;
}

export function AddToCartButton({ product }) {
  const dispatch = useCartDispatch();
  return <button type="button" onClick={() => dispatch({ type: 'added', product })}>Do koszyka</button>;
}

export function CartBadge() {
  const count = useCart().reduce((sum, i) => sum + i.qty, 0);
  return <span className="badge" aria-label={`Koszyk: ${count} szt.`}>🛒 {count}</span>;
}

export function CartSummary() {
  const items = useCart();
  const dispatch = useCartDispatch();
  const total = items.reduce((sum, i) => sum + i.price * i.qty, 0);

  return (
    <section>
      <ul>
        {items.map((i) => (
          <li key={i.id}>
            {i.name} × {i.qty}
            <button type="button" onClick={() => dispatch({ type: 'removed', id: i.id })}>Usuń</button>
          </li>
        ))}
      </ul>
      <p>Razem: {total} zł</p>
      <button type="button" disabled={items.length === 0} onClick={() => dispatch({ type: 'cleared' })}>Wyczyść</button>
    </section>
  );
}
```

#T CODE_TSX Rozwiązanie 4 (TSX)
```
// cart.tsx
import { createContext, useContext, useReducer, type Dispatch, type ReactNode } from 'react';

type Product = { id: string; name: string; price: number };
type CartItem = Product & { qty: number };
type CartAction = { type: 'added'; product: Product } | { type: 'removed'; id: string } | { type: 'cleared' };

function cartReducer(items: CartItem[], action: CartAction): CartItem[] {
  switch (action.type) {
    case 'added': {
      const existing = items.find((i) => i.id === action.product.id);
      return existing
        ? items.map((i) => (i.id === action.product.id ? { ...i, qty: i.qty + 1 } : i))
        : [...items, { ...action.product, qty: 1 }];
    }
    case 'removed':
      return items.filter((i) => i.id !== action.id);
    case 'cleared':
      return [];
  }
}

const CartStateContext = createContext<CartItem[] | null>(null);
const CartDispatchContext = createContext<Dispatch<CartAction> | null>(null);

export function CartProvider({ children }: { children: ReactNode }) {
  const [items, dispatch] = useReducer(cartReducer, []);
  return (
    <CartStateContext value={items}>
      <CartDispatchContext value={dispatch}>{children}</CartDispatchContext>
    </CartStateContext>
  );
}

export function useCart(): CartItem[] {
  const items = useContext(CartStateContext);
  if (!items) throw new Error('useCart musi być użyty wewnątrz <CartProvider>');
  return items;
}

export function useCartDispatch(): Dispatch<CartAction> {
  const dispatch = useContext(CartDispatchContext);
  if (!dispatch) throw new Error('useCartDispatch musi być użyty wewnątrz <CartProvider>');
  return dispatch;
}

export function AddToCartButton({ product }: { product: Product }) {
  const dispatch = useCartDispatch();
  return <button type="button" onClick={() => dispatch({ type: 'added', product })}>Do koszyka</button>;
}

export function CartBadge() {
  const count = useCart().reduce((sum, i) => sum + i.qty, 0);
  return <span className="badge" aria-label={`Koszyk: ${count} szt.`}>🛒 {count}</span>;
}

export function CartSummary() {
  const items = useCart();
  const dispatch = useCartDispatch();
  const total = items.reduce((sum, i) => sum + i.price * i.qty, 0);

  return (
    <section>
      <ul>
        {items.map((i) => (
          <li key={i.id}>
            {i.name} × {i.qty}
            <button type="button" onClick={() => dispatch({ type: 'removed', id: i.id })}>Usuń</button>
          </li>
        ))}
      </ul>
      <p>Razem: {total} zł</p>
      <button type="button" disabled={items.length === 0} onClick={() => dispatch({ type: 'cleared' })}>Wyczyść</button>
    </section>
  );
}
```

#T CODE_BASIC Zadanie 5 — przewidź wynik: kto się przerenderuje
`UserProvider` trzyma `user` i `theme` w jednym kontekście. Użytkownik zmienia motyw. Które komponenty się przerenderują? Co zmieni się po rozdzieleniu kontekstów albo po `memo`?
```
// @check-skip
function AppProvider({ children }) {
  const [user, setUser] = useState({ name: 'Ola' });
  const [theme, setTheme] = useState('light');
  return (
    <AppContext value={{ user, setUser, theme, setTheme }}>
      {children}
    </AppContext>
  );
}

function Avatar() {            // czyta tylko user
  const { user } = useContext(AppContext);
  return <span>{user.name}</span>;
}

function ThemeToggle() {       // czyta theme i setTheme
  const { theme, setTheme } = useContext(AppContext);
  return <button onClick={() => setTheme(theme === 'light' ? 'dark' : 'light')}>{theme}</button>;
}

function Footer() {            // nie czyta kontekstu
  return <footer>© 2026</footer>;
}

<AppProvider>
  <Avatar />
  <ThemeToggle />
  <Footer />
</AppProvider>
```

#T NOTE Odpowiedź do zadania 5
- **Avatar — tak**, choć czyta tylko `user`. Wartość kontekstu to nowy obiekt przy każdym renderze `AppProvider`, a React rerenderuje **wszystkich** konsumentów kontekstu, gdy `value` zmieni referencję. Nie da się „subskrybować” jednego pola.
- **ThemeToggle — tak**, i słusznie.
- **Footer — nie.** Jest przekazany jako `children`, czyli element utworzony przez komponent wyżej. Zmiana stanu w `AppProvider` nie tworzy go na nowo, a sam nie czyta kontekstu.

Poprawki: (1) rozdziel konteksty (`UserContext`, `ThemeContext`) — wtedy zmiana motywu nie dotyka `Avatar`; (2) ustabilizuj `value` (`useMemo`), żeby rerender Providera z innego powodu nie zmieniał referencji. Pamiętaj jednak: dodatkowy render małego komponentu jest tani — poprawiaj, gdy profiler pokazuje problem (rozdział 16).

#T STEP_BY_STEP Zadanie 6 — kontekst ustawień z kilkoma polami
Napisz kontekst preferencji DevDesk z trzema niezależnymi ustawieniami: `density` (`'compact' | 'comfortable'`), `language` (`'pl' | 'en'`), `showClosed` (boolean).

Wymagania:
1. Jeden stan-obiekt w `PreferencesProvider` i funkcja `setPreference(key, value)`.
2. `value` kontekstu ustabilizowane przez `useMemo` (zależności: stan).
3. Hook `usePreferences()` ze strażnikiem.
4. Panel ustawień (`PreferencesPanel`) z selectami i checkboxem — wszystko przez `setPreference`.

Sprawdź się: w TSX `setPreference('density', 'huge')` i `setPreference('showClosed', 'yes')` są błędami kompilacji.

#T CODE_JSX Rozwiązanie 6 (JSX)
```
// preferences.jsx
import { createContext, useContext, useMemo, useState } from 'react';

const DEFAULTS = { density: 'comfortable', language: 'pl', showClosed: false };
const PreferencesContext = createContext(null);

export function PreferencesProvider({ children }) {
  const [prefs, setPrefs] = useState(DEFAULTS);

  const value = useMemo(
    () => ({ prefs, setPreference: (key, val) => setPrefs((p) => ({ ...p, [key]: val })) }),
    [prefs],
  );

  return <PreferencesContext value={value}>{children}</PreferencesContext>;
}

export function usePreferences() {
  const ctx = useContext(PreferencesContext);
  if (!ctx) throw new Error('usePreferences musi być użyty wewnątrz <PreferencesProvider>');
  return ctx;
}

export function PreferencesPanel() {
  const { prefs, setPreference } = usePreferences();
  return (
    <fieldset>
      <legend>Preferencje</legend>
      <label>
        Gęstość
        <select value={prefs.density} onChange={(e) => setPreference('density', e.target.value)}>
          <option value="comfortable">Wygodna</option>
          <option value="compact">Zwarta</option>
        </select>
      </label>
      <label>
        Język
        <select value={prefs.language} onChange={(e) => setPreference('language', e.target.value)}>
          <option value="pl">Polski</option>
          <option value="en">English</option>
        </select>
      </label>
      <label>
        <input type="checkbox" checked={prefs.showClosed} onChange={(e) => setPreference('showClosed', e.target.checked)} />
        Pokazuj zamknięte tickety
      </label>
    </fieldset>
  );
}
```

```
  setPreference: <K extends keyof Preferences>(key: K, value: Preferences[K]) => void;

          <option value="compact">Zwarta</option>
        </select>
      </label>
      <label>
        Język
        <select value={prefs.language} onChange={(e) => setPreference('language', e.target.value as Preferences['language'])}>
          <option value="pl">Polski</option>
          <option value="en">English</option>
        </select>
      </label>
      <label>
        <input type="checkbox" checked={prefs.showClosed} onChange={(e) => setPreference('showClosed', e.target.checked)} />

      </label>
```

#T NOTE JSX ↔ TSX — setter z kluczem i typem wartości
Sygnatura `<K extends keyof Preferences>(key: K, value: Preferences[K]) => void` wiąże typ wartości z kluczem: dla `'showClosed'` wartość musi być `boolean`, dla `'density'` — jedną z dwóch nazw. To ten sam wzorzec, którego użyjesz w hookach formularzy. W JSX setter przyjmie wszystko — `setPreference('showClosed', 'false')` zapisze **tekst** `'false'`, który w warunku jest prawdą.

#T STEP_BY_STEP Zadanie 7 — pierwszy własny hook: useToggle
Masz w aplikacji kilka przełączników: modal, panel boczny, podgląd hasła. Każdy ma `useState(false)` i trzy funkcje. Wydziel to.

Wymagania:
1. `useToggle(initial = false)` zwraca `[value, { toggle, setOn, setOff }]`.
2. Funkcje używają formy funkcyjnej settera.
3. Użyj hooka w `PasswordField` (pokaż/ukryj hasło) i w `Sidebar` (rozwiń/zwiń) — w jednym komponencie `Settings`.
4. Sprawdź, że przełączenie hasła nie zmienia panelu bocznego.

Sprawdź się: dwa wywołania `useToggle` dają dwa niezależne stany — hook współdzieli **logikę**, nie **stan**.

#T CODE_JSX Rozwiązanie 7 (JSX)
```
// useToggle.js
import { useState } from 'react';

export function useToggle(initial = false) {
  const [value, setValue] = useState(initial);
  const toggle = () => setValue((v) => !v);
  const setOn = () => setValue(true);
  const setOff = () => setValue(false);
  return [value, { toggle, setOn, setOff }];
}
```

#T CODE_TSX Rozwiązanie 7 (TSX)
```
// useToggle.ts
import { useState } from 'react';

type ToggleActions = { toggle: () => void; setOn: () => void; setOff: () => void };

export function useToggle(initial = false): [boolean, ToggleActions] {
  const [value, setValue] = useState(initial);
  const toggle = () => setValue((v) => !v);
  const setOn = () => setValue(true);
  const setOff = () => setValue(false);
  return [value, { toggle, setOn, setOff }];
}
```

```
      <button type="button" aria-expanded={sidebarOpen} onClick={sidebar.toggle}>Panel</button>
      {sidebarOpen && <aside>Menu ustawień</aside>}
      <label>
        Hasło
        <input type={showPassword ? 'text' : 'password'} autoComplete="current-password" />
      </label>
```

#T NOTE JSX ↔ TSX — krotka jako typ zwracany
Bez adnotacji `: [boolean, ToggleActions]` TypeScript wywnioskowałby typ `(boolean | ToggleActions)[]` — tablicę, w której każdy element może być jednym z dwóch typów, i `password.toggle` byłby błędem. Jawna krotka (albo `return [value, actions] as const`) mówi: pierwszy element to `boolean`, drugi to obiekt akcji. W JSX destrukturyzacja działa bez tego, ale IDE nie podpowie, co jest pod którym indeksem.

#T STEP_BY_STEP Zadanie 8 — hook z opcjami: useCounter
Napisz `useCounter` przyjmujący obiekt opcji.

Wymagania:
1. `useCounter({ initial = 0, min = -Infinity, max = Infinity, step = 1 } = {})`.
2. Zwraca obiekt `{ count, increment, decrement, reset, set, canIncrement, canDecrement }`.
3. `set(value)` przycina wartość do zakresu.
4. `canIncrement` / `canDecrement` — wyliczane.
5. Użyj go dwa razy w jednym komponencie: liczba dorosłych (1–6) i dzieci (0–4) w formularzu rezerwacji, z sumą osób pod spodem.

Sprawdź się: komponent rezerwacji nie zawiera ani jednego `Math.min` / `Math.max` — cała logika zakresu jest w hooku.

#T CODE_JSX Rozwiązanie 8 (JSX)
```
// useCounter.js
import { useState } from 'react';

export function useCounter({ initial = 0, min = -Infinity, max = Infinity, step = 1 } = {}) {
  const clamp = (v) => Math.min(max, Math.max(min, v));
  const [count, setCount] = useState(() => clamp(initial));

  return {
    count,
    increment: () => setCount((c) => clamp(c + step)),
    decrement: () => setCount((c) => clamp(c - step)),
    reset: () => setCount(clamp(initial)),
    set: (value) => setCount(clamp(value)),
    canIncrement: count + step <= max,
    canDecrement: count - step >= min,
  };
}
```

#T STEP_BY_STEP Zadanie 9 — hook z efektem: useLocalStorage
Napisz hook działający jak `useState`, ale zapamiętujący wartość w `localStorage`.

Wymagania:
1. `useLocalStorage(key, initialValue)` zwraca `[value, setValue]` — ten sam kontrakt co `useState` (setter przyjmuje wartość albo funkcję).
2. Odczyt z `localStorage` w leniwej inicjalizacji (`JSON.parse`, z `try / catch` — uszkodzony wpis daje `initialValue`).
3. Zapis w `useEffect` po każdej zmianie `value` (zależności: `key`, `value`).
4. Użyj hooka do zapamiętania `density` z zadania 6 i ostatnio otwartej zakładki.

Sprawdź się: odświeżenie strony przywraca wartości, a ręczne wpisanie do `localStorage` tekstu „{zepsuty” nie wysypuje aplikacji.

#T CODE_JSX Rozwiązanie 9 (JSX)
```
// useLocalStorage.js
import { useEffect, useState } from 'react';

export function useLocalStorage(key, initialValue) {
  const [value, setValue] = useState(() => {
    try {
      const saved = localStorage.getItem(key);
      return saved === null ? initialValue : JSON.parse(saved);
    } catch {
      return initialValue;
    }
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);

  return [value, setValue];
}
```

#T CODE_TSX Rozwiązanie 9 (TSX)
```
// useLocalStorage.ts
import { useEffect, useState, type Dispatch, type SetStateAction } from 'react';

export function useLocalStorage<T>(key: string, initialValue: T): [T, Dispatch<SetStateAction<T>>] {
  const [value, setValue] = useState<T>(() => {
    try {
      const saved = localStorage.getItem(key);
      return saved === null ? initialValue : (JSON.parse(saved) as T);
    } catch {
      return initialValue;
    }
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);

  return [value, setValue];
}
```

#T STEP_BY_STEP Zadanie 10 — przewidź wynik: czy hooki współdzielą stan
Dwa komponenty używają tego samego hooka `useCounter()`. Kliknięcie „+” w `A` — co pokaże `B`? A co, jeśli przeniesiesz `useState` poza funkcję hooka (na poziom modułu)?
```
// @check-skip
function A() {
  const { count, increment } = useCounter();
  return <button onClick={increment}>A: {count}</button>;
}

function B() {
  const { count } = useCounter();
  return <p>B: {count}</p>;
}

// Wariant 2 — "współdzielony" stan:
let shared = 0;
function useSharedCounter() {
  return { count: shared, increment: () => { shared++; } };
}
```

#T NOTE Odpowiedź do zadania 10
- **Wariant 1** — `B` pokazuje dalej 0. Każde wywołanie hooka to osobne wywołanie `useState` w osobnym komponencie, więc osobny stan. Hook to przepis na logikę, a nie magazyn.
- **Wariant 2** — kliknięcie zmienia zmienną modułu, ale nic nie mówi Reactowi, że ma renderować: `A` i `B` nadal pokazują 0, dopóki coś innego nie wywoła renderu. Do tego zmienna jest wspólna dla wszystkich instancji, testów i (przy SSR) wszystkich użytkowników.

Jeśli `A` i `B` mają dzielić licznik, masz trzy drogi: podnieś stan do wspólnego rodzica, użyj kontekstu (zadanie 12) albo zewnętrznego magazynu z subskrypcją (`useSyncExternalStore`, rozdział 07; Zustand, rozdział 13).

#T STEP_BY_STEP Zadanie 11 — hook formularza: useForm
Uogólnij obsługę formularza z treningu pól kontrolowanych w hook.

Wymagania:
1. `useForm(initialValues, validate)` zwraca `{ values, errors, touched, handleChange, handleBlur, reset, isValid, isDirty }`.
2. `errors` wyliczane przez `validate(values)`; `isValid` i `isDirty` — wyliczane.
3. `handleChange` obsługuje checkboxy (`checked`) i zwykłe pola (`value`).
4. Użyj hooka w formularzu logowania (e-mail, hasło, „zapamiętaj mnie”).

Sprawdź się: komponent formularza nie ma ani jednego `useState`.

#T CODE_JSX Rozwiązanie 11 (JSX)
```
// useForm.js
import { useState } from 'react';

export function useForm(initialValues, validate) {
  const [values, setValues] = useState(initialValues);
  const [touched, setTouched] = useState({});

  const errors = validate(values);

  function handleChange(e) {
    const { name, type, value, checked } = e.target;
    setValues((v) => ({ ...v, [name]: type === 'checkbox' ? checked : value }));
  }

  function handleBlur(e) {
    setTouched((t) => ({ ...t, [e.target.name]: true }));
  }

  function reset() {
    setValues(initialValues);
    setTouched({});
  }

  return {
    values,
    errors,
    touched,
    handleChange,
    handleBlur,
    reset,
    isValid: Object.keys(errors).length === 0,
    isDirty: Object.keys(initialValues).some((k) => values[k] !== initialValues[k]),
  };
}
```

#T CODE_TSX Rozwiązanie 11 (TSX)
```
// useForm.ts
import { useState, type ChangeEvent, type FocusEvent } from 'react';

type Values = Record<string, string | boolean>;
export type FormErrors<T> = Partial<Record<keyof T, string>>;

export function useForm<T extends Values>(initialValues: T, validate: (values: T) => FormErrors<T>) {
  const [values, setValues] = useState<T>(initialValues);
  const [touched, setTouched] = useState<Partial<Record<keyof T, boolean>>>({});

  const errors = validate(values);

  function handleChange(e: ChangeEvent<HTMLInputElement>) {
    const { name, type, value, checked } = e.target;
    setValues((v) => ({ ...v, [name]: type === 'checkbox' ? checked : value }));
  }

  function handleBlur(e: FocusEvent<HTMLInputElement>) {
    setTouched((t) => ({ ...t, [e.target.name]: true }));
  }

  function reset() {
    setValues(initialValues);
    setTouched({});
  }

  return {
    values,
    errors,
    touched,
    handleChange,
    handleBlur,
    reset,
    isValid: Object.keys(errors).length === 0,
    isDirty: (Object.keys(initialValues) as (keyof T)[]).some((k) => values[k] !== initialValues[k]),
  };
}
```

#T STEP_BY_STEP Zadanie 12 — hook nad kontekstem: powiadomienia
Połącz oba mechanizmy: kontekst przechowuje listę powiadomień, a hook `useNotify()` daje komponentom prostą funkcję.

Wymagania:
1. `NotificationsProvider` trzyma tablicę `{ id, message, tone }` i renderuje ją w `<div role="status" aria-live="polite">` pod swoimi dziećmi.
2. `useNotify()` zwraca funkcję `notify(message, tone = 'info')`, która dodaje powiadomienie z ID i automatycznie usuwa je po 3 s.
3. Każde powiadomienie ma przycisk „×” zamykający je wcześniej.
4. Komponent `SaveButton` w głębi drzewa wywołuje `notify('Zapisano', 'success')` — nie wie nic o liście ani timerach.
5. Timer to `setTimeout` w funkcji `notify` (handler, nie Effect).

Sprawdź się: trzy szybkie kliknięcia „Zapisz” pokazują trzy powiadomienia, które znikają po kolei.

#T CODE_JSX Rozwiązanie 12 (JSX)
```
// notifications.jsx
import { createContext, useContext, useState } from 'react';

const NotifyContext = createContext(null);

export function NotificationsProvider({ children }) {
  const [items, setItems] = useState([]);

  const dismiss = (id) => setItems((list) => list.filter((n) => n.id !== id));

  function notify(message, tone = 'info') {
    const id = crypto.randomUUID();
    setItems((list) => [...list, { id, message, tone }]);
    setTimeout(() => dismiss(id), 3000);
  }

  return (
    <NotifyContext value={notify}>
      {children}
      <div role="status" aria-live="polite" className="toasts">
        {items.map((n) => (
          <p key={n.id} className={`toast toast--${n.tone}`}>
            {n.message}
            <button type="button" aria-label="Zamknij" onClick={() => dismiss(n.id)}>×</button>
          </p>
        ))}
      </div>
    </NotifyContext>
  );
}

export function useNotify() {
  const notify = useContext(NotifyContext);
  if (!notify) throw new Error('useNotify musi być użyty wewnątrz <NotificationsProvider>');
  return notify;
}

export function SaveButton() {
  const notify = useNotify();
  return <button type="button" onClick={() => notify('Zapisano', 'success')}>Zapisz</button>;
}
```

#T CODE_TSX Rozwiązanie 12 (TSX)
```
// notifications.tsx
import { createContext, useContext, useState, type ReactNode } from 'react';

type Tone = 'info' | 'success' | 'error';
type Notification = { id: string; message: string; tone: Tone };
type Notify = (message: string, tone?: Tone) => void;

const NotifyContext = createContext<Notify | null>(null);

export function NotificationsProvider({ children }: { children: ReactNode }) {
  const [items, setItems] = useState<Notification[]>([]);

  const dismiss = (id: string) => setItems((list) => list.filter((n) => n.id !== id));

  const notify: Notify = (message, tone = 'info') => {
    const id = crypto.randomUUID();
    setItems((list) => [...list, { id, message, tone }]);
    setTimeout(() => dismiss(id), 3000);
  };

  return (
    <NotifyContext value={notify}>
      {children}
      <div role="status" aria-live="polite" className="toasts">
        {items.map((n) => (
          <p key={n.id} className={`toast toast--${n.tone}`}>
            {n.message}
            <button type="button" aria-label="Zamknij" onClick={() => dismiss(n.id)}>×</button>
          </p>
        ))}
      </div>
    </NotifyContext>
  );
}

export function useNotify(): Notify {
  const notify = useContext(NotifyContext);
  if (!notify) throw new Error('useNotify musi być użyty wewnątrz <NotificationsProvider>');
  return notify;
}

export function SaveButton() {
  const notify = useNotify();
  return <button type="button" onClick={() => notify('Zapisano', 'success')}>Zapisz</button>;
}
```

#T NOTE Dlaczego timer działa, choć funkcja jest „stara”
`setTimeout(() => dismiss(id), 3000)` wywołuje `dismiss` z domknięcia sprzed 3 sekund — a mimo to usuwa właściwy element. Działa, bo `dismiss` używa formy funkcyjnej `setItems((list) => …)`, która zawsze dostaje **aktualną** listę. Gdyby było `setItems(items.filter(…))`, stara migawka `items` przywróciłaby powiadomienia dodane w międzyczasie (zadanie 11 z treningu useState w praktyce). Wartość kontekstu (`notify`) zmienia się przy każdym renderze Providera — przy wielu konsumentach ustabilizujesz ją przez `useCallback` (rozdział 16).

#T SUMMARY Podsumowanie treningu
Przećwiczyłeś Context od podstaw: Provider w stylu React 19, hook-strażnik zamiast eksportu kontekstu, zachowanie domyślnej wartości i zagnieżdżonych Providerów, rozdzielenie stanu i `dispatch` na dwa konteksty, stabilizację `value` i koszt rerenderów konsumentów. Po stronie hooków napisałeś `useToggle`, `useCounter`, `useLocalStorage`, `useForm` i hook nad kontekstem — każdy z jasnym kontraktem, a w TSX z krotką, generykiem lub setterem wiążącym klucz z typem wartości. Najważniejsza lekcja: hook współdzieli **logikę**, a nie stan; wspólny stan wymaga rodzica, kontekstu albo zewnętrznego magazynu.

Kryterium zaliczenia: poprawne odpowiedzi do zadań 3, 5 i 10; żaden konsument nie importuje obiektu kontekstu bezpośrednio, a każdy hook z zadań 7–12 jest użyty w co najmniej dwóch miejscach.
