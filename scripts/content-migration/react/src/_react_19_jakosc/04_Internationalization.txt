#T INTRO Rozgrzewka i problem: DevDesk po angielsku i niemiecku
Rozgrzewka: Jaki odsetek problemów dostępności wykrywa automat? Dlaczego w jsdom nie sprawdzisz kontrastu? Jak testujesz powrót fokusu po zamknięciu modala?

Problem: DevDesk sprzedaje się w Niemczech i Wielkiej Brytanii. Teksty są wpisane na sztywno w komponentach, daty formatowane ręcznie (`${d}.${m}.${y}`), a „1 ticketów” i „5 ticket” pokazują, że liczba mnoga to więcej niż dopisanie „-ów”. **Internacjonalizacja (i18n)** to przygotowanie aplikacji do wielu języków i regionów: teksty w plikach tłumaczeń, poprawna liczba mnoga, formatowanie dat, liczb i walut według ustawień regionalnych. Użyjesz **react-i18next** i wbudowanego w przeglądarkę **Intl**.

#T DEFINITION Pojęcia i18n
- **Klucz tłumaczenia** — identyfikator tekstu (`tickets.title`), a nie sam tekst; tłumaczenia leżą w plikach JSON per język (`pl/common.json`, `en/common.json`).
- **Przestrzenie nazw** (namespaces) — podział tłumaczeń na pliki według funkcji (`common`, `tickets`, `settings`), ładowane osobno.
- **Interpolacja** — wstawianie wartości: `"Witaj, {{name}}"`.
- **Liczba mnoga** — reguły zależą od języka: angielski ma 2 formy (`one`, `other`), polski 4 (`one` — 1, `few` — 2–4, 22–24…, `many` — 5–21, 0…, `other` — ułamki). i18next korzysta z `Intl.PluralRules` i sufiksów kluczy `_one`, `_few`, `_many`, `_other`.
- **Lokalizacja formatów** — `Intl.DateTimeFormat`, `Intl.NumberFormat`, `Intl.RelativeTimeFormat`, `Intl.ListFormat` formatują dane według języka i regionu (`pl-PL`, `de-DE`, `en-GB`).

#T CODE_BASIC Konfiguracja i pliki tłumaczeń
```
// i18n.ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import pl from './locales/pl/common.json';
import en from './locales/en/common.json';

export const resources = { pl: { common: pl }, en: { common: en } } as const;

i18n.use(initReactI18next).init({
  resources,
  lng: localStorage.getItem('devdesk:lang') ?? 'pl',
  fallbackLng: 'en',
  defaultNS: 'common',
  interpolation: { escapeValue: false }, // React sam escapuje
});

export default i18n;

// locales/pl/common.json
// { "tickets": { "title": "Tickety", "open_one": "{{count}} otwarty ticket", "open_few": "{{count}} otwarte tickety",
//   "open_many": "{{count}} otwartych ticketów", "open_other": "{{count}} otwartego ticketu", "assignedTo": "Przypisany do {{name}}" } }
// locales/en/common.json
// { "tickets": { "title": "Tickets", "open_one": "{{count}} open ticket", "open_other": "{{count}} open tickets", "assignedTo": "Assigned to {{name}}" } }
```

#T CODE_JSX Komponent z tłumaczeniami i formatami (JSX)
```
// TicketsHeader.jsx
import { useTranslation } from 'react-i18next';

export function TicketsHeader({ openCount, lastSync }) {
  const { t, i18n } = useTranslation();
  const dateFormat = new Intl.DateTimeFormat(i18n.language, { dateStyle: 'medium', timeStyle: 'short' });

  return (
    <header>
      <h1>{t('tickets.title')}</h1>
      <p>{t('tickets.open', { count: openCount })}</p>
      <p><time dateTime={lastSync.toISOString()}>{dateFormat.format(lastSync)}</time></p>
      <select value={i18n.language} onChange={(e) => i18n.changeLanguage(e.target.value)} aria-label="Język / Language">
        <option value="pl">Polski</option>
        <option value="en">English</option>
      </select>
    </header>
  );
}
```

#T CODE_TSX Typowane klucze tłumaczeń (TSX)
Komponent wygląda tak samo jak w JSX — różnica tkwi w pliku deklaracji poniżej, dzięki któremu `t()` zna wszystkie klucze.
```
// TicketsHeader.tsx
import { useTranslation } from 'react-i18next';

export function TicketsHeader({ openCount, lastSync }: { openCount: number; lastSync: Date }) {
  const { t, i18n } = useTranslation();
  const dateFormat = new Intl.DateTimeFormat(i18n.language, { dateStyle: 'medium', timeStyle: 'short' });

  return (
    <header>
      <h1>{t('tickets.title')}</h1>
      <p>{t('tickets.open', { count: openCount })}</p>
      <p><time dateTime={lastSync.toISOString()}>{dateFormat.format(lastSync)}</time></p>
      <select value={i18n.language} onChange={(e) => i18n.changeLanguage(e.target.value)} aria-label="Język / Language">
        <option value="pl">Polski</option>
        <option value="en">English</option>
      </select>
    </header>
  );
}
```

#T CODE_BASIC Deklaracja zasobów: i18next.d.ts
Rozszerzenie typu `CustomTypeOptions` sprawia, że `t()` zna wszystkie klucze z plików JSON — literówka w kluczu albo brak `count` w kluczu z liczbą mnogą jest błędem kompilacji (wymaga `resolveJsonModule` w tsconfig).
```
// i18next.d.ts
import 'i18next';
import type pl from './locales/pl/common.json';

declare module 'i18next' {
  interface CustomTypeOptions {
    defaultNS: 'common';
    resources: { common: typeof pl };
  }
}
```

#T NOTE JSX ↔ TSX — typowane klucze tłumaczeń
To jedna z najbardziej odczuwalnych korzyści TypeScriptu w i18n: w TSX `t('tickets.titel')` jest błędem kompilacji, a IDE podpowiada wszystkie klucze. W JSX literówka wyświetli na ekranie surowy klucz `tickets.titel` — zauważysz to dopiero w działaniu (pomaga `saveMissing` i log brakujących kluczy w trybie deweloperskim). Typy biorą się z pliku języka podstawowego (`pl`) — pozostałe języki sprawdzasz osobnym skryptem porównującym klucze.

#T CODE_PRACTICAL Formatowanie z Intl: waluty, czas względny, listy
```
// format.ts
export function formatMoney(amount: number, currency: string, locale: string) {
  return new Intl.NumberFormat(locale, { style: 'currency', currency }).format(amount);
}

export function formatRelative(date: Date, locale: string, now = new Date()) {
  const minutes = Math.round((date.getTime() - now.getTime()) / 60000);
  const rtf = new Intl.RelativeTimeFormat(locale, { numeric: 'auto' });
  if (Math.abs(minutes) < 60) return rtf.format(minutes, 'minute');
  const hours = Math.round(minutes / 60);
  if (Math.abs(hours) < 24) return rtf.format(hours, 'hour');
  return rtf.format(Math.round(hours / 24), 'day');
}

export function formatList(items: string[], locale: string) {
  return new Intl.ListFormat(locale, { style: 'long', type: 'conjunction' }).format(items);
}

// formatMoney(1234.5, 'EUR', 'de-DE') → "1.234,50 €"
// formatRelative(wczoraj, 'pl') → "wczoraj"
// formatList(['Ala', 'Ola', 'Ela'], 'pl') → "Ala, Ola i Ela"
```

#T STEP_BY_STEP Budujemy razem: DevDesk w dwóch językach
1. Zainstaluj `i18next react-i18next`, dodaj `i18n.ts` i zaimportuj go w `main` przed renderem.
2. Wyciągnij teksty z nagłówka listy, filtrów i szczegółów ticketu do `locales/pl/common.json`; przetłumacz na `en`.
3. Liczbę otwartych ticketów pokaż kluczem z liczbą mnogą; sprawdź dla 1, 2, 5, 22 i 25 w języku polskim.
4. Zastąp ręczne formatowanie dat i kwot funkcjami z `format.ts`; czas względny w liście komentarzy.
5. Dodaj przełącznik języka zapisywany w `localStorage` i ustawiający `<html lang>` (`i18n.on('languageChanged', (l) => document.documentElement.lang = l)`).
6. W TSX dodaj `i18next.d.ts` i sprawdź, że literówka w kluczu nie kompiluje się; w JSX włącz `saveMissing` z logiem brakujących kluczy.
7. Napisz skrypt porównujący klucze `pl` i `en` (brakujące tłumaczenia) i dodaj go do CI.

#T PITFALL Sklejanie zdań z kawałków
`t('assigned') + ' ' + name + ' ' + t('at') + ' ' + date` — szyk zdania różni się między językami (po niemiecku czasownik bywa na końcu), więc sklejone kawałki dają nienaturalne zdania, których tłumacz nie może poprawić. Tłumacz **całe zdania** z interpolacją: `"assignedAt": "Przypisany do {{name}} {{date}}"`, a fragmenty z formatowaniem (pogrubienie, link) wstaw komponentem `<Trans>` z react-i18next.

#T SUMMARY Kryterium akceptacji i podsumowanie
i18n to teksty w plikach tłumaczeń z kluczami i przestrzeniami nazw, interpolacja całych zdań, liczba mnoga według reguł języka (polski ma cztery formy: `_one`, `_few`, `_many`, `_other`) oraz formatowanie dat, liczb, walut, czasu względnego i list przez `Intl`. react-i18next daje `useTranslation`, `t` i `<Trans>`. W TSX rozszerzenie `CustomTypeOptions` typuje klucze tłumaczeń; w JSX pomagają log brakujących kluczy i skrypt porównujący pliki.

Kryterium akceptacji: lista i szczegóły ticketu działają po polsku i angielsku z przełącznikiem zapamiętywanym między sesjami, liczba mnoga jest poprawna dla 1, 2, 5, 22 i 25, daty i kwoty są formatowane przez `Intl`, `<html lang>` odpowiada wybranemu językowi, a CI wykrywa brakujące tłumaczenia.
