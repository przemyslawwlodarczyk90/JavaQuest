#T INTRO Rozgrzewka i problem: komponenty, których HTML nie ma
Rozgrzewka: Jakie są cztery zasady WCAG? Dlaczego `<button>` jest lepszy od `<div role="button">`? Jak przenosisz fokus po zmianie trasy?

Problem: DevDesk ma komponenty, dla których nie istnieje gotowy element HTML: zakładki, menu akcji ticketu, combobox z wyszukiwaniem agenta, powiadomienia „Ticket zapisany”. Czytnik ekranu nie wie, że to zakładki — słyszy „przycisk, przycisk, przycisk”, a toast znika, zanim ktokolwiek go usłyszy. Tu wchodzi **ARIA** (Accessible Rich Internet Applications) — atrybuty opisujące role, stany i relacje — oraz **wzorce** z przewodnika WAI-ARIA Authoring Practices (APG). Nauczysz się też korzystać z czytnika ekranu, żeby sprawdzić swoją pracę.

#T DEFINITION Role, stany i właściwości
- **Role** (`role="tablist"`, `"tab"`, `"tabpanel"`, `"dialog"`, `"menu"`, `"status"`, `"alert"`) — czym jest element,
- **Stany** (`aria-selected`, `aria-expanded`, `aria-pressed`, `aria-checked`, `aria-invalid`, `aria-busy`, `aria-disabled`) — zmieniają się w czasie i muszą odzwierciedlać stan Reacta,
- **Właściwości i relacje** (`aria-label`, `aria-labelledby`, `aria-describedby`, `aria-controls`, `aria-haspopup`, `aria-activedescendant`) — nazwy i powiązania między elementami (przez `id` — w React generowane `useId`),
- **Regiony na żywo** (`aria-live="polite"`/`"assertive"`, role `status` i `alert`) — czytnik odczytuje zmiany treści bez przenoszenia fokusu.

Każdy wzorzec APG określa także **obsługę klawiatury** — role bez klawiatury to obietnica bez pokrycia.

#T CODE_JSX Zakładki według wzorca APG (JSX)
Wzorzec: strzałki przełączają zakładki, Tab przechodzi do panelu (tylko aktywna zakładka jest w kolejności Tab — „roving tabindex”), Home/End — pierwsza/ostatnia.
```
// Tabs.jsx
import { useId, useRef, useState } from 'react';

export function Tabs({ tabs, label }) {
  const [active, setActive] = useState(0);
  const baseId = useId();
  const refs = useRef([]);

  function focusTab(index) {
    const next = (index + tabs.length) % tabs.length;
    setActive(next);
    refs.current[next]?.focus();
  }

  function onKeyDown(e) {
    if (e.key === 'ArrowRight') focusTab(active + 1);
    else if (e.key === 'ArrowLeft') focusTab(active - 1);
    else if (e.key === 'Home') focusTab(0);
    else if (e.key === 'End') focusTab(tabs.length - 1);
    else return;
    e.preventDefault();
  }

  return (
    <div>
      <div role="tablist" aria-label={label} onKeyDown={onKeyDown}>
        {tabs.map((t, i) => (
          <button key={t.id} ref={(el) => { refs.current[i] = el; }} role="tab" id={`${baseId}-tab-${i}`}
            aria-selected={i === active} aria-controls={`${baseId}-panel-${i}`} tabIndex={i === active ? 0 : -1}
            onClick={() => setActive(i)}>
            {t.title}
          </button>
        ))}
      </div>
      {tabs.map((t, i) => (
        <div key={t.id} role="tabpanel" id={`${baseId}-panel-${i}`} aria-labelledby={`${baseId}-tab-${i}`} hidden={i !== active} tabIndex={0}>
          {t.content}
        </div>
      ))}
    </div>
  );
}
```

#T CODE_TSX Zakładki według wzorca APG (TSX)
```
// Tabs.tsx
import { useId, useRef, useState, type KeyboardEvent, type ReactNode } from 'react';

type Tab = { id: string; title: string; content: ReactNode };

export function Tabs({ tabs, label }: { tabs: Tab[]; label: string }) {
  const [active, setActive] = useState(0);
  const baseId = useId();
  const refs = useRef<(HTMLButtonElement | null)[]>([]);

  function focusTab(index: number) {
    const next = (index + tabs.length) % tabs.length;
    setActive(next);
    refs.current[next]?.focus();
  }

  function onKeyDown(e: KeyboardEvent<HTMLDivElement>) {
    if (e.key === 'ArrowRight') focusTab(active + 1);
    else if (e.key === 'ArrowLeft') focusTab(active - 1);
    else if (e.key === 'Home') focusTab(0);
    else if (e.key === 'End') focusTab(tabs.length - 1);
    else return;
    e.preventDefault();
  }

  return (
    <div>
      <div role="tablist" aria-label={label} onKeyDown={onKeyDown}>
        {tabs.map((t, i) => (
          <button key={t.id} ref={(el) => { refs.current[i] = el; }} role="tab" id={`${baseId}-tab-${i}`}
            aria-selected={i === active} aria-controls={`${baseId}-panel-${i}`} tabIndex={i === active ? 0 : -1}
            onClick={() => setActive(i)}>
            {t.title}
          </button>
        ))}
      </div>
      {tabs.map((t, i) => (
        <div key={t.id} role="tabpanel" id={`${baseId}-panel-${i}`} aria-labelledby={`${baseId}-tab-${i}`} hidden={i !== active} tabIndex={0}>
          {t.content}
        </div>
      ))}
    </div>
  );
}
```

#T NOTE JSX ↔ TSX — typy atrybutów ARIA
Typy Reacta znają atrybuty `aria-*` i ich wartości: `aria-selected` przyjmuje `boolean | 'true' | 'false'`, `aria-live` — `'off' | 'polite' | 'assertive'`, `role` — tekst (`AriaRole` z podpowiedziami). Literówka `aria-selcted` w TSX to błąd kompilacji, w JSX — cicho ignorowany atrybut. Typ `KeyboardEvent<HTMLDivElement>` w TSX dokumentuje, na jakim elemencie słuchasz klawiszy. Poprawności **wzorca** (czy role pasują do siebie, czy klawiatura działa) nie sprawdzi żaden z nich — to robią testy (rozdział 14: `getByRole('tab', { selected: true })`) i czytnik ekranu.

#T CODE_BASIC Ogłaszanie komunikatów: region na żywo
Region `aria-live` musi istnieć w DOM **przed** zmianą treści — dlatego renderujesz go zawsze, a zmieniasz tylko tekst.
```
import { createContext, useCallback, useContext, useState, type ReactNode } from 'react';

const AnnounceContext = createContext<(message: string) => void>(() => {});

export function Announcer({ children }: { children: ReactNode }) {
  const [message, setMessage] = useState('');
  const announce = useCallback((text: string) => {
    setMessage('');
    requestAnimationFrame(() => setMessage(text)); // ta sama treść ogłoszona ponownie
  }, []);
  return (
    <AnnounceContext.Provider value={announce}>
      {children}
      <div role="status" aria-live="polite" className="visually-hidden">{message}</div>
    </AnnounceContext.Provider>
  );
}

export const useAnnounce = () => useContext(AnnounceContext);

// const announce = useAnnounce(); … announce('Ticket #42 zapisany');
```

#T CODE_PRACTICAL Klasa visually-hidden i menu akcji
`visually-hidden` ukrywa tekst wizualnie, ale zostawia go dla czytnika (w przeciwieństwie do `display: none`). Przycisk otwierający menu informuje o stanie przez `aria-expanded` i `aria-haspopup`.
```
/* a11y.css */
.visually-hidden {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip-path: inset(50%);
  white-space: nowrap;
  border: 0;
}

/*
<button aria-haspopup="menu" aria-expanded={open} aria-controls={menuId} onClick={toggle}>Akcje</button>
<ul role="menu" id={menuId} hidden={!open}>
  <li role="menuitem" tabIndex={-1}>Przypisz do mnie</li> …
</ul>
Dla prostych list akcji często wystarczy zwykły przycisk rozwijający listę przycisków (wzorzec „disclosure”) zamiast pełnego role="menu".
*/
```

#T STEP_BY_STEP Budujemy razem: test z czytnikiem ekranu
1. Uruchom czytnik ekranu: Windows — NVDA (darmowy) lub Narrator (Ctrl+Win+Enter); macOS — VoiceOver (Cmd+F5). Naucz się trzech poleceń: czytaj dalej, następny nagłówek (H), następny punkt orientacyjny (D w NVDA).
2. Przejdź ekran ticketu: czy słyszysz nazwę ekranu, nagłówki, nazwy przycisków, stan zakładek („wybrana, 1 z 3”)?
3. Zamień zakładki ticketu na `Tabs`; sprawdź strzałki, Home, End i ogłoszenie przez czytnik.
4. Dodaj `Announcer` w korzeniu aplikacji i ogłaszaj zapis ticketu, dodanie komentarza i błędy zapisu (błąd: `role="alert"`).
5. Menu akcji ticketu oznacz `aria-expanded`/`aria-haspopup`; zastanów się, czy wzorzec „disclosure” nie jest prostszy.
6. Dopisz test RTL: `getByRole('tab', { name: 'Komentarze' })` po strzałce w prawo ma `aria-selected="true"`.
7. W DevTools (Elements → Accessibility) obejrzyj drzewo dostępności — nazwę i rolę każdego elementu.

#T PITFALL Region na żywo renderowany razem z komunikatem
`{saved && <div role="status">Zapisano</div>}` — element pojawia się w DOM razem z tekstem i wiele czytników **go nie ogłosi**, bo region na żywo musi już istnieć, zanim zmieni się jego treść. Renderuj kontener stale (choćby pusty) i zmieniaj tylko jego zawartość. Drugi błąd: `aria-live="assertive"` dla wszystkiego — przerywa użytkownikowi czytanie; zostaw go dla błędów krytycznych.

#T SUMMARY Kryterium akceptacji i podsumowanie
ARIA opisuje role, stany i relacje komponentów, których nie ma w HTML; wzorce APG definiują wymagane role i obsługę klawiatury (np. zakładki z roving tabindex i strzałkami). Stany ARIA muszą odzwierciedlać stan Reacta, a identyfikatory relacji generujesz `useId`. Komunikaty ogłaszasz przez stale wyrenderowany region na żywo (`role="status"`, `aria-live="polite"`), błędy — `role="alert"`. Wynik sprawdzasz czytnikiem ekranu i drzewem dostępności. TSX wyłapuje literówki i złe wartości atrybutów ARIA.

Kryterium akceptacji: zakładki ticketu działają według wzorca APG (klawiatura i odczyt czytnika), zapis i błędy są ogłaszane przez region na żywo, a ekran ticketu został przejrzany czytnikiem ekranu z poprawionymi nazwami i stanami.
