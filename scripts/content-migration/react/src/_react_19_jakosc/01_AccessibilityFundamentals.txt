#T INTRO Rozgrzewka i problem: DevDesk bez myszy
Rozgrzewka: Kiedy wybierasz Vite SPA, a kiedy Next.js? Czym jest wyspa w Astro? Co zapisujesz w ADR?

Problem: nowy agent wsparcia korzysta tylko z klawiatury (uraz ręki), a jeden z klientów zgłasza, że czytnik ekranu w ich firmie czyta przycisk zamknięcia ticketu jako „przycisk” bez nazwy. Odłóż mysz i spróbuj obsłużyć DevDesk tylko klawiszem Tab, Enter, Spacją i strzałkami — szybko zobaczysz klikalne `div`y, do których nie da się dojść, i fokus znikający po otwarciu modala. **Dostępność** (a11y) to nie dodatek, tylko jakość: w UE od 2025 r. obowiązuje Europejski akt o dostępności (EAA) dla wielu usług cyfrowych, a standardem odniesienia są wytyczne WCAG. W tej lekcji poznasz fundamenty i od razu poprawisz komponenty DevDesk.

#T DEFINITION WCAG w skrócie: cztery zasady
Wytyczne WCAG (Web Content Accessibility Guidelines, aktualnie 2.2) opierają się na czterech zasadach (POUR):
- **Postrzegalność** — treść dostępna dla zmysłów użytkownika: tekst alternatywny obrazów, napisy, kontrast tekstu co najmniej 4.5:1 (3:1 dla dużego tekstu i elementów interfejsu), informacja nie tylko kolorem.
- **Funkcjonalność** — wszystko obsłużysz klawiaturą, widoczny fokus, brak pułapek klawiaturowych, wystarczający czas, cele dotyku co najmniej 24×24 px.
- **Zrozumiałość** — język strony (`lang`), przewidywalne zachowanie, etykiety i komunikaty błędów w formularzach.
- **Solidność** — poprawny HTML i role, które technologie wspomagające (czytniki ekranu) potrafią odczytać.

Poziom docelowy w większości regulacji to **AA**.

#T DEFINITION Pierwsza zasada: semantyczny HTML
Najlepsza dostępność jest „za darmo” — z właściwych elementów HTML:
- `<button>` — fokusowalny, obsługuje Enter i Spację, ma rolę „przycisk”; `<div onClick>` — nic z tego,
- `<a href>` — nawigacja (otwórz w nowej karcie, historia), `<button>` — akcja na stronie,
- `<label htmlFor>` — nazwa pola i większy obszar kliknięcia,
- nagłówki `h1–h6` w kolejności i punkty orientacyjne (`<header>`, `<nav>`, `<main>`, `<aside>`, `<footer>`) — czytnik ekranu pozwala skakać po nich,
- `<table>` z `<th scope>` dla danych tabelarycznych, listy `<ul>/<ol>` dla list.

#T CODE_WRONG Typowe błędy w komponentach
```
<div className="btn" onClick={closeTicket}>✕</div>          {/* brak fokusu, klawiatury i nazwy */}
<img src={avatarUrl} />                                     {/* brak alt */}
<input placeholder="E-mail" />                              {/* placeholder to nie etykieta */}
<span style={{ color: 'red' }}>●</span> Pilny               {/* informacja tylko kolorem? tu akurat jest tekst — OK */}
<button><svg>…</svg></button>                               {/* przycisk ikonowy bez nazwy */}
*:focus { outline: none; }                                  /* usunięty widoczny fokus */
```

#T CODE_JSX Dostępny przycisk ikonowy i pole formularza (JSX)
```
// IconButton.jsx
export function IconButton({ label, icon, onClick, ...rest }) {
  return (
    <button type="button" className="icon-button" aria-label={label} title={label} onClick={onClick} {...rest}>
      <span aria-hidden="true">{icon}</span>
    </button>
  );
}

// TextField.jsx
import { useId } from 'react';

export function TextField({ label, error, hint, ...inputProps }) {
  const id = useId();
  const hintId = hint ? `${id}-hint` : undefined;
  const errorId = error ? `${id}-error` : undefined;
  return (
    <div className="field">
      <label htmlFor={id}>{label}</label>
      {hint && <p id={hintId} className="hint">{hint}</p>}
      <input id={id} aria-invalid={Boolean(error)} aria-describedby={[hintId, errorId].filter(Boolean).join(' ') || undefined} {...inputProps} />
      {error && <p id={errorId} className="error">{error}</p>}
    </div>
  );
}
```

#T CODE_TSX Dostępny przycisk ikonowy i pole formularza (TSX)
W TSX `label: string` jest **wymagane** — przycisk ikonowy bez nazwy nie skompiluje się. Typ props rozszerza atrybuty elementu, ale bez `children` (treść to ikona).
```
// IconButton.tsx
import type { ButtonHTMLAttributes, ReactNode } from 'react';

type IconButtonProps = Omit<ButtonHTMLAttributes<HTMLButtonElement>, 'children' | 'aria-label'> & {
  label: string;
  icon: ReactNode;
};

export function IconButton({ label, icon, ...rest }: IconButtonProps) {
  return (
    <button type="button" className="icon-button" aria-label={label} title={label} {...rest}>
      <span aria-hidden="true">{icon}</span>
    </button>
  );
}

// TextField.tsx
import { useId, type InputHTMLAttributes } from 'react';

type TextFieldProps = Omit<InputHTMLAttributes<HTMLInputElement>, 'id'> & { label: string; error?: string; hint?: string };

export function TextField({ label, error, hint, ...inputProps }: TextFieldProps) {
  const id = useId();
  const hintId = hint ? `${id}-hint` : undefined;
  const errorId = error ? `${id}-error` : undefined;
  return (
    <div className="field">
      <label htmlFor={id}>{label}</label>
      {hint && <p id={hintId} className="hint">{hint}</p>}
      <input id={id} aria-invalid={Boolean(error)} aria-describedby={[hintId, errorId].filter(Boolean).join(' ') || undefined} {...inputProps} />
      {error && <p id={errorId} className="error">{error}</p>}
    </div>
  );
}
```

#T NOTE JSX ↔ TSX — wymuszanie dostępności typami
TypeScript może zamienić zasady dostępności w kontrakt: `label: string` w `IconButton` (bez nazwy nie ma kompilacji), `alt: string` wymagane w komponencie `Avatar`, `Omit<…, 'aria-label'>`, żeby nie dało się nadpisać nazwy. W JSX te same zasady pilnuje **eslint-plugin-jsx-a11y** (działa dla obu wersji) — reguły `alt-text`, `click-events-have-key-events`, `no-static-element-interactions`, `label-has-associated-control`. Najlepiej mieć oba: typy dla komponentów projektu, linter dla surowego HTML-a.

#T CODE_PRACTICAL Fokus po zmianie trasy w SPA
W SPA zmiana adresu nie przenosi fokusu ani nie ogłasza nowej strony — użytkownik czytnika ekranu nie wie, że coś się zmieniło. Przenieś fokus na nagłówek nowego ekranu.
```
import { useEffect, useRef } from 'react';
import { useLocation } from 'react-router';

export function RouteHeading({ children }: { children: string }) {
  const ref = useRef<HTMLHeadingElement>(null);
  const { pathname } = useLocation();

  useEffect(() => {
    ref.current?.focus();
  }, [pathname]);

  return (
    <h1 ref={ref} tabIndex={-1} className="route-heading">
      {children}
    </h1>
  );
}
```

#T STEP_BY_STEP Budujemy razem: DevDesk z klawiatury
1. Odłóż mysz. Przejdź klawiszem Tab przez listę ticketów, filtry, szczegóły i formularz komentarza; zapisz każde miejsce, gdzie fokus jest niewidoczny, „ucieka” albo nie da się wykonać akcji.
2. Zamień wszystkie klikalne `div`y na `button` lub `a`; przyciski ikonowe na `IconButton` z nazwą.
3. Pola formularzy zamień na `TextField` (etykieta, podpowiedź, błąd połączony przez `aria-describedby`).
4. Dodaj `:focus-visible` i link „Przejdź do treści” w layoucie; sprawdź, że pierwszy Tab go pokazuje.
5. Użyj `RouteHeading` w ekranach — po nawigacji fokus jest na nagłówku.
6. Sprawdź kontrast kolorów plakietek statusów (DevTools → Inspect → kontrast w podpowiedzi koloru) i popraw te poniżej 4.5:1.
7. Zainstaluj `eslint-plugin-jsx-a11y`, włącz konfigurację `recommended` i popraw zgłoszenia.

#T PITFALL ARIA zamiast HTML
`<div role="button" tabIndex={0} onClick={…} onKeyDown={…}>` da się zrobić dostępnym, ale musisz ręcznie obsłużyć Enter i Spację, stan `disabled`, fokus i styl — a `<button>` ma to wbudowane. Pierwsza zasada ARIA brzmi: **nie używaj ARIA, jeśli istnieje element HTML o tym znaczeniu**. Błędna ARIA jest gorsza niż jej brak — `role="button"` na linku czy `aria-hidden="true"` na fokusowalnym elemencie wprowadza czytnik ekranu w błąd.

#T SUMMARY Kryterium akceptacji i podsumowanie
Dostępność opiera się na zasadach WCAG (postrzegalność, funkcjonalność, zrozumiałość, solidność; poziom AA). Fundamentem jest semantyczny HTML: `button` do akcji, `a` do nawigacji, etykiety pól, nagłówki i punkty orientacyjne. Zapewnij widoczny fokus (`:focus-visible`), link „Przejdź do treści” i przeniesienie fokusu po zmianie trasy w SPA. W TSX wymagane propsy (`label`, `alt`) wymuszają dostępność komponentów, a `eslint-plugin-jsx-a11y` sprawdza surowy JSX w obu wersjach.

Kryterium akceptacji: wszystkie akcje DevDesk da się wykonać samą klawiaturą z widocznym fokusem, przyciski ikonowe mają nazwy, pola formularzy — etykiety i powiązane błędy, po nawigacji fokus trafia na nagłówek, a linter a11y nie zgłasza błędów.
