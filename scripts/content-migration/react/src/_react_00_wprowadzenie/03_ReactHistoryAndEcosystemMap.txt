#T INTRO Dlaczego warto znać historię Reacta
Szukając rozwiązań w internecie, trafisz na kod sprzed pięciu czy ośmiu lat: komponenty klasowe, `componentDidMount`, `this.setState`, Create React App, Redux z ręcznie pisanymi akcjami. Trafisz też na najnowszy kod z komponentami serwerowymi i akcjami. Żeby odróżnić „stary sposób” od „aktualnego”, musisz znać mapę: co kiedy się pojawiło i co dziś jest zalecane.

#T VISUAL_EXAMPLE Oś czasu Reacta
2013  React udostępniony publicznie przez Facebooka — JSX i wirtualny DOM budzą kontrowersje
2015  React Native — ten sam model komponentów na telefonach
2016  Create React App — gotowy start projektu (dziś wycofany z rekomendacji)
2017  React 16 i architektura Fiber — przerywalne renderowanie, granice błędów
2019  React 16.8 — HOOKI: useState, useEffect; komponenty funkcyjne zastępują klasy
2022  React 18 — renderowanie współbieżne, automatyczny batching, useTransition
2024  React 19 — akcje formularzy, use, useOptimistic, ref jako zwykły prop
2025  React Compiler stabilny — automatyczna memoizacja
2025+ kolejne wydania 19.x — dalszy rozwój Activity, View Transitions i komponentów serwerowych

Najważniejsza granica to **hooki (2019)**. Kod „przed hookami” pisano klasami — nadal działa i spotkasz go w starszych projektach (rozdział 22), ale nowy kod pisze się funkcjami i hookami.

#T DEFINITION Rdzeń a ekosystem
Sam pakiet `react` (plus `react-dom` dla przeglądarki) daje: komponenty, JSX, state, efekty, kontekst, refs, Suspense. Reszta pochodzi z ekosystemu:

- **budowanie i serwer deweloperski** — Vite,
- **routing** — React Router (lub routing wbudowany we framework),
- **dane z serwera** — TanStack Query,
- **formularze** — React Hook Form + Zod,
- **stan globalny** — Zustand, Redux Toolkit, Jotai (gdy Context nie wystarcza),
- **testy** — Vitest, React Testing Library, Playwright,
- **frameworki** — Next.js, React Router w trybie frameworka (renderowanie na serwerze),
- **mobile** — React Native.

W tym kursie poznasz wszystkie te elementy, ale zawsze w kolejności: najpierw problem i rozwiązanie „gołym” Reactem, potem biblioteka, która robi to lepiej.

#T NOTE Aktualne zalecenia zespołu Reacta
Oficjalna dokumentacja (react.dev) zaleca dla nowych aplikacji produkcyjnych framework (np. Next.js lub React Router w trybie frameworka), bo daje on routing, pobieranie danych i renderowanie na serwerze. Jednocześnie dopuszcza samodzielną konfigurację z Vite — i to jest najlepsza droga do nauki samego Reacta, bo nie miesza się z nim warstwa frameworka. Dlatego kurs zaczyna od Vite, a frameworki poznasz w rozdziale 18.

Create React App jest oficjalnie wycofany dla nowych projektów. Jeśli tutorial zaczyna się od `npx create-react-app` — jest przestarzały.

#T CODE_BASIC Jak rozpoznać kod sprzed hooków
Komponent klasowy: `class`, `this.state`, `this.setState`, metody cyklu życia. Działa, ale nie piszemy tak nowego kodu.
```
class Counter extends React.Component {
  state = { count: 0 };

  componentDidMount() {
    document.title = `Licznik: ${this.state.count}`;
  }

  render() {
    return (
      <button onClick={() => this.setState({ count: this.state.count + 1 })}>
        {this.state.count}
      </button>
    );
  }
}
```

#T CODE_PRACTICAL Ten sam komponent dzisiaj
Komponent funkcyjny z hookami — krótszy i to jest standard, którego uczy kurs.
```
import { useEffect, useState } from 'react';

export function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    document.title = `Licznik: ${count}`;
  }, [count]);

  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

#T STEP_BY_STEP Jak czytać dokumentację react.dev
1. **Learn** — przewodnik koncepcyjny. Rozdziały „Describing the UI”, „Adding Interactivity”, „Managing State” i „Escape Hatches” pokrywają się z rozdziałami 02–08 tego kursu. Warto czytać równolegle.
2. **Reference** — opis każdego API: `useState`, `useEffect`, `createPortal`… Każda strona ma sekcje „Usage” (przykłady) i „Troubleshooting” (typowe błędy).
3. **Strony „You Might Not Need an Effect” i „Thinking in React”** — dwie najważniejsze strony całej dokumentacji. Wrócimy do nich w rozdziałach 06 i 07.
4. Przykłady w dokumentacji mają przełącznik JS/TS — możesz od razu porównać obie wersje, tak jak w tym kursie.
5. Uważaj na stary serwis legacy.reactjs.org — opisuje komponenty klasowe i stare wzorce.

#T USAGE Ćwiczenie: rozpoznaj epokę kodu
Gdy znajdziesz w internecie przykład, sprawdź:
- `class ... extends React.Component` → przed hookami (przed 2019), szukaj nowszego przykładu,
- `ReactDOM.render(...)` → API sprzed React 18; dziś używa się `createRoot(...).render(...)`,
- `forwardRef` → w React 19 nie jest już potrzebny, `ref` przekazuje się jak zwykły prop,
- `create-react-app`, `react-scripts` → przestarzały sposób startu projektu,
- `'use client'`, `'use server'` → kod frameworka z komponentami serwerowymi (rozdział 17–18).

#T PITFALL Mieszanie wzorców z różnych epok
Częsty efekt kopiowania z kilku źródeł: projekt na React 19, w którym część komponentów to klasy, a część używa `ReactDOM.render`. Kod się kompiluje, ale ostrzeżenia w konsoli i trudności w utrzymaniu są gwarantowane. Zanim skopiujesz rozwiązanie, sprawdź jego datę i wersję Reacta.

#T SUMMARY Podsumowanie
React przeszedł drogę od klas do hooków (2019), od renderowania synchronicznego do współbieżnego (React 18) i od klientowych SPA do komponentów serwerowych (React 19 i frameworki). Rdzeń daje komponenty i hooki; routing, dane, formularze i testy pochodzą z ekosystemu. Kryterium akceptacji: potrafisz rozpoznać, czy przykład kodu jest aktualny, i wiesz, gdzie w dokumentacji react.dev szukać wyjaśnień.
