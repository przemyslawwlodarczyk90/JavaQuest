#T INTRO Pierwsza praktyka: uruchom DevDesk na swoim komputerze
W tej lekcji tworzysz dwa projekty startowe — jeden w JavaScripcie, drugi w TypeScripcie — i uruchamiasz je w przeglądarce. Od tego momentu każdą lekcję możesz realizować w obu wersjach równolegle albo wybrać jedną i do drugiej zaglądać przy porównaniach.

#T DEFINITION Node.js, npm i Vite — kto za co odpowiada
- **Node.js** — środowisko uruchamiające JavaScript poza przeglądarką. Potrzebne do narzędzi: serwera deweloperskiego, budowania, testów. Twoja aplikacja React i tak działa w przeglądarce.
- **npm** — menedżer pakietów instalowany razem z Node. Pobiera biblioteki (`react`, `vite`…) do katalogu `node_modules` i uruchamia skrypty z `package.json`.
- **Vite** — narzędzie do budowania i serwer deweloperski. Podczas pracy serwuje pliki prawie natychmiast i odświeża zmiany bez przeładowania strony (HMR). Przy budowaniu tworzy zoptymalizowane pliki do wdrożenia.

Zalecana wersja Node to aktualna wersja LTS (wydanie z długim wsparciem, w 2026 roku linia 24). Sprawdzisz ją poleceniem `node -v`.

#T STEP_BY_STEP Utwórz oba projekty
1. Zainstaluj Node.js LTS ze strony nodejs.org (lub przez menedżer wersji, np. nvm albo fnm).
2. Sprawdź instalację: `node -v` oraz `npm -v`.
3. Utwórz katalog na kurs i wejdź do niego: `mkdir react-kurs && cd react-kurs`.
4. Projekt JavaScript: `npm create vite@latest devdesk-js -- --template react`.
5. Projekt TypeScript: `npm create vite@latest devdesk-ts -- --template react-ts`.
6. W każdym katalogu zainstaluj zależności: `cd devdesk-js && npm install`.
7. Uruchom serwer deweloperski: `npm run dev` — w terminalu pojawi się adres, zwykle `http://localhost:5173`.
8. Otwórz adres w przeglądarce — zobaczysz stronę startową z licznikiem.
9. To samo zrób dla `devdesk-ts` (drugi serwer dostanie kolejny port, np. 5174).

Podwójne `--` w kroku 4 przekazuje opcję `--template` do kreatora Vite, a nie do samego npm.

#T CODE_JSX Plik startowy main.jsx
Punkt startowy aplikacji JavaScript: znajduje element `#root` w `index.html` i renderuje w nim komponent `App`.
```
// src/main.jsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import './index.css';
import App from './App.jsx';

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <App />
  </StrictMode>,
);
```

#T CODE_TSX Plik startowy main.tsx
Ten sam kod w TypeScripcie. Jedyna różnica: wykrzyknik po `getElementById('root')`. `getElementById` może zwrócić `null`, a `createRoot` wymaga elementu — `!` mówi TypeScriptowi „wiem, że ten element istnieje”.
```
// src/main.tsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import './index.css';
import App from './App.tsx';

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <App />
  </StrictMode>,
);
```

#T NOTE JSX ↔ TSX — różnice w projekcie startowym
Projekt `react-ts` ma dodatkowo:
- pliki `.tsx` zamiast `.jsx` i `.ts` zamiast `.js`,
- `tsconfig.json` (zwykle z odwołaniami do `tsconfig.app.json` dla kodu aplikacji i `tsconfig.node.json` dla konfiguracji Vite) — ustawienia kompilatora TypeScript,
- zależność `typescript` oraz paczki z typami `@types/react` i `@types/react-dom`,
- skrypt `build` uruchamiający najpierw sprawdzanie typów (`tsc -b`), a dopiero potem `vite build`,
- deklarację typów Vite (`vite/client`) — w zależności od wersji szablonu jako plik `src/vite-env.d.ts` lub wpis `types` w tsconfig.

Ważne: `npm run dev` w projekcie TS **nie zatrzyma się na błędzie typów** — Vite tylko usuwa typy i serwuje kod. Błędy typów zobaczysz w edytorze i przy `npm run build`.

#T CODE_BASIC Skrypty w package.json (wersja JS)
```
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "lint": "eslint .",
    "preview": "vite preview"
  }
}
```

#T CODE_PRACTICAL Skrypty w package.json (wersja TS)
```
{
  "scripts": {
    "dev": "vite",
    "build": "tsc -b && vite build",
    "lint": "eslint .",
    "preview": "vite preview"
  }
}
```

#T STEP_BY_STEP Sprawdź HMR i budowanie
1. Przy uruchomionym `npm run dev` otwórz `src/App.jsx` (lub `App.tsx`).
2. Kliknij kilka razy licznik na stronie, tak by pokazywał np. 5.
3. Zmień tekst nagłówka w `App` i zapisz plik. Strona zaktualizuje się bez przeładowania, a licznik nadal pokazuje 5 — to HMR, który zachowuje stan komponentów.
4. Zatrzymaj serwer (Ctrl+C) i uruchom `npm run build`. W katalogu `dist/` pojawią się gotowe pliki: `index.html` i katalog `assets` z plikami JS i CSS o nazwach z hashem.
5. Uruchom `npm run preview` — to lokalny podgląd wersji produkcyjnej z katalogu `dist`.
6. W projekcie TS dopisz w `App.tsx` linię `const x: number = 'tekst';` i uruchom `npm run build` — budowanie zatrzyma się z błędem typu. Usuń tę linię.

#T PITFALL Otwieranie index.html bezpośrednio z dysku
Dwuklik na `index.html` (adres `file:///...`) pokaże pustą stronę. Kod źródłowy w JSX/TSX musi zostać przetworzony przez Vite, a moduły ES nie ładują się z protokołu `file://`. Zawsze uruchamiaj `npm run dev` albo `npm run preview` i wchodź na adres `http://localhost:...`.

#T WHEN_TO_USE Dlaczego Vite, a nie Create React App
Create React App (CRA) był standardem przez lata, ale jest wycofany: wolno startuje, wolno odświeża i nie jest rozwijany. Vite startuje w ułamku sekundy, bo podczas pracy nie skleja całej aplikacji, tylko serwuje moduły na żądanie. Gdy w przyszłości wybierzesz framework (Next.js, React Router w trybie frameworka), on przejmie rolę Vite — ale do nauki samego Reacta Vite jest najlepszym wyborem.

#T SUMMARY Podsumowanie
Node.js uruchamia narzędzia, npm instaluje pakiety i skrypty, Vite serwuje i buduje aplikację. Dwa projekty startowe: `--template react` (JSX) i `--template react-ts` (TSX). Projekt TS ma tsconfig, typy Reacta i sprawdzanie typów w `npm run build`, ale nie w `npm run dev`. Kryterium akceptacji: oba projekty działają pod `localhost`, zmiana w `App` jest widoczna od razu, a `npm run build` tworzy katalog `dist`.
