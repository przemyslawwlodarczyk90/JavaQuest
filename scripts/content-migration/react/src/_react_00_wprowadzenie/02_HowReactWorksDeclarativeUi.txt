#T INTRO Po co React, skoro umiesz manipulować DOM-em?
W torze JavaScript budowałeś interfejs ręcznie: `document.createElement`, `appendChild`, `classList.add`, `textContent = ...`. Przy jednym przycisku to działa. Przy tabeli ticketów z wyszukiwarką, filtrem statusu, sortowaniem, paginacją i licznikiem zaznaczonych wierszy zaczyna się problem: każda zmiana danych wymaga pamiętania, które fragmenty DOM-u trzeba zaktualizować. Zapomnisz o jednym — licznik pokazuje 3, a zaznaczone są 4 wiersze.

React rozwiązuje dokładnie ten problem. Zamiast opisywać kroki („znajdź element, zmień tekst, dodaj klasę”), opisujesz, **jak UI ma wyglądać dla danych danych**. React sam ustala, co zmienić w DOM-ie.

#T DEFINITION Interfejs deklaratywny: UI = f(stan)
**Imperatywnie** mówisz przeglądarce, CO ma zrobić krok po kroku. **Deklaratywnie** mówisz, JAKI ma być wynik.

W React komponent to funkcja: dostaje dane (props i state) i zwraca opis interfejsu (JSX). Gdy dane się zmieniają, React wywołuje funkcję ponownie, porównuje nowy opis z poprzednim i nanosi na prawdziwy DOM tylko różnice.

Czym React NIE jest: nie jest frameworkiem z routingiem, obsługą HTTP i formularzami w zestawie. To biblioteka do budowania interfejsu z komponentów. Resztę (router, pobieranie danych, testy) dobierasz z ekosystemu — tak właśnie zrobimy w kursie.

#T ANALOGY Nawigacja w samochodzie
Imperatywnie: „za 200 m skręć w lewo, potem prosto 2 km, potem w prawo”. Jeśli zjedziesz z trasy, instrukcje przestają pasować.

Deklaratywnie: wpisujesz adres docelowy. Nawigacja sama wylicza drogę z miejsca, w którym aktualnie jesteś — także po każdym zboczeniu z trasy.

W React „adres docelowy” to JSX opisujący UI dla aktualnych danych, a „wyliczanie drogi” to praca Reacta, który ustala minimalne zmiany w DOM-ie.

#T CODE_BASIC Imperatywnie: licznik w czystym JavaScripcie
Musisz pamiętać o każdym miejscu, które zależy od `count`. Dodanie drugiego widoku licznika oznacza dopisanie kolejnej linii aktualizacji.
```
const button = document.querySelector('#add');
const label = document.querySelector('#count');
let count = 0;

button.addEventListener('click', () => {
  count++;
  label.textContent = `Kliknięto ${count} razy`;
  // a jeśli count pokazujemy też w nagłówku? trzeba pamiętać o kolejnej aktualizacji
});
```

#T CODE_PRACTICAL Deklaratywnie: ten sam licznik w React
Opisujesz UI dla wartości `count`. Każde miejsce, które używa `count`, aktualizuje się samo, bo cały opis jest liczony od nowa.
```
import { useState } from 'react';

export function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <h2>Licznik: {count}</h2>
      <button onClick={() => setCount(count + 1)}>Dodaj</button>
      <p>Kliknięto {count} razy</p>
    </div>
  );
}
```

#T VISUAL_EXAMPLE Jak React aktualizuje ekran
  zdarzenie (klik)         →  zmiana stanu: setCount(1)
        │
        ▼
  React wywołuje Counter()  →  nowy opis UI (JSX):  <h2>Licznik: 1</h2> ...
        │
        ▼
  porównanie z poprzednim opisem (<h2>Licznik: 0</h2>)
        │
        ▼
  zmiana w DOM tylko tam, gdzie coś się różni: tekst w <h2> i <p>

Nie musisz wiedzieć, które elementy zmienić. Wystarczy zmienić dane.

#T DEFINITION Komponenty: klocki interfejsu
Interfejs w React składa się z komponentów — funkcji zwracających JSX. Komponent może zawierać inne komponenty, tak jak HTML zawiera elementy. DevDesk rozłożony na komponenty:

App
├── Header
├── Sidebar
│   └── FilterGroup (×3)
└── Main
    ├── StatCard (×3)
    ├── Toolbar
    │   ├── SearchInput
    │   └── StatusSelect
    ├── TicketTable
    │   └── TicketRow (×N)
    └── Pagination

Każdy komponent odpowiada za jeden fragment ekranu. Raz napisany `StatCard` użyjesz trzy razy z różnymi danymi.

#T NOTE Jednokierunkowy przepływ danych
Dane w React płyną z góry na dół: rodzic przekazuje dane dzieciom przez props. Dziecko nie zmienia danych rodzica bezpośrednio — może jedynie wywołać funkcję, którą rodzic mu przekazał („kliknięto wiersz 42”). Dzięki temu zawsze wiadomo, kto jest właścicielem danych i skąd bierze się zmiana. To zasada, do której wrócimy wielokrotnie — szczególnie w rozdziale o architekturze stanu.

#T STEP_BY_STEP Ćwiczenie myślowe: przepisz problem na dane
Zanim napiszesz pierwszy komponent, przećwicz najważniejszy nawyk Reactowca — patrzenie na ekran jak na funkcję danych.
1. Weź makietę DevDesk z poprzedniej lekcji.
2. Wypisz wszystkie dane, które widać na ekranie: lista ticketów, tekst w wyszukiwarce, wybrany status, numer strony, zaznaczony wiersz.
3. Przy każdej pozycji zapytaj: czy to się zmienia, gdy użytkownik coś robi? Jeśli tak — to stan.
4. Przy każdej pozycji zapytaj: czy da się to wyliczyć z innych danych? Liczba „124 otwarte” wynika z listy ticketów — to nie jest osobny stan.
5. Zapisz listę. Wrócimy do niej w rozdziale 04, gdy będziemy projektować state tabeli.

#T PITFALL Myślenie „jak zmienić DOM” w React
Osoby przychodzące z czystego JavaScriptu często próbują w React szukać elementów (`document.querySelector`) i zmieniać je ręcznie. To walka z biblioteką: React przy kolejnym renderze nadpisze Twoje zmiany, bo „prawdą” są dla niego dane, a nie DOM.

#T CODE_WRONG Ręczna zmiana DOM w komponencie
```
export function Counter() {
  let count = 0;
  return (
    <button onClick={() => {
      count++;
      document.querySelector('#label').textContent = count; // React o tym nie wie
    }}>
      Dodaj <span id="label">{count}</span>
    </button>
  );
}
```

#T CODE_RIGHT Zmiana danych — React aktualizuje DOM
```
import { useState } from 'react';

export function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(count + 1)}>
      Dodaj <span>{count}</span>
    </button>
  );
}
```

#T WHEN_TO_USE Kiedy React ma sens, a kiedy nie
React opłaca się, gdy interfejs ma dużo stanu i interakcji: panele administracyjne, aplikacje typu SaaS, formularze wieloetapowe, dashboardy, edytory. Do prostej strony wizytówki z jednym formularzem kontaktowym React jest przesadą — wystarczy HTML i odrobina JavaScriptu, ewentualnie generator stron statycznych. React nie przyspiesza sam z siebie aplikacji; on porządkuje sposób, w jaki budujesz złożony interfejs.

#T SUMMARY Podsumowanie
React to biblioteka do budowania interfejsu z komponentów. Zamiast ręcznie aktualizować DOM, opisujesz UI jako funkcję danych (UI = f(stan)), a React sam nanosi minimalne zmiany. Dane płyną z góry na dół przez props, zmiany zgłasza się w górę przez funkcje. Kryterium akceptacji: potrafisz rozpisać ekran DevDesk na komponenty i wskazać, które dane są stanem, a które da się wyliczyć.
