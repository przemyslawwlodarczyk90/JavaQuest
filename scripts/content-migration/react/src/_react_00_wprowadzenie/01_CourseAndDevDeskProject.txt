#T INTRO Kurs React, w którym po każdej lekcji coś działa na ekranie
Ten tor uczy Reacta przez budowanie jednej, coraz większej aplikacji. Nie zaczynamy od katalogu hooków, tylko od problemu: „chcę tabelę ticketów”, „chcę ją filtrować”, „chcę móc wysłać komuś link do konkretnego ticketu”. Każde narzędzie Reacta pojawia się dokładnie wtedy, gdy jest potrzebne do zbudowania kolejnej funkcji.

Po każdej lekcji możesz powiedzieć: „przed lekcją moja aplikacja tego nie robiła — teraz robi”.

Zakładamy, że znasz JavaScript z toru JavaScript: funkcje strzałkowe, `map`/`filter`, destrukturyzację, spread, moduły ES, `async`/`await` i `fetch`. Tych rzeczy nie tłumaczymy od zera — używamy ich od pierwszej lekcji.

#T DEFINITION Dwa tory jednocześnie: JSX i TSX
React piszemy w JavaScripcie — to jest podstawa kursu. Ale w praktyce większość nowych projektów React powstaje w TypeScripcie, więc od rozdziału 02 każdy przykład dostajesz w dwóch wersjach:

- **JSX** — plik `.jsx`, czysty JavaScript z JSX,
- **TSX** — plik `.tsx`, ten sam kod z typami TypeScript.

Wersje są wyświetlane obok siebie (na wąskim ekranie jedna pod drugą). W każdej lekcji jest też sekcja „JSX ↔ TSX — różnice”, która mówi, co dokładnie dopisaliśmy w TSX i jaki błąd TypeScript wyłapałby za nas. Rozdział 01 to krótkie wprowadzenie do TypeScriptu — tyle, żeby te różnice rozumieć.

#T CODE_JSX Ten sam komponent w JSX
Komponent karty statystyki. W JavaScripcie nic nie mówi, jakie props są wymagane — dowiesz się dopiero, gdy coś się nie wyświetli.
```
// StatCard.jsx
export function StatCard({ label, value }) {
  return (
    <div className="stat-card">
      <span>{label}</span>
      <strong>{value}</strong>
    </div>
  );
}
```

#T CODE_TSX Ten sam komponent w TSX
Jedyna różnica to opis props. Edytor podpowie pola, a pominięcie `value` będzie błędem jeszcze przed uruchomieniem aplikacji.
```
// StatCard.tsx
type StatCardProps = {
  label: string;
  value: number;
};

export function StatCard({ label, value }: StatCardProps) {
  return (
    <div className="stat-card">
      <span>{label}</span>
      <strong>{value}</strong>
    </div>
  );
}
```

Ta jedna aplikacja zawiera prawie wszystko, z czym pracuje się w React: komponenty, tabelę, wyszukiwanie, filtry, sortowanie, paginację, formularze z walidacją, modal, routing, dane z API, obsługę błędów, testy i wdrożenie.

#T CODE_JSX Model danych: ticket w JavaScripcie
Tak wygląda jeden ticket. Ten kształt danych będzie wracał w każdej lekcji — warto go zapamiętać.
```
// data/tickets.js
export const tickets = [
  {
    id: 42,
    title: 'API timeout przy eksporcie',
    description: 'Eksport CSV przerywa się po 30 s.',
    status: 'OPEN',          // 'OPEN' | 'IN_PROGRESS' | 'CLOSED'
    priority: 'HIGH',        // 'LOW' | 'MEDIUM' | 'HIGH' | 'CRITICAL'
    assignee: 'anna',        // albo null, gdy nikt nie jest przypisany
    createdAt: '2026-10-01T09:30:00Z',
    tags: ['api', 'export'],
  },
];
```

#T CODE_TSX Model danych: typ Ticket w TypeScripcie
W TSX ten sam opis z komentarzy staje się typem. TypeScript nie pozwoli wpisać `status: 'DONE'` ani zapomnieć o polu `title`.
```
// types.ts
export type TicketStatus = 'OPEN' | 'IN_PROGRESS' | 'CLOSED';
export type TicketPriority = 'LOW' | 'MEDIUM' | 'HIGH' | 'CRITICAL';

export type Ticket = {
  id: number;
  title: string;
  description: string;
  status: TicketStatus;
  priority: TicketPriority;
  assignee: string | null;
  createdAt: string; // data w formacie ISO
  tags: string[];
};
```

#T STEP_BY_STEP Rytm każdej lekcji
1. **Rozgrzewka** — kilka pytań z wcześniejszych lekcji. Odpowiedz z pamięci, zanim przeczytasz dalej.
2. **Problem w DevDesk** — czego brakuje w aplikacji i dlaczego to przeszkadza.
3. **Model mentalny** — jak działa mechanizm Reacta, który rozwiąże problem.
4. **Działający przykład** — mały, kompletny kod w JSX i TSX.
5. **JSX ↔ TSX** — co różni obie wersje.
6. **Budujemy razem** — dodajesz funkcję do DevDesk krok po kroku.
7. **Pułapki** — błędny kod obok poprawnego.
8. **Kryterium akceptacji** — lista rzeczy, które mają działać na ekranie. Jeśli coś nie działa — wracasz do kroku 6.

Rozdziały kończą się lekcją **Boss**: podobne zadanie w innej domenie (np. katalog produktów zamiast ticketów), z mniejszą liczbą podpowiedzi. To sprawdza, czy umiesz zastosować wiedzę, a nie tylko powtórzyć kroki.

#T NOTE Checkpointy: nie utkniesz przez błąd z poprzedniej lekcji
Każda lekcja praktyczna zaczyna się od stanu projektu „po poprzedniej lekcji” — kod startowy jest w treści lekcji. Jeśli w lekcji 12 coś zepsułeś, lekcja 13 i tak zaczyna się od działającego kodu. Najlepiej trzymać projekt w Gicie i robić commit po każdej lekcji — wtedy łatwo porównać swoją wersję z wzorcową.

#T USAGE Jak pracować z tym kursem
- Pisz kod sam, zamiast kopiować — kopiowanie daje złudzenie zrozumienia.
- Najpierw wersja JSX, potem przepisz ją na TSX i zobacz, co podkreśli edytor. To najszybszy sposób, żeby oswoić się z TypeScriptem.
- Po lekcji zrób quiz bez zaglądania do teorii — przypominanie z pamięci utrwala wiedzę dużo lepiej niż ponowne czytanie.
- Gwiazdki przy lekcji rosną dopiero przy powtórce po kilku dniach. To celowe: wiedza, którą pamiętasz po tygodniu, jest naprawdę Twoja.
- Wszystkie lekcje są otwarte. Platforma podpowiada zalecaną kolejność, ale możesz wejść w dowolny temat.

#T PITFALL Najczęstszy błąd: czytanie zamiast budowania
Przeczytanie komponentu z `useState` i uznanie go za oczywisty to nie to samo, co samodzielne zbudowanie filtrowanej tabeli. Jeśli w lekcji nie uruchomiłeś kodu i nie zobaczyłeś efektu w przeglądarce — lekcja nie jest skończona.
