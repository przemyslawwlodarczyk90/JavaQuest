#T INTRO Co dzieje się między Twoim plikiem .jsx a przeglądarką
Przeglądarka nie rozumie JSX ani TypeScriptu. Rozumie HTML, CSS i JavaScript. Ktoś musi więc zamienić `<App />` na zwykły JavaScript, a z `.tsx` usunąć typy. Robi to Vite. Zrozumienie tej drogi pomaga czytać komunikaty błędów, konfigurować projekt i wiedzieć, dlaczego np. obrazek w `public/` działa inaczej niż obrazek zaimportowany w kodzie.

#T VISUAL_EXAMPLE Struktura projektu startowego
devdesk-js/
├── index.html          ← punkt wejścia: zawiera <div id="root"> i <script src="/src/main.jsx">
├── package.json        ← zależności i skrypty (dev, build, preview, lint)
├── vite.config.js      ← konfiguracja Vite (wtyczka React)
├── eslint.config.js    ← reguły lintera
├── public/             ← pliki kopiowane bez zmian (favicon, robots.txt)
└── src/
    ├── main.jsx        ← createRoot(...).render(<App />)
    ├── App.jsx         ← główny komponent
    ├── App.css
    ├── index.css       ← style globalne
    └── assets/         ← obrazki importowane w kodzie

W projekcie TS dochodzą: `tsconfig.json` (+ `tsconfig.app.json`, `tsconfig.node.json`), a pliki mają rozszerzenia `.ts`/`.tsx` (`vite.config.ts`, `main.tsx`, `App.tsx`).

#T DEFINITION index.html jest punktem wejścia
W Vite to `index.html` (w katalogu głównym, nie w `public/`) jest punktem startowym. Przeglądarka ładuje HTML, a ten zawiera `<script type="module" src="/src/main.jsx">`. Vite przechwytuje to żądanie, przetwarza `main.jsx` i wszystkie importowane przez niego moduły. W projekcie TS skrypt wskazuje `/src/main.tsx`.

#T DEFINITION Transformacja JSX: to tylko wywołania funkcji
JSX to składnia, którą narzędzie zamienia na wywołania funkcji z biblioteki React. Element JSX zamienia się w obiekt opisujący, co narysować. Nie ma tu żadnej magii ani szablonów HTML — to zwykły JavaScript.

#T CODE_BASIC Co piszesz
```
function Greeting({ name }) {
  return <h1 className="title">Cześć, {name}!</h1>;
}
```

#T CODE_PRACTICAL Co z tego robi narzędzie (uproszczenie)
Nowoczesny „automatyczny” runtime JSX importuje funkcję `jsx` sam — dlatego w plikach komponentów nie musisz pisać `import React from 'react'`.
```
import { jsx as _jsx } from 'react/jsx-runtime';

function Greeting({ name }) {
  return _jsx('h1', { className: 'title', children: ['Cześć, ', name, '!'] });
}
```

#T NOTE JSX ↔ TSX — co się dzieje z typami
Przy budowaniu TSX narzędzie robi dwie rzeczy: zamienia JSX na wywołania funkcji (tak samo jak w JSX) i **usuwa typy**. Typy nie istnieją w czasie działania aplikacji — w przeglądarce nie ma żadnej różnicy między wersją JSX a TSX. Sprawdzanie typów to osobny krok (`tsc`), który działa w edytorze i podczas `npm run build`. Dlatego TypeScript chroni Cię przed błędami podczas pisania, ale nie sprawdzi danych, które przyjdą z API w czasie działania — do tego służy walidacja (np. Zod, rozdział 05).

#T CODE_JSX Import zasobów w JSX
Importując obrazek lub plik CSS, mówisz Vite, że jest częścią aplikacji: dostanie nazwę z hashem i trafi do `dist/assets`.
```
import logo from './assets/logo.svg';
import './App.css';

export default function App() {
  return (
    <header>
      <img src={logo} alt="DevDesk" width={32} />
      {/* plik z public/ podajesz ścieżką od korzenia */}
      <img src="/favicon.svg" alt="" width={16} />
    </header>
  );
}
```

#T CODE_TSX Import zasobów w TSX
Kod identyczny. TypeScript wie, że import `.svg` zwraca tekst z adresem, dzięki deklaracjom `vite/client`. Bez nich podkreśliłby import jako „nieznany moduł”.
```
import logo from './assets/logo.svg';
import './App.css';

export default function App() {
  return (
    <header>
      <img src={logo} alt="DevDesk" width={32} />
      <img src="/favicon.svg" alt="" width={16} />
    </header>
  );
}
```

#T STEP_BY_STEP Przygotuj czysty szkielet DevDesk
1. Usuń z `src/App.jsx` (lub `.tsx`) zawartość szablonu i zostaw pusty komponent zwracający `<h1>DevDesk</h1>`.
2. Usuń niepotrzebne `src/assets/react.svg` i zawartość `App.css`.
3. W `index.html` zmień `<title>` na `DevDesk` i `lang` na `pl`.
4. W `src/index.css` zostaw tylko proste style bazowe: `body { margin: 0; font-family: system-ui, sans-serif; }`.
5. Utwórz katalogi `src/components` i `src/data` — tam będą komponenty i dane ticketów.
6. W projekcie TS utwórz `src/types.ts` z typem `Ticket` z lekcji 1.
7. Uruchom `npm run dev` i sprawdź, że widać tylko nagłówek „DevDesk”.
8. Zrób commit: „Czysty szkielet DevDesk”.

#T PITFALL Pliki w public/ a importy
Plik z `public/` jest kopiowany bez zmian i podaje się go ścieżką od korzenia (`/logo.svg`). Plik z `src/assets` trzeba zaimportować. Typowy błąd to wpisanie `src="./assets/logo.svg"` w JSX — taki adres nie przejdzie przez Vite i po zbudowaniu obrazka nie będzie.

#T CODE_WRONG Ścieżka do pliku z src jako tekst
```
<img src="./assets/logo.svg" alt="DevDesk" />
```

#T CODE_RIGHT Import pliku z src
```
import logo from './assets/logo.svg';

<img src={logo} alt="DevDesk" />
```

#T SUMMARY Podsumowanie
`index.html` ładuje `main.jsx`/`main.tsx`, a ten renderuje `App` w `#root`. JSX jest zamieniany na wywołania funkcji `jsx`, a w TSX dodatkowo usuwane są typy — w przeglądarce obie wersje działają identycznie. Pliki z `src` importujesz, pliki z `public` podajesz ścieżką od korzenia. Kryterium akceptacji: masz czysty szkielet DevDesk z katalogami `components` i `data` (oraz `types.ts` w wersji TS) i rozumiesz, co Vite robi z Twoim kodem.
