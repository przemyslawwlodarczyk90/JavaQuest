#T INTRO Spotkanie TypeScriptu z Reactem
Znasz już typy podstawowe, obiekty, unie i generyki. Czas zobaczyć, jak to wszystko wygląda w komponentach React — bo tak będzie wyglądała każda kolejna lekcja. Na konkretnym komponencie DevDesk przejdziesz przez wszystkie miejsca, w których wersja `.tsx` różni się od `.jsx`, i ustalisz zasady, których kurs będzie się trzymał.

#T DEFINITION Gdzie pojawiają się typy w komponencie React
W typowym komponencie TSX typy pojawiają się w kilku stałych miejscach:
1. **props** — `type XProps = {...}` i `function X({ a, b }: XProps)`,
2. **children** — `children: ReactNode`,
3. **callbacki w props** — `onSelect: (id: number) => void`,
4. **stan** — `useState<Typ>(...)`, gdy wartość startowa nie mówi wszystkiego,
5. **zdarzenia** — `ChangeEvent<HTMLInputElement>`, `FormEvent<HTMLFormElement>`,
6. **refs** — `useRef<HTMLInputElement>(null)`,
7. **kontekst** — `createContext<Typ | null>(null)`.

Cała reszta — JSX, logika, hooki, warunki, `map` — wygląda identycznie w obu wersjach.

#T CODE_JSX Wiersz tabeli ticketów w JSX
```
// TicketRow.jsx
export function TicketRow({ ticket, selected, onSelect }) {
  return (
    <tr className={selected ? 'row row--selected' : 'row'} onClick={() => onSelect(ticket.id)}>
      <td>{ticket.id}</td>
      <td>{ticket.title}</td>
      <td>{ticket.assignee ?? '—'}</td>
    </tr>
  );
}
```

#T CODE_TSX Wiersz tabeli ticketów w TSX
```
// TicketRow.tsx
import type { Ticket } from '../types';

type TicketRowProps = {
  ticket: Ticket;
  selected: boolean;
  onSelect: (id: number) => void;
};

export function TicketRow({ ticket, selected, onSelect }: TicketRowProps) {
  return (
    <tr className={selected ? 'row row--selected' : 'row'} onClick={() => onSelect(ticket.id)}>
      <td>{ticket.id}</td>
      <td>{ticket.title}</td>
      <td>{ticket.assignee ?? '—'}</td>
    </tr>
  );
}
```

#T NOTE JSX ↔ TSX — pełne zestawienie dla TicketRow
Dopisaliśmy: `import type { Ticket }` (import samego typu — znika po kompilacji) i `type TicketRowProps` z trzema polami. Ciało komponentu jest **znak w znak** takie samo.

Co zyskujemy:
- użycie `<TicketRow ticket={t} />` bez `selected` i `onSelect` to błąd kompilacji,
- `ticket.` w edytorze podpowiada pola,
- `onSelect(ticket)` zamiast `onSelect(ticket.id)` to błąd — kontrakt mówi o liczbie,
- `ticket.assignee.toUpperCase()` byłoby błędem — `assignee` może być `null`.

Co tracimy: kilka linii kodu i chwilę na zapisanie typu. W zamian dostajemy dokumentację komponentu, która nie może się zdezaktualizować.

#T DEFINITION ReactNode, ReactElement i PropsWithChildren
- **`ReactNode`** — wszystko, co można wyrenderować: element JSX, tekst, liczba, `null`, `undefined`, `false`, tablica tych rzeczy. Typ dla `children` i dla props przyjmujących „treść”.
- **`ReactElement`** (lub `JSX.Element`) — konkretny element JSX (wynik `<Coś />`). Węższy niż `ReactNode`.
- **`PropsWithChildren<P>`** — skrót dodający `children?: ReactNode` do typu props.

Zasada: dla `children` i „slotów” używaj `ReactNode`.

#T CODE_BASIC Komponent z children w TSX
```
import type { ReactNode } from 'react';

type PanelProps = {
  title: string;
  children: ReactNode;
};

export function Panel({ title, children }: PanelProps) {
  return (
    <section className="panel">
      <h2>{title}</h2>
      {children}
    </section>
  );
}
```

#T DEFINITION Jak opisać props w samym JavaScripcie: PropTypes i JSDoc
W czystym JSX masz dwie możliwości „typowania”:
- **JSDoc** — komentarze `/** @param {{ title: string }} props */`. VS Code czyta je i podpowiada pola nawet w pliku `.jsx`, a z opcją `checkJs` może zgłaszać błędy.
- **PropTypes** — biblioteka sprawdzająca props w czasie działania i wypisująca ostrzeżenia w konsoli. W React 19 wbudowane sprawdzanie `propTypes` w komponentach funkcyjnych zostało usunięte — dziś zespół Reacta zaleca TypeScript. PropTypes spotkasz w starszych projektach.

W kursie przy wersji JSX czasem pokażemy JSDoc, żeby było widać, że opis danych da się zrobić także bez TS.

#T CODE_JSX Props opisane przez JSDoc
```
// Panel.jsx
/**
 * @param {{ title: string, children: import('react').ReactNode }} props
 */
export function Panel({ title, children }) {
  return (
    <section className="panel">
      <h2>{title}</h2>
      {children}
    </section>
  );
}
```

#T CODE_TSX Props opisane typem TypeScript
```
// Panel.tsx
import type { ReactNode } from 'react';

export function Panel({ title, children }: { title: string; children: ReactNode }) {
  return (
    <section className="panel">
      <h2>{title}</h2>
      {children}
    </section>
  );
}
```

#T API_REFERENCE Najważniejsze opcje tsconfig dla projektu React
- `"strict": true` — włącza wszystkie ścisłe sprawdzenia (m.in. `strictNullChecks`). Zawsze włączone w kursie.
- `"jsx": "react-jsx"` — nowoczesna transformacja JSX (bez importu `React` w każdym pliku).
- `"noEmit": true` — `tsc` tylko sprawdza typy; budowaniem zajmuje się Vite.
- `"moduleResolution": "bundler"` — rozwiązywanie importów jak w Vite.
- `"noUnusedLocals"`, `"noUnusedParameters"` — błąd przy nieużywanych zmiennych.
- `"allowJs"` i `"checkJs"` — pozwalają mieć pliki `.js`/`.jsx` w projekcie TS i sprawdzać je na podstawie JSDoc (przydatne przy migracji, rozdział 21).
- `"types": ["vite/client"]` — typy Vite (import obrazków, `import.meta.env`).

#T DEFINITION Zasady kursu dla wersji TSX
1. Typy props zawsze jako nazwany `type NazwaKomponentuProps` (wyjątek: bardzo małe komponenty).
2. `type` zamiast `interface`.
3. Importy typów jako `import type { ... }`.
4. Bez `any`. Gdy dane są nieznane — `unknown` i sprawdzenie.
5. Brak wartości w danych = `null` (np. `assignee: string | null`).
6. Generyk w `useState` tylko wtedy, gdy wartość startowa nie mówi wszystkiego.
7. Komponenty jako zwykłe funkcje z typowanym parametrem — bez `React.FC` (starszy zapis, który spotkasz w internecie; nie daje żadnej przewagi).

#T STEP_BY_STEP Przepisz komponent z JSX na TSX
1. W projekcie `devdesk-ts` utwórz `src/components/TicketRow.tsx` i wklej wersję JSX komponentu.
2. Zobacz błędy: parametry `ticket`, `selected`, `onSelect` niejawnie mają typ `any` (przy `strict` to błąd).
3. Dopisz `import type { Ticket } from '../types';`.
4. Dopisz `type TicketRowProps` z trzema polami i dodaj `: TicketRowProps` przy parametrze.
5. Wyrenderuj `<TicketRow ticket={tickets[0]} />` w `App.tsx` — zobacz błąd o brakujących props i dopisz je.
6. Spróbuj wpisać `onSelect={(t) => console.log(t.title)}` — przeczytaj błąd: `t` jest liczbą.
7. Uruchom `npm run build` — sprawdzanie typów przechodzi.

#T PITFALL Typ props za szeroki: any i object
`function TicketRow(props: any)` albo `ticket: object` wyglądają jak typowanie, ale nic nie dają: `any` wyłącza sprawdzanie, a `object` nie ma żadnych znanych pól. Typ props ma dokładnie opisywać dane, z których komponent korzysta.

#T SUMMARY Podsumowanie
Komponent TSX różni się od JSX tylko w kilku stałych miejscach: typ props, `children: ReactNode`, typy callbacków, generyki w hookach, typy zdarzeń i refs. Ciało komponentu jest identyczne. W czystym JS props można opisać JSDoc (podpowiedzi w edytorze) lub PropTypes (starsze projekty). Kurs trzyma się zasad: `strict`, `type` zamiast `interface`, bez `any`, `null` jako brak wartości, bez `React.FC`. Kryterium akceptacji: przepisałeś `TicketRow` z JSX na TSX i doprowadziłeś do przejścia `npm run build`.
