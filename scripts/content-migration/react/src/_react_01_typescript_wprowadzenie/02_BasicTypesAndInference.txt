#T INTRO Typy podstawowe — i kiedy ich NIE pisać
W tej lekcji poznasz typy, które pojawiają się w każdym komponencie: tekst, liczby, wartości logiczne, tablice, `null`. Ważniejsza od samych typów jest jednak druga część lekcji: **inferencja**. TypeScript w większości miejsc sam wie, jaki typ ma zmienna, i dopisywanie typów wszędzie to częsty błąd początkujących.

#T DEFINITION Typy proste
- `string` — tekst: `'OPEN'`, `` `#${id}` ``,
- `number` — każda liczba, całkowita i zmiennoprzecinkowa: `42`, `3.5`,
- `boolean` — `true` / `false`,
- `null` i `undefined` — brak wartości,
- `bigint` i `symbol` — rzadko potrzebne w React.

Adnotację typu zapisujesz po dwukropku: `let title: string = 'Błąd logowania';`. Typy w TS piszemy małymi literami — `String` z wielkiej litery to obiekt opakowujący, którego się nie używa.

#T CODE_JSX Zmienne w JavaScripcie
```
// stats.js
export let openCount = 124;
export let title = 'Otwarte tickety';
export let isUrgent = false;
export let assignee = null;

openCount = 'dużo'; // JavaScript nie protestuje
```

#T CODE_TSX Te same zmienne w TypeScripcie
Bez ani jednej adnotacji TypeScript zna typy wszystkich zmiennych — wywnioskował je z wartości początkowych.
```
// stats.ts
export let openCount = 124;          // number
export let title = 'Otwarte tickety'; // string
export let isUrgent = false;         // boolean
export let assignee: string | null = null; // tu typ trzeba podać — sam null to za mało

// @ts-expect-error — do zmiennej typu number nie przypiszesz tekstu
openCount = 'dużo';
```

#T NOTE JSX ↔ TSX — inferencja w praktyce
W wersji TS dopisaliśmy typ tylko w jednym miejscu: przy `assignee`. Z wartości `null` TypeScript wywnioskowałby typ „zawsze null” i nie pozwoliłby później przypisać `'anna'`. Zasada na cały kurs: **typ podajesz wtedy, gdy wartość początkowa nie mówi wszystkiego** — np. pusta tablica, `null` na start, parametr funkcji. W pozostałych miejscach zaufaj inferencji. To samo dotyczy `useState` w React: `useState(0)` wie, że to liczba, ale `useState(null)` wymaga podpowiedzi — zobaczysz to w rozdziale 04.

#T DEFINITION Tablice i krotki
- `string[]` — tablica tekstów (zapis równoważny: `Array<string>`),
- `number[]` — tablica liczb,
- `Ticket[]` — tablica obiektów typu `Ticket`,
- `[number, string]` — **krotka**: tablica o stałej długości, gdzie każda pozycja ma swój typ.

Krotki znasz już nieświadomie: `useState` zwraca krotkę `[wartość, funkcja]`, którą rozbierasz destrukturyzacją.

#T CODE_BASIC Tablice i krotka
```
export const tags: string[] = ['api', 'export'];
export const ids = [41, 42, 43]; // number[] z inferencji

export const empty: string[] = []; // pusta tablica — typ trzeba podać

export function useToggle(): [boolean, () => void] {
  let value = false;
  return [value, () => { value = !value; }];
}

const [on, toggle] = useToggle(); // on: boolean, toggle: () => void
```

#T CODE_PRACTICAL Metody tablic zachowują typy
`map`, `filter`, `find` znane z toru JavaScript działają tak samo, a TypeScript śledzi typy na każdym etapie.
```
type Ticket = { id: number; title: string; status: 'OPEN' | 'CLOSED' };

export function openTitles(tickets: Ticket[]) {
  const open = tickets.filter((t) => t.status === 'OPEN'); // Ticket[]
  const titles = open.map((t) => t.title);                  // string[]
  const first = tickets.find((t) => t.id === 42);           // Ticket | undefined
  return { titles, first };
}
```

#T DEFINITION any, unknown i never
- **`any`** — „wyłącz sprawdzanie”. Wartość typu `any` można użyć jakkolwiek, a błędy wracają do czasu działania. Unikaj — to dziura w systemie typów.
- **`unknown`** — „nie wiem, co to jest”. Wartości `unknown` nie użyjesz, dopóki nie sprawdzisz jej typu. Bezpieczny odpowiednik `any` dla danych z zewnątrz (np. wynik `JSON.parse`).
- **`never`** — „to się nigdy nie zdarzy”. Pojawia się np. przy sprawdzaniu, czy obsłużyłeś wszystkie przypadki w `switch` (lekcja 4).

#T CODE_WRONG any przepuszcza błędy
```
const data: any = JSON.parse('{"title": "Błąd"}');
data.titel.toUpperCase(); // brak błędu kompilacji — wybuchnie w przeglądarce
```

#T CODE_RIGHT unknown wymusza sprawdzenie
```
const data: unknown = JSON.parse('{"title": "Błąd"}');

if (typeof data === 'object' && data !== null && 'title' in data && typeof data.title === 'string') {
  console.log(data.title.toUpperCase()); // tu TS wie, że title to string
}
```

#T DEFINITION Typy literałowe i as const
Typem może być konkretna wartość: `let status: 'OPEN' = 'OPEN'` przyjmie tylko tekst `'OPEN'`. Zmienna `const` dostaje typ literałowy automatycznie: `const s = 'OPEN'` ma typ `'OPEN'`, a `let s = 'OPEN'` — typ `string`, bo `let` może się zmienić.

`as const` „zamraża” cały obiekt lub tablicę: wszystkie pola stają się tylko do odczytu i dostają typy literałowe. Przydaje się przy listach opcji w React.

#T CODE_PRACTICAL Lista statusów z as const
```
export const STATUSES = ['OPEN', 'IN_PROGRESS', 'CLOSED'] as const;
// typ: readonly ['OPEN', 'IN_PROGRESS', 'CLOSED']

export type Status = (typeof STATUSES)[number]; // 'OPEN' | 'IN_PROGRESS' | 'CLOSED'

export function nextStatus(s: Status): Status {
  const i = STATUSES.indexOf(s);
  return STATUSES[Math.min(i + 1, STATUSES.length - 1)];
}
```

#T STEP_BY_STEP Ćwiczenie w Playground: odgadnij typ
1. Wpisz w TS Playground kolejno: `const a = 5`, `let b = 5`, `const c = [1, 2]`, `const d = { id: 1, done: false }`, `const e = [] `.
2. Zanim najedziesz myszą, zapisz na kartce, jaki typ według Ciebie ma każda zmienna.
3. Najedź myszą i porównaj. Zwróć uwagę na różnicę `const a` (typ `5`) i `let b` (typ `number`).
4. Do `const e = []` spróbuj dodać `e.push('x')` — zobacz, jaki typ ma pusta tablica bez adnotacji, i popraw na `const e: string[] = []`.
5. Dodaj `as const` do `d` i spróbuj zmienić `d.done = true` — przeczytaj komunikat o polu tylko do odczytu.

#T PITFALL Adnotacje wszędzie
Kod w stylu `const count: number = 5; const name: string = 'Anna'; const items: string[] = ['a'];` jest poprawny, ale zbędnie długi — TypeScript zna te typy. Nadmiar adnotacji utrudnia czytanie i zmiany. Pisz typy na granicach: parametry funkcji, props komponentów, puste wartości startowe, dane z zewnątrz.

#T SUMMARY Podsumowanie
Typy proste: `string`, `number`, `boolean`, `null`, `undefined`. Tablice `T[]`, krotki `[A, B]`. `any` wyłącza sprawdzanie (unikaj), `unknown` wymusza sprawdzenie (bezpieczny wybór dla danych z zewnątrz). Typy literałowe i `as const` pozwalają ograniczyć wartości do konkretnej listy. Najważniejsza zasada: zaufaj inferencji, a typ dopisuj tam, gdzie wartość startowa nie mówi wszystkiego. Kryterium akceptacji: w Playground poprawnie przewidziałeś typy pięciu zmiennych i zbudowałeś typ `Status` z tablicy `as const`.
