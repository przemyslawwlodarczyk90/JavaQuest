#T INTRO Funkcje, callbacki i generyki — bez strachu
W React funkcje są wszędzie: komponenty to funkcje, handlery zdarzeń to funkcje, props `onChange` i `onSelect` to funkcje przekazywane w dół. W tej lekcji nauczysz się typować funkcje i callbacki, zrozumiesz generyki (te tajemnicze `<T>`, które zobaczysz w `useState<Ticket | null>`) i poznasz typy narzędziowe, którymi z jednego typu `Ticket` zrobisz typ formularza czy typ aktualizacji.

#T DEFINITION Typowanie funkcji
Parametry funkcji zawsze wymagają typów (TypeScript nie zgadnie, czego oczekujesz). Typ wyniku zwykle wywnioskuje sam, ale można go podać po nawiasie. Parametr opcjonalny oznaczasz `?`, a wartość domyślna od razu nadaje typ.

#T CODE_JSX Funkcje i callback w JavaScripcie
```
// filters.js
export function matches(ticket, query, caseSensitive = false) {
  const title = caseSensitive ? ticket.title : ticket.title.toLowerCase();
  const q = caseSensitive ? query : query.toLowerCase();
  return title.includes(q);
}

export function onEachOpen(tickets, callback) {
  tickets.filter((t) => t.status === 'OPEN').forEach(callback);
}
```

#T CODE_TSX Funkcje i callback w TypeScripcie
Typ callbacku `(ticket: Ticket) => void` to kontrakt: „podaj funkcję, która przyjmie ticket i niczego nie zwróci”.
```
// filters.ts
import type { Ticket } from '../types';

export function matches(ticket: Ticket, query: string, caseSensitive = false): boolean {
  const title = caseSensitive ? ticket.title : ticket.title.toLowerCase();
  const q = caseSensitive ? query : query.toLowerCase();
  return title.includes(q);
}

export function onEachOpen(tickets: Ticket[], callback: (ticket: Ticket) => void) {
  tickets.filter((t) => t.status === 'OPEN').forEach(callback);
}

onEachOpen([], (t) => console.log(t.title)); // t: Ticket — typ wywnioskowany z kontraktu
```

#T NOTE JSX ↔ TSX — callbacki w props
To wzorzec, który zobaczysz w każdym rozdziale: rodzic przekazuje dziecku funkcję. W JSX `onSelect` może być czymkolwiek — dziecko wywoła `onSelect(ticket.id)`, a rodzic oczekiwał całego ticketu i nikt tego nie zauważy. W TSX typ props `onSelect: (id: number) => void` ustala umowę po obu stronach: dziecko musi przekazać liczbę, rodzic dostaje liczbę. Zwróć uwagę, że w callbacku `(t) => ...` nie piszesz typu `t` — TypeScript bierze go z kontraktu (tzw. typowanie kontekstowe). Tak samo będzie w `onChange={(e) => ...}` w JSX Reacta.

#T DEFINITION Typ funkcji jako osobny typ
Typ funkcji możesz nazwać i użyć wielokrotnie: `type TicketHandler = (ticket: Ticket) => void;`. `void` jako typ wyniku oznacza „wynik nie jest używany”. Typ `() => void` (bez parametrów) zobaczysz przy `onClick`, `onClose`, `onRetry`.

#T DEFINITION Generyki: funkcja dla „dowolnego typu, ale konsekwentnie”
Generyk to parametr typu — zapisywany w nawiasach ostrych `<T>`. Pozwala napisać jedną funkcję, która działa dla różnych typów, ale zachowuje informację, jaki to typ. Funkcja `first<T>(items: T[]): T | undefined` dla tablicy ticketów zwraca ticket, dla tablicy tekstów — tekst. Bez generyka musiałbyś napisać `any` i stracić typ wyniku.

#T CODE_BASIC Generyczna funkcja paginacji
Napiszesz ją raz, a użyjesz dla ticketów, użytkowników i komentarzy. TypeScript wnioskuje `T` z argumentu.
```
export function paginate<T>(items: T[], page: number, pageSize: number): T[] {
  const start = (page - 1) * pageSize;
  return items.slice(start, start + pageSize);
}

const pageOfIds = paginate([1, 2, 3, 4, 5], 2, 2);  // number[] → [3, 4]
const pageOfTags = paginate(['api', 'ui'], 1, 1);   // string[] → ['api']
```

#T CODE_PRACTICAL Generyk z ograniczeniem: sortowanie po polu
`K extends keyof T` znaczy: „K to nazwa jednego z pól T”. Sortowanie po nieistniejącym polu jest błędem kompilacji — przyda się w rozdziale 04 przy sortowaniu tabeli.
```
import type { Ticket } from '../types';

export function sortBy<T, K extends keyof T>(items: T[], key: K): T[] {
  return [...items].sort((a, b) => (a[key] < b[key] ? -1 : a[key] > b[key] ? 1 : 0));
}

declare const tickets: Ticket[];
export const byTitle = sortBy(tickets, 'title');
// @ts-expect-error — Ticket nie ma pola 'name'
export const wrong = sortBy(tickets, 'name');
```

#T NOTE Generyki w React, które zobaczysz
- `useState<Ticket | null>(null)` — stan, który na początku jest `null`, a potem ticketem,
- `useRef<HTMLInputElement>(null)` — referencja do pola tekstowego,
- `createContext<Preferences | null>(null)` — kontekst,
- `useQuery<Ticket[]>(...)` — dane z serwera,
- `Array<Ticket>` — to samo co `Ticket[]`.

Wszędzie zasada jest ta sama: w nawiasach ostrych mówisz, jakiego typu wartość będzie przechowywana.

#T API_REFERENCE Typy narzędziowe (utility types)
Wbudowane „przekształcacze” typów. Pozwalają wyprowadzać nowe typy z istniejących, zamiast je przepisywać:
- `Partial<Ticket>` — wszystkie pola opcjonalne (np. dane do częściowej aktualizacji, PATCH),
- `Required<T>` — wszystkie pola wymagane,
- `Pick<Ticket, 'id' | 'title'>` — tylko wybrane pola (np. element listy wyboru),
- `Omit<Ticket, 'id' | 'createdAt'>` — wszystkie pola poza wybranymi (np. dane nowego ticketu, gdzie ID nada serwer),
- `Readonly<T>` — wszystkie pola tylko do odczytu,
- `Record<K, V>` — słownik (poprzednia lekcja),
- `ReturnType<typeof fn>` — typ wyniku funkcji,
- `Parameters<typeof fn>` — typy parametrów funkcji jako krotka,
- `NonNullable<T>` — usuwa `null` i `undefined` z typu,
- `Awaited<T>` — typ wartości, na którą „czeka” Promise.

#T CODE_JSX Dane nowego i edytowanego ticketu w JavaScripcie
W JS te trzy kształty istnieją tylko w głowie i w komentarzach.
```
// api.js
// newTicket: wszystkie pola ticketu bez id i createdAt
export function createTicket(newTicket) {
  return { ...newTicket, id: Date.now(), createdAt: new Date().toISOString() };
}

// changes: dowolny podzbiór pól ticketu
export function updateTicket(ticket, changes) {
  return { ...ticket, ...changes };
}
```

#T CODE_TSX Dane nowego i edytowanego ticketu z Omit i Partial
Gdy dodasz pole do `Ticket`, typy `NewTicket` i `TicketChanges` zaktualizują się same.
```
// api.ts
import type { Ticket } from '../types';

export type NewTicket = Omit<Ticket, 'id' | 'createdAt'>;
export type TicketChanges = Partial<Omit<Ticket, 'id'>>;

export function createTicket(newTicket: NewTicket): Ticket {
  return { ...newTicket, id: Date.now(), createdAt: new Date().toISOString() };
}

export function updateTicket(ticket: Ticket, changes: TicketChanges): Ticket {
  return { ...ticket, ...changes };
}
```

#T DEFINITION Typy z bibliotek: @types i typy wbudowane
Biblioteki pisane w TypeScripcie (React Router, TanStack Query, Zod) mają typy w paczce. Starsze biblioteki w czystym JS mają typy w osobnych paczkach `@types/nazwa` (np. `@types/react` — React sam jest napisany w JS i typy dostarcza społeczność). Instalujesz je jako zależność deweloperską: `npm install -D @types/lodash`. Gdy edytor podpowiada parametry funkcji z biblioteki — to właśnie te typy.

#T STEP_BY_STEP Napisz typowane helpery DevDesk
1. Utwórz `src/utils/tickets.ts`.
2. Napisz `paginate<T>` z tej lekcji.
3. Napisz `countBy<T>(items: T[], getKey: (item: T) => string): Record<string, number>` — np. liczba ticketów w każdym statusie.
4. Wywołaj `countBy(tickets, (t) => t.status)` i najedź na `t` — zobacz, że to `Ticket`.
5. Zdefiniuj `type TicketOption = Pick<Ticket, 'id' | 'title'>` i funkcję `toOptions(tickets: Ticket[]): TicketOption[]`.
6. W wersji JS napisz te same funkcje bez typów i dodaj komentarze JSDoc `/** @param {Ticket[]} tickets */` — edytor VS Code użyje ich do podpowiedzi także w pliku `.js`.

#T PITFALL Generyk, który nic nie robi
`function log<T>(value: T): void` — parametr `T` pojawia się tylko raz, więc nie łączy niczego z niczym. Generyk ma sens, gdy wiąże ze sobą typy: wejście z wyjściem (`T[]` → `T`), parametr z parametrem (`T` i `keyof T`). Jeśli `T` występuje raz — wystarczy `unknown`.

#T SUMMARY Podsumowanie
Parametry funkcji zawsze typujesz, wynik zwykle wnioskuje TS. Typ callbacku `(arg: Typ) => void` to kontrakt między rodzicem a dzieckiem — podstawa props `onX` w React. Generyki `<T>` pozwalają pisać funkcje dla dowolnego typu z zachowaniem informacji o nim, a `K extends keyof T` ogranicza parametr do nazw pól. Typy narzędziowe (`Partial`, `Pick`, `Omit`, `Record`, `ReturnType`) wyprowadzają nowe typy z istniejących. Kryterium akceptacji: masz `utils/tickets.ts` z `paginate`, `countBy` i `toOptions`, a typy `NewTicket` i `TicketChanges` wyprowadzone z `Ticket`.
