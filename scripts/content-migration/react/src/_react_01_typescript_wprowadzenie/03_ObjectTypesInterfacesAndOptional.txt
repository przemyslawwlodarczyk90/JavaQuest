#T INTRO Opisz kształt danych DevDesk
W React prawie wszystko jest obiektem: ticket, użytkownik, props komponentu, stan formularza, odpowiedź z API. Ta lekcja uczy opisywać kształt obiektów — to typ, który będziesz pisał najczęściej. Na końcu lekcji masz kompletny plik `types.ts` dla DevDesk.

#T DEFINITION Typ obiektu
Typ obiektu wymienia pola i ich typy. Można go zapisać wprost przy zmiennej albo nazwać słowem `type` i używać wielokrotnie:

`type User = { login: string; name: string; active: boolean };`

TypeScript sprawdza, czy obiekt ma wszystkie wymagane pola, czy typy się zgadzają i czy nie ma pól nieznanych (przy dosłownym zapisie obiektu).

#T CODE_JSX Obiekty w JavaScripcie
Kształt obiektu użytkownika jest „umową” istniejącą tylko w głowie programisty.
```
// users.js
export const anna = { login: 'anna', name: 'Anna Nowak', active: true };

export function displayName(user) {
  return user.active ? user.name : `${user.name} (nieaktywny)`;
}

displayName({ login: 'piotr' }); // brak name — wyświetli "undefined (nieaktywny)"
```

#T CODE_TSX Obiekty w TypeScripcie
```
// users.ts
export type User = {
  login: string;
  name: string;
  active: boolean;
};

export const anna: User = { login: 'anna', name: 'Anna Nowak', active: true };

export function displayName(user: User): string {
  return user.active ? user.name : `${user.name} (nieaktywny)`;
}

// @ts-expect-error — brakuje pól name i active
displayName({ login: 'piotr' });
```

#T NOTE JSX ↔ TSX — gdzie żyje opis kształtu
W JavaScripcie kształt obiektu opisujesz komentarzem albo wcale — i nikt go nie pilnuje. W TypeScripcie `type User` jest jednym miejscem prawdy: dodasz pole `email` do typu, a kompilator wskaże każde miejsce, w którym tworzysz użytkownika bez e-maila. W React tak samo opisujesz props komponentu — `type StatCardProps = {...}` — i to jest najczęstszy typ w całym kursie.

#T DEFINITION Pola opcjonalne i readonly
- `email?: string` — pole **opcjonalne**: może go nie być. Jego typ to w praktyce `string | undefined`, więc przed użyciem trzeba sprawdzić, czy istnieje.
- `readonly id: number` — pole **tylko do odczytu**: po utworzeniu obiektu nie można go zmienić.

Uwaga na różnicę: `assignee?: string` znaczy „pola może nie być”, a `assignee: string | null` znaczy „pole zawsze jest, ale może mieć wartość null”. W DevDesk używamy drugiej wersji — ticket zawsze ma pole `assignee`, czasem z wartością `null`.

#T CODE_BASIC Pole opcjonalne wymaga sprawdzenia
```
export type Contact = {
  readonly id: number;
  name: string;
  email?: string;
};

export function mailLink(c: Contact) {
  // c.email.toLowerCase() — błąd: email może być undefined
  return c.email ? `mailto:${c.email.toLowerCase()}` : null;
}
```

#T DEFINITION type czy interface
Kształt obiektu można też opisać słowem `interface`:

`interface User { login: string; name: string; }`

Dla obiektów oba zapisy działają prawie identycznie. Różnice: `interface` można rozszerzać słowem `extends` i „dopisywać” (dwie deklaracje o tej samej nazwie się łączą), a `type` może opisać też unię (`'OPEN' | 'CLOSED'`), krotkę czy typ funkcji. W kursie używamy `type` — jeden zapis do wszystkiego. W kodzie bibliotek i w dokumentacji spotkasz oba.

#T CODE_PRACTICAL Rozszerzanie typów: & oraz extends
```
type BaseEntity = { id: number; createdAt: string };

// type: łączenie przez &
export type Comment = BaseEntity & { author: string; text: string };

// interface: rozszerzanie przez extends
export interface Attachment extends BaseEntity {
  fileName: string;
  sizeKb: number;
}

export const c: Comment = { id: 1, createdAt: '2026-10-01', author: 'anna', text: 'Sprawdzam' };
```

#T DEFINITION Record — obiekt jako słownik
`Record<Klucz, Wartość>` opisuje obiekt, w którym klucze są określonego typu. Idealny do map typu „status → etykieta” albo „priorytet → kolor”. Jeśli kluczem jest unia literałów, TypeScript wymusi, że obiekt ma wpis dla **każdej** wartości unii.

#T CODE_JSX Mapa etykiet w JavaScripcie
Po dodaniu nowego statusu łatwo zapomnieć o etykiecie — dowiesz się, gdy w UI pojawi się `undefined`.
```
// labels.js
export const statusLabels = {
  OPEN: 'Otwarty',
  IN_PROGRESS: 'W toku',
  CLOSED: 'Zamknięty',
};
```

#T CODE_TSX Mapa etykiet z Record
Dodasz `'BLOCKED'` do typu `TicketStatus` — kompilator od razu zgłosi, że w `statusLabels` brakuje etykiety.
```
// labels.ts
import type { TicketStatus } from '../types';

export const statusLabels: Record<TicketStatus, string> = {
  OPEN: 'Otwarty',
  IN_PROGRESS: 'W toku',
  CLOSED: 'Zamknięty',
};
```

#T STEP_BY_STEP Zbuduj types.ts dla DevDesk
1. W projekcie `devdesk-ts` otwórz (lub utwórz) `src/types.ts`.
2. Zdefiniuj `TicketStatus` i `TicketPriority` jako unie literałów (szczegóły unii w następnej lekcji): `'OPEN' | 'IN_PROGRESS' | 'CLOSED'` i `'LOW' | 'MEDIUM' | 'HIGH' | 'CRITICAL'`.
3. Zdefiniuj `Ticket` z polami: `id`, `title`, `description`, `status`, `priority`, `assignee: string | null`, `createdAt`, `tags: string[]`.
4. Dodaj `User` z polami `login`, `name`, `role: 'agent' | 'admin'`, `avatarUrl?: string`.
5. Dodaj `Comment` łączący `{ id: number; createdAt: string }` z polami `ticketId`, `author`, `text`.
6. W `src/data/tickets.ts` utwórz tablicę `export const tickets: Ticket[] = [...]` z pięcioma ticketami. Celowo wpisz w jednym `status: 'DONE'` i zobacz błąd — potem popraw.
7. W wersji JS utwórz `src/data/tickets.js` z tymi samymi danymi i komentarzem opisującym kształt obiektu.

#T PITFALL Opcjonalne pole zamiast null
Gdy zamiast `assignee: string | null` napiszesz `assignee?: string`, TypeScript pozwoli tworzyć tickety całkiem bez tego pola. Później w kodzie musisz obsługiwać dwa różne „braki” (`undefined` i — z API — `null`). Wybierz jedną konwencję: pole zawsze obecne, brak wartości = `null`.

#T SUMMARY Podsumowanie
Typ obiektu wymienia pola i ich typy; nazwany przez `type` (lub `interface`) staje się wielokrotnego użytku. `pole?:` jest opcjonalne i wymaga sprawdzenia przed użyciem, `readonly` blokuje zmianę. Typy łączysz przez `&` (albo `extends` w interfejsach), a słowniki opisujesz przez `Record<K, V>`, który pilnuje kompletności kluczy. Kryterium akceptacji: masz `types.ts` z typami `Ticket`, `User` i `Comment` oraz dane ticketów, w których TypeScript odrzuca nieprawidłowy status.
