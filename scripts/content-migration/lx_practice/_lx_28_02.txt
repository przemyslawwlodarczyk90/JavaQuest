#Q
Q: Które pole free najczęściej lepiej ocenia zapas dla nowych aplikacji?
+ available
- free zawsze wystarcza
- shared
- total bez innych pól
E: Available uwzględnia szacunkowo pamięć możliwą do odzyskania.
#Q
Q: Co oznacza free w tabeli RAM?
+ Aktualnie nieużywaną pamięć
- Całą pamięć możliwą do odzyskania
- Cały cache
- Cały swap
E: Free nie obejmuje użytecznych stron cache.
#Q
Q: Co oznacza total w tabeli RAM?
+ Pamięć RAM widoczną dla systemu w tym zakresie
- Rozmiar wszystkich dysków
- Suma PID-ów
- Zawsze fizyczne moduły bez odjęcia rezerw
E: Część pamięci może być zarezerwowana lub niewidoczna w danym środowisku.
#Q
Q: Czy niskie free przy wysokim available dowodzi awarii?
+ Nie, wiele RAM może być użyte jako odzyskiwalny cache
- Tak, zawsze OOM
- Tak, trzeba natychmiast restartować
- Tak, trzeba wyłączyć swap
E: Cache jest normalnym sposobem wykorzystania wolnej pamięci.
#Q
Q: Czym jest page cache?
+ Cache zawartości plików w RAM
- Wyłącznie Java heap
- Wyłącznie dysk swap
- Lista zalogowanych kont
E: Pomaga uniknąć ponownego odczytu danych z nośnika.
#Q
Q: Dlaczego drugi odczyt pliku może być szybszy?
+ Dane mogą już być w page cache
- Plik zawsze automatycznie maleje
- Proces zmienia PID na szybszy
- Drugi cat pomija połowę pliku
E: Wynik zależy od rozmiaru, I/O, cache i innych czynników.
#Q
Q: Czy cache jest automatycznie odzyskiwany przy zapotrzebowaniu na RAM?
+ Jądro może odzyskiwać odpowiednie strony
- Nigdy, trzeba robić cron drop_caches
- Wyłącznie po restarcie
- Wyłącznie po wyłączeniu sieci
E: Czyste strony cache są zwykle kandydatami do odzyskania.
#Q
Q: Czy wszystkie buff/cache są zawsze natychmiast dostępne?
+ Nie, odzyskiwalność zależy od rodzaju i stanu stron
- Tak, bez wyjątków
- Tak, także wszystkie dirty pages
- Tak, także locked memory
E: Available jest estymacją uwzględniającą więcej niż proste free+cache.
#Q
Q: Czym są dirty pages?
+ Strony z modyfikacjami, których jeszcze nie zapisano na nośnik
- Zawsze uszkodzone strony RAM
- Strony wyłącznie zombie
- Puste strony pamięci
E: Przed odzyskaniem danych wymagają właściwego zapisu.
#Q
Q: Co oznacza Writeback w meminfo?
+ Pamięć obecnie zapisywaną do nośnika
- Rozmiar historii powłoki
- Liczbę zapisanych maili
- Rozmiar wszystkich swapfile
E: Writeback opisuje trwający zapis, nie cały rozmiar cache.
#Q
Q: Czy sync usuwa cache?
+ Nie, żąda zapisania zmodyfikowanych danych
- Tak, usuwa cały RAM
- Tak, usuwa page cache i slab
- Tak, zamyka wszystkie procesy
E: Zapis danych i porzucenie czystego cache to różne operacje.
#Q
Q: Co robi zapis 1 do drop_caches?
+ Porzuca czysty page cache
- Zwiększa RAM o 1 GB
- Zabija proces o PID 1
- Wyłącza swap
E: Operacja nie zwalnia dirty objects.
#Q
Q: Co robi zapis 2 do drop_caches?
+ Porzuca odzyskiwalne obiekty slab, np. dentries i inodes
- Usuwa dwie aplikacje
- Przenosi cały heap JVM na dysk
- Wyłącza dwa CPU
E: Odzyskiwalny slab jest osobną kategorią pamięci jądra.
#Q
Q: Co robi zapis 3 do drop_caches?
+ Łączy porzucenie czystego page cache i odzyskiwalnego slab
- Włącza trzy obszary swap
- Usuwa trzy najstarsze pliki
- Szyfruje pamięć
E: To połączenie dwóch rodzajów porzucania cache.
#Q
Q: Dlaczego godzinowy cron drop_caches może spowalniać serwer?
+ Przydatne dane trzeba ponownie odczytać i odtworzyć
- Ponieważ cache nigdy nie jest używane
- Ponieważ zwiększa fizyczny RAM
- Ponieważ zawsze usuwa bazę
E: Jądro zarządza cache samo; ręczne czyszczenie służy głównie kontrolowanym testom.
#Q
Q: Czy drop_caches naprawia wyciek heap aplikacji?
+ Nie, nie jest mechanizmem zwalniania żywych obiektów aplikacji
- Tak, usuwa wszystkie obiekty Java
- Tak, zastępuje GC
- Tak, usuwa wszystkie stacki
E: Trzeba diagnozować pamięć aplikacji, a nie tylko cache systemu.
#Q
Q: Czym jest SReclaimable?
+ Część slab możliwa do odzyskania
- Cały swap
- Rozmiar stosu każdego procesu
- Liczba plików w RAM
E: Obejmuje odzyskiwalne struktury jądra.
#Q
Q: Czym jest SUnreclaim?
+ Część slab niepodlegająca temu odzyskiwaniu
- Nieużywana część swap
- Cały page cache
- Wolne miejsce na dysku
E: Duża wartość wymaga innej interpretacji niż odzyskiwalny cache.
#Q
Q: Co opisuje AnonPages?
+ Strony anonimowe, np. pamięć aplikacji
- Wyłącznie anonimowych użytkowników
- Wyłącznie pliki HTML
- Wyłącznie dane DNS
E: Anonimowa pamięć nie ma zwykłego pliku jako źródła odtworzenia.
#Q
Q: Co opisuje Shmem?
+ Pamięć współdzieloną i zastosowania takie jak tmpfs
- Wyłącznie pamięć SSH
- Wyłącznie cache CPU
- Wyłącznie dyski sieciowe
E: Pole shared w free jest powiązane z Shmem.
#Q
Q: Czy tmpfs zawsze jest przechowywany tylko w fizycznym RAM?
+ Nie, jego strony mogą korzystać ze swap
- Tak, nigdy nie może swapować
- Nie, zawsze zapisuje się do ext4
- Tak, swap nie istnieje dla shmem
E: Pamięć tmpfs jest objęta mechanizmami pamięci wirtualnej.
#Q
Q: Czy total+shared to rozmiar RAM?
+ Nie, shared nie jest dodatkową niezależną pulą poza total
- Tak, należy zawsze je dodać
- Tak, ale tylko przy swap
- Nie, shared to liczba procesów
E: Pola nie tworzą dowolnej sumy niezależnych kategorii.
#Q
Q: Dlaczego kategorie meminfo nie zawsze wolno sumować?
+ Część liczników pokrywa się lub ma inne znaczenie
- Bo liczby są zaszyfrowane
- Bo wszystkie wartości są losowe
- Bo meminfo zawiera wyłącznie procenty
E: Trzeba znać definicję każdego pola.
#Q
Q: Jak interpretować kB w meminfo?
+ Jako jednostki 1024 bajtów, historycznie oznaczone kB
- Zawsze 1000 bitów
- Zawsze 1000 MiB
- Zawsze liczbę stron
E: Do MiB dzielimy te wartości przez 1024.
#Q
Q: Ile bajtów ma MiB?
+ 1048576
- 1000000
- 1024
- 1000
E: MiB to 1024 razy 1024 bajty.
#Q
Q: Co daje free -h?
+ Czytelne jednostki dostosowane do wielkości
- Dokładnie zawsze bajty
- Wyłącznie histogram
- Historię od startu
E: Human-readable jest wygodne dla człowieka, ale mniej stabilne do parsowania.
#Q
Q: Co daje free -w?
+ Oddzielne kolumny buffers i cache
- Automatyczne wyłączenie swap
- Wyzerowanie użycia RAM
- Zapis raportu do systemd
E: Wide rozszerza standardową tabelę.
#Q
Q: Co daje free -s 1 -c 3?
+ Trzy raporty z odstępem jednej sekundy
- Jeden raport co trzy minuty
- Zabicie trzech procesów
- Trzysekundowy restart
E: Interwał i liczba raportów sterują próbkowaniem.
#Q
Q: Czy dokładna definicja used w free jest niezmienna między wersjami procps?
+ Nie, sprawdź wersję i dokumentację narzędzia
- Tak, każda wersja jest identyczna
- Tak, to zawsze sam heap
- Nie, used jest zawsze losowe
E: Nie buduj diagnostyki na założeniu jednego wzoru dla wszystkich wersji.
#Q
Q: Czy used w RAM jest rozmiarem heap JVM?
+ Nie, to metryka systemu, nie jednej JVM
- Tak, jeśli działa Java
- Tak, jeśli PostgreSQL jest wyłączony
- Tak, jeśli load jest niskie
E: System obsługuje procesy, jądro i wiele innych kategorii pamięci.
#Q
Q: Co oznacza zajęty swap?
+ Część pamięci jest przechowywana w obszarze swap
- Zawsze trwa intensywne swapowanie
- Zawsze awaria dysku
- Zawsze brak RAM w tej chwili
E: Zajęte strony mogą pozostać w swap mimo późniejszego wzrostu dostępnego RAM.
#Q
Q: Jak odróżnić zajęty swap od aktywnego swapowania?
+ Sprawdzić si/so w kolejnych próbkach vmstat
- Sprawdzić wyłącznie hostname
- Sprawdzić wyłącznie liczbę kont
- Sprawdzić wyłącznie uptime -s
E: Ruch do i ze swap mówi więcej o bieżącej aktywności.
#Q
Q: Co oznacza si w vmstat?
+ Transfer ze swap do pamięci
- Liczbę sesji interaktywnych
- Procent system idle
- Rozmiar pliku JAR
E: Swap in jest odczytem stron ze swap.
#Q
Q: Co oznacza so w vmstat?
+ Transfer z pamięci do swap
- Liczbę otwartych gniazd
- Liczbę błędów logowania
- Numer gniazda CPU
E: Swap out oznacza zapis stron do swap.
#Q
Q: Czy wyłączenie swap jest neutralną próbą diagnostyczną?
+ Nie, może zwiększyć presję RAM i ryzyko OOM
- Tak, nie zmienia niczego
- Tak, zawsze przyspiesza system
- Tak, odzyskuje fizyczne moduły
E: Nie wyłączamy go automatycznie przy samym wykryciu zajętych stron.
#Q
Q: Czym jest RSS procesu?
+ Pamięć rezydentna procesu w RAM
- Cała zarezerwowana przestrzeń wirtualna
- Wyłącznie Java heap
- Wyłącznie swap procesu
E: RSS może obejmować także strony współdzielone.
#Q
Q: Czym jest VSZ?
+ Rozmiarem przestrzeni wirtualnej procesu
- Zawsze fizycznym użyciem RAM
- Zawsze wolnym swap
- Rozmiarem wszystkich logów
E: Duża rezerwacja wirtualna nie musi oznaczać dużego RSS.
#Q
Q: Dlaczego suma RSS może zawyżać użycie pamięci przez procesy?
+ Współdzielone strony mogą być policzone wiele razy
- Ponieważ każdy RSS jest ujemny
- Ponieważ RSS mierzy wyłącznie dysk
- Ponieważ procesy nie dzielą pamięci
E: PSS rozdziela współdzielone strony proporcjonalnie.
#Q
Q: Czym jest PSS?
+ Proporcjonalnym rozliczeniem stron współdzielonych
- Wyłącznie liczbą wątków
- Maksymalnym rozmiarem swap
- Rozmiarem partycji systemowej
E: PSS pomaga w porównaniu wkładu procesów w użycie RAM.
#Q

- /dev/PID/RAM
- /var/PID/crontab
E: Dostęp zależy od praw i konfiguracji procfs.
#Q
Q: Gdzie można znaleźć VmRSS bieżącej powłoki?

- /dev/$$/status
- /home/$$/status
E: Powłoka rozwija $$ do własnego PID.
#Q
Q: Czy -Xmx ogranicza całe RSS JVM?
+ Nie, poza heap istnieją inne obszary pamięci
- Tak, RSS zawsze równa się Xmx
- Tak, także cache plików hosta
- Tak, także pamięć wszystkich aplikacji
E: Metaspace, stosy, pamięć natywna i bufory mogą zwiększać RSS.
#Q
Q: Czy wysokie VSZ JVM dowodzi wycieku RAM?
+ Nie, trzeba ocenić RSS, heap i trend pamięci
- Tak, każda rezerwacja jest wyciekiem
- Tak, niezależnie od wartości RSS
- Tak, jeśli działa GC
E: Przestrzeń wirtualna może być rezerwowana bez pełnego użycia fizycznej pamięci.
#Q
Q: Który objaw wzmacnia podejrzenie presji RAM?
+ Spadające available wraz z aktywnym swapowaniem i PSI memory
- Duży cache przy wysokim available
- Długi uptime bez innych danych
- Dużo plików na dysku bez innych danych
E: Łączne metryki są bardziej miarodajne niż samo free.
#Q
Q: Co pokazuje memory PSI?
+ Przestoje zadań wynikające z presji pamięci
- Wyłącznie wielkość heap
- Wyłącznie pojemność RAM
- Wyłącznie rozmiar swapfile
E: To miara wpływu presji na postęp zadań.
#Q
Q: Czy wolny RAM hosta gwarantuje brak OOM w kontenerze?
+ Nie, kontener może osiągnąć własny limit cgroup
- Tak, kontener może zawsze użyć całego hosta
- Tak, cgroup nie dotyczy pamięci
- Nie, każdy kontener zawsze ma OOM
E: Zakres pomiaru i limit usługi mają znaczenie.
#Q
Q: Dlaczego procent available nie zastępuje limitów cgroup?
+ Opisuje inny zakres niż budżet konkretnej usługi lub kontenera
- Bo procenty nie są liczbami
- Bo cgroup dotyczy tylko dysku
- Bo available zawsze wynosi 100
E: Trzeba sprawdzić zarówno system, jak i ograniczenia aplikacji.
#Q
Q: Co może oznaczać rosnący RSS procesu przy stałym obciążeniu?
+ Wymaga analizy, np. cache aplikacji lub wycieku
- Zawsze natychmiastowy OOM
- Zawsze uszkodzona pamięć fizyczna
- Zawsze rosnący swap
E: Sam trend jest sygnałem do dalszych pomiarów, nie pełną diagnozą.
#Q
Q: Czy GC JVM zawsze od razu oddaje pamięć systemowi?
+ Nie, zwolnienie obiektów nie gwarantuje spadku RSS
- Tak, każdy GC zeruje RSS
- Tak, GC usuwa cache jądra
- Tak, GC zawsze zmniejsza Xmx
E: Zachowanie zależy od kolektora i konfiguracji sterty.
#Q
Q: Co oznacza Unevictable?
+ Pamięć, której nie można zwyczajnie odzyskać przez wyparcie
- Cały wolny RAM
- Cały page cache
- Wyłącznie wolny swap
E: Obejmuje m.in. strony zablokowane w pamięci.
#Q
Q: Co oznacza Mlocked?
+ Strony zablokowane w RAM przez mechanizmy takie jak mlock
- Nieaktywne konta
- Zablokowane katalogi
- Wszystkie dyski LUKS
E: Nie są zwykłymi kandydatami do swapowania.
#Q
Q: Czy odczyt meminfo wymaga zmiany ustawień jądra?
+ Nie, to pasywny odczyt
- Tak, trzeba wpisać drop_caches=3
- Tak, trzeba wyłączyć swap
- Tak, trzeba uruchomić OOM
E: Diagnoza może zaczynać się od bezpiecznych odczytów.
#Q
Q: Dlaczego nie parsujemy free -h jako stałej liczby bajtów?
+ Jednostki i zaokrąglenia zależą od wielkości
- Bo free -h usuwa liczby
- Bo -h zawsze szyfruje dane
- Bo wynik jest zawsze w sekundach
E: Do obliczeń lepsze są jawne jednostki lub meminfo.
#Q
Q: Czy pojedynczy odczyt free wykrywa przyczynę wycieku?
+ Nie, potrzebne są próbki i metryki procesu
- Tak, od razu wskazuje linię kodu
- Tak, wystarczy pole shared
- Tak, wystarczy pole total
E: Trzeba powiązać trend z zachowaniem aplikacji.
#Q
Q: Dlaczego warto zapisywać znaczniki czasu próbek pamięci?
+ Aby korelować je z ruchem, GC, eksportami i błędami
- Aby zwiększyć RAM
- Aby wyłączyć reclaim
- Aby wyzerować cache
E: Zmiany zasobów często wynikają z określonych zdarzeń.
#Q
Q: Czy duży cache po eksporcie pliku musi zostać ręcznie usunięty?
+ Nie, może pozostać użyteczny i zostać odzyskany przy potrzebie
- Tak, obowiązkowo co minutę
- Tak, inaczej plik zostanie uszkodzony
- Tak, inaczej proces nie zakończy się
E: Jądro zarządza cache bez cyklicznego czyszczenia.
#Q
Q: Czy usunięcie pliku z tmpfs jest tym samym co drop_caches?
+ Nie, usuwa własne dane zamiast tylko porzucać cache
- Tak, obie operacje są identyczne
- Tak, ale tylko dla root
- Nie, tmpfs nigdy nie zawiera plików
E: Nie wolno mylić danych użytkownika z odtwarzalnym cache.

E: Przesunięcie kategorii pamięci nie zastępuje pomiarów zachowania usługi.
