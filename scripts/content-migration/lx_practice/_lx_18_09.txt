#Q
Q: Czym jest repozytorium zewnętrzne APT?
+ Serwerem pakietów prowadzonym przez producenta (lub PPA), dodanym do źródeł APT
- Kopią repozytorium Ubuntu
- Repozytorium z kodem źródłowym
- Folderem z plikami .deb na pulpicie
E: Plik w sources.list.d + klucz GPG.
#Q
Q: Po co APT sprawdza podpisy GPG repozytoriów?
+ Żeby mieć pewność, że indeksy i pakiety pochodzą od właściciela klucza i nie zostały zmienione
- Żeby szyfrować pobieranie
- Żeby przyspieszyć pobieranie
- Żeby liczyć pobrania
E: Pakiety instalowane są jako root.
#Q
Q: Który plik repozytorium jest podpisany kluczem właściciela?
+ InRelease (lub Release z Release.gpg)
- Każdy plik .deb osobno
- Packages
- sources.list
E: Pakiety weryfikuje się przez sumy SHA-256 w podpisanych indeksach.
#Q
Q: Jak APT weryfikuje pojedynczy pakiet .deb z repozytorium?
+ Porównuje jego sumę SHA-256 z wartością w podpisanym indeksie Packages
- Sprawdza podpis GPG każdego pliku .deb
- Nie weryfikuje pakietów
- Pyta użytkownika
E: Łańcuch zaufania: klucz → InRelease → Packages → .deb.
#Q
Q: Gdzie zalecane jest trzymanie kluczy repozytoriów zewnętrznych?
+ W /etc/apt/keyrings/
- W /etc/apt/trusted.gpg
- W /root/.gnupg
- W /usr/bin
E: Plik wskazywany przez Signed-By.
#Q
Q: Co robi gpg --dearmor?
+ Zamienia klucz z formatu tekstowego (ASCII armor) na binarny
- Usuwa klucz
- Szyfruje klucz hasłem
- Weryfikuje klucz
E: APT przyjmuje .gpg (binarny) i .asc (tekstowy).
#Q
Q: Co określa pole Signed-By w pliku .sources?
+ Klucz, którym musi być podpisane to konkretne repozytorium
- Osobę, która dodała repozytorium
- Datę podpisania
- Klucz do wszystkich repozytoriów
E: Klucz nie podpisze niczego z innych repozytoriów.
#Q
Q: Jak w formacie jednoliniowym przypisać klucz do repozytorium?
+ deb [signed-by=/etc/apt/keyrings/nazwa.gpg] URI wydanie sekcje
- deb URI wydanie sekcje key=nazwa.gpg
- deb-key nazwa.gpg URI
- signed deb URI
E: Opcja w nawiasach kwadratowych.
#Q
Q: Dlaczego apt-key jest przestarzały?
+ Dodawał klucze do globalnego zaufania — każdy klucz mógł podpisać pakiety udające systemowe
- Bo był zbyt wolny
- Bo nie obsługiwał RSA
- Bo wymagał internetu
E: Zastąpiony przez keyrings + Signed-By.
#Q
Q: Co wypisze apt-key list w Ubuntu 24.04?
+ Ostrzeżenie: apt-key is deprecated
- Błąd: command not found zawsze
- Listę pakietów
- Nic
E: W nowszych APT polecenie usunięto.
#Q
Q: Co oznacza błąd NO_PUBKEY 4A3F5C1D2B6E8F90?
+ APT nie ma klucza publicznego, którym podpisano repozytorium
- Repozytorium nie istnieje
- Brak internetu
- Klucz wygasł na pewno
E: Repozytorium zostaje zignorowane.
#Q
Q: Jak poprawnie rozwiązać NO_PUBKEY?
+ Pobrać właściwy klucz od producenta do /etc/apt/keyrings i wskazać go w Signed-By
- Dodać [trusted=yes]
- Użyć --allow-unauthenticated
- Usunąć wszystkie klucze
E: Nie wyłączaj weryfikacji.
#Q
Q: Co robi opcja [trusted=yes]?
+ Wyłącza sprawdzanie podpisów dla repozytorium
- Dodaje klucz do zaufanych
- Szyfruje połączenie
- Przyspiesza pobieranie
E: Tylko dla lokalnych repozytoriów testowych.
#Q
Q: Kiedy [trusted=yes] jest dopuszczalne?
+ Dla lokalnego repozytorium testowego (file:/)
- Dla każdego repozytorium producenta
- Dla repozytoriów HTTP
- Zawsze, gdy apt update zgłasza błąd
E: Nigdy z sieci.
#Q
Q: Czym grozi [trusted=yes] dla repozytorium w sieci?
+ Ktoś w sieci lub po przejęciu domeny może podsunąć złośliwy pakiet wykonywany jako root
- Wolniejszym działaniem
- Brakiem aktualizacji
- Niczym
E: postinst działa jako root.
#Q
Q: Czym jest PPA?
+ Personal Package Archive — repozytorium na Launchpadzie dla Ubuntu
- Pakietem Pythona
- Publicznym repozytorium Debiana
- Programem do pakowania
E: ppa:wlasciciel/nazwa.
#Q
Q: Jak dodać PPA w Ubuntu?
+ sudo add-apt-repository ppa:wlasciciel/nazwa
- sudo apt install ppa:nazwa
- sudo dpkg -i ppa
- sudo apt-key add ppa
E: Pobiera klucz i tworzy plik źródeł.
#Q
Q: Jak usunąć PPA?
+ sudo add-apt-repository --remove ppa:wlasciciel/nazwa (lub usunąć plik) i apt update
- sudo apt remove ppa
- sudo dpkg -r ppa
- sudo apt clean
E: Pakiety z PPA zostają zainstalowane.
#Q
Q: Gdzie add-apt-repository w Ubuntu 24.04 umieszcza klucz PPA?
+ Bezpośrednio w polu Signed-By pliku .sources (blok PGP)
- W /etc/apt/trusted.gpg
- W /root/ppa.key
- W /var/lib/apt/lists
E: Plik git-core-ubuntu-ppa-noble.sources.
#Q
Q: Co dzieje się z pakietami zainstalowanymi z repozytorium po usunięciu tego repozytorium?
+ Zostają zainstalowane, ale nie dostają już aktualizacji z tego źródła
- Są usuwane automatycznie
- Przestają działać
- Wracają do wersji z Ubuntu
E: Ewentualny downgrade trzeba zrobić świadomie.
#Q
Q: Co trzeba usunąć, by całkowicie wycofać repozytorium producenta?
+ Plik z sources.list.d i klucz z keyrings, potem apt update
- Tylko klucz
- Tylko pakiety
- /var/lib/apt/lists
E: Zostaw system bez zbędnych zaufanych kluczy.
#Q
Q: Czym jest odcisk (fingerprint) klucza?
+ 40-znakowym skrótem szesnastkowym jednoznacznie identyfikującym klucz
- Hasłem do klucza
- Datą utworzenia klucza
- Adresem e-mail właściciela
E: Porównaj z wartością na stronie producenta.
#Q
Q: Jak wyświetlić informacje o kluczu z pliku bez importowania go?
+ gpg --show-keys plik
- gpg --import plik
- apt-key show plik
- cat plik
E: Pokazuje typ, datę, odcisk i identyfikator.
#Q
Q: Po co porównywać odcisk klucza z opublikowanym przez producenta?
+ Żeby wykryć podmieniony klucz (np. z fałszywej strony)
- Żeby przyspieszyć apt update
- Żeby klucz nie wygasł
- Nie ma potrzeby
E: Pobranie przez HTTPS to nie wszystko.
#Q
Q: Jaki kod uruchamia właściciel repozytorium na Twoim serwerze?
+ Dowolny kod jako root — przez skrypty pakietów przy instalacji i aktualizacji
- Żadnego
- Tylko w katalogu /opt
- Tylko jako zwykły użytkownik
E: Zaufanie do repozytorium to zaufanie do roota.
#Q
Q: Co gwarantuje podpis GPG pakietu?
+ Że pakiet pochodzi od właściciela klucza i nie został zmieniony — nie że właściciel jest uczciwy
- Że pakiet nie ma błędów
- Że pakiet jest bezpieczny
- Że pakiet jest darmowy
E: Wybieraj zaufanych producentów.
