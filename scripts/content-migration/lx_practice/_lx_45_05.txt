#Q
Q: Co dzieje się z danymi w warstwie zapisu kontenera po docker rm?
+ Są usuwane razem z kontenerem
- Trafiają do wolumenu
- Trafiają do obrazu
- Zostają w /tmp gospodarza
E: Trwałe dane muszą być poza kontenerem.
#Q
Q: Jakie trzy mechanizmy montowania danych oferuje Docker?
+ Wolumeny nazwane, bind mount i tmpfs
- NFS, SMB i FTP
- overlay, ext4 i xfs
- Tylko wolumeny
E: Każdy ma inne zastosowanie.
#Q
Q: Jak utworzyć wolumen nazwany pgdata?
+ docker volume create pgdata
- docker create volume pgdata
- mkdir /var/lib/docker/pgdata
- docker run --volume-create pgdata
E: Wolumen powstaje też automatycznie przy -v pgdata:/ścieżka.
#Q
Q: Gdzie na gospodarzu z Docker Engine leżą dane wolumenu pgdata?
+ /var/lib/docker/volumes/pgdata/_data
- /var/lib/pgdata
- /home/anna/pgdata
- /etc/docker/volumes
E: docker volume inspect pokazuje Mountpoint.
#Q
Q: Gdzie leżą dane wolumenów w Docker Desktop na Windows?
+ W dysku docker_data.vhdx maszyny WSL2
- W C:\Users\anna\Docker
- W ~/projekty
- W rejestrze
E: Dostęp z Windows bezpośrednio do nich nie jest przewidziany.
#Q
Q: Czym jest bind mount?
+ Zamontowaniem konkretnego katalogu lub pliku gospodarza w kontenerze
- Wolumenem zarządzanym przez Dockera
- Systemem plików w pamięci
- Warstwą obrazu
E: Np. -v "$PWD":/app.
#Q
Q: Czym jest tmpfs w kontenerze?
+ Systemem plików w pamięci RAM — dane znikają po zatrzymaniu kontenera
- Katalogiem /tmp gospodarza
- Wolumenem nazwanym
- Warstwą zapisu
E: Np. --tmpfs /tmp:size=64m.
#Q
Q: Co oznacza :ro przy montowaniu?
+ Tylko do odczytu
- Root only
- Remove on exit
- Read once
E: Kontener nie może zmienić zawartości.
#Q
Q: Jak zapisać montowanie tylko do odczytu w składni --mount?
+ --mount type=bind,src=...,dst=...,readonly
- --mount ro=true
- --mount type=ro
- --mount readonly src
E: --mount jest bardziej czytelna niż -v.
#Q
Q: Czym jest wolumen anonimowy?
+ Wolumenem z losową nazwą, tworzonym m.in. dla katalogów z instrukcją VOLUME w obrazie
- Wolumenem bez danych
- Wolumenem tylko do odczytu
- Wolumenem sieciowym
E: Łatwo go zgubić po odtworzeniu kontenera.
#Q
Q: Które obrazy z lekcji mają instrukcję VOLUME?
+ postgres (katalog /var/lib/postgresql/data)
- nginx (katalog /etc/nginx)
- alpine (katalog /)
- busybox (katalog /bin)
E: docker image inspect -f '{{json .Config.Volumes}}' to pokaże.
#Q
Q: Co stanie się z danymi bazy po odtworzeniu kontenera postgres bez wolumenu nazwanego?
+ Nowy kontener dostanie nowy, pusty wolumen anonimowy — dane zostaną w osieroconym wolumenie
- Dane zostaną automatycznie podłączone
- Dane zostaną skopiowane do obrazu
- Kontener się nie uruchomi
E: W lekcji tabela produkty „zniknęła”.
#Q
Q: Jak wypisać wolumeny niepodłączone do żadnego kontenera?
+ docker volume ls -f dangling=true
- docker volume ls --orphan
- docker volume prune --dry-run
- docker ps -v
E: Przed usunięciem warto sprawdzić ich zawartość.
#Q
Q: Jak przenieść dane z osieroconego wolumenu do nazwanego?
+ Kontenerem pomocniczym z oboma wolumenami: cp -a /z/. /do/
- docker volume rename
- docker volume move
- mv w /var/lib/docker bez zatrzymania
E: Opcja -a zachowuje prawa i właścicieli.
#Q
Q: Co robi docker rm -v?
