#Q
Q: Co robi bit SUID na pliku wykonywalnym?
+ Program działa z uprawnieniami właściciela pliku, nie uruchamiającego
- Program działa z uprawnieniami uruchamiającego
- Plik staje się tylko do odczytu
- Plik dziedziczy grupę katalogu
E: Np. passwd należy do roota i działa jako root.
#Q
Q: Dlaczego zwykły użytkownik może zmienić swoje hasło, choć /etc/shadow należy do roota?
+ Program passwd ma bit SUID roota i działa z jego uprawnieniami
- /etc/shadow ma prawa 666
- passwd zapisuje do innego pliku
- Każdy ma prawo zapisu do shadow
E: SUID pozwala na kontrolowane podniesienie uprawnień.

E: Np. 2775.

- 2

- 3
E: Np. 1777.

Q: Co oznacza litera s w miejscu x właściciela (-rwsr-xr-x)?
+ Bit SUID przy ustawionym prawie wykonania
- Gniazdo
- Bit SGID
- Sticky bit
E: Mała litera — bit plus x.

#Q
Q: Co oznacza litera t na końcu praw katalogu (drwxrwxrwt)?

- SUID
- SGID
- Katalog tymczasowy
E: Jak /tmp.
#Q
Q: Co oznacza wielkie S w prawach (-rwSr--r--)?

- Sticky bit
- Gniazdo
E: Bit ustawiony, ale brak x pod spodem.

+ Sticky bit bez prawa x dla innych
- SGID
- Sticky bit działający normalnie
- Katalog tylko do odczytu
E: Litera duża, gdy pod spodem nie ma x.
#Q
Q: Co robi SGID na katalogu?
+ Nowe pliki i podkatalogi dziedziczą grupę katalogu (a podkatalogi też bit SGID)
- Pliki działają z grupą właściciela
- Blokuje usuwanie cudzych plików
- Nic
E: Podstawa katalogów zespołowych.
#Q
Q: Co robi sticky bit na katalogu?
+ Plik może usunąć lub przemianować tylko jego właściciel, właściciel katalogu lub root
- Blokuje tworzenie plików
- Nadaje grupę katalogu
- Czyni katalog tymczasowym
E: Nawet gdy inni mają w do katalogu.

+ Operation not permitted
- Permission denied
- No such file
- Read-only

- Bo skrypty nie mają właściciela

+ install -d -o root -g programisci -m 3775 katalog (SGID + sticky)
- chmod 777 katalog
- chmod 755 katalog
- chmod u+s katalog
E: 3775 = SGID + sticky + 775.

- chmod g+s tylko na katalogu głównym
- Nic — dziedziczą automatycznie
E: SGID dziedziczą tylko nowe podkatalogi.
