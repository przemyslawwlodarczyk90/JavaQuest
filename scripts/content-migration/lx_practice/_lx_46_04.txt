+ Zdarzenia zabicia procesu przez OOM killer (0 = brak problemów)
- Logi aplikacji
- Połączenia bazy
- Status usługi
E: Po poprawnej konfiguracji powinno być 0.
#Q
Q: Jak symulować stertę JVM przy limicie 2 GB bez uruchamiania aplikacji?
+ systemd-run --scope -p MemoryMax=2G java -XX:+PrintFlagsFinal -version | grep MaxHeapSize
- java -Xmx2g
- free -h
- top
E: Scope nadaje procesowi limit cgroup.
#Q
Q: Co pokazuje pg_stat_activity?
+ Aktywne połączenia i zapytania do bazy
- Konfigurację
- Rozmiar bazy
- Logi
E: Pozwala policzyć bieżące połączenia.
#Q
Q: Dlaczego aplikacja łączy się z bazą przez 127.0.0.1, a nie localhost w URL?
+ Jednoznaczny adres IPv4 unika niejednoznaczności localhost (IPv4/IPv6)
- Bo localhost nie działa
- Bo jest szybsze
- Bez różnicy w praktyce — oba są akceptowane, projekt wybiera 127.0.0.1
E: Oba wskazują lokalny serwer; projekt stosuje jawny adres.
#Q
Q: Co jest dowodem gotowości środowiska uruchomieniowego (etap 4)?
+ Działa Java, baza nasłuchuje lokalnie, rola sklep się łączy, parametry pamięci zastosowane
- Zainstalowany Nginx
- Certyfikat TLS
- Działający monitoring
E: Weryfikacja przed uruchomieniem usługi.
#Q
Q: Gdzie zapisuje się konfiguracje bazy dla odtwarzalności?
+ W repozytorium infrastruktury (conf.d, wpis pg_hba — bez haseł)
- W katalogu domowym postgres
- W /tmp
- Nigdzie
E: Hasła pozostają w katalogu sekretów serwera.
#Q
Q: Co to jest maintenance_work_mem?
+ Pamięć na operacje konserwacyjne (VACUUM, tworzenie indeksów)
- Pamięć na połączenia
- Rozmiar sterty JVM
- Limit połączeń
E: Ustawiono 128MB.
#Q
Q: Dlaczego work_mem ustawia się ostrożnie (8MB), a nie bardzo wysoko?
+ Jest przydzielany na operację sortowania/haszowania na połączenie — przy wielu połączeniach sumuje się
- Bo baza go ignoruje
- Bo większe wartości nie działają
- Bez powodu
E: 50 połączeń x duży work_mem = dużo pamięci.
#Q
Q: Co daje osobna rola sklep zamiast konta postgres dla aplikacji?
+ Ograniczenie uprawnień — aplikacja ma dostęp tylko do swojej bazy
- Szybsze zapytania
- Mniej pamięci
- Nic
E: postgres to superużytkownik.
#Q
Q: Jakie polecenie sprawdza aktywność usługi bazy?
+ systemctl is-active postgresql@16-main
- pg_isready --service
- docker ps
- ps aux | grep sql
E: Zwraca active lub inactive.
#Q
Q: Co jest warunkiem przejścia do lekcji 5 (usługa systemd)?
+ Działające JRE i baza z rolą sklep oraz hasło w pliku sekretu
- Działający Nginx
- Certyfikat TLS
- Monitoring
E: Usługa korzysta z tych elementów.
#Q
Q: Jak PostgreSQL korzysta z pamięci podręcznej plików systemu?
+ Dane spoza shared_buffers czyta z pamięci podręcznej jądra — dlatego zostawia się na nią miejsce
- Nie korzysta
- Tylko przez swap
- Tylko shared_buffers
E: effective_cache_size informuje o jej rozmiarze.
#Q
Q: Dlaczego instaluje się tylko to, co potrzebne do uruchomienia?
+ Mniejsza powierzchnia ataku i mniej do aktualizowania
- Szybszy procesor
- Więcej pamięci
- Wymóg Javy
E: Zasada minimalnej instalacji.
#Q
Q: Co robi umask 077 przed utworzeniem pliku sekretu?
+ Powoduje, że nowy plik ma prawa tylko dla właściciela (600)
- Usuwa plik
- Ustawia roota
- Szyfruje plik
E: Zapobiega odczytowi przez innych.
#Q
Q: Jak sprawdzić, że hasła nie ma w argumentach procesów?
+ Przekazywać je zmienną/plikiem — wtedy ps go nie pokaże
- grep ps | password
- cat /proc/haslo
- Nie da się
E: Argumenty w ps są widoczne dla innych użytkowników.
#Q
Q: Co jest celem całego etapu 4?
+ Przygotować środowisko uruchomieniowe: Javę i bazę z rozsądnym budżetem pamięci
- Zabezpieczyć SSH
- Skonfigurować TLS
- Napisać skrypt wdrożeniowy
E: Fundament pod usługę aplikacji.
#Q
Q: Jaki jest skutek ExitOnOutOfMemoryError w połączeniu z Restart w usłudze systemd?
+ Po błędzie pamięci JVM kończy się, a systemd restartuje usługę w czystym stanie
- JVM ignoruje błąd
- Serwer się wyłącza
- Baza jest usuwana
E: Lepsze niż działanie w niestabilnym stanie.
#Q
Q: Dlaczego update-alternatives --display java jest przydatne?
+ Pokazuje, która wersja Javy jest domyślna i jakie są alternatywy
- Instaluje Javę
- Usuwa Javę
- Zmienia port
E: Pełna ścieżka w jednostce uniezależnia od tej zmiany.
#Q
Q: Co jest ryzykiem używania konta postgres w aplikacji?
+ To superużytkownik — błąd lub włamanie daje pełną kontrolę nad bazą
- Jest wolniejsze
- Wymaga hasła
- Nie obsługuje SSL
E: Aplikacja powinna mieć minimalne uprawnienia.
#Q
Q: Jak przekazać wiele poleceń SQL do psql bezpiecznie z hasłem?
+ Heredoc z psql -v haslo=... i :'haslo' w CREATE ROLE
- Wpisać hasło w każdej linii
- Zapisać hasło w pliku SQL
- Użyć echo
E: Zmienna nie trafia do treści ani historii.
#Q
Q: Co jest zaletą ustawienia budżetu pamięci przed obciążeniem?
+ Unika się OOM przy pierwszym imporcie/raporcie w produkcji
- Szybszy start
- Mniej logów
- Brak kopii
E: Problem ujawnia się dopiero pod obciążeniem.
#Q
Q: Jakie polecenie instaluje JRE headless i PostgreSQL naraz?
+ apt-get install openjdk-21-jre-headless postgresql
- apt install java postgres
- snap install jre postgresql
- yum install
E: Oba z repozytorium dystrybucji.
