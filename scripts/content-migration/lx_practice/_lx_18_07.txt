#Q
Q: Co robi sudo apt remove pakiet?
+ Usuwa pliki programu, ale zostawia jego pliki konfiguracyjne
- Usuwa program i całą konfigurację
- Usuwa tylko konfigurację
- Usuwa nieużywane zależności
E: Stan w dpkg: rc.
#Q
Q: Co robi sudo apt purge pakiet?
+ Usuwa program razem z plikami konfiguracyjnymi z /etc
- Usuwa tylko pobrane pliki .deb
- Usuwa dane użytkowników z /home
- Usuwa zależności
E: Równoważne apt remove --purge.
#Q
Q: Co robi sudo apt autoremove?
+ Usuwa pakiety automatyczne, od których nic już nie zależy
- Usuwa wszystkie pakiety
- Usuwa pobrane pliki .deb
- Automatycznie usuwa stare konfiguracje
E: Zawsze czytaj listę.
#Q
Q: Co oznacza stan rc w dpkg -l?
+ Pakiet usunięty, konfiguracja pozostała
- Pakiet do ponownej konfiguracji
- Pakiet zainstalowany poprawnie
- Pakiet uszkodzony
E: removed, config-files.
#Q
Q: Co wypisze dpkg -s dla pakietu w stanie rc w polu Status?
+ Status: deinstall ok config-files
- Status: install ok installed
- Status: purged
- Status: removed ok
E: Żądanie deinstall, stan config-files.
#Q
Q: Co się stanie z konfiguracją po ponownej instalacji pakietu usuniętego przez remove?
+ Zostanie odnaleziona i użyta dawna, zmieniona konfiguracja
- Zostanie nadpisana domyślną
- Zostanie usunięta
- Pakiet się nie zainstaluje
E: Przykład /etc/screenrc.
#Q
Q: Jak usunąć konfigurację wszystkich pakietów w stanie rc?
+ sudo apt purge $(dpkg -l | awk '/^rc/ {print $2}')
- sudo apt clean
- sudo apt autoremove
- sudo rm -rf /etc/*
E: Podstawienie listy nazw.
#Q
Q: Czego NIE usuwa purge?
+ Danych w katalogach domowych i zwykle danych usług w /var/lib
- Plików konfiguracyjnych w /etc
- Plików binarnych programu
- Wpisu w bazie dpkg
E: Np. bazy PostgreSQL.
#Q
Q: Czym są conffiles?
+ Plikami konfiguracyjnymi pakietu, które dpkg chroni przy aktualizacji i zostawia po remove
- Plikami tymczasowymi
- Plikami binarnymi
- Kopiami zapasowymi
E: Lista w polu Conffiles w dpkg -s.
#Q
Q: Co oznacza linia Purg w symulacji apt-get -s purge?
+ Pakiet zostałby usunięty razem z konfiguracją
- Pakiet zostałby oczyszczony z błędów
- Pakiet zostałby pobrany
- Pakiet zostałby zaktualizowany
E: Remv — zwykłe usunięcie.
#Q
Q: Kiedy wybrać remove zamiast purge?
+ Gdy konfiguracja może się jeszcze przydać (np. planujesz ponowną instalację)
- Zawsze
- Gdy brakuje miejsca
- Gdy pakiet jest uszkodzony
E: purge — koniec z programem.
#Q
Q: Co trzeba zrobić przed purge zmienionej konfiguracji?
+ Kopię plików z /etc, jeśli mogą się przydać
- Nic
- Restart systemu
- apt clean
E: purge usuwa je bez kopii.
#Q
Q: Które pakiety usuwa autoremove?
+ Automatyczne (zainstalowane jako zależności), których nic już nie wymaga
- Wszystkie ręczne
- Wszystkie przestarzałe
- Wszystkie z sekcji universe
E: Np. zależności usuniętego mc.
#Q
Q: Co robi apt autoremove --purge?
+ Usuwa nieużywane zależności razem z ich konfiguracją
- Usuwa tylko konfigurację
- Czyści pamięć podręczną
- Usuwa jądro
E: Bez pozostałości rc.
#Q
Q: Jak ochronić pakiet przed usunięciem przez autoremove?
+ sudo apt-mark manual pakiet
- sudo apt-mark hold pakiet
- sudo apt-mark auto pakiet
- sudo dpkg --protect pakiet
E: hold blokuje aktualizacje, nie autoremove.
#Q
Q: Co robi sudo apt-mark auto pakiet?
+ Oznacza pakiet jako automatyczny — autoremove usunie go, gdy nic go nie wymaga
- Włącza automatyczne aktualizacje
- Blokuje pakiet
- Instaluje pakiet automatycznie
E: Odwrotność apt-mark manual.
#Q
Q: Dlaczego po oznaczeniu apache2-utils jako auto autoremove chciał usunąć też libapr1t64?
+ Biblioteki były potrzebne tylko apache2-utils, który sam stał się zbędny
- Bo libapr1t64 była uszkodzona
- Bo autoremove usuwa wszystkie biblioteki
- Przez błąd APT
E: Łańcuch zależności automatycznych.
#Q
Q: Co jeszcze usuwa apt remove pakiet poza samym pakietem?
+ Wszystkie pakiety, które od niego zależą
- Wszystkie jego zależności
- Pliki w /home
- Nic więcej
E: Lista REMOVED przed potwierdzeniem.
#Q
Q: Co należy zrobić, gdy lista REMOVED zawiera openssh-server lub ubuntu-minimal?
+ Przerwać operację

- Dodać -y
- Uruchomić apt clean
E: To pakiety krytyczne dla systemu.
#Q
Q: Dlaczego sudo apt remove python3 jest groźne w Ubuntu?

- Bo usuwa jądro
- Bo usuwa sudo

- -y spowalnia operację
- -y usuwa konfigurację
- -y działa tylko z purge
E: Najpierw symulacja.
#Q
Q: Jak zainstalować nowszego Pythona dla projektu bez ruszania systemowego?

#Q
Q: Co oznacza flaga Essential: yes pakietu?
+ Pakiet jest niezbędny do działania systemu — APT wymaga specjalnego potwierdzenia przy usuwaniu
- Pakiet jest płatny
- Pakiet ma wysoki priorytet aktualizacji
- Pakiet jest zalecany
E: Np. coreutils, bash.
#Q
Q: Jakiego potwierdzenia wymaga APT przy usuwaniu pakietu Essential?
+ Wpisania pełnego zdania „Yes, do as I say!”
- Zwykłego Y
- Hasła roota
- Restartu
E: Celowo trudne do przypadkowego wpisania.
#Q
Q: Jaki priorytet mają pakiety niezbędne, jak coreutils?
+ required
- optional
- extra
- standard
E: Hierarchia: required, important, standard, optional.
#Q
Q: Co robi sudo apt clean?
+ Usuwa wszystkie pobrane pliki .deb z /var/cache/apt/archives
- Usuwa nieużywane pakiety
- Usuwa konfiguracje
- Usuwa listy pakietów i blokuje apt

#Q
Q: Co robi sudo apt autoclean?
+ Usuwa tylko te pliki .deb, których nie da się już pobrać z repozytoriów
- Usuwa wszystkie pliki .deb
- Usuwa nieużywane zależności
- Czyści pliki rc
E: Np. stare wersje po aktualizacji.

- /tmp
- /usr/share/apt

- Tak, ale tylko automatyczne
- Tylko gry
E: Zainstalowane pakiety nie są dotykane.
#Q
Q: Co pokazuje apt-get -s clean?

- Stare jądra
- Pliki konfiguracyjne
E: Symulacja czyszczenia.
#Q

- Bo jądra są zbędne
- Bo zajmują RAM
- Nie usuwa

- Żadne
