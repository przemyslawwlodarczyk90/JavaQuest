# Kontrola bezpieczenstwa na plikach modelowych; kod 1 = sa uwagi

ok=0; uwagi=0
spr() { if "$2" > /dev/null 2>&1; then echo "OK     $1"; ok=$((ok+1)); else echo "UWAGA  $1"; uwagi=$((uwagi+1)); fi; }

k_puste()   { [ -z "$(awk -F: '$2==""' "$m/shadow")" ]; }

k_ssh()     { grep -qx 'passwordauthentication no' "$m/sshd-T" && grep -qx 'permitrootlogin no' "$m/sshd-T"; }
k_aa()      { grep -q '^0 profiles are in complain mode' "$m/aa-status"; }
k_porty()   { diff -q <(sort -u "$m/porty-oczekiwane") <(sort -u "$m/porty-teraz"); }
spr "brak wymaganego restartu" k_restart
spr "brak pustych hasel" k_puste
spr "UID 0 tylko root" k_uid0
spr "SSH bez hasel i bez roota" k_ssh
spr "AppArmor bez profili w complain" k_aa
spr "porty zgodne z lista" k_porty
echo "--- OK: $ok, UWAGA: $uwagi"
[ "$uwagi" -eq 0 ]
EOF
chmod 700 "$chk_lab/kontrola.sh"

+ Zapis do tego samego pliku, z którego się czyta, mógłby go wyczyścić
- Bo mv jest szybsze niż cp
- Bo grep nie może pisać do plików
- Bo pliki modelowe są niezmienne
E: Przekierowanie > na czytany plik obcina go przed odczytem.
#Q
Q: Jakie obszary obejmuje lista kontrolna serwera z lekcji?
+ System i aktualizacje, konta, SSH, sieć, usługi, MAC, aplikację, bazy, WWW, logi, integralność i kopie
- Tylko zaporę i SSH
- Tylko aktualizacje
- Tylko kopie zapasowe
E: Każdy obszar odpowiada warstwie omówionej w osobnych rozdziałach kursu.
#Q
Q: Co jest oczekiwanym stanem usługi unattended-upgrades na serwerze z listy?
+ active
- masked
- inactive
- failed
E: Poprawki bezpieczeństwa powinny być instalowane automatycznie.
#Q
Q: Jakie polecenie z listy pomaga ustalić, które procesy wymagają restartu po aktualizacji bibliotek?
+ needrestart
- uptime
- lsmod
- free
E: needrestart wskazuje usługi używające starych wersji bibliotek.
#Q
Q: Jaki wynik `sshd -T` oznacza, że root nie może logować się bezpośrednio?
+ permitrootlogin no
- permitrootlogin prohibit-password
- permitrootlogin yes
- permitemptypasswords no
E: prohibit-password nadal pozwala rootowi logować się kluczem.
#Q
Q: Dlaczego `permitrootlogin prohibit-password` nie spełnia punktu „bez roota” z listy?
+ Pozwala na logowanie roota kluczem, a lista wymaga logowania przez konta osobiste i sudo
- Bo blokuje wszystkich użytkowników
- Bo wyłącza klucze
- Bo jest błędem składni
E: Logowanie przez konta osobiste zapewnia rozliczalność.
#Q
Q: Co oznacza linia `allowgroups ssh-users` w wyniku `sshd -T`?
+ Logować się przez SSH mogą tylko członkowie grupy ssh-users
- Grupa ssh-users ma sudo
- Grupa ssh-users jest zablokowana
- Grupa ssh-users może przekazywać porty
E: AllowGroups ogranicza krąg kont z dostępem zdalnym.
#Q
Q: Co jest oczekiwaną reakcją na profil AppArmor zostawiony w complain po diagnozie?
+ Przywrócić go do enforce po dodaniu brakujących reguł
- Wyłączyć AppArmor
- Usunąć profil
- Zostawić bez zmian
E: Complain nie chroni programu.
#Q
Q: Dlaczego punkt „kopie” obejmuje także off-site?
+ Kopia w tej samej lokalizacji może zginąć razem z serwerem (pożar, ransomware)
- Bo off-site jest szybsze
- Bo lokalne kopie są zabronione
- Bo Lynis tego wymaga
E: Zasada 3-2-1 z rozdziału 34.
#Q
Q: Jakie polecenie z listy pokazuje timery kopii zapasowych?
+ systemctl list-timers 'kopia*'
- crontab -l -u root
- ls /etc/cron.daily
- atq
E: Brak timera kopii to w modelu „po roku” sygnał krytyczny.
#Q
Q: Dlaczego wyniki przeglądów warto przechowywać jako dowody?
+ Audyty i zgodność (CIS, ISO 27001, PCI DSS) wymagają potwierdzenia kontroli
- Bo Lynis je kasuje
- Bo systemd ich wymaga
- Bo zastępują kopie zapasowe
E: Historia przeglądów pokazuje ciągłość procesu.
#Q
Q: Jakie punkty listy kontrolnej warto sprawdzić po incydencie w pierwszej kolejności?
+ Konta, klucze SSH, sudoers, nasłuchujące porty i zmienione pliki
- Motyw powłoki
- Wersję edytora
- Rozmiar /usr/share/doc
E: To typowe miejsca, w których intruz utrwala dostęp.
#Q
Q: Co należy zrobić z wyjątkiem, którego termin przeglądu minął?
+ Ponownie ocenić uzasadnienie i albo przedłużyć z nową datą, albo usunąć odstępstwo
- Nic, wyjątki są bezterminowe
- Usunąć z pliku bez oceny
- Ukryć w raporcie
E: Wyjątki bez przeglądu stają się trwałym dryfem.
#Q
Q: Port 8000 otwarty „dla dostawcy” z przeglądem 2026-06 nadal jest na liście w październiku. Co to sugeruje?
+ Tymczasowa zmiana została na stałe i trzeba ją pilnie ocenić
- Wszystko jest w porządku
- Dostawca nadal na pewno go potrzebuje
- Lynis to naprawi
E: To klasyczny przykład dryfu konfiguracji.
#Q
Q: Czym jest Ubuntu Security Guide (usg)?
+ Narzędziem Ubuntu Pro do audytu i utwardzania zgodnie z profilami CIS i DISA STIG
- Nakładką graficzną na ufw
- Częścią Lynis
- Menedżerem haseł
E: Pozwala stosować i sprawdzać profile norm w Ubuntu.
#Q
Q: Jaki element skryptu kontrolnego decyduje o kodzie wyjścia?
+ Ostatnia linia [ "$uwagi" -eq 0 ]
- Pierwsza linia shebang
- Funkcja spr
- Polecenie echo z podsumowaniem
E: Kod ostatniego polecenia staje się kodem całego skryptu.
#Q
Q: Dlaczego w ćwiczeniu podsumowanie skryptu ma stały format `--- OK: N, UWAGA: M`?
+ Ułatwia automatyczne wycięcie liczby uwag do historii i alertów
- Bo journald wymaga takiego formatu
- Bo Lynis go odczytuje
- Bo inaczej skrypt się nie uruchomi
E: Stabilny format wyjścia to dobra praktyka skryptów monitorujących.
#Q
Q: Jaki sens ma `bash -n` po zapisaniu skryptu kontrolnego?
+ Sprawdza składnię bez wykonywania skryptu
- Uruchamia skrypt bez sudo
- Wyłącza kolory
- Zapisuje skrypt w historii
E: Błąd składni wykryty od razu nie zepsuje nocnej kontroli.
#Q
Q: Czym jest wskaźnik „Hardening index” w Lynis?
+ Liczbą 0–100 podsumowującą wynik testów utwardzenia
- Liczbą otwartych portów
- Wersją Lynis
- Liczbą ostrzeżeń
E: To ogólna miara; ważniejsze są poszczególne uwagi i ich ocena.
#Q
Q: Lynis w wersji z repozytorium dystrybucji bywa starsza. Skąd pobrać nowszą?
+ Ze strony projektu (CISOfy) lub ich repozytorium pakietów
- Z dowolnego mirrora bez weryfikacji
- Ze snapa nieoficjalnego bez podpisu
- Z forum dyskusyjnego
E: Pobierając spoza dystrybucji, weryfikuj sumy i podpisy (lekcja 8).
#Q
Q: Gdzie zapisuje się szczegółowy log działania Lynis?
+ /var/log/lynis.log
- /var/log/lynis-report.dat
- /etc/lynis/lynis.log
- /tmp/lynis.log
E: Raport .dat służy do przetwarzania, log do szczegółów testów.
#Q
Q: Jakie ryzyko niesie automatyczne wdrażanie wszystkich sugestii Lynis?
+ Może zablokować potrzebne funkcje (tunele, zdalne zarządzanie) i spowodować przestoje
- Żadne
- Wyłączy Lynis
- Usunie logi
E: Sugestie oceniamy w kontekście roli serwera.
#Q
Q: Która warstwa listy kontrolnej chroni przed skutkami ransomware najbardziej bezpośrednio?
+ Kopie zapasowe off-site z historią i próbą odtworzenia
- Wskaźnik Lynis
- Nagłówki HTTP
- Hasło GRUB
E: Bez odtwarzalnej kopii zaszyfrowanych danych nie da się odzyskać.
#Q
Q: Dlaczego warto porównywać listę osób z dostępem (klucze, sudo) z aktualnym składem zespołu?
+ Konta i klucze osób, które odeszły, to częsta, przeoczona droga dostępu
- Bo klucze wygasają co tydzień
- Bo sudo wymaga tego co dzień
- Bo Lynis tego nie sprawdzi nigdy
E: To punkt przeglądu ręcznego, którego skrypt nie oceni.
