#Q
Q: Co robi sudo apt update?
+ Pobiera aktualne listy (indeksy) pakietów z repozytoriów — niczego nie instaluje
- Instaluje nowsze wersje wszystkich pakietów
- Aktualizuje system do nowego wydania
- Aktualizuje samo polecenie apt
E: Notatki kursu: apt update NIE aktualizuje systemu.
#Q
Q: Co robi sudo apt upgrade?
+ Instaluje nowsze wersje zainstalowanych pakietów według ostatnio pobranych list
- Pobiera tylko listy pakietów
- Usuwa przestarzałe pakiety
- Aktualizuje dystrybucję do nowego wydania
E: Bez wcześniejszego update użyje starych list.
#Q
Q: Gdzie apt update zapisuje pobrane indeksy?
+ /var/lib/apt/lists/
- /var/cache/apt/archives/
- /etc/apt/sources.list.d/
- /var/lib/dpkg/status
E: Pliki InRelease i Packages każdego repozytorium.
#Q
Q: Co oznacza linia „Hit:” w wyniku apt update?
+ Indeks repozytorium nie zmienił się od ostatniego pobrania
- Indeks pobrano na nowo
- Wystąpił błąd pobierania
- Pakiet został zainstalowany
E: Get — pobrany nowy indeks, Err — błąd, Ign — pominięty.
#Q
Q: Co oznacza linia „Get:” w wyniku apt update?
+ Pobrano nowy plik indeksu, w nawiasie jego rozmiar
- Indeks bez zmian
- Instalację pakietu
- Odrzucenie repozytorium
E: Np. Get:2 ... noble-updates InRelease [126 kB].
#Q
Q: Co oznacza końcowy komunikat „4 packages can be upgraded”?
+ Według świeżych list cztery zainstalowane pakiety mają nowsze wersje
- Cztery pakiety właśnie zaktualizowano
- Cztery pakiety są uszkodzone
- Cztery repozytoria są niedostępne
E: Szczegóły pokaże apt list --upgradable.
#Q
Q: Które polecenie pokazuje pakiety czekające na aktualizację?
+ apt list --upgradable
- apt show --upgrades
- apt update --list
- dpkg -l --new
E: Wynik opiera się na ostatnim apt update.
#Q
Q: Co oznacza zapis [upgradable from: 3.0.13-0ubuntu3.5]?
+ Obecnie zainstalowana jest wersja 3.0.13-0ubuntu3.5, a dostępna nowsza
- Pakiet trzeba zainstalować od wersji 3.0.13-0ubuntu3.5
- Wersja 3.0.13-0ubuntu3.5 jest najnowsza
- Pakiet został zdegradowany
E: Nowa wersja stoi przed nawiasem.
#Q
Q: Po czym w wyniku apt list --upgradable rozpoznasz aktualizację bezpieczeństwa?
+ Po repozytorium -security w nazwie, np. openssl/noble-updates,noble-security
- Po czerwonym kolorze
- Po słowie SECURITY na początku linii
- Po architekturze all
E: Poprawki bezpieczeństwa idą do osobnego repozytorium.
#Q
Q: Czym różni się apt upgrade od apt full-upgrade?
+ upgrade nigdy nie usuwa pakietów, full-upgrade może usuwać, jeśli wymaga tego rozwiązanie zależności
- full-upgrade aktualizuje do nowego wydania dystrybucji
- upgrade pobiera listy, full-upgrade instaluje
- Niczym — to aliasy
E: Np. przy zmianie nazwy biblioteki.
#Q
Q: Jakie jest starsze polecenie odpowiadające apt full-upgrade?
+ apt-get dist-upgrade
- apt-get upgrade
- apt-get full
- dpkg --upgrade
E: Mimo nazwy nie zmienia wydania dystrybucji.
#Q
Q: Czym apt-get upgrade różni się od apt upgrade?
+ apt-get upgrade nie instaluje nowych pakietów, więc aktualizacje wymagające nowych zależności zostają wstrzymane
- apt-get upgrade usuwa pakiety
- apt-get upgrade nie wymaga roota
- apt-get upgrade aktualizuje także jądro do nowego wydania
E: apt upgrade może doinstalować nowe zależności.
#Q
Q: Co oznacza komunikat „The following packages have been kept back”?
+ Pakiety nie zostały zaktualizowane, bo wymagałoby to instalacji nowych lub usunięcia innych pakietów
- Pakiety są uszkodzone
- Pakiety zostały zainstalowane w starej wersji z kopii zapasowej
- Pakiety zostały usunięte
E: Rozwiązanie: świadomie full-upgrade lub apt install konkretnego pakietu.
#Q
Q: Jakie pakiety typowo bywają „kept back” przy apt-get upgrade?
+ Metapakiety jądra, np. linux-generic, bo nowe jądro to nowy pakiet z numerem wersji w nazwie
- Pakiety z dokumentacją
- Pakiety bez zależności
- Pakiety architektury all
E: Nowe jądro to np. linux-image-6.8.0-48-generic.
#Q
Q: Czym są aktualizacje fazowane w Ubuntu?
+ Stopniowym udostępnianiem nowej wersji coraz większemu procentowi maszyn
- Aktualizacjami tylko dla jądra
- Aktualizacjami wymagającymi restartu
- Aktualizacjami ręcznie zatwierdzanymi przez administratora
E: Pozwala wykryć problemy, zanim trafią do wszystkich.
#Q
Q: Co oznacza komunikat „deferred due to phasing”?
+ Aktualizacja jest wydawana stopniowo i ta maszyna jeszcze jej nie dostała — to normalne
- Aktualizacja się nie powiodła
- Repozytorium jest niedostępne
- Pakiet jest zablokowany przez administratora
E: Pojawi się w kolejnych dniach.
#Q
Q: Gdzie zobaczysz procent fazowania nowej wersji pakietu?
+ W apt-cache policy pakiet, np. (phased 30%)
- W /var/run/reboot-required
- W apt list --installed
- W /etc/apt/sources.list
E: Linia wersji kandydata ma dopisek phased.
#Q
Q: Czy należy wymuszać instalację aktualizacji fazowanych?
+ Zwykle nie — fazowanie chroni przed wadliwą wersją; wystarczy poczekać
- Tak, zawsze, bo inaczej system jest niebezpieczny
- Tak, opcją --force-yes
- Nie da się ich zainstalować w żaden sposób
E: Opcja APT::Get::Always-Include-Phased-Updates istnieje, ale do szczególnych przypadków.
#Q
Q: Co oznacza istnienie pliku /var/run/reboot-required?
+ Zainstalowana aktualizacja wymaga restartu systemu
- System restartuje się automatycznie
- Restart jest zabroniony
- Ostatni restart się nie powiódł
E: Lista pakietów w /var/run/reboot-required.pkgs.
#Q
Q: Jakie aktualizacje najczęściej wymagają restartu systemu?
+ Jądro, biblioteka libc, systemd
- Dokumentacja i strony man
- Gry z /usr/games
- Pliki tzdata
E: Nowego jądra nie da się użyć bez restartu (pomijając livepatch).
#Q
Q: Jak w skrypcie sprawdzić, czy potrzebny jest restart?
+ [ -f /var/run/reboot-required ] && echo restart
- apt reboot-check
- uname -r | grep reboot
- cat /etc/reboot
E: Test istnienia pliku.
#Q
Q: Do czego służy needrestart?
+ Po aktualizacji wskazuje usługi korzystające ze starych bibliotek i proponuje ich restart
- Restartuje system co noc
- Blokuje restart podczas aktualizacji
- Sprawdza, czy apt update jest potrzebny
E: Domyślnie w Ubuntu Server.
#Q
Q: Co oznacza NEEDRESTART-KSTA: 3 w wyniku needrestart -b?
+ Działające jądro jest starsze niż zainstalowane — potrzebny restart
- Trzy usługi wymagają restartu
- Jądro jest aktualne
- needrestart działa w wersji 3
E: KCUR — bieżące jądro, KEXP — oczekiwane.
#Q
Q: Jak zaktualizować Ubuntu do nowego wydania (np. 22.04 → 24.04)?
+ do-release-upgrade
- apt full-upgrade
- apt upgrade --release
- apt update --next
E: full-upgrade aktualizuje pakiety w obrębie wydania.
#Q
Q: Co określa Prompt=lts w /etc/update-manager/release-upgrades?
+ do-release-upgrade proponuje tylko przejście na kolejne wydanie LTS
- System nie będzie aktualizowany
- Aktualizacje bezpieczeństwa są wyłączone
- Proponowane są wszystkie wydania, także rozwojowe
E: Inne wartości: normal i never.
#Q
Q: Jak w Debianie przechodzi się na nowe wydanie?
+ Zmienia się nazwę wydania w źródłach (np. bookworm → trixie), a potem apt update i full-upgrade
- Poleceniem do-release-upgrade
- Poleceniem apt upgrade --dist
- Przez ponowną instalację systemu
E: Debian nie ma do-release-upgrade.
#Q
Q: Jaki błąd grozi, gdy instalujesz pakiet ze starymi listami?
+ 404 Not Found — w repozytorium nie ma już wersji zapisanej w liście
- Permission denied
- Unable to locate package
- Segmentation fault
E: Rozwiązanie: sudo apt update.
#Q
Q: Co podpowiada APT po błędzie 404 przy pobieraniu archiwów?
+ maybe run apt-get update or try with --fix-missing?
- reinstall your system
- check your password
- run dpkg --configure -a
E: Właściwie zawsze wystarczy update.
#Q
Q: Co się stanie, gdy uruchomisz apt upgrade bez wcześniejszego apt update?
+ APT skorzysta ze starych list i może zgłosić „0 upgraded”, choć są nowe poprawki
- APT automatycznie wykona update
- APT odmówi działania
- Zainstaluje wszystkie wersje rozwojowe
E: To fałszywe poczucie aktualności systemu.
#Q
Q: Jaka jest typowa sekwencja aktualizacji?
+ sudo apt update && sudo apt upgrade
- sudo apt upgrade && sudo apt update
