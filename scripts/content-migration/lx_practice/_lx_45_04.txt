+ Nie — rozwiązywanie nazw działa w sieciach użytkownika
- Tak, zawsze
- Tylko po restarcie
- Tylko z --privileged

- docker net add sklep-net
- ip link add sklep-net
- docker create network sklep-net
E: Domyślny sterownik to bridge.

Q: Jaki adres ma wbudowany serwer DNS Dockera widoczny w kontenerach sieci użytkownika?
+ 127.0.0.11
- 8.8.8.8
- 172.17.0.1
- 127.0.0.53
E: Rozwiązuje nazwy kontenerów i przekazuje inne zapytania dalej.

Q: Jaką sieć tworzy Docker Compose dla projektu?
+ Sieć użytkownika, w której nazwy usług są nazwami hostów
- Zawsze sieć domyślną bridge
- Sieć host
- Brak sieci

Q: Co oznacza -p 8080:80?
+ Port 8080 gospodarza jest przekazywany do portu 80 kontenera
- Port 80 gospodarza do 8080 kontenera
- Kontener ma dwa porty
- Port 8080 jest blokowany
E: Format: gospodarz:kontener.
#Q
Q: Na jakich adresach gospodarza publikowany jest port przy -p 8080:8080?
+ Na wszystkich (0.0.0.0 i ::)
- Tylko 127.0.0.1
- Tylko na adresie docker0
- Na żadnym
E: Dlatego port jest dostępny z sieci.
#Q
Q: Jak opublikować port tylko lokalnie na gospodarzu?
+ -p 127.0.0.1:5433:5432
- -p local:5433:5432
- -p 5433:5432 --local
- --expose 5432
E: Z innych maszyn połączenie zostanie odrzucone.
#Q
Q: Co robi -p 80 (bez portu gospodarza)?
+ Publikuje port 80 kontenera na losowym wolnym porcie gospodarza
- Publikuje port 80 na 80
- Blokuje port 80
- Nic
E: Przydzielony port pokaże docker port.
#Q
Q: Co robi opcja -P (wielkie P)?
+ Publikuje wszystkie porty z EXPOSE na losowych portach gospodarza
- Publikuje port 80
- Wyłącza porty
- Uruchamia kontener jako uprzywilejowany
E: Rzadko stosowane w produkcji.
#Q
Q: Co robi instrukcja EXPOSE w Dockerfile?
+ Dokumentuje port aplikacji — sama nie publikuje go na gospodarzu
- Publikuje port
- Otwiera port w ufw
- Przypisuje adres IP
E: Publikowanie to -p przy uruchomieniu.
#Q
Q: Które polecenie pokazuje mapowanie portów kontenera?
+ docker port NAZWA
- docker ports
- docker network ports
- docker ps --ports
E: Kolumna PORTS w docker ps pokazuje to samo w skrócie.
#Q
Q: Jaki proces na gospodarzu nasłuchuje na opublikowanym porcie (domyślna konfiguracja)?
+ docker-proxy
- dockerd zawsze
- nginx
- containerd
E: Główną rolę grają reguły DNAT; docker-proxy obsługuje m.in. ruch z localhost.
#Q
Q: Jak Docker przekazuje ruch z opublikowanego portu do kontenera?
+ Regułą DNAT w tablicy nat (łańcuch DOCKER) i przekazaniem w FORWARD
- Przez SSH
- Przez Samba
- Przez /etc/hosts
E: Odpowiedzi wracają dzięki śledzeniu połączeń.
#Q
Q: Co robi reguła MASQUERADE dla sieci Dockera w POSTROUTING?
+ Zamienia adres źródłowy ruchu wychodzącego z kontenerów na adres gospodarza
- Blokuje ruch
- Zmienia port docelowy
- Szyfruje ruch
E: Dzięki temu kontenery mają dostęp do internetu.
#Q
Q: Dlaczego port opublikowany przez Dockera omija reguły ufw?
+ Ruch po DNAT trafia do łańcucha FORWARD, a ufw filtruje ruch do gospodarza w INPUT
- Bo ufw nie obsługuje TCP
- Bo Docker wyłącza ufw
- Bo kontenery mają osobną zaporę
E: ufw status nie pokazuje reguł Dockera.
#Q
Q: W którym łańcuchu iptables wpisuje się własne ograniczenia ruchu do kontenerów?
+ DOCKER-USER
- INPUT
- OUTPUT
- ufw-user-input
E: Docker nie nadpisuje tego łańcucha.
#Q
Q: Jakie jest domyślne zakończenie łańcucha DOCKER-USER?
+ RETURN — ruch przechodzi dalej do reguł Dockera
- DROP
- ACCEPT dla wszystkiego bez dalszych reguł
- REJECT
E: Własne reguły dodaje się przed nim (iptables -I).
#Q
Q: Dlaczego w regule DOCKER-USER używa się --ctorigdstport zamiast --dport?
+ Po DNAT port docelowy jest już portem kontenera — oryginalny port opublikowany zna conntrack
- Bo --dport nie istnieje
- Bo DOCKER-USER działa przed DNAT
- To bez znaczenia
E: Moduł conntrack pamięta pierwotny adres i port.
#Q
Q: Jakie jest najlepsze rozwiązanie dla bazy, która nie musi być dostępna z sieci?
+ Nie publikować portu — kontenery łączą się przez sieć użytkownika; ewentualnie -p 127.0.0.1:...
- Opublikować port i dodać regułę ufw deny
- Zmienić port na 15432
- Wyłączyć ufw
E: Nieopublikowany port nie jest dostępny spoza gospodarza.
#Q
Q: Czym jest localhost w kontenerze?
+ Samym kontenerem — jego własna przestrzeń nazw sieci
- Gospodarzem

+ 172.17.0.0/16
- docker0
- 127.0.0.11
- bridge
E: IPAM — zarządzanie adresami sieci.
#Q
Q: Czym różni się sieć użytkownika od sieci domyślnej pod względem nazw?
+ W sieci użytkownika działa DNS z nazwami kontenerów i aliasami
- Niczym
- Sieć domyślna ma lepszy DNS
- Sieć użytkownika nie ma DNS
E: To główny powód, by zawsze tworzyć własne sieci.
#Q
Q: Kontener ma nazwę sklep-stack-sklep-1 w Compose. Pod jaką nazwą widzą go inne usługi?
+ sklep (nazwa usługi) — oraz pełna nazwa kontenera
- Tylko sklep-stack-sklep-1
- Tylko jego IP
- localhost
E: Compose rejestruje nazwę usługi jako alias.
#Q
Q: Co dzieje się z ruchem wychodzącym z kontenera do internetu?
+ Przechodzi przez bramę mostu i MASQUERADE na adres gospodarza
- Jest blokowany
- Idzie przez 127.0.0.11
- Idzie przez docker-proxy
E: Dla świata zewnętrznego ruch pochodzi z gospodarza.
#Q
Q: Jak sprawdzić, czy port 80 kontenera web jest dostępny z innej maszyny?
+ Z tej maszyny: curl lub nc -zv ADRES_SERWERA 80
- docker port web na serwerze wystarczy
- ping serwera
- docker logs web
E: Test z zewnątrz potwierdza rzeczywistą dostępność.
#Q
Q: Co jest prawdą o kontenerach i protokole IPv6 przy -p?
+ Docker publikuje port także na [::], więc port jest dostępny przez IPv6, jeśli gospodarz ma adres IPv6
- IPv6 nigdy nie działa
- Port jest dostępny tylko przez IPv6
- IPv6 wymaga --network host
E: Reguły zapory warto sprawdzać dla obu protokołów.
